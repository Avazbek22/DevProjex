# 2026-09-11: the task profile decides the winner

## Why

On [2026-09-10](2026-09-10.md) DevProjex needed 61 calls where Repomix needed 37 for the same work,
on two repositories. This day asked three questions in order: does the gap hold on a third
repository and language, does it depend on the kind of task, and where do the extra calls and
characters go.

## 2. Broad tasks against precise tasks, `acbfa6bb`

| Task set | DevProjex calls | Repomix calls | DevProjex tokens | Repomix tokens |
|---|---:|---:|---:|---:|
| Broad: bug localization, change impact stated vaguely | 82 | 47 | 70,825 | 50,199 |
| Precise: an exact value, a symbol's blast radius, a minimal reading set, a contradiction | 33 | 29 | 23,450 | 50,393 |

On the precise set DevProjex was cheaper on each of the four tasks, both sides found every core
file, and the agent kept DevProjex in 3 of 4 tasks. A pack pays a large fixed cost and then reads
cheaply, so it wins when the question needs a whole area; DevProjex pays nothing up front and
reads precisely, so it wins when the question has a specific answer. The Repomix figures moved by
21% between two runs of unchanged Repomix, so per-task differences of that size are noise.

**Secrets probe without a model.** A fixture with seven planted credentials.

| Measurement | DevProjex | Repomix 1.18.0 |
|---|---:|---:|
| Credential values returned to the caller | 0 of 7 | 0 of 7 |
| Files whose surrounding code is still readable | 7 of 7 | 1 of 7 |

Repomix excludes a whole file that contains a secret; DevProjex replaces the value and keeps the
code. Two leaks reported at first were defects in the fixture: an AWS access key id must be base32
to match the rule, and the paired secret was the AWS documentation example, which the allowlist
skips on purpose.

## 3. Why the agent reads whole files

In the broad run on `acbfa6bb`, 12 of 30 `get_file` calls read a whole file. Each was examined:

| Kind of read | Count | Characters | What happened |
|---|---:|---:|---|
| Reflex read with the declaration already in hand | 7 | about 26,000 | the previous result had named the declaration |
| No anchor: truncation never listed the wanted file | 3 | about 46,000 | `src/context.ts` alone was 22,900 characters, after a search capped at 30 of 891 matches in path order |
| Name guess from a tree listing | 2 | — | nothing useful found |

In 8 of 12 the agent already had the declaration name, in 6 of them from an
`Enclosing declarations:` block in the result just before. Every one of these calls followed the
previous result immediately, with no reasoning in between. The capabilities shipped for this case
were not used: symbol reads 0 of 30, `with_symbols` 0, `expand_related` 0.

**Conclusion:** a tool description is read once at session start and cannot affect that moment.
Anything meant to change the next call has to be inside the result the agent is reading. This is
what #387 did on `5f54ea38` (section 7).

## 5. Python module constants in the dependency engine: rolled back

The dependency engine learned to resolve module-level constants. The frozen ranking evaluation
(`tools/RankingEval`, see [2026-09-07](2026-09-07.md)) regressed on Flask, and a repeat run gave
identical numbers:

| Cell | Before | With constants |
|---|---:|---:|
| `json-provider`, `importance-v1`, recall of new files at 4,000 and 8,000 tokens | 0.5 | 0 |
| Cells changed in total | none | 12 worse, 6 better |

New edges change the importance graph, so the regression belongs to the capability, not to the
implementation. **Rolled back whole; no PR was opened.**

What a retry must handle, found in the attempt:

- `del` targets read from the syntax tree, not a regex (`del CONFIG["k"]` does not unbind
  `CONFIG`);
- annotated (`TIMEOUT: int = 30`) and tuple (`A, B = 1, 2`) assignments;
- precedence between an unconditional assignment and a conditional re-export;
- constants re-exported through a package `__init__.py`;
- the order of assignment and deletion (`X = 1; del X; X = 2`).

**Later:** constants were not indexed in the dependency engine again. #497 (November) links an
import of a module constant to the module file instead, gated by one `RankingEval` run against the
saved baseline; #514 added module constants as navigation declarations only.

## 6. The ranking timing gate is noise, and #367

Re-landing the C# entry-point signal (#367 for issue #338, found on [2026-09-09](2026-09-09.md))
hit a gate of `max(5%, 100 ms)` on the warm `focus-v1` incremental of `tools/RankingEval`. Three
runs of identical, unmodified v5.2 code:

| Run | Change against the reference |
|---|---:|
| 1 | −85.97 ms |
| 2 | +135.80 ms |
| 3 | +2.29 ms |

The gate's verdict changed between runs with no code change, and the 105 ms that had caused the
first revert was inside that band. Warm ranking also reuses the cached index (`parsed=0`), so it
cannot see extraction changes at all.

**New protocol, registered before measuring:** the median of five independent warm runs per
repository against the unmodified base, measured back to back in one quiet window, with a 10%
allowance; extraction measured separately with `measure-index-one`.

| Repository | Warm ranking, base | Warm ranking, #367 | Change |
|---|---:|---:|---:|
| DevProjex | 943.29 ms | 817.01 ms | −13.4% |
| Repomix | 376.17 ms | 380.35 ms | +1.1% |
| Flask | 164.13 ms | 166.40 ms | +1.4% |

Repomix and Flask contain no C#, so their +1.1% and +1.4% are the noise floor. Extraction was
unchanged within that floor (DevProjex cold −1.2%, warm +4.2%). The frozen evaluation was identical
in every cell. **#367 kept.**

**Rule from this day:** fix the protocol before measuring, take the median of several runs of base
and change back to back, and use the corpora that cannot contain the change as the noise floor.

## 7. Broad set on four builds

Tasks T1, T2, T4, T5, T7 and T8, one session each, run in the evening after #386, #387 and #389
were merged.

| DevProjex build | DevProjex calls | Repomix calls | DevProjex tokens | Repomix tokens |
|---|---:|---:|---:|---:|
| v5.2 `61b5f004` | 86 | 59 | 79,800 | 63,900 |
| v5.2 `acbfa6bb` | 82 | 47 | 70,800 | 50,200 |
| `acbfa6bb` without caps | 65 | 41 | 74,000 | 56,700 |
| v5.2 `5f54ea38` | 71 | 50 | 60,700 | 62,100 |

On `5f54ea38` the token gap closed because each search became cheaper; the number of calls did not
fall. The `[Search stored] … read_pack` hint appeared in 7 of 25 searches and was followed 0
times. In the same response another line told the agent to narrow the pattern, so the two lines
contradicted each other. From then on, hints were written as refusals that carry the correct call,
not as suggestions. One error: `get_file` with `symbol: "LogContext.Enrich"`, a method the index
did not contain, because C# declarations were indexed per type only.

## Lessons

- Name the task profile whenever a cost comparison is quoted.
- A shipped capability is not a used one.
- The decision to read a whole file is taken right after a result is read. A change meant to
  affect it has to be inside that result.
