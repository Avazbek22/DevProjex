# 2026-09-11: the task profile decides the winner

**Builds:** v5.2 `61b5f004`, `acbfa6bb`, `5f54ea38` · **Other side:** Repomix 1.18.0 · **Agent:**
Claude Haiku 4.5 · **Format:** paired, one agent solves each task once per server

## 1. Three repositories

**Setup.** httpx 0.28.1 (Python), hono v4.13.7 (TypeScript), serilog v4.3.0 (C#). Two tasks each,
bug localization and change impact. C# is our strongest dependency adapter, so serilog favours us
by construction.

| Metric | DevProjex / Repomix |
|---|---|
| Calls | 86 / 59 |
| Estimated tokens | 79,821 / 63,879 |
| Keep verdict | 5 / 1 |
| Mean trust | 4.67 / 4.50 |

Correctness was identical on every task. The token gap narrowed from the day before but did not
close.

**Latency, no model, median of three.** Ready to list tools: 432 to 468 ms / 1,168 to 1,245 ms. A
repeat search costs 15 to 80 ms; the first search, which warms the inventory, 1.0 to 1.8 s.
Repomix packs a repository in about 0.4 s and then greps it in 4 to 29 ms, so time to a first
answer is a tie. Our `tools/list` was 42,370 characters against 17,782.

**Two defects filed.** #362: search repeated the full path on every match and context line, which
cost tokens and hid the line numbers so well that the agent claimed three times we did not print
them. #363: results were ordered by path, so committed generated reports pushed the real
declaration below the cap.

## 2. Broad against precise tasks

Same binary (`acbfa6bb`), same repositories, same day:

| Task profile | Calls, DevProjex / Repomix | Tokens, DevProjex / Repomix |
|---|---|---|
| Broad: bug localization, vague change impact | 82 / 47 | 70,825 / 50,199 |
| Precise: an exact value, a symbol's blast radius, a minimal reading set, a contradiction | 33 / 29 | 23,450 / 50,393 |

On the precise set we were cheaper on all four tasks, with the same core files found and a keep
verdict of 3 to 1. The reason is the model of each tool: a pack pays a large fixed cost and then
reads cheaply, so it wins when the question needs the whole area; we pay nothing up front and read
precisely, so we win when the question has a specific answer. Repomix's own numbers moved 21%
between two runs of unchanged Repomix, so per-task differences of this size are noise.

**Secrets probe, no model.** A fixture with seven planted credentials. Values reaching the caller:
0 of 7 for both. Code around them still readable: 7 of 7 for DevProjex, 1 of 7 for Repomix,
because Repomix drops the whole file that holds a secret. Two false leaks turned out to be defects
in the fixture: an AWS key id must be base32 to match the rule, and the paired secret was the
AWS documentation example, which the allowlist leaves alone on purpose.

## 3. Notice suppression (#347)

Showing `[Effective filters]` and `[Protection]` only once per session saved 217 characters on
tree, pack and related responses, and 1 character on `get_file` and `search_project`, the two
tools that make up most calls. The new text cost more up front: instructions 885 → 1,044
characters, `tools/list` 33,816 → 34,612. The real saving in #347 was the 16,000-character search
cap: one wide search went from 43,182 to 16,519 characters. **Kept** for the cap and the reduced
noise, not for the bytes.

## 4. Python module constants: rolled back

The dependency engine learned to resolve module-level constants. The frozen ranking evaluation
regressed on Flask and the result repeated byte for byte: `json-provider` recall of new files
fell from 0.5 to 0 at 4,000 and 8,000 token budgets, 12 cells worse and 6 better. New edges change
the importance graph, so the regression belongs to the capability, not to the code. **Rolled back
whole, no PR.** The attempt also showed what a retry must handle: `del` targets from the syntax
tree, annotated and tuple assignments, precedence over conditional imports, re-exports through
`__init__.py`, and order of assignment and deletion. Python constants came back later in two
pieces: as relations in #497 and as declarations in #514.

## 5. Ranking timing is noise

Re-landing the C# entry-point signal (#338, PR #367) hit a timing gate of `max(5%, 100 ms)` on the
warm `focus-v1` incremental. Three runs of identical unmodified code gave −85.97, +135.80 and
+2.29 ms. The gate's verdict flipped with no code change, and the 105 ms that had caused the first
revert sat inside that band. Warm ranking also reuses the cached index (`parsed=0`), so it cannot
see extraction changes at all. **Rule from here on:** pre-register the protocol, take the median of
several runs back to back, and use the corpora that cannot contain the change as the noise floor.

## 6. Broad run on `5f54ea38`

Search headers per file, stored results, breadth-first truncation and declarations first:

| Arm | Calls, DevProjex / Repomix | Tokens, DevProjex / Repomix |
|---|---|---|
| `61b5f004` | 86 / 59 | 79.8k / 63.9k |
| `acbfa6bb` | 82 / 47 | 70.8k / 50.2k |
| caps lifted | 65 / 41 | 74.0k / 56.7k |
| `5f54ea38` | 71 / 50 | 60.7k / 62.1k |

The token gap closed because each search got cheaper; the number of calls did not fall. The
`[Search stored] … read_pack` hint fired in 7 of 25 searches and was followed 0 times. In the same
response another line told the agent to narrow the pattern, so the two lines contradicted each
other. One error: `get_file` with `symbol: "LogContext.Enrich"`, a member the index did not hold,
because C# declarations were indexed per type only.

## Lessons

- Name the task profile whenever a cost comparison is quoted.
- Shipping a capability is not the same as an agent using it: on the same tip, symbol reads were
  used 0 times in 30 `get_file` calls.
- The decision to read a whole file is made right after a result is read. A fix has to sit inside
  that result, not in a description read once at session start.
