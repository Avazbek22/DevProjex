## 1. #488: dependency configuration read from the project

**Cause.** Configuration files of every language were read only from the selected files, and the
Python fallback without `pyproject.toml` blocked every import, even `from .core` and the standard
library.

**Fix.** The engine finds configuration files in the directories of the selected files and their
parents up to the project root, as a compiler would, even when a filter excludes them. They define
how imports resolve; they are never returned to the agent. Python without configuration resolves
relative imports, the standard library and neighbouring modules.

| Check | Result |
|---|---|
| click, three requests with and without `pyproject.toml` | same relations |
| click `paths: ["src"]`, internal reference resolution | 0% → 41% |
| `RankingEval`, base `03edce29` against `41a721f8` | 0 of 270 cells changed; release criterion passes, RecallNew delta +0.3667 |
| Cold index, full project, DevProjex, median of seven | 3,922.3 → 4,100.2 ms (+4.5%) |
| Cold index, full project, Repomix | 491.2 → 508.8 ms (+3.6%) |

The cold cost is about 10 to 20 ms for listing roughly one hundred parent directories; nothing new
is found on a full selection. Accepted, because no cheap replacement kept cache invalidation
correct; reducing it went to issue #489.

## 3. #491: outside-selection group, and the CRLF defect found with it

While testing the new group on `git_scope: changes`, a clone of click with 2 changed files selected
all 143. DevProjex runs git with system and global configuration ignored, for safety; Git for
Windows keeps `core.autocrlf=true` in the system configuration, so every rechecked file looked
modified in any Windows clone.

| Case | Before | After |
|---|---:|---:|
| click, 2 changed files | 143 files | 2 files, `outside-selection=4` |
| test clone, 1 of 3 files changed | 3 files | 1 file |
| `changes` call | about 580 ms | about 615 ms |

The fix reads only `core.autocrlf` and `core.eol`, in git's own order (system, user, repository),
validates them and passes them to the one working-tree diff. No other user setting reaches git.
The exception is documented in `Docs/Git-Safety.md`.
