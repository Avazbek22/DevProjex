# 2026-09-12: the measuring tools and what the agent is not told

No new sessions this day. The sessions of 10 and 11 September were analysed again, and the
analysis changed both the product and the way every later benchmark was measured.

## Why

By the evening of 11 September the broad set on `5f54ea38` showed token parity with Repomix
(60,700 against 62,100), and yet every capability shipped to save calls was unused. The question
for this day was where the budget actually goes, and whether the numbers themselves could be
trusted.

## What the existing sessions showed

**Unused capabilities**, over 337 measured calls to DevProjex:

| Capability | Use |
|---|---|
| `related_files` | 1 call |
| Tools never called | 3 of 8 |
| Batched `get_file` | 3 of 62 possible |
| `get_file` by `symbol` | 2 calls, both failed |

The tools agents did use were `list_projects`, `get_tree`, `search_project` and `get_file`, the
equivalents of `ls`, `find`, `grep` and `cat`. The unused ones are those whose result cannot be
predicted before calling them.

**Where search output went:**

- 62.3% of search characters went to files that the answer never cited. The largest single item
  was `Serilog.approved.txt`, a generated snapshot dump: 11,181 characters in 11 of 31 searches,
  cited 0 times. Results were cut in path order, so generated files, tests and vendored code used
  the budget before live source was reached.
- 136 file reads followed 124 searches; 66% of the reads opened a file that search had already
  named, 44% came straight after a search, 45% used a line range.
- The tool catalog was a fixed cost of 42,370 characters per session, 62% of it for tools called
  about once in 337 calls.

**Results the agent could not see were missing.** Search candidates passed four limits in order:
64 MiB scanned, the first 5,000 matching lines kept, the first 64 files annotated, 16,000
characters returned. A sort at the end cannot recover what was not kept, so the response was the
first surviving 16,000 characters, in file-system order, and it looked complete. The worst outcome
of such a limit is a false zero: "no usages" when the tool had stopped looking.

**Defects in DevProjex output:**

- The protective frame around untrusted data did not reach the model on `list_projects` and
  `analyze`: paths and project names arrived as bare JSON.
- The line "read the declaration with `get_file` and `symbol`" was printed 18 times in one run and
  failed both times an agent followed it.

**Defect in the measuring tools.** The benchmark scripts reported characters divided by four as
"tokens". The 60,700 / 62,100 parity was a 2.25% difference measured on a quantity that is not what
the model processes. Claims about cost made on that basis were not valid.

**Earlier claims withdrawn on 11 and 12 September:**

| Claim | Why it was withdrawn |
|---|---|
| "Repomix returns the wrong file for a line range" | its ranged read addresses the packed document by design, not a source file |
| "Start-up is 2.7 times faster" | time to the first answer is a tie ([2026-09-11](2026-09-11.md)) |
| Three statements that a competitor cannot do something | each was checked and was false; Repomix already ships tree-sitter, for example |
| Paired sessions with both servers give an independent comparison | the agent carries knowledge from the first phase into the second |

## What was changed

| Change | Reason |
|---|---|
| #391: the untrusted-data frame on every tool result; printed next-call routes made executable and checked by a test that replays each printed call through the real parser; member-level navigation | the frame did not reach the model on two tools, a printed route failed every time it was followed, and at type level the index cannot answer "who calls this method" |
| #392: dependency facts for twelve languages instead of five | on live repositories 136 of 136 relations were confirmed in source; before, Java had 0 of 12 real relations, Ruby 17 invented of 70, and Kotlin 6 through incompatible source sets |
| A closing line on search results stating how many sources were inspected and what stopped the search, and search keeping the best of what it inspected instead of the first survivors | a cut result must say that it is cut |
| Benchmark totals taken from the client's own token counters | characters divided by four do not measure model input |
| Comparisons run as separate sessions, one server per session | paired sessions are not independent |
