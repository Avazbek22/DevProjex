# 2026-11-14: the reduced tool set becomes the default, four sides with Claude, .NET 10 against .NET 11

#550 was prepared on 12 November, measured the same day on four sides at its head `1f90ac4b`
and merged on 14 November as `2d721078`. This file holds all of it, so that [2026-11-12](2026-11-12.md) stays the record of
#545 to #547. Every section names the day its numbers were taken. The last section is a
measurement without a model of 14 November: `2d721078` published for .NET 10 and for .NET 11.

## Why

The run of [2026-11-12](2026-11-12.md) with Claude Haiku measured the fixed part of a request
directly. On v5.2.2 the first request of a session held 14,802.5 tokens against 11,036.5 on
Repomix, and that part, sent again with every later request, was half of all context tokens of
the run. The tool catalog is the largest piece of it.

Whether the catalog publishes what agents use was then counted over the DevProjex sessions kept
from the November series: 965 sessions and 9,949 tool calls of Claude Haiku and Codex CLI.

`analyze`, `pack_context` and `read_pack` took 10,353 of the 26,383 characters of the tool list
and 74 of the 9,949 calls.

The same sessions end with the agent's remarks on the server it used, 1,084 of them from 7 to
12 November. Counted by keywords, which is a rough count checked by hand on the 18 answers of
v5.2.2 `059f95af` in the three-sided run:

|---|---:|---:|

| Search results cut or too large | 43 to 53% | 44 to 46% |

- The request for the places that use a name is made of Repomix as well, in 38 to 56% of its
  sessions.
- Much of the cutting is the agent's own. Codex CLI set `max_results` in 1,265 of 1,281 searches
  and Claude Haiku in 1,065 of 2,216. Of the 20 searches of v5.2.2 `059f95af` in the three-sided run that did
  not print every match, 11 were cut by the agent's own `max_results`. The stand's prompt tells the agent
  that every tool call and every token counts against it.

Three ideas were dropped on these counts without being built:

- *Never deliver the same lines twice in a session.* 230 of 14,469 delivered lines had been
  delivered before.
- *Several declaration bodies in one search response.* At most 13 later reads saved in 18
  sessions, for about 116,000 characters added.
- *Rewording the line under a search that did not print every match.* It already says that
  every file was searched.

## #550: the tools and parameters agents use, published by default

**What changed.**

- The reduced tool set is the default. It publishes `get_tree`, `search_project`, `get_file`,
  `related_files`, `get_diff` and `read_pack`. `--tool-set full` publishes all nine tools.
- `list_projects` is published only when there is a project to choose: with several local roots
  or with `--allow-remote`.
- In the reduced set `tracked_only`, `git_scope`, `max_file_bytes`, `profile` and
  `exclude_patterns` leave the schemas of the tools where the recorded sessions did not use
  them. Each is still accepted, with the same validation and the same errors. A parameter that a
  tool's own response tells the caller to use stays published.
- The instructions and descriptions of the reduced set name no tool or parameter that it does
  not publish. With one local root two error messages no longer send the caller to
  `list_projects`.
- Nothing is removed from the server. A client that calls `analyze` or `pack_context` through
  MCP adds `--tool-set full` to the server arguments.

| `tools/list` result, characters | Default before | Default after | `--tool-set full` after |
|---|---:|---:|---:|
| One local root | 27,141 | 13,770 | 27,141 |
| Two local roots | 28,548 | 15,590 | 28,548 |
| One local root with `--allow-remote` | 29,171 | 16,035 | 29,171 |
| One local root with per-call exclusions | 30,102 | 15,885 | 30,102 |

The server instructions with one local root went from 1,197 to 966 characters.

**Checked without a model** (12 November).

- The full set is the previous default byte for byte, in the tool list and in the instructions,
  in every configuration of the table.
- 530 recorded calls of 58 sessions were replayed on the base build, on `--tool-set full` and on
  the default set: 18 Claude Haiku sessions with 311 calls and 40 Codex CLI sessions with 219.
  With the full set all 530 responses are identical. With the default set 527 are identical and
  3 are calls to `analyze`, which the default set does not publish.
- The five recorded calls that passed a parameter no longer published (`profile` to `get_file`
  twice, `max_file_bytes` to `get_tree` three times) returned the same responses.
- Every parameter that left a reduced schema has a call that passes it and gets the response it
  got before, and a call that breaks its rule and gets the same error.

**The first replay was stopped and repeated.** It ran the three states of each session at the
same time on one clone. In D1 the default-set state returned an input-output error from
`get_diff` and three searches that reported `sources inspected=477/484` where the base reported
479/486. The cause was not in #550:

- The unchanged base build gives the same four differences when Git is not on the path. 484 is
  486 less two tracked `.gitkeep` files that `.gitignore` patterns cover, so those responses came
  from a server working without Git.
- The changed build alone replayed D1 three times with all 11 responses identical. Ten rounds of
  three simultaneous server processes on one clone produced no difference.
- What made the one Git call fail was not found.

The replay behind the numbers above ran one server process at a time. Its rule for a failure of
the environment was written before any result was seen: one repeat of the affected session in
every state, and a stop at the second such case. No repeat was needed.

**Stand.** The same PR gave `tools/AgentBenchmark` what the next run needed: an arm can pass
arguments to its server, an arm can run Claude Code with its own file tools and no MCP server,
session summaries record the context of the first request, and a replay takes server arguments
for each of its two builds.

**Reading it.**

- The computing part is faster on .NET 11: 29 ms less for a cold start, 86 ms less for the warm
  pipeline and 407 ms less processor time in it. The ranges of the two builds overlap in every
  one of those rows.
- Memory did not fall. The working set is up to 5 MiB higher in the analysis and idle rows and

  not looked into.
- Limits of the measurement: one machine, one repository, `win-x64` only, and no test suite run

## Decisions

- **Kept:** #550, merged into v5.2.2 as `2d721078`.
- **Bar not reached:** 28.8% fewer context tokens than Repomix against 50%, and 9.4% fewer than
  the 5.2 release against 25%. No further change was made for it.
- **From here on** context tokens and tool calls stay a check that nothing got worse on the
  eighteen tasks. They are no longer what the next changes are for.
- **Not done:** judging `1f90ac4b` against the sessions of `059f95af`, the one pair
  that separates the effect of the catalog on answers from spread.
- **Not done:** moving to .NET 11. It brings no gain in speed or memory that would pay for a
  larger executable, a slower search and a runtime with a short support term.
- **Recorded, no decision:** 10 of 18 answers ask for the places that use a name, and the agents
  that had only the client's own tools ask for the same.
- **Recorded, no decision:** after one failed Git call the server answers the rest of the session
  without Git, and its responses show it only in their source counts.
- **Still unmeasured:** a second session per task; the seven-language series on repositories no
  change was measured on (#540); whether an agent finishes the task, not only which files it
  names; the slower interface search on .NET 11 and the open handles of an idle window on
  .NET 10.

## Lessons

- **A saving per request is not a saving per run.** Every request became 3,505 tokens lighter
  and the run made 32 more of them, so the total stayed where it was.
- **One session per task does not carry a percentage bar.** The same two builds, measured twice
  in one day, moved by 5.0% and by 15.7% in context tokens. A bar of 25% against the release
  needs more sessions than one per task to be read.
- **Count use before publishing less.** 965 recorded sessions showed which tools and parameters
  could leave the default catalog, and a replay of recorded calls showed that leaving them out
  changed no response.
- **The client's own tools are a side to measure, not a ceiling.** With the same model they
  needed more calls, named fewer required files, left two tasks unanswered and could not show a
  change.
- **A replay runs one server process per clone.** Three at once produced a failure that belonged
  to neither build, and it cost a stopped run to find that out.
- **Write the rule for a failed environment before looking at results.** With the rule in place
  the second replay needed no judgement call.
- **The measuring tools can stop a run as well as bias it.** A check that read a search pattern
  as a path marked two honest sessions and halted the series.
