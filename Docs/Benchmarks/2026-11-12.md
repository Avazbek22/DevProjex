# 2026-11-12: batch structure measured twice, a lighter catalog, member lists, three sides with Claude

Three changes to the MCP server were measured on this day: #545 twice with Codex CLI, then #546
and #547 without a model and in one Codex series of three builds. The day ended with a run of
all eighteen tasks with Claude Haiku on the 5.2 release, the current branch and Repomix 1.19.0.
The first difference in named files was repeated on new sessions before it was believed, and
the same build measured twice showed how far two series differ with no change at all.

The sections on #545 come first; #546, #547, the series of three builds and the Claude run
follow.

## Why

Codex sessions recorded on v5.2.2 showed where batched `get_file` calls lost work. 220 whole-file
batches asked for 1,064 files: 654 arrived whole, 131 were cut and 271 were not returned. In 117
of the 133 batches that overflowed, the limit reached was 1,000 lines. Across all batch reads of
those sessions, a file that was not returned was requested whole again in 138 of 298 cases. The
ready continuation call printed under a cut batch was shown 142 times and used 0 times. Four call
forms ended in an error: a ninth file against the limit of eight, a line range sent with several
paths, a regular expression sent with `symbols`, and a folder sent to `related_files`.

#545 changed what a batch returns and made those forms work:

- A batch takes up to sixteen files and has one limit, 50,000 characters.
- A large file (more than 300 lines and 20,000 characters) returns its start and its structure
  with line ranges; a file that no longer fits returns its structure instead of nothing.
- A line range sent with several paths is read from each of them, and `path` or `paths` can
  accompany `requests`.
- A regular expression sent with `symbols` runs as a text search and says so.
- A folder given to `related_files` stands for the files directly inside it.
- A search that cannot print every match always keeps room for the per-file counts of the rest.
- The structure of JavaScript and TypeScript test files lists `describe` and `it` blocks.
- The `Exported by:` line follows `tsconfig` `rootDir` and `outDir`, so a built entry point is
  traced back to its source file.
- Seven descriptions were reworded; `list_projects` now says it is not needed with one
  configured root.

## #546: parameters published only where they apply

**Why.** A client receives `tools/list` on connect and sends it to the model with every request.
In the 448 Codex sessions recorded up to this day (2,743 calls) `project` was passed in 2,345
calls, although every stand has one local root and the value selects nothing; `branch` was passed
in none. Five of the seven tool errors left after #545 were `DPX-MCP-UNKNOWN-PROJECT`.

**What changed.**

- `project` is published only when the server has several local roots or runs with
  `--allow-remote`; `branch` only with `--allow-remote`. Both are still accepted when they are not
  published.
- Input schemas no longer publish string lengths, array sizes and patterns that the server checks
  itself. Of 191 such keywords 179 are gone, six `git_scope` patterns became `^diff:`, and six
  stay because only the schema states them.
- With one local root, an unknown `project` is answered with one instruction: omit `project`.

| `tools/list` result, characters | Before | After |
|---|---:|---:|
| One local root | 32,400 | 27,141 |
| Two local roots | 32,400 | 28,548 |
| One local root with `--allow-remote` | 32,393 | 29,171 |
| One local root with per-call exclusions | 35,452 | 30,102 |
| One local root, `--tool-set reduced` | | 17,994 |

**Checked without a model.**

- The 441 recorded calls of 80 Codex sessions were replayed on both builds: 436 responses are
  identical, and 5 unknown-project errors carry the new sentence.
- All 2,743 recorded calls were validated against both catalogs with a JSON Schema validator. The
  new schemas reject no call that the previous ones accepted.
- Each of the 185 keywords that left a schema or changed has a call that breaks it and still gets
  the same error from the server.

## #547: comment hits and members of large declarations

**Why.** Two places where a response pointed at a whole class instead of the member the agent
needed.

- In 80 recorded Codex sessions the structure of a large file was delivered 108 times. In 40 of
  them a declaration of 60 lines or more was one line with a member count and no members, such as
  `Text (type, 55 members)` covering 1,218 of the 1,364 lines of `rich/text.py`. After such a
  list the agent read inside that declaration in 35 of 40 cases, first ran a search scoped to the
  same file in 14, and needed two separate read calls in 6.
- A search hit in a doc comment above a class member was counted for the class. In TypeScript
  sources 323 of the 512 match lines outside any declaration were comment lines. In T5 the body
  shown for such a search was the `Context` class, 505 lines cut at the limit, and not
  `Context.json`, 14 lines.

**What changed.**

- A hit in a comment directly above a declaration is headed by that declaration and listed under
  it in `Declarations found`. It counts toward the body shown only when the declaration's name
  matches the pattern. The same rule applies to the CLI `search` command; declaration-name search
  is unchanged.
- A structure of more than 40 entries with three or more top-level entries lists the direct
  members of the entries that span 60 lines or more, the largest first, while the list has room.
  The limits of 80 entries and 2,500 characters are unchanged, and no top-level entry is removed.

**Checked without a model.** The same 441 recorded calls, replayed on `2a7b532a` and on the head
of #547:

| | `2a7b532a` | #547 |
|---|---:|---:|
| Structure lists in the replayed reads | 108 | 112 |
| Lists where a declaration of 60 lines or more shows no members | 40 | 19 |
| Lists where the largest such declaration shows no members | 40 | 1 |
| Lines inside declarations of 60 lines or more that show no members | 49,713 | 17,809 |
| Lines of file text delivered by batch reads | 80,925 | 79,980 |

- 39 structure lists changed and together grew by 63,575 characters.
- A longer list takes room in a batch read, and a batch fills its limit in request order. In 6 of
  133 replayed batch reads the files after such a list were placed differently: 7 files that had
  fit whole came back as structure only, and 3 came back whole instead of structure only.
- 49 of 162 search responses changed, with the same matches shown; in them 134 shown hits gained
  a declaration name. The body shown changed in 13 responses, and in 5 of them it is now a member
  instead of the type around it.
- Responses of the other tools, the catalog and the server instructions are identical.

**Variants measured on the same recorded calls and not taken.**

- *Members only in the room a batch has left after every file is placed.* By the sizes of the
  recorded responses, 29 of the 39 lists would have been expanded; the 10 left unchanged sit in
  the fullest batches, the ones that hold the large files of T3 and T5.
- *Every comment hit counted toward the body shown.* The body changed in 20 responses, and in 7 of
  them it became a declaration whose own lines hold no match, such as the 102-line `cors`
  function for the pattern `c\.json\(`. With the name rule above, 13 changed.
- *A `(+N more)` line under a declaration none of whose members fit.* It appeared in 4 lists and
  said nothing the member count had not said; such a declaration now keeps its count only.

## Lessons

- **A difference seen once in five sessions per task is a hypothesis.** Eight fewer required
  files of 150 disappeared on ten new sessions per task. One path named in every earlier session
  and in 3 of 5 once was noise as well.
- **Set the thresholds before the run and decide on the new sessions only.** Pooled with the
  first series, T3 still reads 58/60 against 56/60; the pooled number repeats the difference that
  prompted the second run and decides nothing.
- **A sentence in a tool description did what the same advice in the server instructions had
  not.** The instructions already said to skip `list_projects` with one root, and the call was
  made 27 times in 80 sessions; with the sentence in the tool's own description it was made 0
  times in 80.
- **Measure the same build twice before choosing a threshold.** Ten sessions per task differed by
  18 calls in one task and by 20 in total with no change. The threshold of 10 calls came from an
  earlier protocol and was crossed by spread alone.
- **A saving in the catalog belongs to its client.** 5,259 characters less gave about 400 tokens
  per call with Codex CLI. With Claude Code the first request of a session is 3,766 tokens larger
  on v5.2.2 than on Repomix, for a tool list 8,701 characters longer and server instructions 640
  characters longer.
- **The two clients use the server differently.** Codex sends several files in four of five
  `get_file` calls and makes about six calls per session. Haiku asks for one file per call and
  makes about seventeen. A change to batch reads measured with Codex says little about Claude.
