# 2026-09-09: review of the ranking and dependency facts

## Why

After the protocol of [2026-09-07](2026-09-07.md), three independent written reviews of the ranking
and `related_files` design were obtained. None of them ran the product; all of them argued from
`Docs/Ranking.md` and the source. Every claim was checked against the code on v5.2 `e056940e`
before anything was accepted.

## What the check confirmed

| Finding | Where in the code | Effect |
|---|---|---|
| The `[Ranking coverage]` line divided deduplicated file pairs by aggregated references | `ImportanceRankingService` | the printed percentage mixed units; the score itself was not affected |
| The `EntryPoint` role could never fire for C# | the predicate looks for a function or module named `Main`; the C# adapter emitted only type declarations | every `Program.cs` ranked as ordinary source |
| Type arguments of generic method calls were not captured in C# | `csharp/references.scm` | `services.AddScoped<IRepo, Repo>()` produced no relation |

## What the check rejected

| Claim in a review | Finding |
|---|---|
| C# generic invocation arguments are already supported | wrong; no capture and no test fixture existed |
| Replace the BFS of `focus-v1` with personalized PageRank | already measured on 2026-09-07: not better |

## Decisions

| Decision | Reason |
|---|---|
| Issue #338: fix the coverage units, add the C# entry-point evidence, capture generic call type arguments | three verified defects |
| Every one of these changes is gated by the frozen `RankingEval` protocol | they change dependency facts, which ranking consumes |
| Larger ideas (typed relation witnesses, rank fusion, whole-response budgets) go to issue #339 for v5.3 | not needed to fix a measured defect |

## What followed

- C# generic-call evidence was validated against the protocol the next day
  ([2026-09-10](2026-09-10.md)).
- The C# entry-point role landed in #367, after a timing gate that turned out to be noise was
  replaced ([2026-09-11](2026-09-11.md)).
