# 2026-11-10: tree depth and package manifests, measured; Codex CLI sessions on the stand

The first series run from `tools/AgentBenchmark` inside the repository, and a new ranking
baseline. On the same day the stand gained Codex CLI arms, and two series were run with them:
three builds on all eighteen tasks, and the change that made `list_projects` optional.

## Why

The analysis of 161 sessions for issue #463 (summarised in the issue) found two concrete causes of
lost calls and missed files on broad tasks:

- `get_tree` counted `max_depth` from the project root, so a request narrowed with `paths`
  returned an empty or collapsed subtree; 65 of 232 tree calls ended that way, and 38 were followed
  at once by another tree call.
- Nothing linked a package entry point to the manifest that publishes it; `jsr.json` was named in 7
  of 13 sessions of the hono "new middleware" task and in 2 of 9 of the "bun adapter contract"
  task.

The fixes went into #533 (issue #529) and #534 (issue #530). This day measured whether they work
on agents, and whether the new subtree listing turned into extra reads, as expanding small folders
did on [2026-11-09](2026-11-09.md).

## Decisions

- **Kept:** #533 and #534. Issues #529 and #530 closed with these numbers.
- **Not done:** extending a ranged read to the end of a cut declaration, and line counts in tree
  listings; both stay out until a measured cause points at them.
- **Kept:** Codex CLI arms (#541), the corrected scoring (#542), the second key versions (#543),

- **Not done:** a list of affected files for D1. The same kind of list put unrelated tests into

- **Left for a later change:** `package.json` in N2, which needs the `Exported by:` line to follow
  `tsconfig` references.

## Lessons

- **Returning what the agent already asked for is not the same as an unrequested list.** The
  expanded small folders of #519 added reads; the requested subtree of #533 removed calls and
  added none.
- **A fact in a response that is always read reaches the answer.** The entry file is read whole in
  every session, and the manifest named in it reached every answer.
- **A number of calls belongs to its client.** Haiku sessions made about 17 calls per session on
  five tasks and Codex sessions about 7. A saving measured with one client has to be measured
  again with the other.
- **Most missed paths are not delivery misses.** 99 of 120 had been shown. Showing them once more
  does not put them into the answer.
- **An opening call that disappears is not the same number of calls saved.** 47 sessions stopped
  calling `list_projects`, and the series ended 27 calls lower.
