# 2026-09-08: first hands-on comparison

**Build:** DevProjex 5.2 branch before the MCP polish round · **Other side:** Repomix in `--mcp` mode
· **Agent:** one blind agent per task

## Setup

A small Node bridge kept both stdio servers running and logged every call: duration, characters
returned, and an estimate of tokens as characters divided by four. Two corpora: Flask `d318b683`
(236 files) and Repomix `85e3969b` (1,189 files). The agent did not know which server was whose,
had a limit of 14 calls per task and could not read the disk directly. Four tasks: where sessions
live in Flask, how Repomix orders files, a Flask overview, and what `pack_codebase` includes.

## Results

| Task | Calls, DevProjex / Repomix | Estimated tokens, DevProjex / Repomix |
|---|---|---|
| T1 Flask sessions | 3 / 3 | 3,362 / 4,395 |
| T2 Repomix sort order | 6 / 6 | 3,606 / 7,151 |
| T3 Flask overview | 6 / 7 | 9,419 / 7,843 |
| T4 `pack_codebase` scope | 7 / 5 | 5,874 / 17,920 |
| **Total** | **22 / 21** | **22.3k / 37.3k** |

All eight answers were correct. The agent said it trusted the DevProjex answer in all four tasks,
because every claim came with `path:line`.

## What the agent pointed at

On our side, in order of impact:

1. `search_project` with `context_lines` printed overlapping context again for each adjacent hit;
   in T1 lines 219 to 225 came back three times and about half the response was duplicate.
2. The `pack_context` description did not list the accepted values of `detail`, `view`, `rank`
   and `focus`, so the agent guessed `signatures`. `max_tokens` limited the content but not the
   report around it, about 600 tokens more than asked.
3. `project` rejected the name that `list_projects` had just returned (`flask`) and wanted the
   full path.
4. The first `related_files` call took 1.6 s cold against 38 ms warm, and its footer used the words
   "supported" and "unsupported" without saying what they meant.
5. `get_file` read one range of one file per call.

On the Repomix side: grep hits came back twice, line numbers pointed into the pack instead of the
file, a broad grep had no result cap (174 hits, 11.8k tokens), and there was no tool to read one
file.

## What came of it

All five points became 5.2 work: merged search windows, value lists in descriptions, project
names accepted, a background-friendly dependency index, and batched `get_file` reads. The list
was later widened into issues #309 to #314.

## Caveat

Tokens here are characters divided by four, measured at the bridge, not what the model actually
processed. The tasks were not equal in work between the two sides: the agent pulled pack content
into its context. The 22.3k / 37.3k total did not survive the paired run two days later (see
[2026-09-10](2026-09-10.md)) and must not be quoted as a cost advantage.
