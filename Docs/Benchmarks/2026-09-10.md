# 2026-09-10: the first blind runs

**Build:** v5.2 tip, then #342 (`22ab97bc`) · **Other side:** Repomix 1.18.0, Serena, the reference
filesystem server, Claude Code built-in tools · **Agent:** a larger Claude model for the
four-server run, Claude Haiku 4.5 for the rest

Four runs on the same day, each answering a question the previous one raised.

## 1. Four anonymous servers

**Setup.** Arms `server_p` (DevProjex), `server_m` (Repomix), `server_t` (Serena without editing
tools) and `server_k` (filesystem server as a control with no helpers). Repositories owned by none
of the vendors: `encode/httpx` 0.28.1 (~8.8k lines) and `honojs/hono` v4.13.7 (~42.8k lines). Six
tasks (bug localization, change impact, feature orientation per repository) with keys taken from
real merged PRs. This run used a larger model than every later one, which is why it ran out of
budget. Headless `claude -p` with `--strict-mcp-config` and no built-in tools.

**Results, httpx T1 to T3, two runs per server, medians:**

| Server | Calls | Tokens | Seconds |
|---|---|---|---|
| DevProjex | 11 | 29.1k | 94 |
| Serena | 14 | 28.4k | 96 |
| Repomix | 13.5 | 42.2k | 117 |
| Filesystem | 15.5 | 88.1k | 166 |

Every server found every core file in every run, so these tasks only told the servers apart on
cost. The run stopped at 29 of 48 sessions when the API credits ran out.

**Two blockers found on our side:**

1. **`get_file` was invisible to Claude Code.** `tools/list` returned eight tools; the client
   registered seven. The `get_file` input schema had a top-level `oneOf` with `not`, added with
   batch reads, and the client dropped the whole tool. All six DevProjex agents complained about a
   "phantom get_file" that the instructions mentioned.
2. **The secret redactor broke ordinary code.** `password=auth[1]` in `httpx/_client.py` came back
   as `password=DEVPROJEX_REDACTED[connection-password#1]` with the rest of the line cut off. Two
   agents named it as the reason they did not fully trust the content.

**Fixed the same day in #342.** The schema now uses a portable subset, and a contract test rejects
`not`, `allOf`, `anyOf`, `if`, `then`, `else`, `dependentSchemas`, `$ref` and `const`. Connection
detection became a region parser that only fires inside a real connection string. A real client
then listed eight tools, and `password=password` came back byte for byte.

## 2. Built-in tools against MCP

**Setup.** Arms: Claude Code with only Read, Grep and Glob; DevProjex after #342; DevProjex before
#342. Tasks T1 and T2 on httpx, T4 and T5 on hono. Turn cap 25. 24 sessions.

| Repository | Core files found, DevProjex / built-in | Tokens, DevProjex / built-in |
|---|---|---|
| httpx (small) | 4/4 / 4/4 | 32.9k / 26.6k |
| hono (large) | 4/4 / 0/4 | 49.3k / cut off 3 times of 4 |

On a small repository, read plus grep is enough and the MCP schema is pure overhead. On a large
one the built-in agent ran out of turns before finding the answer. The #342 fix made hono about
11% cheaper (49.3k / 55.6k before the fix), and `get_file` became the most used tool of the run.

## 3. Paired run against Repomix

**Setup.** The pilot format: one agent gets both servers as `server_a` (DevProjex) and `server_b`
(Repomix), solves the same task twice, once with each, finding the facts again in each phase.
Tokens as characters divided by four.

| Task | Calls, DevProjex / Repomix | Tokens, DevProjex / Repomix |
|---|---|---|
| T1 httpx | 7 / 7 | 3,558 / 4,043 |
| T2 httpx | 14 / 11 | 10,108 / 7,336 |
| T4 hono | 21 / 9 | 16,688 / 13,986 |
| T5 hono | 19 / 10 | 26,517 / 14,832 |
| **Total** | **61 / 37** | **56,871 / 40,197** |

Correctness was identical. The keep verdict split 2 to 2.

**This overturned the pilot.** Under equal work, Repomix's pack-once-then-grep model is cheaper on
broad exploration, because the pack stays on disk and only the greps enter the context. The agents
still *said* Repomix made them read more, because `pack_codebase` announces a huge token figure
that never reaches the context. Perception and measurement disagreed; the measurement is the one
to quote.

## 4. Head-to-head duel

One agent with both servers in one session chose which to keep, in both orders, four tasks, eight
runs. **It kept DevProjex in 8 of 8**, median trust 5/5 against 4/5. The reasons were attribution
by real `path:line` and targeted reads instead of a whole-repository pack. This is a preference
signal, not an economy one: the agent did most of the work through DevProjex (median 16 calls
against 4), so the Repomix numbers mean it was barely used.

## A free, repeatable probe

`protocol.mjs` sends the same questions straight over the protocol, with no model. Characters
returned, DevProjex / Serena / Repomix: every occurrence of a symbol 885 / 1,257 / 3,692; one file
range 1,126 / 1,895 / not possible (the Repomix range addresses the pack, and lines 546 to 566 of
`_client.py` returned `FUNDING.yml`); project layout 1,985 / 10,863 / only inside the pack.

## Kept

- #342: portable schema with a contract test, and connection detection as a region parser.

## Lessons

- A schema keyword the client does not support can remove a tool without any error.
- Say "keeps the agent inside its budget on a large repository", never "cheaper than a normal
  agent": on a small repository it is not.
- Our real weakness was the number of calls: 61 / 37 for the same work.
