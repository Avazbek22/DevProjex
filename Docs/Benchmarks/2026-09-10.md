# 2026-09-10: first blind runs

Four runs on the same day, each answering a question raised by the previous one.

## Why

The pilot of [2026-09-08](2026-09-08.md) had one agent and both servers in one session. The next
step was the format used for every later series: headless sessions, one server per session,
anonymous server names, repositories owned by no vendor, and keys taken from real merged PRs.

## 1. Four servers, one per session

**Setup.** Arms `server_p` (DevProjex before #342), `server_m` (Repomix), `server_t` (Serena),
`server_k` (Filesystem). Two sessions per task and server. This run used a larger Claude model
than every later run and stopped at 29 of 48 sessions when the API budget ran out.

**Results, httpx T1 to T3, medians per session:**

| Server | Calls | Tokens | Seconds |
|---|---:|---:|---:|
| DevProjex before #342 | 11 | 29,100 | 94 |
| Serena | 14 | 28,400 | 96 |
| Repomix 1.18.0 | 13.5 | 42,200 | 117 |
| Filesystem | 15.5 | 88,100 | 166 |

Every server found every core file in every session, so these tasks separated the servers on
cost only.

**Two defects found in DevProjex:**

1. **`get_file` was not registered by Claude Code.** `tools/list` returned eight tools; the client
   registered seven. The `get_file` input schema had a top-level `oneOf` containing `not`, added
   with batched reads in #331, and the client silently dropped the whole tool. All six DevProjex
   agents complained about a `get_file` that the instructions mentioned but they could not call.
2. **The secret redactor rewrote ordinary code.** `password=auth[1]` in `httpx/_client.py` came
   back as `password=DEVPROJEX_REDACTED[connection-password#1]` with the rest of the line cut off,
   which made the code syntactically wrong. Two agents named it as their reason not to trust the
   content fully.

**Fixed the same day in #342.** The schema uses a portable subset of JSON Schema, and a contract
test rejects `not`, `allOf`, `anyOf`, `if`, `then`, `else`, `dependentSchemas`, `$ref` and `const`.
Connection detection became a region parser that fires only inside a real connection string;
`StructuredRulesVersion` went from v5 to v6 so that cached scans are recomputed. Checked through a
real Claude Code client: eight tools registered, and
`return BasicAuth(username=username, password=password)` comes back unchanged.

| Repository | Arm | Core files | Tokens | Cut off at 25 turns |
|---|---|---:|---:|---:|
| httpx | DevProjex #342 | 4/4 | 32,900 | 0 |
| httpx | Built-in | 4/4 | 26,600 | 0 |

| hono | DevProjex before #342 | 4/4 | 55,600 | 0 |

On a small repository, read plus grep was enough and the MCP schema was pure overhead. On a large

the most used tool of the run (62 calls, against 61 for `search_project`).

## 3. Paired run against Repomix

**Setup.** One agent receives both servers, DevProjex #342 as `server_a` and Repomix 1.18.0 as
`server_b`, and solves the same task twice: first with `server_a` only, then with `server_b`
only, finding the facts again in the second phase. Tokens estimated as characters divided by four.

| Task | DevProjex calls | Repomix calls | DevProjex tokens | Repomix tokens |
|---|---:|---:|---:|---:|
| T1 httpx | 7 | 7 | 3,558 | 4,043 |
| T2 httpx | 14 | 11 | 10,108 | 7,336 |
| T4 hono | 21 | 9 | 16,688 | 13,986 |
| T5 hono | 19 | 10 | 26,517 | 14,832 |
| **Total** | **61** | **37** | **56,871** | **40,197** |

Core files were identical in both phases of every task. The agent's keep verdict split 2 to 2.

**This result overturned the pilot of 8 September.** With equal work, the pack-then-grep model of
Repomix is cheaper on broad exploration, because the pack stays on disk and only greps and reads
enter the context. The agents nevertheless *said* that Repomix made them read more, because
`pack_codebase` reports a large token figure (744,000 on hono) that never enters the context.
Where perception and measurement disagree, the measurement is quoted.

## 4. Head-to-head preference

**Setup.** One agent with both servers in one session chooses which one it would keep. Four
tasks, both orders, eight sessions.

| Metric | DevProjex #342 | Repomix 1.18.0 |
|---|---:|---:|
| Kept | 8 | 0 |
| Median trust score | 5/5 | 4/5 |
| Median calls | 16 | 4 |

The reasons given were `path:line` attribution and targeted reads instead of a packed repository.
This is a preference result only: the agent did most of the work through DevProjex, so the low
Repomix numbers mean it was barely used.

## Ranking gate on the same day: C# generic-call evidence

The fix from the review of [2026-09-09](2026-09-09.md) added type arguments of C# generic method

and gates unchanged:

Kept: the change shows no slowdown outside the run-to-run spread. Full tables are in
[Ranking.md](../Ranking.md).

## Decisions

- **Kept:** #342 and the C# generic-call evidence.
- **Wording rule:** describe DevProjex as keeping the agent within its budget on a large
  repository, not as cheaper than an agent with built-in tools; on a small repository it is not.
