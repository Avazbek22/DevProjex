## 5. The ruler was wrong

The judge had produced 1,081 complaints on answers. Sorting them showed three large groups:

- 230 "a required file is missing": often the agent had seen the file and dropped it, as in T5
  where `bearer-auth` and `cors` appeared in every search but not in the answer;
- 226 "cannot verify a line number or detail": the judge does not see the code and punishes
  precision;
- 217 "an extra file not in the key": part of them were right and the key was incomplete.

**Key audit**, every key checked against the code:

- T5 listed `bearer-auth` and `cors` as `c.json` callers; they only mention it in doc comments.
- N1 listed `test_config.py` and `test_api.py`; they do not read the changed defaults.
- T8 missed three test implementations of the interface and `LogContext.cs`.
- D1 missed `cloudflare-pages/handler.ts` and five tests.

**New ruler.** Keys gained `acceptable` and `unrelated` lists. Judge v3 counts as an error only a
contradiction with the key, never an unverifiable detail, and the same rule applies to both sides.
An objective score against the key (required files, required tests, known-wrong files, calls,
tokens) became the main metric, with the judge as a second opinion. Rejudging cost about $3 to $5
and no new sessions.

| Comparison, corrected judge | Correctness | Order-dependent |
|---|---|---|
| v5.2.2 / Repomix, 42 pairs | 30 / 6 (was 36 / 3) | 5, and 1 tie |
| v5.2.2 / master, 42 pairs | 17 / 12 (was 15 / 11) | 10, and 3 ties |
| Rename / base, 12 pairs | 1 / 7 | 4 |
| Change focus / base, 12 pairs | 5 / 6 | 1 |

Complaints on our answers fell from 179 to 105, on Repomix's from 244 to 216. About 40% of the
complaints against us had been artifacts of the ruler, and it had hit our answers harder than the
other side's.

| Four tasks, corrected keys | Required files | Required tests | Known-wrong files |
|---|---|---|---|
| Base | 36/60 | 25/39 | 32 |
| Rename | 45/60 | 33/39 | 49 |
| Change focus | 46/60 | 34/39 | 46 |

The more often the agent calls the dependency tool, the more required files it finds and the more
wrong ones it copies. The judge nets that as no gain.

**Judge noise.** In one round D1, N2 and T5 behaved the same in both builds and the judge still gave
6 to 1. **Rule:** a decision is never taken on judge votes alone; an objective metric has to move by
more than the spread of identical code.

## 7. Fixes from the real complaints (#509 to #513)

- **#509** keeps declarations outside a damaged syntax construct. TypeScript call-signature
  overloads without `;` in an interface had broken the parse of the whole `src/types.ts`; the file
  now yields 50 dependency and 97 navigation declarations. The first version was rejected by its own
  gate: cold indexing of hono 895 → 1,124 ms. The gate had been set to "no slower at all", for a
  one-time cost per project against three to five extra searches per session. With a threshold of
  +10% cold, the damage search was made 50 times cheaper (239 → 4.5 ms) and cold indexing ended at
  866 → 839 ms. RankingEval: 0 of 270 cells changed.
- **#510** normalizes MCP responses to LF.
- **#511** shows the signature head instead of a cut fragment for a long declaration body.
- **#512** matches multi-line patterns in `search_project`. Before, `\n` or `[\s\S]` in a pattern
  silently returned nothing.
- **#513** adds an `Imports:` line to `get_file` with the project files the imports resolve to, and
  reads the module file when a missing path names one.

## Lessons

- **Any list becomes a to-do list.** Affected-file sections and dependent lists raise recall and
  precision errors together.
- **Hints for a different call form are not followed.** 0 of 54.
- **Name moves the probe, not the answer.** Count use in full sessions, not in the first ten calls.
- **A gate that forbids any slowdown rejects real wins.** State the threshold against what the
  user pays, and measure it as a median of alternating runs.
- **Audit the keys before believing a judge.**
