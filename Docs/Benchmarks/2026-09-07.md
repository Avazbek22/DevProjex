## 1. CLI cold scan against Repomix

**Why.** Before agent sessions were measured, the basic question was how long a full scan takes
and how much memory it needs, with both tools following `.gitignore` and checking for secrets.

| Corpus | DevProjex ms | Repomix ms | DevProjex peak RSS | Repomix peak RSS |
|---|---:|---:|---:|---:|
| Flask | 2,805 | 548 | 106.6 MiB | 291.4 MiB |
| Godot | 62,445 | 8,269 | 1,037.6 MiB | 3,478.0 MiB |

Each cell is the median of three runs. The two tools select different file sets, so this is not an
identical-workload ranking; the commands and both series are in [Benchmarks.md](../Benchmarks.md).

**What it led to.** The content pipeline was rebuilt, starting from `c249c309`. On the same pinned
inputs the cold medians
of `export context` became 1,092 ms for Flask and 10,391 ms for Godot: 3.25 times faster on Godot,
short of the 4 times that was the target. Peak memory on Godot did not improve, because the peak comes from
detector and runtime churn, not from retained text.

## 2. Ranking: does global importance assemble a task's files?

**Why.** The dependency engine (spike #293: in a manual review of 60 relationships, 54 correct, 5 wrong,
1 disputed, none pointing at a false file; engine #295; `rank: importance` in #296) was designed on 6 September as one graph for
three consumers: the GUI panel, `related_files` and ranking. One rule of that design was that
ranking weights are chosen only after a frozen protocol. The protocol was written before the first
run: 3 repositories × 5 tasks, budgets of 4,000, 8,000 and 16,000 estimated tokens, sufficient file
sets written by reading call sites, and gold paths never used in a query or a score.

**Localization series**, mean recall over the nine repository and budget groups:

| Order | Mean recall | Complete sufficient sets admitted |
|---|---:|---:|
| Combined `importance-v1` (graph 0.85, Git 0.10, role 0.05) | 0.0111 | 0 |
| Git activity only | 0.0444 | 0 |
| PageRank only | 0.0519 | 0 |
| Directed: search, then `related_files`, then pack those paths | 0.1889 | 2 of 2 feasible Flask sets at 16,000 |

**Missing-signal policy**, same weights:

| Policy | Mean recall | Problem |
|---|---:|---|
| Renormalize the available weights | 0.0333 | a manifest with only its role signal scored 1.0, above a strongly linked file |
| Fill missing signals with 0.5 | 0.0111 | manufactures evidence |
| Limit the score by available confidence | 0.0111 | none; chosen |

**Decisions:**

| Decision | Reason |
|---|---|
| Ranking ships as experimental, as a seedless overview order | global importance rewards broadly connected infrastructure, while a task needs a narrow slice; it admitted no complete set |
| The recommended agent workflow is `search_project` → `related_files` → `pack_context(paths)` | the directed order had the best recall and the only complete sets |
| Missing signals limit the score instead of being renormalized | renormalization's 0.0222 recall advantage came from the same defect that put a manifest above linked code |

## 3. Ranking around a known file: `focus-v1`

**Why.** If a task has a known starting file, the graph could order its neighbourhood. The seeds,
comparators and gates were committed in `2780a547` before the first successful run. The gates:
higher RecallNew than seed-first with no lost complete set, a warm addition below
`max(5%, 100 ms)`, and peak memory growth below 10%.

| Result over the 15 eligible task-budget cells | Value |
|---|---:|
| Mean RecallNew, `focus-v1` minus seed-first | +0.3333 |
| By repository: DevProjex, Repomix, Flask | +0.1000, +0.3889, +1.0000 |
| Complete sets lost against seed-first | 0 |
| Warm cost added (rerun on 2026-09-09, `9c25fd17`) | DevProjex +36.23 ms, Repomix +67.92 ms, Flask +8.08 ms |
| Peak memory growth | 0.17% to 0.63% |

All gates passed. `focus-v1` and the directed workflow had the same recall and the same complete
sets in all nine groups, and the directed workflow spent less of its budget on unrelated files in
every group.

**Decisions:**

| Decision | Reason |
|---|---|
| `focus` ships as experimental | all pre-registered gates passed |
| It is described as automating the directed workflow in one call, not as a better order | it never beat the directed workflow |
| Personalized PageRank stays in the evaluator only | it was not better than the minimum-hop BFS |
