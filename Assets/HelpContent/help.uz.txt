## 1) Nima va nima uchun
DevProjex loyiha kontekstini tez tayyorlaydi: papka/fayl tuzilmasini ko‘rsatadi, elementlarni belgilash va daraxtni va/yoki fayl mazmunini buferga nusxalash imkonini beradi. Code review, qo‘llab‑quvvatlash, o‘qitish va loyiha tuzilmasini AI‑yordamchiga berish uchun qulay.

Muhim: ilova faqat o‘qish rejimida ishlaydi va fayllarni o‘zgartirmaydi.

## 2) Loyiha daraxti
* Fayl/papka ikonkalari.
* Tugunlardagi checkboxlar.
* Ochish/yopish.

Checkboxlar: tugunni belgilash uning avlodlariga qo‘llanadi; ota holati avtomatik qayta hisoblanadi.

Issiq tugmalar:
* Ctrl+E — hammasini ochish
* Ctrl+W — hammasini yopish (ildiz ochiq qoladi)

## 3) Fayl
* Jildni ochish… — ildiz papkani ochish (Ctrl+O)
* Yangi oyna — DevProjex’ning yangi mustaqil nusxasini ochish
* So‘nggilar — yaqinda ochilgan lokal jildlar ro‘yxati
* Yangilash — lokal jildni qayta o‘qish va daraxtni qayta qurish (F5)
* Faylga eksport:
  * Daraxtni eksport qilish
  * Mazmunni eksport qilish
  * Daraxt va mazmunni eksport qilish

Format qoidalari:
* Daraxtni eksport qilish:
  * ASCII -> faqat `.txt`.
  * JSON -> standart `.json`, saqlash oynasida `.json` va `.txt` mavjud.
  * XML -> standart `.xml`, saqlash oynasida `.xml` va `.txt` mavjud.
  * MD -> standart `.md`, saqlash oynasida `.md` va `.txt` mavjud.
* Mazmunni eksport qilish — har doim mazmunning matn formati, `.txt` fayl (daraxt formati tumbleri ta’sir qilmaydi).
* Daraxt va mazmunni eksport qilish — har doim `.txt` fayl; tanlangan daraxt formati faqat natijadagi daraxt blokining formatiga ta’sir qiladi.

Eksport fayllari UTF-8 (BOMsiz) formatida yoziladi.

### Drag & Drop
Drag & Drop loyiha yuklanmagan holatda boshlang‘ich maydonda (Drop Zone) ishlaydi.

Qoidalar:
* papkani tashlash mumkin;
* faylni tashlash mumkin — bu holda fayl joylashgan papka ochiladi;
* bir nechta obyekt tashlansa, birinchi mos lokal yo‘l ishlatiladi;
* yo‘l mavjud bo‘lmasa yoki kirish bo‘lmasa, «Jildni ochish…» dagi kabi bir xil kirish tekshiruvlari qo‘llanadi;
* qo‘llab-quvvatlanmaydigan yoki lokal bo‘lmagan obyektlar e’tiborga olinmaydi.

### So‘nggilar
“Fayl → So‘nggilar” bandi yaqinda ochilgan lokal jildlar tarixini ko‘rsatadi.

Qoidalar:
* ro‘yxatga faqat lokal jildlar qo‘shiladi;
* DevProjex orqali klonlangan Git repozitoriylari bu ro‘yxatga qo‘shilmaydi;
* dublikatlar yaratilmaydi — bir xil jildni qayta ochish uni ro‘yxatning yuqorisiga olib chiqadi;
* 15 tagacha so‘nggi jild saqlanadi;
* tarix ilova qayta ishga tushirilganda ham saqlanadi.

Har bir elementda yuqori jild va loyiha nomi ko‘rsatiladi, masalan `Projects / App`.

## 4) Terminaldan ishga tushirish
DevProjex-ni terminaldan ishga tushirish mumkin.

Agar buyruq allaqachon sozlangan bo‘lsa, terminalni ochib bajaring:
`devprojex --help`

Shunda barcha mavjud buyruqlar, parametrlar va misollarni ko‘rasiz.

Misollar:
* `devprojex .` — joriy papkani ochish.
* `devprojex "C:\Projects\App"` — ko‘rsatilgan papkani ochish.
* `devprojex . --export tree` — loyiha daraxtini terminalga chiqarish.
* `devprojex . --export content` — fayllar mazmunini terminalga chiqarish.
* `devprojex . --export tree-content` — daraxt va mazmunni terminalga chiqarish.
* `devprojex . --export tree-content -o context.txt` — natijani faylga saqlash.
* `devprojex --benchmark "C:\Projects\App"` — standart loyiha hisoboti workflow’ini o‘lchash.
* `devprojex --last --preview` — oxirgi loyihani darhol preview rejimida ochish.
* `devprojex --benchmark-ui "C:\Projects\App"` — standart UI ssenariysini o‘lchash.
* `devprojex --session-metrics "C:\Projects\App"` — oyna yopilguncha UI sessiyasi metrikalarini yozib borish.

Xususiyatlar:
* `.` terminaldagi joriy papkani bildiradi;
* bo‘sh joyli yo‘llar qo‘shtirnoqqa olinishi kerak;
* chiqish fayli ko‘rsatilmasa, natija bevosita terminalga chiqariladi;
* buyruq loyiha fayllarini o‘zgartirmaydi — DevProjex read-only rejimida ishlaydi.

Agar `devprojex` buyrug‘i ishlamasa, DevProjex ichida oching:
«Yordam → Terminaldan ishga tushirish».

## 5) Git
Git menyusi faqat DevProjex orqali klonlangan loyihalarda mavjud (Git Clone). Ilova fayllaringizga tegmaydi — faqat kesh bilan ishlaydi.

Kesh tizimning vaqtinchalik papkasida saqlanadi. Windows’da odatda:
`%TEMP%\DevProjex\RepoCache`

* Tarmoq — mavjud tarmoqlar ro‘yxatini faol tarmoq belgisi bilan ko‘rsatadi; almashganda daraxt tanlangan tarmoqqa yangilanadi. Agar tarmoq allaqachon lokal bo‘lsa, almashish tarmoqsiz (yangilanishsiz) bo‘ladi. Agar tarmoq lokalda bo‘lmasa, u fetch orqali yuklanib, lokal yaratiladi.
* Yangilanishlarni olish — faqat joriy tarmoqni yangilaydi: fetch va origin/<tarmoq> ga reset. Git Clone loyihasida F5 xuddi shu amalni bajaradi; odatiy «Fayl → Yangilash» buyrug‘i o‘chirilgan bo‘ladi.

### Klonlash oynasi
Git Clone oynasida URL maydoni ostida “So‘nggi repozitoriylar” ro‘yxati ko‘rsatilishi mumkin.

Qoidalar:
* ro‘yxat faqat tarixda yaqinda klonlangan repozitoriylar bo‘lsa paydo bo‘ladi;
* ro‘yxatga faqat repozitoriy URL manzillari qo‘shiladi;
* lokal jildlar bu ro‘yxatga qo‘shilmaydi;
* dublikatlar yaratilmaydi — bir xil repozitoriyani qayta klonlash uni ro‘yxatning yuqorisiga olib chiqadi;
* 7 tagacha so‘nggi repozitoriy saqlanadi;
* tarix ilova qayta ishga tushirilganda ham saqlanadi.

Ro‘yxatdan element tanlansa, URL avtomatik ravishda kiritish maydoniga qo‘yiladi.
Faol klonlash vaqtida ro‘yxat vaqtincha yashiriladi.

## 6) Nusxa
### Daraxt formati tumbleri (ASCII / JSON / XML / MD)
Tumbler natijada daraxt ishtirok etadigan amallar uchun daraxt ko‘rinishi formatini belgilaydi.

* ASCII — shoxlari bor matnli daraxt.
* JSON — JSON formatidagi strukturali daraxt.
* XML — parserlar va vositalar uchun ixcham XML daraxt.
* MD — hujjatlar va AI promptlar uchun ichma-ich Markdown ro‘yxat.

Tumbler quyidagilarga ta’sir qiladi:
* Daraxtni nusxalash
* Daraxt + mazmunni nusxalash
* Daraxtni eksport qilish
* Daraxt va mazmunni eksport qilish

Tumbler quyidagilarga ta’sir qilmaydi:
* Mazmunni nusxalash
* Mazmunni eksport qilish

### Daraxtni nusxalash
Loyiha daraxtini nusxalaydi.
Agar belgilangan tugunlar bo‘lsa, daraxt tanlov bo‘yicha quriladi; tanlov bo‘sh yoki yaroqsiz bo‘lsa, to‘liq daraxt nusxalanadi.
Natija formati daraxt formati tumbleri bilan aniqlanadi.
Tugmalar: Ctrl+Shift+C va Ctrl+Alt+C.

### Mazmunni nusxalash
Fayllar mazmunini nusxalaydi:
* agar fayllar belgilangan bo‘lsa — faqat ular; aks holda — loyihadagi barcha fayllar;
* matnli bo‘lmagan fayllar e’tiborga olinmaydi (binarlarni ham);
* bo‘sh matnli fayllar uchun yo‘l va `[No Content, 0 bytes]` yoziladi;
* faqat bo‘sh joylar/satr uzilishlaridan iborat fayllar uchun yo‘l va `[Whitespace, N bytes]` yoziladi.
Tugma: Ctrl+Alt+V.

### Daraxt + mazmunni nusxalash
Daraxt va mazmunni birlashtiradi:
* daraxt tanlov bo‘yicha; agar tanlov bo‘sh yoki yaroqsiz bo‘lsa — to‘liq daraxt;
* mazmun «Mazmunni nusxalash» qoidalari bo‘yicha;
* daraxt blokining formati daraxt formati tumbleri bilan aniqlanadi.
Tugma: Ctrl+Shift+V.

### Daraxt ko‘rinishlari
Daraxt formatlari bir xil tanlangan loyiha daraxtini turlicha ko‘rsatadi.

JSON:
* `rootPath` — `/` orqali normallashtirilgan absolyut ildiz yo‘li.
* `tree` — ildiz papkaning mazmuni.
* JSON eksport shu daraxt formatidan foydalanadi: massivlar fayllarni, obyektlar ichki papkalarni, `/` joriy papkadagi fayllarni saqlaydi, `[]` esa bo‘sh papkani bildiradi.

XML:
* ildiz tugun — `<t r="...">`;
* papkalar — `<d n="...">`;
* fayllar — `<f>File.cs</f>`.

MD:
* `Root: ...` bilan boshlanadi;
* ichma-ich Markdown ro‘yxatidan foydalanadi;
* papkalar `/` bilan tugaydi.

Daraxt + mazmun:
* tanlangan daraxt formati daraxt blokiga qo‘llanadi;
* mazmun bloki matn bo‘lib qoladi;
* mazmun blokidagi fayl sarlavhalari `/` orqali relative yo‘llardan foydalanadi;
* eksport `.txt` formatida saqlanadi.

## 7) Preview rejimi
Yuqori paneldagi ko‘zcha ikonali tugma yoki Ctrl+B orqali ochiladi.

Yakuniy natijani daraxt yonidagi alohida ishchi hududda ko‘rsatadi. Bu rejim o‘zi hech narsani clipboardga nusxalamaydi va faylga eksport qilmaydi — u faqat ko‘rish uchun xizmat qiladi.

Standart holatda ishchi hudud quyidagicha ochiladi:
* chapda — loyiha daraxti;
* markazda — preview oroli;
* o‘ngda — agar ochiq bo‘lsa, sozlamalar paneli.

Mavjud rejimlar:
* Daraxt
* Mazmun
* Daraxt va mazmun

Nusxalash va eksportdagi qoidalar shu yerda ham qo‘llanadi:
* belgilangan tugunlar hisobga olinadi;
* tanlov bo‘sh bo‘lsa, to‘liq ma’lumotlar to‘plami ishlatiladi;
* joriy ignore qoidalari va tanlov parametrlari qo‘llanadi.

Qo‘shimcha:
* preview ichida fayllar gorizontal chiziqlar bilan ajratiladi;
* skroll paytida joriy fayl yo‘li tepada mahkamlanadi;
* daraxt va preview masshtabi alohida yashashi mumkin.
* preview rejimida “Nusxa” menyusiga kirmasdan turib to‘liq joriy natijani ham, joriy ko‘rinib turgan fayl blokini ham nusxalash mumkin.

Tugmalar:
* yuqori preview orolining chap tomonidagi nusxa tugmasi — joriy preview rejimini nusxalaydi:
  * Daraxt
  * Mazmun
  * Daraxt va mazmun
* daraxt orolidagi X — daraxtni yashiradi va faqat preview orolini qoldiradi;
* preview’ning yuqori orolidagi X — preview rejimini to‘liq yopadi;
* faylning mahkamlangan yuqori sarlavhasidagi kichik nusxa tugmasi — joriy ko‘rinib turgan fayl blokini previewda ko‘rsatilgan holatda nusxalaydi;
* ko‘zcha ikonani yana bir marta bosish yoki Ctrl+B ham preview rejimini yopadi.

Qidiruv va filtr preview ichida daraxt oroli ko‘rinib turgan paytda ishlaydi.
Agar daraxt yashirilsa, qidiruv va filtr preview-only rejimidan chiqquncha vaqtincha ishlamaydi.

## 9) Daraxt bo'yicha qidiruv
Qidiruv panelini ochadi, mosliklarni yoritadi va navigatsiya qiladi.

* Enter — keyingi
* Shift+Enter — oldingi
* Esc — yopish

Qidiruv faqat kerakli shoxlarni ochadi; so‘rov tozalansa, daraxt yig‘iladi (ildizdan tashqari).
Mosliklar soni juda ko‘p bo‘lsa, interfeys tezkorligini saqlash uchun ilova avtomatik ochish va ommaviy yoritishni cheklashi mumkin.
Qidiruv paneli yopilganda, yopilish animatsiyasi tugagach so‘rov tozalanadi.

Cheklovlar:

* qidiruv preview ichida daraxt oroli ko‘rinib turgan paytda mavjud;
* daraxt yashirilsa, qidiruv vaqtincha mavjud emas.

Cheklovlar:
* filtr ochilganda, qidiruv avtomatik yopiladi;
* filtr preview ichida daraxt oroli ko‘rinib turgan paytda mavjud;

## 11) Sozlamalar
O‘ng tomonda mavjud:
* Sozlamalarni qo‘llash
* E’tiborsiz qoldirish
* Fayl turlari
* Yuqori darajadagi jildlar

«E’tiborsiz qoldirish», «Fayl turlari» va «Yuqori darajadagi jildlar» o‘zgarishlari panelda tayyorlanadi va «Sozlamalarni qo‘llash» bosilgandan keyin qo‘llanadi.

Belgilash katagi o‘zgargandan keyin ilova mavjud bandlar va ularning hisoblagichlarini fonda yangilashi mumkin. Yakuniy daraxt faqat «Sozlamalarni qo‘llash» bosilgandan keyin qayta quriladi.

Mavjud parametrlarni yangilash status-bardagi X tugmasi bilan bekor qilinsa, tugallanmagan o‘zgarishlar qo‘llanmaydi va panel oxirgi yakunlangan holatiga qaytadi.

Har bir ro‘yxatda Barchasi tugmasi bor.

«Fayl turlari» bo‘yicha izoh:
* bu ro‘yxatda faqat kengaytmali fayllar ko‘rsatiladi;
* kengaytmasiz fayllar bu ro‘yxatga qo‘shilmaydi va «E’tiborsiz qoldirish» ichidagi alohida band orqali boshqariladi.

Ctrl+P — panelni ko‘rsatish/yashirish.

### 11.1 Mahalliy loyiha parametr profillari
Mahalliy jildlar uchun DevProjex loyihaning oxirgi qo‘llangan parametrlarini eslab qoladi:
* tanlangan yuqori darajadagi jildlar;
* tanlangan fayl turlari;
* «E’tiborsiz qoldirish» blokidagi tanlangan qoidalar.

Saqlash «Sozlamalarni qo‘llash» tugmasi bosilganda bajariladi.
Xuddi shu mahalliy jild qayta ochilganda parametrlar avtomatik tiklanadi.

Muhim:
* profillar faqat mahalliy loyihalar uchun saqlanadi;
* Git Clone orqali ochilgan loyihalar uchun profillar saqlanmaydi;
* agar joriy loyihada saqlangan ayrim bandlar endi mavjud bo‘lmasa, ular o‘tkazib yuboriladi, qolgan parametrlar qo‘llanadi.
* yangilash yoki qayta ochishdan keyin yangi yuqori darajadagi jild, yangi fayl turi yoki «E’tiborsiz qoldirish» ichida yangi band paydo bo‘lsa, u odatda yoqilgan bo‘ladi;
* avvaldan ma’lum bandlar foydalanuvchining aniq tanlovini saqlaydi: o‘chirilgan turdagi yangi fayllar bu turni qayta yoqmaydi.

## 12) Ignorlash
«Ignorlash» bloki daraxt, kontent, nusxalash va eksportdan qaysi fayl hamda papkalar chiqarilishini boshqaradi.

Element faqat uning yuqori darajadagi papkasi va fayl turi tanlangan, shuningdek hech bir faol qoida uni yashirmagan bo‘lsa ko‘rsatiladi. Qoidalar birgalikda ishlaydi: kamida bittasi elementni yashirsa, boshqa qoida uni ko‘rsata olmaydi.

### 12.1 Mavjud qoidalar
Loyiha mazmuniga qarab Smart Ignore, «.gitignore dan foydalanish», bo‘sh, yashirin yoki nuqta bilan boshlanuvchi papka va fayllar hamda kengaytmasiz fayllar ko‘rsatilishi mumkin.

Band joriy daraxtni o‘zgartira olganda paydo bo‘ladi. Shu sababli boshqa qoida, yuqori darajadagi papka yoki fayl turi almashtirilganda ro‘yxat o‘zgarishi mumkin. Yangi band birinchi paydo bo‘lganda odatda yoqiladi; avvaldan ma’lum band vaqtincha yo‘qolsa ham foydalanuvchi tanlovini saqlaydi.

### 12.2 Smart Ignore
Smart Ignore bog‘liqliklar, build natijalari, keshlar va boshqa xizmat artefaktlarini yashiradi. DevProjex loyiha turini tuzilma va `.csproj`, `package.json`, `pyproject.toml`, `Cargo.toml` kabi marker fayllar orqali aniqlaydi. Tegishli stek qoidalari faqat topilgan loyiha hududida ishlaydi va qo‘shni boshqa stek loyihasiga yoyilmaydi.

`build`, `vendor`, `packages`, `cache`, `pkg`, `Library` kabi noaniq nomlarda papka mazmuni ham tekshiriladi. Oddiy foydalanuvchi papkasi faqat nomi sababli yashirilmaydi. Ayrim bog‘liqlik omborlari va xizmat papkalari aniq topilgan loyihadan tashqarida ham ichki tuzilishi orqali tanilishi mumkin.

Katta foydalanuvchi papkasidagi har bir katalogni qayta tahlil qilmaslik uchun yangi loyiha hududlarini izlash cheklangan. Oddiy tuzilma sayoz, tanilgan monorepo esa chuqurroq tekshiriladi. Hudud topilgach, Smart Ignore uning butun ichki daraxtiga chuqurlik cheklovisiz qo‘llanadi.

### 12.3 .gitignore dan foydalanish
Yoqilganda DevProjex faqat root faylini emas, barcha yetib boriladigan `.gitignore` fayllarini qo‘llaydi. Har bir fayl o‘z papkasi va uning barcha ochiq ichki papkalariga ta’sir qiladi, lekin ota yoki qo‘shni papkalarga emas.

Muayyan yo‘l uchun qoidalar ota `.gitignore` faylidan chuqurroq fayllarga, bitta fayl ichida esa yuqoridan pastga qarab ishlanadi. Oxirgi mos qoida Git natijasini belgilaydi.

`!` bilan boshlangan qoida faqat o‘z hududidagi oldingi Git istisnosini bekor qiladi. Ota papka hali ham chiqarilgan bo‘lsa, faylni qaytara olmaydi. To‘liq chiqarilgan va yetib bo‘lmaydigan papka ichidagi `.gitignore` ishlanmaydi.

Buzilgan yoki qo‘llanmaydigan satr alohida o‘tkazib yuboriladi, qolgan to‘g‘ri qoidalar ishlashda davom etadi. Bu band faqat ishchi daraxtdagi `.gitignore` fayllariga tegishli; `.git/info/exclude`, global Git qoidalari va Git index holati qo‘llanmaydi.

### 12.4 .gitignore va Smart Ignore aloqasi
Bitta hudud va o‘z `.gitignore` fayliga ega loyihada interfeys odatda faqat «.gitignore dan foydalanish» bandini ko‘rsatadi. Bu rejimda u `.gitignore` va mos Smart Ignore qoidalarini birga yoqadi. Bir nechta loyihali ish jildida ikkala band alohida ko‘rinib, o‘z hududlarida mustaqil ishlashi mumkin.

`!` Git inkori faqat Git natijasini bekor qiladi; Smart Ignore yoki asosiy qoidani yengmaydi. Umumiy «kuchliroq» qoida yo‘q: element ko‘rinishi uchun barcha faol mexanizmlardan o‘tishi kerak.

### 12.5 Asosiy qoidalar
Nuqta bilan boshlanish qoidalari nomni, yashirin element qoidalari esa tizimdagi Hidden atributini tekshiradi. Platformaga qarab ular bir xil yoki turli elementlarga tegishli bo‘lishi mumkin.

«Bo‘sh fayllar» 0 baytli fayllarni, «Kengaytmasiz fayllar» esa `Dockerfile`, `Makefile`, `README` kabi fayllarni yashiradi.

«Bo‘sh papkalar» mantiqan bo‘sh papkalarni yashiradi. Tanlangan fayl turlari va barcha boshqa qoidalar qo‘llangach ko‘rinadigan fayl yoki ichki papka qolmasa, papka mantiqan bo‘sh hisoblanadi. Shu sababli boshqa qoida o‘zgarganda uning hisoblagichi ham o‘zgarishi mumkin.

### 12.6 Hisoblagichlar
Hisoblagich diskdagi fizik sonni emas, joriy sozlamalarda qoidaning bevosita hissasini ko‘rsatadi. Bir element bir vaqtning o‘zida bir nechta ustma-ust hisoblagichga yozilmaydi.

Barqaror tartib: papkalar uchun `.gitignore`, Smart Ignore, nomdagi nuqta, Hidden atributi; fayllar uchun `.gitignore`, Smart Ignore, nomdagi nuqta, kengaytma yo‘qligi, bo‘sh fayl, Hidden atributi. Bu tartib faqat hisoblagichlarga ta’sir qiladi. Ko‘rinish uchun istalgan faol mexanizm elementni chiqarishi mumkin.

### 12.7 O‘zgarishlarni qo‘llash
Belgilarni almashtirish avval mavjud parametrlar va hisoblagichlarni yangilaydi. Yakuniy daraxt «Sozlamalarni qo‘llash» bosilgach qayta quriladi. Tayyorlash bekor qilinsa, DevProjex oxirgi to‘liq tugallangan holatga qaytadi; qisman hisoblangan qoidalar qo‘llanmaydi.

## 13) Daraxt va metrikalar qanday hisoblanadi
Natija quyidagilarga bog‘liq:
* tanlangan yuqori darajadagi jildlar
* tanlangan fayl turlari
* e’tiborsiz qoldirish qoidalari
* faol filtr
* daraxtdagi checkbox orqali belgilangan tugunlar (tanlovga asoslangan amallar uchun)

Agar ruxsat bo‘lmasa, tugun "Kirish taqiqlangan" deb belgilanadi.

### 13.1 Status-bardagi hisoblagichlar nimani ko‘rsatadi
Status-barda ikki blok bor:
* Daraxt — daraxtning matnli chiqishi metrikalari;
* Mazmun — fayl mazmuni chiqishi metrikalari.

Format:
* Satrlar
* Belgilar
* ~Tokenlar (taxminiy)

Katta qiymatlar qisqa formatda (K/M) ko‘rsatiladi.

Muhim:
* «Satrlar» («Daraxt» blokida) diskdagi fayllar soni emas, daraxtning yakuniy ko‘rinishidagi satrlar sonini bildiradi;
* bu qiymatga papkalar, fayllar va daraxtning xizmat elementlari (masalan, kirish taqiqlangan tugunlar) kiradi.

### 13.2 Metrikalar qanday hisoblanadi
Daraxt metrikalari:
* aynan eksport pipeline’i yaratadigan real daraxt matni bo‘yicha hisoblanadi;
* joriy daraxt formatini hisobga oladi.

Mazmun metrikalari:
* mazmunni nusxalash/eksport qilish qoidalari bilan bir xil hisoblanadi;
* binar fayllar kiritilmaydi;
* bo‘sh va faqat bo‘sh joyli fayllar servis markerlari orqali hisoblanadi (`[No Content, 0 bytes]`, `[Whitespace, N bytes]`).

### 13.3 Hisoblagichlar qachon yangilanadi
Qayta hisoblash quyidagi holatlarda bajariladi:
* loyiha ochilgandan/yangilangandan keyin;
* sozlamalar qo‘llangandan keyin (ignore, fayl turlari, root jildlar);
* daraxtdagi checkboxlar o‘zgarganda (debounce bilan);
* daraxt formati almashtirilganda (daraxt ishlatiladigan amallar uchun).
* fon hisoblash bekor qilinsa, keyingi to‘liq yakunlangan qayta hisoblashgacha hisoblagichlar 0 ga o‘rnatiladi.

## 14) Ikonkalar
Ikonka tanlash tartibi:
1) tugun turi (papka/fayl)
2) aniq nom (qoida bo‘lsa)
3) kengaytma
4) aks holda — noma’lum

## 15) Mavzu va effektlar
«Mavzu» bo‘limida yorug‘ yoki qorong‘i mavzu va bitta fon effektini tanlash mumkin:
* Shaffoflik
* Xiralashtirish
* Mica

Effektlar bir vaqtda ishlamaydi. Tanlangan effektni qayta bosish uni o‘chiradi va oddiy shaffof bo‘lmagan fonni qaytaradi.

Mavjud sozlamalar:
* Fon shaffofligi — Shaffoflik va Xiralashtirish rejimlarida mavjud.
* Yuqori panel kontrasti — preview, qidiruv, filtr va daraxt formati buyruqlari joylashgan asosiy panelni sozlaydi.
* Menyu shaffofligi — asosiy menyu va uning ichki menyulariga bir xil qo‘llanadi.
* Chegaralar ko‘rinishi — interfeys chegaralarining qanchalik aniq ko‘rinishini sozlaydi.

Mica platformaning tizim materialidan foydalanadi va fon shaffofligi uchun alohida sozlamaga ega emas. Tizim effektni qo‘llamasa, ilova xavfsiz shaffof bo‘lmagan ko‘rinishdan foydalanadi.

## 16) Yordam

### 16.1 Sozlamalarni tiklash
Sozlamalarni tiklash (Yordam → Sozlamalarni tiklash) mavzu, effektlar, ixcham rejim, daraxt animatsiyasi va interfeys tilini standart qiymatlarga qaytaradi. Loyiha profillari, tarix va diskdagi fayllar o‘zgartirilmaydi.

### 16.2 Ma’lumotlarni tiklash
Ma’lumotlarni tiklash (Yordam → Ma’lumotlarni tiklash) mahalliy loyiha parametrlarining saqlangan profillarini o‘chiradi:
* tanlangan yuqori darajadagi jildlar;
* tanlangan fayl turlari;
* «E’tiborsiz qoldirish» blokidagi tanlangan qoidalar.

Muhim:
* lokal jildlar uchun “So‘nggilar” tarixi tozalanmaydi;
* Git Clone oynasidagi “So‘nggi repozitoriylar” tarixi tozalanmaydi;
* diskdagi loyiha fayllari va jildlari o‘zgartirilmaydi va o‘chirilmaydi.

## 17) Tillar
Til menyusi orqali tanlanadi.
Tanlangan til ilova qayta ishga tushirilganda saqlanadi. «Yordam → Sozlamalarni tiklash» saqlangan til tanlovini tozalaydi va interfeys tilini standart holatga qaytaradi.

## 18) Progress-bar va bekor qilish
Status-bar markazida faol amal va progress ko‘rsatiladi.

Progress rejimlari:
* Indeterminate — foizsiz (amal davomiyligi noma’lum).
* Determinate — foiz bilan (0–100).

Xulq-atvor:
* fon rejimida ma’lumot hisoblash vaqtida foizli progress ko‘rsatiladi;
* ayrim Git amallarida progress manbasi foiz berganda foiz ko‘rsatiladi;
* mavjud parametrlarni yangilash va sozlamalarni qo‘llash amal sezilarli vaqt olsa ko‘rsatiladi;
* tez amallar progressni ko‘rsatmasdan yakunlanadi.

Status-bardagi X (bekor qilish) tugmasi:
* bekor qilishni qo‘llaydigan amallar uchun best-effort bekor qilishni bajaradi;
* fon rejimidagi ma’lumot hisoblashni to‘xtatadi;
* mavjud parametrlarni yangilash bekor qilinganda panelni oxirgi yakunlangan holatiga qaytaradi;
* bekor qilishni qo‘llamaydigan amallarda status-bar indikatsiyasini tugatadi, lekin amal fon rejimida yakunlanishi mumkin.

## 19) Eslatmalar
* Standart holatda Xiralashtirish effektli qorong‘i mavzu ishlatiladi. Tizim effektni qo‘llamasa, ilova xavfsiz shaffof bo‘lmagan ko‘rinishdan foydalanadi.
* Ruxsat yetarli bo‘lmasa, ilova admin huquqi bilan qayta ishga tushirishni taklif qiladi; rad etilsa, xabar chiqadi.
