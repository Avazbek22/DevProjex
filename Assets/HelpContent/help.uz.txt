## 1) Nima va nima uchun
DevProjex loyiha kontekstini tez tayyorlaydi: jild/fayl tuzilmasini ko‘rsatadi, elementlarni belgilash va daraxtni va/yoki fayl tarkibini buferga nusxalash imkonini beradi. Code review, qo‘llab‑quvvatlash, o‘qitish va loyiha tuzilmasini AI‑yordamchiga berish uchun qulay.

Muhim: DevProjex ochilgan loyihadagi fayllarni o‘zgartirmaydi. Yagona istisno — Cursor yoki VS Code uchun aniq MCP ulanishi: u `.cursor/mcp.json` yoki `.vscode/mcp.json` faylini yaratadi yoki yangilaydi (19.1-bo‘lim).

## 2) Loyiha daraxti
* Fayl/jild ikonkalari.
* Tugunlardagi belgilash kataklari.
* Ochish/yopish.

Belgilash kataklari: tugunni belgilash uning avlodlariga qo‘llanadi; ota holati avtomatik qayta hisoblanadi.

Issiq tugmalar:
* {mod}E — hammasini ochish
* {collapseAll} — hammasini yopish (ildiz ochiq qoladi)

### Kontekst menyusi
Tugun ustida sichqonchaning o‘ng tugmasini bosing — yoki fokusdagi tugunda {shift}F10 / Menyu tugmasi:
* File Explorerda ko‘rsatish / Finderda ko‘rsatish / Fayl menejerida ochish — elementni tizim fayl menejerida ko‘rsatadi; nom joriy platformaga mos keladi.
* To‘liq yo‘lni nusxalash — elementning mutlaq yo‘li.
* Nisbiy yo‘lni nusxalash — loyiha ildizidan boshlanadigan yo‘l; u ildiz jild nomidan boshlanadi, masalan `project/src/File.cs`.
* Tarkibni nusxalash — fayllar uchun: tarkibni qo‘llangan o‘zgartirishlar bilan nusxalaydi, xuddi nusxalash va eksport chiqargani kabi.
* Faqat shuni tanlash — faqat shu tugunni belgilab, qolgan tanlovni bekor qiladi; faqat boshqa element ham belgilangan paytda ko‘rinadi.
* Tarmoqni yoyish / Tarmoqni yig‘ish — jildlar uchun.

Agar yo‘l diskda endi mavjud bo‘lmasa, fayl menejerida ochish va tarkibni nusxalash xato xabarini ko‘rsatadi; yo‘llarni nusxalash ishlashda davom etadi.

## 3) Fayl
* Jildni ochish… — ildiz jildni ochish ({mod}O)
* Yangi oyna — DevProjex’ning yangi mustaqil nusxasini ochish
* So‘nggi — yaqinda ochilgan mahalliy jildlar ro‘yxati
* Yangilash — mahalliy jildni qayta o‘qish va daraxtni qayta qurish (F5)
* Faylga eksport:
  * Daraxtni eksport qilish
  * Tarkibni eksport qilish
  * Daraxt va tarkibni eksport qilish
* Loyihani eksport qilish:
  * Jildga…
  * ZIP arxivga…

Loyihani eksport qilish joriy daraxtdan kataloglar tuzilmasini saqlagan holda alohida jild yoki ZIP arxiv yaratadi.

Tanlangan fayl turlari, istisno qoidalari va belgilangan elementlar hisobga olinadi. Hech narsa belgilanmasa, butun joriy daraxt eksport qilinadi.

Matnli va binar fayllar nusxalanadi, kiritilgan bo‘sh jildlar ham saqlanadi. Asl fayllar o‘zgartirilmaydi. Natijani boshlang‘ich loyiha ichiga saqlab bo‘lmaydi.

Eksport paytida daraxt yoki parametrlarni o‘zgartirish, filtrdan foydalanish, format yoki ko‘rib chiqish rejimini almashtirish, Git buyruqlarini, yangilashni yoki boshqa loyihani ochishni ishga tushirish mumkin emas.

Format qoidalari:
* Daraxtni eksport qilish:
  * ASCII -> faqat `.txt`.
  * JSON -> standart `.json`, saqlash oynasida `.json` va `.txt` mavjud.
  * XML -> standart `.xml`, saqlash oynasida `.xml` va `.txt` mavjud.
  * MD -> standart `.md`, saqlash oynasida `.md` va `.txt` mavjud.
* Tarkibni eksport qilish — har doim tarkibning matn formati, `.txt` fayl (daraxt formati tumbleri ta’sir qilmaydi).
* Daraxt va tarkibni eksport qilish — har doim `.txt` fayl; tanlangan daraxt formati faqat natijadagi daraxt blokining formatiga ta’sir qiladi.

Eksport fayllari UTF-8 (BOMsiz) formatida yoziladi.

### Drag & Drop
Drag & Drop loyiha yuklanmagan holatda boshlang‘ich maydonda (Drop Zone) ishlaydi.

Qoidalar:
* jildni tashlash mumkin;
* faylni tashlash mumkin — bu holda fayl joylashgan jild ochiladi;
* bir nechta obyekt tashlansa, birinchi mos mahalliy yo‘l ishlatiladi;
* yo‘l mavjud bo‘lmasa yoki kirish bo‘lmasa, «Jildni ochish…» dagi kabi bir xil kirish tekshiruvlari qo‘llanadi;
* qo‘llab-quvvatlanmaydigan yoki mahalliy bo‘lmagan obyektlar e’tiborga olinmaydi.

### So‘nggi
«Fayl → So‘nggi» bandi yaqinda ochilgan mahalliy jildlar tarixini ko‘rsatadi.

Qoidalar:
* ro‘yxatga faqat mahalliy jildlar qo‘shiladi;
* DevProjex orqali klonlangan Git repozitoriylari bu ro‘yxatga qo‘shilmaydi;
* dublikatlar yaratilmaydi — bir xil jildni qayta ochish uni ro‘yxatning yuqorisiga olib chiqadi;
* 32 tagacha so‘nggi jild saqlanadi;
* tarix ilova qayta ishga tushirilganda ham saqlanadi.

Har bir elementda yuqori jild va loyiha nomi ko‘rsatiladi, masalan `Projects / App`.

## 4) Terminaldan ishga tushirish
DevProjex interaktiv terminal ish maydoni hamda skriptlar va CI uchun to‘g‘ridan-to‘g‘ri buyruqlarni taqdim etadi.

Agar buyruq allaqachon sozlangan bo‘lsa, terminalni ochib bajaring:
`devprojex --help`

Shunda yuqori darajadagi buyruqlar va parametrlarni ko‘rasiz. Muayyan buyruqning parametrlari va misollarini `devprojex help <command>` ko‘rsatadi.

Misollar:
* `devprojex` — interaktiv terminal ish maydonini ochish. Ish maydonida amallar `:` orqali buyruq satrida bajariladi (masalan, `:copy`, `:analyze`, `:branch`, `:language`); buyruqlarning to‘liq ro‘yxati ish maydonining ichki yordami va loyiha hujjatlarida berilgan.
* `devprojex tui .` — ko‘rsatilgan jildni darhol terminal ish maydonida ochish.
* `devprojex open . --preview` — joriy jildni Desktop ko‘rib chiqish rejimida ochish.
* `devprojex analyze . --format json` — joriy loyihani JSON sifatida tahlil qilish.
* `devprojex tree .` — loyiha daraxtini terminalga chiqarish.
* `devprojex export context . --format markdown -o ../devprojex-context.md` — AI uchun tayyor kontekstni manba loyihasidan tashqarida saqlash.
* `devprojex export project . --as folder -o ../devprojex-submission` — samarali loyiha daraxtini aniq jildga eksport qilish.
* `devprojex export project . --as zip -o ../devprojex-submission.zip` — samarali loyiha daraxtini ZIP arxiviga eksport qilish.
* `devprojex export context https://github.com/owner/repo -o -` — masofaviy repozitoriyni qo‘lda klonlamasdan qadoqlash.
* `devprojex analyze . --git-mode tracked --exclude smart-ignore` — Git kuzatuvidagi fayllarni Smart Ignore bilan tahlil qilish.
* `devprojex search Configure . --symbols` — deklaratsiya qayerda aniqlanganini topish; `--symbols` deklaratsiya nomlarini qabul qiladi va muntazam ifoda sintaksisini rad etadi, `--regex` esa matnni muntazam ifoda bilan qidiradi.
* `devprojex related src/App.cs` — fayl foydalanadigan fayllarni va undan foydalanadigan fayllarni ro‘yxatlash.
* `devprojex mcp --root .` — AI agentlar loyihani xavfsiz o‘qishi uchun mahalliy faqat o‘qiladigan MCP serverini ishga tushirish.
* `devprojex mcp connect . --client claude-code` — AI mijozni loyihaga ulash (19-bo‘lim).
* `devprojex mcp log . --last` — agent jurnalining oxirgi seansini ko‘rsatish.

Eslatmalar:
* `.` terminaldagi joriy jildni bildiradi;
* bo‘sh joyli yo‘llar qo‘shtirnoqqa olinishi kerak;
* `--git-mode` `none`, `gitignore`, `tracked`, `staged`, `changes` yoki `diff:<ref>..<ref>` qiymatini tanlaydi;
* `--exclude` oddiy istisnolarni Git filtrlashdan alohida boshqaradi;
* tahlil va eksport buyruqlari deterministik bo‘lib, grafik interfeysni ochmaydi;
* `tui`, `open`, `analyze`, `search`, `tree` va ikkala `export` buyrug‘i Git repozitoriysi URL manzilini ham qabul qiladi, `related` esa uni `--project` orqali qabul qiladi; klon boshqariladigan keshga tushadi (`devprojex cache`);
* buyruqlarning hujjatlashtirilgan aliaslari va qisqa bayroqlari bor — masalan `export ctx`, `-f`, `-n`; ularni `devprojex help` ko‘rsatadi;
* `analyze --findings` maskalash topilmalarini qiymatlarisiz ro‘yxatlaydi, `--fail-on-findings` esa CI uchun noldan farqli chiqish kodini qaytaradi;
* `export context --max-tokens N` kontekstni token byudjeti doirasida saqlaydi, tajribaviy `--rank importance` esa eng muhim fayllarni birinchi bo‘lib kiritadi;
* tahlil, qidiruv va eksport buyruqlari loyiha fayllarini o‘zgartirmaydi — DevProjex faqat o‘qish rejimida ishlaydi.

Agar `devprojex` buyrug‘i ishlamasa, DevProjex ichida oching:
«Yordam → Terminaldan ishga tushirish».

## 5) Git
«Git → Repozitoriyni klonlash…» repozitoriyni DevProjex keshiga klonlaydi va ochadi. «Tarmoq» va «Yangilanishlarni olish» faqat shu tarzda klonlangan loyihalarda mavjud. Ilova fayllaringizga tegmaydi — faqat kesh bilan ishlaydi.

Kesh foydalanuvchining tizim kesh katalogida saqlanadi. Haqiqiy yo‘lni `devprojex doctor` buyrug‘i ko‘rsatadi.

* Tarmoq — mavjud tarmoqlar ro‘yxatini faol tarmoq belgisi bilan ko‘rsatadi; almashganda daraxt tanlangan tarmoqqa yangilanadi. Agar tarmoq allaqachon mahalliy bo‘lsa, almashish internetga ulanmasdan (yangilanishsiz) bajariladi. Agar tarmoq mahalliy bo‘lmasa, u fetch orqali yuklanib, mahalliy yaratiladi.
* Yangilanishlarni olish — faqat joriy tarmoqni yangilaydi: fetch va origin/<tarmoq> ga reset. Git Clone loyihasida F5 xuddi shu amalni bajaradi; odatiy «Fayl → Yangilash» buyrug‘i o‘chirilgan bo‘ladi.

### Klonlash oynasi
Git Clone oynasida URL maydoni ostida «So‘nggi havolalar» ro‘yxati ko‘rsatilishi mumkin.

Qoidalar:
* ro‘yxat faqat tarixda yaqinda klonlangan repozitoriylar bo‘lsa paydo bo‘ladi;
* ro‘yxatga faqat tarmoq repozitoriy manbalari (`https://`, `ssh://` va SCP sintaksisi) qo‘shiladi;
* mahalliy yo‘llar va `file://` manbalari bu ro‘yxatga qo‘shilmaydi;
* dublikatlar yaratilmaydi — bir xil repozitoriyni qayta klonlash uni ro‘yxatning yuqorisiga olib chiqadi;
* 16 tagacha so‘nggi repozitoriy saqlanadi;
* tarix ilova qayta ishga tushirilganda ham saqlanadi.

Ro‘yxatdan element tanlansa, URL avtomatik ravishda kiritish maydoniga qo‘yiladi.
Faol klonlash vaqtida ro‘yxat vaqtincha yashiriladi.

## 6) Nusxa
### Daraxt formati tumbleri (ASCII / JSON / XML / MD)
Tumbler natijada daraxt ishtirok etadigan amallar uchun daraxt ko‘rinishi formatini belgilaydi.

* ASCII — shoxlari bor matnli daraxt.
* JSON — JSON formatidagi strukturali daraxt.
* XML — parserlar va vositalar uchun ixcham XML daraxt.
* MD — hujjatlar va AI promptlar uchun ichma-ich Markdown ro‘yxat.

Tumbler quyidagilarga ta’sir qiladi:
* Daraxtni nusxalash
* Daraxt + tarkibni nusxalash
* Daraxtni eksport qilish
* Daraxt va tarkibni eksport qilish

Tumbler quyidagilarga ta’sir qilmaydi:
* Tarkibni nusxalash
* Tarkibni eksport qilish

### Daraxtni nusxalash
Loyiha daraxtini nusxalaydi.
Agar belgilangan tugunlar bo‘lsa, daraxt tanlov bo‘yicha quriladi; tanlov bo‘sh yoki yaroqsiz bo‘lsa, to‘liq daraxt nusxalanadi.
Natija formati daraxt formati tumbleri bilan aniqlanadi.
Tugmalar: {mod}{shift}C va {mod}{alt}C.

### Tarkibni nusxalash
Fayllar tarkibini nusxalaydi:
* agar fayllar belgilangan bo‘lsa — faqat ular; aks holda — loyihadagi barcha fayllar;
* har bir fayl oldidan uning to‘liq mahalliy yo‘li yozilgan sarlavha chiqariladi (Git Clone loyihalari uchun — repozitoriyning veb-yo‘li);
* matnli bo‘lmagan fayllar e’tiborga olinmaydi (binarlarni ham);
* bo‘sh matnli fayllar uchun yo‘l va `[No Content, 0 bytes]` yoziladi;
* faqat bo‘sh joylar/satr uzilishlaridan iborat fayllar uchun yo‘l va `[Whitespace, N bytes]` yoziladi.
Tugma: {mod}{alt}V.

### Daraxt + tarkibni nusxalash
Daraxt va tarkibni birlashtiradi:
* daraxt tanlov bo‘yicha; agar tanlov bo‘sh yoki yaroqsiz bo‘lsa — to‘liq daraxt;
* tarkib «Tarkibni nusxalash» qoidalari bo‘yicha;
* daraxt blokining formati daraxt formati tumbleri bilan aniqlanadi.
Tugma: {mod}{shift}V.

### Daraxt ko‘rinishlari
Daraxt formatlari bir xil tanlangan loyiha daraxtini turlicha ko‘rsatadi.

JSON:
* `rootPath` — `/` orqali normallashtirilgan absolyut ildiz yo‘li.
* `tree` — ildiz jildning tarkibi.
* JSON eksport shu daraxt formatidan foydalanadi: massivlar fayllarni, obyektlar ichki jildlarni, `/` joriy jilddagi fayllarni saqlaydi, `[]` esa bo‘sh jildni bildiradi.

XML:
* ildiz tugun — `<t r="...">`;
* jildlar — `<d n="...">`;
* fayllar — `<f>File.cs</f>`.

MD:
* `Root: ...` bilan boshlanadi;
* ichma-ich Markdown ro‘yxatidan foydalanadi;
* jildlar `/` bilan tugaydi.

Daraxt + tarkib:
* tanlangan daraxt formati daraxt blokiga qo‘llanadi;
* tarkib bloki matn bo‘lib qoladi;
* tarkib blokidagi fayl sarlavhalari `/` ajratgichli nisbiy yo‘llardan foydalanadi;
* eksport `.txt` formatida saqlanadi.

## 7) Ko‘rib chiqish rejimi
Yuqori paneldagi ko‘zcha ikonali tugma yoki {mod}B orqali ochiladi.

Sichqonchaning yon tugmalari brauzerdagi kabi ishlaydi: «Oldinga» ko‘rib chiqish rejimini ochadi, «Orqaga» esa yopadi. Joriy yo‘nalishni qayta bosish hech narsani o‘zgartirmaydi.

{mod}{shift}F ko‘rib chiqishdagi fayllar tarkibidan qidirishni ochadi yoki yopadi. Enter yoki F3 keyingi moslikka, {shift}Enter yoki {shift}F3 oldingi moslikka o‘tadi.

Yakuniy natijani daraxt yonidagi alohida ishchi hududda ko‘rsatadi. Bu rejim o‘zi hech narsani almashish buferiga nusxalamaydi va faylga eksport qilmaydi — u faqat ko‘rish uchun xizmat qiladi.

Standart holatda ishchi hudud quyidagicha ochiladi:
* chapda — loyiha daraxti;
* markazda — ko‘rib chiqish oroli;
* o‘ngda — agar ochiq bo‘lsa, sozlamalar paneli.

Mavjud rejimlar:
* Daraxt
* Tarkib
* Daraxt va tarkib

Nusxalash va eksportdagi qoidalar shu yerda ham qo‘llanadi:
* belgilangan tugunlar hisobga olinadi;
* tanlov bo‘sh bo‘lsa, to‘liq ma’lumotlar to‘plami ishlatiladi;
* joriy ignore qoidalari va tanlov parametrlari qo‘llanadi.

Qo‘shimcha:
* ko‘rib chiqish ichida fayllar gorizontal chiziqlar bilan ajratiladi;
* skroll paytida joriy fayl yo‘li tepada mahkamlanadi; mahkamlangan yo‘lni bosish o‘sha fayl boshiga olib boradi;
* ko‘rib chiqish skroll-bari qidiruv mosliklari va topilgan qiymatlari bor qatorlarni belgilaydi; belgini bosish uning qatoriga olib boradi; saqlab qolingan qiymat belgilangancha qoladi, sarlavhalardagi maskalangan yo‘llar esa birinchi qatorida bitta belgi beradi;
* daraxt va ko‘rib chiqish masshtabi bir-biridan mustaqil bo‘lishi mumkin;
* ko‘rib chiqish rejimida «Nusxa» menyusiga kirmasdan turib to‘liq joriy natijani ham, joriy ko‘rinib turgan fayl blokini ham nusxalash mumkin.

Tugmalar:
* yuqori ko‘rib chiqish orolining chap tomonidagi nusxa tugmasi — joriy ko‘rib chiqish rejimini nusxalaydi:
  * Daraxt
  * Tarkib
  * Daraxt va tarkib
* daraxt orolidagi X — daraxtni yashiradi va faqat ko‘rib chiqish orolini qoldiradi;
* ko‘rib chiqishning yuqori orolidagi X — ko‘rib chiqish rejimini to‘liq yopadi;
* faylning mahkamlangan yuqori sarlavhasidagi kichik nusxa tugmasi — joriy ko‘rinib turgan fayl blokini ko‘rib chiqishda ko‘rsatilgan holatda nusxalaydi;
* ko‘zcha ikonani yana bir marta bosish yoki {mod}B ham ko‘rib chiqish rejimini yopadi.

Qidiruv va filtr ko‘rib chiqish ichida daraxt oroli ko‘rinib turgan paytda ishlaydi.
Agar daraxt yashirilsa, qidiruv va filtr daraxtsiz ko‘rib chiqish rejimidan chiqquncha vaqtincha ishlamaydi.

## 8) Ko‘rinish
### Masshtab
* {mod}+ / {mod}= — kattalashtirish
* {mod}- — kichraytirish
* {mod}0 — tiklash
* {mod}g‘ildirak — kursor turgan orolda silliq zoom

Xulq-atvor:
* oddiy rejimda daraxt masshtablanadi;
* daraxt ko‘rinib turgan ko‘rib chiqish rejimida menyudagi kattalashtirish, kichraytirish va tiklash daraxt va ko‘rib chiqishga bir vaqtda qo‘llanadi;
* {mod}g‘ildirak bilan daraxt va ko‘rib chiqish kursor joylashuviga qarab mustaqil masshtablanadi;
* daraxtsiz ko‘rib chiqish rejimida faqat ko‘rib chiqish oroli masshtablanadi.

Oraliq: 6–28, tiklash — 15.

### Ixcham rejim
Interfeysni zichroq qiladi: daraxt va sozlamalarda oraliqlar kichikroq.
Ko‘rib chiqish ish maydoni faol bo‘lganda ixcham rejim avtomatik ravishda yoqiladi.

### Animatsiyalar
«Ko‘rinish → Animatsiyalar» bo‘limida daraxtni ochish, holat hisoblagichlari va asboblarning ilk ko‘rinishi alohida boshqariladi. Uchala animatsiya ham standart holatda yoqilgan; o‘chirilgan animatsiya yakuniy holatni darhol ko‘rsatadi.

### Daraxt shrifti
Daraxt shrifti «Ko‘rinish → Daraxt shrifti» orqali tanlanadi.
«Standart» daraxtning odatiy shriftini qaytaradi.
Tanlangan shrift sozlamalar panelidagi «Sozlamalarni qo‘llash» tugmasi bosilgandan keyin qo‘llanadi.

### Agent faolligi
Jonli AI agent qaysi fayllarni olganini ko‘rish uchun «Ko‘rinish → Agent faolligi» bandini yoqing: bunday fayllar daraxtda ✦ belgisi bilan belgilanadi (19.4-bo‘lim).

## 9) Daraxt bo‘yicha qidiruv
Qidiruv panelini ochadi, mosliklarni yoritadi va navigatsiya qiladi.
* {mod}F — ko‘rsatish/yashirish
* Enter — keyingi
* {shift}Enter — oldingi
* Esc — yopish

Qidiruv faqat kerakli shoxlarni ochadi; so‘rov tozalansa, daraxt yig‘iladi (ildizdan tashqari).
Moslik qatorlari daraxt skroll-barida ham belgilanadi; belgini bosish o‘sha moslikka olib boradi.
Mosliklar soni juda ko‘p bo‘lsa, interfeys tezkorligini saqlash uchun ilova avtomatik ochish va ommaviy yoritishni cheklashi mumkin.
Qidiruv paneli yopilganda, yopilish animatsiyasi tugagach so‘rov tozalanadi.

Cheklovlar:
* qidiruv ochilganda, filtr avtomatik yopiladi;
* qidiruv ko‘rib chiqish ichida daraxt oroli ko‘rinib turgan paytda mavjud;
* daraxt yashirilsa, qidiruv vaqtincha mavjud emas.

## 10) Nom bo‘yicha filtr
Filtr satriga mos tugunlar va ularning ota‑onalarini ko‘rsatadi. Yangilanish kechikish bilan.
* {mod}{shift}N — filtrni ko‘rsatish/yashirish
* Esc — filtrni yopish

Cheklovlar:
* filtr ochilganda, qidiruv avtomatik yopiladi;
* filtr ko‘rib chiqish ichida daraxt oroli ko‘rinib turgan paytda mavjud;
* daraxt yashirilsa, filtr vaqtincha mavjud emas.

## 11) Sozlamalar
O‘ng tomonda mavjud:
* Sozlamalarni qo‘llash
* Tarkibni qayta ishlash
* Istisnolar
* Fayl turlari

«Istisnolar» va «Fayl turlari» o‘zgarishlari panelda tayyorlanadi va «Sozlamalarni qo‘llash» bosilgandan keyin qo‘llanadi.

Belgilash katagi o‘zgargandan keyin ilova mavjud bandlar va ularning hisoblagichlarini fonda yangilashi mumkin. Yakuniy daraxt faqat «Sozlamalarni qo‘llash» bosilgandan keyin qayta quriladi.

Mavjud parametrlarni yangilash status-bardagi X tugmasi bilan bekor qilinsa, tugallanmagan o‘zgarishlar qo‘llanmaydi va panel oxirgi yakunlangan holatiga qaytadi.

Har bir ro‘yxatda Barchasi tugmasi bor.

«Fayl turlari» bo‘yicha izoh:
* bu ro‘yxatda faqat kengaytmali fayllar ko‘rsatiladi;
* kengaytmasiz fayllar bu ro‘yxatga qo‘shilmaydi va «Istisnolar» ichidagi alohida band orqali boshqariladi.

Tarkibni qayta ishlash:
* bu bo‘lim tanlangan matn fayllari tarkibini daraxtni o‘zgartirmasdan o‘zgartiradi;
* «Sirlarni yashirish» va «Shaxsiy ma’lumot yashirish» topilgan qiymatlarni almashtiradi (12.3 va 12.4 bo‘limlari);
* «Kodni siqish» e’lonlarni saqlab, nomlangan implementatsiyalarni 14 tilda qisqartiradi;
* «Izohlarni olib tashlash» 20 til paketida izohlar va hujjat izohlarini olib tashlaydi;
* «Bo‘sh qatorlarni olib tashlash» o‘sha paketlarda faqat bo‘sh joylardan iborat qatorlarni olib tashlab, ko‘p qatorli literallarni saqlaydi;
* o‘zgarishlar «Sozlamalarni qo‘llash» bosilgandan keyin kuchga kiradi.

{mod}P — panelni ko‘rsatish/yashirish.

### 11.1 Mahalliy loyiha parametr profillari
Mahalliy jildlar uchun DevProjex loyihaning oxirgi qo‘llangan parametrlarini eslab qoladi:
* tanlangan fayl turlari;
* «Istisnolar» bo‘limidagi tanlangan qoidalar.

Saqlash «Sozlamalarni qo‘llash» tugmasi bosilganda bajariladi.
Xuddi shu mahalliy jild qayta ochilganda parametrlar avtomatik tiklanadi.

Muhim:
* profillar faqat mahalliy loyihalar uchun saqlanadi;
* Git Clone orqali ochilgan loyihalar uchun profillar saqlanmaydi;
* agar joriy loyihada saqlangan ayrim bandlar endi mavjud bo‘lmasa, ular o‘tkazib yuboriladi, qolgan parametrlar qo‘llanadi.
* yangilash yoki qayta ochishdan keyin yangi fayl turi yoki «Istisnolar» ichida yangi band paydo bo‘lsa, u odatda yoqilgan bo‘ladi;
* avvaldan ma’lum bandlar foydalanuvchining aniq tanlovini saqlaydi: o‘chirilgan turdagi yangi fayllar bu turni qayta yoqmaydi.

## 12) Istisnolar
«Istisnolar» bo‘limi daraxt, tarkib, nusxalash va eksport natijalaridan qaysi fayl va jildlar chiqarib tashlanishini boshqaradi.

Element faqat quyidagi shartlarning barchasi bajarilganda ko‘rsatiladi:
* faylning turi bo‘lsa, shu tur tanlangan;
* hech bir yoqilgan e’tiborsiz qoldirish qoidasi uni chiqarib tashlamaydi.

E’tiborsiz qoldirish qoidalari jamlanadi. Kamida bitta yoqilgan qoida elementni yashirsa, boshqa qoida uni ko‘rinadigan qila olmaydi.

### 12.1 Mavjud qoidalar
Loyiha tarkibiga qarab quyidagi bandlar ko‘rsatilishi mumkin:

* Smart Ignore
* Bo‘sh jildlar
* Bo‘sh fayllar
* Yashirin jildlar
* Yashirin fayllar
* Nuqtali jildlar
* Nuqtali fayllar
* Kengaytmasiz fayllar

Git filtrlashni qo‘llab bo‘lmaganda GUI selektori va TUI’dagi Git o‘qining radio qatorlari butunlay yashiriladi: repozitoriy chegarasi yo‘q va `.gitignore` filtri joriy daraxtni o‘zgartira olmaydi. O‘q repozitoriydan tashqarida ko‘rinsa, GUI faqat filtrlashsiz rejim va `.gitignore`ni taklif qiladi, TUI esa repozitoriy talab qiladigan qatorlarni o‘chiradi. Git repozitoriysida beshta odatiy qiymat mavjud: filtrlashsiz, `.gitignore`, kuzatiladigan fayllar, Indeksdagi Git fayllari va barcha joriy o‘zgarishlar; TUI’da faol `diff:<ref>..<ref>` doirasi oltinchi qatorda paydo bo‘ladi. Qiymatni tanlash Smart Ignore va asosiy istisnolarni o‘zgartirmasdan joriy Git rejimini almashtiradi. Boshqa bandlar ularning qoidalari joriy daraxtni o‘zgartira olganda ko‘rsatiladi, shuning uchun boshqa qoida yoki fayl turi almashtirilgach ro‘yxat o‘zgarishi mumkin.

Yangi band birinchi marta paydo bo‘lganda odatda yoqilgan bo‘ladi. Ma’lum band ro‘yxatdan vaqtincha yo‘qolsa ham foydalanuvchi tanlovini saqlaydi.

### 12.2 Smart Ignore
Smart Ignore bog‘liqliklar, build natijalari, keshlar va loyihaning boshqa xizmat artefaktlarini yashiradi.

DevProjex avval loyiha turini tuzilmasi va marker fayllari orqali aniqlaydi, masalan:

* `.csproj`
* `package.json`
* `pyproject.toml`
* `Cargo.toml`

So‘ng tegishli stek qoidalari aniqlangan loyiha hududi ichida qo‘llanadi. Masalan, .NET qoidalari qo‘shni Python yoki JavaScript loyihasiga yoyilmaydi.

Jild nomining o‘zi har doim ham yetarli emas. `build`, `vendor`, `packages`, `cache`, `pkg` yoki `Library` kabi noaniq nomlar tarkibi bo‘yicha ham tekshiriladi. Bu oddiy foydalanuvchi jildini faqat nomi o‘xshashligi uchun yashirilishdan saqlaydi.

Ayrim bog‘liqlik omborlari va xizmat kataloglari aniq topilgan loyihadan tashqarida ham o‘ziga xos ichki tuzilishi orqali taniladi.

Katta foydalanuvchi jildini yuklash har bir katalogni qayta-qayta to‘liq tahlil qilishga aylanmasligi uchun loyiha hududlarini izlash cheklangan. Oddiy tuzilmalar sayoz, tanilgan monorepolar esa chuqurroq tekshiriladi. Hudud topilgach, Smart Ignore uning butun ichki daraxtiga chuqurlik cheklovisiz qo‘llanadi.

### 12.3 Sirlarni yashirish
«Sirlarni yashirish» odatda o‘chirilgan bo‘ladi. Bu parametr faqat tanlangan matnni tekshiradi va topilgan har bir qiymatni o‘z joyida almashtiradi; fayl va uning atrofidagi kod saqlanadi. Parametr o‘chiq bo‘lsa, tekshiruv ishlamaydi va hisoblagich ko‘rsatilmaydi. Joriy tanlov tekshirilgach, nom topilgan qiymatlar sonini ko‘rsatadi; «o‘zgarishsiz qoldirish» qarorlari yashirilganlar sonini kamaytirsa, ikkala son — topilgan/yashirilgan — ko‘rsatiladi, qatordagi «?» indikatori esa ularni matn bilan bildiradi.

Mos kelgan joylar ko‘rib chiqishda ajratib ko‘rsatiladi. Faqat bitta uchrashuvni o‘zgarishsiz qoldirish uchun uni bosing; {alt}↓ / {alt}↑ topilmalar bo‘ylab yuradi, Enter faolini almashtiradi. Terminal Workspace ichida `[` va `]` uchrashuvlar bo‘ylab yuradi, `Enter` yoki `Space` esa faol uchrashuvni almashtiradi. Qaror shu seans davomida ko‘rib chiqish, almashish buferi, kontekst eksporti, jild va ZIP uchun amal qiladi; loyiha profilida saqlanmaydi.

Ko‘rib chiqish kontekst menyusi bu qarorlarni kengaytiradi. Topilgan uchrashuv ustida o‘ng tugmani bosish bitta amal bilan uning qoidasidagi barcha uchrashuvlarni yoki o‘sha fayldagi barcha topilgan uchrashuvlarni saqlab qolish — yoki qayta yashirish — imkonini beradi. Fayl tarkibida tanlangan qiymat ustida o‘ng tugmani bosish qo‘lda belgi qo‘shadi: «…ni shu yerda yashirish» faqat shu uchrashuvni seans davomida yashiradi, «…ni doim yashirish» qiymatning barcha uchrashuvlari uchun doimiy belgi yaratadi, «…ni shaxsiy ma’lumot sifatida yashirish» esa «Shaxsiy ma’lumot yashirish» parametri boshqaradigan doimiy belgi yaratadi. «Belgini olib tashlash» qo‘lda qo‘yilgan belgida paydo bo‘lib, uni o‘chiradi; detektor hali ham topadigan qiymat yashirin qoladi. Qo‘lda kiritiladigan qiymat — fayl tarkibida tanlangan, 8 dan 512 belgigacha bo‘lgan bitta qator. Belgi yaratish tegishli parametrni avtomatik yoqadi. Doimiy belgilar faqat kalitli qiymat identifikatori va uning sinfini saqlaydi, asl matnni hech qachon saqlamaydi.

Jild yoki ZIP nusxasidagi mos matn ham o‘zgaradi, shu sababli natija yig‘ilmasligi yoki ishga tushmasligi mumkin. Ikkilik fayllar tekshirilmaydi va o‘zgarishsiz ko‘chiriladi. Hajmi 16 MiB dan katta tanlangan matn fayli tashlab ketiladi va bu haqda xabar beriladi, qolgan natijani yaratish esa davom etadi. Aniqlash xatosi butun operatsiyani to‘xtatadi.

Hisoblagich faqat qoidalarga mos kelgan joylarni bildiradi. Nol loyiha xavfsiz degani emas. CLI’da `--hide-secrets` ishlatiladi; tafsilotlar `Docs/HideSecrets.md` faylida.

### 12.4 Shaxsiy ma’lumot yashirish
«Shaxsiy ma’lumot yashirish» odatda o‘chirilgan bo‘ladi. Bu parametr tanlangan matn fayllaridagi elektron pochta manzillari, global IP manzillar, yo‘llardagi mahalliy foydalanuvchi nomlari, MAC manzillar va xalqaro telefon raqamlarini aniqlaydi. Topilmalar uchun Sirlarni yashirishdagi kabi ko‘rib chiqish qarorlari va bir xil chiqish konveyeri ishlatiladi; «…ni shaxsiy ma’lumot sifatida yashirish» orqali yaratilgan qo‘lda belgilar shu sinfga tegishli bo‘lib, shu parametrga bo‘ysunadi (12.3-bo‘lim). Yaratiladigan yo‘l sarlavhalaridagi va daraxt ildizidagi mahalliy foydalanuvchi nomlari bitta umumiy topilma sifatida maskalanadi: hisoblagich uni bitta qiymat deb sanaydi, «?» indikatori u yashirilgan yoki ko‘rsatilganini bildiradi, bitta bosish esa barcha maskalangan yo‘llarni birdaniga almashtiradi.

Hujjat uchun ajratilgan diapazonlar va hostlar, odatiy CI foydalanuvchilari, taniqli ochiq DNS resolverlari hamda hujjatlashtirilgan uydirma raqamlar ko‘rinib qoladi. Nol moslik maxfiylik kafolati emas. CLI-da `--hide-private-data` ishlatiladi; to‘liq qoidalar va birinchi bosqich chegaralari `Docs/HidePrivateData.md` faylida berilgan.

### 12.5 .gitignore dan foydalanish
Yoqilganda DevProjex ishchi daraxtni `git status` kabi ko‘rsatadi: kuzatiladigan fayllar ko‘rinib turadi, kuzatilmaydigan fayllar esa repozitoriyning e’tiborsiz qoldirish qoidalari ularni chiqarib tashlamasa ko‘rsatiladi. U ochilgan jild ildizidagi faylnigina emas, balki barcha yetib boriladigan `.gitignore` fayllarini, jumladan undan yuqorida repozitoriy ildizigacha bo‘lgan fayllarni ham qo‘llaydi.

Har bir `.gitignore` quyidagilarga qo‘llanadi:

* o‘zi joylashgan jildga;
* uning ostidagi barcha ochiq jildlarga;
* faqat shu hudud ichida.

Ichki `.gitignore` qoidalari ota yoki qo‘shni jildlarga ta’sir qilmaydi.

Muayyan yo‘l uchun qoidalar ota `.gitignore` faylidan chuqurroq fayllar tomon ishlanadi. Bitta fayl ichida qoidalar yuqoridan pastga qarab ishlanadi. Oxirgi mos qoida Git natijasini belgilaydi.

`!` bilan boshlanadigan qoida oldingi Git istisnosini faqat o‘z hududida bekor qiladi. Ota jild chiqarilgan bo‘lib qolsa, u faylni qaytara olmaydi. To‘liq chiqarilgan va yetib bo‘lmaydigan jild ichidagi `.gitignore` baholashda qatnashmaydi.

Buzilgan yoki qo‘llab-quvvatlanmaydigan satr alohida o‘tkazib yuboriladi. O‘sha fayldagi boshqa to‘g‘ri qoidalar va qo‘shni hududlardagi qoidalar ishlashda davom etadi.

Repozitoriyning mahalliy `.git/info/exclude` fayli ham qo‘llanadi, uning ustuvorligi ildizdagi `.gitignore` faylidan past. O‘z `.git` katalogiga ega ichki jild ham `git status` qoidasiga bo‘ysunadi: `.gitmodules` ichida e’lon qilinmagan ichki repozitoriy shaffof emas, shuning uchun uning fayllari ko‘rsatilmaydi, e’lon qilingan submodul esa o‘zining `.gitignore` va `info/exclude` fayllarini qo‘llaydi. Ichki repozitoriylar fayllarini ko‘rish uchun `none` ni tanlang. Global Git istisno qoidalari (`core.excludesFile`) qo‘llanmaydi; yo‘llarni taqqoslash uchun `core.ignoreCase` hamda macOS tizimida `core.precomposeUnicode` kabi repozitoriyning amaldagi sozlamalari hisobga olinadi. `.gitignore` nomli ramziy havola o‘qilmaydi — bu Gitning ushbu boshqaruv fayliga nisbatan xatti-harakatiga mos keladi. `.gitignore` yoki `info/exclude` faylini o‘qib bo‘lmasa, uning katalog doirasi xavfsiz tarzda to‘liq chiqariladi va tekshiruv barcha qoidalarni baholamasdan fayllarni yashirincha kiritish o‘rniga qisman kirish haqida xabar beradi. Yo‘l tegishli bo‘lgan repozitoriy sohasi uchun o‘qiladigan Git indeksi mavjud bo‘lsa, kuzatiladigan fayllar `.gitignore` ga mos kelsa ham ko‘rinadi; ushbu indeks yoki Git CLI bo‘lmasa, bu soha xavfsiz tarzda faqat andozalarni baholashga qaytadi.

Ichki `standard` profili `gitignore` rejimini hamda `smart-ignore`, `hidden-folders`, `hidden-files`, `dot-folders`, `dot-files`, `empty-folders`, `empty-files` va `extensionless-files` ni tanlaydi.

### 12.6 Faqat Git kuzatadigan fayllar
«Faqat Git kuzatadigan fayllar» daraxtning Git bosqichini har bir o‘qiladigan Git indeksida qayd etilgan, ishchi daraxtda mavjud fayllardan tuzadi. O‘zgartirilgan kuzatiladigan fayllar va indeksga qo‘shilgan yangi fayllar kiritiladi; kuzatilmaydigan fayllar chiqariladi. Bu `HEAD` yoki masofaviy repozitoriyning tarixiy nusxasi emas, joriy ishchi daraxtdir.

Har bir repozitoriy mustaqil qayta ishlanadi: ochilgan jild ichidagi qo‘shni repozitoriylar va e’lon qilingan submodullar har biri o‘z indeksidan foydalanadi, ichki repozitoriy esa ota yoki qo‘shni repozitoriyning kuzatiladigan yo‘llarini meros qilib olmaydi. `.gitmodules` ichida e’lon qilinmagan ichki repozitoriy `.gitignore` rejimidagi kabi shaffof emas bo‘lib qoladi. Bu rejim uchun Git CLI kerak; o‘qiladigan bo‘sh indeks yaroqli. Terminal ish maydoni (TUI) shu rejimda ishga tushirilib, hech bir mos indeks yuklanmasa, ish maydoni ochilmaydi. Rejim allaqachon ochiq TUI ish maydonida interaktiv tarzda tanlanib, hech bir mos indeks yuklanmasa, o‘zgarish rad etiladi va oxirgi ishlaydigan Git rejimi faol qoladi. Xuddi shu holatda to‘g‘ridan-to‘g‘ri buyruqlar siyosat yoki tekshiruv xatosi bilan tugaydi. DevProjex hech qachon yashirincha `.gitignore` ga o‘tmaydi. Boshqa mos indeks o‘qilsa, indeksini o‘qib bo‘lmaydigan ichki sohalar ogohlantirish bilan chiqariladi.

Allaqachon ochiq Desktop ish maydonida aniq tanlov ko‘rinib turadi va fail-closed ishlaydi: tayyorlik xatosida chiqarish va eksport bloklanadi, qisman tayyorlikda esa amal mahalliylashtirilgan ogohlantirish bilan davom etadi.

Git rejimlari o‘zaro istisno; `none` Git filtrlashni o‘chiradi. Vaqtinchalik `staged`, `changes` va `diff:<ref>..<ref>` rejimlari profillarda saqlanmaydi. Vaqtinchalik rejim faol bo‘lsa, GUI’dagi mahalliy loyiha profili oxirgi yoqilgan doimiy `gitignore` yoki `tracked` rejimini saqlab qoladi. `none` faqat saqlash vaqtida o‘zi faol bo‘lsa saqlanadi. TUI va CLI vaqtinchalik rejim faol bo‘lganda ko‘chma profilni saqlashni rad etadi.

### 12.7 Git filtrlashi va Smart Ignore aloqasi
Tanlangan Git rejimi va Smart Ignore mustaqil boshqariladi. Avval har bir erishiladigan Git hududida Git rejimi, keyin qolgan elementlarga Smart Ignore, oxirida esa asosiy qoidalar qo‘llanadi.

Tanlangan Git rejimi barcha Smart Ignore nomzodlarini qamrab turganda Smart Ignore yashirin bo‘lishi va Git rejimi o‘zgartirilgach yoki o‘chirilgach paydo bo‘lishi mumkin. Git repozitoriysida repozitoriyni talab qiladigan barcha Git rejimlari mavjud.

`!` Git inkori faqat Git natijasini bekor qiladi; u Smart Ignore yoki asosiy qoidani o‘chirmaydi.

### 12.8 Asosiy qoidalar
«Nuqtali jildlar» va «Nuqtali fayllar» element nomi nuqta bilan boshlanishini tekshiradi.

«Yashirin jildlar» va «Yashirin fayllar» tizimdagi Hidden atributini tekshiradi. Ayrim platformalarda nuqta bilan boshlanuvchi nom va tizim atributi bir xil yoki turli elementlarni tavsiflashi mumkin.

«Bo‘sh fayllar» hajmi 0 bayt bo‘lgan fayllarni yashiradi.

«Kengaytmasiz fayllar» `Dockerfile`, `Makefile` va `README` kabi fayllarni yashiradi.

«Bo‘sh jildlar» mantiqan bo‘sh jildlarni yashiradi. Tanlangan fayl turlari va barcha boshqa qoidalar qo‘llangach, jildda hech qanday ko‘rinadigan fayl yoki ichki jild qolmasa, u mantiqan bo‘sh hisoblanadi.

Shu sababli boshqa qoida almashtirilgach bo‘sh jildlar soni o‘zgarishi mumkin: fayllarni yashirish ularni o‘z ichiga olgan jildlarni mantiqan bo‘sh qilib qo‘yishi mumkin.

### 12.9 Hisoblagichlar
Qoida yonidagi son diskdagi o‘xshash elementlarning fizik sonini emas, joriy sozlamalarda uning bevosita hissasini ko‘rsatadi.

Bitta element bir vaqtning o‘zida bir nechta ustma-ust tushadigan hisoblagichga yozilmaydi. Masalan, `.git` jildi ham nuqta bilan boshlanuvchi nomga, ham tizimning Hidden atributiga ega bo‘lishi mumkin, lekin uning chiqarilishi faqat bitta qoidaga yoziladi.

Chiqarilish egasini tanlash uchun barqaror tartib ishlatiladi:

* jildlar: `.gitignore`, Smart Ignore, nuqta bilan boshlanuvchi nom, tizimning Hidden atributi;
* fayllar: `.gitignore`, Smart Ignore, nuqta bilan boshlanuvchi nom, kengaytma yo‘qligi, bo‘sh fayl, tizimning Hidden atributi.

Bu tartib faqat hisoblagichlarga ta’sir qiladi. Yakuniy ko‘rinish soddaroq qoidaga bo‘ysunadi: istalgan yoqilgan mexanizm elementni chiqarsa, u yashiriladi.

### 12.10 O‘zgarishlarni qo‘llash
Belgilash kataklarini almashtirish avval paneldagi mavjud sozlamalar va hisoblagichlarni yangilaydi. Yakuniy daraxt «Sozlamalarni qo‘llash» tanlangach qayta quriladi.

Sozlamalarni tayyorlash bekor qilinsa, DevProjex panelni oxirgi to‘liq yakunlangan holatga qaytaradi. Qisman hisoblangan qoidalar qo‘llanmaydi.

* daraxtda belgilash katagi orqali belgilangan tugunlar (tanlovga asoslangan amallar uchun)

Format:

* Belgilar

Muhim:

* aynan eksport konveyeri yaratadigan real daraxt matni bo‘yicha hisoblanadi;

Tarkib metrikalari:

* binar fayllar kiritilmaydi;
* bo‘sh va faqat bo‘sh joyli fayllar servis markerlari orqali hisoblanadi (`[No Content, 0 bytes]`, `[Whitespace, N bytes]`).

### 13.3 Hisoblagichlar qachon yangilanadi

* loyiha ochilgandan/yangilangandan keyin;
* sozlamalar qo‘llangandan keyin (istisnolar va fayl turlari);
* daraxtdagi belgilash kataklari o‘zgarganda (kechikish bilan);
* daraxt formati almashtirilganda (daraxt ishlatiladigan amallar uchun).
* fon hisoblash bekor qilinsa, keyingi to‘liq yakunlangan qayta hisoblashgacha hisoblagichlar 0 ga o‘rnatiladi.

## 15) Mavzu va effektlar
«Mavzu» bo‘limida Tizim, Yorug‘ yoki Qorong‘i rejim va bitta fon effektini tanlash mumkin:
* Shaffoflik
* Xiralashtirish
* Mica

Standart holatda Tizim rejimi tanlanadi va u operatsion tizim mavzusidagi o‘zgarishlarni kuzatadi. Birinchi ishga tushirishdan yoki sozlamalarni tiklashdan keyin tizimning yorug‘ mavzusi oddiy shaffof bo‘lmagan fon bilan, qorong‘i mavzusi esa Xiralashtirish bilan ishga tushadi. Tizim tanlovini aniqlab bo‘lmasa, DevProjex Qorong‘i rejimni Xiralashtirish bilan ishlatadi. Yorug‘ va Qorong‘i mavzular o‘z effektlarini alohida eslab qoladi. Yorug‘ yoki Qorong‘i rejimni aniq tanlash Tizim qayta tanlanmaguncha tizim o‘zgarishlarini e’tiborsiz qoldiradi.

Effektlar bir vaqtda ishlamaydi. Tanlangan effektni qayta bosish uni o‘chiradi va oddiy shaffof bo‘lmagan fonni qaytaradi.

Mavjud sozlamalar:
* Fon shaffofligi — Shaffoflik va Xiralashtirish rejimlarida mavjud.
* Yuqori panel kontrasti — ko‘rib chiqish, qidiruv, filtr va daraxt formati buyruqlari joylashgan asosiy panelni sozlaydi.
* Menyu shaffofligi — asosiy menyu va uning ichki menyulariga bir xil qo‘llanadi.
* Chegaralar ko‘rinishi — interfeys chegaralarining qanchalik aniq ko‘rinishini sozlaydi.

Mica platformaning tizim materialidan foydalanadi va fon shaffofligi uchun alohida sozlamaga ega emas. Tanlangan Xiralashtirish yoki Mica effekti mavjud bo‘lmasa, ilova avval boshqa tizim effektini sinab ko‘radi. Oddiy shaffof bo‘lmagan fon faqat ikkala effekt ham mavjud bo‘lmaganda ishlatiladi.

«Shaffoflik» rejimida asosiy oyna foni shaffof bo‘lib qoladi. Menyular, ichki menyular va boshqa ochiluvchi yuzalar, agar qo‘llab-quvvatlansa, Xiralashtirishdan foydalanadi, shunda ularning ortidagi daraxt va tarkib o‘qishga xalaqit bermaydi.

## 16) Yordam

### 16.1 Yangilanishlar
«Yordam → Yangilanishlar» joriy versiyani GitHub’dagi eng so‘nggi barqaror reliz bilan taqqoslaydi. Avtomatik tekshiruv standart holatda o‘chirilgan; u yoqilsa, DevProjex oxirgi muvaffaqiyatli tekshiruvdan kamida yetti kun o‘tganda ishga tushish vaqtida tekshiradi. Belgilash katagi darhol qo‘llanadi. Oxirgi muvaffaqiyatli natija dastur qayta ishga tushirilganda saqlanadi va keyingi tarmoq xatosi tufayli o‘chirilmaydi. O‘rnatishni foydalanuvchi o‘zi bajaradi.

### 16.2 Sozlamalarni tiklash
Sozlamalarni tiklash (Yordam → Sozlamalarni tiklash) mavzu, effektlar, ixcham rejim, animatsiya sozlamalari va interfeys tilini standart qiymatlarga qaytaradi. Loyiha profillari, tarix va diskdagi fayllar o‘zgartirilmaydi.

### 16.3 Ma’lumotlarni tiklash
Ma’lumotlarni tiklash (Yordam → Ma’lumotlarni tiklash) mahalliy loyiha parametrlarining saqlangan profillarini o‘chiradi:
* tanlangan fayl turlari;
* «Istisnolar» bo‘limidagi tanlangan qoidalar;
* tarkibga ishlov berishning tanlangan sozlamalari;
* qo‘lda qo‘yilgan maxfiy ma’lumot belgilari.

Shuningdek, agent jurnalining yakunlangan seanslari tozalanadi (19.3-bo‘lim); faol seanslar saqlanadi.

Muhim:
* mahalliy jildlar uchun «So‘nggi» tarixi tozalanmaydi;
* Git Clone oynasidagi «So‘nggi havolalar» tarixi tozalanmaydi;
* diskdagi loyiha fayllari va jildlari o‘zgartirilmaydi va o‘chirilmaydi.

## 17) Tillar
Til menyusi orqali tanlanadi.
Tanlangan til ilova qayta ishga tushirilganda saqlanadi. «Yordam → Sozlamalarni tiklash» saqlangan til tanlovini tozalaydi va interfeys tilini standart holatga qaytaradi.

## 18) Progress-bar va bekor qilish
Status-bar markazida faol amal va progress ko‘rsatiladi.

Progress rejimlari:
* Indeterminate — foizsiz (amal davomiyligi noma’lum).
* Determinate — foiz bilan (0–100).

Xulq-atvor:
* fon rejimida ma’lumot hisoblash vaqtida foizli progress ko‘rsatiladi;
* ayrim Git amallarida progress manbasi foiz berganda foiz ko‘rsatiladi;
* mavjud parametrlarni yangilash va sozlamalarni qo‘llash amal sezilarli vaqt olsa ko‘rsatiladi;
* tez amallar progressni ko‘rsatmasdan yakunlanadi.

Status-bardagi X (bekor qilish) tugmasi:
* bekor qilishni qo‘llaydigan amallar uchun best-effort bekor qilishni bajaradi;
* fon rejimidagi ma’lumot hisoblashni to‘xtatadi;
* mavjud parametrlarni yangilash bekor qilinganda panelni oxirgi yakunlangan holatiga qaytaradi;
* bekor qilishni qo‘llamaydigan amallarda status-bar indikatsiyasini tugatadi, lekin amal fon rejimida yakunlanishi mumkin.

## 19) MCP va AI agentlar
DevProjex tarkibida faqat o‘qish uchun mo‘ljallangan mahalliy MCP server bor. Claude Code, Codex, Cursor va VS Code kabi AI agentlar loyihani u orqali o‘qiydi: sirlarni maskalash doim yoqilgan, agent esa loyiha fayllarini o‘zgartira olmaydi. Serverda sakkizta vosita bor: `list_projects`, `get_tree`, `analyze`, `search_project`, `related_files`, `get_file`, `pack_context` va `read_pack`.

### 19.1 Mijozni ulash
MCP menyusida quyidagilar bor:
* Live context — server shu oynada belgilangan elementlarga amal qiladi (19.2-bo‘lim);
* Oddiy — server oynadagi tanlovga bog‘liq emas;
* Jurnal… — agentlar nimani so‘ragani va nimani olgani (19.3-bo‘lim);
* Hujjatlar — MCP server hujjatlarini ochadi.

Live context va Oddiy ichki menyularida bir xil amallar bor — Claude Code’da ochish, Codex’da ochish, Cursor’da ochish, VS Code’da ochish va Boshqa mijozlar… — ular loyiha ochiq bo‘lganda mavjud.

Claude Code va Codex o‘zlarining o‘rnatilgan buyrug‘i orqali ro‘yxatdan o‘tkaziladi, so‘ng mijoz loyiha jildida yangi terminalda ochiladi. Cursor va VS Code loyihaning mahalliy `.cursor/mcp.json` yoki `.vscode/mcp.json` faylini oladi; shu fayldagi boshqa serverlar saqlanadi. «Boshqa mijozlar…» Claude Desktop va boshqa mijozlar uchun tayyor konfiguratsiyani ko‘rsatadi. Mijoz buyrug‘i topilmasa yoki ulanish muvaffaqiyatsiz bo‘lsa, DevProjex buning o‘rniga qo‘lda sozlash konfiguratsiyasini ko‘rsatadi. Muvaffaqiyatli ulanishdan keyin DevProjex `devprojex` buyrug‘ini PATH’ga qo‘shishni taklif qilishi mumkin.

Codex bitta umumiy DevProjex ulanishini saqlaydi, shuning uchun boshqa loyihani ulashda uni almashtirishdan oldin tasdiq so‘raladi. Allaqachon ishlayotgan mijoz seansi serverni yuklashi uchun qayta ishga tushirilishi kerak. Terminalda `devprojex mcp connect` odatda oddiy rejimni ro‘yxatdan o‘tkazadi; Live context uchun `--mode live`, faqat konfiguratsiyani chiqarish uchun esa `--print` qo‘shing.

### 19.2 Live context
Live context rejimida daraxtda belgilangan elementlar agentning diqqat markazini belgilaydi: daraxt, qidiruv, tahlil, bog‘liq fayllar va jamlash so‘rovlari ular doirasida qoladi. Oyna filtrlari — fayl turlari, istisnolar va Git rejimi — kirish chegarasi hisoblanadi: agent boshqa fayllarni nomi bo‘yicha ocha oladi, lekin faqat shu filtrlar ruxsat bergan fayllarni.

Oyna ochiq turishi shart emas. Server har bir so‘rovda loyiha uchun oxirgi saqlangan tanlovni o‘qiydi, shuning uchun yangi belgilar va qo‘llangan sozlamalar agentni qayta ishga tushirmasdan uning keyingi so‘rovida hisobga olinadi.

Jonli seans faol bo‘lganda oyna sarlavhasi `· Live context (<client>)` bilan, bir nechta seans faol bo‘lsa esa seanslar soni bilan tugaydi.

### 19.3 Jurnal
«MCP → Jurnal…» agentlar DevProjex orqali nimani so‘ragani va nimani olganini ko‘rsatadi: mijoz, rejim, chaqiruvlar, belgilar, taxminiy tokenlar, yetkazilgan fayllar va maskalangan qiymatlar ko‘rsatilgan seanslar hamda tanlangan seansning chaqiruvlari. U loyiha ochilmaganda ham mavjud; loyiha ochiq bo‘lsa, odatda «Faqat joriy loyiha» tanlangan bo‘ladi.

Jurnal faqat shu kompyuterda, DevProjex holat jildida saqlanadi va 30 kun davomida ko‘pi bilan 200 ta seansni saqlaydi. Unda fayl tarkibi, topilgan sir qiymatlari yoki qidiruv so‘rovlari matni saqlanmaydi. «Eksport…» seansni Markdown yoki JSON kvitansiyasi sifatida saqlaydi. «Tozalash» tasdiqlangandan keyin yakunlangan seanslarni o‘chiradi; faol seanslar va boshqa loyihalar bilan umumiy seanslar saqlanadi.

### 19.4 Agent faolligi
«Ko‘rinish → Agent faolligi» odatda o‘chirilgan: belgilarni yoqish uchun ushbu bandni tanlang, o‘chirish uchun esa uni yana tanlang. U yoqilgan va jonli seans faol bo‘lganda, agent shu seansda tarkibini olgan har bir fayl — butun fayl, qatorlar oralig‘i, qidiruv mosliklari yoki e’lon — daraxtda ✦ bilan belgilanadi. Agent faqat daraxt ro‘yxatida yoki hajm bahosida ko‘rgan fayl belgilanmaydi. Agent faylni necha marta olganini ko‘rish uchun kursorni ✦ ustiga olib boring, masalan: «Agent 3 marta oldi».

Belgilar faqat nima yetkazilganini ko‘rsatadi: ular belgilash kataklarini, filtrlarni yoki agent o‘qiy oladigan narsalarni hech qachon o‘zgartirmaydi. Ular yangi jonli seans boshlanganda, jonli seans tugaganda, Agent faolligi o‘chirilganda va loyiha qayta ochilganda tozalanadi; shundan keyin agent olgan fayllar yana belgilanadi. Oddiy seanslar jurnalda ko‘rinadi, lekin belgi qo‘shmaydi.

Terminal ish maydonida `:set activity on` xuddi shu fayllarni daraxtda A harfi bilan belgilaydi, bunday fayl fokusda bo‘lganda esa holat satri agent uni necha marta olganini ko‘rsatadi; `:set activity off` belgilarni olib tashlaydi.
