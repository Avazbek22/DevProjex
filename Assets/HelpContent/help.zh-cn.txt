## 1) 它是什么以及为什么
DevProjex可快速准备项目上下文：显示文件夹/文件结构，允许您用复选框选择项目，并将树和/或文件内容复制到剪贴板。适用于代码审查、技术支持、学习，以及与AI助手共享项目结构。

重要提示：DevProjex不会修改您打开的项目中的文件。唯一的例外是为Cursor或VS Code显式建立MCP连接，此时会创建或更新`.cursor/mcp.json`或`.vscode/mcp.json`（第19.1节）。

## 2) 项目树
* 文件/文件夹类型图标。
* 节点上的复选框。
* 展开/折叠。

复选框：选择一个节点会作用于其子节点；父节点的状态会自动重新计算。

热键：
* {mod}E — 全部展开
* {collapseAll} — 全部折叠（根节点保持展开）

### 上下文菜单
右键单击节点，或在获得焦点的节点上按{shift}F10或菜单键：
* 在文件资源管理器中显示/在Finder中显示/在文件管理器中打开 — 在系统文件管理器中显示该项目；标签与当前平台一致。
* 复制完整路径 — 项目的绝对路径。
* 复制相对路径 — 从项目根目录开始、以根文件夹名称开头的路径，例如`project/src/File.cs`。
* 复制内容 — 针对文件：复制应用了内容转换后的内容，与复制和导出生成的结果完全一致。
* 仅选择此项 — 只选中此节点并清除其余选择；仅当还有其他项目被选中时才显示。
* 展开分支/折叠分支 — 用于文件夹。

如果该路径在磁盘上已不存在，在文件管理器中打开该项目或复制其内容会显示错误消息；复制路径仍然可用。

## 3) 文件
* 打开文件夹... — 打开根文件夹（{mod}O）
* 新窗口 — 打开一个新的独立DevProjex实例
* 最近使用 — 最近打开的本地文件夹列表
* 刷新 — 重新扫描本地文件夹并重建树（F5）
* 导出到文件：
  * 导出树
  * 导出内容
  * 导出树和内容
* 导出项目：
  * 到文件夹…
  * 到ZIP压缩包…

“导出项目”会根据当前树创建一个单独的文件夹或ZIP压缩包，并保留目录结构。

会遵循所选的文件类型、排除规则和选中的项目。如果没有选中任何项目，则导出整个当前树。

文本文件和二进制文件都会被复制，包含在内的空文件夹也会保留。源文件不会被修改。结果不能保存在源项目内部。

导出期间，您无法更改树或设置、使用过滤器、更改格式或预览模式、运行Git命令、刷新或打开其他项目。

格式规则：
* 导出树：
  * ASCII -> 仅`.txt`。
  * JSON -> 默认`.json`，“保存”对话框中可选`.json`和`.txt`。
  * XML -> 默认`.xml`，“保存”对话框中可选`.xml`和`.txt`。
  * MD -> 默认`.md`，“保存”对话框中可选`.md`和`.txt`。
* 导出内容 — 始终为文本内容格式，`.txt`文件（树格式切换不适用）。
* 导出树和内容 — 始终为`.txt`文件；所选树格式只影响结果中树块的格式。

导出文件以不带BOM的UTF-8编码写入。

### 拖放
未加载项目时，可在启动区域（Drop Zone）中拖放。

规则：
* 可以拖放文件夹；
* 可以拖放文件——此时会打开其所在的文件夹；
* 如果拖放了多个项目，则使用第一个合适的本地路径；
* 如果路径不可用或不存在，则执行与“打开文件夹...”相同的访问检查；
* 不支持的项目或非本地项目会被忽略。

### 最近使用
“文件→最近使用”显示最近打开的本地文件夹的历史记录。

规则：
* 只有本地文件夹会被添加到列表中；
* 通过DevProjex克隆的Git存储库不会添加到此列表中；
* 不会产生重复项——再次打开同一文件夹会将其移到顶部；
* 最多保存32个最近使用的文件夹；
* 历史记录在应用程序多次启动之间保留。

每一项都显示父文件夹和项目名称，例如`Projects / App`。

## 4) 从终端启动
DevProjex提供交互式终端工作区，以及面向脚本和CI的直接命令。

如果命令已设置，请打开终端并运行：
`devprojex --help`

此命令会列出顶级命令和选项。运行`devprojex help <command>`可查看该命令自身的选项和示例。

示例：
* `devprojex` — 打开交互式终端工作区。在工作区中，可通过`:`命令行执行操作（例如`:copy`、`:analyze`、`:branch`、`:language`）；完整命令列表请参阅内置的工作区帮助和项目文档。
* `devprojex tui .` — 直接在终端工作区中打开指定的文件夹。
* `devprojex open . --preview` — 在桌面版的预览中打开当前文件夹。
* `devprojex analyze . --format json` — 以JSON格式分析当前项目。
* `devprojex tree .` — 将项目树打印到终端。
* `devprojex export context . --format markdown -o ../devprojex-context.md` — 在源项目外部保存可直接用于AI的上下文。
* `devprojex export project . --as folder -o ../devprojex-submission` — 将有效项目树导出到指定的文件夹。
* `devprojex export project . --as zip -o ../devprojex-submission.zip` — 将有效项目树导出为ZIP压缩包。
* `devprojex export context https://github.com/owner/repo -o -` — 打包远程存储库，无需自行克隆。
* `devprojex analyze . --git-mode tracked --exclude smart-ignore` — 结合智能忽略分析已跟踪的Git文件。
* `devprojex search Configure . --symbols` — 查找声明的定义位置；`--symbols`接受声明名称并拒绝正则表达式语法，而`--regex`使用正则表达式搜索文本。
* `devprojex related src/App.cs` — 列出某个文件使用的文件以及使用该文件的文件。
* `devprojex mcp --root .` — 启动本地只读MCP服务器，以便AI代理安全地读取项目。
* `devprojex mcp connect . --client claude-code` — 将AI客户端连接到项目（第19节）。
* `devprojex mcp log . --last` — 显示最近一次代理日志会话。

注意：
* `.`表示当前终端文件夹；
* 包含空格的路径必须用引号括起来；
* `--git-mode`可选择`none`、`gitignore`、`tracked`、`staged`、`changes`或`diff:<ref>..<ref>`；
* `--exclude`独立于Git过滤，单独控制普通排除项；
* 分析和导出命令的结果是确定性的，并且不会打开桌面版界面；
* `tui`、`open`、`analyze`、`search`、`tree`以及两个`export`命令也接受Git存储库URL，`related`则通过`--project`接受URL；克隆会存入托管缓存（`devprojex cache`）；
* 命令具有文档记录的别名和短选项——例如`export ctx`、`-f`、`-n`；`devprojex help`会列出它们；
* `analyze --findings`列出脱敏检测结果但不显示其值，`--fail-on-findings`会为CI返回非零退出代码；
* `export context --max-tokens N`将上下文控制在词元预算之内，实验性的`--rank importance`会优先纳入最重要的文件；
* 分析、搜索和导出命令不会修改项目文件——DevProjex以只读模式工作。

如果`devprojex`命令不起作用，请在DevProjex中打开：
“帮助→从终端启动”。

## 5) Git
“Git→克隆存储库...”会将存储库克隆到DevProjex缓存中并打开它。“分支”和“获取更新”仅适用于以这种方式克隆的项目。应用程序不会触碰您的文件——它只使用缓存。

缓存存储在用户的系统缓存目录中。运行`devprojex doctor`可查看解析后的路径。

* 分支 — 显示可用分支列表并标记当前分支；切换后，树会更新为所选分支。如果分支已存在于本地，则离线切换（不更新）。如果本地不存在，则会获取并创建该分支。
* 获取更新 — 仅更新当前分支：执行fetch并重置为origin/<branch>。对于克隆的项目，F5执行相同的操作；常规的“文件→刷新”命令会被禁用。

### 克隆窗口
在克隆存储库窗口中，URL字段下方可能会出现“最近的链接”列表。

规则：
* 仅当历史记录中已有最近克隆的存储库时，才会显示该列表；
* 只有网络存储库源（`https://`、`ssh://`以及SCP语法）会被添加到列表中；
* 本地路径和`file://`源不会添加到此列表中；
* 不会产生重复项——再次克隆同一存储库会将其移到顶部；
* 最多保存16个最近的存储库；
* 历史记录在应用程序多次启动之间保留。

选择某一项会自动填充URL字段。
克隆进行期间，该列表会暂时隐藏。

## 6) 复制
### 树格式切换（ASCII / JSON / XML / MD）
该切换决定树作为输出一部分时所用的表示格式。

* ASCII — 带分支线的文本树。
* JSON — JSON格式的结构化树。
* XML — 适用于解析器和工具的紧凑XML树。
* MD — 适用于文档和AI提示词的Markdown嵌套列表。

切换会影响：
* 复制树
* 复制树和内容
* 导出树
* 导出树和内容

切换不影响：
* 复制内容
* 导出内容

### 复制树
复制项目树。
如果有选中的节点，则根据选择构建树；如果选择为空或无效，则复制完整的树。
结果格式由树格式切换决定。
热键：{mod}{shift}C和{mod}{alt}C。

### 复制内容
复制文件内容：
* 如果选中了文件，则只复制这些文件；否则复制项目的所有文件；
* 每个文件前都有一个包含其完整本地路径的标头（对于克隆的项目，为存储库的Web路径）；
* 非文本文件（包括二进制文件）会被忽略；
* 对于空文本文件，输出路径和`[No Content, 0 bytes]`行；
* 对于仅包含空白/换行符的文件，输出路径和`[Whitespace, N bytes]`行。
热键：{mod}{alt}V。

### 复制树和内容
组合树和内容：
* 树根据选择构建；如果选择为空或无效，则使用完整的树；
* 内容遵循与“复制内容”相同的规则；
* 树块的格式由树格式切换决定。
热键：{mod}{shift}V。

### 树表示
不同的树格式以不同方式表示同一棵所选项目树。

JSON：
* `rootPath` — 以`/`规范化的绝对根路径。
* `tree` — 根文件夹的内容。
* JSON导出使用这种树格式：数组包含文件，对象包含子文件夹，`/`包含当前文件夹中的文件，`[]`表示空文件夹。

XML：
* 根节点为`<t r="...">`；
* 文件夹为`<d n="...">`；
* 文件为`<f>File.cs</f>`。

MD：
* 以`Root: ...`开头；
* 使用Markdown嵌套列表；
* 文件夹以`/`结尾。

树和内容：
* 所选树格式适用于树块；
* 内容块仍为文本；
* 内容块中的文件标头使用以`/`分隔的相对路径；
* 导出为`.txt`。

## 7) 预览模式
使用顶部栏中的眼睛图标按钮或{mod}B打开。

鼠标侧键采用浏览器式导航：“前进”打开预览模式，“后退”关闭预览模式。重复当前方向不起作用。

{mod}{shift}F在预览中打开或关闭文件内容搜索。Enter或F3转到下一个匹配项；{shift}Enter或{shift}F3转到上一个匹配项。

在树旁边的独立工作区中显示最终结果。此模式本身不会复制到剪贴板，也不会导出到文件——它是一种查看模式。

默认情况下，工作区布局为：
* 左侧 — 项目树；
* 中间 — 预览窗格；
* 右侧 — 设置面板（如果之前已打开）。

可用模式：
* 树
* 内容
* 树+内容

应用与复制和导出相同的规则：
* 遵循选中的节点；
* 如果选择为空，则使用完整数据集；
* 应用当前的忽略规则和选择选项。

此外：
* 预览中的文件之间用水平线分隔；
* 滚动时，当前文件的路径固定在顶部；单击固定的路径会滚动回该文件的开头；
* 预览滚动条会标记搜索匹配项和带有脱敏检测结果的行；单击标记会跳转到对应行；保持原样的检测结果仍会被标记，被遮蔽的路径标头会在其第一行添加一个标记；
* 树和预览可以分别缩放。
* 在预览模式下，无需打开“复制”菜单即可复制完整的当前结果或当前可见的文件块。

按钮：
* 顶部预览岛左侧的复制按钮 — 复制当前预览模式的内容：
  * 树
  * 内容
  * 树+内容
* 树窗格中的X — 隐藏树，只保留预览窗格；
* 顶部预览窗格中的X — 完全关闭预览模式；
* 固定文件标头中的小复制按钮 — 按预览中显示的样子复制当前可见的文件块；
* 再次单击眼睛图标或按{mod}B也会关闭预览模式。

预览中树窗格可见时，可以使用搜索和过滤。
如果树被隐藏，搜索和过滤会暂时不可用，直到您退出仅预览模式。

## 8) 视图
### 缩放
* {mod}+ / {mod}= — 放大
* {mod}- — 缩小
* {mod}0 — 重置
* {mod}+鼠标滚轮 — 平滑缩放光标下方的窗格

行为：
* 在普通模式下，缩放树；
* 在树可见的预览中，菜单中的“放大”“缩小”和“重置缩放”同时作用于树和预览；
* 使用{mod}+鼠标滚轮时，树和预览根据光标所在位置分别缩放；
* 在仅预览模式下，只缩放预览窗格。

范围：6–28，重置值为15。

### 紧凑模式
使界面更紧凑：树和设置中的间距更小。
预览工作区处于活动状态时，会自动启用紧凑模式。

### 动画
“视图→动画”可分别控制树展开、状态计数器和工具首次显示的动画。三种动画默认均已启用；禁用某种动画后，会立即显示其最终状态。

### 树字体
通过“视图→树字体”选择树字体。
“默认”恢复标准树字体。
在设置面板中单击“应用设置”后，所选字体才会生效。

### 代理活动
“视图→代理活动”会标记AI代理在实时MCP会话中收到的文件；请参阅第19.4节。

## 9) 搜索（树）
打开搜索栏，突出显示匹配项并支持在其间导航。
* {mod}F — 显示/隐藏
* Enter — 下一个结果
* {shift}Enter — 上一个结果
* Esc — 关闭

搜索只展开所需的分支；清除查询会折叠树（根节点除外）。
匹配行也会标记在树的滚动条上；单击标记即可跳转到该匹配项。
匹配项非常多时，应用程序可能会限制自动展开和全局突出显示，以保持界面响应。
关闭搜索栏时，查询会在关闭动画完成后被清除。

限制：
* 打开搜索会自动关闭过滤；
* 预览中树窗格可见时，可以使用搜索；
* 如果树被隐藏，搜索暂时不可用。

## 10) 过滤（按名称）
仅显示与过滤字符串匹配的节点及其父节点。更新会经过防抖处理。
* {mod}{shift}N — 显示/隐藏过滤
* Esc — 关闭过滤

限制：
* 打开过滤会自动关闭搜索；
* 预览中树窗格可见时，可以使用过滤；
* 如果树被隐藏，过滤暂时不可用。

## 11) 选项（设置面板）
位于右侧：
* 应用设置
* 内容处理
* 排除项
* 文件类型

“排除项”和“文件类型”中的更改会先暂存在面板中，单击“应用设置”后才会应用。

复选框更改后，应用程序可能会在后台更新可用选项及其计数。只有单击“应用设置”后才会重建最终的树。

如果使用状态栏中的X按钮取消可用选项的更新，未完成的更改不会被应用，面板会恢复到上次完成的状态。

每个列表都有“全部”切换开关。

关于“文件类型”的说明：
* 此列表只显示带扩展名的文件；
* 没有扩展名的文件不会添加到此列表中，而是由“排除项”中的单独选项控制。

内容处理：
* 转换所选文本文件的内容，而不更改树；
* “隐藏机密信息”和“隐藏个人数据”会替换检测到的值（第12.3节和第12.4节）；
* “压缩代码”在14种语言中保留声明，同时精简具名实现；
* “移除注释”在20个语言包中删除注释和文档注释；
* “移除空白行”在同样的语言包中删除仅含空白的行，同时保留多行字面量；
* 更改在单击“应用设置”后生效。

{mod}P — 显示/隐藏面板。

### 11.1 本地项目参数配置文件
对于本地文件夹，DevProjex会记住上次应用的项目参数：
* 所选的文件类型；
* “排除项”部分中所选的选项。

单击“应用设置”时执行保存。
再次打开同一本地文件夹时，会自动恢复这些参数。

重要：
* 只为本地项目保存配置文件；
* 对于通过克隆打开的项目，不保存配置文件；
* 如果某些已保存的选项在当前项目中已不可用，则跳过这些选项，并应用其余参数。
* 如果刷新或重新打开后在“排除项”中出现新的文件类型或选项，则默认启用；
* 已出现过的选项会保留用户的明确选择：被禁用类型的新文件不会让该类型重新启用。

## 12) 排除项
“排除项”部分控制从树、内容、复制和导出结果中排除哪些文件和文件夹。

只有同时满足以下所有条件时，项目才会显示：
* 如果文件有类型，其文件类型已被选中；
* 没有任何已启用的忽略规则将其排除。

忽略规则是累积的。只要有一条已启用的规则隐藏了某个项目，其他规则就无法让它重新可见。

### 12.1 可用规则
根据项目内容，可能会显示以下选项：

* 智能忽略
* 空文件夹
* 空文件
* 隐藏文件夹
* 隐藏文件
* 点文件夹
* 点文件
* 没有扩展名的文件

当Git过滤不适用时（不存在存储库边界，并且`.gitignore`过滤器无法改变当前树），GUI选择器和TUI中的Git轴单选行会完全隐藏。在存储库之外仍显示该轴时，GUI只提供不过滤和`.gitignore`，而TUI会禁用需要存储库的行。在Git存储库中有五个常规值：不过滤、`.gitignore`、已跟踪的文件、已暂存的文件和所有当前更改；在TUI中，处于活动状态的`diff:<ref>..<ref>`范围显示为第六行。选择一个值只会替换当前Git模式，不会更改智能忽略或基本排除项。其他选项会在其规则可能改变当前树时显示，因此在切换其他规则或文件类型后，列表可能会发生变化。

新选项首次出现时默认启用。已知选项即使暂时从列表中消失，也会保留用户的选择。

### 12.2 智能忽略
智能忽略（Smart Ignore）会隐藏依赖项、构建输出、缓存以及其他项目服务产物。

DevProjex首先根据项目结构和标记文件识别项目类型，例如：

* `.csproj`
* `package.json`
* `pyproject.toml`
* `Cargo.toml`

然后在检测到的项目范围内应用相应技术栈的规则。例如，.NET规则不会延伸到相邻的Python或JavaScript项目中。

仅凭文件夹名称并不总是足够的。`build`、`vendor`、`packages`、`cache`、`pkg`或`Library`等含义模糊的名称还会通过其内容加以验证。这可以防止普通用户文件夹仅因名称相似而被隐藏。

即使在明确检测到的项目之外，某些依赖项存储和服务目录也能通过其特有的内部结构被识别出来。

项目范围的发现是有界的，因此加载大型用户文件夹不会变成对每个目录的完整重复分析。常规结构使用浅层发现，而已识别的单体仓库（monorepo）会进行更深的搜索。找到范围后，智能忽略会应用于其整个子树，不受深度限制。

### 12.3 隐藏机密信息
“隐藏机密信息”默认关闭。它只扫描所选的文本内容，并就地替换每个检测到的值，同时保留文件及其周围的代码。该选项关闭时不会进行扫描，也不显示计数。扫描当前选择后，标签会显示检测到的值的数量；如果“保持原样”的决定使隐藏的值变少，则显示“检测到/已隐藏”，该行的“?”指示器会报告这两个计数。

被遮蔽的范围会在预览中突出显示。单击其中一处可仅将该处保持原样；{alt}↓ / {alt}↑在检测结果之间移动，Enter切换当前结果。在终端工作区中，使用`[`和`]`在各处之间移动，使用`Enter`或`Space`切换当前结果。该决定适用于当前会话中的预览、剪贴板、上下文导出、文件夹副本和ZIP，但不会保存到项目配置文件中。

预览的上下文菜单扩展了这些决定。右键单击检测到的某处，可一次性将同一规则的所有结果或同一文件中的所有检测结果保持原样或重新隐藏。要手动标记文件内容中选中的值，请右键单击它：“在此处隐藏…”仅在当前会话中隐藏这一处，“始终隐藏…”为该值的每次出现创建持久标记，“将…标记为个人数据并隐藏”则创建由“隐藏个人数据”控制的持久标记。“移除标记”会出现在手动标记上并将其删除；检测器仍能匹配的值会继续隐藏。手动标记的值必须是在文件内容中选中的单行文本，长度为8到512个字符。创建标记会自动启用相应的选项。持久标记只存储经过密钥处理的值标识及其类别，绝不存储原始文本。

文件夹或ZIP副本也会更改匹配的文本，因此可能无法再构建或运行。二进制文件会原样复制，且不会被扫描。超过16 MiB的选定文本文件会被省略并报告，其余输出仍会完成。检测失败会中止整个操作。

计数只报告规则匹配。计数为零并不意味着项目是安全的。CLI使用`--hide-secrets`；技术细节和限制见`Docs/HideSecrets.md`。

### 12.4 隐藏个人数据
“隐藏个人数据”默认关闭。它会检测所选文本文件中的电子邮件地址、全局IP地址、路径中的本地用户名、MAC地址和国际电话号码。检测结果使用与“隐藏机密信息”相同的预览决定和输出管道；通过“将…标记为个人数据并隐藏”创建的手动标记也属于此类，并受此开关控制（第12.3节）。生成的路径标头和树根中的本地用户名会作为一个共享结果被遮蔽：计数器将其计为一个值，“?”指示器报告它是隐藏还是显示，单击一次即可切换所有被遮蔽的路径。

文档专用的地址范围和主机、常见的CI用户名、知名的公共DNS解析器以及文档中记载的虚构电话号码段保持可见。零匹配并不代表隐私得到保证。CLI使用`--hide-private-data`；完整规则和第一阶段的限制见`Docs/HidePrivateData.md`。

### 12.5 使用.gitignore
启用后，DevProjex遵循`git status`的工作树视图：已跟踪的文件保持可见，未跟踪的文件只要未被存储库的忽略规则排除就会显示。它会应用每个可访问的`.gitignore`，而不仅是打开的文件夹根目录下的那个，其中也包括其上方直到存储库根目录的文件。

每个`.gitignore`适用于：

* 包含它的文件夹；
* 其下方所有可访问的文件夹；
* 且仅限于该范围之内。

嵌套`.gitignore`中的规则不会影响父文件夹或同级文件夹。

对于特定路径，规则从上层的`.gitignore`向更深层的文件依次处理。在同一个文件中，规则从上到下处理。最后一条匹配的规则决定Git结果。

以`!`开头的规则只在其范围内取消之前的Git排除。只要父文件夹仍被排除，它就无法恢复其中的文件。位于完全被排除且无法访问的文件夹中的`.gitignore`不参与计算。

格式错误或不受支持的行会被单独跳过。该文件中的其他有效规则以及相邻范围中的规则继续生效。

存储库本地的`.git/info/exclude`文件同样会被应用，其优先级低于根目录的`.gitignore`。带有自己`.git`的嵌套文件夹同样遵循`git status`：未在`.gitmodules`中声明的嵌入式存储库是不透明的，因此不会显示其中的文件；而已声明的子模块会应用其自身的`.gitignore`和`info/exclude`。选择`none`可查看嵌入式存储库中的文件。全局Git排除规则（`core.excludesFile`）不会被应用；存储库实际生效的路径比较设置会得到遵循，例如`core.ignoreCase`，以及macOS上的`core.precomposeUnicode`。名为`.gitignore`的符号链接不会被跟随，这与Git对控制文件的处理方式一致。如果某个`.gitignore`或`info/exclude`文件无法读取，其目录范围会以失败即关闭的方式被排除，扫描会报告部分访问，而不是在规则未完整计算的情况下悄悄包含文件。当路径所属存储库范围的索引可读时，已跟踪的文件即使匹配`.gitignore`也仍然可见；如果没有该索引或Git CLI，该范围会安全地退回到仅按模式计算。

内置的`standard`配置文件选择`gitignore`，以及`smart-ignore`、`hidden-folders`、`hidden-files`、`dot-folders`、`dot-files`、`empty-folders`、`empty-files`和`extensionless-files`。

### 12.6 仅已跟踪的Git文件
“仅已跟踪的Git文件”根据每个可读Git索引中记录的、实际存在的工作树文件构建树的Git阶段。已修改的已跟踪文件和已暂存的新增文件仍会包含在内；未跟踪的文件会被排除。这是当前的工作树，而不是`HEAD`或远程存储库的历史快照。

每个存储库都独立解析：打开的文件夹中的同级存储库和已声明的子模块各自使用自己的索引，子存储库不会从其父存储库或同级存储库继承已跟踪的路径。未在`.gitmodules`中声明的嵌入式存储库保持不透明，与`.gitignore`模式相同。此模式需要Git CLI；可读的空索引也是有效的。如果终端工作区（TUI）以此模式启动且无法加载适用的索引，则工作区不会打开。如果在已打开的TUI工作区中以交互方式选择此模式且无法加载适用的索引，则更改会被拒绝，最后一个可用的Git模式保持活动状态。在同样的情况下，直接命令会返回策略失败或检查失败。DevProjex绝不会悄悄退回到`.gitignore`。如果另一个适用的索引可读，则不可用的嵌套范围会被排除并显示警告。

在已打开的桌面版工作区中，显式选择的已跟踪模式保持可见，并以失败即关闭的方式工作：准备失败时会阻止输出和导出，部分准备完成时则会继续并显示本地化的警告。

各Git模式互斥；`none`会禁用Git过滤。临时的`staged`、`changes`和`diff:<ref>..<ref>`模式不会保存到配置文件中。临时模式处于活动状态时，GUI的本地项目配置文件会保留上次启用的持久模式`gitignore`或`tracked`。只有在保存时`none`本身处于活动状态，才会保存`none`。临时模式处于活动状态时，TUI和CLI会拒绝保存便携式配置文件。

### 12.7 Git过滤与智能忽略的关系
所选的Git模式和智能忽略是相互独立的控件。Git模式首先在每个可访问的Git范围内应用，然后由智能忽略处理剩余的项目，最后运行基本规则。

当所选的Git模式已经覆盖了智能忽略的所有候选项时，智能忽略选项可能保持隐藏，并在更改或清除Git模式后出现。在Git存储库中，所有基于存储库的Git模式都可用。

以`!`开头的Git否定规则只取消Git结果，不会禁用智能忽略或基本规则。

### 12.8 基本规则
“点文件夹”和“点文件”检查项目名称。

“隐藏文件夹”和“隐藏文件”检查系统隐藏属性。在某些平台上，以点开头的名称和系统属性可能描述同一个项目，也可能描述不同的项目。

“空文件”隐藏大小为0字节的文件。

“没有扩展名的文件”隐藏`Dockerfile`、`Makefile`和`README`之类的文件。

“空文件夹”隐藏逻辑上为空的文件夹。如果在应用所选文件类型和所有其他规则后，文件夹中不再有可见的文件或子文件夹，则该文件夹在逻辑上为空。

因此，切换其他规则后，空文件夹的计数可能会发生变化：隐藏文件可能使包含它们的文件夹在逻辑上变为空。

### 12.9 计数器
规则旁的计数显示该规则在当前设置下的直接贡献，而不是磁盘上同类项目的实际数量。

同一个项目不会同时计入多个重叠的计数器。例如，`.git`文件夹可能既有以点开头的名称，又有系统隐藏属性，但它的排除只归属于一条规则。

选择排除归属规则时使用固定顺序：

* 文件夹：`.gitignore`、智能忽略、以点开头的名称、系统隐藏属性；
* 文件：`.gitignore`、智能忽略、以点开头的名称、无扩展名、空文件、系统隐藏属性。

此顺序只影响计数器。最终可见性遵循更简单的规则：只要任何已启用的机制排除了某个项目，该项目就会被隐藏。

### 12.10 应用更改
切换复选框会先更新面板中的可用设置和计数器。选择“应用设置”后才会重建最终的树。

如果设置准备被取消，DevProjex会将面板恢复到上次完全完成的状态。部分计算的规则不会被应用。

## 13) 树和指标的计算方式
结果取决于：
* 所选的文件类型
* 忽略规则
* 当前的过滤
* 树中选中的节点（用于基于选择的操作）

如果访问被拒绝，节点保留其通常的名称和图标，并带有“[拒绝访问]”后缀。

### 13.1 状态栏计数器显示的内容
状态栏有两个块：
* 树 — 树文本输出的指标；
* 内容 — 导出的文件内容输出的指标。

格式：
* 行数
* 字符
* ≈词元（近似值）

较大的值以紧凑后缀（K/M）显示。

重要：
* “树”块中的“行数”表示最终树表示中的行数，而不是磁盘上的文件数；
* 该值包括文件夹、文件和树的服务元素（例如访问被拒绝的节点）。

### 13.2 指标的计算方式
树指标：
* 根据同一导出管道生成的实际树输出计算；
* 遵循当前的树格式。

内容指标：
* 遵循与内容复制/导出相同的规则；
* 排除二进制文件；
* 空文件和仅含空白的文件通过服务标记计数（`[No Content, 0 bytes]`、`[Whitespace, N bytes]`）。

### 13.3 计数器何时更新
在以下情况下重新计算：
* 打开/刷新项目后；
* 应用设置（排除项和文件类型）后；
* 树的复选框发生变化时（带防抖）；
* 切换树格式时（针对使用树输出的操作）。
* 后台计算被取消时，计数器会被设为0，直到下一次重新计算完成。

## 14) 图标
图标选择顺序：
1) 节点类型（文件夹/文件）
2) 精确名称（如果存在对应规则）
3) 扩展名
4) 否则为未知

## 15) 主题和效果
“主题”部分可选择系统、浅色或深色，以及一种背景效果：
* 透明度
* 模糊
* Mica

默认选择“系统”，并跟随操作系统的主题变化。首次启动或重置设置后，浅色系统主题以常规不透明背景启动，深色系统主题则以“模糊”启动。如果无法确定系统偏好，DevProjex会使用“深色”加“模糊”。浅色和深色会分别记住各自的效果。显式选择浅色或深色后，会忽略系统变化，直到再次选择“系统”。

各效果互斥。再次单击已选中的效果会将其禁用，并恢复常规的不透明背景。

可用设置：
* 背景透明度 — 适用于“透明度”和“模糊”。
* 顶栏对比度 — 调整包含预览、搜索、过滤和树格式命令的主面板。
* 菜单透明度 — 同样作用于主菜单及其子菜单。
* 边框可见性 — 调整界面边框的显示强度。

Mica使用平台的系统材质，没有单独的背景透明度设置。如果所选的“模糊”或Mica效果不可用，应用程序会先尝试另一种原生效果。只有在“模糊”和Mica都不可用时，才使用常规不透明背景。

在“透明度”模式下，主窗口背景保持透明。菜单、子菜单和其他弹出界面在支持时会使用“模糊”，以免其后方的树和内容元素影响可读性。

## 16) 帮助

### 16.1 更新
“帮助→更新”会将当前版本与GitHub上最新的稳定版本进行比较。自动检查默认关闭；启用后，DevProjex会在距上次成功检查至少7天后于启动时检查。该复选框立即生效。最近一次成功的结果会在应用程序多次运行之间保留，不会被之后的网络故障清除。安装仍由用户执行。

### 16.2 重置设置
重置设置（帮助→重置设置）会恢复默认的主题、效果、紧凑模式、动画设置和界面语言。项目配置文件、历史记录和磁盘上的文件不会更改。

### 16.3 重置数据
重置数据（帮助→重置数据）会删除已保存的本地项目参数配置文件：
* 所选的文件类型；
* “排除项”部分中所选的选项；
* 所选的内容处理设置；
* 手动机密标记。

它还会清除已完成的代理日志会话（第19.3节）；活动会话会保留。

重要：
* 本地文件夹的“最近使用”历史记录不会被清除；
* 克隆存储库窗口中的“最近的链接”历史记录不会被清除；
* 磁盘上的文件和文件夹不会被修改或删除。

## 17) 语言
通过“语言”菜单选择语言。
所选语言会在多次启动之间保留。“帮助→重置设置”会清除已保存的语言选择，并将界面语言恢复为默认值。

## 18) 进度条和取消
状态栏中间显示当前操作及其进度。

进度模式：
* 不确定 — 不显示百分比（操作持续时间未知）。
* 确定 — 显示百分比（0–100）。

行为：
* 后台数据计算期间显示百分比进度；
* 对于某些Git操作，当进度来源提供百分比时显示百分比；
* 当可用选项的更新和设置的应用耗时明显时，会显示相应进度；
* 快速操作完成时不显示进度。

状态栏中的X按钮（取消）：
* 对支持取消的操作尽力取消；
* 停止后台数据计算；
* 取消可用选项的更新时，将面板恢复到上次完成的状态；
* 对于不支持取消的操作，它只停止状态栏中的指示，操作本身仍可能在后台完成。

## 19) MCP与AI代理
DevProjex内置本地只读MCP服务器。Claude Code、Codex、Cursor和VS Code等AI代理通过它读取项目：机密信息遮蔽始终开启，代理无法更改项目文件。服务器提供八个工具：`list_projects`、`get_tree`、`analyze`、`search_project`、`related_files`、`get_file`、`pack_context`和`read_pack`。

### 19.1 连接客户端
MCP菜单包含：
* Live context — 服务器跟随此窗口中选中的项目（第19.2节）；
* 标准 — 服务器不依赖窗口中的选择；
* 日志… — 代理请求和收到的内容（第19.3节）；
* 文档 — 打开MCP服务器文档。

Live context和“标准”包含相同的操作——“在 Claude Code 中打开”“在 Codex 中打开”“在 Cursor 中打开”“在 VS Code 中打开”和“其他客户端…”，这些操作在打开项目后可用。

Claude Code和Codex通过其已安装的命令完成注册，随后客户端会在项目文件夹的新终端中打开。Cursor和VS Code会收到项目本地的`.cursor/mcp.json`或`.vscode/mcp.json`；该文件中的其他服务器会被保留。“其他客户端…”显示适用于Claude Desktop和其他客户端的现成配置。如果缺少客户端命令或连接失败，DevProjex会改为显示手动配置。连接成功后，DevProjex可能会提议将`devprojex`命令添加到PATH。

Codex只保留一个共享的DevProjex连接，因此连接另一个项目时会先询问是否替换。已在运行的客户端会话必须重新启动才能加载服务器。在终端中，`devprojex mcp connect`默认注册标准模式；添加`--mode live`可使用Live context，添加`--print`则只打印配置。

### 19.2 Live context
在Live context中，树中选中的项目决定代理的关注范围：树、搜索、分析、相关文件和打包请求都限定在这些项目之内。窗口的过滤器——文件类型、排除项和Git模式——构成访问边界：代理仍可按名称打开其他文件，但只能是这些过滤器允许的文件。

窗口无需保持打开。服务器在每次请求时都会读取为该项目最后保存的选择，因此新勾选的项目和已应用的设置会在代理的下一次请求中生效，无需重新启动代理。

实时会话处于活动状态时，窗口标题末尾会显示`· Live context (<client>)`；如果有多个活动会话，则显示会话数量。

### 19.3 日志
“MCP→日志…”显示代理通过DevProjex请求和收到的内容：会话及其客户端、模式、调用次数、字符数、估计词元数、已交付的文件和已遮盖的值，以及所选会话的各次调用。它在未打开项目时也可用；打开项目后，默认选中“仅当前项目”。

日志只存储在本计算机上的DevProjex状态文件夹中，最多保留200个会话，保存30天。它不会存储文件内容、检测到的机密值或搜索查询的文本。“导出…”将会话保存为Markdown或JSON回执。“清除”在确认后删除已完成的会话；活动会话以及与其他项目共享的会话会被保留。

### 19.4 代理活动
“视图→代理活动”默认关闭。开启后，代理在最近一次实时会话中收到的文件会在树中以✦标记，标记的工具提示会显示代理收到该文件的次数。这些标记绝不会更改过滤器或复选框。当新的实时会话开始、代理活动被关闭或项目被重新打开时，标记会被清除。标准会话会出现在日志中，但不会添加标记。
