## 1) Що це таке і чому
DevProjex швидко готує контекст проекту: показує структуру папки/файлу, дозволяє вибирати елементи за допомогою прапорців і копіювати дерево та/або вміст файлу в буфер обміну. Корисно для перегляду коду, підтримки, вивчення та обміну структурою проекту з помічником AI.

Важливо: DevProjex не змінює файли в проекті, який ви відкриваєте.

## 2) Дерево проекту
* Значки типів файлів/папок.
* Прапорці на вузлах.
* Розгорнути/згорнути.

Прапорці: вибір вузла застосовується до його дочірніх елементів; батьківський стан перераховується автоматично.

Гарячі клавіші:
* {mod}E — розгорнути все
* {collapseAll} — згорнути все (корінь залишається розгорнутим)

### Контекстне меню
Клацніть вузол правою кнопкою миші або натисніть {shift}F10 або клавішу «Меню» на вузлі, у якому вибрано фокус:
* Показати у Провіднику файлів / Показати в Finder / Відкрити в менеджері файлів — показує елемент у системному файловому менеджері; мітка відповідає поточній платформі.
* Копіювати повний шлях — абсолютний шлях до елемента.
* Копіювати відносний шлях — шлях із кореня проекту, починаючи з назви кореневої папки, наприклад `project/src/File.cs`.
* Копіювати вміст — для файлів: копіює вміст із застосованими перетвореннями вмісту точно так само, як копіювання та експорт.
* Select only this — перевіряє лише цей вузол і очищає решту; відображається лише тоді, коли інший пункт також позначено.
* Розгорнути гілку / Згорнути гілку — для папок.

Якщо шлях більше не існує на диску, відкриття елемента в файловому менеджері або копіювання його вмісту показує повідомлення про помилку; копіювання шляху все ще працює.

## 3) Файл
* Open folder… — відкрити кореневу папку ( {mod}O)
* Нове вікно — відкрити новий незалежний екземпляр DevProjex
* Останні — список нещодавно відкритих локальних папок
* Оновити — пересканувати локальну папку та перебудувати дерево (F5)
* Експорт у файл:
  * Дерево експорту
  * Експорт вмісту
  * Експорт дерева та вмісту
* Експортувати проєкт:
  * До папки…
  * В ZIP архів…

Експорт проекту створює окрему папку або ZIP архів із поточного дерева зі збереженням структури каталогів.

Вибрані типи файлів, правила виключення та позначені елементи дотримуються. Якщо нічого не позначено, експортується все поточне дерево.

Текстові та двійкові файли копіюються, а включені порожні папки зберігаються. Вихідні файли не змінено. Результат неможливо зберегти всередині вихідного проекту.

Під час експорту ви не можете змінювати дерево або налаштування, використовувати фільтр, змінювати формат або режим попереднього перегляду, виконувати команди Git, оновлювати або відкривати інший проект.

Правила формату:
* Дерево експорту:
  * Лише ASCII -> `.txt`.
  * JSON -> за замовчуванням `.json`, з `.json` і `.txt` доступними в діалоговому вікні збереження.
  * XML -> за замовчуванням `.xml`, з `.xml` і `.txt` доступними в діалоговому вікні збереження.
  * MD -> за замовчуванням `.md`, з `.md` і `.txt` доступними в діалоговому вікні збереження.
* Експорт вмісту — завжди текстовий формат вмісту, файл `.txt` (перемикач формату дерева не застосовується).
* Експорт дерева та вмісту — завжди файл `.txt`; вибраний формат дерева впливає лише на формат блоку дерева в результаті.

Файли експорту записуються в UTF-8 без специфікації матеріалів.

### Перетягніть і опустіть
Перетягування працює в області запуску (Drop Zone), коли жоден проект не завантажено.

правила:
* можна скинути папку;
* ви можете скинути файл — у цьому випадку відкривається папка, що містить;
* якщо викинуто кілька елементів, використовується перший відповідний локальний шлях;
* якщо шлях недоступний або не існує, застосовуються ті самі перевірки доступу, що й у «Відкрити папку…»;
* непідтримувані або нелокальні елементи ігноруються.

### Останні
Пункт «Файл → Останні» показує історію нещодавно відкритих локальних папок.

правила:
* до списку додаються лише локальні папки;
* Сховища Git, клоновані за допомогою DevProjex, не додаються до цього списку;
* дублікати не створюються — повторне відкриття тієї ж папки переміщує її наверх;
* зберігається до 32 останніх папок;
* історія зберігається між запусками програми.

Кожен елемент показує батьківську папку та назву проекту, наприклад `Projects / App`.

## 4) Запуск з терміналу
DevProjex надає інтерактивний термінальний робочий простір і прямі команди для сценаріїв і CI.

Якщо команда вже налаштована, відкрийте термінал і запустіть:
`devprojex --help`

Це список команд і параметрів верхнього рівня. Запустіть `devprojex help <command>`, щоб переглянути параметри та приклади цієї команди.

приклади:
* `devprojex` — відкрити інтерактивну робочу область терміналу. Усередині робочої області керуйте діями через командний рядок `:` (наприклад `:copy`, `:analyze`, `:branch`); повний список команд див. у довідці вбудованої робочої області та документації проекту.
* `devprojex tui .` — відкрити вказану папку безпосередньо в робочій області терміналу.
* `devprojex open . --preview` — відкрити поточну папку в Desktop Preview.
* `devprojex analyze . --format json` — аналізувати поточний проект як JSON.
* `devprojex tree .` — вивести дерево проекту на термінал.
* `devprojex export context . --format markdown -o ../devprojex-context.md` — зберегти готовий для ШІ контекст поза вихідним проектом.
* `devprojex export project . --as folder -o ../devprojex-submission` — експортувати ефективне дерево проекту до точної папки.
* `devprojex export project . --as zip -o ../devprojex-submission.zip` — експортувати ефективне дерево проекту до архіву ZIP.
* `devprojex export context https://github.com/owner/repo -o -` — запакуйте віддалений репозиторій, не клонуючи його самостійно.
* `devprojex analyze . --git-mode tracked --exclude smart-ignore` — аналізувати відстежені файли Git за допомогою Smart Ignore.
* `devprojex mcp --root .` — запускає локальний сервер MCP лише для читання, щоб агенти ШІ могли безпечно читати проект.

Примітки:
* `.` означає поточну папку терміналу;
* шляхи з пробілами повинні бути взяті в лапки;
* `--git-mode` вибирає режим без фільтрації Git, `.gitignore` або лише відстежувані файли Git;
* `--exclude` контролює звичайні виключення окремо від фільтрації Git;
* команди аналізу та експорту детерміновані та не відкривають інтерфейс робочого столу;
* `tui`, `open`, `analyze` та обидві команди `export` також приймають URL-адресу сховища Git; клон потрапляє в керований кеш (`devprojex cache`);
* команди мають задокументовані псевдоніми та короткі позначки — наприклад `export ctx`, `-f`, `-n`; `devprojex help` показує їх;
* `analyze --findings` перелічує результати маскування без вихідних значень, а `--fail-on-findings` повертає ненульовий код виходу для CI;
* команда не змінює файли проекту — DevProjex працює в режимі лише для читання.

Якщо команда `devprojex` не працює, відкрийте в DevProjex:
«Довідка → Запуск із терміналу».

## 5) Git
Меню Git доступне лише для проектів, клонованих через DevProjex (Git Clone). Додаток не торкається ваших файлів — працює тільки з кешем.

Кеш зберігається в каталозі системного кешу користувача. Запустіть `devprojex doctor`, щоб побачити вирішений шлях.

* Гілка — показує список доступних гілок із позначенням активної; перемикання оновлює дерево до вибраної гілки. Якщо гілка вже існує локально, перемикання відбувається офлайн (без отримання оновлень). Інакше гілку буде отримано та створено.
* Отримати оновлення — оновлює лише поточну гілку: отримати та скинути до origin/<branch>. Для проекту Git Clone F5 виконує ту саму дію; звичайна команда «Файл → Оновити» вимкнена.

### Вікно клонування
У вікні Git Clone під полем URL-адреси може з’явитися список «Останні сховища».

правила:
* список з’являється, лише якщо в історії вже є нещодавно клоновані сховища;
* до списку додаються лише URL-адреси сховища;
* локальні папки не додаються до цього списку;
* дублікати не створюються — повторне клонування того самого сховища переміщує його наверх;
* зберігається до 16 останніх сховищ;
* історія зберігається між запусками програми.

Вибір елемента автоматично заповнює поле URL-адреси.
Під час клонування список тимчасово приховано.

## 6) Копія
### Перемикач формату дерева (ASCII / JSON / XML / MD)
Перемикач визначає формат представлення дерева для операцій, де дерево є частиною виводу.

* ASCII — текстове дерево з гілками.
* JSON — структуроване дерево в JSON.
* XML — компактне XML дерево для аналізаторів і інструментів.
* MD — вкладений список Markdown для документації та підказок AI.

Перемикач впливає на:
* Копіювати дерево
* Копіювати дерево + вміст
* Дерево експорту
* Експорт дерева та вмісту

Перемикач не впливає на:
* Скопіюйте вміст
* Експорт вмісту

### Копіювати дерево
Копіює дерево проекту.
Якщо є позначені вузли, дерево будується з виділення; якщо виділення порожнє або недійсне, копіюється повне дерево.
Формат результату визначається перемикачем формату дерева.
Гарячі клавіші: {mod}{shift}C і {mod}{alt}C.

### Скопіюйте вміст
Копіює вміст файлу:
* якщо перевіряються файли — тільки ті; інакше — усі файли проекту;
* кожному файлу передує заголовок із повним локальним шляхом (для проектів Git Clone — веб-шлях до сховища);
* нетекстові файли ігноруються (включаючи двійкові);
* для порожніх текстових файлів виводиться шлях і рядок `[No Content, 0 bytes]`;
* для файлів, які містять лише пробіли/розриви рядків, виводиться шлях і рядок `[Whitespace, N bytes]`.
Гаряча клавіша: {mod}{alt}V.

### Копіювати дерево + вміст
Поєднує дерево та вміст:
* дерево будується з відбору; якщо вибір порожній/недійсний, використовується повне дерево;
* вміст відповідає тим же правилам, що й «Копіювати вміст»;
* формат блоку дерева визначається перемикачем формату дерева.
Гаряча клавіша: {mod}{shift}V.

### Представлення дерев
Формати дерева використовують різні представлення для одного вибраного дерева проекту.

JSON:
* `rootPath` — абсолютний кореневий шлях, нормалізований за допомогою `/`.
* `tree` — вміст кореневої папки.
* Експорт JSON використовує цей формат дерева: масиви містять файли, об’єкти містять вкладені папки, `/` містить файли в поточній папці, а `[]` представляє порожню папку.

XML:
* кореневий вузол `<t r="...">`;
* папки `<d n="...">`;
* файли `<f>File.cs</f>`.

MD:
* починається з `Root: ...`;
* використовує вкладений список Markdown;
* папки закінчуються на `/`.

Дерево + вміст:
* вибраний формат дерева застосовується до блоку дерева;
* блок контенту залишається текстом;
* заголовки файлів у блоці вмісту використовують відносні шляхи з `/`;
* експортовано як `.txt`.

## 7) Режим попереднього перегляду
Відкривається за допомогою кнопки зі значком ока на верхній панелі або за допомогою {mod}B.

Бічні кнопки миші відповідають навігації в стилі браузера: «Вперед» відкривається режим попереднього перегляду, а «Назад» — закривається. Повторення поточного напрямку не має ефекту.

{mod}{shift}F відкриває або закриває пошук у вмісті файлу в Preview. Enter або F3 перехід до наступного збігу; {shift}Enter або {shift}F3 перехід до попереднього збігу.

Показує кінцевий результат в окремій робочій області поруч із деревом. Цей режим не копіює в буфер обміну та не експортує у файл самостійно — це режим перегляду.

За замовчуванням робоча область відкривається так:
* зліва — дерево проекту;
* центр — панель попереднього перегляду;
* справа — панель налаштувань, якщо вона була відкрита.

Доступні режими:
* дерево
* Зміст
* Дерево і зміст

Застосовуються ті самі правила, що й для копіювання та експорту:
* перевірені вузли дотримуються;
* якщо вибір порожній, використовується повний набір даних;
* застосовано поточні правила ігнорування та параметри вибору.

додатково:
* файли в попередньому перегляді розділені горизонтальними лініями;
* під час прокручування шлях до поточного файлу закріплюється вгорі; клацання закріпленого шляху повертає назад до початку цього файлу;
* смуга прокрутки попереднього перегляду позначає пошукові збіги та рядки з результатами редагування; клацання маркера переходить до його лінії; знахідка, яка зберігається як є, залишається позначеною, а замасковані заголовки шляху додають один маркер у свій перший рядок;
* дерево і масштаб попереднього перегляду можуть жити незалежно.
* у режимі попереднього перегляду ви можете скопіювати або повний поточний результат, або поточний видимий блок файлу, не відкриваючи меню «Копіювати».

кнопки:
* кнопка копіювати зліва на верхньому острові попереднього перегляду — копіює поточний режим попереднього перегляду:
  * дерево
  * Зміст
  * Дерево і зміст
* X на панелі дерева — приховує дерево і залишає лише панель попереднього перегляду;
* X у верхній панелі попереднього перегляду — повністю закриває режим попереднього перегляду;
* маленька кнопка копіювання в закріпленому заголовку файлу — копіює поточний видимий блок файлу точно так, як він показаний у попередньому перегляді;
* повторне натискання значка ока або {mod}B також закриває режим попереднього перегляду.

Пошук і фільтр доступні, коли панель дерева відображається в попередньому перегляді.
Якщо дерево приховано, пошук і фільтр тимчасово недоступні, доки ви не вийдете з режиму лише попереднього перегляду.

## 8) Перегляд
### Збільшити
* {mod}+ / {mod} = — збільшити
* {mod} - — зменшити масштаб
* {mod}0 — скидання
* {mod} колесо миші — плавне збільшення панелі під курсором

Поведінка:
* у звичайному режимі дерево збільшено;
* у попередньому перегляді з видимим деревом, «Збільшити», «Зменшити» та «Скинути» з меню застосовуються як до дерева, так і до попереднього перегляду;
* з {mod} коліщатком миші, деревом і масштабуванням попереднього перегляду незалежно від того, де знаходиться курсор;
* у режимі лише попереднього перегляду масштабується лише панель попереднього перегляду.

Діапазон: 6–28, скидання 15.

### Компактний режим
Робить інтерфейс користувача щільнішим: менший інтервал у дереві та налаштуваннях.
Поки робоча область попереднього перегляду активна, компактний режим вмикається автоматично.

### Анімації
У розділі «Вигляд → Анімації» окремо налаштовуються розгортання дерева, лічильники стану та перша поява інструментів. Усі три анімації типово ввімкнені; вимкнена анімація одразу показує кінцевий стан.

### Дерево шрифт
Шрифт дерева вибирається за допомогою «Перегляд → Шрифт дерева».
«За замовчуванням» відновлює стандартний шрифт дерева.
Вибраний шрифт буде застосовано після натискання «Застосувати налаштування» на панелі налаштувань.

## 9) Пошук (дерево)
Відкриває панель пошуку, виділяє збіги та дозволяє навігацію.
* {mod}F — показати/сховати
* Enter — наступний результат
* {shift}Enter — попередній
* Esc — закрити

Пошук автоматично розгортає лише потрібні гілки; очищення запиту згортає дерево (крім кореня).
Лінії відповідності також позначені на смузі прокрутки дерева; натискання маркера переходить до цього збігу.
Для дуже великих наборів збігів програма може обмежити автоматичне розгортання та глобальне виділення, щоб користувальницький інтерфейс залишався чуйним.
Коли рядок пошуку закрито, запит очищається після завершення анімації закриття.

Обмеження:
* відкриття Пошуку автоматично закриває Фільтр;
* Пошук доступний у попередньому перегляді, коли видно панель дерева;
* якщо дерево приховано, пошук тимчасово недоступний.

## 10) Фільтр (за назвою)
Показує лише вузли, які відповідають рядку фільтра, і їхні батьки. Оновлення припиняються.
* {mod}{shift}N — показати/сховати фільтр
* Esc — закрити фільтр

Обмеження:
* відкриття фільтра автоматично закриває пошук;
* Фільтр доступний у попередньому перегляді, коли видно панель дерева;
* якщо дерево приховано, фільтр тимчасово недоступний.

## 11) Параметри (панель налаштувань)
Доступно праворуч:
* Застосувати налаштування
* Обробка контенту
* Винятки
* Розширення

Зміни в «Виключеннях» і «Розширеннях» встановлюються на панелі та застосовуються після натискання «Застосувати налаштування».

Після зміни прапорця програма може оновити доступні параметри та їх кількість у фоновому режимі. Отримане дерево перебудовується тільки після натискання «Застосувати налаштування».

Якщо оновлення доступних параметрів скасовано за допомогою кнопки X у рядку стану, незавершені зміни не застосовуються, і панель повертається до останнього завершеного стану.

Кожен список має перемикач «Усі».

Примітка щодо "Розширень":
* цей список показує лише файли, які мають розширення;
* файли без розширення не додаються до цього списку та контролюються окремою опцією в «Виключеннях».

Обробка контенту:
* перетворює вміст виділених текстових файлів без зміни дерева;
* Hide secrets і Hide private data замінюють виявлені значення (розділи 12.3 і 12.4);
* Код стиснення зберігає оголошення, скорочуючи іменовані реалізації на 14 мовах;
* Видалення коментарів видаляє коментарі та коментарі документації в 20 мовних пакетах;
* Видалення порожніх рядків видаляє рядки лише з пробілами в тих самих пакетах, зберігаючи багаторядкові літерали;
* зміни вступають в силу після «Застосувати налаштування».

{mod}P — показати/приховати панель.

### 11.1 Локальні профілі параметрів проекту
Для локальних папок DevProjex запам’ятовує останні застосовані параметри проекту:
* вибрані типи файлів;
* вибрані параметри в розділі «Винятки».

Збереження виконується при натисканні кнопки «Застосувати налаштування».
При повторному відкритті тієї самої локальної папки параметри відновлюються автоматично.

Важливо:
* профілі зберігаються тільки для локальних проектів;
* для проектів, відкритих через Git Clone, профілі не зберігаються;
* якщо деякі збережені параметри більше не доступні в поточному проекті, вони пропускаються, а параметри, що залишилися, застосовуються.
* якщо під час оновлення або повторного відкриття в «Виключеннях» з’являється новий тип файлу або параметр, це ввімкнено за замовчуванням;
* параметри, які вже розглядаються, зберігають явний вибір користувача: нові файли вимкненого типу не вмикають цей тип знову.

## 12) Винятки
Розділ «Винятки» визначає, які файли та папки виключаються з дерева, вмісту, результатів копіювання та експорту.

Елемент відображається лише тоді, коли виконуються всі ці умови:
* вибирається його тип файлу, якщо файл має тип;
* жодне ввімкнене правило ігнорування не виключає його.

Правила ігнорування накопичуються. Якщо хоча б одне ввімкнене правило приховує елемент, інше правило не може зробити його видимим.

### 12.1 Доступні правила
Залежно від вмісту проекту можуть відображатися такі параметри:

* Smart Ignore
* Використовуйте.gitignore
* Лише відстежувані файли Git
* Порожні папки
* Порожні файли
* Приховані папки
* Приховані файли
* Папки з префіксом крапка
* Файли з крапковим префіксом
* Файли без розширення

У сховищі Git параметри «Використовувати.gitignore» і «Лише відстежувані файли Git » залишаються видимими як стабільна пара прапорців. Увімкнення одного очищає інше. Повторне клацання активного прапорця очищає його, залишаючи обидва фільтри Git вимкненими без зміни Smart Ignore або основних виключень. Інші параметри показані, коли їхні правила можуть змінювати поточне дерево. Тому список може змінитися після зміни іншого правила або типу файлу.

Нова опція вмикається за замовчуванням, коли вона з’являється вперше. Відома опція зберігає вибір користувача, навіть якщо вона тимчасово зникає зі списку.

### 12.2 Smart Ignore
Smart Ignore приховує залежності, вихід збірки, кеші та інші артефакти служби проекту.

DevProjex спочатку визначає тип проекту за його структурою та файлами маркерів, наприклад:

* `.csproj`
* `package.json`
* `pyproject.toml`
* `Cargo.toml`

Правила для відповідного стека потім застосовуються в межах виявленої області проекту. Наприклад, правила.NET не поширюються на сусідні проекти Python або JavaScript.

Одного імені папки не завжди достатньо. Неоднозначні назви, такі як `build`, `vendor`, `packages`, `cache`, `pkg` або `Library` також перевіряються їхнім вмістом. Це запобігає приховуванню папки звичайного користувача лише тому, що вона має подібну назву.

Деякі сховища залежностей і каталоги служб можна розпізнати за характерною внутрішньою структурою навіть за межами явно виявленого проекту.

Виявлення обсягу проекту обмежене, тому завантаження великої папки користувача не перетворюється на повний повторний аналіз кожного каталогу. Звичайні структури використовують неглибоке відкриття, тоді як розпізнані монорепо шукають глибше. Після того, як область знайдено, Smart Ignore застосовується до всього піддерева без обмеження глибини.

### 12.3 Приховати секрети
«Приховати секрети» вимкнено за замовчуванням. Він сканує лише вибраний текстовий вміст і замінює кожне виявлене значення на місце, зберігаючи файл і його оточуючий код. Якщо опцію вимкнено, сканування не виконується та не відображається підрахунок. Після сканування поточного вибору на мітці відображається кількість виявлених значень; якщо рішення «залишити як є» залишають менше значень прихованим, воно показує виявлені/приховані, а рядок? індикатор повідомляє обидва підрахунки.

Замасковані діапазони виділяються в попередньому перегляді. Клацніть діапазон, щоб залишити лише це входження без змін; переходьте між знахідками за допомогою {alt}↓ / {alt}↑, а активну знахідку перемикайте клавішею Enter. У термінальному робочому просторі використовуйте `[` і `]` для переходу між входженнями, а `Enter` або `Space` — для перемикання активного входження. Рішення діє для попереднього перегляду, буфера обміну, експорту контексту, копіювання папки та ZIP у поточному сеансі й не зберігається в профілі проєкту.

Контекстне меню попереднього перегляду розширює ці рішення. Клацніть правою кнопкою миші виявлене входження, щоб за одну дію залишити як є або знову приховати всі входження за цим правилом чи всі виявлені входження в тому самому файлі. Щоб позначити вибране значення у вмісті файлу вручну, клацніть його правою кнопкою: «Приховати… тут» приховує лише це входження в поточному сеансі, «Завжди приховувати…» створює постійну позначку для кожного входження значення, а «Приховати… як особисті дані» — постійну позначку, якою керує опція «Приховувати особисті дані». Команда «Видалити позначку» видаляє ручну позначку; значення, яке й далі виявляє детектор, залишається прихованим. Вручну можна вибрати один рядок завдовжки від 8 до 512 символів у вмісті файлу. Створення позначки автоматично вмикає відповідну опцію. Постійні позначки зберігають лише ключований ідентифікатор значення та його клас, але ніколи не зберігають початковий текст.

Папка або ZIP копія також змінює відповідний текст і більше не може створювати чи запускатися. Двійкові файли копіюються без змін і не скануються. Вибраний текстовий файл розміром понад 16 МБ або помилка виявлення зупиняє операцію замість експорту неперевіреного тексту.

Лише збіги збігаються з правилом підрахунку. Нуль не означає, що проект безпечний. CLI використовує `--hide-secrets`; технічні деталі та обмеження знаходяться в `Docs/HideSecrets.md`.

### 12.4 Приховати особисті дані
«Приховати особисті дані» вимкнено за замовчуванням. Опція виявляє адреси електронної пошти, глобальні IP-адреси, локальні імена користувачів у шляхах, MAC-адреси та міжнародні номери телефонів у вибраних текстових файлах. До знахідок застосовуються ті самі рішення попереднього перегляду й той самий конвеєр виведення, що й для «Приховувати секрети»; ручні позначки «Приховати… як особисті дані» належать до цього класу й керуються цим перемикачем (розділ 12.3). Локальні імена користувачів у згенерованих заголовках шляхів і корені дерева маскуються як одна спільна знахідка: лічильник враховує її як одне значення,? індикатор показує, прихована вона чи відображається, а одне клацання перемикає всі замасковані шляхи.

Діапазони документації та хости, загальні імена користувачів CI, добре відомі загальнодоступні DNS-перетворювачі та задокументовані діапазони вигаданих телефонів залишаються видимими. Відсутність збігів не є гарантією конфіденційності. CLI використовує `--hide-private-data`; повні правила та обмеження першої фази знаходяться в `Docs/HidePrivateData.md`.

### 12.5 Використовуйте.gitignore
Якщо ввімкнено, DevProjex застосовує кожен доступний `.gitignore`, а не лише файл у корені відкритої теки.

Кожен `.gitignore` застосовується:

* до папки, яка його містить;
* до всіх доступних папок під ним;
* тільки в межах цієї сфери.

Правила вкладеного `.gitignore` не впливають на батьківські та однорідні папки.

Для певного шляху правила обробляються від батьківського `.gitignore` до глибших файлів. В одному файлі правила обробляються зверху вниз. Останнє відповідне правило визначає результат Git.

Правило, що починається з `!` скасовує попередні виключення Git лише в межах своєї області. Він не може відновити файл, поки його батьківська папка залишається виключеною. `.gitignore` всередині повністю виключеної та недоступної папки не бере участі в оцінці.

Неправильний або непідтримуваний рядок пропускається самостійно. Інші дійсні правила в цьому файлі та правила в сусідніх областях продовжують працювати.

Цей параметр стосується лише звичайних файлів робочого дерева `.gitignore`. Правила з `.git/info/exclude` і глобальні правила виключення Git не застосовуються; Дотримуються ефективних параметрів порівняння шляхів сховища, таких як `core.ignoreCase` і, в macOS, `core.precomposeUnicode`. Символічне посилання під назвою `.gitignore` не переходить, що відповідає поведінці керуючого файлу Git. Якщо звичайний `.gitignore` не може бути прочитаний, його область каталогу виключається після помилкового закриття, а сканування повідомляє про частковий доступ замість тихого включення файлів без повної оцінки правила. Коли доступний доступний для читання індекс для області репозиторію, що володіє шляхом, відстежувані файли залишаються видимими, навіть якщо вони відповідають `.gitignore`; без цього індексу або Git CLI ця область безпечно повертається до оцінки лише за шаблоном.

Вбудований `standard` профіль вибирає `gitignore` плюс `smart-ignore`, `hidden-folders`, `hidden-files`, `dot-folders`, `dot-files`, `empty-folders`, `empty-files` і `extensionless-files`.

### 12.6 Лише відстежувані файли Git
«Лише відстежувані файли Git » створює стадію Git дерева з існуючих файлів робочого дерева, записаних у кожному читабельному індексі Git. Змінені відстежувані файли та поетапні доповнення залишаються включеними; невідстежувані файли виключаються. Це поточне робоче дерево, а не історичний знімок `HEAD` або віддаленого сховища.

Кожен доступний вкладений репозиторій і робоче дерево вирішуються незалежно на будь-якому доступному рівні вкладеності. Дочірній репозиторій не успадковує відстежувані шляхи від батьківського чи братського. Для цього режиму потрібен Git CLI; читабельний порожній індекс є дійсним. Якщо робоче середовище терміналу ( TUI) запускається в цьому режимі, і жоден відповідний індекс не може бути завантажений, робоче середовище не відкривається. Якщо режим вибрано в інтерактивному режимі у відкритій робочій області TUI і жоден відповідний індекс не може бути завантажений, зміна відхиляється, а останній доступний режим Git залишається активним. У тій же ситуації прямі команди повертають помилку політики або перевірки. DevProjex ніколи мовчки не повертається до `.gitignore`. Якщо інший відповідний індекс доступний для читання, недоступні вкладені області виключаються з попередженням.

У вже відкритій робочій області Desktop явний відстежуваний вибір залишається видимим і закритим при помилках: вивід і експорт блокуються, коли готовність не вдається, тоді як часткова готовність продовжується з локалізованим попередженням.

"Використовувати.gitignore" і "Відстежувані лише файли Git " є взаємовиключними, якщо ввімкнено. Активний прапорець також можна зняти, щоб вимкнути фільтрацію Git. Для локальних проектів, які підтримують профілі, цей стан зберігається з типом файлу та іншими параметрами виключення.

### 12.7 Зв’язок між фільтрацією Git і Smart Ignore
Прапорці Git і Smart Ignore є незалежними елементами керування. Вибраний режим Git застосовується спочатку в кожній доступній області Git. Потім Smart Ignore обробляє решту елементів, а основні правила виконуються останніми.

Smart Ignore може залишатися прихованим, поки вибраний режим Git уже охоплює всіх своїх кандидатів, а потім з’являтися після того, як режим Git буде змінено або очищено. Обидва прапорці Git залишаються доступними в сховищі Git.

Правило заперечення Git, що починається з `!` скасовує лише результат Git. Це не вимикає Smart Ignore або базове правило.

### 12.8 Основні правила
«Папки з префіксом із крапкою» та «Файли з префіксом із крапкою» перевірте назву елемента.

«Приховані папки» та «Приховані файли» перевіряють системний прихований атрибут. На деяких платформах назва з префіксом із крапкою та системний атрибут можуть описувати той самий або різні елементи.

«Порожні файли» приховує файли розміром 0 байт.

«Файли без розширення» приховують такі файли, як `Dockerfile`, `Makefile` і `README`.

«Порожні папки» приховує логічно порожні папки. Папка є логічно порожньою, якщо після вибраних типів файлів і застосування всіх інших правил не залишається жодного видимого файлу чи вкладеної папки.

Тому кількість порожніх папок може змінитися після перемикання іншого правила: приховування файлів може зробити папки, що їх містять, логічно порожніми.

### 12.9 Лічильники
Підрахунок поруч із правилом показує його прямий внесок у поточні налаштування, а не фізичну кількість подібних елементів на диску.

Один елемент не приписується одночасно кільком лічильникам, що перекриваються. Наприклад, папка `.git` може мати назву з префіксом крапки та системний атрибут Hidden, але її виключення пов’язано лише з одним правилом.

Для вибору власника виключення використовується стабільний порядок:

* папки: `.gitignore`, Smart Ignore, ім'я з префіксом крапки, системний атрибут Hidden;
* файли: `.gitignore`, Smart Ignore, назва з префіксом крапки, без розширення, порожній файл, системний атрибут Hidden.

Цей порядок впливає лише на лічильники. Остаточна видимість відповідає простішому правилу: елемент приховано, якщо будь-який увімкнений механізм виключає його.

### 12.10 Застосування змін
Перемикання прапорців спочатку оновлює доступні параметри та лічильники на панелі. Остаточне дерево буде перебудовано після вибору «Застосувати налаштування».

Якщо підготовку налаштувань скасовано, DevProjex повертає панель до останнього повністю завершеного стану. Частково обчислені правила не застосовуються.

## 13) Як обчислюється дерево та метрика
Результат залежить від:
* вибрані розширення
* Ігноруйте правила
* активний фільтр
* перевірені вузли дерева (для операцій на основі вибору)

Якщо доступ заборонено, вузол зберігає свою звичайну назву та значок і отримує суфікс "[доступ заборонено]".

### 13.1 Що показують лічильники рядка стану
Рядок стану має два блоки:
* Дерево — метрика виведення тексту дерева;
* Вміст — метрика виведення вмісту експортованого файлу.

Формат:
* Рядки
* Символи
* ~Токени (приблизно)

Великі значення відображаються з компактними суфіксами (K/M).

Важливо:
* «Рядки» в блоці «Дерево» означають кількість рядків у остаточному представленні дерева, а не кількість файлів на диску;
* це значення включає папки, файли та елементи служби дерева (наприклад, вузли із забороненим доступом).

### 13.2 Як обчислюються показники
Метрики дерева:
* обчислюються з фактичного виводу дерева, згенерованого тим самим конвеєром експорту;
* дотримуватися поточного формату дерева.

Показники вмісту:
* дотримуйтеся тих самих правил, що й для копіювання/експорту вмісту;
* двійкові файли виключені;
* Пусті файли та файли, що містять лише пробіли, підраховуються за допомогою службових маркерів ( `[No Content, 0 bytes]`, `[Whitespace, N bytes]`).

### 13.3 Коли лічильники оновлюються
Перерахунок виконується:
* після відкриття/оновлення проекту;
* після застосування налаштувань (виключення та розширення);
* при зміні прапорців дерева (з усуненням дребезгу);
* під час перемикання формату дерева (для операцій, де використовується вихід дерева).
* коли фонове обчислення скасовано, лічильники встановлюються на 0 до наступного завершеного перерахунку.

## 14) Піктограми
Порядок вибору піктограм:
1) тип вузла (папка/файл)
2) точна назва (якщо правило існує)
3) розширення
4) інакше — невідомо

## 15) Тема та ефекти
У розділі «Тема» можна вибрати «Система», «Світлий» або «Темний» і один фоновий ефект:
* Прозорість
* Розмиття
* Mica

Система вибирається за замовчуванням і відповідає змінам теми операційної системи. Після першого запуску або скидання налаштувань світла системна тема починається зі звичайного непрозорого фону, тоді як темна системна тема починається з розмиття. Якщо системні параметри неможливо визначити, DevProjex використовує Темний із Розмиттям. Світло і Темрява запам'ятовують свої ефекти незалежно. Явний вибір «Світлий» або «Темний» ігнорує системні зміни, доки система не буде вибрана знову.

Ефекти взаємовиключні. Повторне натискання вибраного ефекту вимикає його та відновлює звичайний непрозорий фон.

Доступні налаштування:
* Прозорість фону — доступна для прозорості та розмиття.
* Контраст верхньої панелі — регулює головну панель, яка містить команди «Попередній перегляд», «Пошук», «Фільтр» і деревовидне форматування.
* Прозорість меню — однаково стосується головного меню та його підменю.
* Видимість кордону — регулює, наскільки яскраво відображаються межі інтерфейсу.

Mica використовує системний матеріал платформи та не має окремого налаштування прозорості фону. Якщо вибраний ефект «Розмиття» або Mica недоступний, програма спочатку спробує інший природний ефект. Звичайний непрозорий фон використовується лише тоді, коли недоступні ні Blur, ні Mica.

У режимі прозорості фон головного вікна залишається прозорим. Меню, підменю та інші спливаючі поверхні використовують Blur, якщо це підтримується, тому дерево та елементи вмісту за ними не заважають читабельності.

## 16) Допомога

### 16.1 Оновлення
«Довідка → Оновлення» порівнює поточну версію з останнім стабільним випуском GitHub. Автоматичні перевірки вимкнено за замовчуванням; якщо ввімкнено, DevProjex перевіряє під час запуску після того, як минуло щонайменше сім днів після попередньої успішної перевірки. Прапорець набуває чинності негайно. Останній успішний результат зберігається між запусками програми та не стирається через пізніший збій мережі. Встановлення залишається дією користувача.

### 16.2 Скидання налаштувань
Скидання налаштувань (Довідка → Скидання налаштувань) відновлює типову тему, ефекти, компактний режим, налаштування анімацій та мову інтерфейсу. Профілі проекту, історія та файли на диску не змінюються.

### 16.3 Скидання даних
Скинути дані (Довідка → Скинути дані) видаляє збережені профілі параметрів локального проекту:
* вибрані типи файлів;
* вибрані параметри в розділі «Винятки».

Важливо:
* Остання історія локальних папок не очищається;
* Історія останніх сховищ у вікні Git Clone не очищається;
* файли та папки на диску не змінюються та не видаляються.

## 17) Мови
Мова вибирається через меню «Мова».
Вибрана мова зберігається між запусками. «Довідка → Скинути налаштування» очищає збережену мову та повертає мову інтерфейсу до стандартної.

## 18) Індикатор виконання та скасування
У центрі рядка стану відображається активна операція та її хід.

Режими прогресу:
* Невизначений — немає відсотків (тривалість операції невідома).
* Визначити — з відсотками (0–100).

Поведінка:
* під час обчислення фонових даних відображається прогрес у відсотках;
* для деяких операцій Git відсоток відображається, якщо це надає джерело прогресу;
* доступні опції оновлень і налаштування програми відображаються, коли операція займає помітний час;
* швидкі операції завершуються без відображення прогресу.

Кнопка X (скасувати) у рядку стану:
* виконує найкраще скасування для операцій, які підтримують скасування;
* зупиняє обчислення фонових даних;
* коли оновлення доступних параметрів скасовується, повертає панель до останнього завершеного стану;
* для операцій без підтримки скасування він припиняє індикацію рядка стану, тоді як сама операція все ще може завершитися у фоновому режимі.

## 19) Примітки
* Якщо дозволів недостатньо, програма може запропонувати перезапустити з підвищенням рівня; якщо відхилено, буде показано сповіщення.
