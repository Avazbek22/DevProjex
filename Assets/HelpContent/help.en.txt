## 1) What it is and why
DevProjex quickly prepares project context: shows the folder/file structure, lets you select items with checkboxes, and copy the tree and/or file contents to the clipboard. Useful for code review, support, learning, and sharing project structure with an AI assistant.

Important: DevProjex does not modify files in the project you open.

## 2) Project tree
* File/folder type icons.
* Checkboxes on nodes.
* Expand/collapse.

Checkboxes: selecting a node applies to its children; parent state is recalculated automatically.

Hotkeys:
* {mod}E — expand all
* {collapseAll} — collapse all (root stays expanded)

### Context menu
Right-click a node, or press {shift}F10 or the Menu key on the focused node:
* Show in File Explorer / Reveal in Finder / Open in file manager — reveals the item in the system file manager; the label matches the current platform.
* Copy full path — the absolute path of the item.
* Copy relative path — the path from the project root, starting with the root folder name, for example `project/src/File.cs`.
* Copy contents — for files: copies the content with the applied content transformations, exactly as copy and export produce it.
* Select only this — checks only this node and clears the rest; shown only while another item is also checked.
* Expand branch / Collapse branch — for folders.

If the path no longer exists on disk, opening the item in the file manager or copying its contents shows an error message; path copying still works.

## 3) File
* Open folder… — open root folder ({mod}O)
* New window — open a new independent DevProjex instance
* Recent — list of recently opened local folders
* Refresh — rescan a local folder and rebuild the tree (F5)
* Export to file:
  * Export tree
  * Export content
  * Export tree and content
* Export project:
  * To folder…
  * To ZIP archive…

Export project creates a separate folder or ZIP archive from the current tree while preserving the directory structure.

Selected file types, exclusion rules, and checked items are respected. If nothing is checked, the entire current tree is exported.

Text and binary files are copied, and included empty folders are preserved. The source files are not modified. The result cannot be saved inside the source project.

During export, you cannot change the tree or settings, use the filter, change the format or preview mode, run Git commands, refresh, or open another project.

Format rules:
* Export tree:
  * ASCII -> `.txt` only.
  * JSON -> default `.json`, with both `.json` and `.txt` available in Save dialog.
  * XML -> default `.xml`, with both `.xml` and `.txt` available in Save dialog.
  * MD -> default `.md`, with both `.md` and `.txt` available in Save dialog.
* Export content — always text content format, `.txt` file (tree format toggle does not apply).
* Export tree and content — always `.txt` file; the selected tree format affects only the tree block format inside the result.

Export files are written in UTF-8 without BOM.

### Drag & Drop
Drag and drop works in the startup area (Drop Zone) when no project is loaded.

Rules:
* you can drop a folder;
* you can drop a file — in this case the containing folder is opened;
* if multiple items are dropped, the first suitable local path is used;
* if a path is unavailable or does not exist, the same access checks as in “Open folder…” are applied;
* unsupported or non-local items are ignored.

### Recent
The “File → Recent” item shows the history of recently opened local folders.

Rules:
* only local folders are added to the list;
* Git repositories cloned via DevProjex are not added to this list;
* duplicates are not created — opening the same folder again moves it to the top;
* up to 32 recent folders are stored;
* history is preserved between app launches.

Each item shows the parent folder and project name, for example `Projects / App`.

## 4) Launch from terminal
DevProjex provides an interactive Terminal Workspace and direct commands for scripts and CI.

If the command is already set up, open a terminal and run:
`devprojex --help`

This lists the top-level commands and options. Run `devprojex help <command>` to see that command's own options and examples.

Examples:
* `devprojex` — open the interactive Terminal Workspace. Inside the workspace, drive actions through the `:` command line (for example `:copy`, `:analyze`, `:branch`); see the built-in workspace help and project documentation for the full command list.
* `devprojex tui .` — open the specified folder directly in the Terminal Workspace.
* `devprojex open . --preview` — open the current folder in Desktop Preview.
* `devprojex analyze . --format json` — analyze the current project as JSON.
* `devprojex tree .` — print the project tree to the terminal.
* `devprojex export context . --format markdown -o ../devprojex-context.md` — save AI-ready context outside the source project.
* `devprojex export project . --as folder -o ../devprojex-submission` — export the effective project tree to an exact folder.
* `devprojex export project . --as zip -o ../devprojex-submission.zip` — export the effective project tree to a ZIP archive.
* `devprojex export context https://github.com/owner/repo -o -` — pack a remote repository without cloning it yourself.
* `devprojex analyze . --git-mode tracked --exclude smart-ignore` — analyze tracked Git files with Smart Ignore.
* `devprojex mcp --root .` — start the local read-only MCP server so AI agents can read the project safely.

Notes:
* `.` means the current terminal folder;
* paths with spaces must be wrapped in quotes;
* `--git-mode` selects no Git filtering, `.gitignore`, or tracked Git files;
* `--exclude` controls ordinary exclusions separately from Git filtering;
* analysis and export commands are deterministic and do not open the desktop interface;
* `tui`, `open`, `analyze`, and both `export` commands also accept a Git repository URL; the clone goes into a managed cache (`devprojex cache`);
* commands have documented aliases and short flags — for example `export ctx`, `-f`, `-n`; `devprojex help` shows them;
* `analyze --findings` lists redaction findings without their values, and `--fail-on-findings` returns a nonzero exit code for CI;
* the command does not modify project files — DevProjex works in read-only mode.

If the `devprojex` command does not work, open in DevProjex:
“Help → Launch from terminal”.

## 5) Git
Git menu is available only for projects cloned via DevProjex (Git Clone). The app does not touch your files — it works only with the cache.

The cache is stored in the user's system cache directory. Run `devprojex doctor` to see the resolved path.

* Branch — shows the list of available branches with the active one marked; switching updates the tree to the selected branch. If the branch already exists locally, switching is offline (no update). If it does not exist locally, it is fetched and created.
* Get updates — updates only the current branch: fetch and reset to origin/<branch>. For a Git Clone project, F5 performs the same action; the regular “File → Refresh” command is disabled.

### Clone window
In the Git Clone window, a “Recent repositories” list can appear below the URL field.

Rules:
* the list appears only if the history already contains recently cloned repositories;
* only repository URLs are added to the list;
* local folders are not added to this list;
* duplicates are not created — cloning the same repository again moves it to the top;
* up to 16 recent repositories are stored;
* history is preserved between app launches.

Selecting an item automatically fills the URL field.
While cloning is in progress, the list is temporarily hidden.

## 6) Copy
### Tree format toggle (ASCII / JSON / XML / MD)
The toggle defines the tree representation format for operations where the tree is part of the output.

* ASCII — text tree with branches.
* JSON — structured tree in JSON.
* XML — compact XML tree for parsers and tools.
* MD — Markdown nested list for documentation and AI prompts.

The toggle affects:
* Copy tree
* Copy tree + content
* Export tree
* Export tree and content

The toggle does not affect:
* Copy content
* Export content

### Copy tree
Copies the project tree.
If there are checked nodes, the tree is built from selection; if the selection is empty or invalid, the full tree is copied.
The result format is defined by the tree format toggle.
Hotkeys: {mod}{shift}C and {mod}{alt}C.

### Copy content
Copies file contents:
* if files are checked — only those; otherwise — all project files;
* each file is preceded by a header with its full local path (for Git Clone projects — the repository web path);
* non-text files are ignored (including binary);
* for empty text files, the path and the line `[No Content, 0 bytes]` are output;
* for files containing only whitespace/line breaks, the path and the line `[Whitespace, N bytes]` are output.
Hotkey: {mod}{alt}V.

### Copy tree + content
Combines tree and content:
* tree is built from selection; if selection is empty/invalid, the full tree is used;
* content follows the same rules as “Copy content”;
* tree block format is defined by the tree format toggle.
Hotkey: {mod}{shift}V.

### Tree representations
Tree formats use different representations for the same selected project tree.

JSON:
* `rootPath` — absolute root path normalized with `/`.
* `tree` — contents of the root folder.
* JSON export uses this tree format: arrays contain files, objects contain subfolders, `/` contains files in the current folder, and `[]` represents an empty folder.

XML:
* root node is `<t r="...">`;
* folders are `<d n="...">`;
* files are `<f>File.cs</f>`.

MD:
* starts with `Root: ...`;
* uses a Markdown nested list;
* folders end with `/`.

Tree + content:
* the selected tree format applies to the tree block;
* content block remains text;
* file headers in the content block use relative paths with `/`;
* exported as `.txt`.

## 7) Preview mode
Opened with the eye icon button in the top bar or with {mod}B.

Mouse side buttons follow browser-style navigation: Forward opens Preview mode, and Back closes it. Repeating the current direction has no effect.

{mod}{shift}F opens or closes search in file contents in Preview. Enter or F3 goes to the next match; {shift}Enter or {shift}F3 goes to the previous match.

Shows the final result in a separate workspace next to the tree. This mode does not copy to the clipboard and does not export to a file on its own — it is a viewing mode.

By default, the workspace opens as:
* left — project tree;
* center — preview pane;
* right — settings panel, if it was open.

Available modes:
* Tree
* Content
* Tree and content

The same rules as copy and export are applied:
* checked nodes are respected;
* if selection is empty, the full data set is used;
* current ignore rules and selection options are applied.

Additionally:
* files in preview are separated by horizontal lines;
* while scrolling, the path of the current file is pinned at the top; clicking the pinned path scrolls back to the beginning of that file;
* the preview scrollbar marks search matches and lines with redaction findings; clicking a marker jumps to its line; a finding kept as-is stays marked, and masked path headers add one marker at their first line;
* tree and preview zoom can live independently.
* in Preview mode, you can copy either the full current result or the current visible file block without opening the Copy menu.

Buttons:
* copy button on the left side of the top preview island — copies the current preview mode:
  * Tree
  * Content
  * Tree and content
* X in the tree pane — hides the tree and leaves only the preview pane;
* X in the top preview pane — closes Preview mode completely;
* small copy button in the pinned file header — copies the current visible file block exactly as it is shown in Preview;
* pressing the eye icon again or {mod}B also closes Preview mode.

Search and Filter are available while the tree pane is visible in Preview.
If the tree is hidden, Search and Filter are temporarily unavailable until you leave preview-only mode.

## 11) Options (settings panel)
Available on the right:
* Apply settings
* Content processing
* Exclusions
* Extensions

Changes in “Exclusions” and “Extensions” are staged in the panel and applied after clicking “Apply settings”.

After a checkbox changes, the app may update available options and their counts in the background. The resulting tree is rebuilt only after clicking “Apply settings”.

If an available-options update is canceled with the X button in the status bar, unfinished changes are not applied and the panel returns to its last completed state.

Each list has an All toggle.

Note about "Extensions":

Content processing:

* Hide secrets and Hide private data replace detected values (sections 12.3 and 12.4);
* Compress code keeps declarations while shortening named implementations across 14 languages;

* Strip blank lines removes whitespace-only lines in the same packs while preserving multiline literals;
* changes take effect after "Apply settings".

{mod}P — show/hide the panel.

### 11.1 Local project parameter profiles
For local folders, DevProjex remembers the last applied project parameters:
* selected file types;
* selected options in the "Exclusions" section.

Saving is performed when you click "Apply settings".
When the same local folder is opened again, parameters are restored automatically.

Important:
* profiles are saved only for local projects;
* for projects opened via Git Clone, profiles are not saved;
* if some saved options are no longer available in the current project, they are skipped, and the remaining parameters are applied.
* if refresh or reopening reveals a new file type or option in "Exclusions", it is enabled by default;
* options already seen keep the user's explicit choice: new files of a disabled type do not enable that type again.

## 12) Exclusions
The "Exclusions" section controls which files and folders are excluded from the tree, content, copy, and export results.

An item is shown only when all of these conditions are met:
* its file type is selected, if the file has a type;
* no enabled ignore rule excludes it.

Ignore rules are cumulative. If at least one enabled rule hides an item, another rule cannot make it visible.

### 12.1 Available rules
Depending on the project contents, the following options may be shown:

* Smart Ignore
* Use .gitignore
* Tracked Git files only
* Empty folders
* Empty files
* Hidden folders
* Hidden files
* Dot-prefixed folders
* Dot-prefixed files
* Files without extension

Inside a Git repository, "Use .gitignore" and "Tracked Git files only" remain visible as a stable checkbox pair. Enabling one clears the other. Clicking the active checkbox again clears it, leaving both Git filters off without changing Smart Ignore or the basic exclusions. Other options are shown when their rules can change the current tree. The list may therefore change after switching another rule or a file type.

A new option is enabled by default when it first appears. A known option keeps the user's choice even if it temporarily disappears from the list.

### 12.2 Smart Ignore
Smart Ignore hides dependencies, build output, caches, and other project service artifacts.

DevProjex first identifies the project type from its structure and marker files, for example:

* `.csproj`
* `package.json`
* `pyproject.toml`
* `Cargo.toml`

Rules for the corresponding stack are then applied inside the detected project scope. For example, .NET rules do not extend into a neighboring Python or JavaScript project.

A folder name alone is not always enough. Ambiguous names such as `build`, `vendor`, `packages`, `cache`, `pkg`, or `Library` are also verified by their contents. This prevents an ordinary user folder from being hidden only because it has a similar name.

Some dependency stores and service directories can be recognized by their characteristic internal structure even outside an explicitly detected project.

Project scope discovery is bounded so loading a large user folder does not become a full repeated analysis of every directory. Regular structures use shallow discovery, while recognized monorepos are searched more deeply. After a scope is found, Smart Ignore applies to its entire subtree without a depth limit.

### 12.3 Hide Secrets
"Hide Secrets" is off by default. It scans only selected text content and replaces each detected value in place, keeping the file and its surrounding code. While the option is off, no scan runs and no count is shown. After the current selection is scanned, the label shows the number of detected values; if keep-as-is decisions leave fewer values hidden, it shows detected/hidden, and the row's ? indicator reports both counts.

Redacted spans are highlighted in Preview. Click one to keep only that occurrence as-is; {alt}↓ / {alt}↑ move between findings and Enter toggles the active one. In Terminal Workspace, use `[` and `]` to move between occurrences and `Enter` or `Space` to toggle the active one. The decision applies to Preview, clipboard, context export, folder copy, and ZIP for the current session; it is not saved in the project profile.

The Preview context menu extends these decisions. Right-click a detected occurrence to keep — or hide again — all occurrences of its rule or all detected occurrences in the same file in one action. Right-click a selected value inside file content to mark it manually: "Hide … here" hides only that occurrence for the session, "Always hide …" creates a persistent mark for every occurrence of the value, and "Hide … as private data" creates a persistent mark controlled by Hide private data. "Remove mark" appears on a manual mark and deletes it; a value still matched by the detector stays hidden. A manual value must be a single line of 8 to 512 characters selected inside file content. Creating a mark enables the corresponding option automatically. Persistent marks store only a keyed value identity and its class, never the original text.

A folder or ZIP copy also changes matching text and may no longer build or run. Binary files are copied unchanged and are not scanned. A selected text file above 16 MiB or a detection failure stops the operation instead of exporting uninspected text.

The count reports rule matches only. Zero does not mean that the project is safe. CLI uses `--hide-secrets`; technical details and limits are in `Docs/HideSecrets.md`.

### 12.4 Hide private data
"Hide private data" is off by default. It detects email addresses, global IP addresses, local usernames in paths, MAC addresses, and international phone numbers in selected text files. Findings use the same Preview decisions and the same output pipeline as Hide Secrets; manual marks created with "Hide … as private data" belong to this class and follow this switch (section 12.3). Local usernames in generated path headers and the tree root are masked as one shared finding: the counter includes it as one value, the ? indicator reports whether it is hidden or shown, and one click toggles every masked path.

Documentation ranges and hosts, common CI usernames, well-known public DNS resolvers, and documented fictional phone ranges stay visible. Zero matches is not a privacy guarantee. CLI uses `--hide-private-data`; the complete rules and phase-one limits are in `Docs/HidePrivateData.md`.

### 12.5 Use .gitignore
When enabled, DevProjex applies every reachable `.gitignore`, not only the file at the root of the opened folder.

Each `.gitignore` applies:

* to the folder that contains it;
* to all accessible folders below it;
* only inside that scope.

Rules from a nested `.gitignore` do not affect parent or sibling folders.

For a particular path, rules are processed from the parent `.gitignore` toward deeper files. Within one file, rules are processed from top to bottom. The last matching rule determines the Git result.

A rule starting with `!` cancels an earlier Git exclusion only within its scope. It cannot restore a file while its parent folder remains excluded. A `.gitignore` inside a fully excluded and unreachable folder does not participate in evaluation.

A malformed or unsupported line is skipped independently. Other valid rules in that file and rules in neighboring scopes continue to work.

This option covers regular working-tree `.gitignore` files only. Rules from `.git/info/exclude` and global Git exclusion rules are not applied; effective repository path-comparison settings such as `core.ignoreCase` and, on macOS, `core.precomposeUnicode` are respected. A symbolic link named `.gitignore` is not followed, matching Git's control-file behavior. If a regular `.gitignore` cannot be read, its directory scope is excluded fail-closed and the scan reports partial access instead of silently including files without complete rule evaluation. When a readable index for the path's owning repository scope is available, tracked files remain visible even if they match `.gitignore`; without that index or the Git CLI, that scope safely falls back to pattern-only evaluation.

The built-in `standard` profile selects `gitignore` plus `smart-ignore`, `hidden-folders`, `hidden-files`, `dot-folders`, `dot-files`, `empty-folders`, `empty-files`, and `extensionless-files`.

### 12.6 Tracked Git files only
"Tracked Git files only" builds the Git stage of the tree from existing working-tree files recorded in each readable Git index. Modified tracked files and staged additions remain included; untracked files are excluded. This is the current working tree, not a historical snapshot of `HEAD` or a remote repository.

Every reachable nested repository and worktree is resolved independently at any reachable nesting level. A child repository does not inherit tracked paths from its parent or sibling. This mode requires the Git CLI; a readable empty index is valid. If the Terminal Workspace (TUI) starts in this mode and no applicable index can be loaded, the workspace does not open. If the mode is selected interactively in an open TUI workspace and no applicable index can be loaded, the change is rejected and the last usable Git mode remains active. In the same situation, direct commands return a policy or check failure. DevProjex never silently falls back to `.gitignore`. If another applicable index is readable, unavailable nested scopes are excluded with a warning.

In an already-open Desktop workspace, the explicit tracked selection remains visible and fail-closed: output and export are blocked when readiness fails, while partial readiness continues with a localized warning.

"Use .gitignore" and "Tracked Git files only" are mutually exclusive when enabled. The active checkbox may also be cleared to disable Git filtering. For local projects that support profiles, this state is saved with the file-type and other exclusion settings.

### 12.7 Relationship between Git filtering and Smart Ignore
The Git checkboxes and Smart Ignore are independent controls. The selected Git mode applies first at every reachable Git scope. Smart Ignore then processes the remaining items, and the basic rules run last.

Smart Ignore can stay hidden while the selected Git mode already covers all of its candidates, then appear after the Git mode is changed or cleared. Both Git checkboxes remain available inside a Git repository.

A Git negation rule starting with `!` cancels only a Git result. It does not disable Smart Ignore or a basic rule.

### 12.8 Basic rules
"Dot-prefixed folders" and "Dot-prefixed files" inspect the item name.

"Hidden folders" and "Hidden files" inspect the system hidden attribute. On some platforms, a dot-prefixed name and the system attribute may describe the same item or different items.

"Empty files" hides files whose size is 0 bytes.

"Files without extension" hides files such as `Dockerfile`, `Makefile`, and `README`.

"Empty folders" hides logically empty folders. A folder is logically empty when no visible file or subfolder remains after the selected file types and all other rules are applied.

The empty-folder count can therefore change after another rule is switched: hiding files can make their containing folders logically empty.

### 12.9 Counters
The count next to a rule shows its direct contribution under the current settings, not the physical number of similar items on disk.

One item is not attributed to several overlapping counters at the same time. For example, the `.git` folder may have both a dot-prefixed name and the system Hidden attribute, but its exclusion is attributed to only one rule.

A stable order is used to select the owner of an exclusion:

* folders: `.gitignore`, Smart Ignore, dot-prefixed name, system Hidden attribute;
* files: `.gitignore`, Smart Ignore, dot-prefixed name, no extension, empty file, system Hidden attribute.

This order affects counters only. Final visibility follows a simpler rule: an item is hidden if any enabled mechanism excludes it.

### 12.10 Applying changes
Switching checkboxes first updates the available settings and counters in the panel. The final tree is rebuilt after "Apply settings" is selected.

If settings preparation is cancelled, DevProjex returns the panel to the last fully completed state. Partially calculated rules are not applied.

## 13) How the tree and metrics are calculated
Result depends on:
* selected Extensions
* Ignore rules
* active Filter
* checked tree nodes (for selection-based operations)

If access is denied, the node keeps its usual name and icon and gets an "[access denied]" suffix.

### 13.1 What status bar counters show
The status bar has two blocks:
* Tree — metrics of the tree text output;
* Content — metrics of exported file content output.

Format:
* Lines
* Chars
* ~Tokens (approximate)

Large values are shown with compact suffixes (K/M).

Important:
* "Lines" in the "Tree" block means the number of lines in the final tree representation, not the number of files on disk;
* this value includes folders, files, and tree service elements (for example, access-denied nodes).

### 13.2 How metrics are calculated
Tree metrics:
* are calculated from the actual tree output generated by the same export pipeline;
* respect the current tree format.

Content metrics:
* follow the same rules as content copy/export;
* binary files are excluded;
* empty and whitespace-only files are counted via service markers (`[No Content, 0 bytes]`, `[Whitespace, N bytes]`).

### 13.3 When counters update
Recalculation runs:
* after opening/refreshing a project;
* after applying settings (exclusions and extensions);
* when tree checkboxes change (with debounce);
* when switching tree format (for operations where tree output is used).
* when background calculation is canceled, counters are set to 0 until the next completed recalculation.

## 15) Theme and effects
The Theme section lets you select System, Light, or Dark and one background effect:
* Transparency
* Blur
* Mica

System is selected by default and follows operating-system theme changes. After first launch or a settings reset, a light system theme starts with a regular opaque background, while a dark system theme starts with Blur. If the system preference cannot be determined, DevProjex uses Dark with Blur. Light and Dark remember their effects independently. An explicit Light or Dark selection ignores system changes until System is selected again.

Effects are mutually exclusive. Clicking the selected effect again disables it and restores a regular opaque background.

Available settings:
* Background transparency — available for Transparency and Blur.
* Top panel contrast — adjusts the main panel containing Preview, Search, Filter, and tree-format commands.
* Menu transparency — applies equally to the main menu and its submenus.
* Border visibility — adjusts how strongly interface borders are shown.

Mica uses the platform's system material and has no separate background-transparency setting. If the selected Blur or Mica effect is unavailable, the app first tries the other native effect. A regular opaque background is used only when neither Blur nor Mica is available.

In Transparency mode, the main-window background remains transparent. Menus, submenus, and other popup surfaces use Blur when supported so tree and content elements behind them do not interfere with readability.

## 16) Help

### 16.1 Updates
“Help → Updates” compares the current version with the latest stable GitHub release. Automatic checks are off by default; when enabled, DevProjex checks at startup after at least seven days have passed since the previous successful check. The checkbox takes effect immediately. The latest successful result is retained between application runs and is not erased by a later network failure. Installation remains a user action.

### 16.2 Reset settings
Reset settings (Help → Reset settings) restores the default theme, effects, Compact mode, Tree expansion animation, and interface language. Project profiles, history, and files on disk are not changed.

### 16.3 Reset data
Reset data (Help → Reset data) removes saved local-project parameter profiles:
* selected file types;
* selected options in the "Exclusions" section.

Important:
* Recent history for local folders is not cleared;
* Recent repositories history in the Git Clone window is not cleared;
* files and folders on disk are not modified or deleted.

## 17) Languages
Language is selected via the Language menu.
The selected language is saved between launches. “Help → Reset settings” clears the saved language choice and returns the interface language to the default.

## 18) Progress bar and cancel
The center of the status bar shows the active operation and its progress.

Progress modes:
* Indeterminate — no percent (operation duration is unknown).
* Determinate — with percent (0–100).

Behavior:
* during background data calculation, percent progress is shown;
* for some Git operations, percent is shown when the progress source provides it;
* available-option updates and settings application are shown when the operation takes noticeable time;
* fast operations finish without showing progress.

X button (cancel) in the status bar:
* performs best-effort cancellation for operations that support cancellation;
* stops background data calculation;
* when an available-options update is canceled, returns the panel to its last completed state;
* for operations without cancellation support, it stops status-bar indication, while the operation itself may still finish in background.
