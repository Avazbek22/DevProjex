## 1) What it is and why
DevProjex quickly prepares project context: shows the folder/file structure, lets you select items with checkboxes, and copy the tree and/or file contents to the clipboard. Useful for code review, support, learning, and sharing project structure with an AI assistant.

Important: the app is read-only and never modifies files.

## 2) Project tree
* File/folder type icons.
* Checkboxes on nodes.
* Expand/collapse.

Checkboxes: selecting a node applies to its children; parent state is recalculated automatically.

Hotkeys:
* Ctrl+E — expand all
* Ctrl+W — collapse all (root stays expanded)

## 3) File
* Open folder… — open root folder (Ctrl+O)
* New window — open a new independent DevProjex instance
* Recent — list of recently opened local folders
* Refresh — rescan and rebuild the tree (F5)
* Export to file:
  * Export tree
  * Export content
  * Export tree and content

Format rules:
* Export tree:
  * ASCII -> `.txt` only.
  * JSON -> default `.json`, with both `.json` and `.txt` available in Save dialog.
* Export content — always text content format, `.txt` file (ASCII/JSON toggle does not apply).
* Export tree and content — always `.txt` file; the ASCII/JSON toggle affects only the tree block format inside the result.

Export files are written in UTF-8 without BOM.

### Drag & Drop
Drag and drop works in the startup area (Drop Zone) when no project is loaded.

Rules:
* you can drop a folder;
* you can drop a file — in this case the containing folder is opened;
* if multiple items are dropped, the first suitable local path is used;
* if a path is unavailable or does not exist, the same access checks as in “Open folder…” are applied;
* unsupported or non-local items are ignored.

### Recent
The “File → Recent” item shows the history of recently opened local folders.

Rules:
* only local folders are added to the list;
* Git repositories cloned via DevProjex are not added to this list;
* duplicates are not created — opening the same folder again moves it to the top;
* up to 10 recent folders are stored;
* history is preserved between app launches.

Each item shows the short folder name, and the full path is available in a tooltip.

## 4) Launch from terminal
DevProjex can be launched from the terminal.

If the command is already set up, open a terminal and run:
`devprojex --help`

This shows all available commands, options, and examples.

Examples:
* `devprojex .` — open the current folder.
* `devprojex "C:\Projects\App"` — open the specified folder.
* `devprojex . --export tree` — print the project tree in the terminal.
* `devprojex . --export content` — print file contents in the terminal.
* `devprojex . --export tree-content` — print the tree and contents in the terminal.
* `devprojex . --export tree-content -o context.txt` — save the result to a file.

Notes:
* `.` means the current terminal folder;
* paths with spaces must be wrapped in quotes;
* if no output file is specified, the result is printed directly to the terminal;
* the command does not modify project files — DevProjex works in read-only mode.

If the `devprojex` command does not work, open in DevProjex:
“Help → Launch from terminal”.

## 5) Git
Git menu is available only for projects cloned via DevProjex (Git Clone). The app does not touch your files — it works only with the cache.

The cache is stored in the system temp folder. On Windows it is usually:
`%TEMP%\DevProjex\RepoCache`

* Branch — shows the list of available branches with the active one marked; switching updates the tree to the selected branch. If the branch already exists locally, switching is offline (no update). If it does not exist locally, it is fetched and created.
* Get updates — updates only the current branch: fetch and reset to origin/<branch>.

### Clone window
In the Git Clone window, a “Recent repositories” list can appear below the URL field.

Rules:
* the list appears only if the history already contains recently cloned repositories;
* only repository URLs are added to the list;
* local folders are not added to this list;
* duplicates are not created — cloning the same repository again moves it to the top;
* up to 7 recent repositories are stored;
* history is preserved between app launches.

Selecting an item automatically fills the URL field.
While cloning is in progress, the list is temporarily hidden.

## 6) Copy
### Tree format toggle (ASCII/JSON)
The toggle defines the tree representation format for operations where the tree is part of the output.

* ASCII — text tree with branches.
* JSON — structured tree in JSON.

The toggle affects:
* Copy tree
* Copy tree + content
* Export tree
* Export tree and content

The toggle does not affect:
* Copy content
* Export content

### Copy tree
Copies the project tree.
If there are checked nodes, the tree is built from selection; if the selection is empty or invalid, the full tree is copied.
The result format is defined by the ASCII/JSON toggle.
Hotkeys: Ctrl+Shift+C and Ctrl+Alt+C.

### Copy content
Copies file contents:
* if files are checked — only those; otherwise — all project files;
* non-text files are ignored (including binary);
* for empty text files, the path and the line `[No Content, 0 bytes]` are output;
* for files containing only whitespace/line breaks, the path and the line `[Whitespace, N bytes]` are output.
Hotkey: Ctrl+Alt+V.

### Copy tree + content
Combines tree and content:
* tree is built from selection; if selection is empty/invalid, the full tree is used;
* content follows the same rules as “Copy content”;
* tree block format is defined by the ASCII/JSON toggle.
Hotkey: Ctrl+Shift+V.

### JSON representation
JSON mode uses a compact tree structure.

Tree (Copy tree / Export tree):
* `rootPath` — root path in the current output format:
  * for a local folder — absolute local path;
  * for a Git project — repository URL.
* `root` — root node.
* node fields: `name`, `path`, `dirs`, `files`, `accessDenied` (when needed).

Tree + content:
* JSON applies to the tree block;
* content block remains text;
* exported as `.txt`.

## 7) Preview mode
Opened with the eye icon button in the top bar or with Ctrl+B.

Shows the final result in a separate workspace next to the tree. This mode does not copy to the clipboard and does not export to a file on its own — it is a viewing mode.

By default, the workspace opens as:
* left — project tree;
* center — preview pane;
* right — settings panel, if it was open.

Available modes:
* Tree
* Content
* Tree and content

The same rules as copy and export are applied:
* checked nodes are respected;
* if selection is empty, the full data set is used;
* current ignore rules and selection options are applied.

Additionally:
* files in preview are separated by horizontal lines;
* while scrolling, the path of the current file is pinned at the top;
* tree and preview zoom can live independently.
* in Preview mode, you can copy either the full current result or the current visible file block without opening the Copy menu.

Buttons:
* copy button on the left side of the top preview island — copies the current preview mode:
  * Tree
  * Content
  * Tree and content
* X in the tree pane — hides the tree and leaves only the preview pane;
* X in the top preview pane — closes Preview mode completely;
* small copy button in the pinned file header — copies the current visible file block exactly as it is shown in Preview;
* pressing the eye icon again or Ctrl+B also closes Preview mode.

Search and Filter are available while the tree pane is visible in Preview.
If the tree is hidden, Search and Filter are temporarily unavailable until you leave preview-only mode.

## 8) View
### Zoom
* Ctrl++ / Ctrl+= — zoom in
* Ctrl+- — zoom out
* Ctrl+0 — reset
* Ctrl + mouse wheel — smooth zoom in the pane under the cursor

Behavior:
* in normal mode, the tree is zoomed;
* in Preview with the tree visible, Zoom In, Zoom Out, and Reset from the menu apply to both the tree and the preview;
* with Ctrl + mouse wheel, tree and preview zoom independently depending on where the cursor is;
* in preview-only mode, only the preview pane is zoomed.

Range: 6–28, reset is 15.

### Compact Mode
Makes the UI denser: smaller spacing in the tree and settings.
While the preview workspace is active, Compact Mode is enabled automatically.

### Tree animation
Enables smooth slide animation when hovering over tree rows.

### Tree font
The tree font is selected via “View → Tree font”.
“Default” restores the standard tree font.
The selected font is applied after clicking “Apply settings” in the settings panel.

## 9) Search (tree)
Opens the search bar, highlights matches, and allows navigation.
* Ctrl+F — show/hide
* Enter — next result
* Shift+Enter — previous
* Esc — close

Search auto-expands only the needed branches; clearing the query collapses the tree (except root).
For very large match sets, the app may limit auto-expand and global highlighting to keep the UI responsive.
When the search bar is closed, the query is cleared after the close animation completes.

Constraints:
* opening Search closes Filter automatically;
* Search is available in Preview while the tree pane is visible;
* if the tree is hidden, Search is temporarily unavailable.

## 10) Filter (by name)
Shows only nodes matching the filter string and their parents. Updates are debounced.
* Ctrl+Shift+N — show/hide filter
* Esc — close filter

Constraints:
* opening Filter closes Search automatically;
* Filter is available in Preview while the tree pane is visible;
* if the tree is hidden, Filter is temporarily unavailable.

## 11) Options (settings panel)
Available on the right:
* Apply settings
* Ignore options
* Extensions
* Root folders

Changes in “Ignore options”, “Extensions”, and “Root folders” are staged in the panel and applied after clicking “Apply settings”.

Each list has an All toggle.

Note about "Extensions":
* this list shows only files that have an extension;
* files without an extension are not added to this list and are controlled by a separate option in "Ignore".

Ctrl+P — show/hide the panel.

### 11.1 Local project parameter profiles
For local folders, DevProjex remembers the last applied project parameters:
* selected top-level folders;
* selected file types;
* selected options in the "Ignore" block.

Saving is performed when you click "Apply settings".
When the same local folder is opened again, parameters are restored automatically.

Important:
* profiles are saved only for local projects;
* for projects opened via Git Clone, profiles are not saved;
* if some saved options are no longer available in the current project, they are skipped, and the remaining parameters are applied.
* if refresh or reopening reveals a new top-level folder, file type, or option in "Ignore", it is enabled by default;
* options already seen keep the user's explicit choice: new files of a disabled type do not enable that type again.

## 12) Ignore
The "Ignore" list is built automatically from the current path and selected top-level folders.

Option order:
* Smart ignore (when available)
* Use .gitignore (when at least one `.gitignore` is found)
* Empty folders
* Empty files
* Hidden folders
* Hidden files
* Dot-prefixed folders
* Dot-prefixed files
* Files without extension

Basic-rule options (hidden, dot-prefixed, empty, extensionless) are shown only when matching elements exist.
When an option in "Ignore" becomes available for the first time, it is enabled by default. An option explicitly disabled earlier keeps that state when it becomes available again.

The separator under "Use .gitignore" splits Git/Smart rules from basic visibility rules.

### 12.1 Rule scope
The app builds project scopes where ignore rules are applied:
* root (if root has `.gitignore` or a project marker)
* first-level folders
* nested project subfolders

Nested project scope discovery depth is fixed: 2 levels.
This limit only controls discovery of nested scopes for `.gitignore` and Smart Ignore. Once a scope is found, rules are applied to that scope's contents through the normal tree scan.

### 12.2 "Use .gitignore"
* Enabled: `.gitignore` rules are applied in detected scopes.
* Disabled: `.gitignore` rules are fully disabled.

For multi-project folders, one project's `.gitignore` is not applied to neighboring projects outside its scope.

### 12.3 "Smart ignore"
* Shown only when it is relevant.
* Enabled: common build/tool artifacts are additionally hidden.
* Disabled: smart rules are not applied.

### 12.4 Basic rules
Options:
* Hidden folders
* Hidden files
* Dot-prefixed folders
* Dot-prefixed files
* Empty folders
* Empty files
* Files without extension

When enabled, an option hides matching elements from the tree and from copy/export results.
Basic rules are enabled separately from `.gitignore` and Smart Ignore, but the final result is always calculated from the current tree after all active filters are applied.

### 12.5 Internal behavior: common cases
1. Single project with `.gitignore`.
Usually only "Use .gitignore" is shown.
When enabled, `.gitignore` and Smart Ignore work together.
When disabled, both `.gitignore` and Smart Ignore are disabled.

2. Single project without `.gitignore`.
"Use .gitignore" is not shown.
"Smart ignore" is shown only when relevant.

3. Multi-project workspace, some projects have `.gitignore`, some do not.
Both "Use .gitignore" and "Smart ignore" are shown.
`.gitignore` works inside its own scopes.
Smart Ignore (when enabled) complements filtering in detected scopes.

4. Multi-project workspace, all projects have `.gitignore`.
"Use .gitignore" is shown.
"Smart ignore" is not shown as a separate option.

5. Folder without relevant rules.
If no `.gitignore` is found and Smart Ignore is not relevant, these options are hidden.
Only basic visibility rules remain.

### 12.6 Empty folders
Hides logically empty folders from the tree and from copy/export results.
A logically empty folder is a folder that has no visible descendants after the current visibility rules, `.gitignore`, Smart Ignore, and selected file types are applied.
If the folder itself is not hidden by other rules, removing it from the tree is controlled by this option.

### 12.7 Empty files
Hides empty files with size 0 bytes from the tree and from copy/export results.

### 12.8 Files without extension
Hides files without extension (for example: `Dockerfile`, `Makefile`, `README`) from the tree and from copy/export results.

### 12.9 Counters in the "Ignore" block
Counts are shown near available options in the `(N)` format.
For basic rules, this count shows how many elements are hidden by that specific rule in the current tree configuration.
## 13) How the tree and metrics are calculated
Result depends on:
* selected Root folders
* selected Extensions
* Ignore rules
* active Filter
* checked tree nodes (for selection-based operations)

If access is denied, the node is marked Access denied.

### 13.1 What status bar counters show
The status bar has two blocks:
* Tree — metrics of the tree text output;
* Content — metrics of exported file content output.

Format:
* Lines
* Chars
* ~Tokens (approximate)

Large values are shown with compact suffixes (K/M).

Important:
* "Lines" in the "Tree" block means the number of lines in the final tree representation, not the number of files on disk;
* this value includes folders, files, and tree service elements (for example, access-denied nodes).

### 13.2 How metrics are calculated
Tree metrics:
* are calculated from the actual tree output generated by the same export pipeline;
* respect the current ASCII/JSON format.

Content metrics:
* follow the same rules as content copy/export;
* binary files are excluded;
* empty and whitespace-only files are counted via service markers (`[No Content, 0 bytes]`, `[Whitespace, N bytes]`).

### 13.3 When counters update
Recalculation runs:
* after opening/refreshing a project;
* after applying settings (ignore, extensions, root folders);
* when tree checkboxes change (with debounce);
* when switching ASCII/JSON (for operations where tree output is used).
* when background calculation is canceled, counters are set to 0 until the next completed recalculation.

## 15) Theme and effects
Theme popover lets you switch:
* light/dark theme

Items marked [Beta] may change between versions.

## 16) Help

### 16.1 Reset settings
Reset settings (Help → Reset settings) resets only visual interface settings (theme, effects, Compact mode, Tree animation) and does not modify project data.
Reset settings also clears the saved interface language selection.

### 16.2 Reset data
Reset data (Help → Reset data) removes saved local-project parameter profiles:
* selected top-level folders;
* selected file types;
* selected options in the "Ignore" block.

Important:
* Recent history for local folders is not cleared;
* Recent repositories history in the Git Clone window is not cleared;
* files and folders on disk are not modified or deleted.

## 17) Languages
Language is selected via the Language menu.
The selected language is saved between launches. “Help → Reset settings” clears the saved language choice and returns the interface language to the default.

## 18) Progress bar and cancel
The center of the status bar shows the active operation and its progress.

Progress modes:
* Indeterminate — no percent (operation duration is unknown).
* Determinate — with percent (0–100).

Behavior:
* during background data calculation, percent progress is shown;
* for some Git operations, percent is shown when the progress source provides it;
* for very fast operations, progress can appear only briefly.

X button (cancel) in the status bar:
* performs best-effort cancellation for operations that support cancellation;
* stops background data calculation;
* for operations without cancellation support, it stops status-bar indication, while the operation itself may still finish in background.

## 19) Notes
* By default, dark theme and transparency effects are enabled (if supported).
* If permissions are insufficient, the app may suggest restarting with elevation; if declined, a notification is shown.
