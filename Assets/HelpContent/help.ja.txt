## 1) それは何か、そしてなぜ
DevProjex、プロジェクト コンテキストを迅速に準備します。フォルダー/ファイル構造を表示し、チェックボックスで項目を選択し、ツリーやファイルの内容をクリップボードにコピーできます。コードのレビュー、サポート、学習、およびAIアシスタントとのプロジェクト構造の共有に役立ちます。

重要: DevProjex、開いたプロジェクト内のファイルを変更しません。

## 2) プロジェクトツリー
* ファイル/フォルダーの種類のアイコン。
* ノード上のチェックボックス。
* 展開/折りたたみ。

チェックボックス: ノードの選択はその子に適用されます。親の状態は自動的に再計算されます。

ホットキー:
* {mod}E — すべて展開
* {collapseAll} — すべてを折りたたみます (ルートは展開されたままになります)

### コンテキストメニュー
ノードを右クリックするか、フォーカスされたノードで{shift}F10またはメニュー キーを押します。
* ファイル エクスプローラーで表示 / Finderで表示 / ファイル マネージャーで開く — システム ファイル マネージャーでアイテムを表示します。ラベルは現在のプラットフォームと一致します。
* フルパスをコピーします — 項目の絶対パス。
* 相対パスをコピーします。ルート フォルダー名で始まるプロジェクト ルートからのパス (例: `project/src/File.cs`)。
* コンテンツのコピー — ファイルの場合: コピーとエクスポートで作成されたとおりに、適用されたコンテンツ変換を使用してコンテンツをコピーします。
* これのみを選択 — このノードのみをチェックし、残りをクリアします。他の項目もチェックされている場合にのみ表示されます。
* ブランチを展開/ブランチを折りたたむ — フォルダーの場合。

パスがディスク上に存在しない場合、ファイル マネージャーで項目を開くか、その内容をコピーすると、エラー メッセージが表示されます。パスのコピーは引き続き機能します。

## 3) ファイル
* フォルダーを開く… — ルート フォルダーを開きます ( {mod}O)
* 新しいウィンドウ - 新しい独立したDevProjexインスタンスを開きます
* 最近 — 最近開いたローカル フォルダーのリスト
* 更新 — ローカル フォルダーを再スキャンし、ツリーを再構築します (F5)
* ファイルにエクスポート:
  * エクスポートツリー
  * コンテンツのエクスポート
  * ツリーとコンテンツをエクスポートする
* プロジェクトのエクスポート:
  * フォルダへ…
  * ZIPアーカイブに…

プロジェクトをエクスポートすると、ディレクトリ構造を維持しながら、現在のツリーから別のフォルダーまたはZIPアーカイブが作成されます。

選択したファイル タイプ、除外ルール、およびチェックされた項目が尊重されます。何もチェックされていない場合は、現在のツリー全体がエクスポートされます。

テキスト ファイルとバイナリ ファイルがコピーされ、含まれる空のフォルダーは保存されます。ソースファイルは変更されません。結果をソース プロジェクト内に保存することはできません。

エクスポート中は、ツリーや設定の変更、フィルターの使用、形式やプレビュー モードの変更、Gitコマンドの実行、更新、または別のプロジェクトを開くことはできません。

フォーマット規則:
* エクスポートツリー:
  * ASCII -> `.txt`のみ。
  * JSON -> デフォルトの`.json`。保存ダイアログで`.json`と`.txt`の両方を使用できます。
  * XML -> デフォルトの`.xml`。保存ダイアログで`.xml`と`.txt`の両方を使用できます。
  * MD -> デフォルトの`.md`。保存ダイアログで`.md`と`.txt`の両方を使用できます。
* コンテンツのエクスポート — 常にテキスト コンテンツ形式、`.txt`ファイル (ツリー形式の切り替えは適用されません)。
* ツリーとコンテンツをエクスポートします — 常に`.txt`ファイルです。選択したツリー形式は、結果内のツリー ブロック形式にのみ影響します。

エクスポート ファイルはBOMなしのUTF-8で書き込まれます。

### ドラッグ＆ドロップ
プロジェクトがロードされていない場合、ドラッグ アンド ドロップは起動領域 (ドロップ ゾーン) で機能します。

ルール:
* フォルダーをドロップできます。
* ファイルをドロップできます。この場合、ファイルを含むフォルダーが開きます。
* 複数の項目がドロップされた場合は、最初の適切なローカル パスが使用されます。
* パスが使用できないか存在しない場合は、「フォルダーを開く…」と同じアクセス チェックが適用されます。
* サポートされていない項目または非ローカルな項目は無視されます。

### 最近の
「ファイル→最近」項目には、最近開いたローカルフォルダーの履歴が表示されます。

ルール:
* ローカル フォルダーのみがリストに追加されます。
* DevProjex経由で複製されたGitリポジトリは、このリストには追加されません。
* 重複は作成されません。同じフォルダーをもう一度開くと、そのフォルダーが一番上に移動します。
* 最大32個の最近使用したフォルダーが保存されます。
* 履歴はアプリの起動間で保存されます。

各項目には、親フォルダーとプロジェクト名が表示されます（例：`Projects / App`）。

## 4) ターミナルから起動
DevProjexは、対話型のターミナルワークスペースと、スクリプトやCIで直接使えるコマンドを提供します。

コマンドがすでに設定されている場合は、ターミナルを開いて次を実行します。
`devprojex --help`

これには、最上位のコマンドとオプションがリストされます。`devprojex help <command>`を実行すると、そのコマンド自体のオプションと例が表示されます。

例:
* `devprojex` — 対話型のターミナル ワークスペースを開きます。ワークスペース内では、`:`コマンドラインを通じてアクションを実行します (例`:copy`、`:analyze`、`:branch`、`:language`)。完全なコマンド リストについては、組み込みワークスペースのヘルプとプロジェクトのドキュメントを参照してください。
* `devprojex tui .` — 指定されたフォルダーをターミナル ワークスペースで直接開きます。
* `devprojex open . --preview` — 現在のフォルダーをデスクトップ プレビューで開きます。
* `devprojex analyze . --format json` — 現在のプロジェクトをJSONとして分析します。
* `devprojex tree .` — プロジェクト ツリーをターミナルに出力します。
* `devprojex export context . --format markdown -o ../devprojex-context.md` — AI対応コンテキストをソース プロジェクトの外部に保存します。
* `devprojex export project . --as folder -o ../devprojex-submission` — 有効なプロジェクト ツリーを正確なフォルダーにエクスポートします。
* `devprojex export project . --as zip -o ../devprojex-submission.zip` — 有効なプロジェクト ツリーをZIPアーカイブにエクスポートします。
* `devprojex export context https://github.com/owner/repo -o -` — 自分でクローンを作成せずにリモート リポジトリをパックします。
* `devprojex analyze . --git-mode tracked --exclude smart-ignore` — Smart Ignoreを使用して追跡されたGitファイルを分析します。
* `devprojex mcp --root .` — AIエージェントがプロジェクトを安全に読み取れるように、ローカルの読み取り専用MCPサーバーを起動します。

注:
* `.`は現在のターミナルフォルダーを意味します。
* スペースを含むパスは引用符で囲む必要があります。
* `--git-mode`では、`none`、`gitignore`、`tracked`、`staged`、`changes`、`diff:<ref>..<ref>`のいずれかを選択します。
* `--exclude` Gitフィルタリングとは別に通常の除外を制御します。
* 分析コマンドとエクスポート コマンドは決定的であり、デスクトップ インターフェイスを開きません。
* `tui`、`open`、`analyze`、2つの`export`コマンドはGitリポジトリのURLも受け付けます。クローンは管理対象のキャッシュ（`devprojex cache`）に保存されます。
* コマンドには、`export ctx`、`-f`、`-n`などのエイリアスや短縮フラグが用意されています。`devprojex help`で確認できます。
* `analyze --findings`は元の値を表示せずにマスキング結果を一覧化し、`--fail-on-findings`はCI向けに0以外の終了コードを返します。
* コマンドがプロジェクトファイルを変更することはありません。DevProjexは読み取り専用モードで動作します。

`devprojex`コマンドが動作しない場合は、DevProjexで「ヘルプ→ターミナルから起動」を開いてください。

## 5) Git
Gitメニューは、DevProjexのGit Cloneでクローンしたプロジェクトでのみ利用できます。アプリは元のファイルには触れず、管理対象のキャッシュだけを操作します。

キャッシュはユーザーのシステム キャッシュ ディレクトリに保存されます。`devprojex doctor`を実行して、解決されたパスを確認します。

* ブランチ — 使用可能なブランチのリストをアクティブなブランチにマークを付けて表示します。切り替えると、選択したブランチにツリーが更新されます。ブランチがローカルにすでに存在する場合、スイッチングはオフラインになります (更新されません)。ローカルに存在しない場合は、フェッチされて作成されます。
* 更新を取得 — 現在のブランチのみを更新します。フェッチして、origin/<ブランチ> にリセットします。Git Cloneプロジェクトの場合、F5キーは同じアクションを実行します。通常の「ファイル → 更新」コマンドは無効になります。

### クローンウィンドウ
Git Cloneウィンドウでは、URLフィールドの下に「最近のリポジトリ」リストが表示されます。

ルール:
* このリストは、最近複製されたリポジトリが履歴にすでに含まれている場合にのみ表示されます。
* ネットワーク リポジトリ ソース（`https://`、`http://`、`ssh://`、`git://`、SCP形式）のみがリストに追加されます。
* ローカル パスと`file://`ソースはこのリストには追加されません。
* 重複は作成されません。同じリポジトリのクローンを再度作成すると、そのリポジトリが先頭に移動します。
* 最大16個の最近のリポジトリが保存されます。
* 履歴はアプリの起動間で保存されます。

項目を選択すると、URLフィールドに自動的に入力されます。
クローン作成の進行中、リストは一時的に非表示になります。

## 6) コピー
### ツリー形式の切り替え (ASCII / JSON / XML / MD)
トグルは、ツリーが出力の一部である操作のツリー表現形式を定義します。

* ASCII — ブランチのあるテキスト ツリー。
* JSON — JSONの構造化ツリー。
* XML — パーサーとツール用のコンパクトなXMLツリー。
* MD — ドキュメントとAIプロンプト用のマークダウンのネストされたリスト。

トグルは以下に影響します。
* ツリーのコピー
* ツリーとコンテンツをコピー
* エクスポートツリー
* ツリーとコンテンツをエクスポートする

トグルは以下には影響しません。
* コンテンツをコピーする
* コンテンツのエクスポート

### ツリーのコピー
プロジェクトツリーをコピーします。
チェックされたノードがある場合、ツリーは選択に基づいて構築されます。選択内容が空または無効な場合は、ツリー全体がコピーされます。
結果の形式は、ツリー形式の切り替えによって定義されます。
ホットキー: {mod}{shift}Cおよび{mod}{alt}C。

### コンテンツをコピーする
ファイルの内容をコピーします:
* ファイルがチェックされている場合は、そのファイルのみ。それ以外の場合 - すべてのプロジェクト ファイル。
* 各ファイルの前には、完全なローカル パス ( Git Cloneプロジェクトの場合はリポジトリWebパス) を含むヘッダーが続きます。
* 非テキスト ファイル (バイナリを含む) は無視されます。
* 空のテキスト ファイルの場合は、パスと行`[No Content, 0 bytes]`が出力されます。
* ホワイトスペース/改行のみを含むファイルの場合は、パスと行`[Whitespace, N bytes]`が出力されます。
ホットキー: {mod}{alt}V.

### ツリーとコンテンツをコピー
ツリーとコンテンツを結合します。
* ツリーは選択内容から構築されます。選択が空または無効の場合は、ツリー全体が使用されます。
* コンテンツは「コンテンツのコピー」と同じルールに従います。
* ツリー ブロック形式は、ツリー形式の切り替えによって定義されます。
ホットキー: {mod}{shift}V.

### ツリー表現
ツリー形式では、選択した同じプロジェクト ツリーに対して異なる表現が使用されます。

JSON:
* `rootPath` — `/`で正規化された絶対ルート パス。
* `tree` — ルート フォルダーの内容。
* JSONエクスポートでは、このツリー形式が使用されます。配列にはファイルが含まれ、オブジェクトにはサブフォルダーが含まれ、`/`には現在のフォルダー内のファイルが含まれ、`[]`は空のフォルダーを表します。

XML:
* ルートノードは`<t r="...">`です。
* フォルダーは`<d n="...">`です。
* ファイルは`<f>File.cs</f>`です。

MD:
* `Root: ...`で始まります。
* Markdownのネストされたリストを使用します。
* フォルダーは`/`で終わります。

ツリー + コンテンツ:
* 選択したツリー形式がツリー ブロックに適用されます。
* コンテンツブロックはテキストのままです。
* コンテンツ ブロック内のファイル ヘッダーは`/`を含む相対パスを使用します。
* `.txt`としてエクスポートされます。

## 7) プレビューモード
トップバーの目のアイコンボタンまたは{mod}Bで開きます。

マウスのサイド ボタンはブラウザ スタイルのナビゲーションに従います。[進む] でプレビュー モードが開き、[戻る] でプレビュー モードが閉じます。現在の方向を繰り返しても効果はありません。

{mod}{shift}Fは、プレビューでファイルの内容の検索を開始または終了します。EnterまたはF3を押すと次の一致に進みます。{shift}Enterまたは{shift}F3で前の一致に移動します。

最終結果をツリーの隣の別のワークスペースに表示します。このモードはクリップボードにコピーせず、独自にファイルにエクスポートしません。これは表示モードです。

デフォルトでは、ワークスペースは次のように開きます。
* 左 - プロジェクト ツリー。
* 中央 - プレビュー ペイン。
* 右 — 設定パネル（開いている場合）。

利用可能なモード:
* 木
* コンテンツ
* ツリーとコンテンツ

コピーとエクスポートと同じルールが適用されます。
* チェックされたノードは尊重されます。
* 選択が空の場合は、完全なデータセットが使用されます。
* 現在の無視ルールと選択オプションが適用されます。

さらに：
* プレビュー内のファイルは水平線で区切られています。
* スクロール中、現在のファイルのパスが上部に固定されます。固定されたパスをクリックすると、そのファイルの先頭にスクロールして戻ります。
* プレビュー スクロールバーは、検索の一致と編集結果のある行をマークします。マーカーをクリックするとその行にジャンプします。そのままの結果はマークされたままになり、マスクされたパス ヘッダーは最初の行に1つのマーカーを追加します。
* ツリーとプレビュー ズームは独立して動作できます。
* プレビュー モードでは、[コピー] メニューを開かずに、現在の結果全体または現在表示されているファイル ブロックのいずれかをコピーできます。

ボタン:
* 上部のプレビュー アイランドの左側にあるコピー ボタン — 現在のプレビュー モードをコピーします。
  * 木
  * コンテンツ
  * ツリーとコンテンツ
* ツリー ペインのX — ツリーを非表示にし、プレビュー ペインのみを残します。
* 上部のプレビュー ペインのX — プレビュー モードを完全に閉じます。
* 固定されたファイル ヘッダーにある小さなコピー ボタン — 現在表示されているファイル ブロックを、プレビューに表示されているとおりに正確にコピーします。
* 目のアイコンをもう一度押すか、{mod}Bを押すと、プレビュー モードも閉じます。

ツリー ペインがプレビューに表示されている間は、検索とフィルターを使用できます。
ツリーが非表示の場合、プレビュー専用モードを終了するまで、検索とフィルターは一時的に使用できなくなります。

## 8) 見る
### ズーム
* {mod}+ / {mod} = — ズームイン
* {mod} - — ズームアウト
* {mod}0 — リセット
* {mod}マウスホイール — カーソルの下のペインをスムーズにズームします

行動：
* 通常モードでは、ツリーがズームされます。
* ツリーが表示されているプレビューで、メニューのズームイン、ズームアウト、およびリセットはツリーとプレビューの両方に適用されます。
* {mod}マウス ホイールを使用すると、カーソルの位置に応じてツリーとプレビューが個別にズームします。
* プレビュー専用モードでは、プレビュー ペインのみがズームされます。

範囲: 6 ～ 28、リセットは15。

### コンパクトモード
UIがより密になり、ツリーと設定の間隔が狭くなります。
プレビュー ワークスペースがアクティブな間は、コンパクト モードが自動的に有効になります。

### アニメーション
「表示→アニメーション」では、ツリーの展開、ステータスカウンター、ツールの初回表示を個別に設定できます。3つのアニメーションは既定で有効です。無効にしたアニメーションは最終状態をすぐに表示します。

### ツリーフォント
ツリーフォントは「表示→ツリーフォント」で選択します。
「デフォルト」は標準のツリーフォントを復元します。
設定パネルの「設定を適用」をクリックすると、選択したフォントが適用されます。

## 9) 検索(ツリー)
検索バーを開き、一致するものを強調表示して、ナビゲーションを可能にします。
* {mod}F — 表示/非表示
* 入力してください — 次の結果
* {shift}Enter — 前へ
* Esc — 閉じる

検索は必要なブランチのみを自動展開します。クエリをクリアすると、ツリー (ルートを除く) が折りたたまれます。
マッチ ラインはツリー スクロールバーにもマークされます。マーカーをクリックすると、その一致にジャンプします。
非常に大規模な一致セットの場合、アプリはUIの応答性を維持するために自動展開とグローバル ハイライトを制限する場合があります。
検索バーを閉じると、閉じるアニメーションが完了した後にクエリがクリアされます。

制約:
* 検索を開くとフィルターが自動的に閉じます。
* 検索は、ツリー ペインが表示されている間はプレビューで利用できます。
* ツリーが非表示になっている場合、検索は一時的に利用できなくなります。

## 10) フィルター (名前による)
フィルター文字列に一致するノードとその親のみを表示します。更新はデバウンスされます。
* {mod}{shift}N — フィルタの表示/非表示
* Esc — フィルターを閉じる

制約:
* フィルターを開くと検索が自動的に閉じます。
* ツリー ペインが表示されている間、フィルターはプレビューで使用できます。
* ツリーが非表示の場合、フィルターは一時的に使用できなくなります。

## 11) オプション (設定パネル)
右側で利用可能:
* 設定を適用する
* コンテンツ処理
* 除外事項
* 拡張機能

「除外」と「拡張」の変更はパネル内で段階的に行われ、「設定を適用」をクリックした後に適用されます。

チェックボックスが変更された後、アプリは利用可能なオプションとその数をバックグラウンドで更新する場合があります。結果のツリーは、「設定を適用」をクリックした後にのみ再構築されます。

ステータス バーの [X] ボタンを使用して利用可能なオプションの更新をキャンセルすると、未完了の変更は適用されず、パネルは最後に完了した状態に戻ります。

各リストには [すべて] の切り替えがあります。

「拡張機能」についての注意:
* このリストには拡張子を持つファイルのみが表示されます。
* 拡張子のないファイルはこのリストに追加されず、「除外」の別のオプションによって制御されます。

コンテンツ処理:
* ツリーを変更せずに、選択したテキスト ファイルの内容を変換します。
* 「シークレットを隠す」と「個人データを隠す」は、検出された値を置き換えます（セクション12.3および12.4）。
* コードを圧縮すると、14の言語にわたって名前付き実装が短縮されながら宣言が保持されます。
* コメントの削除は、20の言語パックにわたるコメントとドキュメントのコメントを削除します。
* 空白行の除去は、複数行リテラルを保持しながら、同じパック内の空白のみの行を削除します。
* 変更は「設定の適用」後に有効になります。

{mod}P — パネルを表示/非表示にします。

### 11.1 ローカルプロジェクトパラメータプロファイル
ローカル フォルダーの場合、DevProjex最後に適用されたプロジェクト パラメーターを記憶しています。
* 選択されたファイルの種類。
* 「除外」セクションで選択したオプション。

「設定を適用」をクリックすると保存が行われます。
同じローカルフォルダーを再度開くと、パラメータは自動的に復元されます。

重要：
* プロファイルはローカル プロジェクトに対してのみ保存されます。
* Git Clone経由で開かれたプロジェクトの場合、プロファイルは保存されません。
* 保存されたオプションの一部が現在のプロジェクトで使用できなくなった場合、それらはスキップされ、残りのパラメータが適用されます。
* 更新または再度開くと、「除外」に新しいファイル タイプまたはオプションが表示される場合、デフォルトで有効になります。
* すでに表示されているオプションでは、ユーザーの明示的な選択が維持されます。無効になったタイプの新しいファイルは、そのタイプを再度有効にしません。

## 12) 除外事項
「除外」セクションでは、ツリー、コンテンツ、コピー、エクスポートの結果からどのファイルとフォルダーを除外するかを制御します。

項目は、次の条件がすべて満たされた場合にのみ表示されます。
* ファイルにタイプがある場合は、そのファイル タイプが選択されます。
* 有効な無視ルールでは除外されません。

無視ルールは累積されます。少なくとも1つの有効なルールによって項目が非表示になっている場合、別のルールではその項目を表示できません。

### 12.1 利用可能なルール
プロジェクトの内容に応じて、次のオプションが表示される場合があります。

* Smart Ignore
* 空のフォルダー
* 空のファイル
* 隠しフォルダー
* 隠しファイル
* ドット接頭辞の付いたフォルダー
* ドット接頭辞のファイル
* 拡張子のないファイル

Gitリポジトリ内のGUIでは、フィルタリングなし、`.gitignore`、追跡対象、ステージ済み、現在のすべての変更という5つのGitモードから選択できます。リポジトリ外では、フィルタリングなしと`.gitignore`だけを選択できます。TUIでは常に同じ5つの値がラジオ項目として表示されますが、リポジトリがない場合はリポジトリを必要とする項目が無効になります。`diff:<ref>..<ref>`スコープが有効な場合は6行目に表示されます。値を選ぶと、Smart Ignoreや基本的な除外を変更せずに現在のGitモードだけが置き換わります。他の項目は、その規則が現在のツリーに影響する場合に表示されます。

新しいオプションは、最初に表示されたときにデフォルトで有効になります。既知のオプションは、リストから一時的に消えた場合でも、ユーザーの選択を保持します。

### 12.2 Smart Ignore
Smart Ignore、依存関係、ビルド出力、キャッシュ、およびその他のプロジェクト サービス アーティファクトを非表示にします。

DevProjexまず、次のように構造ファイルとマーカー ファイルからプロジェクト タイプを識別します。

* `.csproj`
* `package.json`
* `pyproject.toml`
* `Cargo.toml`

対応するスタックのルールは、検出されたプロジェクト スコープ内に適用されます。たとえば、.NETルールは、隣接するPythonまたはJavaScriptプロジェクトには拡張されません。

フォルダー名だけでは必ずしも十分とは限りません。`build`、`vendor`、`packages`、`cache`、`pkg`、`Library`などのあいまいな名前も、その内容によって検証されます。これにより、名前が似ているという理由だけで通常のユーザー フォルダーが非表示になることがなくなります。

一部の依存関係ストアとサービス ディレクトリは、明示的に検出されたプロジェクトの外部であっても、その特徴的な内部構造によって認識できます。

プロジェクト スコープの検出には制限があるため、大きなユーザー フォルダーを読み込んでも、すべてのディレクトリを完全に繰り返し分析することにはなりません。通常の構造では浅い検出が使用されますが、認識されたモノリポジトリはより深く検索されます。スコープが見つかると、Smart Ignore深さ制限なしでそのサブツリー全体に適用されます。

### 12.3 秘密を隠す
「シークレットの非表示」はデフォルトではオフになっています。選択したテキスト コンテンツのみをスキャンし、検出された各値を所定の位置に置き換え、ファイルとその周囲のコードを保持します。このオプションがオフの場合、スキャンは実行されず、カウントは表示されません。現在の選択範囲がスキャンされると、ラベルに検出された値の数が表示されます。現状維持の決定により非表示にされる値が少ない場合は、検出/非表示と行の? が表示されます。インジケーターは両方のカウントを報告します。

マスキングされた範囲はプレビューで強調表示されます。クリックすると、その箇所だけを元の値のまま保持できます。{alt}↓ / {alt}↑で検出結果間を移動し、Enterで選択中の結果を切り替えます。ターミナルワークスペースでは、`[`と`]`で出現箇所間を移動し、`Enter`または`Space`で選択中の箇所を切り替えます。この決定は現在のセッションのプレビュー、クリップボード、コンテキストのエクスポート、フォルダーコピー、ZIPに適用されますが、プロジェクトプロファイルには保存されません。

プレビューのコンテキストメニューでは、判断の対象範囲を広げられます。検出箇所を右クリックすると、同じルールに該当するすべての箇所、または同じファイルで検出されたすべての箇所を、1回の操作でそのまま保持するか再度非表示にできます。ファイル内容で選択した値を手動でマークするには右クリックします。「ここで…を非表示」は現在のセッションでその箇所だけを非表示にし、「常に…を非表示」は値のすべての出現箇所に永続マークを作成します。「…を個人データとして非表示」は「個人データを非表示」で管理される永続マークを作成します。「マークを削除」は手動マークを削除しますが、検出器が引き続き一致させる値は非表示のままです。手動で選択する値は、ファイル内容内の8～512文字の単一行である必要があります。マークを作成すると対応するオプションが自動的に有効になります。永続マークに保存されるのはキー付きハッシュによる値IDと分類だけで、元のテキストは保存されません。

フォルダーまたはZIPコピーも一致するテキストを変更し、ビルドまたは実行できなくなる可能性があります。バイナリ ファイルは変更されずにコピーされ、スキャンされません。選択したテキスト ファイルが16 MiBを超える場合、そのファイルは除外されて報告され、残りの出力は完了します。検出に失敗すると、操作全体が停止します。

カウントはルールの一致のみを報告します。ゼロはプロジェクトが安全であることを意味するものではありません。CLI `--hide-secrets`を使用します。技術的な詳細と制限は`Docs/HideSecrets.md`に記載されています。

### 12.4 個人データを非表示にする
「個人データを非表示にする」はデフォルトでオフです。選択したテキストファイル内のメールアドレス、グローバルIPアドレス、パス内のローカルユーザー名、MACアドレス、国際電話番号を検出します。検出結果には「シークレットを非表示」と同じプレビュー上の判断と出力パイプラインが適用されます。「…を個人データとして非表示」で作成した手動マークもこの分類に属し、このスイッチに従います（セクション12.3）。生成されたパスヘッダーとツリーのルートに含まれるローカルユーザー名は、1つの共有結果としてマスキングされます。カウンターでは1件として数えられ、?インジケーターに非表示か表示かが示されます。1回の操作ですべてのマスキング対象パスを切り替えられます。

ドキュメントの範囲とホスト、一般的なCIユーザー名、よく知られているパブリックDNSリゾルバー、およびドキュメント化された架空の電話範囲は引き続き表示されます。ゼロ一致はプライバシーを保証するものではありません。CLI `--hide-private-data`を使用します。完全なルールとフェーズ1の制限は`Docs/HidePrivateData.md`にあります。

### 12.5 .gitignoreの使用
有効にすると、DevProjex、開かれたフォルダーのルートにあるファイルだけでなく、到達可能なすべての`.gitignore`を適用します。

各`.gitignore`が適用されます。

* それを含むフォルダーに移動します。
* その下のアクセス可能なすべてのフォルダー。
* その範囲内でのみ。

ネストされた`.gitignore`からのルールは、親フォルダーや兄弟フォルダーには影響しません。

特定のパスの場合、ルールは親の`.gitignore`からより深いファイルに向かって処理されます。1つのファイル内で、ルールは上から下に処理されます。最後に一致したルールによってGit結果が決まります。

`!`で始まるルールは、そのスコープ内でのみ以前のGit除外をキャンセルします。親フォルダーが除外されたままになっていると、ファイルを復元できません。完全に除外され、到達不能なフォルダー内の`.gitignore`は評価に参加しません。

不正な形式またはサポートされていない行は、個別にスキップされます。そのファイル内の他の有効なルールと隣接するスコープ内のルールは引き続き機能します。

このオプションは、通常の作業ツリー`.gitignore`ファイルのみを対象としています。`.git/info/exclude`のルールとグローバルGit除外ルールは適用されません。`core.ignoreCase`やmacOSの場合は`core.precomposeUnicode`などの効果的なリポジトリ パス比較設定が尊重されます。`.gitignore`という名前のシンボリック リンクはたどられず、Gitの制御ファイルの動作に一致します。通常の`.gitignore`読み取れない場合、そのディレクトリ スコープはフェイルクローズで除外され、完全なルール評価を行わずにファイルをサイレントに含めるのではなく、スキャンによって部分的なアクセスが報告されます。パスを所有するリポジトリ スコープの読み取り可能なインデックスが利用可能な場合、追跡されたファイルは`.gitignore`に一致する場合でも表示されたままになります。そのインデックスやGit CLIがなければ、そのスコープは安全にパターンのみの評価に戻ります。

組み込みの`standard`プロファイルは、`gitignore`に加えて`smart-ignore`、`hidden-folders`、`hidden-files`、`dot-folders`、`dot-files`、`empty-folders`、`empty-files`、および`extensionless-files`を選択します。

### 12.6 追跡されたGitファイルのみ
「追跡されたGitファイルのみ」では、読み取り可能な各Gitインデックスに記録された既存の作業ツリー ファイルからツリーのGitステージが構築されます。変更された追跡ファイルと段階的な追加は引き続き含まれます。追跡されていないファイルは除外されます。これは現在の作業ツリーであり、`HEAD`またはリモート リポジトリの履歴スナップショットではありません。

到達可能なすべてのネストされたリポジトリとワークツリーは、到達可能なネスト レベルで個別に解決されます。子リポジトリは、親または兄弟から追跡されたパスを継承しません。このモードにはGit CLIが必要です。読み取り可能な空のインデックスは有効です。ターミナル ワークスペース ( TUI) がこのモードで開始され、該当するインデックスをロードできない場合、ワークスペースは開きません。開いているTUIワークスペースでモードが対話的に選択され、該当するインデックスをロードできない場合、変更は拒否され、最後に使用可能なGitモードがアクティブのままになります。同じ状況では、直接コマンドはポリシーを返すか、失敗をチェックします。DevProjex黙って`.gitignore`にフォールバックすることはありません。別の該当するインデックスが読み取り可能な場合、使用できないネストされたスコープは警告とともに除外されます。

すでに開いているデスクトップ ワークスペースでは、明示的に追跡された選択は表示されたままになり、フェールクローズされます。準備が失敗すると出力とエクスポートはブロックされますが、部分的な準備は継続され、ローカライズされた警告が表示されます。

Gitモードは相互排他で、`none`を選ぶとGitフィルタリングが無効になります。一時的な`staged`、`changes`、`diff:<ref>..<ref>`はプロファイルに保存されません。一時モードが有効な間、GUIのローカルプロジェクトプロファイルには、最後に有効にした永続モードの`gitignore`または`tracked`が保持されます。`none`は、保存時に`none`自体が有効な場合にのみ保存されます。TUIとCLIでは、一時モードが有効な間はポータブルプロファイルを保存できません。

### 12.7 GitフィルタリングとSmart Ignoreの関係
選択したGitモードとSmart Ignoreは独立したコントロールです。Gitモードは到達可能なすべてのGitスコープで最初に適用され、次にSmart Ignoreが残りの項目を処理し、最後に基本ルールが適用されます。

選択したGitモードがすべての候補をすでにカバーしている間、Smart Ignoreは非表示のままになり、Gitモードを変更または無効にすると表示されることがあります。Gitリポジトリ内では、リポジトリを必要とするすべてのGitモードを利用できます。

`!`で始まるGit否定ルールは、Git結果のみをキャンセルします。Smart Ignoreや基本ルールは無効になりません。

### 12.8 基本ルール
「ドット接頭辞のフォルダー」と「ドット接頭辞のファイル」は項目名を検査します。

「隠しフォルダー」と「隠しファイル」は、システムの隠し属性を検査します。一部のプラットフォームでは、ドットの接頭辞が付いた名前とシステム属性が同じアイテムまたは異なるアイテムを表す場合があります。

「空のファイル」は、サイズが0バイトのファイルを非表示にします。

「拡張子のないファイル」は、`Dockerfile`、`Makefile`、`README`などのファイルを非表示にします。

「空のフォルダー」は、論理的に空のフォルダーを非表示にします。選択したファイル タイプと他のすべてのルールが適用された後に表示されるファイルまたはサブフォルダーが残っていない場合、フォルダーは論理的に空です。

したがって、空のフォルダーの数は、別のルールが切り替えられた後に変更される可能性があります。ファイルを非表示にすると、そのファイルを含むフォルダーが論理的に空になる可能性があります。

### 12.9 カウンター
ルールの横にあるカウントは、ディスク上の同様のアイテムの物理的な数ではなく、現在の設定でのルールの直接的な影響を示します。

1つのアイテムが同時に複数の重複するカウンターに関連付けられることはありません。たとえば、`.git`フォルダーにはドット接頭辞が付いた名前とシステムのHidden属性の両方が付いている場合がありますが、その除外は1つのルールのみに起因します。

安定した順序は、除外の所有者を選択するために使用されます。

* フォルダー: `.gitignore`、Smart Ignore、ドット接頭辞付きの名前、システムの隠し属性。
* ファイル: `.gitignore`、Smart Ignore、ドット接頭辞付きの名前、拡張子なし、空のファイル、システムの隠し属性。

この順序はカウンターのみに影響します。最終的な可視性は、より単純なルールに従います。つまり、有効なメカニズムによってアイテムが除外されている場合、そのアイテムは非表示になります。

### 12.10 変更の適用
チェックボックスを切り替えると、まずパネル内の利用可能な設定とカウンターが更新されます。「設定を適用」を選択すると、最終的なツリーが再構築されます。

設定の準備がキャンセルされた場合、DevProjexパネルを最後に完全に完了した状態に戻します。部分的に計算されたルールは適用されません。

## 13) ツリーとメトリクスの計算方法
結果は以下によって異なります。
* 選択された拡張機能
* ルールを無視する
* アクティブフィルター
* チェックされたツリー ノード (選択ベースの操作用)

アクセスが拒否された場合、ノードは通常の名前とアイコンを維持し、「[アクセスが拒否されました]」というサフィックスが付きます。

### 13.1 ステータスバーカウンターが示すもの
ステータス バーには2つのブロックがあります。
* ツリー — ツリー テキスト出力のメトリック。
* コンテンツ — エクスポートされたファイル コンテンツ出力のメトリクス。

形式：
* 行数
* 文字
* ~トークン (概算)

大きな値は、コンパクトな接尾語 (K/M) を付けて表示されます。

重要：
* 「ツリー」ブロックの「行」は、ディスク上のファイルの数ではなく、最終的なツリー表現の行数を意味します。
* この値には、フォルダー、ファイル、およびツリー サービス要素 (アクセスが拒否されたノードなど) が含まれます。

### 13.2 メトリクスの計算方法
ツリーメトリクス:
* 同じエクスポート パイプラインによって生成された実際のツリー出力から計算されます。
* 現在のツリー形式を尊重します。

コンテンツの指標:
* コンテンツのコピー/エクスポートと同じルールに従います。
* バイナリ ファイルは除外されます。
* 空のファイルと空白のみのファイルは、サービス マーカー ( `[No Content, 0 bytes]`、`[Whitespace, N bytes]`) によってカウントされます。

### 13.3 カウンタが更新されるとき
再計算が実行されます。
* プロジェクトを開いたり更新した後;
* 設定（除外と拡張）を適用した後。
* ツリーのチェックボックスが変更されたとき (デバウンスあり)。
* ツリー形式を切り替えるとき（ツリー出力を使用する操作の場合）。
* バックグラウンド計算がキャンセルされると、次に完了する再計算までカウンターは0に設定されます。

## 14) アイコン
アイコンの選択順序:
1) ノードタイプ（フォルダー/ファイル）
2) 正確な名前 (ルールが存在する場合)
3) 拡大
4) それ以外の場合 - 不明

## 15) テーマと効果
「テーマ」セクションでは、システム、ライト、またはダークと1つの背景効果を選択できます。
* 透明性
* ぼかし
* Mica

システムはデフォルトで選択されており、オペレーティング システムのテーマの変更に従います。最初の起動または設定のリセット後、ライト システム テーマは通常の不透明な背景で始まり、ダーク システム テーマはぼかしで始まります。システム設定を決定できない場合、DevProjex Dark with Blurを使用します。ライトとダークはそれぞれの効果を独立して記憶します。ライトまたはダークを明示的に選択すると、システムが再度選択されるまでシステムの変更は無視されます。

効果は相互に排他的です。選択した効果を再度クリックすると、その効果が無効になり、通常の不透明な背景に戻ります。

利用可能な設定:
* 背景の透明度 — 透明度とぼかしに使用できます。
* トップ パネルのコントラスト — プレビュー、検索、フィルター、およびツリー形式のコマンドを含むメイン パネルを調整します。
* メニューの透明性 — メイン メニューとそのサブメニューに同様に適用されます。
* 境界線の可視性 — インターフェースの境界線がどの程度強く表示されるかを調整します。

Micaはプラットフォームのシステム マテリアルを使用し、個別の背景透明設定はありません。選択したブラーまたはマイカ効果が利用できない場合、アプリは最初に他のネイティブ効果を試します。通常の不透明な背景は、ブラーもマイカも使用できない場合にのみ使用されます。

透明モードでは、メイン ウィンドウの背景は透明のままです。メニュー、サブメニュー、およびその他のポップアップ サーフェスは、サポートされている場合はブラーを使用するため、その背後にあるツリー要素とコンテンツ要素が読みやすさを妨げません。

## 16) ヘルプ

### 16.1 アップデート
「ヘルプ → アップデート」では、現在のバージョンと最新の安定したGitHubリリースを比較します。自動チェックはデフォルトではオフになっています。有効にすると、DevProjex、前回のチェックが成功してから少なくとも7日が経過した後に起動時にチェックを行います。チェックボックスはすぐに有効になります。最新の成功結果はアプリケーションの実行間で保持され、その後のネットワーク障害によって消去されることはありません。インストールは依然としてユーザーの操作です。

### 16.2 設定のリセット
設定をリセットすると（[ヘルプ]→[設定をリセット]）、デフォルトのテーマ、効果、コンパクトモード、アニメーション設定、インターフェイス言語が復元されます。プロジェクトのプロファイル、履歴、ディスク上のファイルは変更されません。

### 16.3 データのリセット
データをリセットすると ([ヘルプ] → [データをリセット])、保存されているローカル プロジェクトのパラメーター プロファイルが削除されます。
* 選択されたファイルの種類。
* 「除外」セクションで選択したオプション。
* 選択したコンテンツ処理設定。
* 手動のシークレットマーク。

重要：
* ローカル フォルダーの最近の履歴は消去されません。
* Git Cloneウィンドウの最近のリポジトリ履歴はクリアされません。
* ディスク上のファイルとフォルダーは変更または削除されません。

## 17) 言語
言語は、言語メニューから選択します。
選択した言語は、起動の間に保存されます。「ヘルプ→設定をリセット」を選択すると、保存された言語の選択がクリアされ、インターフェース言語がデフォルトに戻ります。

## 18) プログレスバーとキャンセル
ステータス バーの中央には、アクティブな操作とその進行状況が表示されます。

プログレスモード:
* 不確定 — パーセントなし (操作期間は不明)。
* 決定 — パーセント (0 ～ 100) で決定します。

行動：
* バックグラウンドデータの計算中に、進捗率が表示されます。
* 一部のGit操作では、進行状況ソースが提供するときにパーセントが表示されます。
* 操作にかなりの時間がかかる場合、利用可能なオプションの更新と設定アプリケーションが表示されます。
* 高速操作は進行状況を表示せずに終了します。

ステータスバーのXボタン（キャンセル）：
* キャンセルをサポートする操作に対してベストエフォート型のキャンセルを実行します。
* バックグラウンドデータの計算を停止します。
* 利用可能なオプションの更新がキャンセルされると、パネルを最後に完了した状態に戻します。
* キャンセルサポートのない操作の場合、ステータスバーの表示は停止しますが、操作自体はバックグラウンドで終了する可能性があります。

## 19) 注意事項
* 権限が不十分な場合、アプリは昇格して再起動することを提案する場合があります。拒否された場合は、通知が表示されます。
