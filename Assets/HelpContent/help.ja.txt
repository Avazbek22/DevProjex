## 1) 概要と用途
DevProjexはプロジェクトのコンテキストをすばやく準備します。フォルダーとファイルの構造を表示し、チェックボックスで項目を選択して、ツリーやファイルの内容をクリップボードにコピーできます。コードレビュー、サポート、学習、AIアシスタントとのプロジェクト構造の共有に役立ちます。

重要：DevProjexは、開いたプロジェクトのファイルを変更しません。唯一の例外はCursorまたはVS Code向けの明示的なMCP接続で、この場合は`.cursor/mcp.json`または`.vscode/mcp.json`を作成または更新します（セクション19.1）。

## 2) プロジェクトツリー
* ファイルとフォルダーの種類を示すアイコン。
* ノードのチェックボックス。
* 展開と折りたたみ。

チェックボックス：ノードの選択はその子に適用され、親の状態は自動的に再計算されます。

ホットキー：
* {mod}E — すべて展開
* {collapseAll} — すべて折りたたむ（ルートは展開されたまま）

### コンテキストメニュー
ノードを右クリックするか、フォーカスのあるノードで{shift}F10またはメニューキーを押します。
* ファイルエクスプローラーで表示／Finderで表示／ファイルマネージャーで開く — システムのファイルマネージャーで項目を表示します。表示される名前は現在のプラットフォームに合わせて変わります。
* フルパスをコピー — 項目の絶対パスをコピーします。
* 相対パスをコピー — ルートフォルダー名で始まるプロジェクトルートからのパスをコピーします（例：`project/src/File.cs`）。
* コンテンツをコピー — ファイルの場合、コピーやエクスポートと同じコンテンツ変換を適用した内容をコピーします。
* これだけを選択 — このノードだけをチェックし、ほかのチェックを外します。ほかの項目もチェックされている場合にのみ表示されます。
* サブツリーを展開／サブツリーを折りたたむ — フォルダーで使用できます。

パスがディスク上に存在しなくなった場合、ファイルマネージャーで項目を開く操作や内容のコピーはエラーメッセージを表示します。パスのコピーは引き続き機能します。

## 3) ファイル
* フォルダーを開く... — ルートフォルダーを開きます（{mod}O）
* 新しいウィンドウ — 独立した新しいDevProjexインスタンスを開きます
* 最近使ったフォルダー — 最近開いたローカルフォルダーの一覧
* 再読み込み — ローカルフォルダーを再スキャンしてツリーを再構築します（F5）
* ファイルにエクスポート：
  * ツリーをエクスポート
  * コンテンツをエクスポート
  * ツリーとコンテンツをエクスポート
* プロジェクトをエクスポート：
  * フォルダーへ…
  * ZIPアーカイブへ…

「プロジェクトをエクスポート」は、ディレクトリ構造を保ったまま、現在のツリーから別のフォルダーまたはZIPアーカイブを作成します。

選択したファイルの種類、除外ルール、チェックした項目が反映されます。何もチェックしていない場合は、現在のツリー全体がエクスポートされます。

テキストファイルとバイナリファイルがコピーされ、含まれる空のフォルダーも保持されます。元のファイルは変更されません。結果を元のプロジェクト内に保存することはできません。

エクスポート中は、ツリーや設定の変更、フィルターの使用、形式やプレビューモードの変更、Gitコマンドの実行、再読み込み、別のプロジェクトを開く操作はできません。

形式の規則：
* ツリーをエクスポート：
  * ASCII -> `.txt`のみ。
  * JSON -> 既定は`.json`。保存ダイアログでは`.json`と`.txt`を選択できます。
  * XML -> 既定は`.xml`。保存ダイアログでは`.xml`と`.txt`を選択できます。
  * MD -> 既定は`.md`。保存ダイアログでは`.md`と`.txt`を選択できます。
* コンテンツをエクスポート — 常にテキスト形式の`.txt`ファイルです（ツリー形式の切り替えは適用されません）。
* ツリーとコンテンツをエクスポート — 常に`.txt`ファイルです。選択したツリー形式は、結果内のツリーブロックの形式にのみ影響します。

エクスポートしたファイルはBOMなしのUTF-8で書き込まれます。

### ドラッグ＆ドロップ
プロジェクトが読み込まれていないとき、起動画面の領域（ドロップゾーン）でドラッグ＆ドロップを使用できます。

ルール：
* フォルダーをドロップできます。
* ファイルをドロップすることもでき、その場合はファイルを含むフォルダーが開きます。
* 複数の項目をドロップした場合は、最初に見つかった適切なローカルパスが使用されます。
* パスが利用できないか存在しない場合は、「フォルダーを開く...」と同じアクセスチェックが適用されます。
* サポートされていない項目やローカルでない項目は無視されます。

### 最近使ったフォルダー
「ファイル → 最近使ったフォルダー」には、最近開いたローカルフォルダーの履歴が表示されます。

ルール：
* 一覧に追加されるのはローカルフォルダーだけです。
* DevProjexでクローンしたGitリポジトリは、この一覧には追加されません。
* 重複は作成されません。同じフォルダーをもう一度開くと、そのフォルダーが先頭に移動します。
* 最近のフォルダーは最大32件保存されます。
* 履歴はアプリを再起動しても保持されます。

各項目には、親フォルダーとプロジェクト名が表示されます（例：`Projects / App`）。

## 4) ターミナルから起動
DevProjexには、対話型のターミナルワークスペースと、スクリプトやCIで使える直接コマンドがあります。

コマンドがすでに設定されている場合は、ターミナルを開いて次を実行します。
`devprojex --help`

最上位のコマンドとオプションが一覧表示されます。各コマンド固有のオプションと例を確認するには、`devprojex help <command>`を実行します。

例：
* `devprojex` — 対話型のターミナルワークスペースを開きます。ワークスペースでは`:`コマンドライン（例：`:copy`、`:analyze`、`:branch`、`:language`）で操作します。コマンドの完全な一覧は、ワークスペースの組み込みヘルプとプロジェクトのドキュメントを参照してください。
* `devprojex tui .` — 指定したフォルダーをターミナルワークスペースで直接開きます。
* `devprojex open . --preview` — 現在のフォルダーをデスクトップのプレビューで開きます。
* `devprojex analyze . --format json` — 現在のプロジェクトを分析し、JSONで出力します。
* `devprojex tree .` — プロジェクトツリーをターミナルに出力します。
* `devprojex export context . --format markdown -o ../devprojex-context.md` — AI向けのコンテキストを元のプロジェクトの外に保存します。
* `devprojex export project . --as folder -o ../devprojex-submission` — 有効なプロジェクトツリーを指定したフォルダーにエクスポートします。
* `devprojex export project . --as zip -o ../devprojex-submission.zip` — 有効なプロジェクトツリーをZIPアーカイブにエクスポートします。
* `devprojex export context https://github.com/owner/repo -o -` — 自分でクローンせずにリモートリポジトリをパックします。
* `devprojex analyze . --git-mode tracked --exclude smart-ignore` — Gitで追跡されているファイルをスマート無視付きで分析します。
* `devprojex search Configure . --symbols` — 宣言が定義されている場所を検索します。`--symbols`は宣言名を受け取り、正規表現の構文は拒否します。正規表現でテキストを検索するには`--regex`を使用します。
* `devprojex related src/App.cs` — あるファイルが使用しているファイルと、そのファイルを使用しているファイルを一覧表示します。
* `devprojex mcp --root .` — AIエージェントがプロジェクトを安全に読み取れるよう、ローカルの読み取り専用MCPサーバーを起動します。
* `devprojex mcp connect . --client claude-code` — AIクライアントをプロジェクトに接続します（セクション19）。
* `devprojex mcp log . --last` — エージェントジャーナルの最新のセッションを表示します。

注：
* `.`は現在のターミナルフォルダーを表します。
* スペースを含むパスは引用符で囲む必要があります。
* `--git-mode`では、`none`、`gitignore`、`tracked`、`staged`、`changes`、`diff:<ref>..<ref>`のいずれかを選択します。
* `--exclude`は、Gitフィルタリングとは別に通常の除外を制御します。
* 分析コマンドとエクスポートコマンドの結果は決定的で、デスクトップのインターフェイスは開きません。
* `tui`、`open`、`analyze`、`search`、`tree`、2つの`export`コマンドはGitリポジトリのURLも受け付け、`related`は`--project`でURLを受け付けます。クローンは管理対象のキャッシュ（`devprojex cache`）に保存されます。
* コマンドには`export ctx`、`-f`、`-n`などのエイリアスと短いフラグがあります。`devprojex help`で確認できます。
* `analyze --findings`は値を表示せずにマスキングの検出結果を一覧表示し、`--fail-on-findings`はCI向けに0以外の終了コードを返します。
* `export context --max-tokens N`はコンテキストをトークン予算内に収め、試験的な`--rank importance`は重要度の高いファイルから優先して含めます。
* 分析、検索、エクスポートのコマンドはプロジェクトのファイルを変更しません。DevProjexは読み取り専用で動作します。

`devprojex`コマンドが動作しない場合は、DevProjexで「ヘルプ → ターミナルから起動」を開いてください。

## 5) Git
「Git → リポジトリをクローン...」は、リポジトリをDevProjexのキャッシュにクローンして開きます。「ブランチ」と「更新を取得」は、この方法でクローンしたプロジェクトでのみ使用できます。アプリは元のファイルには触れず、キャッシュだけを操作します。

キャッシュはユーザーのシステムキャッシュディレクトリに保存されます。実際のパスは`devprojex doctor`で確認できます。

* ブランチ — 利用可能なブランチの一覧を、現在のブランチに印を付けて表示します。切り替えると、ツリーが選択したブランチの内容に更新されます。ブランチがすでにローカルにある場合、切り替えはオフラインで行われます（更新はしません）。ローカルにない場合は、フェッチしてから作成します。
* 更新を取得 — 現在のブランチだけを更新します。フェッチしてからorigin/<branch>にリセットします。Gitでクローンしたプロジェクトでは、F5も同じ操作を実行し、通常の「ファイル → 再読み込み」は無効になります。

### クローンウィンドウ
Gitのクローンウィンドウでは、URL欄の下に「最近のリンク」の一覧が表示されることがあります。

ルール：
* 一覧は、最近クローンしたリポジトリが履歴にある場合にのみ表示されます。
* 一覧に追加されるのはネットワーク上のリポジトリ（`https://`、`ssh://`、SCP形式）だけです。
* ローカルパスと`file://`のソースはこの一覧に追加されません。
* 重複は作成されません。同じリポジトリをもう一度クローンすると、そのリポジトリが先頭に移動します。
* 最近のリポジトリは最大16件保存されます。
* 履歴はアプリを再起動しても保持されます。

項目を選択すると、URL欄に自動的に入力されます。
クローンの実行中は、一覧が一時的に非表示になります。

## 6) コピー
### ツリー形式の切り替え（ASCII / JSON / XML / MD）
この切り替えは、出力にツリーを含む操作でのツリーの表現形式を決めます。

* ASCII — 枝線付きのテキストツリー。
* JSON — JSONの構造化ツリー。
* XML — パーサーやツール向けのコンパクトなXMLツリー。
* MD — ドキュメントやAIプロンプト向けのMarkdownの入れ子リスト。

切り替えが影響する操作：
* ツリーをコピー
* ツリーとコンテンツをコピー
* ツリーをエクスポート
* ツリーとコンテンツをエクスポート

切り替えが影響しない操作：
* コンテンツをコピー
* コンテンツをエクスポート

### ツリーをコピー
プロジェクトツリーをコピーします。
チェックしたノードがある場合は、選択からツリーを構築します。選択が空または無効な場合は、ツリー全体をコピーします。
結果の形式はツリー形式の切り替えで決まります。
ホットキー：{mod}{shift}Cと{mod}{alt}C。

### コンテンツをコピー
ファイルの内容をコピーします。
* ファイルがチェックされている場合はそのファイルだけ、それ以外の場合はプロジェクトのすべてのファイルが対象です。
* 各ファイルの前には、完全なローカルパス（GitでクローンしたプロジェクトではリポジトリのWebパス）を含むヘッダーが付きます。
* テキスト以外のファイル（バイナリを含む）は無視されます。
* 空のテキストファイルでは、パスと`[No Content, 0 bytes]`の行が出力されます。
* 空白や改行だけを含むファイルでは、パスと`[Whitespace, N bytes]`の行が出力されます。
ホットキー：{mod}{alt}V。

### ツリーとコンテンツをコピー
ツリーとコンテンツをまとめます。
* ツリーは選択から構築されます。選択が空または無効な場合は、ツリー全体が使用されます。
* コンテンツは「コンテンツをコピー」と同じルールに従います。
* ツリーブロックの形式はツリー形式の切り替えで決まります。
ホットキー：{mod}{shift}V。

### ツリーの表現
ツリー形式ごとに、同じ選択済みプロジェクトツリーを異なる方法で表現します。

JSON：
* `rootPath` — `/`で正規化された絶対ルートパス。
* `tree` — ルートフォルダーの内容。
* JSONのエクスポートはこのツリー形式を使用します。配列はファイル、オブジェクトはサブフォルダー、`/`は現在のフォルダー内のファイルを表し、`[]`は空のフォルダーを表します。

XML：
* ルートノードは`<t r="...">`です。
* フォルダーは`<d n="...">`です。
* ファイルは`<f>File.cs</f>`です。

MD：
* `Root: ...`で始まります。
* Markdownの入れ子リストを使用します。
* フォルダー名は`/`で終わります。

ツリー + コンテンツ：
* 選択したツリー形式がツリーブロックに適用されます。
* コンテンツブロックはテキストのままです。
* コンテンツブロックのファイルヘッダーは`/`区切りの相対パスを使用します。
* `.txt`としてエクスポートされます。

## 7) プレビューモード
上部バーの目のアイコンのボタン、または{mod}Bで開きます。

マウスのサイドボタンはブラウザーと同じように動作します。「進む」でプレビューモードが開き、「戻る」で閉じます。同じ方向を繰り返しても何も起こりません。

{mod}{shift}Fで、プレビュー内のファイル内容の検索を開閉します。EnterまたはF3で次の一致に、{shift}Enterまたは{shift}F3で前の一致に移動します。

最終的な結果をツリーの横にある別のワークスペースに表示します。このモードは表示専用で、単独でクリップボードにコピーしたりファイルにエクスポートしたりはしません。

既定では、ワークスペースは次の配置で開きます。
* 左 — プロジェクトツリー。
* 中央 — プレビューペイン。
* 右 — 設定パネル（開いていた場合）。

利用できるモード：
* ツリー
* コンテンツ
* ツリー + コンテンツ

コピーやエクスポートと同じルールが適用されます。
* チェックしたノードが反映されます。
* 選択が空の場合は、データ全体が使用されます。
* 現在の除外ルールと選択オプションが適用されます。

さらに：
* プレビュー内のファイルは横線で区切られます。
* スクロール中は、現在のファイルのパスが上部に固定されます。固定されたパスをクリックすると、そのファイルの先頭に戻ります。
* プレビューのスクロールバーには、検索の一致とマスキングの検出結果がある行が表示されます。マーカーをクリックするとその行に移動します。元の値のまま保持した検出結果も表示され続け、マスクされたパスヘッダーは最初の行に1つのマーカーを追加します。
* ツリーとプレビューのズームは個別に設定できます。
* プレビューモードでは、「コピー」メニューを開かずに、現在の結果全体または表示中のファイルブロックをコピーできます。

ボタン：
* 上部のプレビューアイランドの左側にあるコピーボタン — 現在のプレビューモードの内容をコピーします。
  * ツリー
  * コンテンツ
  * ツリー + コンテンツ
* ツリーペインのX — ツリーを非表示にして、プレビューペインだけを残します。
* 上部のプレビューペインのX — プレビューモードを完全に閉じます。
* 固定されたファイルヘッダーの小さなコピーボタン — 表示中のファイルブロックを、プレビューの表示どおりにコピーします。
* 目のアイコンをもう一度押すか{mod}Bを押しても、プレビューモードが閉じます。

プレビューでツリーペインが表示されている間は、検索とフィルターを使用できます。
ツリーが非表示の場合、プレビューのみのモードを終了するまで検索とフィルターは一時的に使用できません。

## 8) 表示
### ズーム
* {mod}+ ／ {mod}= — ズームイン
* {mod}- — ズームアウト
* {mod}0 — リセット
* {mod}+マウスホイール — カーソルの下のペインをなめらかにズーム

動作：
* 通常モードでは、ツリーがズームされます。
* ツリーが表示されているプレビューでは、メニューの「ズームイン」「ズームアウト」「ズームをリセット」がツリーとプレビューの両方に適用されます。
* {mod}+マウスホイールでは、カーソルの位置に応じてツリーとプレビューが個別にズームされます。
* プレビューのみのモードでは、プレビューペインだけがズームされます。

範囲：6～28、リセット値は15。

### コンパクトモード
UIを詰めて表示し、ツリーと設定の余白を小さくします。
プレビューのワークスペースがアクティブな間は、コンパクトモードが自動的に有効になります。

### アニメーション
「表示 → アニメーション」では、ツリーの展開、ステータスカウンター、ツールの初回表示をそれぞれ設定できます。3つとも既定で有効で、無効にしたアニメーションは最終状態をすぐに表示します。

### ツリーフォント
ツリーのフォントは「表示 → ツリーフォント」で選択します。
「既定」を選ぶと標準のツリーフォントに戻ります。
選択したフォントは、設定パネルで「設定を適用」をクリックすると適用されます。

### エージェントのアクティビティ
「表示 → エージェントのアクティビティ」をオンにすると、ライブセッションでAIエージェントが受け取ったファイルを確認できます。該当するファイルにはツリーで✦の印が付きます（セクション19.4）。

## 9) 検索（ツリー）
検索バーを開き、一致を強調表示して移動できるようにします。
* {mod}F — 表示／非表示
* Enter — 次の結果
* {shift}Enter — 前の結果
* Esc — 閉じる

検索では必要な枝だけが自動的に展開されます。クエリをクリアすると、ツリーは折りたたまれます（ルートを除く）。
一致した行はツリーのスクロールバーにも表示されます。マーカーをクリックすると、その一致に移動します。
一致が非常に多い場合は、UIの応答性を保つため、自動展開と全体の強調表示が制限されることがあります。
検索バーを閉じると、閉じるアニメーションの完了後にクエリがクリアされます。

制約：
* 検索を開くと、フィルターは自動的に閉じます。
* 検索は、プレビューでツリーペインが表示されている間も使用できます。
* ツリーが非表示の場合、検索は一時的に使用できません。

## 10) フィルター（名前）
フィルター文字列に一致するノードとその親だけを表示します。更新は入力が止まってから行われます（デバウンス）。
* {mod}{shift}N — フィルターの表示／非表示
* Esc — フィルターを閉じる

制約：
* フィルターを開くと、検索は自動的に閉じます。
* フィルターは、プレビューでツリーペインが表示されている間も使用できます。
* ツリーが非表示の場合、フィルターは一時的に使用できません。

## 11) オプション（設定パネル）
右側に次の項目があります。
* 設定を適用
* コンテンツ処理
* 除外事項
* ファイルの種類

「除外事項」と「ファイルの種類」の変更はパネル内で保留され、「設定を適用」をクリックすると適用されます。

チェックボックスを変更すると、利用可能なオプションとその件数がバックグラウンドで更新されることがあります。結果のツリーは「設定を適用」をクリックした後にだけ再構築されます。

利用可能なオプションの更新をステータスバーのXボタンでキャンセルすると、未完了の変更は適用されず、パネルは最後に完了した状態に戻ります。

各一覧には「すべて」の切り替えがあります。

「ファイルの種類」についての注意：
* この一覧には拡張子のあるファイルだけが表示されます。
* 拡張子のないファイルはこの一覧に追加されず、「除外事項」の別のオプションで制御されます。

コンテンツ処理：
* ツリーを変更せずに、選択したテキストファイルの内容を変換します。
* 「シークレットを非表示」と「個人データを非表示」は、検出した値を置き換えます（セクション12.3と12.4）。
* 「コードを圧縮」は、14言語で宣言を残したまま名前付きの実装を短くします。
* 「コメントを削除」は、20の言語パックでコメントとドキュメントコメントを削除します。
* 「空行を削除」は、同じ言語パックで複数行リテラルを保ったまま空白だけの行を削除します。
* 変更は「設定を適用」の後に有効になります。

{mod}P — パネルの表示／非表示。

### 11.1 ローカルプロジェクトのパラメータープロファイル
ローカルフォルダーでは、DevProjexは最後に適用したプロジェクトのパラメーターを記憶します。
* 選択したファイルの種類。
* 「除外事項」セクションで選択したオプション。

保存は「設定を適用」をクリックしたときに行われます。
同じローカルフォルダーをもう一度開くと、パラメーターが自動的に復元されます。

重要：
* プロファイルはローカルプロジェクトに対してのみ保存されます。
* Gitでクローンして開いたプロジェクトでは、プロファイルは保存されません。
* 保存されたオプションの一部が現在のプロジェクトで使用できなくなった場合、そのオプションはスキップされ、残りのパラメーターが適用されます。
* 再読み込みや再オープンで新しいファイルの種類や「除外事項」のオプションが現れた場合、それは既定で有効になります。
* すでに表示されたことのあるオプションでは、ユーザーの明示的な選択が維持されます。無効にした種類の新しいファイルが現れても、その種類は再び有効になりません。

## 12) 除外事項
「除外事項」セクションでは、ツリー、コンテンツ、コピー、エクスポートの結果から除外するファイルとフォルダーを制御します。

項目は、次の条件をすべて満たす場合にのみ表示されます。
* ファイルに種類がある場合は、その種類が選択されている。
* 有効な除外ルールのどれにも除外されていない。

除外ルールは累積的に働きます。有効なルールが1つでも項目を非表示にすると、別のルールでその項目を表示に戻すことはできません。

### 12.1 利用可能なルール
プロジェクトの内容に応じて、次のオプションが表示される場合があります。

* スマート無視
* 空のフォルダー
* 空のファイル
* 隠しフォルダー
* 隠しファイル
* ドットフォルダー
* ドットファイル
* 拡張子のないファイル

Gitフィルタリングを適用できない場合、つまりリポジトリの境界がなく、`.gitignore`フィルターが現在のツリーを変更できない場合は、GUIのセレクターとTUIのGit軸のラジオ項目が完全に非表示になります。リポジトリの外で軸が表示される場合、GUIでは「フィルタリングなし」と`.gitignore`だけを選択でき、TUIではリポジトリが必要な項目が無効になります。Gitリポジトリ内では、通常の5つの値として、フィルタリングなし、`.gitignore`、追跡されているファイル、ステージ済みのファイル、現在のすべての変更を選択できます。TUIでは、有効な`diff:<ref>..<ref>`スコープが6行目として表示されます。値を選ぶと、スマート無視や基本的な除外は変えずに、現在のGitモードだけが置き換わります。そのほかのオプションは、そのルールが現在のツリーを変更できる場合に表示されるため、別のルールやファイルの種類を切り替えると一覧が変わることがあります。

新しいオプションは、初めて表示されたときに既定で有効になります。既知のオプションは、一時的に一覧から消えてもユーザーの選択を保持します。

### 12.2 スマート無視
スマート無視は、依存関係、ビルド出力、キャッシュなど、プロジェクトの作業用の生成物を非表示にします。

DevProjexはまず、構造とマーカーファイルからプロジェクトの種類を判別します。例：

* `.csproj`
* `package.json`
* `pyproject.toml`
* `Cargo.toml`

その後、対応するスタックのルールを、検出したプロジェクトのスコープ内に適用します。たとえば、.NETのルールが隣のPythonやJavaScriptのプロジェクトに及ぶことはありません。

フォルダー名だけでは判断できないこともあります。`build`、`vendor`、`packages`、`cache`、`pkg`、`Library`のようなあいまいな名前は、中身も確認されます。これにより、似た名前というだけで通常のユーザーフォルダーが非表示になることを防ぎます。

一部の依存関係ストアやサービスディレクトリは、明示的に検出されたプロジェクトの外でも、特徴的な内部構造から認識できます。

プロジェクトのスコープの検出には上限があるため、大きなユーザーフォルダーを読み込んでも、すべてのディレクトリを繰り返し完全に分析することにはなりません。通常の構造では浅い検出を行い、認識されたモノレポはより深く検索します。スコープが見つかると、スマート無視はそのサブツリー全体に深さの制限なく適用されます。

### 12.3 シークレットを非表示
「シークレットを非表示」は既定でオフです。選択したテキストの内容だけをスキャンし、検出した値をその場で置き換えて、ファイルと周囲のコードは残します。オフの間はスキャンが実行されず、件数も表示されません。現在の選択をスキャンすると、ラベルに検出した値の件数が表示されます。「元の値のまま保持」の判断によって非表示の値が少なくなった場合は「検出数／非表示数」が表示され、その行の?インジケーターが両方の件数を示します。

マスキングされた箇所はプレビューで強調表示されます。クリックすると、その箇所だけを元の値のまま保持できます。{alt}↓ ／ {alt}↑で検出結果の間を移動し、Enterで選択中の結果を切り替えます。ターミナルワークスペースでは、`[`と`]`で出現箇所の間を移動し、`Enter`または`Space`で選択中の箇所を切り替えます。この判断は現在のセッションのプレビュー、クリップボード、コンテキストのエクスポート、フォルダーへのコピー、ZIPに適用され、プロジェクトのプロファイルには保存されません。

プレビューのコンテキストメニューでは、この判断をまとめて行えます。検出箇所を右クリックすると、同じルールのすべての箇所、または同じファイルで検出されたすべての箇所を、1回の操作で元の値のまま保持したり、再び非表示にしたりできます。ファイル内容で選択した値を右クリックすると、手動でマークできます。『この箇所の「…」を非表示』はセッション中その箇所だけを非表示にし、『「…」を常に非表示』はその値のすべての出現箇所に永続的なマークを作成し、『「…」を個人データとして非表示』は「個人データを非表示」で制御される永続的なマークを作成します。手動マークには「マークを削除」が表示され、マークを削除できます。検出器が引き続き一致させる値は非表示のままです。手動でマークする値は、ファイル内容の中で選択した8～512文字の1行である必要があります。マークを作成すると、対応するオプションが自動的に有効になります。永続的なマークに保存されるのはキー付きの値の識別子と分類だけで、元のテキストは保存されません。

フォルダーやZIPへのコピーでも一致したテキストが変更されるため、ビルドや実行ができなくなる場合があります。バイナリファイルは変更されずにコピーされ、スキャンされません。16 MiBを超える選択したテキストファイルは省略されて報告され、残りの出力は完了します。検出に失敗すると、操作全体が停止します。

件数はルールの一致だけを示します。0件でもプロジェクトが安全であるとは限りません。CLIでは`--hide-secrets`を使用します。技術的な詳細と制限は`Docs/HideSecrets.md`にあります。

### 12.4 個人データを非表示
「個人データを非表示」は既定でオフです。選択したテキストファイル内のメールアドレス、グローバルIPアドレス、パス内のローカルユーザー名、MACアドレス、国際電話番号を検出します。検出結果には「シークレットを非表示」と同じプレビューでの判断と出力パイプラインが適用されます。『「…」を個人データとして非表示』で作成した手動マークもこの分類に属し、このスイッチに従います（セクション12.3）。生成されたパスヘッダーとツリーのルートに含まれるローカルユーザー名は、1つの共通の検出結果としてマスキングされます。カウンターでは1件として数えられ、?インジケーターが非表示か表示かを示し、1回のクリックでマスクされたすべてのパスを切り替えられます。

ドキュメント用のアドレス範囲とホスト、一般的なCIのユーザー名、よく知られたパブリックDNSリゾルバー、ドキュメント用に定められた架空の電話番号の範囲は表示されたままです。一致が0件でもプライバシーが保証されるわけではありません。CLIでは`--hide-private-data`を使用します。完全なルールとフェーズ1の制限は`Docs/HidePrivateData.md`にあります。

### 12.5 .gitignoreを使用
有効にすると、DevProjexは`git status`の作業ツリーの見え方に従います。追跡されているファイルは表示されたままで、追跡されていないファイルはリポジトリの除外ルールで除外されない限り表示されます。開いたフォルダーのルートにあるファイルだけでなく、到達可能なすべての`.gitignore`を適用し、開いたフォルダーより上にあるリポジトリのルートまでのファイルも含みます。

各`.gitignore`は次の範囲に適用されます。

* そのファイルを含むフォルダー。
* その下にあるアクセス可能なすべてのフォルダー。
* そのスコープの内側だけ。

入れ子になった`.gitignore`のルールは、親フォルダーや兄弟フォルダーには影響しません。

特定のパスについては、親の`.gitignore`からより深いファイルへ向かってルールを処理します。1つのファイル内では上から下へ処理します。最後に一致したルールがGitの結果を決めます。

`!`で始まるルールは、そのスコープ内でだけ、それより前のGitの除外を取り消します。親フォルダーが除外されたままの場合、ファイルを復元することはできません。完全に除外されて到達できないフォルダー内の`.gitignore`は評価に使われません。

不正な形式やサポートされていない行は個別にスキップされます。同じファイル内のほかの有効なルールや、隣接するスコープのルールは引き続き機能します。

リポジトリ固有の`.git/info/exclude`も、ルートの`.gitignore`より低い優先度で適用されます。独自の`.git`を持つ入れ子のフォルダーも`git status`と同じように扱われます。`.gitmodules`で宣言されていない埋め込みリポジトリは不透明で、そのファイルは表示されません。宣言されたサブモジュールでは、そのサブモジュール自身の`.gitignore`と`info/exclude`が適用されます。埋め込みリポジトリのファイルを表示するには`none`を選択します。グローバルなGitの除外ルール（`core.excludesFile`）は適用されません。`core.ignoreCase`や、macOSでの`core.precomposeUnicode`など、リポジトリで有効なパス比較の設定は尊重されます。`.gitignore`という名前のシンボリックリンクは、Gitの制御ファイルの扱いと同じく、たどられません。`.gitignore`または`info/exclude`を読み取れない場合、そのディレクトリのスコープはフェイルクローズで除外され、ルールを完全に評価できないファイルを黙って含める代わりに、スキャンが部分的なアクセスを報告します。パスを所有するリポジトリのスコープに読み取り可能なインデックスがある場合、追跡されているファイルは`.gitignore`に一致しても表示されたままです。そのインデックスやGit CLIがない場合、そのスコープは安全にパターンだけの評価に切り替わります。

組み込みの`standard`プロファイルは、`gitignore`に加えて`smart-ignore`、`hidden-folders`、`hidden-files`、`dot-folders`、`dot-files`、`empty-folders`、`empty-files`、`extensionless-files`を選択します。

### 12.6 Git追跡ファイルのみ
「Git追跡ファイルのみ」は、読み取り可能な各Gitインデックスに記録されている、作業ツリー上に存在するファイルからツリーのGit段階を構築します。変更された追跡ファイルとステージ済みの追加ファイルは含まれ、追跡されていないファイルは除外されます。これは現在の作業ツリーであり、`HEAD`やリモートリポジトリの過去のスナップショットではありません。

各リポジトリは個別に解決されます。開いたフォルダー内の兄弟リポジトリと宣言されたサブモジュールはそれぞれ独自のインデックスを使い、子リポジトリが親や兄弟から追跡パスを引き継ぐことはありません。`.gitmodules`で宣言されていない埋め込みリポジトリは、`.gitignore`モードと同じく不透明なままです。このモードにはGit CLIが必要です。読み取り可能な空のインデックスは有効です。ターミナルワークスペース（TUI）をこのモードで起動し、該当するインデックスを読み込めない場合、ワークスペースは開きません。開いているTUIのワークスペースでこのモードを対話的に選択し、該当するインデックスを読み込めない場合、変更は拒否され、最後に使用できたGitモードが有効なままになります。同じ状況で、直接コマンドはポリシーまたはチェックの失敗を返します。DevProjexが黙って`.gitignore`にフォールバックすることはありません。ほかに読み取り可能な該当インデックスがある場合、利用できない入れ子のスコープは警告付きで除外されます。

すでに開いているデスクトップのワークスペースでは、明示的に選んだ追跡モードの選択は表示されたままフェイルクローズで動作します。準備に失敗すると出力とエクスポートはブロックされ、部分的に準備できた場合はローカライズされた警告を表示して続行します。

Gitモードは互いに排他的で、`none`を選ぶとGitフィルタリングが無効になります。一時的なモードの`staged`、`changes`、`diff:<ref>..<ref>`はプロファイルに保存されません。一時的なモードが有効な間、GUIのローカルプロジェクトのプロファイルには、最後に有効にした永続的なモードの`gitignore`または`tracked`が保持されます。`none`は、保存時に`none`自体が有効な場合にのみ保存されます。TUIとCLIでは、一時的なモードが有効な間はポータブルプロファイルを保存できません。

### 12.7 Gitフィルタリングとスマート無視の関係
選択したGitモードとスマート無視は、独立した設定です。Gitモードは到達可能なすべてのGitスコープで最初に適用され、次にスマート無視が残りの項目を処理し、最後に基本ルールが適用されます。

選択したGitモードがスマート無視の候補をすべて除外している間はスマート無視が表示されず、Gitモードを変更または解除すると表示されることがあります。Gitリポジトリ内では、リポジトリを使うすべてのGitモードを利用できます。

`!`で始まるGitの否定ルールは、Gitの結果だけを取り消します。スマート無視や基本ルールは無効になりません。

### 12.8 基本ルール
「ドットフォルダー」と「ドットファイル」は、項目の名前を調べます。

「隠しフォルダー」と「隠しファイル」は、システムの隠し属性を調べます。プラットフォームによっては、ドットで始まる名前とシステム属性が同じ項目を指すことも、別の項目を指すこともあります。

「空のファイル」は、サイズが0バイトのファイルを非表示にします。

「拡張子のないファイル」は、`Dockerfile`、`Makefile`、`README`などのファイルを非表示にします。

「空のフォルダー」は、論理的に空のフォルダーを非表示にします。選択したファイルの種類とほかのすべてのルールを適用した後に、表示されるファイルもサブフォルダーも残らない場合、そのフォルダーは論理的に空です。

そのため、別のルールを切り替えると空のフォルダーの件数が変わることがあります。ファイルを非表示にすると、それを含むフォルダーが論理的に空になる場合があるためです。

### 12.9 カウンター
ルールの横の件数は、ディスク上の類似する項目の物理的な数ではなく、現在の設定でそのルールが直接除外している数を示します。

1つの項目が、重なり合う複数のカウンターに同時に数えられることはありません。たとえば`.git`フォルダーは、ドットで始まる名前とシステムの隠し属性の両方を持つことがありますが、その除外は1つのルールにだけ数えられます。

除外をどのルールに数えるかは、固定の順序で決まります。

* フォルダー：`.gitignore`、スマート無視、ドットで始まる名前、システムの隠し属性。
* ファイル：`.gitignore`、スマート無視、ドットで始まる名前、拡張子なし、空のファイル、システムの隠し属性。

この順序はカウンターにだけ影響します。最終的な表示はもっと単純なルールに従います。有効な仕組みのどれかが除外すれば、その項目は非表示になります。

### 12.10 変更の適用
チェックボックスを切り替えると、まずパネル内の利用可能な設定とカウンターが更新されます。最終的なツリーは「設定を適用」を選択した後に再構築されます。

設定の準備をキャンセルすると、DevProjexはパネルを最後に完全に完了した状態に戻します。途中まで計算されたルールは適用されません。

## 13) ツリーとメトリックの計算方法
結果は次の要素によって決まります。
* 選択したファイルの種類
* 除外ルール
* 有効なフィルター
* チェックしたツリーのノード（選択に基づく操作の場合）

アクセスが拒否された場合、ノードは通常の名前とアイコンのまま、「[アクセスが拒否されました]」という接尾辞が付きます。

### 13.1 ステータスバーのカウンターが示すもの
ステータスバーには2つのブロックがあります。
* ツリー — ツリーのテキスト出力のメトリック。
* コンテンツ — エクスポートされるファイル内容の出力のメトリック。

形式：
* 行数
* 文字
* ≈トークン（概算）

大きな値は、短い接尾辞（K／M）を付けて表示されます。

重要：
* 「ツリー」ブロックの「行数」は、ディスク上のファイル数ではなく、最終的なツリー表現の行数です。
* この値には、フォルダー、ファイル、ツリーの補助要素（アクセスが拒否されたノードなど）が含まれます。

### 13.2 メトリックの計算方法
ツリーのメトリック：
* 同じエクスポートパイプラインで生成される実際のツリー出力から計算されます。
* 現在のツリー形式が反映されます。

コンテンツのメトリック：
* コンテンツのコピーやエクスポートと同じルールに従います。
* バイナリファイルは除外されます。
* 空のファイルと空白だけのファイルは、補助マーカー（`[No Content, 0 bytes]`、`[Whitespace, N bytes]`）で数えられます。

### 13.3 カウンターが更新されるタイミング
再計算は次のタイミングで実行されます。
* プロジェクトを開いたり再読み込みしたりした後。
* 設定（除外事項とファイルの種類）を適用した後。
* ツリーのチェックボックスが変わったとき（デバウンスあり）。
* ツリー形式を切り替えたとき（ツリーの出力を使う操作の場合）。
* バックグラウンドの計算がキャンセルされた場合、次の再計算が完了するまでカウンターは0になります。

## 14) アイコン
アイコンは次の順序で選択されます。
1) ノードの種類（フォルダー／ファイル）
2) 正確な名前（ルールがある場合）
3) 拡張子
4) それ以外 — 不明

## 15) テーマと効果
「テーマ」セクションでは、システム、ライト、ダークのいずれかと、背景効果を1つ選択できます。
* 透明
* ぼかし
* Mica

既定ではシステムが選択されており、オペレーティングシステムのテーマの変更に従います。初回起動時や設定のリセット後は、システムのテーマがライトなら通常の不透明な背景で、ダークならぼかしで始まります。システムの設定を判別できない場合、DevProjexはダークとぼかしを使用します。ライトとダークは、それぞれの効果を個別に記憶します。ライトまたはダークを明示的に選択すると、再びシステムを選択するまでシステムの変更は無視されます。

効果は互いに排他的です。選択中の効果をもう一度クリックすると、その効果が無効になり、通常の不透明な背景に戻ります。

利用できる設定：
* 背景の透明度 — 「透明」と「ぼかし」で使用できます。
* 上部バーのコントラスト — プレビュー、検索、フィルター、ツリー形式のコマンドがあるメインパネルを調整します。
* メニューの透明度 — メインメニューとそのサブメニューに同じように適用されます。
* 境界線の表示 — インターフェイスの境界線の見え方の強さを調整します。

Micaはプラットフォームのシステム素材を使用し、背景の透明度の設定はありません。選択したぼかしまたはMicaの効果が使用できない場合、アプリはまずもう一方のネイティブ効果を試します。ぼかしもMicaも使用できない場合にだけ、通常の不透明な背景が使われます。

「透明」モードでは、メインウィンドウの背景は透明のままです。メニュー、サブメニュー、そのほかのポップアップは、サポートされている場合はぼかしを使うため、背後にあるツリーやコンテンツの要素で読みにくくなることはありません。

## 16) ヘルプ

### 16.1 アップデート
「ヘルプ → アップデート」は、現在のバージョンをGitHubの最新の安定版リリースと比較します。自動チェックは既定でオフです。有効にすると、前回の成功したチェックから7日以上経過している場合に、起動時にチェックします。チェックボックスはすぐに有効になります。最後に成功した結果はアプリを再起動しても保持され、その後のネットワークエラーで消えることはありません。インストールはユーザーが行います。

### 16.2 設定のリセット
「設定をリセット」（ヘルプ → 設定をリセット）は、テーマ、効果、コンパクトモード、アニメーションの設定、インターフェイスの言語を既定に戻します。プロジェクトのプロファイル、履歴、ディスク上のファイルは変更されません。

### 16.3 データのリセット
「データをリセット」（ヘルプ → データをリセット）は、保存されているローカルプロジェクトのパラメータープロファイルを削除します。
* 選択したファイルの種類。
* 「除外事項」セクションで選択したオプション。
* 選択したコンテンツ処理の設定。
* シークレットの手動マーク。

完了したエージェントジャーナルのセッションも消去されます（セクション19.3）。アクティブなセッションは保持されます。

重要：
* ローカルフォルダーの最近の履歴は消去されません。
* Gitのクローンウィンドウにある最近のリポジトリの履歴は消去されません。
* ディスク上のファイルとフォルダーは変更も削除もされません。

## 17) 言語
言語は「言語」メニューで選択します。
選択した言語は次回の起動時にも保持されます。「ヘルプ → 設定をリセット」を実行すると、保存された言語の選択がクリアされ、インターフェイスの言語が既定に戻ります。

## 18) 進行状況バーとキャンセル
ステータスバーの中央には、実行中の操作とその進行状況が表示されます。

進行状況のモード：
* 不確定 — パーセントなし（操作の所要時間が不明）。
* 確定 — パーセント付き（0～100）。

動作：
* バックグラウンドでのデータ計算中は、パーセントで進行状況が表示されます。
* 一部のGit操作では、進行状況の情報源が提供する場合にパーセントが表示されます。
* 利用可能なオプションの更新と設定の適用は、時間がかかる場合に表示されます。
* 短時間で終わる操作は、進行状況を表示せずに完了します。

ステータスバーのXボタン（キャンセル）：
* キャンセルに対応した操作を、可能な範囲でキャンセルします。
* バックグラウンドでのデータ計算を停止します。
* 利用可能なオプションの更新をキャンセルした場合、パネルを最後に完了した状態に戻します。
* キャンセルに対応していない操作では、ステータスバーの表示だけが止まり、操作自体はバックグラウンドで完了することがあります。

## 19) MCPとAIエージェント
DevProjexには、ローカルの読み取り専用MCPサーバーが含まれています。Claude Code、Codex、Cursor、VS CodeなどのAIエージェントは、このサーバーを通じてプロジェクトを読み取ります。シークレットのマスキングは常に有効で、エージェントがプロジェクトのファイルを変更することはできません。サーバーには8つのツールがあります：`list_projects`、`get_tree`、`analyze`、`search_project`、`related_files`、`get_file`、`pack_context`、`read_pack`。

### 19.1 クライアントの接続
「MCP」メニューには次の項目があります。
* Live context — サーバーがこのウィンドウでチェックした項目に従います（セクション19.2）。
* 標準 — サーバーはウィンドウの選択に依存しません。
* ジャーナル… — エージェントが要求して受け取った内容（セクション19.3）。
* ドキュメント — MCPサーバーのドキュメントを開きます。

「Live context」と「標準」には同じ操作があります：「Claude Code で開く」「Codex で開く」「Cursor で開く」「VS Code で開く」「その他のクライアント…」。これらはプロジェクトを開いている間に使用できます。

Claude CodeとCodexは、インストールされているコマンドで登録され、その後プロジェクトフォルダーを開いた新しいターミナルでクライアントが起動します。CursorとVS Codeには、プロジェクト内の`.cursor/mcp.json`または`.vscode/mcp.json`が書き込まれ、そのファイル内のほかのサーバーは保持されます。「その他のクライアント…」は、Claude Desktopなどのクライアントですぐに使える構成を表示します。クライアントのコマンドが見つからない場合や接続に失敗した場合は、代わりに手動構成が表示されます。接続に成功した後、DevProjexが`devprojex`コマンドをPATHに追加するよう提案することがあります。

Codexが保持するDevProjexの接続は共有の1つだけなので、別のプロジェクトを接続するときは置き換える前に確認します。すでに実行中のクライアントセッションは、サーバーを読み込むために再起動する必要があります。ターミナルでは、`devprojex mcp connect`は既定で標準モードを登録します。Live contextにするには`--mode live`を、構成を表示するだけなら`--print`を追加します。

### 19.2 Live context
Live contextでは、ツリーでチェックした項目がエージェントのフォーカスになります。ツリー、検索、分析、関連ファイル、パックの要求は、その範囲内に限られます。ウィンドウのフィルター（ファイルの種類、除外事項、Gitモード）はアクセスの境界です。エージェントは名前を指定してほかのファイルを開くこともできますが、開けるのはこれらのフィルターが許可するファイルだけです。

ウィンドウを開いたままにしておく必要はありません。サーバーは要求のたびに、そのプロジェクトについて最後に保存された選択を読み込むため、新しくチェックした項目や適用した設定は、エージェントを再起動しなくても次の要求から反映されます。

ライブセッションがアクティブな間、ウィンドウのタイトルの末尾に`· Live context (<client>)`が表示されます。複数のセッションがアクティブな場合はセッション数が表示されます。

### 19.3 ジャーナル
「MCP → ジャーナル…」は、エージェントがDevProjexを通じて要求し、受け取った内容を表示します。セッションごとにクライアント、モード、呼び出し、文字数、推定トークン数、配信されたファイル、マスクされた値が表示され、選択したセッションの呼び出しも確認できます。プロジェクトを開いていなくても使用できます。プロジェクトを開いている場合は、既定で「現在のプロジェクトのみ」が選択されています。

ジャーナルはこのコンピューターにのみ、DevProjexの状態フォルダーに保存され、最大200セッションを30日間保持します。ファイルの内容、検出されたシークレットの値、検索クエリのテキストは保存されません。「エクスポート…」はセッションをMarkdownまたはJSONの受領記録として保存します。「消去」は確認の後に完了したセッションを削除します。アクティブなセッションと、ほかのプロジェクトと共有しているセッションは保持されます。

### 19.4 エージェントのアクティビティ
「表示 → エージェントのアクティビティ」は既定でオフです。選択すると印が表示され、もう一度選択すると非表示になります。オンの間にライブセッションがアクティブであれば、そのセッションでエージェントが内容を受け取ったファイル（ファイル全体、行範囲、検索の一致箇所、宣言のいずれか）に、ツリーで✦の印が付きます。ツリーの一覧やサイズの見積もりでしか扱われなかったファイルには印は付きません。✦にポインターを合わせると、エージェントがそのファイルを受け取った回数が「エージェントが 3 回受信」のように表示されます。

印は受け渡された内容を示すだけで、チェックボックス、フィルター、エージェントが読み取れる範囲を変えることはありません。印は、新しいライブセッションが始まったとき、ライブセッションが終了したとき、エージェントのアクティビティをオフにしたとき、プロジェクトを開き直したときに消去されます。その後にエージェントが受け取ったファイルには、改めて印が付きます。標準モードのセッションはジャーナルに表示されますが、印は付きません。

ターミナルワークスペースでは、`:set activity on`で同じファイルにツリーでAの印が付き、そのファイルにフォーカスがあると、エージェントが受け取った回数がステータス行に表示されます。`:set activity off`で印を消せます。

## 20) 注意事項
* 権限が不足している場合、アプリは昇格して再起動するよう提案することがあります。拒否すると通知が表示されます。
