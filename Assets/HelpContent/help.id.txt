## 1) Apa itu dan untuk apa
DevProjex dengan cepat menyiapkan konteks proyek: menampilkan struktur folder/file, memungkinkan Anda memilih item dengan kotak centang, lalu menyalin pohon dan/atau isi file ke clipboard. Berguna untuk peninjauan kode, dukungan, pembelajaran, dan berbagi struktur proyek dengan asisten AI.

Penting: DevProjex tidak mengubah file di proyek yang Anda buka. Satu-satunya pengecualian adalah koneksi MCP eksplisit untuk Cursor atau VS Code, yang membuat atau memperbarui `.cursor/mcp.json` atau `.vscode/mcp.json` (bagian 19.1).

## 2) Pohon proyek
* Ikon jenis file/folder.
* Kotak centang pada node.
* Luaskan/ciutkan.

Kotak centang: memilih sebuah node juga berlaku untuk anak-anaknya; status induk dihitung ulang secara otomatis.

Tombol pintas:
* {mod}E — perluas semua
* {collapseAll} — ciutkan semua (root tetap terbuka)

### Menu konteks
Klik kanan sebuah node, atau tekan {shift}F10 atau tombol Menu pada node yang sedang difokuskan:
* Tampilkan di File Explorer / Buka di Finder / Buka di pengelola file — menampilkan item di pengelola file sistem; labelnya sesuai dengan platform saat ini.
* Salin jalur lengkap — jalur absolut item.
* Salin jalur relatif — jalur dari root proyek, dimulai dengan nama folder root, misalnya `project/src/File.cs`.
* Salin isi — untuk file: menyalin isi dengan transformasi konten yang diterapkan, persis seperti yang dihasilkan oleh penyalinan dan ekspor.
* Pilih hanya ini — mencentang hanya node ini dan menghapus centang lainnya; hanya ditampilkan jika ada item lain yang juga dicentang.
* Perluas cabang / Ciutkan cabang — untuk folder.

Jika jalur tidak lagi ada di disk, membuka item di pengelola file atau menyalin isinya akan menampilkan pesan kesalahan; penyalinan jalur tetap berfungsi.

## 3) File
* Buka folder... — membuka folder root ({mod}O)
* Jendela baru — membuka instans DevProjex baru yang independen
* Terbaru — daftar folder lokal yang baru dibuka
* Segarkan — memindai ulang folder lokal dan membangun ulang pohon (F5)
* Ekspor ke file:
  * Ekspor pohon
  * Ekspor konten
  * Ekspor pohon dan konten
* Ekspor Proyek:
  * Ke Folder…
  * Ke Arsip ZIP…

Ekspor Proyek membuat folder atau arsip ZIP terpisah dari pohon saat ini dengan tetap mempertahankan struktur direktori.

Jenis file yang dipilih, aturan pengecualian, dan item yang dicentang akan dipatuhi. Jika tidak ada yang dicentang, seluruh pohon saat ini akan diekspor.

File teks dan biner disalin, dan folder kosong yang disertakan tetap dipertahankan. File sumber tidak diubah. Hasilnya tidak dapat disimpan di dalam proyek sumber.

Selama ekspor, Anda tidak dapat mengubah pohon atau pengaturan, menggunakan filter, mengubah format atau mode pratinjau, menjalankan perintah Git, menyegarkan, atau membuka proyek lain.

Aturan format:
* Ekspor pohon:
  * ASCII -> hanya `.txt`.
  * JSON -> bawaan `.json`, dengan `.json` dan `.txt` tersedia di dialog Simpan.
  * XML -> bawaan `.xml`, dengan `.xml` dan `.txt` tersedia di dialog Simpan.
  * MD -> bawaan `.md`, dengan `.md` dan `.txt` tersedia di dialog Simpan.
* Ekspor konten — selalu dalam format konten teks, file `.txt` (pengalih format pohon tidak berlaku).
* Ekspor pohon dan konten — selalu file `.txt`; format pohon yang dipilih hanya memengaruhi format blok pohon di dalam hasil.

File ekspor ditulis dalam UTF-8 tanpa BOM.

### Seret & Lepas
Seret dan lepas berfungsi di area awal (Drop Zone) saat belum ada proyek yang dimuat.

Aturan:
* Anda dapat melepaskan folder;
* Anda dapat melepaskan file — dalam hal ini folder yang memuatnya akan dibuka;
* jika beberapa item dilepaskan, jalur lokal pertama yang sesuai akan digunakan;
* jika jalur tidak tersedia atau tidak ada, pemeriksaan akses yang sama seperti pada “Buka folder...” diterapkan;
* item yang tidak didukung atau bukan lokal diabaikan.

### Terbaru
Item “File → Terbaru” menampilkan riwayat folder lokal yang baru dibuka.

Aturan:
* hanya folder lokal yang ditambahkan ke daftar;
* repositori Git yang dikloning melalui DevProjex tidak ditambahkan ke daftar ini;
* duplikat tidak dibuat — membuka folder yang sama lagi akan memindahkannya ke atas;
* hingga 32 folder terbaru disimpan;
* riwayat dipertahankan di antara peluncuran aplikasi.

Setiap item menampilkan folder induk dan nama proyek, misalnya `Projects / App`.

## 4) Peluncuran dari terminal
DevProjex menyediakan Terminal Workspace interaktif dan perintah langsung untuk skrip dan CI.

Jika perintah sudah disiapkan, buka terminal dan jalankan:
`devprojex --help`

Perintah ini menampilkan perintah dan opsi tingkat atas. Jalankan `devprojex help <command>` untuk melihat opsi dan contoh khusus perintah tersebut.

Contoh:
* `devprojex` — membuka Terminal Workspace interaktif. Di dalam ruang kerja, jalankan tindakan melalui baris perintah `:` (misalnya `:copy`, `:analyze`, `:branch`, `:language`); lihat bantuan bawaan ruang kerja dan dokumentasi proyek untuk daftar perintah lengkap.
* `devprojex tui .` — membuka folder yang ditentukan langsung di Terminal Workspace.
* `devprojex open . --preview` — membuka folder saat ini di Pratinjau Desktop.
* `devprojex analyze . --format json` — menganalisis proyek saat ini sebagai JSON.
* `devprojex tree .` — mencetak pohon proyek ke terminal.
* `devprojex export context . --format markdown -o ../devprojex-context.md` — menyimpan konteks siap AI di luar proyek sumber.
* `devprojex export project . --as folder -o ../devprojex-submission` — mengekspor pohon proyek efektif ke folder yang ditentukan.
* `devprojex export project . --as zip -o ../devprojex-submission.zip` — mengekspor pohon proyek efektif ke arsip ZIP.
* `devprojex export context https://github.com/owner/repo -o -` — mengemas repositori jarak jauh tanpa perlu mengkloningnya sendiri.
* `devprojex analyze . --git-mode tracked --exclude smart-ignore` — menganalisis file Git yang dilacak dengan Abaikan dengan cerdas.
* `devprojex search Configure . --symbols` — menemukan tempat sebuah deklarasi didefinisikan; `--symbols` menerima nama deklarasi dan menolak sintaks ekspresi reguler, sedangkan `--regex` mencari teks dengan ekspresi reguler.
* `devprojex related src/App.cs` — menampilkan file yang digunakan oleh sebuah file dan file yang menggunakannya.
* `devprojex mcp --root .` — memulai server MCP lokal hanya-baca agar agen AI dapat membaca proyek dengan aman.
* `devprojex mcp connect . --client claude-code` — menghubungkan klien AI ke proyek (bagian 19).
* `devprojex mcp log . --last` — menampilkan sesi jurnal agen terakhir.

Catatan:
* `.` berarti folder terminal saat ini;
* jalur yang mengandung spasi harus diapit tanda kutip;
* `--git-mode` memilih `none`, `gitignore`, `tracked`, `staged`, `changes`, atau `diff:<ref>..<ref>`;
* `--exclude` mengatur pengecualian biasa secara terpisah dari pemfilteran Git;
* perintah analisis dan ekspor bersifat deterministik dan tidak membuka antarmuka Desktop;
* `tui`, `open`, `analyze`, `search`, `tree`, dan kedua perintah `export` juga menerima URL repositori Git, dan `related` menerimanya melalui `--project`; hasil klon masuk ke cache terkelola (`devprojex cache`);
* perintah memiliki alias dan flag pendek yang terdokumentasi — misalnya `export ctx`, `-f`, `-n`; `devprojex help` menampilkannya;
* `analyze --findings` mencantumkan temuan penyamaran tanpa nilainya, dan `--fail-on-findings` mengembalikan kode keluar bukan nol untuk CI;
* `export context --max-tokens N` menjaga konteks tetap dalam anggaran token, dan `--rank importance` yang bersifat eksperimental memasukkan file terpenting lebih dulu;
* perintah analisis, pencarian, dan ekspor tidak mengubah file proyek — DevProjex bekerja dalam mode hanya-baca.

Jika perintah `devprojex` tidak berfungsi, buka di DevProjex:
“Bantuan → Luncurkan dari terminal”.

## 5) Git
“Git → Klon repositori...” mengkloning repositori ke cache DevProjex lalu membukanya. Cabang dan Dapatkan pembaruan hanya tersedia untuk proyek yang dikloning dengan cara ini. Aplikasi tidak menyentuh file Anda — aplikasi hanya bekerja dengan cache.

Cache disimpan di direktori cache sistem milik pengguna. Jalankan `devprojex doctor` untuk melihat jalur yang digunakan.

* Cabang — menampilkan daftar cabang yang tersedia dengan cabang aktif ditandai; beralih cabang memperbarui pohon ke cabang yang dipilih. Jika cabang sudah ada secara lokal, peralihan dilakukan secara offline (tanpa pembaruan). Jika belum ada secara lokal, cabang akan diambil dan dibuat.
* Dapatkan pembaruan — hanya memperbarui cabang saat ini: fetch lalu reset ke origin/<branch>. Untuk proyek Git Clone, F5 melakukan tindakan yang sama; perintah biasa “File → Segarkan” dinonaktifkan.

### Jendela klon
Di jendela Git Clone, daftar “Tautan terbaru” dapat muncul di bawah kolom URL.

Aturan:
* daftar hanya muncul jika riwayat sudah berisi repositori yang baru dikloning;
* hanya sumber repositori jaringan (`https://`, `ssh://`, dan sintaks SCP) yang ditambahkan ke daftar;
* jalur lokal dan sumber `file://` tidak ditambahkan ke daftar ini;
* duplikat tidak dibuat — mengkloning repositori yang sama lagi akan memindahkannya ke atas;
* hingga 16 repositori terbaru disimpan;
* riwayat dipertahankan di antara peluncuran aplikasi.

Memilih item akan mengisi kolom URL secara otomatis.
Selama kloning berlangsung, daftar disembunyikan untuk sementara.

## 6) Salin
### Pengalih format pohon (ASCII / JSON / XML / MD)
Pengalih ini menentukan format representasi pohon untuk operasi yang menyertakan pohon dalam hasilnya.

* ASCII — pohon teks dengan cabang.
* JSON — pohon terstruktur dalam JSON.
* XML — pohon XML ringkas untuk parser dan alat.
* MD — daftar bersarang Markdown untuk dokumentasi dan prompt AI.

Pengalih ini memengaruhi:
* Salin pohon
* Salin pohon dan konten
* Ekspor pohon
* Ekspor pohon dan konten

Pengalih ini tidak memengaruhi:
* Salin konten
* Ekspor konten

### Salin pohon
Menyalin pohon proyek.
Jika ada node yang dicentang, pohon dibangun dari pilihan; jika pilihan kosong atau tidak valid, seluruh pohon disalin.
Format hasil ditentukan oleh pengalih format pohon.
Tombol pintas: {mod}{shift}C dan {mod}{alt}C.

### Salin konten
Menyalin isi file:
* jika ada file yang dicentang — hanya file tersebut; jika tidak — semua file proyek;
* setiap file diawali header berisi jalur lokal lengkapnya (untuk proyek Git Clone — jalur web repositori);
* file non-teks diabaikan (termasuk biner);
* untuk file teks kosong, keluarannya berupa jalur dan baris `[No Content, 0 bytes]`;
* untuk file yang hanya berisi spasi/jeda baris, keluarannya berupa jalur dan baris `[Whitespace, N bytes]`.
Tombol pintas: {mod}{alt}V.

### Salin pohon dan konten
Menggabungkan pohon dan konten:
* pohon dibangun dari pilihan; jika pilihan kosong/tidak valid, seluruh pohon digunakan;
* konten mengikuti aturan yang sama seperti “Salin konten”;
* format blok pohon ditentukan oleh pengalih format pohon.
Tombol pintas: {mod}{shift}V.

### Representasi pohon
Format pohon menggunakan representasi berbeda untuk pohon proyek terpilih yang sama.

JSON:
* `rootPath` — jalur root absolut yang dinormalisasi dengan `/`.
* `tree` — isi folder root.
* Ekspor JSON menggunakan format pohon ini: array berisi file, objek berisi subfolder, `/` berisi file di folder saat ini, dan `[]` menandakan folder kosong.

XML:
* node root adalah `<t r="...">`;
* folder adalah `<d n="...">`;
* file adalah `<f>File.cs</f>`.

MD:
* dimulai dengan `Root: ...`;
* menggunakan daftar bersarang Markdown;
* folder diakhiri dengan `/`.

Pohon + konten:
* format pohon yang dipilih berlaku untuk blok pohon;
* blok konten tetap berupa teks;
* header file di blok konten menggunakan jalur relatif dengan `/`;
* diekspor sebagai `.txt`.

## 7) Mode pratinjau
Dibuka dengan tombol ikon mata di bilah atas atau dengan {mod}B.

Tombol samping mouse mengikuti navigasi gaya browser: Maju membuka mode Pratinjau, dan Kembali menutupnya. Mengulangi arah yang sedang aktif tidak berpengaruh.

{mod}{shift}F membuka atau menutup pencarian di isi file dalam Pratinjau. Enter atau F3 berpindah ke hasil berikutnya; {shift}Enter atau {shift}F3 berpindah ke hasil sebelumnya.

Menampilkan hasil akhir di ruang kerja terpisah di samping pohon. Mode ini tidak menyalin ke clipboard dan tidak mengekspor ke file dengan sendirinya — ini adalah mode tampilan.

Secara bawaan, ruang kerja dibuka sebagai berikut:
* kiri — pohon proyek;
* tengah — panel pratinjau;
* kanan — panel pengaturan, jika sedang terbuka.

Mode yang tersedia:
* Pohon
* Isi
* Pohon + konten

Aturan yang sama seperti penyalinan dan ekspor diterapkan:
* node yang dicentang dipatuhi;
* jika pilihan kosong, seluruh data digunakan;
* aturan pengecualian dan opsi pemilihan saat ini diterapkan.

Selain itu:
* file dalam pratinjau dipisahkan oleh garis horizontal;
* saat menggulir, jalur file saat ini disematkan di bagian atas; mengklik jalur yang disematkan akan menggulir kembali ke awal file tersebut;
* bilah gulir pratinjau menandai hasil pencarian dan baris yang berisi temuan penyamaran; mengklik penanda akan melompat ke barisnya; temuan yang dibiarkan apa adanya tetap ditandai, dan header jalur yang disamarkan menambahkan satu penanda pada baris pertamanya;
* zoom pohon dan pratinjau dapat diatur secara terpisah;
* dalam mode Pratinjau, Anda dapat menyalin seluruh hasil saat ini atau blok file yang sedang terlihat tanpa membuka menu Salin.

Tombol:
* tombol salin di sisi kiri pulau pratinjau atas — menyalin mode pratinjau saat ini:
  * Pohon
  * Isi
  * Pohon + konten
* X di panel pohon — menyembunyikan pohon dan hanya menyisakan panel pratinjau;
* X di panel pratinjau atas — menutup mode Pratinjau sepenuhnya;
* tombol salin kecil di header file yang disematkan — menyalin blok file yang sedang terlihat persis seperti yang ditampilkan di Pratinjau;
* menekan ikon mata lagi atau {mod}B juga menutup mode Pratinjau.

Pencarian dan Filter tersedia selama panel pohon terlihat di Pratinjau.
Jika pohon disembunyikan, Pencarian dan Filter tidak tersedia untuk sementara hingga Anda keluar dari mode khusus pratinjau.

## 8) Tampilan
### Zoom
* {mod}+ / {mod}= — perbesar
* {mod}- — perkecil
* {mod}0 — atur ulang
* {mod}roda mouse — zoom halus pada panel di bawah kursor

Perilaku:
* dalam mode normal, pohon yang diperbesar;
* di Pratinjau dengan pohon terlihat, Perbesar, Perkecil, dan Setel ulang zoom dari menu berlaku untuk pohon dan pratinjau;
* dengan {mod}roda mouse, pohon dan pratinjau di-zoom secara terpisah tergantung posisi kursor;
* dalam mode khusus pratinjau, hanya panel pratinjau yang diperbesar.

Rentang: 6–28, nilai atur ulang adalah 15.

### Modus ringkas
Membuat UI lebih padat: jarak yang lebih kecil di pohon dan pengaturan.
Saat ruang kerja pratinjau aktif, Modus ringkas diaktifkan secara otomatis.

### Animasi
“Tampilan → Animasi” mengatur perluasan pohon, penghitung status, dan kemunculan awal alat secara terpisah. Ketiganya aktif secara bawaan; animasi yang dinonaktifkan langsung menampilkan keadaan akhirnya.

### Fonta pohon
Fonta pohon dipilih melalui “Tampilan → Fonta pohon”.
“Bawaan” mengembalikan fonta pohon standar.
Fonta yang dipilih diterapkan setelah mengklik “Terapkan pengaturan” di panel pengaturan.

### Aktivitas agen
Aktifkan “Tampilan → Aktivitas agen” untuk melihat file mana yang diterima agen AI live: file tersebut mendapat penanda ✦ di pohon (bagian 19.4).

## 9) Pencarian (pohon)
Membuka bilah pencarian, menyorot hasil yang cocok, dan memungkinkan navigasi.
* {mod}F — tampilkan/sembunyikan
* Enter — hasil berikutnya
* {shift}Enter — hasil sebelumnya
* Esc — tutup

Pencarian hanya memperluas cabang yang diperlukan secara otomatis; menghapus kueri akan menciutkan pohon (kecuali root).
Baris yang cocok juga ditandai pada bilah gulir pohon; mengklik penanda akan melompat ke hasil tersebut.
Untuk jumlah hasil yang sangat besar, aplikasi dapat membatasi perluasan otomatis dan penyorotan global agar UI tetap responsif.
Saat bilah pencarian ditutup, kueri dihapus setelah animasi penutupan selesai.

Batasan:
* membuka Pencarian akan menutup Filter secara otomatis;
* Pencarian tersedia di Pratinjau selama panel pohon terlihat;
* jika pohon disembunyikan, Pencarian tidak tersedia untuk sementara.

## 10) Filter (berdasarkan nama)
Hanya menampilkan node yang cocok dengan string filter beserta induknya. Pembaruan diterapkan setelah jeda singkat (debounce).
* {mod}{shift}N — tampilkan/sembunyikan filter
* Esc — tutup filter

Batasan:
* membuka Filter akan menutup Pencarian secara otomatis;
* Filter tersedia di Pratinjau selama panel pohon terlihat;
* jika pohon disembunyikan, Filter tidak tersedia untuk sementara.

## 11) Pilihan (panel pengaturan)
Tersedia di sebelah kanan:
* Terapkan pengaturan
* Pemrosesan konten
* Pengecualian
* Jenis file

Perubahan di “Pengecualian” dan “Jenis file” ditampung di panel dan diterapkan setelah mengklik “Terapkan pengaturan”.

Setelah kotak centang berubah, aplikasi dapat memperbarui opsi yang tersedia beserta jumlahnya di latar belakang. Pohon hasil baru dibangun ulang setelah mengklik “Terapkan pengaturan”.

Jika pembaruan opsi yang tersedia dibatalkan dengan tombol X di bilah status, perubahan yang belum selesai tidak diterapkan dan panel kembali ke keadaan terakhir yang telah selesai.

Setiap daftar memiliki pengalih Semua.

Catatan tentang “Jenis file”:
* daftar ini hanya menampilkan file yang memiliki ekstensi;
* file tanpa ekstensi tidak ditambahkan ke daftar ini dan diatur oleh opsi terpisah di “Pengecualian”.

Pemrosesan konten:
* mengubah isi file teks yang dipilih tanpa mengubah pohon;
* Sembunyikan informasi rahasia dan Sembunyikan data pribadi mengganti nilai yang terdeteksi (bagian 12.3 dan 12.4);
* Kompres kode mempertahankan deklarasi sambil memperpendek implementasi bernama di 14 bahasa;
* Hapus komentar menghapus komentar dan komentar dokumentasi di 20 paket bahasa;
* Hapus baris kosong menghapus baris yang hanya berisi spasi di paket yang sama sambil mempertahankan literal multibaris;
* perubahan berlaku setelah “Terapkan pengaturan”.

{mod}P — tampilkan/sembunyikan panel.

### 11.1 Profil parameter proyek lokal
Untuk folder lokal, DevProjex mengingat parameter proyek yang terakhir diterapkan:
* jenis file yang dipilih;
* opsi yang dipilih di bagian “Pengecualian”.

Penyimpanan dilakukan saat Anda mengklik “Terapkan pengaturan”.
Saat folder lokal yang sama dibuka kembali, parameter dipulihkan secara otomatis.

Penting:
* profil hanya disimpan untuk proyek lokal;
* untuk proyek yang dibuka melalui Git Clone, profil tidak disimpan;
* jika beberapa opsi tersimpan tidak lagi tersedia di proyek saat ini, opsi tersebut dilewati dan parameter lainnya tetap diterapkan;
* jika penyegaran atau pembukaan ulang memunculkan jenis file atau opsi baru di “Pengecualian”, opsi tersebut diaktifkan secara bawaan;
* opsi yang sudah pernah terlihat mempertahankan pilihan eksplisit pengguna: file baru dari jenis yang dinonaktifkan tidak mengaktifkan jenis itu lagi.

## 12) Pengecualian
Bagian “Pengecualian” mengatur file dan folder mana yang dikecualikan dari pohon, konten, salinan, dan hasil ekspor.

Item hanya ditampilkan jika semua kondisi berikut terpenuhi:
* jenis filenya dipilih, jika file tersebut memiliki jenis;
* tidak ada aturan pengecualian aktif yang mengecualikannya.

Aturan pengecualian bersifat kumulatif. Jika setidaknya satu aturan aktif menyembunyikan item, aturan lain tidak dapat menampilkannya kembali.

### 12.1 Aturan yang tersedia
Tergantung isi proyek, opsi berikut dapat ditampilkan:

* Abaikan dengan cerdas
* Folder kosong
* File kosong
* Folder tersembunyi
* File tersembunyi
* Folder titik
* File titik
* File tanpa ekstensi

Pemilih GUI dan baris radio sumbu Git di TUI disembunyikan sepenuhnya saat pemfilteran Git tidak berlaku: tidak ada batas repositori dan filter `.gitignore` tidak dapat mengubah pohon saat ini. Saat sumbu terlihat di luar repositori, GUI hanya menyediakan tanpa pemfilteran dan `.gitignore`, sedangkan TUI menonaktifkan baris yang memerlukan repositori. Di dalam repositori Git tersedia lima nilai biasa: tanpa pemfilteran, `.gitignore`, file yang dilacak, file yang disiapkan di Git, dan semua perubahan saat ini; di TUI, cakupan `diff:<ref>..<ref>` yang aktif muncul sebagai baris keenam. Memilih satu nilai menggantikan mode Git saat ini tanpa mengubah Abaikan dengan cerdas atau pengecualian dasar. Opsi lain ditampilkan jika aturannya dapat mengubah pohon saat ini, sehingga daftar dapat berubah setelah aturan atau jenis file lain dialihkan.

Opsi baru diaktifkan secara bawaan saat pertama kali muncul. Opsi yang sudah dikenal tetap mempertahankan pilihan pengguna meskipun untuk sementara hilang dari daftar.

### 12.2 Abaikan dengan cerdas (Smart Ignore)
Abaikan dengan cerdas menyembunyikan dependensi, keluaran build, cache, dan artefak layanan proyek lainnya.

DevProjex terlebih dahulu mengenali jenis proyek dari struktur dan file penandanya, misalnya:

* `.csproj`
* `package.json`
* `pyproject.toml`
* `Cargo.toml`

Aturan untuk stack yang sesuai kemudian diterapkan di dalam cakupan proyek yang terdeteksi. Misalnya, aturan .NET tidak meluas ke proyek Python atau JavaScript di sebelahnya.

Nama folder saja tidak selalu cukup. Nama ambigu seperti `build`, `vendor`, `packages`, `cache`, `pkg`, atau `Library` juga diverifikasi berdasarkan isinya. Ini mencegah folder pengguna biasa disembunyikan hanya karena namanya mirip.

Beberapa penyimpanan dependensi dan direktori layanan dapat dikenali dari struktur internal khasnya, bahkan di luar proyek yang terdeteksi secara eksplisit.

Penemuan cakupan proyek dibatasi agar memuat folder pengguna yang besar tidak berubah menjadi analisis berulang penuh atas setiap direktori. Struktur biasa menggunakan penemuan dangkal, sedangkan monorepo yang dikenali ditelusuri lebih dalam. Setelah cakupan ditemukan, Abaikan dengan cerdas berlaku untuk seluruh subpohonnya tanpa batas kedalaman.

### 12.3 Sembunyikan informasi rahasia
“Sembunyikan informasi rahasia” nonaktif secara bawaan. Opsi ini hanya memindai konten teks yang dipilih dan mengganti setiap nilai yang terdeteksi di tempatnya, dengan tetap mempertahankan file dan kode di sekitarnya. Selama opsi nonaktif, tidak ada pemindaian dan tidak ada jumlah yang ditampilkan. Setelah pilihan saat ini dipindai, label menampilkan jumlah nilai yang terdeteksi; jika keputusan untuk membiarkan nilai apa adanya membuat nilai yang disembunyikan lebih sedikit, label menampilkan terdeteksi/disembunyikan, dan indikator ? pada baris tersebut melaporkan kedua jumlah itu.

Rentang yang disamarkan disorot di Pratinjau. Klik salah satunya untuk membiarkan hanya kemunculan itu apa adanya; {alt}↓ / {alt}↑ berpindah antar temuan dan Enter mengalihkan temuan aktif. Di Terminal Workspace, gunakan `[` dan `]` untuk berpindah antar kemunculan dan `Enter` atau `Space` untuk mengalihkan kemunculan aktif. Keputusan ini berlaku untuk Pratinjau, clipboard, ekspor konteks, salinan folder, dan ZIP selama sesi saat ini; keputusan tidak disimpan di profil proyek.

Menu konteks Pratinjau memperluas keputusan ini. Klik kanan kemunculan yang terdeteksi untuk membiarkan — atau menyembunyikan lagi — semua kemunculan dari aturannya atau semua kemunculan yang terdeteksi dalam file yang sama sekaligus. Klik kanan nilai yang dipilih di dalam isi file untuk menandainya secara manual: “Sembunyikan … di sini” hanya menyembunyikan kemunculan tersebut selama sesi, “Selalu sembunyikan …” membuat tanda permanen untuk setiap kemunculan nilai tersebut, dan “Sembunyikan … sebagai data pribadi” membuat tanda permanen yang dikendalikan oleh Sembunyikan data pribadi. “Hapus tanda” muncul pada tanda manual dan menghapusnya; nilai yang masih cocok dengan detektor tetap tersembunyi. Nilai manual harus berupa satu baris sepanjang 8 hingga 512 karakter yang dipilih di dalam isi file. Membuat tanda akan mengaktifkan opsi terkait secara otomatis. Tanda permanen hanya menyimpan identitas nilai berkunci dan kelasnya, tidak pernah teks aslinya.

Salinan folder atau ZIP juga mengubah teks yang cocok dan mungkin tidak lagi dapat di-build atau dijalankan. File biner disalin tanpa perubahan dan tidak dipindai. File teks terpilih yang lebih besar dari 16 MiB dilewati dan dilaporkan, sementara sisa keluaran tetap diselesaikan. Kegagalan deteksi menghentikan seluruh operasi.

Jumlah ini hanya melaporkan kecocokan aturan. Nol tidak berarti proyek aman. CLI menggunakan `--hide-secrets`; detail teknis dan batasannya ada di `Docs/HideSecrets.md`.

### 12.4 Sembunyikan data pribadi
“Sembunyikan data pribadi” nonaktif secara bawaan. Opsi ini mendeteksi alamat email, alamat IP global, nama pengguna lokal di jalur, alamat MAC, dan nomor telepon internasional dalam file teks yang dipilih. Temuan menggunakan keputusan Pratinjau dan alur keluaran yang sama seperti Sembunyikan informasi rahasia; tanda manual yang dibuat dengan “Sembunyikan … sebagai data pribadi” termasuk dalam kelas ini dan mengikuti sakelar ini (bagian 12.3). Nama pengguna lokal di header jalur yang dihasilkan dan di root pohon disamarkan sebagai satu temuan bersama: penghitung menghitungnya sebagai satu nilai, indikator ? melaporkan apakah nilai itu disembunyikan atau ditampilkan, dan satu klik mengalihkan semua jalur yang disamarkan.

Rentang dan host dokumentasi, nama pengguna CI yang umum, resolver DNS publik yang terkenal, dan rentang nomor telepon fiktif yang terdokumentasi tetap terlihat. Nol kecocokan bukan jaminan privasi. CLI menggunakan `--hide-private-data`; aturan lengkap dan batasan fase pertama ada di `Docs/HidePrivateData.md`.

### 12.5 Gunakan .gitignore
Jika diaktifkan, DevProjex mengikuti tampilan pohon kerja dari `git status`: file yang dilacak tetap terlihat, dan file yang tidak dilacak ditampilkan kecuali dikecualikan oleh aturan abaikan repositori. DevProjex menerapkan setiap `.gitignore` yang dapat dijangkau, bukan hanya file di root folder yang dibuka, termasuk file di atasnya hingga root repositori.

Setiap `.gitignore` berlaku:

* untuk folder yang memuatnya;
* untuk semua folder yang dapat diakses di bawahnya;
* hanya di dalam cakupan tersebut.

Aturan dari `.gitignore` bersarang tidak memengaruhi folder induk atau folder setingkat.

Untuk jalur tertentu, aturan diproses dari `.gitignore` induk menuju file yang lebih dalam. Di dalam satu file, aturan diproses dari atas ke bawah. Aturan cocok terakhir menentukan hasil Git.

Aturan yang dimulai dengan `!` membatalkan pengecualian Git sebelumnya hanya di dalam cakupannya. Aturan ini tidak dapat memulihkan file selama folder induknya tetap dikecualikan. `.gitignore` di dalam folder yang sepenuhnya dikecualikan dan tidak dapat dijangkau tidak ikut dievaluasi.

Baris yang salah format atau tidak didukung dilewati secara terpisah. Aturan valid lainnya di file tersebut dan aturan di cakupan sekitarnya tetap berfungsi.

File `.git/info/exclude` lokal repositori juga diterapkan, dengan prioritas lebih rendah daripada `.gitignore` di root. Folder bersarang yang memiliki `.git` sendiri juga mengikuti `git status`: repositori tertanam yang tidak dideklarasikan di `.gitmodules` bersifat tertutup sehingga file-filenya tidak ditampilkan, sedangkan submodul yang dideklarasikan menerapkan `.gitignore` dan `info/exclude` miliknya sendiri. Pilih `none` untuk melihat file repositori tertanam. Aturan pengecualian Git global (`core.excludesFile`) tidak diterapkan; pengaturan perbandingan jalur repositori yang berlaku seperti `core.ignoreCase` dan, di macOS, `core.precomposeUnicode` dipatuhi. Tautan simbolik bernama `.gitignore` tidak diikuti, sesuai dengan perilaku Git untuk file kontrol. Jika file `.gitignore` atau `info/exclude` tidak dapat dibaca, cakupan direktorinya dikecualikan secara aman (fail-closed) dan pemindaian melaporkan akses parsial alih-alih diam-diam menyertakan file tanpa evaluasi aturan yang lengkap. Jika indeks yang dapat dibaca tersedia untuk cakupan repositori pemilik jalur tersebut, file yang dilacak tetap terlihat meskipun cocok dengan `.gitignore`; tanpa indeks tersebut atau Git CLI, cakupan itu dengan aman kembali ke evaluasi pola saja.

Profil bawaan `standard` memilih `gitignore` beserta `smart-ignore`, `hidden-folders`, `hidden-files`, `dot-folders`, `dot-files`, `empty-folders`, `empty-files`, dan `extensionless-files`.

### 12.6 Hanya file Git yang dilacak
“Hanya file Git yang dilacak” membangun tahap Git pada pohon dari file pohon kerja yang ada dan tercatat di setiap indeks Git yang dapat dibaca. File terlacak yang diubah dan penambahan yang sudah di-stage tetap disertakan; file yang tidak dilacak dikecualikan. Ini adalah pohon kerja saat ini, bukan snapshot historis `HEAD` atau repositori jarak jauh.

Setiap repositori diselesaikan secara terpisah: repositori setingkat di dalam folder yang dibuka dan submodul yang dideklarasikan masing-masing menggunakan indeksnya sendiri, dan repositori anak tidak mewarisi jalur terlacak dari induk atau repositori setingkatnya. Repositori tertanam yang tidak dideklarasikan di `.gitmodules` tetap tertutup, seperti dalam mode `.gitignore`. Mode ini memerlukan Git CLI; indeks kosong yang dapat dibaca tetap valid. Jika Terminal Workspace (TUI) dimulai dalam mode ini dan tidak ada indeks yang berlaku yang dapat dimuat, ruang kerja tidak dibuka. Jika mode ini dipilih secara interaktif di ruang kerja TUI yang terbuka dan tidak ada indeks yang berlaku yang dapat dimuat, perubahan ditolak dan mode Git terakhir yang dapat digunakan tetap aktif. Dalam situasi yang sama, perintah langsung mengembalikan kegagalan kebijakan atau pemeriksaan. DevProjex tidak pernah diam-diam beralih ke `.gitignore`. Jika indeks lain yang berlaku dapat dibaca, cakupan bersarang yang tidak tersedia dikecualikan dengan peringatan.

Di ruang kerja Desktop yang sudah terbuka, pilihan file terlacak yang eksplisit tetap terlihat dan bersifat fail-closed: keluaran dan ekspor diblokir jika kesiapan gagal, sedangkan kesiapan parsial dilanjutkan dengan peringatan yang dilokalkan.

Mode Git saling eksklusif; `none` menonaktifkan pemfilteran Git. Mode sementara `staged`, `changes`, dan `diff:<ref>..<ref>` tidak disimpan di profil. Selama mode sementara aktif, profil proyek lokal GUI mempertahankan mode persisten terakhir yang diaktifkan, yaitu `gitignore` atau `tracked`. Mode `none` hanya disimpan jika sedang aktif saat penyimpanan. TUI dan CLI menolak menyimpan profil portabel selama mode sementara aktif.

### 12.7 Hubungan antara pemfilteran Git dan Abaikan dengan cerdas
Mode Git yang dipilih dan Abaikan dengan cerdas adalah kontrol yang independen. Mode Git diterapkan lebih dulu di setiap cakupan Git yang dapat dijangkau. Abaikan dengan cerdas kemudian memproses item yang tersisa, dan aturan dasar dijalankan terakhir.

Abaikan dengan cerdas dapat tetap tersembunyi selama mode Git yang dipilih sudah mencakup semua kandidatnya, lalu muncul setelah mode Git diubah atau dimatikan. Di dalam repositori Git, semua mode Git yang bergantung pada repositori tetap tersedia.

Aturan negasi Git yang dimulai dengan `!` hanya membatalkan hasil Git. Aturan ini tidak menonaktifkan Abaikan dengan cerdas atau aturan dasar.

### 12.8 Aturan dasar
“Folder titik” dan “File titik” memeriksa nama item: apakah nama diawali titik.

“Folder tersembunyi” dan “File tersembunyi” memeriksa atribut tersembunyi sistem. Pada beberapa platform, nama berawalan titik dan atribut sistem dapat menggambarkan item yang sama atau item yang berbeda.

“File kosong” menyembunyikan file berukuran 0 byte.

“File tanpa ekstensi” menyembunyikan file seperti `Dockerfile`, `Makefile`, dan `README`.

“Folder kosong” menyembunyikan folder yang kosong secara logis. Folder dianggap kosong secara logis jika tidak ada file atau subfolder yang terlihat setelah jenis file yang dipilih dan semua aturan lain diterapkan.

Karena itu, jumlah folder kosong dapat berubah setelah aturan lain dialihkan: menyembunyikan file dapat membuat folder yang memuatnya menjadi kosong secara logis.

### 12.9 Penghitung
Angka di samping aturan menunjukkan kontribusi langsungnya berdasarkan pengaturan saat ini, bukan jumlah fisik item serupa di disk.

Satu item tidak diatribusikan ke beberapa penghitung yang tumpang tindih sekaligus. Misalnya, folder `.git` dapat memiliki nama berawalan titik sekaligus atribut sistem Tersembunyi, tetapi pengecualiannya hanya diatribusikan ke satu aturan.

Urutan tetap digunakan untuk memilih pemilik pengecualian:

* folder: `.gitignore`, Abaikan dengan cerdas, nama berawalan titik, atribut sistem Tersembunyi;
* file: `.gitignore`, Abaikan dengan cerdas, nama berawalan titik, tanpa ekstensi, file kosong, atribut sistem Tersembunyi.

Urutan ini hanya memengaruhi penghitung. Visibilitas akhir mengikuti aturan yang lebih sederhana: item disembunyikan jika ada mekanisme aktif yang mengecualikannya.

### 12.10 Menerapkan perubahan
Mengalihkan kotak centang terlebih dahulu memperbarui pengaturan dan penghitung yang tersedia di panel. Pohon akhir dibangun ulang setelah “Terapkan pengaturan” dipilih.

Jika persiapan pengaturan dibatalkan, DevProjex mengembalikan panel ke keadaan terakhir yang selesai sepenuhnya. Aturan yang dihitung sebagian tidak diterapkan.

## 13) Cara pohon dan metrik dihitung
Hasil bergantung pada:
* Jenis file yang dipilih
* Aturan pengecualian
* Filter aktif
* node pohon yang dicentang (untuk operasi berbasis pilihan)

Jika akses ditolak, node tetap memakai nama dan ikon biasanya serta mendapat akhiran “[akses ditolak]”.

### 13.1 Apa yang ditampilkan penghitung bilah status
Bilah status memiliki dua blok:
* Pohon — metrik keluaran teks pohon;
* Isi — metrik keluaran isi file yang diekspor.

Format:
* Baris
* Karakter
* ≈Token (perkiraan)

Nilai besar ditampilkan dengan akhiran ringkas (K/M).

Penting:
* “Baris” di blok “Pohon” berarti jumlah baris dalam representasi pohon akhir, bukan jumlah file di disk;
* nilai ini mencakup folder, file, dan elemen layanan pohon (misalnya node dengan akses ditolak).

### 13.2 Cara metrik dihitung
Metrik pohon:
* dihitung dari keluaran pohon sebenarnya yang dihasilkan oleh alur ekspor yang sama;
* mengikuti format pohon saat ini.

Metrik isi:
* mengikuti aturan yang sama seperti penyalinan/ekspor konten;
* file biner dikecualikan;
* file kosong dan file yang hanya berisi spasi dihitung melalui penanda layanan (`[No Content, 0 bytes]`, `[Whitespace, N bytes]`).

### 13.3 Kapan penghitung diperbarui
Penghitungan ulang dijalankan:
* setelah membuka/menyegarkan proyek;
* setelah menerapkan pengaturan (pengecualian dan jenis file);
* saat kotak centang pohon berubah (dengan debounce);
* saat mengganti format pohon (untuk operasi yang menggunakan keluaran pohon);
* saat penghitungan latar belakang dibatalkan, penghitung diatur ke 0 hingga penghitungan ulang berikutnya selesai.

## 14) Ikon
Urutan pemilihan ikon:
1) jenis node (folder/file)
2) nama persis (jika ada aturannya)
3) ekstensi
4) selain itu — tidak dikenal

## 15) Tema dan efek
Bagian Tema memungkinkan Anda memilih Sistem, Terang, atau Gelap serta satu efek latar belakang:
* Transparansi
* Buram
* Mica

Sistem dipilih secara bawaan dan mengikuti perubahan tema sistem operasi. Setelah peluncuran pertama atau pengaturan ulang, tema sistem terang dimulai dengan latar belakang solid biasa, sedangkan tema sistem gelap dimulai dengan Buram. Jika preferensi sistem tidak dapat ditentukan, DevProjex menggunakan Gelap dengan Buram. Terang dan Gelap mengingat efeknya masing-masing secara terpisah. Pilihan Terang atau Gelap yang eksplisit mengabaikan perubahan sistem hingga Sistem dipilih kembali.

Efek saling eksklusif. Mengklik lagi efek yang dipilih akan menonaktifkannya dan memulihkan latar belakang solid biasa.

Pengaturan yang tersedia:
* Transparansi latar belakang — tersedia untuk Transparansi dan Buram.
* Kontras bilah atas — menyesuaikan panel utama yang berisi perintah Pratinjau, Pencarian, Filter, dan format pohon.
* Transparansi menu — berlaku sama untuk menu utama dan submenunya.
* Visibilitas batas — menyesuaikan seberapa jelas batas antarmuka ditampilkan.

Mica menggunakan material sistem platform dan tidak memiliki pengaturan transparansi latar belakang terpisah. Jika efek Buram atau Mica yang dipilih tidak tersedia, aplikasi terlebih dahulu mencoba efek native lainnya. Latar belakang solid biasa hanya digunakan jika Buram maupun Mica tidak tersedia.

Dalam mode Transparansi, latar belakang jendela utama tetap transparan. Menu, submenu, dan permukaan popup lainnya menggunakan Buram jika didukung agar elemen pohon dan konten di belakangnya tidak mengganggu keterbacaan.

## 16) Bantuan

### 16.1 Pembaruan
“Bantuan → Pembaruan” membandingkan versi saat ini dengan rilis GitHub stabil terbaru. Pemeriksaan otomatis nonaktif secara bawaan; jika diaktifkan, DevProjex memeriksa saat startup setelah setidaknya tujuh hari berlalu sejak pemeriksaan berhasil sebelumnya. Kotak centang langsung berlaku. Hasil berhasil terakhir dipertahankan di antara sesi aplikasi dan tidak terhapus oleh kegagalan jaringan berikutnya. Instalasi tetap merupakan tindakan pengguna.

### 16.2 Atur ulang pengaturan
Atur ulang pengaturan (Bantuan → Atur ulang pengaturan) memulihkan tema, efek, Modus ringkas, pengaturan animasi, dan bahasa antarmuka ke bawaan. Profil proyek, riwayat, dan file di disk tidak diubah.

Setel ulang data (Bantuan → Setel ulang data) menghapus profil parameter proyek lokal yang tersimpan:
* jenis file yang dipilih;

* pengaturan pemrosesan konten yang dipilih;

Tindakan ini juga menghapus sesi jurnal agen yang sudah selesai (bagian 19.3); sesi aktif tetap dipertahankan.

Penting:
* riwayat Terbaru untuk folder lokal tidak dihapus;
* riwayat repositori terbaru di jendela Git Clone tidak dihapus;
* file dan folder di disk tidak diubah atau dihapus.

Bahasa dipilih melalui menu Bahasa.
Bahasa yang dipilih disimpan di antara peluncuran. “Bantuan → Atur ulang pengaturan” menghapus pilihan bahasa yang tersimpan dan mengembalikan bahasa antarmuka ke bawaan.

## 18) Bilah kemajuan dan pembatalan
Bagian tengah bilah status menampilkan operasi yang sedang berjalan dan kemajuannya.

Mode kemajuan:
* Tak tentu — tanpa persentase (durasi operasi tidak diketahui).
* Tentu — dengan persentase (0–100).

Perilaku:
* selama penghitungan data latar belakang, kemajuan dalam persen ditampilkan;
* untuk beberapa operasi Git, persentase ditampilkan jika sumber kemajuan menyediakannya;
* pembaruan opsi yang tersedia dan penerapan pengaturan ditampilkan jika operasi memakan waktu yang terasa;
* operasi cepat selesai tanpa menampilkan kemajuan.

Tombol X (batal) di bilah status:
* melakukan pembatalan sebisa mungkin untuk operasi yang mendukung pembatalan;
* menghentikan penghitungan data latar belakang;
* saat pembaruan opsi yang tersedia dibatalkan, mengembalikan panel ke keadaan terakhir yang selesai;
* untuk operasi tanpa dukungan pembatalan, tombol ini menghentikan indikasi di bilah status, sementara operasinya sendiri mungkin tetap selesai di latar belakang.

## 19) MCP dan agen AI
DevProjex menyertakan server MCP lokal hanya-baca. Agen AI seperti Claude Code, Codex, Cursor, dan VS Code membaca proyek melaluinya: penyamaran rahasia selalu aktif, dan agen tidak dapat mengubah file proyek. Server menyediakan delapan alat: `list_projects`, `get_tree`, `analyze`, `search_project`, `related_files`, `get_file`, `pack_context`, dan `read_pack`.

### 19.1 Menghubungkan klien
Menu MCP berisi:
* Live context — server mengikuti item yang dicentang di jendela ini (bagian 19.2);
* Standar — server tidak bergantung pada pilihan di jendela;
* Jurnal… — apa yang diminta dan diterima agen (bagian 19.3);
* Dokumentasi — membuka dokumentasi server MCP.

Live context dan Standar berisi tindakan yang sama — Buka di Claude Code, Buka di Codex, Buka di Cursor, Buka di VS Code, dan Klien lain… — yang tersedia selama proyek terbuka.

Claude Code dan Codex didaftarkan melalui perintah yang terinstal, lalu klien dibuka di terminal baru di folder proyek. Cursor dan VS Code menerima `.cursor/mcp.json` atau `.vscode/mcp.json` lokal proyek; server lain di file tersebut tetap dipertahankan. Klien lain… menampilkan konfigurasi siap pakai untuk Claude Desktop dan klien lain. Jika perintah klien tidak ditemukan atau koneksi gagal, DevProjex menampilkan konfigurasi manual sebagai gantinya. Setelah koneksi berhasil, DevProjex dapat menawarkan untuk menambahkan perintah `devprojex` ke PATH.

Codex menyimpan satu koneksi DevProjex bersama, sehingga menghubungkan proyek lain akan meminta konfirmasi sebelum menggantinya. Sesi klien yang sudah berjalan harus dimulai ulang agar memuat server. Di terminal, `devprojex mcp connect` mendaftarkan mode standar secara bawaan; tambahkan `--mode live` untuk Live context atau `--print` untuk hanya mencetak konfigurasi.

### 19.2 Live context
Dalam Live context, item yang dicentang di pohon menentukan fokus agen: permintaan pohon, pencarian, analisis, file terkait, dan paket tetap berada di dalamnya. Filter jendela — jenis file, pengecualian, dan mode Git — adalah batas akses: agen tetap dapat membuka file lain berdasarkan nama, tetapi hanya file yang diizinkan oleh filter tersebut.

Jendela tidak perlu tetap terbuka. Server membaca pilihan yang terakhir disimpan untuk proyek pada setiap permintaan, sehingga centang baru dan pengaturan yang diterapkan sampai ke agen pada permintaan berikutnya tanpa perlu memulai ulang agen.

Selama sesi live aktif, judul jendela diakhiri dengan `· Live context (<client>)`, atau dengan jumlah sesi jika ada beberapa sesi aktif.

### 19.3 Jurnal
“MCP → Jurnal…” menampilkan apa yang diminta dan diterima agen melalui DevProjex: sesi beserta klien, mode, panggilan, karakter, perkiraan token, file yang dikirim, dan nilai yang disamarkan, serta panggilan dari sesi yang dipilih. Jurnal tersedia tanpa proyek yang terbuka; saat proyek terbuka, “Hanya proyek saat ini” dipilih secara bawaan.

Jurnal hanya disimpan di komputer ini, di folder status DevProjex, dan menyimpan paling banyak 200 sesi selama 30 hari. Jurnal tidak menyimpan isi file, nilai rahasia yang terdeteksi, atau teks kueri pencarian. Ekspor… menyimpan sesi sebagai tanda terima Markdown atau JSON. Hapus menghapus sesi yang sudah selesai setelah konfirmasi; sesi aktif dan sesi yang juga dipakai proyek lain tetap dipertahankan.

### 19.4 Aktivitas agen
“Tampilan → Aktivitas agen” nonaktif secara bawaan: pilih untuk mengaktifkan penanda, lalu pilih lagi untuk menonaktifkannya. Selama opsi ini aktif dan ada sesi live yang aktif, setiap file yang isinya diterima agen dalam sesi tersebut — seluruh file, rentang baris, baris hasil pencarian, atau sebuah deklarasi — ditandai dengan ✦ di pohon. File yang hanya dilihat agen dalam daftar pohon atau dalam perkiraan ukuran tidak ditandai. Arahkan kursor ke ✦ untuk melihat berapa kali agen menerima file tersebut, misalnya “Agen menerima 3 kali”.

Penanda hanya menunjukkan apa yang telah dikirim: penanda tidak pernah mengubah kotak centang, filter, atau apa yang dapat dibaca agen. Penanda dihapus saat sesi live yang lebih baru dimulai, saat sesi live berakhir, saat Aktivitas agen dimatikan, dan saat proyek dibuka kembali; file yang diterima agen setelah itu akan ditandai lagi. Sesi Standar muncul di jurnal tetapi tidak menambahkan penanda.

Di Terminal Workspace, `:set activity on` menandai file yang sama dengan A di pohon, dan saat file tersebut difokuskan, baris status menampilkan berapa kali agen menerimanya; `:set activity off` menghapus penanda.

## 20) Catatan
* Jika izin tidak mencukupi, aplikasi dapat menyarankan untuk memulai ulang dengan hak akses yang lebih tinggi; jika ditolak, pemberitahuan akan ditampilkan.
