## 1) Что это и для чего
DevProjex быстро формирует контекст проекта: показывает структуру папок/файлов, позволяет выбрать элементы галочками и скопировать дерево и/или содержимое файлов в буфер обмена. Удобно для code review, поддержки, обучения и передачи структуры проекта AI-ассистенту.

Важно: DevProjex не изменяет файлы в открытом проекте.

## 2) Дерево проекта
* Иконки типов файлов/папок.
* Чекбоксы на узлах.
* Раскрытие/сворачивание.

Чекбоксы: отметка узла применяется к потомкам; состояние родителей пересчитывается автоматически.

Горячие клавиши:
* Ctrl+E — раскрыть всё
* Ctrl+W — свернуть всё (корень остаётся раскрытым)

## 3) Файл
* Открыть папку… — открыть корневую папку (Ctrl+O)
* Новое окно — открыть новый независимый экземпляр DevProjex
* Недавние — список недавно открытых локальных папок
* Обновить — перечитать локальную папку и перестроить дерево (F5)
* Экспорт в файл:
  * Экспорт дерева
  * Экспорт содержимого
  * Экспорт дерева и содержимого
* Экспорт проекта:
  * В папку…
  * В ZIP-архив…

Экспорт проекта создаёт отдельную папку или ZIP-архив из текущего дерева с сохранением структуры каталогов.

Учитываются выбранные типы файлов, правила исключения и отмеченные элементы. Если ничего не отмечено, экспортируется всё текущее дерево.

Копируются текстовые и бинарные файлы, а также сохраняются включённые пустые папки. Исходные файлы не изменяются. Результат нельзя сохранить внутрь исходного проекта.

Во время экспорта нельзя изменять дерево и параметры, использовать фильтр, менять формат или режим предпросмотра, запускать команды Git, обновление и открытие другого проекта.

Правила формата:
* Экспорт дерева:
  * ASCII → только `.txt`.
  * JSON → по умолчанию `.json`, при сохранении доступны `.json` и `.txt`.
  * XML → по умолчанию `.xml`, при сохранении доступны `.xml` и `.txt`.
  * MD → по умолчанию `.md`, при сохранении доступны `.md` и `.txt`.
* Экспорт содержимого — всегда текстовый формат содержимого, файл `.txt` (переключатель формата дерева не влияет).
* Экспорт дерева и содержимого — всегда файл `.txt`; выбранный формат дерева влияет только на формат блока дерева внутри результата.

Файлы экспорта записываются в UTF-8 без BOM.

### Drag & Drop
Перетаскивание работает через стартовую область (Drop Zone), когда проект не загружен.

Правила:
* можно перетаскивать папку;
* можно перетаскивать файл — в этом случае открывается папка, в которой находится файл;
* если перетащено несколько объектов, используется первый подходящий локальный путь;
* если путь недоступен или не существует, применяется та же проверка доступа, что и при «Открыть папку…»;
* неподдерживаемые или нелокальные объекты игнорируются.

### Недавние
Пункт «Файл → Недавние» показывает историю недавно открытых локальных папок.

Правила:
* в список попадают только локальные папки;
* Git-репозитории, клонированные через DevProjex, в этот список не добавляются;
* дубликаты не создаются — повторное открытие той же папки поднимает её вверх списка;
* хранится до 32 последних папок;
* история сохраняется между запусками приложения.

Для каждого пункта показываются имя родительской папки и имя проекта, например `Projects / App`.

## 4) Запуск из терминала
DevProjex предоставляет интерактивное терминальное рабочее пространство и прямые команды для скриптов и CI.

Если команда уже настроена, откройте терминал и выполните:
`devprojex --help`

Так вы увидите все доступные команды, параметры и примеры.

Примеры:
* `devprojex` — открыть интерактивное терминальное рабочее пространство.
* `devprojex open . --preview` — открыть текущую папку в режиме превью Desktop.
* `devprojex analyze . --format json` — проанализировать текущий проект в формате JSON.
* `devprojex export context . --format markdown -o ../devprojex-context.md` — сохранить контекст для ИИ вне исходного проекта.
* `devprojex export project . --as folder -o ../devprojex-submission` — экспортировать эффективное дерево проекта точно в указанную папку.
* `devprojex export project . --as zip -o ../devprojex-submission.zip` — экспортировать эффективное дерево проекта в ZIP-архив.
* `devprojex analyze . --git-mode tracked --exclude smart-ignore` — проанализировать отслеживаемые Git-файлы со Smart Ignore.

Особенности:
* точка `.` означает текущую папку терминала;
* пути с пробелами нужно брать в кавычки;
* `--git-mode` выбирает отсутствие Git-фильтрации, `.gitignore` или только отслеживаемые Git-файлы;
* `--exclude` управляет обычными исключениями отдельно от Git-фильтрации;
* команды анализа и экспорта детерминированы и не открывают графический интерфейс;
* команда не изменяет файлы проекта — DevProjex работает в режиме чтения.

Если команда `devprojex` не работает, откройте в DevProjex:
«Справка → Запуск из терминала».

## 5) Git
Git‑меню доступно только для проектов, клонированных через DevProjex (Git Clone). Приложение не трогает ваши файлы — работает только с кэшем.

Кэш хранится в системном каталоге кэша пользователя. Фактический путь показывает команда `devprojex doctor`.

* Ветка — показывает список доступных веток с пометкой активной. При переключении дерево обновляется под выбранную ветку. Если ветка уже есть локально, переключение без сети (без обновления). Если локальной ветки нет — выполняется fetch и создаётся локальная ветка.
* Получить обновления — обновляет только текущую ветку: выполняется fetch и сброс к origin/<ветка>. Для проекта Git Clone клавиша F5 выполняет это же действие; обычный пункт «Файл → Обновить» недоступен.

### Окно клонирования
В окне Git Clone под полем URL может показываться список «Недавние репозитории».

Правила:
* список появляется только если в истории уже есть недавно клонированные репозитории;
* в список попадают только URL репозиториев;
* локальные папки в этот список не добавляются;
* дубликаты не создаются — повторное клонирование того же репозитория поднимает его вверх списка;
* хранится до 16 последних репозиториев;
* история сохраняется между запусками приложения.

Если выбрать пункт из списка, URL автоматически подставляется в поле ввода.
Во время активного клонирования список временно скрывается.

## 6) Копирование
### Переключатель формата дерева (ASCII / JSON / XML / MD)
Переключатель задаёт формат представления дерева для операций, где дерево участвует в результате.

* ASCII — текстовое дерево с ветками.
* JSON — структурированное дерево в JSON.
* XML — компактное XML-дерево для парсеров и инструментов.
* MD — Markdown-список для документации и AI-промптов.

Переключатель влияет на:
* Скопировать дерево
* Скопировать дерево + содержимое
* Экспорт дерева
* Экспорт дерева и содержимого

Переключатель не влияет на:
* Скопировать содержимое
* Экспорт содержимого

### Скопировать дерево
Копирует дерево проекта.
Если есть отмеченные узлы — дерево строится по выделению; если выделение пустое или невалидное — копируется полное дерево.
Формат результата определяется переключателем формата дерева.
Горячие клавиши: Ctrl+Shift+C и Ctrl+Alt+C.

### Скопировать содержимое
Копирует содержимое файлов:
* если есть отмеченные файлы — берутся только они; иначе — все файлы проекта;
* нетекстовые файлы игнорируются (включая бинарные);
* для пустых текстовых файлов выводится путь и строка `[No Content, 0 bytes]`;
* для файлов, состоящих только из пробелов/переводов строк, выводится путь и строка `[Whitespace, N bytes]`.
Горячая клавиша: Ctrl+Alt+V.

### Скопировать дерево + содержимое
Комбинирует дерево и содержимое:
* дерево строится по выделению; если выделение пустое/невалидное — берётся полное дерево;
* содержимое берётся по тем же правилам, что в «Скопировать содержимое»;
* формат блока дерева определяется переключателем формата дерева.
Горячая клавиша: Ctrl+Shift+V.

### Представления дерева
Форматы дерева по-разному представляют одно и то же выбранное дерево проекта.

JSON:
* `rootPath` — абсолютный путь корня, нормализованный через `/`.
* `tree` — содержимое корневой папки.
* JSON-экспорт использует такой формат дерева: массивы содержат файлы, объекты содержат подпапки, `/` содержит файлы текущей папки, а `[]` обозначает пустую папку.

XML:
* корневой узел — `<t r="...">`;
* папки — `<d n="...">`;
* файлы — `<f>File.cs</f>`.

MD:
* начинается с `Root: ...`;
* использует вложенный Markdown-список;
* папки заканчиваются на `/`.

Дерево + содержимое:
* выбранный формат дерева применяется к блоку дерева;
* блок содержимого остаётся текстовым;
* заголовки файлов в блоке содержимого используют относительные пути через `/`;
* при экспорте сохраняется в `.txt`.

## 7) Режим превью
Открывается кнопкой с иконкой глаза в верхней панели или клавишами Ctrl+B.

Боковые кнопки мыши работают как навигация в браузере: «Вперёд» открывает режим превью, «Назад» закрывает его. Повторное нажатие уже активного направления ничего не меняет.

Показывает итоговый результат в отдельной рабочей области рядом с деревом. Сам по себе этот режим ничего не копирует и не экспортирует — это режим просмотра.

По умолчанию открывается рабочая область:
* слева — дерево проекта;
* по центру — остров превью;
* справа — панель параметров, если она была открыта.

Доступные режимы:
* Дерево
* Содержимое
* Дерево и содержимое

Применяются те же правила, что и при копировании и экспорте:
* учитываются отмеченные узлы;
* если выбор пустой, используется полный набор данных;
* действуют текущие игнор-правила и параметры отбора.

Дополнительно:
* файлы в превью разделяются горизонтальными линиями;
* при прокрутке сверху закрепляется путь текущего файла;
* масштаб дерева и превью может жить отдельно.
* в режиме превью можно копировать либо весь текущий результат, либо текущий видимый блок файла без выхода в меню «Копировать».

Кнопки:
* кнопка копирования слева в верхнем острове превью — копирует текущий режим превью:
  * Дерево
  * Содержимое
  * Дерево и содержимое
* X в острове дерева — скрывает дерево и оставляет только остров превью;
* X в верхнем острове превью — закрывает режим превью целиком;
* маленькая кнопка копирования в закреплённой верхней панели файла — копирует текущий видимый блок файла в том виде, как он показан в превью;
* повторное нажатие на иконку глаза или Ctrl+B — тоже закрывает режим превью.

Поиск и фильтр доступны, пока в превью виден остров дерева.
Если дерево скрыто, поиск и фильтр временно недоступны до выхода из режима только превью.

## 8) Вид
### Масштаб
* Ctrl++ / Ctrl+= — увеличить
* Ctrl+- — уменьшить
* Ctrl+0 — сброс
* Ctrl + колесо мыши — плавное изменение масштаба в том острове, над которым находится курсор

Поведение:
* в обычном режиме масштабируется дерево;
* в превью с деревом команды увеличения, уменьшения и сброса из меню применяются к дереву и превью одновременно;
* при Ctrl + колесо дерево и превью масштабируются независимо, в зависимости от положения курсора;
* в режиме только превью масштабируется только остров превью.

Диапазон: 6–28, сброс — 15.

### Компактный режим
Делает интерфейс плотнее: меньше отступы в дереве и настройках.
В режиме превью компактность включается автоматически на время работы preview workspace.

### Анимация раскрытия дерева
Плавно поворачивает стрелку и раскрывает или сворачивает ветвь дерева, сдвигая соседние строки. Включена по умолчанию; при отключении раскрытие происходит мгновенно.

### Шрифт дерева
Шрифт дерева выбирается через «Вид → Шрифт дерева».
Пункт «По умолчанию» возвращает стандартный шрифт дерева.
Выбор шрифта применяется после нажатия «Применить настройки» в панели параметров.

## 9) Поиск по дереву
Открывает панель поиска, подсвечивает совпадения и позволяет навигацию.
* Ctrl+F — показать/скрыть
* Enter — следующий результат
* Shift+Enter — предыдущий
* Esc — закрыть

Поиск автоматически раскрывает только нужные ветки; при очистке запроса дерево сворачивается (кроме корня).
При очень большом количестве совпадений приложение может ограничивать авто-раскрытие и массовую подсветку, чтобы сохранить отзывчивость интерфейса.
При закрытии панели поиска запрос очищается после завершения анимации закрытия.

Ограничения:
* при открытии поиска фильтр закрывается автоматически;
* поиск доступен в превью, пока виден остров дерева;
* если дерево скрыто, поиск временно недоступен.

## 10) Фильтр по имени
Показывает только узлы, соответствующие строке фильтра, и их родителей. Обновление — с задержкой (debounce).
* Ctrl+Shift+N — показать/скрыть фильтр
* Esc — закрыть фильтр

Ограничения:
* при открытии фильтра поиск закрывается автоматически;
* фильтр доступен в превью, пока виден остров дерева;
* если дерево скрыто, фильтр временно недоступен.

## 11) Параметры
Справа доступны:
* Применить настройки
* Исключения
* Типы файлов

Изменения в списках «Исключения» и «Типы файлов» подготавливаются в панели и применяются после нажатия «Применить настройки».

После переключения галочек приложение может в фоне обновлять доступные пункты и их счётчики. Итоговое дерево перестраивается только после нажатия «Применить настройки».

Если отменить обновление доступных параметров кнопкой X в статус-баре, незавершённые изменения не применяются, а панель возвращается к последнему завершённому состоянию.

У каждого списка есть переключатель Все (включить/выключить всё).

Примечание по «Типам файлов»:
* в этом списке отображаются только файлы с расширением;
* файлы без расширения в этот список не добавляются и управляются отдельным пунктом в «Исключения».

Ctrl+P — показать/скрыть панель.

### 11.1 Профили параметров локальных проектов
Для локальных папок DevProjex запоминает последние применённые параметры проекта:
* выбранные типы файлов;
* выбранные правила в разделе «Исключения».

Сохранение выполняется при нажатии «Применить настройки».
При повторном открытии той же локальной папки параметры восстанавливаются автоматически.

Важно:
* профили сохраняются только для локальных проектов;
* для проектов, открытых через Git Clone, профили не сохраняются;
* если часть сохранённых пунктов больше недоступна в текущем проекте, они пропускаются, остальные параметры применяются.
* если после обновления или повторного открытия появляется новый тип файлов или новый пункт в «Исключения», он включается по умолчанию;
* уже известные пункты сохраняют явный выбор пользователя: новые файлы снятого типа не включают этот тип обратно.

## 12) Исключения
Раздел «Исключения» управляет тем, какие файлы и папки исключаются из дерева, содержимого, копирования и экспорта.

Итоговый элемент отображается, только если одновременно выполнены все условия:
* выбран его тип файла, если у файла есть тип;
* элемент не исключён ни одним включённым правилом игнорирования.

Правила игнорирования складываются. Если элемент скрывает хотя бы одно включённое правило, другое правило не может сделать его видимым.

### 12.1 Доступные правила
В зависимости от содержимого проекта могут отображаться:

* Умный игнор
* Использовать .gitignore
* Только отслеживаемые Git-файлы
* Пустые папки
* Пустые файлы
* Скрытые папки
* Скрытые файлы
* Папки с точкой в начале
* Файлы с точкой в начале
* Файлы без расширений

Внутри Git-репозитория пункты «Использовать .gitignore» и «Только отслеживаемые Git-файлы» остаются видимой парой галочек. Включение одной снимает другую. Повторный клик по активной галочке снимает её и оставляет оба Git-фильтра выключенными, не меняя Умный игнор и базовые исключения. Остальные пункты показываются, когда соответствующее правило может изменить текущее дерево. Поэтому состав списка может меняться после переключения других правил или типов файлов.

Новый пункт при первом появлении включается по умолчанию. Уже известный пункт сохраняет сделанный пользователем выбор, даже если временно исчезал из списка.

### 12.2 Умный игнор
«Умный игнор» скрывает зависимости, результаты сборки, кэши и другие служебные артефакты проекта.

DevProjex сначала определяет тип проекта по его структуре и файлам-маркерам, например:

* `.csproj`
* `package.json`
* `pyproject.toml`
* `Cargo.toml`

После этого внутри найденной проектной области применяются правила соответствующего стека. Например, правила .NET не распространяются на соседний Python- или JavaScript-проект.

Одного имени папки не всегда достаточно. Неоднозначные имена вроде `build`, `vendor`, `packages`, `cache`, `pkg` или `Library` дополнительно проверяются по содержимому. Это не позволяет скрыть обычную пользовательскую папку только из-за похожего имени.

Некоторые хранилища зависимостей и служебные каталоги могут распознаваться по характерной внутренней структуре даже вне явно найденного проекта.

Поиск новых проектных областей ограничен, чтобы загрузка большой пользовательской папки не превращалась в полный повторный анализ каждого каталога. В обычной структуре используется неглубокий поиск, а в распознанном monorepo — более глубокий. После обнаружения области Smart Ignore применяется ко всему её поддереву без ограничения глубины.

### 12.3 Скрывать секреты
«Скрывать секреты» по умолчанию выключено. Опция проверяет только выбранный текст и заменяет каждое обнаруженное значение на месте, сохраняя файл и окружающий код. Пока опция выключена, проверка не выполняется и счётчик не показывается. После проверки текущего выбора рядом с опцией появляется число значений, которые остаются скрытыми.

Скрытые фрагменты выделяются в превью. Нажмите на фрагмент, чтобы оставить без изменений только это вхождение. В Terminal Workspace клавиши `[` и `]` переходят между вхождениями, а `Enter` или `Space` переключают активное. Решение действует для превью, буфера обмена, экспорта контекста, папки и ZIP до закрытия приложения; в профиль проекта оно не записывается.

В копии проекта совпавший текст тоже меняется, поэтому такая папка или ZIP может не собираться и не запускаться. Двоичные файлы не проверяются и копируются без изменений. Текстовый файл больше 16 МиБ или ошибка детектора останавливают операцию: непроверенный текст не экспортируется молча.

Счётчик сообщает только о совпадениях с правилами. Ноль не означает, что проект безопасен. В CLI используется `--hide-secrets`; подробности и ограничения описаны в `Docs/HideSecrets.md`.

### 12.4 Скрывать приватные данные
«Скрывать приватные данные» по умолчанию выключено. Опция находит в выбранных текстовых файлах адреса электронной почты, глобальные IP-адреса, локальные имена пользователей в путях, MAC-адреса и международные телефонные номера. Для находок действуют те же решения в превью и тот же конвейер вывода, что и для секретов.

Документационные диапазоны и хосты, распространённые имена CI-пользователей, известные публичные DNS-резолверы и задокументированные вымышленные номера остаются видимыми. Ноль совпадений не гарантирует конфиденциальность. В CLI используется `--hide-private-data`; полный список правил и границы первой фазы описаны в `Docs/HidePrivateData.md`.

### 12.5 Использовать .gitignore
При включённом пункте DevProjex применяет все достижимые файлы `.gitignore`, а не только файл в корне открытой папки.

Каждый `.gitignore` действует:

* на папку, в которой он находится;
* на все её доступные вложенные папки;
* только внутри этой области.

Правила вложенного `.gitignore` не влияют на родительские или соседние папки.

Для конкретного пути правила обрабатываются от родительского `.gitignore` к более глубокому. Внутри одного файла они обрабатываются сверху вниз. Последнее подходящее правило определяет Git-результат.

Правило с `!` отменяет более раннее Git-исключение только в своей области. Оно не может вернуть файл, если его родительская папка остаётся исключённой. `.gitignore`, находящийся внутри полностью исключённой и недостижимой папки, не участвует в обработке.

Повреждённая или неподдерживаемая строка пропускается отдельно. Остальные корректные правила этого файла и правила соседних областей продолжают работать.

Пункт относится только к обычным файлам `.gitignore` в рабочем дереве. Правила исключения из `.git/info/exclude` и глобальные правила исключения Git не применяются; эффективные настройки репозитория для сравнения путей, включая `core.ignoreCase` и на macOS `core.precomposeUnicode`, учитываются. Символическая ссылка с именем `.gitignore` не читается — это соответствует поведению Git для управляющего файла. Если обычный `.gitignore` прочитать нельзя, область его каталога безопасно исключается целиком, а сканирование сообщает о частично недоступных данных вместо молчаливого включения файлов без полной обработки правил. Когда для области репозитория, которой принадлежит путь, доступен читаемый индекс Git, отслеживаемые файлы остаются видимыми даже при совпадении с `.gitignore`; без этого индекса или Git CLI данная область безопасно возвращается к обработке только по шаблонам.

Встроенный профиль `standard` выбирает `gitignore` и все восемь групп исключений: `smart-ignore`, `hidden-folders`, `hidden-files`, `dot-folders`, `dot-files`, `empty-folders`, `empty-files` и `extensionless-files`.

### 12.6 Только отслеживаемые Git-файлы
Пункт «Только отслеживаемые Git-файлы» формирует Git-этап дерева из существующих файлов рабочего дерева, записанных в каждом читаемом индексе Git. Изменённые отслеживаемые файлы и новые файлы, добавленные в индекс, остаются включёнными; неотслеживаемые файлы исключаются. Это состояние текущего рабочего дерева, а не исторический снимок `HEAD` или удалённого репозитория.

Каждый достижимый вложенный репозиторий и каждый достижимый worktree обрабатываются независимо на любом доступном уровне вложенности. Дочерний репозиторий не наследует отслеживаемые пути родительского или соседнего репозитория. Для этого режима нужен Git CLI; читаемый пустой индекс допустим. Если терминальное рабочее пространство (TUI) запускается в этом режиме и ни один подходящий индекс загрузить нельзя, рабочее пространство не открывается. Если режим выбирается интерактивно в уже открытом TUI и ни один подходящий индекс загрузить нельзя, изменение отклоняется, а последний работоспособный Git-режим сохраняется. В той же ситуации прямые команды завершаются ошибкой политики или проверки. DevProjex никогда молча не переключается на `.gitignore`. Когда читается другой подходящий индекс, недоступные вложенные области исключаются с предупреждением.

В уже открытом рабочем пространстве Desktop явный выбор остаётся видимым и работает fail-closed: при ошибке готовности вывод и экспорт блокируются, а при частичной готовности операция продолжается с локализованным предупреждением.

Пункты «Использовать .gitignore» и «Только отслеживаемые Git-файлы» взаимно исключаются при включении. Активную галочку можно снять, чтобы полностью отключить Git-фильтрацию. Для локальных проектов это состояние сохраняется вместе с типами файлов и остальными настройками исключения.

### 12.7 Связь Git-фильтрации и Умного игнора
Git-галочки и Умный игнор управляются независимо. Сначала на каждом достижимом Git-уровне применяется выбранный Git-режим, затем Умный игнор обрабатывает оставшиеся элементы, после него действуют базовые правила.

Умный игнор может быть скрыт, пока выбранный Git-режим уже покрывает всех его кандидатов, и появиться после смены или отключения Git-режима. Внутри Git-репозитория обе Git-галочки остаются доступными.

Git-отрицание `!` отменяет только результат Git-правил. Оно не отключает Умный игнор или базовые правила.

### 12.8 Базовые правила
«Папки с точкой в начале» и «Файлы с точкой в начале» проверяют имя элемента.

«Скрытые папки» и «Скрытые файлы» проверяют системный атрибут скрытого элемента. На некоторых платформах имя с точкой и системный атрибут могут описывать один и тот же элемент, а могут отличаться.

«Пустые файлы» скрывает файлы размером 0 байт.

«Файлы без расширений» скрывает файлы вроде `Dockerfile`, `Makefile` и `README`.

«Пустые папки» скрывает логически пустые папки. Папка считается логически пустой, если после применения выбранных типов файлов и всех остальных правил в ней не осталось видимых файлов или подпапок.

Поэтому количество пустых папок может измениться после переключения другого правила: скрытие файлов способно сделать содержащие их папки логически пустыми.

### 12.9 Счётчики
Счётчик рядом с правилом показывает его прямой вклад при текущем сочетании настроек, а не физическое количество похожих элементов на диске.

Один элемент не учитывается одновременно в нескольких пересекающихся счетчиках. Например, папка `.git` может одновременно иметь точку в имени и системный атрибут Hidden, но её исключение будет отнесено только к одному правилу.

Для определения владельца исключения используется стабильный порядок:

* для папок: `.gitignore`, Умный игнор, точка в имени, системный атрибут Hidden;
* для файлов: `.gitignore`, Умный игнор, точка в имени, отсутствие расширения, пустой файл, системный атрибут Hidden.

Этот порядок влияет только на счетчики. На итоговую видимость действует более простое правило: элемент скрыт, если его исключает хотя бы один включённый механизм.

### 12.10 Применение изменений
Переключение галочек сначала обновляет доступные параметры и счетчики в панели. Итоговое дерево перестраивается после нажатия «Применить настройки».

Если подготовка параметров отменена, DevProjex возвращает панель к последнему полностью завершённому состоянию. Частично рассчитанные правила не применяются.

## 13) Как строится дерево и подсчёт данных
На результат влияют:
* выбранные типы файлов
* правила игнорирования
* активный фильтр
* отмеченные чекбоксами узлы (для операций по выделению)

Если нет разрешения на доступ к папке, узел помечается как Доступ запрещён.

### 13.1 Что показывают счётчики в статус-баре
В статус-баре есть два блока:
* Дерево — метрики текстового представления дерева;
* Содержимое — метрики блока содержимого файлов.

Формат:
* Строки
* Символы
* ~Токены (приблизительная оценка)

Для крупных значений используется сокращение (K/M).

Важно:
* «Строки» в блоке «Дерево» — это количество строк итогового представления дерева, а не количество файлов на диске;
* в это число входят и папки, и файлы, и служебные элементы дерева (например, узлы с пометкой доступа).

### 13.2 Как считаются метрики
Метрики дерева:
* считаются по фактическому тексту дерева, который формируется тем же экспортным пайплайном;
* учитывают текущий формат дерева.

Метрики содержимого:
* считаются по тем же правилам, что и экспорт/копирование содержимого;
* бинарные файлы не включаются;
* пустые и whitespace-only файлы учитываются через служебные маркеры (`[No Content, 0 bytes]`, `[Whitespace, N bytes]`).

### 13.3 Когда счётчики обновляются
Пересчёт выполняется:
* после открытия/обновления проекта;
* после применения настроек (исключения и типы файлов);
* при изменении чекбоксов в дереве (с debounce);
* при переключении формата дерева (для операций, где участвует дерево).
* при отмене фонового подсчёта значения счётчиков устанавливаются в 0 до следующего завершённого пересчёта.

## 14) Иконки
Иконка выбирается по:
1) типу узла (папка/файл)
2) точному имени (если есть правило)
3) расширению
4) иначе — неизвестный

## 15) Тема и эффекты
Раздел «Тема» позволяет выбрать режим «Системная», «Светлая» или «Тёмная» и один из эффектов фона:
* Прозрачность
* Blur
* Mica

По умолчанию выбрана «Системная»: она следует за изменениями темы операционной системы. После первого запуска или сброса настроек светлая системная тема включается с обычным непрозрачным фоном, а тёмная — с Blur. Если тему системы определить невозможно, DevProjex использует тёмную тему с Blur. Светлая и тёмная темы запоминают выбранные эффекты независимо. Явный выбор «Светлая» или «Тёмная» игнорирует изменения системы, пока снова не будет выбрана «Системная».

Эффекты взаимоисключающие. Повторное нажатие на выбранный эффект отключает его и возвращает обычный непрозрачный фон.

Доступные параметры:
* Прозрачность фона — доступна для режимов «Прозрачность» и Blur.
* Контраст верхней панели — регулирует фон главной панели с командами превью, поиска, фильтра и формата дерева.
* Прозрачность меню — одинаково применяется к основному меню и его подменю.
* Видимость границ — регулирует выраженность границ элементов интерфейса.

Mica использует системный материал платформы и не имеет отдельной настройки прозрачности фона. Если выбранный Blur или Mica недоступен, приложение сначала пробует другой системный эффект. Обычный непрозрачный фон используется только тогда, когда недоступны и Blur, и Mica.

В режиме «Прозрачность» прозрачным остаётся фон главного окна. Меню, подменю и другие всплывающие поверхности используют Blur, если он поддерживается, чтобы элементы дерева и содержимого не мешали чтению.

## 16) Справка

### 16.1 Обновления
«Справка → Обновления» сравнивает текущую версию с последним стабильным релизом на GitHub. Автоматическая проверка отключена по умолчанию; если её включить, DevProjex проверяет обновления при запуске, когда с предыдущей успешной проверки прошло не менее семи дней. Изменение галочки применяется сразу. Последний успешный результат сохраняется между запусками приложения и не стирается при последующей ошибке сети. Установка выполняется только пользователем.

### 16.2 Сброс настроек
Сброс настроек (Справка → Сбросить настройки) возвращает к значениям по умолчанию тему, эффекты, компактный режим, анимацию раскрытия дерева и язык интерфейса. Профили проектов, история и файлы на диске не изменяются.

### 16.3 Сброс данных
Сброс данных (Справка → Сбросить данные) удаляет сохранённые профили параметров локальных проектов:
* выбранные типы файлов;
* выбранные правила в разделе «Исключения».

Важно:
* история «Недавние» для локальных папок не очищается;
* история «Недавние репозитории» в окне Git Clone не очищается;
* файлы и папки проектов на диске не изменяются и не удаляются.

## 17) Языки
Выбор языка выполняется через меню Язык.
Выбранный язык сохраняется между запусками приложения. «Справка → Сброс настроек» очищает сохраненный выбор языка и возвращает язык к значению по умолчанию.

## 18) Прогресс-бар и отмена
В центральной части статус-бара показывается текущая операция и прогресс.

Режимы прогресса:
* Indeterminate — без процента (операция неопределённой длительности).
* Determinate — с процентом (0–100).

Поведение:
* во время фонового подсчёта данных показывается процентный прогресс;
* для части Git-операций процент отображается, если источник прогресса передаёт значение в процентах;
* обновление доступных параметров и применение настроек показываются, если операция занимает заметное время;
* быстрые операции завершаются без показа прогресса.

Кнопка X (отмена) в статус-баре:
* выполняет best-effort отмену операций, у которых есть поддержка отмены;
* останавливает фоновый подсчёт данных;
* при отмене обновления доступных параметров возвращает панель к последнему завершённому состоянию;
* для операций без поддержки отмены завершает индикацию в статус-баре, при этом сама операция может завершиться в фоне.

## 19) Примечания
* При нехватке прав приложение может предложить перезапуск с повышенными правами; при отказе покажет уведомление.
