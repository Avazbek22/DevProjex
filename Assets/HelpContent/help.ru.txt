## 1) Что это и для чего
DevProjex быстро формирует контекст проекта: показывает структуру папок/файлов, позволяет выбрать элементы галочками и скопировать дерево и/или содержимое файлов в буфер обмена. Удобно для code review, поддержки, обучения и передачи структуры проекта AI-ассистенту.

Важно: приложение работает только в режиме чтения и не изменяет файлы.

## 2) Дерево проекта
* Иконки типов файлов/папок.
* Чекбоксы на узлах.
* Раскрытие/сворачивание.

Чекбоксы: отметка узла применяется к потомкам; состояние родителей пересчитывается автоматически.

Горячие клавиши:
* Ctrl+E — раскрыть всё
* Ctrl+W — свернуть всё (корень остаётся раскрытым)

## 3) Файл
* Открыть папку… — открыть корневую папку (Ctrl+O)
* Новое окно — открыть новый независимый экземпляр DevProjex
* Недавние — список недавно открытых локальных папок
* Обновить — перечитать локальную папку и перестроить дерево (F5)
* Экспорт в файл:
  * Экспорт дерева
  * Экспорт содержимого
  * Экспорт дерева и содержимого

Правила формата:
* Экспорт дерева:
  * ASCII → только `.txt`.
  * JSON → по умолчанию `.json`, при сохранении доступны `.json` и `.txt`.
  * XML → по умолчанию `.xml`, при сохранении доступны `.xml` и `.txt`.
  * MD → по умолчанию `.md`, при сохранении доступны `.md` и `.txt`.
* Экспорт содержимого — всегда текстовый формат содержимого, файл `.txt` (переключатель формата дерева не влияет).
* Экспорт дерева и содержимого — всегда файл `.txt`; выбранный формат дерева влияет только на формат блока дерева внутри результата.

Файлы экспорта записываются в UTF-8 без BOM.

### Drag & Drop
Перетаскивание работает через стартовую область (Drop Zone), когда проект не загружен.

Правила:
* можно перетаскивать папку;
* можно перетаскивать файл — в этом случае открывается папка, в которой находится файл;
* если перетащено несколько объектов, используется первый подходящий локальный путь;
* если путь недоступен или не существует, применяется та же проверка доступа, что и при «Открыть папку…»;
* неподдерживаемые или нелокальные объекты игнорируются.

### Недавние
Пункт «Файл → Недавние» показывает историю недавно открытых локальных папок.

Правила:
* в список попадают только локальные папки;
* Git-репозитории, клонированные через DevProjex, в этот список не добавляются;
* дубликаты не создаются — повторное открытие той же папки поднимает её вверх списка;
* хранится до 15 последних папок;
* история сохраняется между запусками приложения.

Для каждого пункта показываются имя родительской папки и имя проекта, например `Projects / App`.

## 4) Запуск из терминала
DevProjex можно запускать из терминала.

Если команда уже настроена, откройте терминал и выполните:
`devprojex --help`

Так вы увидите все доступные команды, параметры и примеры.

Примеры:
* `devprojex .` — открыть текущую папку.
* `devprojex "C:\Projects\App"` — открыть указанную папку.
* `devprojex . --export tree` — вывести дерево проекта в терминал.
* `devprojex . --export content` — вывести содержимое файлов в терминал.
* `devprojex . --export tree-content` — вывести дерево и содержимое в терминал.
* `devprojex . --export tree-content -o context.txt` — сохранить результат в файл.
* `devprojex --benchmark "C:\Projects\App"` — измерить стандартный сценарий отчёта по проекту.
* `devprojex --last --preview` — открыть последний проект сразу в режиме превью.
* `devprojex --benchmark-ui "C:\Projects\App"` — измерить стандартный UI-сценарий.
* `devprojex --session-metrics "C:\Projects\App"` — записывать метрики UI-сессии до закрытия окна.

Особенности:
* точка `.` означает текущую папку терминала;
* пути с пробелами нужно брать в кавычки;
* если не указан файл вывода, результат печатается прямо в терминал;
* команда не изменяет файлы проекта — DevProjex работает в режиме чтения.

Если команда `devprojex` не работает, откройте в DevProjex:
«Справка → Запуск из терминала».

## 5) Git
Git‑меню доступно только для проектов, клонированных через DevProjex (Git Clone). Приложение не трогает ваши файлы — работает только с кэшем.

Кэш хранится в системной временной папке. На Windows это обычно:
`%TEMP%\DevProjex\RepoCache`

* Ветка — показывает список доступных веток с пометкой активной. При переключении дерево обновляется под выбранную ветку. Если ветка уже есть локально, переключение без сети (без обновления). Если локальной ветки нет — выполняется fetch и создаётся локальная ветка.
* Получить обновления — обновляет только текущую ветку: выполняется fetch и сброс к origin/<ветка>. Для проекта Git Clone клавиша F5 выполняет это же действие; обычный пункт «Файл → Обновить» недоступен.

### Окно клонирования
В окне Git Clone под полем URL может показываться список «Недавние репозитории».

Правила:
* список появляется только если в истории уже есть недавно клонированные репозитории;
* в список попадают только URL репозиториев;
* локальные папки в этот список не добавляются;
* дубликаты не создаются — повторное клонирование того же репозитория поднимает его вверх списка;
* хранится до 7 последних репозиториев;
* история сохраняется между запусками приложения.

Если выбрать пункт из списка, URL автоматически подставляется в поле ввода.
Во время активного клонирования список временно скрывается.

## 6) Копирование
### Переключатель формата дерева (ASCII / JSON / XML / MD)
Переключатель задаёт формат представления дерева для операций, где дерево участвует в результате.

* ASCII — текстовое дерево с ветками.
* JSON — структурированное дерево в JSON.
* XML — компактное XML-дерево для парсеров и инструментов.
* MD — Markdown-список для документации и AI-промптов.

Переключатель влияет на:
* Скопировать дерево
* Скопировать дерево + содержимое
* Экспорт дерева
* Экспорт дерева и содержимого

Переключатель не влияет на:
* Скопировать содержимое
* Экспорт содержимого

### Скопировать дерево
Копирует дерево проекта.
Если есть отмеченные узлы — дерево строится по выделению; если выделение пустое или невалидное — копируется полное дерево.
Формат результата определяется переключателем формата дерева.
Горячие клавиши: Ctrl+Shift+C и Ctrl+Alt+C.

### Скопировать содержимое
Копирует содержимое файлов:
* если есть отмеченные файлы — берутся только они; иначе — все файлы проекта;
* нетекстовые файлы игнорируются (включая бинарные);
* для пустых текстовых файлов выводится путь и строка `[No Content, 0 bytes]`;
* для файлов, состоящих только из пробелов/переводов строк, выводится путь и строка `[Whitespace, N bytes]`.
Горячая клавиша: Ctrl+Alt+V.

### Скопировать дерево + содержимое
Комбинирует дерево и содержимое:
* дерево строится по выделению; если выделение пустое/невалидное — берётся полное дерево;
* содержимое берётся по тем же правилам, что в «Скопировать содержимое»;
* формат блока дерева определяется переключателем формата дерева.
Горячая клавиша: Ctrl+Shift+V.

### Представления дерева
Форматы дерева по-разному представляют одно и то же выбранное дерево проекта.

JSON:
* `rootPath` — абсолютный путь корня, нормализованный через `/`.
* `tree` — содержимое корневой папки.
* JSON-экспорт использует такой формат дерева: массивы содержат файлы, объекты содержат подпапки, `/` содержит файлы текущей папки, а `[]` обозначает пустую папку.

XML:
* корневой узел — `<t r="...">`;
* папки — `<d n="...">`;
* файлы — `<f>File.cs</f>`.

MD:
* начинается с `Root: ...`;
* использует вложенный Markdown-список;
* папки заканчиваются на `/`.

Дерево + содержимое:
* выбранный формат дерева применяется к блоку дерева;
* блок содержимого остаётся текстовым;
* заголовки файлов в блоке содержимого используют относительные пути через `/`;
* при экспорте сохраняется в `.txt`.

## 7) Режим превью
Открывается кнопкой с иконкой глаза в верхней панели или клавишами Ctrl+B.

Показывает итоговый результат в отдельной рабочей области рядом с деревом. Сам по себе этот режим ничего не копирует и не экспортирует — это режим просмотра.

По умолчанию открывается рабочая область:
* слева — дерево проекта;
* по центру — остров превью;
* справа — панель параметров, если она была открыта.

Доступные режимы:
* Дерево
* Содержимое
* Дерево и содержимое

Применяются те же правила, что и при копировании и экспорте:
* учитываются отмеченные узлы;
* если выбор пустой, используется полный набор данных;
* действуют текущие игнор-правила и параметры отбора.

Дополнительно:
* файлы в превью разделяются горизонтальными линиями;
* при прокрутке сверху закрепляется путь текущего файла;
* масштаб дерева и превью может жить отдельно.
* в режиме превью можно копировать либо весь текущий результат, либо текущий видимый блок файла без выхода в меню «Копировать».

Кнопки:
* кнопка копирования слева в верхнем острове превью — копирует текущий режим превью:
  * Дерево
  * Содержимое
  * Дерево и содержимое
* X в острове дерева — скрывает дерево и оставляет только остров превью;
* X в верхнем острове превью — закрывает режим превью целиком;
* маленькая кнопка копирования в закреплённой верхней панели файла — копирует текущий видимый блок файла в том виде, как он показан в превью;
* повторное нажатие на иконку глаза или Ctrl+B — тоже закрывает режим превью.

Поиск и фильтр доступны, пока в превью виден остров дерева.
Если дерево скрыто, поиск и фильтр временно недоступны до выхода из режима только превью.

## 8) Вид
### Масштаб
* Ctrl++ / Ctrl+= — увеличить
* Ctrl+- — уменьшить
* Ctrl+0 — сброс
* Ctrl + колесо мыши — плавное изменение масштаба в том острове, над которым находится курсор

Поведение:
* в обычном режиме масштабируется дерево;
* в превью с деревом команды увеличения, уменьшения и сброса из меню применяются к дереву и превью одновременно;
* при Ctrl + колесо дерево и превью масштабируются независимо, в зависимости от положения курсора;
* в режиме только превью масштабируется только остров превью.

Диапазон: 6–28, сброс — 15.

### Компактный режим
Делает интерфейс плотнее: меньше отступы в дереве и настройках.
В режиме превью компактность включается автоматически на время работы preview workspace.

### Анимация дерева
Включает плавную анимацию смещения строк при наведении на элементы дерева.

### Шрифт дерева
Шрифт дерева выбирается через «Вид → Шрифт дерева».
Пункт «По умолчанию» возвращает стандартный шрифт дерева.
Выбор шрифта применяется после нажатия «Применить настройки» в панели параметров.

## 9) Поиск по дереву
Открывает панель поиска, подсвечивает совпадения и позволяет навигацию.
* Ctrl+F — показать/скрыть
* Enter — следующий результат
* Shift+Enter — предыдущий
* Esc — закрыть

Поиск автоматически раскрывает только нужные ветки; при очистке запроса дерево сворачивается (кроме корня).
При очень большом количестве совпадений приложение может ограничивать авто-раскрытие и массовую подсветку, чтобы сохранить отзывчивость интерфейса.
При закрытии панели поиска запрос очищается после завершения анимации закрытия.

Ограничения:
* при открытии поиска фильтр закрывается автоматически;
* поиск доступен в превью, пока виден остров дерева;
* если дерево скрыто, поиск временно недоступен.

## 10) Фильтр по имени
Показывает только узлы, соответствующие строке фильтра, и их родителей. Обновление — с задержкой (debounce).
* Ctrl+Shift+N — показать/скрыть фильтр
* Esc — закрыть фильтр

Ограничения:
* при открытии фильтра поиск закрывается автоматически;
* фильтр доступен в превью, пока виден остров дерева;
* если дерево скрыто, фильтр временно недоступен.

## 11) Параметры
Справа доступны:
* Применить настройки
* Игнорировать
* Типы файлов
* Папки верхнего уровня

Изменения в списках «Игнорировать», «Типы файлов» и «Папки верхнего уровня» подготавливаются в панели и применяются после нажатия «Применить настройки».

После переключения галочек приложение может в фоне обновлять доступные пункты и их счётчики. Итоговое дерево перестраивается только после нажатия «Применить настройки».

Если отменить обновление доступных параметров кнопкой X в статус-баре, незавершённые изменения не применяются, а панель возвращается к последнему завершённому состоянию.

У каждого списка есть переключатель Все (включить/выключить всё).

Примечание по «Типам файлов»:
* в этом списке отображаются только файлы с расширением;
* файлы без расширения в этот список не добавляются и управляются отдельным пунктом в «Игнорировать».

Ctrl+P — показать/скрыть панель.

### 11.1 Профили параметров локальных проектов
Для локальных папок DevProjex запоминает последние применённые параметры проекта:
* выбранные папки верхнего уровня;
* выбранные типы файлов;
* выбранные правила в блоке «Игнорировать».

Сохранение выполняется при нажатии «Применить настройки».
При повторном открытии той же локальной папки параметры восстанавливаются автоматически.

Важно:
* профили сохраняются только для локальных проектов;
* для проектов, открытых через Git Clone, профили не сохраняются;
* если часть сохранённых пунктов больше недоступна в текущем проекте, они пропускаются, остальные параметры применяются.
* если после обновления или повторного открытия появляется новая папка верхнего уровня, новый тип файлов или новый пункт в «Игнорировать», он включается по умолчанию;
* уже известные пункты сохраняют явный выбор пользователя: новые файлы снятого типа не включают этот тип обратно.

## 12) Игнорирование
Список «Игнорировать» формируется автоматически по текущему пути и выбранным папкам верхнего уровня.

Порядок пунктов:
* Умный игнор (если применим)
* Использовать .gitignore (если применим)
* Пустые папки
* Пустые файлы
* Скрытые папки
* Скрытые файлы
* Папки с точкой в начале
* Файлы с точкой в начале
* Файлы без расширений

Состав списка зависит от текущего дерева и активных правил. Базовый пункт показывается только тогда, когда может изменить результат. Если подходящие элементы уже скрыты другим правилом, пункт может временно исчезнуть и снова появиться после изменения настроек.

Пункты `.gitignore` и «Умный игнор» также учитывают реальное влияние на дерево. Явно выключенный пункт может оставаться видимым, чтобы пользователь мог включить его обратно.

Новый пункт включается по умолчанию при первом появлении. Уже известный пункт сохраняет явный выбор пользователя, даже если временно исчезал из списка.

Линия под «Использовать .gitignore» отделяет Git/Smart-правила от базовых правил видимости.

### 12.1 Область применения правил
Приложение строит проектные области (scope), в которых применяются правила игнорирования:
* корень (если в корне есть `.gitignore` или маркер проекта)
* папки первого уровня
* вложенные проектные подпапки

Поиск вложенных проектных областей ограничен и зависит от структуры папки.
Для обычных проектов используется неглубокий поиск. В распознанных monorepo поиск может выполняться глубже.
Служебные папки, зависимости и подтверждённые артефакты сборки при поиске областей пропускаются.

Это ограничение относится только к обнаружению вложенных областей для `.gitignore` и Smart Ignore. Когда область найдена, правила применяются к её содержимому обычным обходом дерева.

### 12.2 Что делает «Использовать .gitignore»
* Включено: применяются правила `.gitignore` в найденных областях.
* Выключено: правила `.gitignore` полностью отключаются.

Для папки с несколькими проектами `.gitignore` одного проекта не применяется к соседним проектам вне его области.

### 12.3 Как работает «Умный игнор»
Smart Ignore скрывает типичные артефакты сборки, кэши инструментов и хранилища зависимостей. Он использует два дополняющих друг друга подхода:

1. Правила проекта. По файлам-маркерам, например `.csproj`, `package.json`, `pyproject.toml` или `Cargo.toml`, определяется тип проекта. После этого внутри его области применяются правила для соответствующего стека.
2. Проверка артефактов. Для неоднозначных имён вроде `build`, `vendor`, `packages`, `cache`, `pkg` или `Library` одного имени недостаточно. Содержимое папки должно подтверждать, что это результат сборки, кэш или хранилище зависимостей.

В распознанном проекте стандартная папка артефактов определяется по сочетанию типа проекта и имени. Вне такого контекста Smart Ignore действует консервативно и не скрывает обычную папку только из-за похожего имени.

Некоторые подтверждённые универсальные артефакты могут быть скрыты и вне формальной области проекта. Это позволяет корректно обрабатывать смешанные рабочие папки, не распространяя правила одного проекта на соседние исходники.

Если «Умный игнор» выключен, оба подхода отключаются.

### 12.4 Базовые правила
Пункты:
* Скрытые папки
* Скрытые файлы
* Папки с точкой в начале
* Файлы с точкой в начале
* Пустые папки
* Пустые файлы
* Файлы без расширений

При включении пункт скрывает соответствующие элементы из дерева и из результатов копирования/экспорта.
Базовые правила включаются отдельно от `.gitignore` и Smart Ignore, но итоговый результат всегда считается по текущему дереву после применения всех активных фильтров.

### 12.5 Как сочетаются `.gitignore` и Smart Ignore
1. Один проект с одной областью и `.gitignore`.
Обычно показывается только «Использовать .gitignore». Этот переключатель управляет общей политикой игнорирования проекта: при включении работают `.gitignore` и подходящие Smart-правила, при выключении отключаются оба механизма.

2. Один проект без `.gitignore`.
Показывается «Умный игнор», если он может повлиять на дерево.

3. Рабочая папка с несколькими проектами.
`.gitignore` применяется только в областях, где он найден. «Умный игнор» может отображаться отдельно и дополнять правила в остальных применимых областях. Переключатели в этом случае работают независимо.

4. Папка без применимых правил.
Если `.gitignore` и Smart Ignore не влияют на результат, эти пункты не показываются. В списке остаются только подходящие базовые правила.

### 12.6 Пустые папки
Скрывает логически пустые папки из дерева и результатов копирования/экспорта.
Логически пустая папка — это папка, в которой после применения текущих правил видимости, `.gitignore`, Smart Ignore и выбранных типов файлов не остаётся видимых потомков.
Если сама папка не скрыта другими правилами, её удаление из дерева контролируется именно этим пунктом.

### 12.7 Пустые файлы
Скрывает пустые файлы размером 0 байт из дерева и результатов копирования/экспорта.

### 12.8 Файлы без расширений
Скрывает файлы без расширений (например: `Dockerfile`, `Makefile`, `README`) из дерева и результатов копирования/экспорта.

### 12.9 Счетчики в блоке «Игнорировать»
Рядом с доступными базовыми правилами показывается количество элементов в формате `(N)`.

Счётчик показывает прямой вклад конкретного правила при текущем сочетании настроек, а не общее количество похожих элементов на диске. Поэтому значение одного пункта может измениться после переключения другого: один объект не должен одновременно учитываться как результат нескольких пересекающихся правил.

Например, папка `.git` на Windows может одновременно быть папкой с точкой и скрытой папкой. Пока её скрывает правило «Папки с точкой в начале», она не учитывается как отдельный результат правила «Скрытые папки».

## 13) Как строится дерево и подсчёт данных
На результат влияют:
* выбранные папки верхнего уровня
* выбранные типы файлов
* правила игнорирования
* активный фильтр
* отмеченные чекбоксами узлы (для операций по выделению)

Если нет разрешения на доступ к папке, узел помечается как Доступ запрещён.

### 13.1 Что показывают счётчики в статус-баре
В статус-баре есть два блока:
* Дерево — метрики текстового представления дерева;
* Содержимое — метрики блока содержимого файлов.

Формат:
* Строки
* Символы
* ~Токены (приблизительная оценка)

Для крупных значений используется сокращение (K/M).

Важно:
* «Строки» в блоке «Дерево» — это количество строк итогового представления дерева, а не количество файлов на диске;
* в это число входят и папки, и файлы, и служебные элементы дерева (например, узлы с пометкой доступа).

### 13.2 Как считаются метрики
Метрики дерева:
* считаются по фактическому тексту дерева, который формируется тем же экспортным пайплайном;
* учитывают текущий формат дерева.

Метрики содержимого:
* считаются по тем же правилам, что и экспорт/копирование содержимого;
* бинарные файлы не включаются;
* пустые и whitespace-only файлы учитываются через служебные маркеры (`[No Content, 0 bytes]`, `[Whitespace, N bytes]`).

### 13.3 Когда счётчики обновляются
Пересчёт выполняется:
* после открытия/обновления проекта;
* после применения настроек (игнор, типы файлов, папки верхнего уровня);
* при изменении чекбоксов в дереве (с debounce);
* при переключении формата дерева (для операций, где участвует дерево).
* при отмене фонового подсчёта значения счётчиков устанавливаются в 0 до следующего завершённого пересчёта.

## 14) Иконки
Иконка выбирается по:
1) типу узла (папка/файл)
2) точному имени (если есть правило)
3) расширению
4) иначе — неизвестный

## 15) Тема и эффекты
Раздел «Тема» позволяет выбрать светлую или тёмную тему и один из эффектов фона:
* Прозрачность
* Blur
* Mica

Эффекты взаимоисключающие. Повторное нажатие на выбранный эффект отключает его и возвращает обычный непрозрачный фон.

Доступные параметры:
* Прозрачность фона — доступна для режимов «Прозрачность» и Blur.
* Контраст верхней панели — регулирует фон главной панели с командами превью, поиска, фильтра и формата дерева.
* Прозрачность меню — одинаково применяется к основному меню и его подменю.
* Видимость границ — регулирует выраженность границ элементов интерфейса.

Mica использует системный материал платформы и не имеет отдельной настройки прозрачности фона. Если выбранный эффект не поддерживается системой, используется безопасный непрозрачный вариант.

## 16) Справка

### 16.1 Сброс настроек
Сброс настроек (Справка → Сбросить настройки) возвращает к значениям по умолчанию тему, эффекты, компактный режим, анимацию дерева и язык интерфейса. Профили проектов, история и файлы на диске не изменяются.

### 16.2 Сброс данных
Сброс данных (Справка → Сбросить данные) удаляет сохранённые профили параметров локальных проектов:
* выбранные папки верхнего уровня;
* выбранные типы файлов;
* выбранные правила в блоке «Игнорировать».

Важно:
* история «Недавние» для локальных папок не очищается;
* история «Недавние репозитории» в окне Git Clone не очищается;
* файлы и папки проектов на диске не изменяются и не удаляются.

## 17) Языки
Выбор языка выполняется через меню Язык.
Выбранный язык сохраняется между запусками приложения. «Справка → Сброс настроек» очищает сохраненный выбор языка и возвращает язык к значению по умолчанию.

## 18) Прогресс-бар и отмена
В центральной части статус-бара показывается текущая операция и прогресс.

Режимы прогресса:
* Indeterminate — без процента (операция неопределённой длительности).
* Determinate — с процентом (0–100).

Поведение:
* во время фонового подсчёта данных показывается процентный прогресс;
* для части Git-операций процент отображается, если источник прогресса передаёт значение в процентах;
* обновление доступных параметров и применение настроек показываются, если операция занимает заметное время;
* быстрые операции завершаются без показа прогресса.

Кнопка X (отмена) в статус-баре:
* выполняет best-effort отмену операций, у которых есть поддержка отмены;
* останавливает фоновый подсчёт данных;
* при отмене обновления доступных параметров возвращает панель к последнему завершённому состоянию;
* для операций без поддержки отмены завершает индикацию в статус-баре, при этом сама операция может завершиться в фоне.

## 19) Примечания
* По умолчанию применяется тёмная тема с эффектом Blur. Если эффект не поддерживается системой, используется безопасный непрозрачный вариант.
* При нехватке прав приложение может предложить перезапуск с повышенными правами; при отказе покажет уведомление.
