## 1) Qué es y para qué sirve
DevProjex prepara rápidamente el contexto de un proyecto: muestra la estructura de carpetas y archivos, permite seleccionar elementos con casillas y copiar al portapapeles el árbol, el contenido de los archivos o ambos. Resulta útil para revisiones de código, soporte, aprendizaje y para compartir la estructura del proyecto con un asistente de IA.

Importante: DevProjex no modifica los archivos del proyecto que abre. La única excepción es una conexión MCP explícita para Cursor o VS Code, que crea o actualiza `.cursor/mcp.json` o `.vscode/mcp.json` (sección 19.1).

## 2) Árbol del proyecto
* Iconos según el tipo de archivo o carpeta.
* Casillas en los nodos.
* Expandir y contraer.

Casillas: marcar un nodo se aplica a sus hijos; el estado del nodo padre se recalcula automáticamente.

Teclas de acceso rápido:
* {mod}E — expandir todo
* {collapseAll} — contraer todo (la raíz permanece expandida)

### Menú contextual
Haga clic derecho en un nodo o pulse {shift}F10 o la tecla Menú sobre el nodo enfocado:
* Mostrar en el Explorador de archivos / Mostrar en el Finder / Abrir en el gestor de archivos — muestra el elemento en el gestor de archivos del sistema; la etiqueta corresponde a la plataforma actual.
* Copiar ruta completa — la ruta absoluta del elemento.
* Copiar ruta relativa — la ruta desde la raíz del proyecto, empezando por el nombre de la carpeta raíz, por ejemplo `project/src/File.cs`.
* Copiar contenido — para archivos: copia el contenido con las transformaciones de contenido aplicadas, exactamente como lo producen la copia y la exportación.
* Seleccionar solo esto — marca solo este nodo y desmarca el resto; aparece solo mientras otro elemento también está marcado.
* Expandir rama / Contraer rama — para carpetas.

Si la ruta ya no existe en el disco, abrir el elemento en el gestor de archivos o copiar su contenido muestra un mensaje de error; copiar la ruta sigue funcionando.

## 3) Archivo
* Abrir carpeta... — abre la carpeta raíz ({mod}O)
* Nueva ventana — abre una nueva instancia independiente de DevProjex
* Reciente — lista de carpetas locales abiertas recientemente
* Actualizar — vuelve a analizar una carpeta local y reconstruye el árbol (F5)
* Exportar a archivo:
  * Exportar árbol
  * Exportar contenido
  * Exportar árbol y contenido
* Exportar proyecto:
  * A una carpeta…
  * A un archivo ZIP…

«Exportar proyecto» crea una carpeta o un archivo ZIP independiente a partir del árbol actual y conserva la estructura de directorios.

Se respetan los tipos de archivo seleccionados, las reglas de exclusión y los elementos marcados. Si no hay nada marcado, se exporta todo el árbol actual.

Se copian los archivos de texto y los binarios, y se conservan las carpetas vacías incluidas. Los archivos de origen no se modifican. El resultado no puede guardarse dentro del proyecto de origen.

Durante la exportación no se puede cambiar el árbol ni la configuración, usar el filtro, cambiar el formato o el modo de vista previa, ejecutar comandos de Git, actualizar ni abrir otro proyecto.

Reglas de formato:
* Exportar árbol:
  * ASCII -> solo `.txt`.
  * JSON -> `.json` de forma predeterminada; en el cuadro de diálogo Guardar están disponibles `.json` y `.txt`.
  * XML -> `.xml` de forma predeterminada; en el cuadro de diálogo Guardar están disponibles `.xml` y `.txt`.
  * MD -> `.md` de forma predeterminada; en el cuadro de diálogo Guardar están disponibles `.md` y `.txt`.
* Exportar contenido — siempre en formato de contenido de texto, archivo `.txt` (el selector de formato del árbol no se aplica).
* Exportar árbol y contenido — siempre un archivo `.txt`; el formato de árbol seleccionado solo afecta al bloque del árbol dentro del resultado.

Los archivos exportados se escriben en UTF-8 sin BOM.

### Arrastrar y soltar
Arrastrar y soltar funciona en el área de inicio (zona de colocación) cuando no hay ningún proyecto cargado.

Reglas:
* puede soltar una carpeta;
* puede soltar un archivo; en ese caso se abre la carpeta que lo contiene;
* si suelta varios elementos, se usa la primera ruta local adecuada;
* si una ruta no está disponible o no existe, se aplican las mismas comprobaciones de acceso que en «Abrir carpeta...»;
* los elementos no compatibles o no locales se ignoran.

### Reciente
El elemento «Archivo → Reciente» muestra el historial de carpetas locales abiertas recientemente.

Reglas:
* solo se añaden a la lista carpetas locales;
* los repositorios Git clonados con DevProjex no se añaden a esta lista;
* no se crean duplicados: volver a abrir la misma carpeta la mueve al principio;
* se guardan hasta 32 carpetas recientes;
* el historial se conserva entre ejecuciones de la aplicación.

Cada elemento muestra la carpeta principal y el nombre del proyecto, por ejemplo `Projects / App`.

## 4) Iniciar desde la terminal
DevProjex ofrece un espacio de trabajo interactivo en la terminal (Terminal Workspace) y comandos directos para scripts y CI.

Si el comando ya está configurado, abra una terminal y ejecute:
`devprojex --help`

Esto muestra los comandos y las opciones de nivel superior. Ejecute `devprojex help <command>` para ver las opciones y los ejemplos de un comando concreto.

Ejemplos:
* `devprojex` — abre el espacio de trabajo interactivo de la terminal. Dentro de él, las acciones se ejecutan desde la línea de comandos `:` (por ejemplo, `:copy`, `:analyze`, `:branch`, `:language`); la lista completa de comandos está en la ayuda integrada del espacio de trabajo y en la documentación del proyecto.
* `devprojex tui .` — abre la carpeta indicada directamente en el espacio de trabajo de la terminal.
* `devprojex open . --preview` — abre la carpeta actual en la vista previa de Desktop.
* `devprojex analyze . --format json` — analiza el proyecto actual y devuelve JSON.
* `devprojex tree .` — imprime el árbol del proyecto en la terminal.
* `devprojex export context . --format markdown -o ../devprojex-context.md` — guarda un contexto listo para IA fuera del proyecto de origen.
* `devprojex export project . --as folder -o ../devprojex-submission` — exporta el árbol efectivo del proyecto a una carpeta exacta.
* `devprojex export project . --as zip -o ../devprojex-submission.zip` — exporta el árbol efectivo del proyecto a un archivo ZIP.
* `devprojex export context https://github.com/owner/repo -o -` — empaqueta un repositorio remoto sin que tenga que clonarlo usted.
* `devprojex analyze . --git-mode tracked --exclude smart-ignore` — analiza los archivos rastreados por Git con Smart Ignore.
* `devprojex search Configure . --symbols` — encuentra dónde se define una declaración; `--symbols` acepta nombres de declaraciones y rechaza la sintaxis de expresiones regulares, mientras que `--regex` busca texto con una expresión regular.
* `devprojex related src/App.cs` — enumera los archivos que usa un archivo y los archivos que lo usan.
* `devprojex mcp --root .` — inicia el servidor MCP local de solo lectura para que los agentes de IA lean el proyecto de forma segura.
* `devprojex mcp connect . --client claude-code` — conecta un cliente de IA al proyecto (sección 19).
* `devprojex mcp log . --last` — muestra la última sesión del registro del agente.

Notas:
* `.` significa la carpeta actual de la terminal;
* las rutas con espacios deben ir entre comillas;
* `--git-mode` selecciona `none`, `gitignore`, `tracked`, `staged`, `changes` o `diff:<ref>..<ref>`;
* `--exclude` controla las exclusiones normales por separado del filtrado de Git;
* los comandos de análisis y exportación son deterministas y no abren la interfaz gráfica;
* `tui`, `open`, `analyze`, `search`, `tree` y los dos comandos `export` también aceptan la URL de un repositorio Git, y `related` la acepta mediante `--project`; el clon se guarda en una caché gestionada (`devprojex cache`);
* los comandos tienen alias y opciones cortas documentados, por ejemplo `export ctx`, `-f`, `-n`; `devprojex help` los muestra;
* `analyze --findings` enumera los hallazgos de ocultación sin sus valores, y `--fail-on-findings` devuelve un código de salida distinto de cero para CI;
* `export context --max-tokens N` mantiene el contexto dentro de un presupuesto de tokens, y la opción experimental `--rank importance` admite primero los archivos más importantes;
* los comandos de análisis, búsqueda y exportación no modifican los archivos del proyecto: DevProjex funciona en modo de solo lectura.

Si el comando `devprojex` no funciona, abra en DevProjex:
«Ayuda → Iniciar desde la terminal».

## 5) Git
«Git → Clonar repositorio...» clona un repositorio en la caché de DevProjex y lo abre. «Rama» y «Obtener actualizaciones» solo están disponibles para los proyectos clonados de esta forma. La aplicación no toca sus archivos: solo trabaja con la caché.

La caché se guarda en el directorio de caché del sistema del usuario. Ejecute `devprojex doctor` para ver la ruta efectiva.

* Rama — muestra la lista de ramas disponibles con la activa marcada; al cambiar, el árbol se actualiza a la rama seleccionada. Si la rama ya existe localmente, el cambio se hace sin conexión (sin actualizar). Si no existe localmente, se descarga y se crea.
* Obtener actualizaciones — actualiza solo la rama actual: fetch y restablecimiento a origin/<branch>. En un proyecto clonado con Git Clone, F5 hace lo mismo; el comando habitual «Archivo → Actualizar» está desactivado.

### Ventana de clonación
En la ventana de Git Clone puede aparecer la lista «Enlaces recientes» con los repositorios clonados recientemente debajo del campo de la URL.

Reglas:
* la lista aparece solo si el historial ya contiene repositorios clonados recientemente;
* solo se añaden a la lista orígenes de repositorios en red (`https://`, `ssh://` y la sintaxis SCP);
* las rutas locales y los orígenes `file://` no se añaden a esta lista;
* no se crean duplicados: volver a clonar el mismo repositorio lo mueve al principio;
* se guardan hasta 16 repositorios recientes;
* el historial se conserva entre ejecuciones de la aplicación.

Al seleccionar un elemento, el campo de la URL se rellena automáticamente.
Mientras se clona, la lista se oculta temporalmente.

## 6) Copiar
### Selector de formato del árbol (ASCII / JSON / XML / MD)
El selector define el formato de representación del árbol en las operaciones en las que el árbol forma parte del resultado.

* ASCII — árbol de texto con ramas.
* JSON — árbol estructurado en JSON.
* XML — árbol XML compacto para analizadores y herramientas.
* MD — lista anidada de Markdown para documentación y prompts de IA.

El selector afecta a:
* Copiar árbol
* Copiar árbol y contenido
* Exportar árbol
* Exportar árbol y contenido

El selector no afecta a:
* Copiar contenido
* Exportar contenido

### Copiar árbol
Copia el árbol del proyecto.
Si hay nodos marcados, el árbol se construye a partir de la selección; si la selección está vacía o no es válida, se copia el árbol completo.
El formato del resultado lo define el selector de formato del árbol.
Teclas de acceso rápido: {mod}{shift}C y {mod}{alt}C.

### Copiar contenido
Copia el contenido de los archivos:
* si hay archivos marcados, solo esos; si no, todos los archivos del proyecto;
* cada archivo va precedido de un encabezado con su ruta local completa (en los proyectos de Git Clone, la ruta web del repositorio);
* los archivos que no son de texto se ignoran (incluidos los binarios);
* para los archivos de texto vacíos se muestran la ruta y la línea `[No Content, 0 bytes]`;
* para los archivos que solo contienen espacios o saltos de línea se muestran la ruta y la línea `[Whitespace, N bytes]`.
Tecla de acceso rápido: {mod}{alt}V.

### Copiar árbol y contenido
Combina el árbol y el contenido:
* el árbol se construye a partir de la selección; si la selección está vacía o no es válida, se usa el árbol completo;
* el contenido sigue las mismas reglas que «Copiar contenido»;
* el formato del bloque del árbol lo define el selector de formato del árbol.
Tecla de acceso rápido: {mod}{shift}V.

### Representaciones del árbol
Los formatos de árbol usan representaciones distintas para el mismo árbol de proyecto seleccionado.

JSON:
* `rootPath` — ruta absoluta de la raíz normalizada con `/`.
* `tree` — contenido de la carpeta raíz.
* La exportación JSON usa este formato de árbol: las matrices contienen archivos, los objetos contienen subcarpetas, `/` contiene los archivos de la carpeta actual y `[]` representa una carpeta vacía.

XML:
* el nodo raíz es `<t r="...">`;
* las carpetas son `<d n="...">`;
* los archivos son `<f>File.cs</f>`.

MD:
* empieza con `Root: ...`;
* usa una lista anidada de Markdown;
* las carpetas terminan en `/`.

Árbol + contenido:
* el formato de árbol seleccionado se aplica al bloque del árbol;
* el bloque de contenido sigue siendo texto;
* los encabezados de archivo del bloque de contenido usan rutas relativas con `/`;
* se exporta como `.txt`.

## 7) Modo de vista previa
Se abre con el botón del icono del ojo de la barra superior o con {mod}B.

Los botones laterales del ratón siguen la navegación de un navegador: Adelante abre el modo de vista previa y Atrás lo cierra. Repetir la dirección actual no tiene efecto.

{mod}{shift}F abre o cierra la búsqueda en el contenido de los archivos de la vista previa. Enter o F3 va a la siguiente coincidencia; {shift}Enter o {shift}F3, a la anterior.

Muestra el resultado final en un espacio de trabajo aparte, junto al árbol. Este modo no copia al portapapeles ni exporta a un archivo por sí mismo: es un modo de visualización.

De forma predeterminada, el espacio de trabajo se abre así:
* a la izquierda, el árbol del proyecto;
* en el centro, el panel de vista previa;
* a la derecha, el panel de configuración, si estaba abierto.

Modos disponibles:
* Árbol
* Contenido
* Árbol + contenido

Se aplican las mismas reglas que al copiar y exportar:
* se respetan los nodos marcados;
* si la selección está vacía, se usa el conjunto de datos completo;
* se aplican las reglas de exclusión y las opciones de selección actuales.

Además:
* en la vista previa, los archivos están separados por líneas horizontales;
* al desplazarse, la ruta del archivo actual queda fijada arriba; hacer clic en la ruta fijada vuelve al principio de ese archivo;
* la barra de desplazamiento de la vista previa marca las coincidencias de búsqueda y las líneas con valores detectados; hacer clic en una marca salta a su línea; un valor conservado sin cambios sigue marcado, y los encabezados de ruta enmascarados añaden una sola marca en su primera línea;
* el zoom del árbol y el de la vista previa pueden ser independientes;
* en el modo de vista previa puede copiar el resultado actual completo o el bloque del archivo visible sin abrir el menú Copiar.

Botones:
* botón de copiar a la izquierda de la isla superior de la vista previa — copia el modo de vista previa actual:
  * Árbol
  * Contenido
  * Árbol + contenido
* X en el panel del árbol — oculta el árbol y deja solo el panel de vista previa;
* X en el panel superior de la vista previa — cierra por completo el modo de vista previa;
* botón pequeño de copiar en el encabezado del archivo fijado — copia el bloque del archivo visible exactamente como se muestra en la vista previa;
* volver a pulsar el icono del ojo o {mod}B también cierra el modo de vista previa.

Buscar y Filtrar están disponibles mientras el panel del árbol es visible en la vista previa.
Si el árbol está oculto, Buscar y Filtrar no están disponibles temporalmente hasta que salga del modo de solo vista previa.

## 8) Ver
### Zoom
* {mod}+ / {mod}= — acercar
* {mod}- — alejar
* {mod}0 — restablecer
* {mod}rueda del ratón — zoom suave en el panel bajo el cursor

Comportamiento:
* en el modo normal, se amplía el árbol;
* en la vista previa con el árbol visible, Acercar, Alejar y Restablecer zoom del menú se aplican tanto al árbol como a la vista previa;
* con {mod}rueda del ratón, el árbol y la vista previa se amplían por separado según dónde esté el cursor;
* en el modo de solo vista previa, solo se amplía el panel de vista previa.

Rango: 6–28; el valor al restablecer es 15.

### Modo compacto
Hace la interfaz más densa: menos espacio en el árbol y en la configuración.
Mientras el espacio de trabajo de vista previa está activo, el modo compacto se activa automáticamente.

### Animaciones
«Ver → Animaciones» controla por separado la expansión del árbol, los contadores de estado y la aparición inicial de las herramientas. Las tres están activadas de forma predeterminada; una animación desactivada muestra su estado final de inmediato.

### Fuente del árbol
La fuente del árbol se selecciona en «Ver → Fuente del árbol».
«Predeterminado» restaura la fuente estándar del árbol.
La fuente seleccionada se aplica después de hacer clic en «Aplicar configuración» en el panel de configuración.

### Actividad del agente
«Ver → Actividad del agente» marca los archivos que un agente de IA recibió durante una sesión MCP en vivo; consulte la sección 19.4.

## 9) Búsqueda (árbol)
Abre la barra de búsqueda, resalta las coincidencias y permite navegar entre ellas.
* {mod}F — mostrar u ocultar
* Enter — siguiente resultado
* {shift}Enter — resultado anterior
* Esc — cerrar

La búsqueda expande automáticamente solo las ramas necesarias; borrar la consulta contrae el árbol (excepto la raíz).
Las líneas con coincidencias también se marcan en la barra de desplazamiento del árbol; hacer clic en una marca salta a esa coincidencia.
Con conjuntos de coincidencias muy grandes, la aplicación puede limitar la expansión automática y el resaltado global para que la interfaz siga respondiendo.
Al cerrar la barra de búsqueda, la consulta se borra cuando termina la animación de cierre.

Restricciones:
* abrir Buscar cierra Filtrar automáticamente;
* Buscar está disponible en la vista previa mientras el panel del árbol es visible;
* si el árbol está oculto, Buscar no está disponible temporalmente.

## 10) Filtro (por nombre)
Muestra solo los nodos que coinciden con el texto del filtro y sus nodos padre. La lista se actualiza con un breve retraso mientras escribe.
* {mod}{shift}N — mostrar u ocultar el filtro
* Esc — cerrar el filtro

Restricciones:
* abrir Filtrar cierra Buscar automáticamente;
* Filtrar está disponible en la vista previa mientras el panel del árbol es visible;
* si el árbol está oculto, Filtrar no está disponible temporalmente.

## 11) Opciones (panel de configuración)
Disponible a la derecha:
* Aplicar configuración
* Procesamiento de contenido
* Exclusiones
* Tipos de archivos

Los cambios en «Exclusiones» y «Tipos de archivos» quedan pendientes en el panel y se aplican al hacer clic en «Aplicar configuración».

Después de cambiar una casilla, la aplicación puede actualizar en segundo plano las opciones disponibles y sus recuentos. El árbol resultante se reconstruye solo después de hacer clic en «Aplicar configuración».

Si una actualización de las opciones disponibles se cancela con el botón X de la barra de estado, los cambios sin terminar no se aplican y el panel vuelve a su último estado completado.

Cada lista tiene un interruptor «Todos».

Nota sobre «Tipos de archivos»:
* esta lista solo muestra archivos que tienen extensión;
* los archivos sin extensión no se añaden a esta lista y se controlan con una opción aparte en «Exclusiones».

Procesamiento de contenido:
* transforma el contenido de los archivos de texto seleccionados sin cambiar el árbol;
* «Ocultar secretos» y «Ocultar datos privados» sustituyen los valores detectados (secciones 12.3 y 12.4);
* «Comprimir código» conserva las declaraciones y acorta las implementaciones con nombre en 14 lenguajes;
* «Eliminar comentarios» quita los comentarios y los comentarios de documentación en 20 paquetes de lenguajes;
* «Eliminar líneas en blanco» quita las líneas que solo contienen espacios en los mismos paquetes y conserva los literales multilínea;
* los cambios surten efecto tras «Aplicar configuración».

{mod}P — mostrar u ocultar el panel.

### 11.1 Perfiles de parámetros de proyectos locales
Para las carpetas locales, DevProjex recuerda los últimos parámetros del proyecto aplicados:
* tipos de archivo seleccionados;
* opciones seleccionadas en la sección «Exclusiones».

Se guardan al hacer clic en «Aplicar configuración».
Cuando se vuelve a abrir la misma carpeta local, los parámetros se restauran automáticamente.

Importante:
* los perfiles solo se guardan para proyectos locales;
* para los proyectos abiertos con Git Clone no se guardan perfiles;
* si algunas opciones guardadas ya no están disponibles en el proyecto actual, se omiten y se aplican los demás parámetros;
* si al actualizar o volver a abrir aparece un nuevo tipo de archivo o una nueva opción en «Exclusiones», se activa de forma predeterminada;
* las opciones ya conocidas conservan la elección explícita del usuario: los archivos nuevos de un tipo desactivado no vuelven a activar ese tipo.

## 12) Exclusiones
La sección «Exclusiones» controla qué archivos y carpetas se excluyen del árbol, del contenido y de los resultados de copia y exportación.

Un elemento se muestra solo cuando se cumplen todas estas condiciones:
* su tipo de archivo está seleccionado, si el archivo tiene tipo;
* ninguna regla de exclusión activada lo excluye.

Las reglas de exclusión son acumulativas. Si al menos una regla activada oculta un elemento, otra regla no puede volver a mostrarlo.

### 12.1 Reglas disponibles
Según el contenido del proyecto, pueden mostrarse las siguientes opciones:

* Smart Ignore
* Carpetas vacías
* Archivos vacíos
* Carpetas ocultas
* Archivos ocultos
* Carpetas con punto inicial
* Archivos con punto inicial
* Archivos sin extensión

El selector de la GUI y las filas de opción del eje Git en la TUI se ocultan por completo cuando el filtrado de Git no es aplicable: no hay un límite de repositorio y el filtro `.gitignore` no puede cambiar el árbol actual. Cuando el eje es visible fuera de un repositorio, la GUI ofrece solo «sin filtrado» y `.gitignore`, mientras que la TUI desactiva las filas que requieren un repositorio. Dentro de un repositorio Git, los cinco valores habituales son: sin filtrado, `.gitignore`, archivos rastreados, archivos preparados y todos los cambios actuales; en la TUI, un ámbito `diff:<ref>..<ref>` activo aparece como sexta fila. Elegir un valor sustituye el modo Git actual sin cambiar Smart Ignore ni las exclusiones básicas. Las demás opciones aparecen cuando sus reglas pueden cambiar el árbol actual, por lo que la lista puede cambiar después de cambiar otra regla o un tipo de archivo.

Una opción nueva se activa de forma predeterminada cuando aparece por primera vez. Una opción conocida conserva la elección del usuario aunque desaparezca temporalmente de la lista.

### 12.2 Smart Ignore
Smart Ignore oculta dependencias, resultados de compilación, cachés y otros artefactos de servicio del proyecto.

DevProjex identifica primero el tipo de proyecto a partir de su estructura y de los archivos marcadores, por ejemplo:

* `.csproj`
* `package.json`
* `pyproject.toml`
* `Cargo.toml`

Después se aplican las reglas de la pila correspondiente dentro del ámbito del proyecto detectado. Por ejemplo, las reglas de .NET no se extienden a un proyecto vecino de Python o JavaScript.

El nombre de una carpeta no siempre basta. Los nombres ambiguos como `build`, `vendor`, `packages`, `cache`, `pkg` o `Library` también se verifican por su contenido. Así se evita ocultar una carpeta normal del usuario solo porque tiene un nombre parecido.

Algunos almacenes de dependencias y directorios de servicio pueden reconocerse por su estructura interna característica incluso fuera de un proyecto detectado explícitamente.

La detección de ámbitos de proyecto está limitada, para que cargar una carpeta grande del usuario no se convierta en un análisis completo y repetido de cada directorio. Las estructuras normales usan una detección superficial, mientras que los monorepos reconocidos se examinan con más profundidad. Una vez encontrado un ámbito, Smart Ignore se aplica a todo su subárbol sin límite de profundidad.

### 12.3 Ocultar secretos
«Ocultar secretos» está desactivado de forma predeterminada. Solo analiza el contenido de texto seleccionado y sustituye cada valor detectado en su lugar, conservando el archivo y el código que lo rodea. Mientras la opción está desactivada, no se ejecuta ningún análisis ni se muestra ningún recuento. Tras analizar la selección actual, la etiqueta muestra el número de valores detectados; si las decisiones de conservar dejan menos valores ocultos, muestra detectados/ocultos, y el indicador ? de la fila informa de ambos recuentos.

Los fragmentos ocultados se resaltan en la vista previa. Haga clic en uno para conservar sin cambios solo esa aparición; {alt}↓ / {alt}↑ recorren los hallazgos y Enter alterna el activo. En el Terminal Workspace, `[` y `]` recorren las apariciones y `Enter` o `Space` alternan la activa. La decisión se aplica durante la sesión actual a la vista previa, el portapapeles, la exportación de contexto, la copia en carpeta y el ZIP; no se guarda en el perfil del proyecto.

El menú contextual de la vista previa amplía estas decisiones. Un clic derecho sobre una aparición detectada permite conservar —o volver a ocultar— en una sola acción todas las apariciones de su regla o todas las apariciones detectadas en el mismo archivo. Un clic derecho sobre un valor seleccionado dentro del contenido de un archivo permite marcarlo manualmente: «Ocultar … aquí» oculta solo esa aparición durante la sesión, «Ocultar siempre …» crea una marca persistente para todas las apariciones del valor y «Ocultar … como dato privado» crea una marca persistente controlada por «Ocultar datos privados». «Quitar marca» aparece sobre una marca manual y la elimina; un valor que el detector sigue encontrando permanece oculto. Un valor manual debe ser una sola línea de 8 a 512 caracteres seleccionada dentro del contenido del archivo. Crear una marca activa automáticamente la opción correspondiente. Las marcas persistentes solo guardan una identidad del valor con clave y su clase, nunca el texto original.

Una copia en carpeta o ZIP también modifica el texto coincidente y es posible que ya no se compile ni se ejecute. Los archivos binarios se copian sin cambios y no se analizan. Un archivo de texto seleccionado de más de 16 MiB se omite y se notifica, mientras el resto de la salida se completa. Un fallo de detección detiene toda la operación.

El recuento solo informa de coincidencias con las reglas. Cero no significa que el proyecto sea seguro. La CLI usa `--hide-secrets`; los detalles técnicos y los límites están en `Docs/HideSecrets.md`.

### 12.4 Ocultar datos privados
«Ocultar datos privados» está desactivado de forma predeterminada. Detecta direcciones de correo electrónico, direcciones IP globales, nombres de usuario locales en rutas, direcciones MAC y números de teléfono internacionales en los archivos de texto seleccionados. Los hallazgos usan las mismas decisiones de la vista previa y el mismo flujo de salida que «Ocultar secretos»; las marcas manuales creadas con «Ocultar … como dato privado» pertenecen a esta clase y siguen esta opción (sección 12.3). Los nombres de usuario locales en los encabezados de ruta generados y en la raíz del árbol se enmascaran como un único hallazgo compartido: el recuento lo incluye como un valor, el indicador ? informa de si está oculto o visible, y un clic alterna todas las rutas enmascaradas.

Los rangos y hosts de documentación, los nombres de usuario habituales de CI, los resolutores DNS públicos conocidos y los rangos de teléfonos ficticios documentados permanecen visibles. Cero coincidencias no garantizan la privacidad. La CLI usa `--hide-private-data`; las reglas completas y los límites de la primera fase están en `Docs/HidePrivateData.md`.

### 12.5 Usar .gitignore
Cuando está activado, DevProjex sigue la vista del árbol de trabajo de `git status`: los archivos rastreados permanecen visibles y los no rastreados se muestran salvo que las reglas de exclusión del repositorio los excluyan. Aplica todos los `.gitignore` accesibles, no solo el de la raíz de la carpeta abierta, incluidos los que están por encima de ella hasta la raíz del repositorio.

Cada `.gitignore` se aplica:

* a la carpeta que lo contiene;
* a todas las carpetas accesibles por debajo de ella;
* solo dentro de ese ámbito.

Las reglas de un `.gitignore` anidado no afectan a las carpetas superiores ni a las hermanas.

Para una ruta concreta, las reglas se procesan desde el `.gitignore` superior hacia los más profundos. Dentro de un archivo, las reglas se procesan de arriba abajo. La última regla que coincide determina el resultado de Git.

Una regla que empieza por `!` anula una exclusión de Git anterior solo dentro de su ámbito. No puede restaurar un archivo mientras su carpeta superior siga excluida. Un `.gitignore` dentro de una carpeta completamente excluida e inaccesible no participa en la evaluación.

Una línea mal formada o no compatible se omite de forma independiente. Las demás reglas válidas de ese archivo y las reglas de los ámbitos vecinos siguen funcionando.

También se aplica el archivo local del repositorio `.git/info/exclude`, con menor prioridad que el `.gitignore` de la raíz. Una carpeta anidada con su propio `.git` también sigue a `git status`: un repositorio incrustado que no está declarado en `.gitmodules` es opaco, por lo que sus archivos no se muestran, mientras que un submódulo declarado aplica su propio `.gitignore` y su `info/exclude`. Seleccione `none` para ver los archivos de los repositorios incrustados. No se aplican las reglas de exclusión globales de Git (`core.excludesFile`); sí se respetan los ajustes efectivos del repositorio para comparar rutas, como `core.ignoreCase` y, en macOS, `core.precomposeUnicode`. No se sigue un enlace simbólico llamado `.gitignore`, igual que hace Git con este archivo de control. Si no se puede leer un archivo `.gitignore` o `info/exclude`, el ámbito de su directorio se excluye de forma segura y el análisis informa de un acceso parcial en lugar de incluir en silencio archivos sin evaluar todas las reglas. Cuando hay un índice legible para el ámbito del repositorio al que pertenece la ruta, los archivos rastreados permanecen visibles aunque coincidan con `.gitignore`; sin ese índice o sin la CLI de Git, ese ámbito vuelve de forma segura a evaluar solo los patrones.

El perfil integrado `standard` selecciona `gitignore` además de `smart-ignore`, `hidden-folders`, `hidden-files`, `dot-folders`, `dot-files`, `empty-folders`, `empty-files` y `extensionless-files`.

### 12.6 Solo archivos rastreados por Git
«Solo archivos rastreados por Git» construye la etapa Git del árbol a partir de los archivos existentes del árbol de trabajo registrados en cada índice Git legible. Los archivos rastreados modificados y los archivos nuevos preparados siguen incluidos; los archivos no rastreados se excluyen. Se trata del árbol de trabajo actual, no de una instantánea histórica de `HEAD` ni de un repositorio remoto.

Cada repositorio se resuelve de forma independiente: los repositorios hermanos dentro de la carpeta abierta y los submódulos declarados usan cada uno su propio índice, y un repositorio hijo no hereda las rutas rastreadas de su repositorio padre ni de uno hermano. Un repositorio incrustado que no está declarado en `.gitmodules` sigue siendo opaco, como en el modo `.gitignore`. Este modo requiere la CLI de Git; un índice vacío pero legible es válido. Si el Terminal Workspace (TUI) se inicia en este modo y no se puede cargar ningún índice aplicable, el espacio de trabajo no se abre. Si el modo se selecciona de forma interactiva en un espacio de trabajo TUI ya abierto y no se puede cargar ningún índice aplicable, el cambio se rechaza y sigue activo el último modo Git utilizable. En la misma situación, los comandos directos devuelven un fallo de política o de comprobación. DevProjex nunca cambia en silencio a `.gitignore`. Si se puede leer otro índice aplicable, los ámbitos anidados no disponibles se excluyen con una advertencia.

En un espacio de trabajo de Desktop ya abierto, la selección explícita de archivos rastreados permanece visible y falla de forma segura: la salida y la exportación se bloquean cuando falla la disponibilidad, mientras que con una disponibilidad parcial se continúa con una advertencia localizada.

Los modos Git son mutuamente excluyentes; `none` desactiva el filtrado de Git. Los modos momentáneos `staged`, `changes` y `diff:<ref>..<ref>` no se guardan en los perfiles. Mientras un modo momentáneo está activo, el perfil local del proyecto en la GUI conserva el último modo persistente activado, `gitignore` o `tracked`. El modo `none` solo se guarda cuando está activo en el momento de guardar. La TUI y la CLI rechazan guardar un perfil portátil mientras haya un modo momentáneo activo.

### 12.7 Relación entre el filtrado de Git y Smart Ignore
El modo Git seleccionado y Smart Ignore son controles independientes. El modo Git se aplica primero en cada ámbito Git accesible. Después, Smart Ignore procesa los elementos restantes y, por último, se aplican las reglas básicas.

Smart Ignore puede permanecer oculto mientras el modo Git seleccionado ya cubra todos sus candidatos y aparecer después de cambiar o desactivar el modo Git. Dentro de un repositorio Git siguen disponibles todos los modos Git que dependen del repositorio.

Una regla de negación de Git que empieza por `!` anula solo un resultado de Git. No desactiva Smart Ignore ni una regla básica.

### 12.8 Reglas básicas
«Carpetas con punto inicial» y «Archivos con punto inicial» examinan el nombre del elemento.

«Carpetas ocultas» y «Archivos ocultos» examinan el atributo oculto del sistema. En algunas plataformas, un nombre que empieza por punto y el atributo del sistema pueden describir el mismo elemento o elementos distintos.

«Archivos vacíos» oculta los archivos cuyo tamaño es de 0 bytes.

«Archivos sin extensión» oculta archivos como `Dockerfile`, `Makefile` y `README`.

«Carpetas vacías» oculta las carpetas lógicamente vacías. Una carpeta está lógicamente vacía cuando no queda ningún archivo ni subcarpeta visible después de aplicar los tipos de archivo seleccionados y todas las demás reglas.

Por eso, el recuento de carpetas vacías puede cambiar al activar o desactivar otra regla: ocultar archivos puede dejar lógicamente vacías las carpetas que los contienen.

### 12.9 Contadores
El recuento junto a una regla muestra su contribución directa con la configuración actual, no el número físico de elementos similares en el disco.

Un mismo elemento no se atribuye a la vez a varios contadores superpuestos. Por ejemplo, la carpeta `.git` puede tener a la vez un nombre que empieza por punto y el atributo Oculto del sistema, pero su exclusión se atribuye a una sola regla.

Para elegir a qué regla se atribuye una exclusión se usa un orden estable:

* carpetas: `.gitignore`, Smart Ignore, nombre con punto inicial, atributo Oculto del sistema;
* archivos: `.gitignore`, Smart Ignore, nombre con punto inicial, sin extensión, archivo vacío, atributo Oculto del sistema.

Este orden solo afecta a los contadores. La visibilidad final sigue una regla más sencilla: un elemento se oculta si cualquier mecanismo activado lo excluye.

### 12.10 Aplicar los cambios
Al cambiar las casillas, primero se actualizan los ajustes disponibles y los contadores del panel. El árbol final se reconstruye después de seleccionar «Aplicar configuración».

Si se cancela la preparación de la configuración, DevProjex devuelve el panel al último estado completado por completo. Las reglas calculadas parcialmente no se aplican.

## 13) Cómo se calculan el árbol y las métricas
El resultado depende de:
* los tipos de archivo seleccionados
* las reglas de exclusión
* el filtro activo
* los nodos marcados del árbol (para las operaciones basadas en la selección)

Si se deniega el acceso, el nodo conserva su nombre e icono habituales y recibe el sufijo «[acceso denegado]».

### 13.1 Qué muestran los contadores de la barra de estado
La barra de estado tiene dos bloques:
* Árbol — métricas de la salida de texto del árbol;
* Contenido — métricas de la salida del contenido de los archivos exportados.

Formato:
* Líneas
* Caracteres
* ≈Tokens (aproximados)

Los valores grandes se muestran con sufijos compactos (K/M).

Importante:
* «Líneas» en el bloque «Árbol» es el número de líneas de la representación final del árbol, no el número de archivos en el disco;
* este valor incluye carpetas, archivos y elementos de servicio del árbol (por ejemplo, los nodos con acceso denegado).

### 13.2 Cómo se calculan las métricas
Métricas del árbol:
* se calculan a partir de la salida real del árbol que genera el mismo proceso de exportación;
* respetan el formato de árbol actual.

Métricas del contenido:
* siguen las mismas reglas que la copia y la exportación de contenido;
* los archivos binarios se excluyen;
* los archivos vacíos y los que solo contienen espacios se cuentan mediante marcadores de servicio (`[No Content, 0 bytes]`, `[Whitespace, N bytes]`).

### 13.3 Cuándo se actualizan los contadores
El recálculo se ejecuta:
* después de abrir o actualizar un proyecto;
* después de aplicar la configuración (exclusiones y tipos de archivo);
* cuando cambian las casillas del árbol (con un breve retraso);
* al cambiar el formato del árbol (para las operaciones en las que se usa la salida del árbol);
* cuando se cancela el cálculo en segundo plano, los contadores se ponen a 0 hasta el siguiente recálculo completado.

## 14) Iconos
Orden de selección de iconos:
1) tipo de nodo (carpeta o archivo)
2) nombre exacto (si existe una regla)
3) extensión
4) en otro caso, desconocido

## 15) Tema y efectos
La sección Tema permite elegir Sistema, Claro u Oscuro y un efecto de fondo:
* Transparencia
* Desenfoque
* Mica

Sistema está seleccionado de forma predeterminada y sigue los cambios de tema del sistema operativo. Tras el primer inicio o un restablecimiento de la configuración, un tema claro del sistema empieza con un fondo opaco normal, mientras que un tema oscuro del sistema empieza con Desenfoque. Si no se puede determinar la preferencia del sistema, DevProjex usa Oscuro con Desenfoque. Claro y Oscuro recuerdan sus efectos por separado. Una selección explícita de Claro u Oscuro ignora los cambios del sistema hasta que se vuelve a seleccionar Sistema.

Los efectos son mutuamente excluyentes. Volver a hacer clic en el efecto seleccionado lo desactiva y restaura un fondo opaco normal.

Ajustes disponibles:
* Transparencia de fondo — disponible para Transparencia y Desenfoque.
* Contraste de la barra superior — ajusta el panel principal que contiene los comandos de vista previa, búsqueda, filtro y formato del árbol.
* Transparencia del menú — se aplica por igual al menú principal y a sus submenús.
* Visibilidad del borde — ajusta la intensidad con la que se muestran los bordes de la interfaz.

Mica usa el material del sistema de la plataforma y no tiene un ajuste propio de transparencia de fondo. Si el efecto Desenfoque o Mica seleccionado no está disponible, la aplicación prueba primero el otro efecto nativo. Solo se usa un fondo opaco normal cuando no están disponibles ni Desenfoque ni Mica.

En el modo Transparencia, el fondo de la ventana principal permanece transparente. Los menús, submenús y demás superficies emergentes usan Desenfoque cuando es compatible, para que los elementos del árbol y del contenido que hay detrás no dificulten la lectura.

## 16) Ayuda

### 16.1 Actualizaciones
«Ayuda → Actualizaciones» compara la versión actual con la última versión estable publicada en GitHub. Las comprobaciones automáticas están desactivadas de forma predeterminada; si se activan, DevProjex comprueba al iniciarse cuando han pasado al menos siete días desde la última comprobación correcta. La casilla surte efecto de inmediato. El último resultado correcto se conserva entre ejecuciones de la aplicación y un error de red posterior no lo borra. La instalación sigue siendo una acción del usuario.

### 16.2 Restablecer configuración
Restablecer configuración («Ayuda → Restablecer configuración») restaura los valores predeterminados del tema, los efectos, el modo compacto, las animaciones y el idioma de la interfaz. Los perfiles de proyecto, el historial y los archivos del disco no se modifican.

### 16.3 Restablecer datos
Restablecer datos («Ayuda → Restablecer datos») elimina los perfiles de parámetros guardados de los proyectos locales:
* tipos de archivo seleccionados;
* opciones seleccionadas en la sección «Exclusiones»;
* ajustes seleccionados de procesamiento de contenido;
* marcas manuales de secretos.

También borra las sesiones finalizadas del registro del agente (sección 19.3); las sesiones activas se conservan.

Importante:
* el historial de carpetas locales recientes no se borra;
* el historial de repositorios recientes de la ventana de Git Clone no se borra;
* los archivos y las carpetas del disco no se modifican ni se eliminan.

## 17) Idiomas
El idioma se selecciona en el menú Idioma.
El idioma seleccionado se conserva entre ejecuciones. «Ayuda → Restablecer configuración» borra el idioma guardado y devuelve la interfaz al idioma predeterminado.

## 18) Barra de progreso y cancelación
El centro de la barra de estado muestra la operación activa y su progreso.

Modos de progreso:
* Indeterminado — sin porcentaje (se desconoce la duración de la operación).
* Determinado — con porcentaje (0–100).

Comportamiento:
* durante el cálculo de datos en segundo plano se muestra el progreso en porcentaje;
* en algunas operaciones de Git, el porcentaje se muestra cuando la fuente de progreso lo proporciona;
* la actualización de las opciones disponibles y la aplicación de la configuración se muestran cuando la operación tarda un tiempo apreciable;
* las operaciones rápidas terminan sin mostrar progreso.

Botón X (cancelar) de la barra de estado:
* intenta cancelar, en la medida de lo posible, las operaciones que admiten cancelación;
* detiene el cálculo de datos en segundo plano;
* si se cancela una actualización de las opciones disponibles, devuelve el panel a su último estado completado;
* en las operaciones que no admiten cancelación, detiene la indicación en la barra de estado, aunque la operación puede seguir terminando en segundo plano.

## 19) MCP y agentes de IA
DevProjex incluye un servidor MCP local de solo lectura. Los agentes de IA como Claude Code, Codex, Cursor y VS Code leen el proyecto a través de él: la ocultación de secretos está siempre activa y el agente no puede cambiar los archivos del proyecto. El servidor ofrece ocho herramientas: `list_projects`, `get_tree`, `analyze`, `search_project`, `related_files`, `get_file`, `pack_context` y `read_pack`.

### 19.1 Conectar un cliente
El menú MCP contiene:
* Live context — el servidor sigue los elementos marcados en esta ventana (sección 19.2);
* Estándar — el servidor no depende de la selección de la ventana;
* Registro… — lo que los agentes solicitaron y recibieron (sección 19.3);
* Documentación — abre la documentación del servidor MCP.

Live context y Estándar contienen las mismas acciones —Abrir en Claude Code, Abrir en Codex, Abrir en Cursor, Abrir en VS Code y Otros clientes…—, disponibles mientras hay un proyecto abierto.

Claude Code y Codex se registran mediante su comando instalado y, después, el cliente se abre en una terminal nueva en la carpeta del proyecto. Cursor y VS Code reciben un `.cursor/mcp.json` o un `.vscode/mcp.json` local del proyecto; los demás servidores de ese archivo se conservan. «Otros clientes…» muestra una configuración lista para Claude Desktop y otros clientes. Si falta el comando de un cliente o la conexión falla, DevProjex muestra en su lugar la configuración manual. Tras una conexión correcta, DevProjex puede ofrecer añadir el comando `devprojex` al PATH.

Codex mantiene una única conexión compartida con DevProjex, así que conectar otro proyecto pide confirmación antes de sustituirla. Una sesión de cliente que ya está en ejecución debe reiniciarse para cargar el servidor. En una terminal, `devprojex mcp connect` registra el modo estándar de forma predeterminada; añada `--mode live` para Live context o `--print` para solo imprimir la configuración.

### 19.2 Live context
En Live context, los elementos marcados en el árbol definen el foco del agente: las solicitudes de árbol, búsqueda, análisis, archivos relacionados y empaquetado se mantienen dentro de ellos. Los filtros de la ventana —tipos de archivo, exclusiones y modo Git— son el límite de acceso: el agente puede abrir otros archivos por su nombre, pero solo los que permiten esos filtros.

No es necesario mantener la ventana abierta. El servidor lee en cada solicitud la última selección guardada del proyecto, de modo que las nuevas marcas y la configuración aplicada llegan al agente en su siguiente solicitud sin reiniciarlo.

Mientras hay una sesión en vivo activa, el título de la ventana termina en `· Live context (<client>)`, o con el número de sesiones cuando hay varias activas.

### 19.3 Registro
«MCP → Registro…» muestra lo que los agentes solicitaron y recibieron a través de DevProjex: las sesiones con su cliente, modo, llamadas, caracteres, tokens estimados, archivos entregados y valores enmascarados, y las llamadas de la sesión seleccionada. Está disponible sin un proyecto abierto; con un proyecto abierto, «Solo el proyecto actual» está seleccionado de forma predeterminada.

El registro se guarda solo en este equipo, en la carpeta de estado de DevProjex, y conserva como máximo 200 sesiones durante 30 días. No guarda el contenido de los archivos, los valores secretos detectados ni el texto de las consultas de búsqueda. «Exportar…» guarda una sesión como recibo en Markdown o JSON. «Borrar» elimina las sesiones finalizadas tras una confirmación; las sesiones activas y las compartidas con otros proyectos se conservan.

### 19.4 Actividad del agente
«Ver → Actividad del agente» está desactivado de forma predeterminada. Cuando está activado, los archivos que el agente recibió durante la última sesión en vivo se marcan con ✦ en el árbol, y la información sobre herramientas de la marca indica cuántas veces recibió el agente el archivo. Las marcas nunca cambian los filtros ni las casillas. Se borran cuando empieza una sesión en vivo más reciente, cuando se desactiva «Actividad del agente» y cuando se vuelve a abrir el proyecto. Las sesiones estándar aparecen en el registro, pero no añaden marcas.

## 20) Notas
* Si los permisos no son suficientes, la aplicación puede proponer reiniciarse con privilegios elevados; si lo rechaza, se muestra una notificación.
