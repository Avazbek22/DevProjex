## 1) Бұл не және не үшін
DevProjex жоба контекстін тез дайындайды: қалта/файл құрылымын көрсетеді, элементтерді белгілеуге және ағашты және/немесе файл мазмұнын алмасу буферіне көшіруге мүмкіндік береді. Code review, қолдау, оқыту және жоба құрылымын AI‑көмекшіге беру үшін ыңғайлы.

Маңызды: қолданба тек оқу режимінде жұмыс істейді және файлдарды өзгертпейді.

## 2) Жоба ағашы
* Файл/қалта түрі иконкалары.
* Түйіндердегі чекбокстар.
* Ашып/жабу.

Чекбокстар: түйінді белгілеу оның ұрпақтарына қолданылады; ата‑ананың күйі автоматты қайта есептеледі.

Ыстық пернелер:
* Ctrl+E — бәрін ашу
* Ctrl+W — бәрін жабу (түбір ашық қалады)

## 3) Файл
* Қалтаны ашу… — түбір қалтаны ашу (Ctrl+O)
* Жаңа терезе — DevProjex қолданбасының жаңа тәуелсіз данасын ашу
* Жуырда ашылғандар — жуырда ашылған жергілікті қалталардың тізімі
* Жаңарту — жергілікті қалтаны қайта оқу және ағашты қайта құру (F5)
* Файлға экспорттау:
  * Ағашты экспорттау
  * Мазмұнды экспорттау
  * Ағаш пен мазмұнды экспорттау
* Жобаны экспорттау:
  * Қалтаға…
  * ZIP мұрағатына…

Жобаны экспорттау ағымдағы ағаштан каталогтар құрылымын сақтайтын бөлек қалта немесе ZIP мұрағатын жасайды.

Таңдалған жоғарғы деңгей қалталары, файл түрлері, алып тастау ережелері және белгіленген элементтер ескеріледі. Ештеңе белгіленбесе, ағымдағы ағаш толығымен экспортталады.

Мәтіндік және бинарлық файлдар көшіріледі, сондай-ақ қосылған бос қалталар сақталады. Бастапқы файлдар өзгертілмейді. Нәтижені бастапқы жобаның ішіне сақтауға болмайды.

Экспорт кезінде ағаш пен параметрлерді өзгертуге, сүзгіні пайдалануға, пішімді немесе алдын ала қарау режимін ауыстыруға, Git пәрмендерін, жаңартуды немесе басқа жобаны ашуды іске қосуға болмайды.

Пішім ережелері:
* Ағашты экспорттау:
  * ASCII -> тек `.txt`.
  * JSON -> әдепкі `.json`, сақтау терезесінде `.json` және `.txt` қолжетімді.
  * XML -> әдепкі `.xml`, сақтау терезесінде `.xml` және `.txt` қолжетімді.
  * MD -> әдепкі `.md`, сақтау терезесінде `.md` және `.txt` қолжетімді.
* Мазмұнды экспорттау — әрқашан мәтіндік мазмұн пішімі, `.txt` файлы (ағаш пішімінің ауыстырғышы әсер етпейді).
* Ағаш пен мазмұнды экспорттау — әрқашан `.txt` файлы; таңдалған ағаш пішімі нәтиже ішіндегі ағаш блогының пішіміне ғана әсер етеді.

Экспорт файлдары UTF-8 (BOM-сыз) пішімінде жазылады.

### Drag & Drop
Drag & Drop жоба жүктелмеген кезде бастапқы аймақта (Drop Zone) жұмыс істейді.

Ережелер:
* қалтаны сүйреп тастауға болады;
* файлды сүйреп тастауға болады — бұл жағдайда файл орналасқан қалта ашылады;
* бірнеше объект тасталса, бірінші жарамды жергілікті жол қолданылады;
* жол қолжетімсіз немесе жоқ болса, «Қалтаны ашу…» әрекетіндегідей қолжетімділік тексерістері қолданылады;
* қолдауы жоқ немесе жергілікті емес объекттер еленбейді.

### Жуырда ашылғандар
«Файл → Жуырда ашылғандар» тармағы жуырда ашылған жергілікті қалталардың тарихын көрсетеді.

Ережелер:
* тізімге тек жергілікті қалталар қосылады;
* DevProjex арқылы клондалған Git-репозиторийлер бұл тізімге қосылмайды;
* қайталанулар жасалмайды — сол қалтаны қайта ашу оны тізімнің жоғарғы жағына шығарады;
* соңғы 15 қалтаға дейін сақталады;
* тарих қолданбаны қайта іске қосқаннан кейін де сақталады.

Әр тармақта ата-аналық қалта мен жоба атауы көрсетіледі, мысалы `Projects / App`.

## 4) Терминалдан іске қосу
DevProjex-ті терминалдан іске қосуға болады.

Егер команда бапталған болса, терминалды ашып, орындаңыз:
`devprojex --help`

Осылай барлық қолжетімді командаларды, параметрлерді және мысалдарды көресіз.

Мысалдар:
* `devprojex .` — ағымдағы папканы ашу.
* `devprojex "C:\Projects\App"` — көрсетілген папканы ашу.
* `devprojex . --export tree` — жоба ағашын терминалға шығару.
* `devprojex . --export content` — файлдардың мазмұнын терминалға шығару.
* `devprojex . --export tree-content` — ағаш пен мазмұнды терминалға шығару.
* `devprojex . --export tree-content -o context.txt` — нәтижені файлға сақтау.
* `devprojex --benchmark "C:\Projects\App"` — стандартты жоба есебі workflow-ын өлшеу.
* `devprojex --last --preview` — соңғы жобаны бірден preview режимінде ашу.
* `devprojex --benchmark-ui "C:\Projects\App"` — стандартты UI сценарийін өлшеу.
* `devprojex --session-metrics "C:\Projects\App"` — терезе жабылғанға дейін UI сессиясының метрикаларын жазу.

Ерекшеліктер:
* `.` терминалдың ағымдағы папкасын білдіреді;
* бос орындары бар жолдарды тырнақшаға алу керек;
* шығару файлы көрсетілмесе, нәтиже тікелей терминалға шығарылады;
* команда жоба файлдарын өзгертпейді — DevProjex оқу режимінде жұмыс істейді.

Егер `devprojex` командасы жұмыс істемесе, DevProjex ішінде ашыңыз:
«Анықтама → Терминалдан іске қосу».

## 5) Git
Git мәзірі тек DevProjex арқылы клондалған жобаларда қолжетімді (Git Clone). Қолданба файлдарыңызды өзгертпейді — тек кэшпен жұмыс істейді.

Кэш жүйелік уақытша қалтада сақталады. Windows-та әдетте:
`%TEMP%\DevProjex\RepoCache`

* Ветка — қолжетімді веткалардың тізімін белсенді ветка белгісімен көрсетеді; ауысқанда ағаш таңдалған веткаға жаңарады. Егер ветка жергілікті бар болса, ауысу желісіз (жаңартусыз) болады. Егер ветка жергілікті жоқ болса, ол fetch арқылы жүктеліп, жергілікті құрылады.
* Жаңартуларды алу — тек ағымдағы ветканы жаңартады: fetch және origin/<ветка> күйіне reset. Git Clone жобасында F5 осы әрекетті орындайды; кәдімгі «Файл → Жаңарту» командасы өшірулі болады.

### Клондау терезесі
Git Clone терезесінде URL өрісінің астында «Жуырдағы репозиторийлер» тізімі көрсетілуі мүмкін.

Ережелер:
* тізім тек тарихта жуырда клондалған репозиторийлер бар болса ғана пайда болады;
* тізімге тек репозиторий URL-дері қосылады;
* жергілікті қалталар бұл тізімге қосылмайды;
* қайталанулар жасалмайды — сол репозиторийді қайта клондау оны тізімнің жоғарғы жағына шығарады;
* соңғы 7 репозиторийге дейін сақталады;
* тарих қолданбаны қайта іске қосқаннан кейін де сақталады.

Тізімнен тармақты таңдасаңыз, URL енгізу өрісіне автоматты түрде қойылады.
Белсенді клондау кезінде тізім уақытша жасырылып тұрады.

## 6) Көшіру
### Ағаш пішімінің ауыстырғышы (ASCII / JSON / XML / MD)
Ауыстырғыш нәтиже құрамында ағаш бар операциялар үшін ағашты көрсету пішімін анықтайды.

* ASCII — бұтақтары бар мәтіндік ағаш.
* JSON — JSON форматындағы құрылымдалған ағаш.
* XML — парсерлер мен құралдарға арналған ықшам XML ағашы.
* MD — құжаттама мен AI prompt үшін Markdown кірістірілген тізімі.

Ауыстырғыш мынаған әсер етеді:
* Ағашты көшіру
* Ағаш + мазмұнды көшіру
* Ағашты экспорттау
* Ағаш пен мазмұнды экспорттау

Ауыстырғыш мынаған әсер етпейді:
* Мазмұнды көшіру
* Мазмұнды экспорттау

### Ағашты көшіру
Жоба ағашын көшіреді.
Егер белгіленген түйіндер болса, ағаш таңдау бойынша құрылады; таңдау бос немесе жарамсыз болса, толық ағаш көшіріледі.
Нәтиже пішімі ағаш пішімінің ауыстырғышымен анықталады.
Пернелер: Ctrl+Shift+C және Ctrl+Alt+C.

### Мазмұнды көшіру
Файлдардың мазмұнын көшіреді:
* егер файлдар белгіленсе — тек солар; әйтпесе — жобадағы барлық файлдар;
* мәтіндік емес файлдар еленбейді (бинарлықтарды қоса);
* бос мәтіндік файлдар үшін жолы және `[No Content, 0 bytes]` жолы шығарылады;
* тек бос орындар/жол тасымалдарынан тұратын файлдар үшін жолы және `[Whitespace, N bytes]` жолы шығарылады.
Перне: Ctrl+Alt+V.

### Ағаш + мазмұнды көшіру
Ағаш пен мазмұнды біріктіреді:
* ағаш таңдау бойынша; егер таңдау бос немесе жарамсыз болса — толық ағаш;
* мазмұн «Мазмұнды көшіру» ережелерімен алынады;
* ағаш блогының пішімі ағаш пішімінің ауыстырғышымен анықталады.
Перне: Ctrl+Shift+V.

### Ағаш көрсетілімдері
Ағаш пішімдері бір таңдалған жоба ағашын әртүрлі көрсетеді.

JSON:
* `rootPath` — `/` арқылы нормаланған абсолют түбір жолы.
* `tree` — түбір буманың мазмұны.
* JSON экспорты осы ағаш пішімін қолданады: массивтер файлдарды, объектілер ішкі бумаларды, `/` ағымдағы буманың файлдарын қамтиды, ал `[]` бос буманы білдіреді.

XML:
* түбір түйін — `<t r="...">`;
* бумалар — `<d n="...">`;
* файлдар — `<f>File.cs</f>`.

MD:
* `Root: ...` жолынан басталады;
* Markdown кірістірілген тізімін қолданады;
* бумалар `/` таңбасымен аяқталады.

Ағаш + мазмұн:
* таңдалған ағаш пішімі ағаш блогына қолданылады;
* мазмұн блогы мәтін күйінде қалады;
* мазмұн блогындағы файл тақырыптары `/` арқылы relative жолдарды пайдаланады;
* экспорт `.txt` ретінде сақталады.

## 7) Алдын ала қарау режимі
Жоғарғы панельдегі көз белгісі бар түйме немесе Ctrl+B арқылы ашылады.

Қорытынды нәтижені ағаштың жанындағы бөлек жұмыс аймағында көрсетеді. Бұл режим өзі ештеңені буферге көшірмейді және файлға экспорттамайды — ол тек көруге арналған.

Әдепкіде жұмыс аймағы былай ашылады:
* сол жақта — жоба ағашы;
* ортасында — превью аралы;
* оң жақта — егер ашық болса, параметрлер панелі.

Қолжетімді режимдер:
* Ағаш
* Мазмұн
* Ағаш және мазмұн

Көшіру және экспорттағы ережелер осы жерде де қолданылады:
* белгіленген түйіндер ескеріледі;
* таңдау бос болса, деректердің толық жиыны қолданылады;
* ағымдағы елемеу ережелері мен таңдау параметрлері қолданылады.

Қосымша:
* превьюдегі файлдар көлденең сызықтармен бөлінеді;
* скролл кезінде ағымдағы файл жолы жоғарыда бекітіліп тұрады;
* ағаш пен превью масштабы бөлек өмір сүре алады.
* алдын ала қарау режимінде «Көшіру» мәзіріне кірмей-ақ не толық ағымдағы нәтижені, не ағымдағы көрініп тұрған файл блогын көшіруге болады.

Түймелер:
* превьюдің жоғарғы аралының сол жағындағы көшіру түймесі — ағымдағы превью режимін көшіреді:
  * Ағаш
  * Мазмұн
  * Ағаш және мазмұн
* ағаш аралындағы X — ағашты жасырады да, тек превью аралын қалдырады;
* превьюдің жоғарғы аралындағы X — алдын ала қарау режимін толық жабады;
* файлдың бекітілген жоғарғы панеліндегі шағын көшіру түймесі — ағымдағы көрініп тұрған файл блогын превьюде көрсетілген күйінде көшіреді;
* көз белгісін қайта басу немесе Ctrl+B да алдын ала қарау режимін жабады.

Іздеу мен сүзгі превью ішінде ағаш аралы көрініп тұрған кезде қолжетімді.
Егер ағаш жасырылса, іздеу мен сүзгі тек превью режимінен шыққанға дейін уақытша қолжетімсіз болады.

## 8) Көрініс
### Масштаб
* Ctrl++ / Ctrl+= — үлкейту
* Ctrl+- — кішірейту
* Ctrl+0 — қалпына келтіру
* Ctrl + тінтуір дөңгелегі — курсор тұрған аралда бірқалыпты зум

Мінез-құлық:
* қалыпты режимде ағаш масштабталады;
* ағаш көрініп тұрған превью режимінде мәзірдегі үлкейту, кішірейту және қалпына келтіру ағаш пен превьюге бір уақытта қолданылады;
* Ctrl + тінтуір дөңгелегімен ағаш пен превью курсор орнына қарай тәуелсіз масштабталады;
* тек превью режимінде тек превью аралы ғана масштабталады.

Диапазон: 6–28, қалпына келтіру — 15.

### Ықшам режим
Интерфейсті тығыздайды: ағашта және баптауларда аралықтар азаяды.
Preview workspace белсенді болғанда ықшам режим автоматты түрде қосылады.

### Ағаш анимациясы
Ағаш жолдарына курсорды апарған кезде бірқалыпты жылжу анимациясын қосады.

### Ағаш қарпі
Ағаш қарпі «Көрініс → Ағаш қарпі» арқылы таңдалады.
«Әдепкі» стандартты ағаш қарпін қайтарады.
Таңдалған қаріп параметрлер панеліндегі «Қолдану» батырмасы басылғаннан кейін қолданылады.

## 9) Ағаш бойынша іздеу
Іздеу жолағын ашады, сәйкестіктерді белгілеп, навигация береді.
* Ctrl+F — көрсету/жасыру
* Enter — келесі нәтиже
* Shift+Enter — алдыңғы
* Esc — жабу

Іздеу тек керек бұтақтарды ашады; сұраныс тазаланса, ағаш жиналады (түбірден басқа).
Сәйкестіктер өте көп болса, интерфейс жауап беруін сақтау үшін қолданба авто-ашуды және жаппай ерекшелеуді шектеуі мүмкін.
Іздеу панелі жабылғанда, жабылу анимациясы аяқталғаннан кейін сұраныс тазартылады.

Шектеулер:
* іздеуді ашқанда сүзгі автоматты түрде жабылады;
* іздеу превью ішінде ағаш аралы көрініп тұрған кезде қолжетімді;
* ағаш жасырылса, іздеу уақытша қолжетімсіз.

## 10) Атау бойынша сүзгі
Сүзгіге сай түйіндер мен олардың ата‑аналарын көрсетеді. Жаңарту кешіктіріледі (debounce).
* Ctrl+Shift+N — сүзгіні көрсету/жасыру
* Esc — сүзгіні жабу

Шектеулер:
* сүзгіні ашқанда іздеу автоматты түрде жабылады;
* сүзгі превью ішінде ағаш аралы көрініп тұрған кезде қолжетімді;
* ағаш жасырылса, сүзгі уақытша қолжетімсіз.

## 11) Параметрлер
Оң жақта қолжетімді:
* Қолдану
* Елемеу
* Файл түрлері
* Жоғарғы деңгей қалталары

«Елемеу», «Файл түрлері» және «Жоғарғы деңгей қалталары» өзгерістері панельде дайындалып, «Қолдану» батырмасы басылғаннан кейін қолданылады.

Құсбелгі өзгергеннен кейін қолданба қолжетімді тармақтар мен олардың санағыштарын фонда жаңартуы мүмкін. Қорытынды ағаш «Қолдану» батырмасы басылғаннан кейін ғана қайта құрылады.

Қолжетімді параметрлерді жаңарту статус-жолақтағы X батырмасымен тоқтатылса, аяқталмаған өзгерістер қолданылмайды және панель соңғы аяқталған күйіне қайтарылады.

Әр тізімде Барлығы ауыстырғышы бар.

«Файл түрлері» туралы ескерту:
* бұл тізімде тек кеңейтімі бар файлдар көрсетіледі;
* кеңейтімсіз файлдар бұл тізімге қосылмайды және «Елемеу» бөліміндегі жеке тармақпен басқарылады.

Ctrl+P — панельді көрсету/жасыру.

### 11.1 Жергілікті жоба параметрлерінің профильдері
Жергілікті қалталар үшін DevProjex жобаның соңғы қолданылған параметрлерін сақтайды:
* таңдалған жоғарғы деңгей қалталары;
* таңдалған файл түрлері;
* «Елемеу» блогындағы таңдалған ережелер.

Сақтау «Қолдану» батырмасы басылғанда орындалады.
Сол жергілікті қалта қайта ашылғанда параметрлер автоматты түрде қалпына келтіріледі.

Маңызды:
* профильдер тек жергілікті жобалар үшін сақталады;
* Git Clone арқылы ашылған жобалар үшін профильдер сақталмайды;
* егер ағымдағы жобада сақталған кейбір тармақтар енді қолжетімді болмаса, олар өткізіліп, қалған параметрлер қолданылады.
* жаңарту немесе қайта ашу кезінде жаңа жоғарғы деңгей қалтасы, жаңа файл түрі немесе «Елемеу» бөлімінде жаңа тармақ пайда болса, ол әдепкі бойынша қосылады;
* бұрыннан белгілі тармақтар пайдаланушының нақты таңдауын сақтайды: өшірілген түрдің жаңа файлдары сол түрді қайта қоспайды.

## 12) Елемеу
«Елемеу» блогы ағаштан, мазмұннан, көшіру және экспорт нәтижелерінен қандай файлдар мен қалталар алынып тасталатынын басқарады.

Элемент тек жоғарғы деңгейдегі қалтасы мен файл түрі таңдалып, оны ешбір белсенді ереже жасырмаған кезде көрсетіледі. Ережелер бірге әрекет етеді: кемінде бір ереже элементті жасырса, басқа ереже оны қайта көрсете алмайды.

### 12.1 Қолжетімді ережелер
Жоба мазмұнына қарай Smart Ignore, «.gitignore пайдалану», «Тек Git бақылайтын файлдар», бос, жасырын немесе атауы нүктеден басталатын қалталар мен файлдар және кеңейтімсіз файлдар көрсетілуі мүмкін.

Git репозиторийінде «.gitignore пайдалану» және «Тек Git бақылайтын файлдар» тұрақты ауыстырып-қосқыш жұбы ретінде көрініп тұрады. Басқа тармақтар ағымдағы ағашты өзгерте алғанда ғана пайда болады. Сондықтан тізім басқа ереже, жоғарғы деңгей қалтасы немесе файл түрі ауыстырылғаннан кейін өзгеруі мүмкін. Жаңа тармақ алғаш пайда болғанда әдепкі бойынша қосылады; бұрын белгілі тармақ уақытша жоғалса да, пайдаланушы таңдауын сақтайды.

### 12.2 Smart Ignore
Smart Ignore тәуелділіктерді, build нәтижелерін, кэштерді және басқа қызметтік артефактілерді жасырады. DevProjex жоба түрін құрылым мен `.csproj`, `package.json`, `pyproject.toml`, `Cargo.toml` сияқты маркер файлдар арқылы анықтайды. Тиісті стек ережелері тек табылған жоба аймағында қолданылады және көрші басқа стек жобасына таралмайды.

`build`, `vendor`, `packages`, `cache`, `pkg`, `Library` сияқты екіұшты атаулар үшін қалта мазмұны да тексеріледі. Сондықтан кәдімгі пайдаланушы қалтасы тек атауына байланысты жасырылмайды. Кейбір тәуелділік қоймалары мен қызметтік қалталар айқын табылған жобадан тыс жерде де ішкі құрылымы бойынша танылады.

Үлкен пайдаланушы қалтасының әр каталогын қайта талдамау үшін жаңа жоба аймақтарын іздеу шектелген. Кәдімгі құрылымда іздеу таяз, ал танылған monorepo ішінде тереңірек. Аймақ табылғаннан кейін Smart Ignore оның бүкіл ішкі ағашына тереңдік шектеуінсіз қолданылады.

### 12.3 .gitignore пайдалану
Қосылғанда DevProjex тек түбірдегі файлды емес, барлық қолжетімді `.gitignore` файлдарын қолданады. Әр файл өзі орналасқан қалтаға және оның барлық қолжетімді ішкі қалталарына ғана әсер етеді; ата-аналық және көрші қалталарға әсер етпейді.

Нақты жол үшін ережелер ата-аналық `.gitignore` файлынан тереңірек файлдарға қарай, ал бір файл ішінде жоғарыдан төмен қарай өңделеді. Соңғы сәйкес ереже Git нәтижесін анықтайды.

`!` таңбасынан басталатын ереже тек өз аймағындағы бұрынғы Git елемеуін болдырмайды. Ата-аналық қалта әлі еленбесе, файлды қайтара алмайды. Толық еленген және қолжетімсіз қалта ішіндегі `.gitignore` өңделмейді.

Бұзылған немесе қолдау көрсетілмейтін жол жеке өткізіледі, қалған дұрыс ережелер жұмысын жалғастырады. Бұл тармақ тек жұмыс ағашындағы `.gitignore` файлдарына қатысты; `.git/info/exclude` және жаһандық Git ережелері қолданылмайды. Оқылатын Git индексі бар болса, бақыланатын файлдар `.gitignore` үлгісіне сәйкес келсе де көрінеді; индекс немесе Git CLI болмаса, DevProjex қауіпсіз түрде тек үлгілер бойынша өңдеуге оралады.

### 12.4 Тек Git бақылайтын файлдар
«Тек Git бақылайтын файлдар» ағаштың Git кезеңін әрбір оқылатын Git индексінде тіркелген жұмыс ағашындағы бар файлдардан құрады. Өзгертілген бақыланатын файлдар мен индекске қосылған жаңа файлдар қамтылады; бақыланбайтын файлдар алынып тасталады. Бұл `HEAD` күйінің немесе қашықтағы репозиторийдің тарихи суреті емес, ағымдағы жұмыс ағашы.

Әрбір қолжетімді кірістірілген репозиторий мен worktree кез келген қолжетімді кірістірілу деңгейінде дербес өңделеді. Еншілес репозиторий ата-аналық немесе көрші репозиторийдің бақыланатын жолдарын мұраламайды. Индексті қауіпсіз оқу мүмкін болмаса, қатаң режим оны `.gitignore` үлгілерін өңдеумен үнсіз алмастырмайды.

«.gitignore пайдалану» және «Тек Git бақылайтын файлдар» бір-бірін өзара жоққа шығарады: біреуін қосу екіншісін өшіреді. Профильдерді қолдайтын жергілікті жобаларда таңдалған режим жоғарғы деңгей қалталарымен, файл түрлерімен және басқа елемеу параметрлерімен бірге сақталады.

### 12.5 Git сүзгілеуі мен Smart Ignore байланысы
Таңдалған Git режимі мен Smart Ignore — тәуелсіз ауыстырып-қосқыштар. Алдымен әрбір қолжетімді Git аймағында Git режимі, содан кейін қалған элементтерге Smart Ignore, ең соңында базалық ережелер қолданылады.

Таңдалған Git режимі барлық Smart Ignore үміткерлерін қамтып тұрғанда Smart Ignore жасырын болып, Git режимі өзгертілгеннен кейін пайда болуы мүмкін. Git репозиторийінде екі Git режимі де тұрақты жұп ретінде көрініп тұрады.

`!` Git терістеуі тек Git нәтижесін болдырмайды; ол Smart Ignore немесе базалық ережені өшірмейді.

### 12.6 Базалық ережелер
Нүктеден басталу ережелері атауды, ал жасырын элемент ережелері жүйелік Hidden атрибутын тексереді. Платформаға қарай олар бір элементті немесе әртүрлі элементтерді сипаттауы мүмкін.

«Бос файлдар» 0 байт файлдарды, «Кеңейтімсіз файлдар» `Dockerfile`, `Makefile`, `README` сияқты файлдарды жасырады.

«Бос қалталар» логикалық бос қалталарды жасырады. Таңдалған файл түрлері мен барлық басқа ережелер қолданылғаннан кейін көрінетін файл немесе ішкі қалта қалмаса, қалта логикалық бос саналады. Сондықтан басқа ереже өзгергенде оның санағышы да өзгеруі мүмкін.

### 12.7 Санағыштар
Санағыш дискідегі физикалық санды емес, ағымдағы баптаулардағы ереженің тікелей үлесін көрсетеді. Бір элемент бір уақытта бірнеше қабаттасатын санағышқа жазылмайды.

Тұрақты рет: қалталар үшін `.gitignore`, Smart Ignore, атаудағы нүкте, Hidden атрибуты; файлдар үшін `.gitignore`, Smart Ignore, атаудағы нүкте, кеңейтімнің болмауы, бос файл, Hidden атрибуты. Бұл рет тек санағыштарға әсер етеді. Көріну үшін кез келген белсенді механизм элементті жасыра алады.

### 12.8 Өзгерістерді қолдану
Белгілерді ауыстыру алдымен қолжетімді параметрлер мен санағыштарды жаңартады. Соңғы ағаш «Параметрлерді қолдану» басылғаннан кейін қайта құрылады. Дайындау тоқтатылса, DevProjex соңғы толық аяқталған күйге оралады; жартылай есептелген ережелер қолданылмайды.

## 13) Ағаш пен метрикалар қалай есептеледі
Нәтижеге әсер етеді:
* таңдалған жоғарғы деңгей қалталары
* таңдалған файл түрлері
* елемеу ережелері
* белсенді сүзгі
* ағашта чекбокспен белгіленген түйіндер (таңдауға негізделген операциялар үшін)

Қолжетімсіз болса, түйін Қолжетімділік жоқ деп белгіленеді.

### 13.1 Статус-жолақтағы санағыштар нені көрсетеді
Статус-жолақта екі блок бар:
* Ағаш — ағаштың мәтіндік шығару метрикалары;
* Мазмұн — файл мазмұнының шығару метрикалары.

Пішім:
* Жолдар
* Таңбалар
* ~Токендер (шамамен)

Үлкен мәндер ықшам K/M форматында көрсетіледі.

Маңызды:
* «Жолдар» («Ағаш» блогында) — дискідегі файл саны емес, ағаштың қорытынды көрсетіліміндегі жолдар саны;
* бұл санға қалталар, файлдар және ағаштың қызметтік элементтері (мысалы, қолжетімсіз түйіндер) кіреді.

### 13.2 Метрикалар қалай есептеледі
Ағаш метрикалары:
* сол экспорт пайплайны құратын нақты ағаш мәтіні бойынша есептеледі;
* ағымдағы ағаш пішімін ескереді.

Мазмұн метрикалары:
* мазмұнды көшіру/экспорт ережелерімен бірдей есептеледі;
* бинарлық файлдар кірмейді;
* бос және тек бос орындардан тұратын файлдар сервистік маркерлер арқылы есептеледі (`[No Content, 0 bytes]`, `[Whitespace, N bytes]`).

### 13.3 Санағыштар қашан жаңарады
Қайта есептеу мына кезде орындалады:
* жобаны ашқаннан/жаңартқаннан кейін;
* параметрлерді қолданғаннан кейін (елемеу, файл түрлері, түбір қалталар);
* ағашта чекбокстар өзгергенде (debounce-пен);
* ағаш пішімі ауысқанда (ағаш қатысатын операциялар үшін).
* фондық есептеу тоқтатылса, келесі толық аяқталған қайта есептеуге дейін санағыштар 0 мәніне орнатылады.

## 14) Иконкалар
Таңдау тәртібі:
1) түйін түрі (қалта/файл)
2) нақты атау (ереже болса)
3) кеңейтім
4) әйтпесе — белгісіз

## 15) Тақырып және эффекттер
«Тақырып» бөлімінде ашық немесе қараңғы тақырыпты және бір фон эффектісін таңдауға болады:
* Мөлдірлік
* Бұлдырлату
* Mica

Эффекттер бір уақытта бірге қолданылмайды. Таңдалған эффектіні қайта басу оны өшіріп, кәдімгі мөлдір емес фонды қайтарады.

Қолжетімді параметрлер:
* Фон мөлдірлігі — Мөлдірлік және Бұлдырлату режимдерінде қолжетімді.
* Жоғарғы панель контрасты — preview, іздеу, сүзгі және ағаш пішімі командалары орналасқан негізгі панельді реттейді.
* Мәзір мөлдірлігі — негізгі мәзірге және оның ішкі мәзірлеріне бірдей қолданылады.
* Шекара көрінуі — интерфейс шекараларының айқындылығын реттейді.

Mica платформаның жүйелік материалын қолданады және фон мөлдірлігінің жеке параметрі жоқ. Таңдалған Бұлдырлату немесе Mica эффектісі қолжетімсіз болса, қолданба алдымен басқа жүйелік эффектіні қолданып көреді. Екеуі де қолжетімсіз болғанда ғана кәдімгі мөлдір емес фон қолданылады.

«Мөлдірлік» режимінде негізгі терезенің фоны мөлдір болып қалады. Мәзірлер, ішкі мәзірлер және басқа қалқымалы беттер, қолдау болса, Бұлдырлатуды қолданады, сондықтан олардың артындағы ағаш пен мазмұн оқуға кедергі келтірмейді.

## 16) Анықтама

### 16.1 Параметрлерді қалпына келтіру
Параметрлерді қалпына келтіру (Анықтама → Параметрлерді қалпына келтіру) тақырыпты, эффекттерді, ықшам режимді, ағаш анимациясын және интерфейс тілін әдепкі мәндерге қайтарады. Жоба профильдері, тарих және дискідегі файлдар өзгертілмейді.

### 16.2 Деректерді қалпына келтіру
Деректерді қалпына келтіру (Анықтама → Деректерді қалпына келтіру) жергілікті жоба параметрлерінің сақталған профильдерін жояды:
* таңдалған жоғарғы деңгей қалталары;
* таңдалған файл түрлері;
* «Елемеу» блогындағы таңдалған ережелер.

Маңызды:
* жергілікті қалталарға арналған «Жуырда ашылғандар» тарихы тазаланбайды;
* Git Clone терезесіндегі «Жуырдағы репозиторийлер» тарихы тазаланбайды;
* дискідегі жоба файлдары мен қалталары өзгертілмейді және жойылмайды.

## 17) Тілдер
Тіл мәзірі арқылы таңдалады.
Таңдалған тіл қолданба қайта іске қосылғанда сақталады. «Анықтама → Параметрлерді қалпына келтіру» сақталған тіл таңдауын тазалап, интерфейс тілін әдепкі мәнге қайтарады.

## 18) Прогресс-жолағы және болдырмау
Статус-жолақтың ортасында белсенді операция мен прогресс көрсетіледі.

Прогресс режимдері:
* Indeterminate — пайызсыз (операция ұзақтығы белгісіз).
* Determinate — пайызбен (0–100).

Мінез-құлық:
* деректерді фондық есептеу кезінде пайыздық прогресс көрсетіледі;
* кейбір Git операцияларында прогресс көзі пайыз берсе, пайыз көрсетіледі;
* қолжетімді параметрлерді жаңарту және баптауларды қолдану операция айтарлықтай уақыт алса көрсетіледі;
* жылдам операциялар прогресті көрсетпей аяқталады.

Статус-жолақтағы X (болдырмау) батырмасы:
* болдырмауды қолдайтын операцияларға best-effort болдырмау әрекетін орындайды;
* фондық дерек есептеуін тоқтатады;
* қолжетімді параметрлерді жаңарту тоқтатылғанда панельді соңғы аяқталған күйіне қайтарады;
* болдырмауды қолдамайтын операцияларда статус-жолақ индикациясын тоқтатады, ал операция фондық режимде аяқталуы мүмкін.

## 19) Ескертпелер
* Әдепкіде Бұлдырлату эффектісі бар қараңғы тақырып қолданылады. Бұлдырлату қолжетімсіз болса, қолданба Mica-ны қолданып көреді; екі эффект те қолжетімсіз болса, олар өшіріледі.
* Рұқсат жеткіліксіз болса, қолданба әкімші құқықтарымен қайта іске қосуды ұсынады; бас тартылса — хабарлама көрсетіледі.
