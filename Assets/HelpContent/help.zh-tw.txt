## 1) 它是什麼以及為什麼
DevProjex可快速準備專案上下文：顯示資料夾/檔案結構，讓您用核取方塊選取項目，並將樹和/或檔案內容複製到剪貼簿。適用於程式碼審查、技術支援、學習，以及與AI助理分享專案結構。

重要提示：DevProjex不會修改您開啟的專案中的檔案。唯一的例外是為Cursor或VS Code明確建立MCP連線，此時會建立或更新`.cursor/mcp.json`或`.vscode/mcp.json`（第19.1節）。

## 2) 專案樹
* 檔案/資料夾類型圖示。
* 節點上的核取方塊。
* 展開/折疊。

核取方塊：選取一個節點會套用到其子節點；父節點的狀態會自動重新計算。

快速鍵：
* {mod}E — 全部展開
* {collapseAll} — 全部折疊（根節點保持展開）

### 內容選單
在節點上按一下滑鼠右鍵，或在取得焦點的節點上按{shift}F10或選單鍵：
* 在檔案總管中顯示/在Finder中顯示/在檔案管理員中開啟 — 在系統檔案管理員中顯示該項目；標籤與目前平台一致。
* 複製完整路徑 — 項目的絕對路徑。
* 複製相對路徑 — 從專案根目錄開始、以根資料夾名稱開頭的路徑，例如`project/src/File.cs`。
* 複製內容 — 針對檔案：複製套用內容轉換後的內容，與複製和匯出產生的結果完全一致。
* 僅選取此項 — 只選取此節點並清除其餘選取；僅當還有其他項目被選取時才顯示。
* 展開分支/折疊分支 — 用於資料夾。

如果該路徑在磁碟上已不存在，在檔案管理員中開啟該項目或複製其內容會顯示錯誤訊息；複製路徑仍然可用。

## 3) 檔案
* 開啟資料夾… — 開啟根資料夾（{mod}O）
* 新視窗 — 開啟一個新的獨立DevProjex執行個體
* 最近使用 — 最近開啟的本機資料夾清單
* 重新整理 — 重新掃描本機資料夾並重建樹（F5）
* 匯出到檔案：
  * 匯出樹
  * 匯出內容
  * 匯出樹和內容
* 匯出專案：
  * 到資料夾…
  * 到ZIP壓縮檔…

「匯出專案」會根據目前的樹建立一個獨立的資料夾或ZIP壓縮檔，並保留目錄結構。

會遵循所選的檔案類型、排除規則和選取的項目。如果沒有選取任何項目，則匯出整個目前的樹。

文字檔和二進位檔都會被複製，包含在內的空資料夾也會保留。原始檔案不會被修改。結果不能儲存在原始專案內部。

匯出期間，您無法變更樹或設定、使用篩選、變更格式或預覽模式、執行Git命令、重新整理或開啟其他專案。

格式規則：
* 匯出樹：
  * ASCII -> 僅`.txt`。
  * JSON -> 預設`.json`，「儲存」對話方塊中可選`.json`和`.txt`。
  * XML -> 預設`.xml`，「儲存」對話方塊中可選`.xml`和`.txt`。
  * MD -> 預設`.md`，「儲存」對話方塊中可選`.md`和`.txt`。
* 匯出內容 — 一律為文字內容格式，`.txt`檔案（樹格式切換不適用）。
* 匯出樹和內容 — 一律為`.txt`檔案；所選樹格式只影響結果中樹區塊的格式。

匯出檔案以不含BOM的UTF-8編碼寫入。

### 拖放
未載入專案時，可在啟動區域（Drop Zone）中拖放。

規則：
* 可以拖放資料夾；
* 可以拖放檔案——此時會開啟其所在的資料夾；
* 如果拖放了多個項目，則使用第一個合適的本機路徑；
* 如果路徑無法使用或不存在，則執行與「開啟資料夾…」相同的存取檢查；
* 不支援的項目或非本機項目會被忽略。

### 最近使用
「檔案→最近使用」顯示最近開啟的本機資料夾的歷史記錄。

規則：
* 只有本機資料夾會被加入清單；
* 透過DevProjex克隆的Git儲存庫不會加入此清單；
* 不會產生重複項目——再次開啟同一資料夾會將其移到頂端；
* 最多儲存32個最近使用的資料夾；
* 歷史記錄在應用程式多次啟動之間保留。

每一項都會顯示上層資料夾和專案名稱，例如`Projects / App`。

## 4) 從終端機啟動
DevProjex提供互動式終端機工作區，以及適用於指令碼和CI的直接命令。

如果命令已設定，請開啟終端機並執行：
`devprojex --help`

此命令會列出最上層的命令和選項。執行`devprojex help <command>`可查看該命令本身的選項和範例。

範例：
* `devprojex` — 開啟互動式終端機工作區。在工作區中，可透過`:`命令列執行操作（例如`:copy`、`:analyze`、`:branch`、`:language`）；完整的命令清單請參閱內建的工作區說明和專案文件。
* `devprojex tui .` — 直接在終端機工作區中開啟指定的資料夾。
* `devprojex open . --preview` — 在桌面版的預覽中開啟目前的資料夾。
* `devprojex analyze . --format json` — 以JSON格式分析目前的專案。
* `devprojex tree .` — 將專案樹列印到終端機。
* `devprojex export context . --format markdown -o ../devprojex-context.md` — 在原始專案外部儲存可直接用於AI的上下文。
* `devprojex export project . --as folder -o ../devprojex-submission` — 將有效專案樹匯出到指定的資料夾。
* `devprojex export project . --as zip -o ../devprojex-submission.zip` — 將有效專案樹匯出為ZIP壓縮檔。
* `devprojex export context https://github.com/owner/repo -o -` — 打包遠端儲存庫，無需自行克隆。
* `devprojex analyze . --git-mode tracked --exclude smart-ignore` — 搭配智慧忽略分析已追蹤的Git檔案。
* `devprojex search Configure . --symbols` — 尋找宣告的定義位置；`--symbols`接受宣告名稱並拒絕規則運算式語法，而`--regex`則以規則運算式搜尋文字。
* `devprojex related src/App.cs` — 列出某個檔案使用的檔案，以及使用該檔案的檔案。
* `devprojex mcp --root .` — 啟動本機唯讀MCP伺服器，讓AI代理程式能安全地讀取專案。
* `devprojex mcp connect . --client claude-code` — 將AI用戶端連線到專案（第19節）。
* `devprojex mcp log . --last` — 顯示最近一次的代理程式日誌工作階段。

注意：
* `.`表示目前的終端機資料夾；
* 包含空格的路徑必須以引號括住；
* `--git-mode`可選擇`none`、`gitignore`、`tracked`、`staged`、`changes`或`diff:<ref>..<ref>`；
* `--exclude`獨立於Git篩選，單獨控制一般排除項目；
* 分析和匯出命令的結果是確定性的，而且不會開啟桌面版介面；
* `tui`、`open`、`analyze`、`search`、`tree`以及兩個`export`命令也接受Git儲存庫URL，`related`則透過`--project`接受URL；克隆會存入受管理的快取（`devprojex cache`）；
* 命令具有文件記載的別名和簡短選項——例如`export ctx`、`-f`、`-n`；`devprojex help`會列出它們；
* `analyze --findings`列出遮罩偵測結果但不顯示其值，`--fail-on-findings`會為CI傳回非零的結束代碼；
* `export context --max-tokens N`將上下文控制在詞元預算之內，實驗性的`--rank importance`會優先納入最重要的檔案；
* 分析、搜尋和匯出命令不會修改專案檔案——DevProjex以唯讀模式運作。

如果`devprojex`命令無法運作，請在DevProjex中開啟：
「說明→從終端機啟動」。

## 5) Git
「Git→克隆儲存庫…」會將儲存庫克隆到DevProjex快取中並開啟它。「分支」和「取得更新」僅適用於以這種方式克隆的專案。應用程式不會更動您的檔案——它只使用快取。

快取儲存在使用者的系統快取目錄中。執行`devprojex doctor`可查看解析後的路徑。

* 分支 — 顯示可用分支的清單並標示目前的分支；切換後，樹會更新為所選分支。如果分支已存在於本機，則離線切換（不更新）。如果本機不存在，則會擷取並建立該分支。
* 取得更新 — 僅更新目前的分支：執行fetch並重設為origin/<branch>。對於克隆的專案，F5執行相同的操作；一般的「檔案→重新整理」命令會停用。

### 克隆視窗
在克隆儲存庫視窗中，URL欄位下方可能會出現「最近的連結」清單。

規則：
* 僅當歷史記錄中已有最近克隆的儲存庫時，才會顯示該清單；
* 只有網路儲存庫來源（`https://`、`ssh://`以及SCP語法）會加入清單；
* 本機路徑和`file://`來源不會加入此清單；
* 不會產生重複項目——再次克隆同一儲存庫會將其移到頂端；
* 最多儲存16個最近的儲存庫；
* 歷史記錄在應用程式多次啟動之間保留。

選取某一項會自動填入URL欄位。
克隆進行期間，該清單會暫時隱藏。

## 6) 複製
### 樹格式切換（ASCII / JSON / XML / MD）
此切換決定樹作為輸出的一部分時所使用的表示格式。

* ASCII — 帶有分支線的文字樹。
* JSON — JSON格式的結構化樹。
* XML — 適用於剖析器和工具的精簡XML樹。
* MD — 適用於文件和AI提示詞的Markdown巢狀清單。

切換會影響：
* 複製樹
* 複製樹和內容
* 匯出樹
* 匯出樹和內容

切換不影響：
* 複製內容
* 匯出內容

### 複製樹
複製專案樹。
如果有選取的節點，則根據選取範圍建立樹；如果選取範圍為空或無效，則複製完整的樹。
結果格式由樹格式切換決定。
快速鍵：{mod}{shift}C和{mod}{alt}C。

### 複製內容
複製檔案內容：
* 如果選取了檔案，則只複製這些檔案；否則複製專案的所有檔案；
* 每個檔案前都有一個包含其完整本機路徑的標頭（對於克隆的專案，為儲存庫的Web路徑）；
* 非文字檔案（包括二進位檔案）會被忽略；
* 對於空的文字檔案，輸出路徑和`[No Content, 0 bytes]`行；
* 對於只包含空白/換行字元的檔案，輸出路徑和`[Whitespace, N bytes]`行。
快速鍵：{mod}{alt}V。

### 複製樹和內容
結合樹和內容：
* 樹根據選取範圍建立；如果選取範圍為空或無效，則使用完整的樹；
* 內容遵循與「複製內容」相同的規則；
* 樹區塊的格式由樹格式切換決定。
快速鍵：{mod}{shift}V。

### 樹表示法
不同的樹格式以不同方式表示同一棵所選的專案樹。

JSON：
* `rootPath` — 以`/`正規化的絕對根路徑。
* `tree` — 根資料夾的內容。
* JSON匯出使用這種樹格式：陣列包含檔案，物件包含子資料夾，`/`包含目前資料夾中的檔案，`[]`表示空資料夾。

XML：
* 根節點為`<t r="...">`；
* 資料夾為`<d n="...">`；
* 檔案為`<f>File.cs</f>`。

MD：
* 以`Root: ...`開頭；
* 使用Markdown巢狀清單；
* 資料夾以`/`結尾。

樹和內容：
* 所選樹格式套用於樹區塊；
* 內容區塊仍為文字；
* 內容區塊中的檔案標頭使用以`/`分隔的相對路徑；
* 匯出為`.txt`。

## 7) 預覽模式
使用頂端列中的眼睛圖示按鈕或{mod}B開啟。

滑鼠側鍵採用瀏覽器式的導覽：「前進」開啟預覽模式，「後退」關閉預覽模式。重複目前的方向不會有作用。

{mod}{shift}F在預覽中開啟或關閉檔案內容搜尋。Enter或F3移至下一個相符項目；{shift}Enter或{shift}F3移至上一個相符項目。

在樹旁邊的獨立工作區中顯示最終結果。此模式本身不會複製到剪貼簿，也不會匯出到檔案——它是一種檢視模式。

預設情況下，工作區的版面配置為：
* 左側 — 專案樹；
* 中間 — 預覽窗格；
* 右側 — 設定面板（如果之前已開啟）。

可用模式：
* 樹
* 內容
* 樹+內容

套用與複製和匯出相同的規則：
* 遵循選取的節點；
* 如果選取範圍為空，則使用完整的資料集；
* 套用目前的忽略規則和選取選項。

此外：
* 預覽中的檔案之間以水平線分隔；
* 捲動時，目前檔案的路徑會固定在頂端；按一下固定的路徑會捲回該檔案的開頭；
* 預覽捲軸會標示搜尋相符項目和含有遮罩偵測結果的行；按一下標記會跳到對應的行；保持原樣的偵測結果仍會被標示，被遮罩的路徑標頭會在其第一行加上一個標記；
* 樹和預覽可以分別縮放。
* 在預覽模式下，無需開啟「複製」選單即可複製完整的目前結果或目前可見的檔案區塊。

按鈕：
* 頂端預覽島左側的複製按鈕 — 複製目前預覽模式的內容：
  * 樹
  * 內容
  * 樹+內容
* 樹窗格中的X — 隱藏樹，只保留預覽窗格；
* 頂端預覽窗格中的X — 完全關閉預覽模式；
* 固定檔案標頭中的小型複製按鈕 — 依照預覽中顯示的樣子複製目前可見的檔案區塊；
* 再按一次眼睛圖示或按{mod}B也會關閉預覽模式。

預覽中樹窗格可見時，可以使用搜尋和篩選。
如果樹被隱藏，搜尋和篩選會暫時無法使用，直到您離開僅預覽模式。

## 8) 檢視
### 縮放
* {mod}+ / {mod}= — 放大
* {mod}- — 縮小
* {mod}0 — 重設
* {mod}+滑鼠滾輪 — 平滑縮放游標下方的窗格

行為：
* 在一般模式下，縮放樹；
* 在樹可見的預覽中，選單中的「放大」、「縮小」和「重設縮放」會同時作用於樹和預覽；
* 使用{mod}+滑鼠滾輪時，樹和預覽會依游標所在位置分別縮放；
* 在僅預覽模式下，只縮放預覽窗格。

範圍：6–28，重設值為15。

### 緊湊模式
讓介面更緊湊：樹和設定中的間距更小。
預覽工作區處於使用中時，會自動啟用緊湊模式。

### 動畫
「檢視→動畫」可分別控制樹展開、狀態計數器和工具首次顯示的動畫。三種動畫預設皆已啟用；停用某種動畫後，會立即顯示其最終狀態。

### 樹字體
透過「檢視→樹字體」選擇樹字體。
「預設」會還原標準樹字體。
在設定面板中按一下「套用設定」後，所選字體才會生效。

### 代理程式活動
開啟「檢視→代理程式活動」即可查看即時AI代理程式收到了哪些檔案：這些檔案會在樹中帶有✦標記（第19.4節）。

## 9) 搜尋（樹）
開啟搜尋列，醒目提示相符項目並支援在其間導覽。
* {mod}F — 顯示/隱藏
* Enter — 下一個結果
* {shift}Enter — 上一個結果
* Esc — 關閉

搜尋只會展開所需的分支；清除查詢會折疊樹（根節點除外）。
相符的行也會標示在樹的捲軸上；按一下標記即可跳到該相符項目。
相符項目非常多時，應用程式可能會限制自動展開和全域醒目提示，以保持介面回應。
關閉搜尋列時，查詢會在關閉動畫完成後清除。

限制：
* 開啟搜尋會自動關閉篩選；
* 預覽中樹窗格可見時，可以使用搜尋；
* 如果樹被隱藏，搜尋暫時無法使用。

## 10) 篩選（依名稱）
只顯示符合篩選字串的節點及其父節點。更新會經過防彈跳處理。
* {mod}{shift}N — 顯示/隱藏篩選
* Esc — 關閉篩選

限制：
* 開啟篩選會自動關閉搜尋；
* 預覽中樹窗格可見時，可以使用篩選；
* 如果樹被隱藏，篩選暫時無法使用。

## 11) 選項（設定面板）
位於右側：
* 套用設定
* 內容處理
* 排除項目
* 檔案類型

「排除項目」和「檔案類型」中的變更會先暫存在面板中，按一下「套用設定」後才會套用。

核取方塊變更後，應用程式可能會在背景更新可用的選項及其計數。只有按一下「套用設定」後才會重建最終的樹。

如果使用狀態列中的X按鈕取消可用選項的更新，未完成的變更不會被套用，面板會還原到上次完成的狀態。

每個清單都有「全部」切換開關。

關於「檔案類型」的說明：
* 此清單只顯示有副檔名的檔案；
* 沒有副檔名的檔案不會加入此清單，而是由「排除項目」中的單獨選項控制。

內容處理：
* 轉換所選文字檔案的內容，而不變更樹；
* 「隱藏機密資訊」和「隱藏個人資料」會取代偵測到的值（第12.3節和第12.4節）；
* 「壓縮程式碼」在14種語言中保留宣告，同時精簡具名的實作；
* 「移除註解」在20個語言套件中刪除註解和文件註解；
* 「移除空白行」在同樣的語言套件中刪除只含空白的行，同時保留多行常值；
* 變更會在按一下「套用設定」後生效。

{mod}P — 顯示/隱藏面板。

### 11.1 本機專案參數設定檔
對於本機資料夾，DevProjex會記住上次套用的專案參數：
* 所選的檔案類型；
* 「排除項目」區段中所選的選項。

按一下「套用設定」時會進行儲存。
再次開啟同一本機資料夾時，會自動還原這些參數。

重要：
* 只為本機專案儲存設定檔；
* 對於透過克隆開啟的專案，不儲存設定檔；
* 如果某些已儲存的選項在目前的專案中已無法使用，則略過這些選項，並套用其餘參數。
* 如果重新整理或重新開啟後在「排除項目」中出現新的檔案類型或選項，則預設為啟用；
* 已出現過的選項會保留使用者的明確選擇：被停用類型的新檔案不會讓該類型重新啟用。

## 12) 排除項目
「排除項目」區段控制要從樹、內容、複製和匯出結果中排除哪些檔案和資料夾。

只有同時符合以下所有條件時，項目才會顯示：
* 如果檔案有類型，其檔案類型已被選取；
* 沒有任何已啟用的忽略規則將其排除。

忽略規則是累積的。只要有一條已啟用的規則隱藏了某個項目，其他規則就無法讓它重新顯示。

### 12.1 可用規則
視專案內容而定，可能會顯示以下選項：

* 智慧忽略
* 空資料夾
* 空檔案
* 隱藏資料夾
* 隱藏檔案
* 點資料夾
* 點檔案
* 沒有副檔名的檔案

當Git篩選不適用時（不存在儲存庫邊界，而且`.gitignore`篩選無法改變目前的樹），GUI選取器和TUI中的Git軸選項列會完全隱藏。在儲存庫之外仍顯示該軸時，GUI只提供不篩選和`.gitignore`，而TUI會停用需要儲存庫的列。在Git儲存庫中有五個一般值：不篩選、`.gitignore`、已追蹤的檔案、已暫存的檔案和所有目前的變更；在TUI中，使用中的`diff:<ref>..<ref>`範圍會顯示為第六列。選取一個值只會取代目前的Git模式，不會變更智慧忽略或基本排除項目。其他選項會在其規則可能改變目前的樹時顯示，因此在切換其他規則或檔案類型後，清單可能會改變。

新選項首次出現時預設為啟用。已知的選項即使暫時從清單中消失，也會保留使用者的選擇。

### 12.2 智慧忽略
智慧忽略（Smart Ignore）會隱藏相依性、建置輸出、快取以及其他專案服務產物。

DevProjex會先根據專案結構和標記檔案識別專案類型，例如：

* `.csproj`
* `package.json`
* `pyproject.toml`
* `Cargo.toml`

接著在偵測到的專案範圍內套用對應技術堆疊的規則。例如，.NET規則不會延伸到相鄰的Python或JavaScript專案中。

僅憑資料夾名稱並不一定足夠。`build`、`vendor`、`packages`、`cache`、`pkg`或`Library`等含義模糊的名稱還會依其內容加以驗證。這可以避免一般使用者資料夾只因名稱相似而被隱藏。

即使在明確偵測到的專案之外，某些相依性存放區和服務目錄也能依其特有的內部結構被識別出來。

專案範圍的探索是有上限的，因此載入大型使用者資料夾不會變成對每個目錄的完整重複分析。一般結構使用淺層探索，而已識別的單一存放庫（monorepo）會進行更深的搜尋。找到範圍後，智慧忽略會套用於其整個子樹，不受深度限制。

### 12.3 隱藏機密資訊
「隱藏機密資訊」預設為關閉。它只掃描所選的文字內容，並就地取代每個偵測到的值，同時保留檔案及其周圍的程式碼。此選項關閉時不會進行掃描，也不顯示計數。掃描目前的選取範圍後，標籤會顯示偵測到的值的數量；如果「保持原樣」的決定使隱藏的值變少，則顯示「偵測到/已隱藏」，該列的「?」指示器會回報這兩個計數。

被遮罩的範圍會在預覽中醒目提示。按一下其中一處可僅將該處保持原樣；{alt}↓ / {alt}↑在偵測結果之間移動，Enter切換目前的結果。在終端機工作區中，使用`[`和`]`在各處之間移動，使用`Enter`或`Space`切換目前的結果。此決定適用於目前工作階段中的預覽、剪貼簿、上下文匯出、資料夾副本和ZIP，但不會儲存到專案設定檔中。

預覽的內容選單擴充了這些決定。在偵測到的某處上按一下滑鼠右鍵，可一次將同一規則的所有結果或同一檔案中的所有偵測結果保持原樣或重新隱藏。要手動標記檔案內容中選取的值，請在該值上按一下滑鼠右鍵：「在此處隱藏…」只在目前工作階段中隱藏這一處，「始終隱藏…」為該值的每次出現建立持久標記，「將…隱藏為個人資料」則建立由「隱藏個人資料」控制的持久標記。「移除標記」會出現在手動標記上並將其刪除；偵測器仍能比對到的值會繼續隱藏。手動標記的值必須是在檔案內容中選取的單行文字，長度為8到512個字元。建立標記會自動啟用對應的選項。持久標記只儲存經過金鑰處理的值識別及其類別，絕不儲存原始文字。

資料夾或ZIP副本也會變更相符的文字，因此可能無法再建置或執行。二進位檔案會原樣複製，而且不會被掃描。超過16 MiB的所選文字檔案會被略過並回報，其餘輸出仍會完成。偵測失敗會中止整個操作。

計數只回報規則比對結果。計數為零並不代表專案是安全的。CLI使用`--hide-secrets`；技術細節和限制請參閱`Docs/HideSecrets.md`。

### 12.4 隱藏個人資料
「隱藏個人資料」預設為關閉。它會偵測所選文字檔案中的電子郵件地址、全域IP位址、路徑中的本機使用者名稱、MAC位址和國際電話號碼。偵測結果使用與「隱藏機密資訊」相同的預覽決定和輸出管線；透過「將…隱藏為個人資料」建立的手動標記也屬於此類，並受此開關控制（第12.3節）。產生的路徑標頭和樹根中的本機使用者名稱會作為一個共用結果被遮罩：計數器將其計為一個值，「?」指示器回報它是隱藏還是顯示，按一下即可切換所有被遮罩的路徑。

文件專用的位址範圍和主機、常見的CI使用者名稱、知名的公用DNS解析器，以及文件中記載的虛構電話號碼段會保持可見。零相符並不代表隱私獲得保證。CLI使用`--hide-private-data`；完整規則和第一階段的限制請參閱`Docs/HidePrivateData.md`。

### 12.5 使用.gitignore
啟用後，DevProjex會遵循`git status`的工作樹檢視：已追蹤的檔案保持可見，未追蹤的檔案只要沒有被儲存庫的忽略規則排除就會顯示。它會套用每個可存取的`.gitignore`，而不只是開啟的資料夾根目錄下的那一個，其中也包括其上方直到儲存庫根目錄的檔案。

每個`.gitignore`適用於：

* 包含它的資料夾；
* 其下方所有可存取的資料夾；
* 而且僅限於該範圍之內。

巢狀`.gitignore`中的規則不會影響上層資料夾或同層資料夾。

對於特定路徑，規則會從上層的`.gitignore`往更深層的檔案依序處理。在同一個檔案中，規則從上到下處理。最後一條相符的規則決定Git結果。

以`!`開頭的規則只會在其範圍內取消先前的Git排除。只要上層資料夾仍被排除，它就無法還原其中的檔案。位於完全被排除且無法存取之資料夾中的`.gitignore`不會參與計算。

格式錯誤或不受支援的行會被個別略過。該檔案中的其他有效規則以及相鄰範圍中的規則仍會繼續生效。

儲存庫本機的`.git/info/exclude`檔案同樣會被套用，其優先順序低於根目錄的`.gitignore`。帶有自己`.git`的巢狀資料夾同樣遵循`git status`：未在`.gitmodules`中宣告的內嵌儲存庫是不透明的，因此不會顯示其中的檔案；而已宣告的子模組會套用其自身的`.gitignore`和`info/exclude`。選擇`none`可查看內嵌儲存庫中的檔案。全域Git排除規則（`core.excludesFile`）不會被套用；儲存庫實際生效的路徑比較設定會受到遵循，例如`core.ignoreCase`，以及macOS上的`core.precomposeUnicode`。名為`.gitignore`的符號連結不會被追蹤，這與Git對控制檔案的處理方式一致。如果某個`.gitignore`或`info/exclude`檔案無法讀取，其目錄範圍會以失敗即關閉的方式被排除，掃描會回報部分存取，而不是在規則未完整計算的情況下悄悄納入檔案。當路徑所屬儲存庫範圍的索引可讀取時，已追蹤的檔案即使符合`.gitignore`也仍然可見；如果沒有該索引或Git CLI，該範圍會安全地退回到僅依模式計算。

內建的`standard`設定檔會選取`gitignore`，以及`smart-ignore`、`hidden-folders`、`hidden-files`、`dot-folders`、`dot-files`、`empty-folders`、`empty-files`和`extensionless-files`。

### 12.6 僅已追蹤的Git檔案
「僅已追蹤的Git檔案」會根據每個可讀取的Git索引中記錄、且實際存在的工作樹檔案建立樹的Git階段。已修改的已追蹤檔案和已暫存的新增檔案仍會包含在內；未追蹤的檔案會被排除。這是目前的工作樹，而不是`HEAD`或遠端儲存庫的歷史快照。

每個儲存庫都獨立解析：開啟的資料夾中的同層儲存庫和已宣告的子模組各自使用自己的索引，子儲存庫不會從其上層或同層儲存庫繼承已追蹤的路徑。未在`.gitmodules`中宣告的內嵌儲存庫保持不透明，與`.gitignore`模式相同。此模式需要Git CLI；可讀取的空索引也是有效的。如果終端機工作區（TUI）以此模式啟動且無法載入適用的索引，則工作區不會開啟。如果在已開啟的TUI工作區中以互動方式選取此模式且無法載入適用的索引，則變更會被拒絕，最後一個可用的Git模式會保持使用中。在同樣的情況下，直接命令會傳回原則失敗或檢查失敗。DevProjex絕不會悄悄退回到`.gitignore`。如果另一個適用的索引可讀取，則無法使用的巢狀範圍會被排除並顯示警告。

在已開啟的桌面版工作區中，明確選取的已追蹤模式會保持可見，並以失敗即關閉的方式運作：準備失敗時會封鎖輸出和匯出，部分準備完成時則會繼續並顯示當地語系化的警告。

各Git模式互斥；`none`會停用Git篩選。暫時性的`staged`、`changes`和`diff:<ref>..<ref>`模式不會儲存到設定檔中。暫時性模式使用中時，GUI的本機專案設定檔會保留上次啟用的持久模式`gitignore`或`tracked`。只有在儲存時`none`本身處於使用中，才會儲存`none`。暫時性模式使用中時，TUI和CLI會拒絕儲存可攜式設定檔。

### 12.7 Git篩選與智慧忽略的關係
所選的Git模式和智慧忽略是彼此獨立的控制項。Git模式會先在每個可存取的Git範圍內套用，接著由智慧忽略處理剩餘的項目，最後執行基本規則。

當所選的Git模式已經涵蓋智慧忽略的所有候選項目時，智慧忽略選項可能保持隱藏，並在變更或清除Git模式後出現。在Git儲存庫中，所有以儲存庫為基礎的Git模式都可使用。

以`!`開頭的Git否定規則只會取消Git結果，不會停用智慧忽略或基本規則。

### 12.8 基本規則
「點資料夾」和「點檔案」檢查項目名稱。

「隱藏資料夾」和「隱藏檔案」檢查系統隱藏屬性。在某些平台上，以點開頭的名稱和系統屬性可能描述同一個項目，也可能描述不同的項目。

「空檔案」會隱藏大小為0位元組的檔案。

「沒有副檔名的檔案」會隱藏`Dockerfile`、`Makefile`和`README`之類的檔案。

「空資料夾」會隱藏邏輯上為空的資料夾。如果在套用所選檔案類型和所有其他規則後，資料夾中不再有可見的檔案或子資料夾，則該資料夾在邏輯上為空。

因此，切換其他規則後，空資料夾的計數可能會改變：隱藏檔案可能會讓包含它們的資料夾在邏輯上變為空。

### 12.9 計數器
規則旁的計數顯示該規則在目前設定下的直接貢獻，而不是磁碟上同類項目的實際數量。

同一個項目不會同時計入多個重疊的計數器。例如，`.git`資料夾可能同時具有以點開頭的名稱和系統隱藏屬性，但它的排除只歸屬於一條規則。

選擇排除的歸屬規則時使用固定的順序：

* 資料夾：`.gitignore`、智慧忽略、以點開頭的名稱、系統隱藏屬性；
* 檔案：`.gitignore`、智慧忽略、以點開頭的名稱、無副檔名、空檔案、系統隱藏屬性。

此順序只影響計數器。最終的可見性遵循更簡單的規則：只要任何已啟用的機制排除了某個項目，該項目就會被隱藏。

### 12.10 套用變更
切換核取方塊會先更新面板中的可用設定和計數器。選擇「套用設定」後才會重建最終的樹。

如果設定準備被取消，DevProjex會將面板還原到上次完全完成的狀態。部分計算的規則不會被套用。

## 13) 樹和指標的計算方式
結果取決於：
* 所選的檔案類型
* 忽略規則
* 目前的篩選
* 樹中選取的節點（用於以選取範圍為基礎的操作）

如果存取被拒，節點會保留其一般的名稱和圖示，並加上「[拒絕存取]」後綴。

### 13.1 狀態列計數器顯示的內容
狀態列有兩個區塊：
* 樹 — 樹文字輸出的指標；
* 內容 — 匯出的檔案內容輸出的指標。

格式：
* 行數
* 字元
* ≈詞元（近似值）

較大的值會以精簡後綴（K/M）顯示。

重要：
* 「樹」區塊中的「行數」表示最終樹表示中的行數，而不是磁碟上的檔案數；
* 此值包含資料夾、檔案和樹的服務元素（例如拒絕存取的節點）。

### 13.2 指標的計算方式
樹指標：
* 依據同一匯出管線產生的實際樹輸出計算；
* 遵循目前的樹格式。

內容指標：
* 遵循與內容複製/匯出相同的規則；
* 排除二進位檔案；
* 空檔案和只含空白的檔案會透過服務標記計數（`[No Content, 0 bytes]`、`[Whitespace, N bytes]`）。

### 13.3 計數器何時更新
在下列情況下會重新計算：
* 開啟/重新整理專案後；
* 套用設定（排除項目和檔案類型）後；
* 樹的核取方塊變更時（含防彈跳）；
* 切換樹格式時（針對使用樹輸出的操作）。
* 背景計算被取消時，計數器會設為0，直到下一次重新計算完成。

## 14) 圖示
圖示選擇順序：
1) 節點類型（資料夾/檔案）
2) 完整名稱（如果有對應規則）
3) 副檔名
4) 否則為未知

## 15) 主題和效果
「主題」區段可選擇系統、淺色或深色，以及一種背景效果：
* 透明度
* 模糊
* Mica

預設選擇「系統」，並跟隨作業系統的主題變更。首次啟動或重設設定後，淺色系統主題會以一般不透明背景啟動，深色系統主題則以「模糊」啟動。如果無法判斷系統偏好，DevProjex會使用「深色」加「模糊」。淺色和深色會分別記住各自的效果。明確選擇淺色或深色後，會忽略系統的變更，直到再次選擇「系統」。

各效果互斥。再按一下已選取的效果會將其停用，並還原一般的不透明背景。

可用設定：
* 背景透明度 — 適用於「透明度」和「模糊」。
* 頂欄對比度 — 調整包含預覽、搜尋、篩選和樹格式命令的主面板。
* 選單透明度 — 同樣作用於主選單及其子選單。
* 邊框可見性 — 調整介面邊框的顯示強度。

Mica使用平台的系統材質，沒有單獨的背景透明度設定。如果所選的「模糊」或Mica效果無法使用，應用程式會先嘗試另一種原生效果。只有在「模糊」和Mica都無法使用時，才使用一般的不透明背景。

在「透明度」模式下，主視窗背景保持透明。選單、子選單和其他快顯介面在支援時會使用「模糊」，以免其後方的樹和內容元素影響可讀性。

## 16) 說明

### 16.1 更新
「說明→更新」會將目前版本與GitHub上最新的穩定版本進行比較。自動檢查預設為關閉；啟用後，DevProjex會在距上次成功檢查至少7天後於啟動時檢查。此核取方塊會立即生效。最近一次成功的結果會在應用程式多次執行之間保留，不會被之後的網路故障清除。安裝仍由使用者執行。

### 16.2 重置設定
重置設定（說明→重置設定）會還原預設的主題、效果、緊湊模式、動畫設定和介面語言。專案設定檔、歷史記錄和磁碟上的檔案不會變更。

### 16.3 重置資料
重置資料（說明→重置資料）會刪除已儲存的本機專案參數設定檔：
* 所選的檔案類型；
* 「排除項目」區段中所選的選項；
* 所選的內容處理設定；
* 手動機密標記。

它還會清除已完成的代理程式日誌工作階段（第19.3節）；使用中的工作階段會保留。

重要：
* 本機資料夾的「最近使用」歷史記錄不會被清除；
* 克隆儲存庫視窗中的「最近的連結」歷史記錄不會被清除；
* 磁碟上的檔案和資料夾不會被修改或刪除。

## 17) 語言
透過「語言」選單選擇語言。
所選語言會在多次啟動之間保留。「說明→重置設定」會清除已儲存的語言選擇，並將介面語言還原為預設值。

## 18) 進度列和取消
狀態列中間會顯示目前的操作及其進度。

進度模式：
* 不確定 — 不顯示百分比（操作持續時間未知）。
* 確定 — 顯示百分比（0–100）。

行為：
* 背景資料計算期間會顯示百分比進度；
* 對於某些Git操作，當進度來源提供百分比時會顯示百分比；
* 當可用選項的更新和設定的套用耗時明顯時，會顯示對應的進度；
* 快速的操作完成時不顯示進度。

狀態列中的X按鈕（取消）：
* 對支援取消的操作盡力取消；
* 停止背景資料計算；
* 取消可用選項的更新時，將面板還原到上次完成的狀態；
* 對於不支援取消的操作，它只會停止狀態列中的指示，操作本身仍可能在背景完成。

## 19) MCP與AI代理程式
DevProjex內建本機唯讀MCP伺服器。Claude Code、Codex、Cursor和VS Code等AI代理程式會透過它讀取專案：機密資訊遮罩永遠開啟，代理程式無法變更專案檔案。伺服器提供八個工具：`list_projects`、`get_tree`、`analyze`、`search_project`、`related_files`、`get_file`、`pack_context`和`read_pack`。

### 19.1 連線用戶端
MCP選單包含：
* Live context — 伺服器會跟隨此視窗中選取的項目（第19.2節）；
* 標準 — 伺服器不依賴視窗中的選取範圍；
* 日誌… — 代理程式請求和收到的內容（第19.3節）；
* 文件 — 開啟MCP伺服器文件。

Live context和「標準」包含相同的操作——「在 Claude Code 中開啟」、「在 Codex 中開啟」、「在 Cursor 中開啟」、「在 VS Code 中開啟」和「其他用戶端…」，這些操作在開啟專案後可以使用。

Claude Code和Codex會透過其已安裝的命令完成註冊，接著用戶端會在專案資料夾的新終端機中開啟。Cursor和VS Code會收到專案本機的`.cursor/mcp.json`或`.vscode/mcp.json`；該檔案中的其他伺服器會被保留。「其他用戶端…」會顯示適用於Claude Desktop和其他用戶端的現成設定。如果缺少用戶端命令或連線失敗，DevProjex會改為顯示手動設定。連線成功後，DevProjex可能會提議將`devprojex`命令加入PATH。

Codex只保留一個共用的DevProjex連線，因此連線另一個專案時會先詢問是否取代。已在執行的用戶端工作階段必須重新啟動才能載入伺服器。在終端機中，`devprojex mcp connect`預設註冊標準模式；加上`--mode live`可使用Live context，加上`--print`則只列印設定。

### 19.2 Live context
在Live context中，樹中選取的項目決定代理程式的關注範圍：樹、搜尋、分析、相關檔案和打包請求都限定在這些項目之內。視窗的篩選條件——檔案類型、排除項目和Git模式——構成存取邊界：代理程式仍可依名稱開啟其他檔案，但只能是這些篩選條件允許的檔案。

視窗不需要保持開啟。伺服器在每次請求時都會讀取為該專案最後儲存的選取範圍，因此新勾選的項目和已套用的設定會在代理程式的下一次請求中生效，無需重新啟動代理程式。

即時工作階段使用中時，視窗標題結尾會顯示`· Live context (<client>)`；如果有多個使用中的工作階段，則顯示工作階段的數量。

### 19.3 日誌
「MCP→日誌…」會顯示代理程式透過DevProjex請求和收到的內容：工作階段及其用戶端、模式、呼叫次數、字元數、估計詞元數、已交付的檔案和已遮罩的值，以及所選工作階段的各次呼叫。未開啟專案時也可以使用；開啟專案後，預設會選取「僅目前專案」。

日誌只儲存在本電腦上的DevProjex狀態資料夾中，最多保留200個工作階段，保存30天。它不會儲存檔案內容、偵測到的機密值或搜尋查詢的文字。「匯出…」會將工作階段儲存為Markdown或JSON收據。「清除」會在確認後刪除已完成的工作階段；使用中的工作階段以及與其他專案共用的工作階段會被保留。

### 19.4 代理程式活動
「檢視→代理程式活動」預設為關閉：選取該項即可開啟標記，再次選取即可關閉。開啟此項且有即時工作階段處於使用中時，代理程式在該工作階段中收到其內容的每個檔案——整個檔案、某個行範圍、搜尋相符行或某個宣告——都會在樹中以✦標示。代理程式僅在樹狀清單或大小估算中看到的檔案不會被標示。將滑鼠游標停在✦上即可查看代理程式收到該檔案的次數，例如「代理程式已收到 3 次」。

這些標記只表示已傳送的內容：它們絕不會變更核取方塊、篩選條件或代理程式可讀取的範圍。當新的即時工作階段開始、即時工作階段結束、代理程式活動被關閉或專案被重新開啟時，標記會被清除；之後代理程式收到的檔案會重新被標示。標準工作階段會出現在日誌中，但不會加上標記。

在終端機工作區中，`:set activity on`會在樹中以A標示同樣的檔案；焦點位於此類檔案時，狀態列會顯示代理程式收到該檔案的次數；`:set activity off`會移除標記。

## 20) 注意事項
* 如果權限不足，應用程式可能會建議以提升的權限重新啟動；如果拒絕，則會顯示一則通知。
