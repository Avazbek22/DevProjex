## 1) 它是什麼以及為什麼
DevProjex快速準備項目上下文：顯示資料夾/檔案結構，讓您可以選擇具有複選框的項目，並將樹和/或檔案內容複製到剪貼簿。對於程式碼審查、支援、學習以及與 AI 助理共享專案結構非常有用。

重要提示： DevProjex不會修改您開啟的專案中的檔案。

## 2) 項目樹
* 文件/資料夾類型圖示。
* 節點上的複選框。
* 展開/折疊。

複選框：選擇節點適用於其子節點；父狀態會自動重新計算。

熱鍵：
* {mod}E — 全部展開
* {collapseAll} — 全部折疊（根保持展開狀態）

### 內容選單
右鍵點選節點，或按聚焦節點上的{shift}F10 或選單鍵：
* 在檔案總管中顯示/在 Finder 中顯示/在檔案管理器中開啟 — 顯示系統檔案管理器中的項目；此標籤與目前平台相符。
* 複製完整路徑 — 專案的絕對路徑。
* 複製相對路徑 - 從專案根目錄開始的路徑，以根資料夾名稱開頭，例如`project/src/File.cs` 。
* 複製內容 - 對於文件：使用應用程式的內容轉換複製內容，與複製和匯出產生的內容完全相同。
* Select only this — 僅選取此節點並清除其餘節點；僅當也檢查了另一個項目時才顯示。
* 展開分支/折疊分支 — 用於資料夾。

如果磁碟上不再存在該路徑，則在檔案管理器中開啟該專案或複製其內容會顯示錯誤訊息；路徑複製仍然有效。

## 3) 文件
* 開啟資料夾... — 開啟根資料夾 ( {mod}O)
* 新視窗 — 開啟一個新的獨立DevProjex實例
* 最近 — 最近開啟的本機資料夾列表
* 刷新 — 重新掃描本機資料夾並重建樹 (F5)
* 匯出到文件：
  * 導出樹
  * 匯出內容
  * 匯出樹和內容
* 出口項目：
  * 到資料夾...
  * 至ZIP存檔...

匯出專案從目前樹建立一個單獨的資料夾或ZIP存檔，同時保留目錄結構。

尊重選定的文件類型、排除規則和選取的項目。如果未檢查任何內容，則匯出整個目前樹。

複製文字和二進位文件，並保留包含的空資料夾。來源文件沒有被修改。結果無法保存在來源項目中。

匯出期間，您無法變更樹或設定、使用篩選器、變更格式或預覽模式、執行Git命令、重新整理或開啟其他項目。

格式規則：
* 導出樹：
  * 僅限 ASCII -> `.txt` 。
  * JSON -> 預設`.json` ， `.json`和`.txt`在「儲存」對話方塊中均可使用。
  * XML -> 預設`.xml` ， `.xml`和`.txt`在「儲存」對話方塊中皆可使用。
  * MD -> 預設`.md` ， `.md`和`.txt`在「儲存」對話方塊中均可使用。
* 匯出內容 — 永遠為文字內容格式， `.txt`檔案（樹格式切換不適用）。
* 匯出樹與內容 — 始終為`.txt`檔案；所選的樹格式僅影響結果內的樹塊格式。

匯出檔案以 UTF-8 無 BOM 格式編寫。

### 拖放
當沒有載入項目時，拖放可以在啟動區域（Drop Zone）中進行。

規則：
* 您可以刪除一個資料夾；
* 您可以刪除檔案 - 在這種情況下，包含的資料夾將被開啟；
* 如果刪除了多個項目，則使用第一個適當的本機路徑；
* 如果路徑不可用或不存在，則套用與「開啟資料夾...」中相同的存取檢查；
* 不支援的或非本地的項目將被忽略。

### 最近的
「檔案→最近」項目顯示最近開啟的本機資料夾的歷史記錄。

規則：
* 僅本地資料夾被加入到清單中；
* 透過DevProjex克隆的Git存儲庫不會添加到此列表中；
* 不會建立重複項 - 再次開啟相同資料夾會將其移至頂部；
* 最多可儲存 32 個最近使用的資料夾；
* 應用程式啟動之間的歷史記錄會被保留。

每個專案都顯示父資料夾和專案名稱，例如`Projects / App` 。

## 4) 從終端啟動
DevProjex提供互動式終端工作區以及腳本和CI的直接命令。

如果命令已設置，請打開終端並運行：
`devprojex --help`

這列出了頂級命令和選項。執行`devprojex help <command>`以查看該命令自己的選項和範例。

範例：
* `devprojex` — 開啟互動式終端機工作區。在工作區中，透過`:`命令列驅動操作（例如`:copy` 、 `:analyze` 、 `:branch` ）；有關完整命令列表，請參閱內建工作區說明和專案文件。
* `devprojex tui .` — 直接在終端工作區中開啟指定的資料夾。
* `devprojex open . --preview` — 在桌面預覽中開啟目前資料夾。
* `devprojex analyze . --format json` — 將目前專案分析為JSON 。
* `devprojex tree .` — 將項目樹印到終端。
* `devprojex export context . --format markdown -o ../devprojex-context.md` — 在來源專案外部儲存 AI 就緒上下文。
* `devprojex export project . --as folder -o ../devprojex-submission` — 將有效項目樹匯出到確切的資料夾。
* `devprojex export project . --as zip -o ../devprojex-submission.zip` — 將有效項目樹匯出到ZIP檔案。
* `devprojex export context https://github.com/owner/repo -o -` — 打包遠端儲存庫，無需自行複製。
* `devprojex analyze . --git-mode tracked --exclude smart-ignore` — 使用Smart Ignore分析追蹤的Git檔。
* `devprojex mcp --root .` — 啟動本機只讀MCP伺服器，以便 AI 代理程式可以安全地讀取專案。

筆記：
* `.`表示目前終端機資料夾；
* 帶有空格的路徑必須用引號引起來；
* `--git-mode`選擇不進行Git過濾、 `.gitignore`或追蹤的Git檔；
* `--exclude`與Git過濾分開控制普通排除；
* 分析和導出命令是確定性的，不打開桌面介面；
* `tui` 、 `open` 、 `analyze`和兩個`export`指令也接受Git儲存庫 URL；複製進入託管快取（ `devprojex cache` ）；
* 指令已記錄別名和短標誌 - 例如`export ctx` 、 `-f` 、 `-n` ； `devprojex help`顯示它們；
* `analyze --findings`列出了沒有其值的修訂結果，並且`--fail-on-findings`返回CI的非零退出代碼；
* 此指令不會修改專案檔 - DevProjex在唯讀模式下運作。

如果`devprojex`指令不起作用，請在DevProjex中開啟：
「幫助→從終端啟動」。

## 5) Git
Git選單僅適用於透過DevProjex ( Git Clone) 複製的項目。該應用程式不會觸及您的檔案 - 它僅適用於快取。

快取儲存在使用者的系統快取目錄中。運行`devprojex doctor`以查看解析的路徑。

* 分支 — 顯示可用分支的列表，並標記了活動分支；切換將樹更新到選定的分支。如果本機已經存在分支，則切換為離線狀態（不更新）。如果本機不存在，則取得並建立它。
* 取得更新 — 僅更新目前分支：取得並重設為 origin/<branch>。對於Git Clone 項目，F5 執行相同的操作；常規的「檔案→刷新」命令被停用。

### 複製視窗
在Git Clone 視窗中，URL 欄位下方會出現「最近的儲存庫」清單。

規則：
* 只有當歷史記錄已包含最近複製的儲存庫時，才會顯示該清單；
* 僅儲存庫 URL 會新增到清單中；
* 本機資料夾不會新增到此清單中；
* 不會建立重複項 - 再次複製相同儲存庫會將其移至頂部；
* 最多儲存 16 個最近的儲存庫；
* 應用程式啟動之間的歷史記錄會被保留。

選擇一個項目會自動填入 URL 欄位。
克隆正在進行時，該清單會暫時隱藏。

## 6) 複製
### 樹格式切換（ASCII / JSON / XML / MD）
此切換定義了操作的樹表示格式，其中樹是輸出的一部分。

* ASCII — 有分支的文字樹。
* JSON — JSON中的結構化樹。
* XML — 用於解析器和工具的緊湊XML樹。
* MD — 用於文件和 AI 提示的 Markdown 巢狀清單。

切換會影響：
* 複製樹
* 複製樹+內容
* 導出樹
* 匯出樹和內容

切換不會影響：
* 複製內容
* 匯出內容

### 複製樹
複製項目樹。
如果有選取的節點，則根據選擇建立樹；如果選擇為空或無效，則複製整個樹。
結果格式由樹格式切換定義。
熱鍵： {mod}{shift}C 和{mod}{alt}C。

### 複製內容
複製文件內容：
* 如果檢查文件－只檢查那些文件；否則－所有項目文件；
* 每個檔案前面都有一個標頭及其完整的本機路徑（對於Git Clone 專案 - 儲存庫 Web 路徑）；
* 非文字檔案被忽略（包括二進位）；
* 對於空文本文件，輸出路徑和行`[No Content, 0 bytes]` ；
* 對於僅包含空格/換行符的文件，將輸出路徑和行`[Whitespace, N bytes]` 。
熱鍵： {mod}{alt}V.

### 複製樹+內容
組合樹和內容：
* 樹是透過選擇而建構的；如果選擇為空/無效，則使用完整的樹；
* 內容遵循與「複製內容」相同的規則；
* 樹塊格式由樹狀格式切換定義。
熱鍵： {mod}{shift}V。

### 樹表示
樹格式對同一選定項目樹使用不同的表示方式。

JSON ：
* `rootPath` — 用`/`規範化的絕對根路徑。
* `tree` — 根資料夾的內容。
* JSON匯出使用這種樹格式：陣列包含文件，物件包含子資料夾， `/`包含目前資料夾中的文件， `[]`代表空資料夾。

XML ：
* 根節點是`<t r="...">` ；
* 資料夾是`<d n="...">` ；
* 檔案是`<f>File.cs</f>` 。

醫學博士：
* 以`Root: ...`開頭；
* 使用 Markdown 嵌套清單；
* 資料夾以`/`結尾。

樹+內容：
* 所選的樹格式適用於樹塊；
* 內容區塊仍然是文字；
* 內容區塊中的檔案頭使用帶有`/`相對路徑；
* 導出為`.txt` 。

## 7) 預覽模式
使用頂部欄中的眼睛圖示按鈕或使用{mod}B 開啟。

滑鼠側按鈕遵循瀏覽器式導覽：前進開啟預覽模式，後退關閉預覽模式。重複當前方向沒有效果。

{mod}{shift}F 開啟或關閉預覽中檔案內容的搜尋。 Enter 或 F3 轉到下一場比賽； {shift}Enter 或{shift}F3 轉到上一場比賽。

在樹旁的單獨工作區中顯示最終結果。此模式不會複製到剪貼簿，也不會單獨匯出到檔案 - 它是一種檢視模式。

預設情況下，工作區開啟為：
* 左 — 項目樹；
* center — 預覽窗格；
* 右 — 設定面板（如果已開啟）。

可用模式：
* 樹
* 內容
* 樹和內容

應用與複製和導出相同的規則：
* 已檢查的節點受到尊重；
* 如果選擇為空，則使用完整資料集；
* 應用目前忽略規則和選擇選項。

另外：
* 預覽中的文件以水平線分隔；
* 滾動時，當前文件的路徑固定在頂部；單擊固定路徑會滾動回該文件的開頭；
* 預覽滾動條標記搜尋符合項目和帶有密文結果的行；點擊標記跳至其所在行；按原樣保留的結果保持標記，並且屏蔽路徑標頭在其第一行添加一個標記；
* 樹和預覽縮放可以獨立存在。
* 在預覽模式下，您可以複製完整的目前結果或目前可見光檔案區塊，而無需開啟「複製」功能表。

按鈕：
* 頂部預覽島左側的複製按鈕 — 複製目前預覽模式：
  * 樹
  * 內容
  * 樹和內容
* 樹狀圖窗格中的 X — 隱藏樹並僅保留預覽窗格；
* 頂部預覽窗格中的 X — 完全關閉預覽模式；
* 固定檔案頭中的小複製按鈕 — 完全按照預覽中顯示的方式複製目前可見檔案區塊；
* 再次按眼睛圖示或{mod}B 也會關閉預覽模式。

當樹窗格在預覽中可見時，搜尋和過濾可用。
如果樹被隱藏，搜尋和過濾將暫時不可用，直到您離開僅預覽模式。

## 8) 查看
### 飛漲
* {mod}+ / {mod} = — 放大
* {mod} - — 縮小
* {mod}0 — 重置
* {mod}滑鼠滾輪 — 平滑縮放遊標下方的窗格

行為：
* 在正常模式下，樹被縮放；
* 在樹可見的預覽中，選單中的放大、縮小和重置適用於樹和預覽；
* 使用{mod}滑鼠滾輪，樹和預覽縮放獨立於遊標所在位置；
* 在僅預覽模式下，僅縮放預覽窗格。

範圍：6–28，重設為 15。

### 緊湊模式
使 UI 更密集：樹和設定中的間距更小。
當預覽工作區處於活動狀態時，會自動啟用緊湊模式。

### 樹展開動畫
在移動相鄰行的同時，平滑地旋轉 V 形並展開或折疊樹枝。預設啟用；當停用時，擴充是立即的。

### 樹字體
樹形字體透過「檢視→樹形字體」選擇。
“預設”恢復標準樹字體。
在設定面板中按一下「套用設定」後，將會套用所選字體。

## 9) 搜尋（樹）
打開搜尋欄，突出顯示匹配項並允許導航。
* {mod}F — 顯示/隱藏
* 輸入 — 下一個結果
* {shift}輸入 — 上一個
* Esc — 關閉

搜尋僅自動擴展所需的分支；清除查詢會折疊樹（根除外）。
匹配線也標記在樹形捲軸上；點擊標記即可跳到該匹配項。
對於非常大的匹配集，應用程式可能會限制自動擴展和全局突出顯示，以保持 UI 響應能力。
當搜尋欄關閉時，關閉動畫完成後查詢將會被清除。

限制條件：
* 開啟搜尋會自動關閉過濾器；
* 當樹狀窗格可見時，可以在預覽中進行搜尋；
* 如果樹被隱藏，則搜尋暫時不可用。

## 10) 過濾（按名稱）
僅顯示與過濾字串相符的節點及其父節點。更新已消除。
* {mod}{shift}N — 顯示/隱藏過濾器
* Esc — 關閉過濾器

限制條件：
* 開啟過濾器會自動關閉搜尋；
* 當樹狀窗格可見時，過濾器在預覽中可用；
* 如果樹被隱藏，則過濾器暫時不可用。

## 11) 選項（設定面板）
右側可用：
* 應用程式設定
* 內容處理
* 排除情況
* 擴充

「排除」和「擴充功能」中的變更會在面板中進行，並在按一下「套用設定」後套用。

複選框變更後，應用程式可能會在背景更新可用選項及其計數。僅在單擊“應用設定”後才會重建生成的樹。

如果使用狀態列中的 X 按鈕取消可用選項更新，則不會套用未完成的更改，並且面板將返回到上次完成的狀態。

每個清單都有一個「全部」切換開關。

關於「擴展」的注意事項：
* 此列表僅顯示具有擴展名的檔案；
* 沒有擴展名的檔案不會添加到此列表中，並由「排除」中的單獨選項控制。

內容處理：
* 轉換選定文字檔案的內容而不更改樹；
* 隱藏秘密和隱藏私人資料替換偵測到的值（第 12.3 和 12.4 節）；
* 壓縮程式碼保留聲明，同時縮短 14 種語言的命名實作；
* Strip comments 刪除跨 20 個語言套件的註解和文件註解；
* 剝離空白行會刪除同一包中僅包含空白的行，同時保留多行文字；
* 變更在「套用設定」後生效。

{mod}P — 顯示/隱藏面板。

### 11.1 本地專案參數設定檔
對於本機資料夾， DevProjex會記住上次套用的專案參數：
* 選定的文件類型；
* 在“排除”部分中選擇的選項。

點選“套用設定”時會執行儲存。
當再次開啟相同本機資料夾時，參數將自動恢復。

重要的：
* 僅儲存本機項目的設定檔；
* 對於透過Git Clone 開啟的項目，不會儲存設定檔；
* 如果某些已儲存的選項在目前專案中不再可用，則會跳過它們，並套用其餘參數。
* 如果刷新或重新開啟在「排除」中顯示新的文件類型或選項，則預設啟用；
* 已經看到的選項保留使用者的明確選擇：停用類型的新檔案不會再次啟用該類型。

## 12) 除外情況
「排除」部分控制從樹、內容、複製和匯出結果中排除哪些文件和資料夾。

僅當滿足所有這些條件時才會顯示項目：
* 如果文件有類型，則選擇其文件類型；
* 沒有啟用的忽略規則將其排除。

忽略規則是累積的。如果至少一個啟用的規則隱藏了某個項目，則另一個規則無法使其可見。

### 12.1 可用規則
根據項目內容，可能會顯示以下選項：

* Smart Ignore
* 使用.gitignore
* 僅追蹤Git文件
* 空資料夾
* 空白文件
* 隱藏資料夾
* 隱藏文件
* 以點為前綴的資料夾
* 以點為前綴的文件
* 沒有副檔名的文件

在Git儲存庫中，「使用 .gitignore」和「僅追蹤的Git檔案」作為穩定的複選框對保持可見。啟用其中一個會清除另一個。再次按一下活動複選框會將其清除，從而使兩個Git過濾器保持關閉狀態，而不更改Smart Ignore或基本排除。當其他選項的規則可以更改目前樹時，會顯示其他選項。因此，在切換另一個規則或檔案類型後，該清單可能會變更。

新選項首次出現時預設為啟用。即使已知選項暫時從清單中消失，它也會保留使用者的選擇。

### 12.2 Smart Ignore
Smart Ignore隱藏依賴項、建置輸出、快取和其他專案服務工件。

DevProjex首先從其結構和標記檔案中識別項目類型，例如：

* `.csproj`
* `package.json`
* `pyproject.toml`
* `Cargo.toml`

然後，在偵測到的項目範圍內套用對應堆疊的規則。例如，.NET 規則不會擴展到相鄰的 Python 或 JavaScript 專案。

僅有資料夾名稱並不總是足夠的。諸如`build` 、 `vendor` 、 `packages` 、 `cache` 、 `pkg`或`Library`之類的不明確名稱也會透過其內容進行驗證。這可以防止普通用戶資料夾僅因為名稱相似而被隱藏。

即使在明確檢測到的項目之外，某些依賴項儲存和服務目錄也可以透過其特有的內部結構來識別。

專案範圍發現是有限的，因此載入大型使用者資料夾不會成為對每個目錄的完全重複分析。常規結構使用淺層發現，而公認的單一儲存庫則進行更深入的搜尋。找到範圍後， Smart Ignore將應用於其整個子樹，沒有深度限制。

### 12.3 隱藏秘密
“隱藏秘密”預設為關閉狀態。它僅掃描選定的文字內容並替換每個偵測到的值，保留檔案及其周圍的程式碼。當該選項關閉時，不會執行掃描，也不會顯示計數。掃描目前選擇後，標籤顯示偵測到的值的個數；如果「保持原樣」決策留下較少的隱藏值，則會顯示偵測到/隱藏，以及該行的 ?指標會報告這兩個計數。

編輯過的跨度在預覽中突出顯示。點選其中一個僅保留該事件的原樣； {alt}↓ / {alt}↑ 在結果之間移動，按 Enter 鍵切換活動結果。在終端工作區中，使用`[`和`]`在出現的事件之間移動，並使用`Enter`或`Space`切換活動的事件。此決定適用於目前會話的預覽、剪貼簿、上下文匯出、資料夾複製和ZIP ；它不會保存在專案設定檔中。

預覽上下文選單擴展了這些決策。右鍵點選偵測到的事件，可透過一項操作保留（或再次隱藏）其規則的所有事件或相同檔案中偵測到的所有事件。右鍵單擊文件內容中的選定值以手動標記它：“在此處隱藏...”僅隱藏會話中出現的該值，“始終隱藏...”為每次出現的值創建持久標記，“隱藏...作為私有數據”創建由隱藏私有數據控制的持久標記。手動標記上出現“刪除標記”，將其刪除；檢測器仍然匹配的值保持隱藏。手動值必須是在文件內容中選擇的單行 8 到 512 個字元。建立標記會自動啟用對應的選項。持久標記僅儲存鍵值身分及其類別，而不儲存原始文字。

資料夾或ZIP副本也會更改匹配的文本，並且可能不再建置或運行。二進位檔案原封不動地複製且不會被掃描。選定的文字檔案超過 16 MiB 或偵測失敗會停止操作，而不是匯出未經檢查的文字。

計數報告規則僅符合。零並不意味著該項目是安全的。 CLI使用`--hide-secrets` ；技術細節和限制位於`Docs/HideSecrets.md`中。

### 12.4 隱藏私人數據
“隱藏私人資料”預設為關閉狀態。它會偵測選定文字檔案中的電子郵件地址、全球 IP 位址、路徑中的本機使用者名稱、MAC 位址和國際電話號碼。調查結果使用與隱藏秘密相同的預覽決策和相同的輸出管道；使用「隱藏…作為私有資料」建立的手動標記屬於此類並遵循此開關（第 12.3 節）。產生的路徑標頭和樹根中的本機使用者名稱被掩蓋為一個共享發現：計數器將其包含為一個值，?指示器報告它是隱藏還是顯示，只需單擊即可切換每個屏蔽路徑。

文件範圍和主機、常見CI使用者名稱、眾所周知的公共 DNS 解析器以及記錄的虛構電話範圍保持可見。零匹配並不是隱私保證。 CLI使用`--hide-private-data` ；完整的規則和第一階段的限制位於`Docs/HidePrivateData.md` 。

### 12.5 使用.gitignore
啟用後， DevProjex將套用每個可存取的`.gitignore` ，而不僅僅是開啟資料夾根目錄下的檔案。

每個`.gitignore`都適用：

* 到包含它的資料夾；
* 其下方所有可存取的資料夾；
* 僅限於該範圍內。

嵌套`.gitignore`中的規則不會影響父資料夾或同級資料夾。

對於特定路徑，規則從父`.gitignore`到更深的檔案進行處理。在一個文件中，規則是從上到下處理的。最後的匹配規則決定了Git結果。

以`!`開頭的規則僅在其範圍內取消早期的Git排除。當其父資料夾仍被排除時，它無法恢復檔案。完全排除且無法存取的資料夾內的`.gitignore`不參與評估。

單獨跳過格式錯誤或不支援的行。該文件中的其他有效規則和相鄰範圍中的規則繼續有效。

此選項僅涵蓋常規工作樹`.gitignore`文件。不應用`.git/info/exclude`中的規則和全域Git排除規則；有效的儲存庫路徑比較設置，例如`core.ignoreCase`以及在macOS上的`core.precomposeUnicode`受到尊重。不遵循名為`.gitignore`的符號鏈接，這與Git的控製文件行為相符。如果無法讀取常規`.gitignore` ，則其目錄範圍將被排除在故障關閉之外，並且掃描會報告部分訪問，而不是在沒有完整規則評估的情況下靜默包含文件。當路徑所屬儲存庫範圍的可讀索引可用時，追蹤的檔案即使符合`.gitignore`仍然可見；如果沒有該索引或Git CLI ，該範圍將安全地退回到僅模式評估。

內建的`standard`設定檔選擇`gitignore`加上`smart-ignore` 、 `hidden-folders` `hidden-files` `dot-folders` 、「dot-folders」、 `dot-files` 、 `empty-folders` 、 `empty-files`和`extensionless-files` 。

### 12.6 僅追蹤Git文件
「僅追蹤的Git檔」根據每個可讀Git索引中記錄的現有工作樹檔案建立樹的Git階段。修改後的追蹤文件和分階段添加仍然包括在內；未追蹤的文件被排除。這是目前的工作樹，而不是`HEAD`或遠端儲存庫的歷史快照。

每個可到達的巢狀儲存庫和工作樹都在任何可到達的巢狀層級上獨立解析。子儲存庫不會從其父儲存庫或同級儲存庫繼承追蹤路徑。此模式需要Git CLI ；可讀的空索引是有效的。如果終端工作區 ( TUI ) 在此模式下啟動且無法載入適用的索引，則工作區不會開啟。如果在開啟的TUI工作區中以互動方式選擇模式並且無法載入適用的索引，則變更將被拒絕，並且最後一個可用的Git模式保持活動狀態。在相同情況下，直接命令返回策略或檢查失敗。 DevProjex永遠不會默默地退回`.gitignore` 。如果另一個適用的索引可讀，則排除不可用的巢狀範圍並顯示警告。

在已開啟的桌面工作區中，明確追蹤的選擇保持可見並失敗關閉：當準備失敗時，輸出和匯出將被阻止，而部分準備繼續並出現本地化警告。

啟用後，「使用 .gitignore」和「僅追蹤的Git檔案」是互斥的。也可以清除活動複選框以停用Git過濾。對於支援設定檔的本機項目，此狀態會與檔案類型和其他排除設定一起儲存。

### 12.7 Git過濾和Smart Ignore之間的關係
Git複選框和Smart Ignore是獨立的控制項。所選的Git模式首先應用於每個可到達的Git範圍。然後， Smart Ignore處理剩餘的項目，最後運行基本規則。

當所選的Git模式已經涵蓋所有候選模式時， Smart Ignore可以保持隱藏狀態，然後在變更或清除Git模式後出現。這兩個Git複選框在Git存儲庫中仍然可用。

以`!`開頭的Git否定規則僅取消Git結果。它不會停用Smart Ignore或基本規則。

### 12.8 基本規則
“點前綴資料夾”和“點前綴檔案”檢查項目名稱。

“隱藏資料夾”和“隱藏檔案”檢查系統隱藏屬性。在某些平台上，點前綴名稱和系統屬性可能描述相同的項目或不同的項目。

「空檔案」隱藏大小為0位元組的檔案。

「沒有副檔名的檔案」隱藏諸如`Dockerfile` 、 `Makefile`和`README`之類的檔案。

「空資料夾」隱藏邏輯上空的資料夾。如果在套用選取的檔案類型和所有其他規則後不保留任何可見檔案或子資料夾，則資料夾在邏輯上為空。

因此，在切換另一個規則後，空資料夾計數可能會變更：隱藏檔案可以使其包含的資料夾在邏輯上為空。

### 12.9 計數器
規則旁邊的計數顯示其在目前設定下的直接貢獻，而不是磁碟上類似項目的實體數量。

一項不會同時歸屬於多個重疊計數器。例如， `.git`資料夾可能同時具有點前綴名稱和系統隱藏屬性，但其排除僅歸因於一個規則。

使用穩定順序來選擇排除項的擁有者：

* 資料夾： `.gitignore` ， Smart Ignore ，點前綴名稱，系統隱藏屬性；
* 文件： `.gitignore` ， Smart Ignore ，點前綴名稱，無副檔名，空文件，系統隱藏屬性。

此命令僅影響計數器。最終可見性遵循一個更簡單的規則：如果任何啟用的機制將某個項目排除在外，則該項目將被隱藏。

### 12.10 應用更改
切換複選框首先更新面板中的可用設定和計數器。選擇“套用設定”後，將重建最終的樹。

如果取消設定準備， DevProjex會將面板回到上次完全完成的狀態。不應用部分計算的規則。

## 13) 樹和指標是如何計算的
結果取決於：
* 選定的擴展
* 忽略規則
* 有源濾波器
* 檢查樹節點（用於基於選擇的操作）

如果訪問被拒絕，節點將保留其常用名稱和圖標，並獲得“[訪問被拒絕]”後綴。

### 13.1 狀態列計數器顯示什麼
狀態列有兩個區塊：
* Tree — 樹文本輸出的度量；
* 內容 — 匯出文件內容輸出的指標。

格式：
* 線路
* 字元
* ~代幣（約）

大值以緊湊後綴 (K/M) 顯示。

重要的：
* 「Tree」區塊中的「Lines」表示最終樹表示中的行數，而不是磁碟上的檔案數；
* 該值包括資料夾、檔案和樹服務元素（例如，拒絕存取的節點）。

### 13.2 指標如何計算
樹指標：
* 根據同一導出管道產生的實際樹輸出計算；
* 尊重當前的樹格式。

內容指標：
* 遵循與內容複製/導出相同的規則；
* 排除二進位檔案；
* 空白文件和僅空白文件透過服務標記進行計數（ `[No Content, 0 bytes]` 、 `[Whitespace, N bytes]` ）。

### 13.3 計數器何時更新
重新計算運行：
* 打開/刷新項目後；
* 應用設定（排除和擴展）後；
* 當樹複選框發生變化時（帶有去抖）；
* 切換樹格式時（對於使用樹輸出的操作）。
* 當取消後台計算時，計數器將設為 0，直到下次完成重新計算。

## 14) 圖標
圖示選擇順序：
1) 節點類型（資料夾/檔案）
2) 確切名稱（如果規則存在）
3) 擴大
4) 否則——未知

## 15) 主題和效果
主題部分可讓您選擇系統、淺色或深色以及一種背景效果：
* 透明度
* 模糊
* 雲母

預設選擇系統並遵循作業系統主題變更。首次啟動或重設設定後，淺色系統主題以常規不透明背景開始，而深色系統主題以模糊開始。如果無法確定係統首選項， DevProjex將使用 Dark 和 Blur。光明和黑暗獨立地記住它們的效果。顯式的淺色或深色選擇會忽略系統更改，直到再次選擇系統。

效果是互相排斥的。再次按一下選取的效果可將其停用並恢復常規的不透明背景。

可用設定：
* 背景透明度 — 可用於透明度和模糊。
* 頂部面板對比 — 調整包含預覽、搜尋、過濾器和樹格式指令的主面板。
* 選單透明度 — 同樣適用於主選單及其子選單。
* 邊框可見性 — 調整介面邊框的顯示強度。

Mica 使用平台的系統材質，沒有單獨的背景透明度設定。如果所選的模糊或雲母效果不可用，應用程式將首先嘗試其他本機效果。僅當 Blur 和 Mica 都不可用時才使用常規不透明背景。

在透明模式下，主視窗背景保持透明。選單、子選單和其他彈出介面在支援時使用模糊，因此它們後面的樹和內容元素不會影響可讀性。

## 16) 幫助

### 16.1 更新
「幫助 → 更新」將目前版本與最新穩定的GitHub版本進行比較。自動檢查預設關閉；啟用後， DevProjex會在上次成功檢查後至少 7 天後在啟動時進行檢查。該複選框立即生效。最新的成功結果會在應用程式運行之間保留，並且不會因以後的網路故障而被刪除。安裝仍然是使用者操作。

### 16.2 重置設定
重置設定（幫助→重置設定）恢復預設主題、效果、緊湊模式、樹展開動作畫和介面語言。磁碟上的項目設定檔、歷史記錄和檔案不會變更。

### 16.3 重置數據
重置資料（幫助→重置資料）會刪除已儲存的本機項目參數設定檔：
* 選定的文件類型；
* 在“排除”部分中選擇的選項。

重要的：
* 本地資料夾的最近歷史記錄不會被清除；
* Git Clone 視窗中最近的儲存庫歷史記錄未清除；
* 磁碟上的檔案和資料夾不會被修改或刪除。

## 17) 語言
透過語言選單選擇語言。
所選語言將在兩次啟動之間保存。 「幫助→重設設定」清除已儲存的語言選擇並將介面語言還原為預設值。

## 18) 進度條和取消
狀態列的中心顯示活動操作及其進度。

進度模式：
* 不確定 — 無百分比（操作持續時間未知）。
* 決定 — 帶百分比 (0–100)。

行為：
* 後台資料計算時，顯示百分比進度；
* 對於某些Git操作，當進度來源提供百分比時，會顯示百分比；
* 當操作花費明顯時間時，會顯示可用選項更新和設定應用程式；
* 快速操作完成但沒有顯示進度。

狀態列中的 X 按鈕（取消）：
* 對支援取消的操作執行盡力取消；
* 停止後台資料計算；
* 當取消可用選項更新時，將面板返回到上次完成的狀態；
* 對於不支援取消的操作，它會停止狀態列指示，而操作本身仍可能在背景完成。
