## 1) O que é e para que serve
O DevProjex prepara rapidamente o contexto de um projeto: mostra a estrutura de pastas e ficheiros, permite selecionar itens com caixas de seleção e copiar para a área de transferência a árvore, o conteúdo dos ficheiros ou ambos. É útil para revisão de código, suporte, aprendizagem e para partilhar a estrutura do projeto com um assistente de IA.

Importante: o DevProjex não modifica os ficheiros do projeto que abre. A única exceção é uma ligação MCP explícita para o Cursor ou o VS Code, que cria ou atualiza `.cursor/mcp.json` ou `.vscode/mcp.json` (secção 19.1).

## 2) Árvore do projeto
* Ícones por tipo de ficheiro ou pasta.
* Caixas de seleção nos nós.
* Expandir e recolher.

Caixas de seleção: marcar um nó aplica-se aos seus filhos; o estado do nó pai é recalculado automaticamente.

Teclas de atalho:
* {mod}E — expandir tudo
* {collapseAll} — recolher tudo (a raiz permanece expandida)

### Menu de contexto
Clique com o botão direito num nó ou prima {shift}F10 ou a tecla Menu no nó em foco:
* Mostrar no Explorador de Ficheiros / Mostrar no Finder / Abrir no gestor de ficheiros — mostra o item no gestor de ficheiros do sistema; o rótulo corresponde à plataforma atual.
* Copiar caminho completo — o caminho absoluto do item.
* Copiar caminho relativo — o caminho a partir da raiz do projeto, começando pelo nome da pasta raiz, por exemplo `project/src/File.cs`.
* Copiar conteúdo — para ficheiros: copia o conteúdo com as transformações de conteúdo aplicadas, exatamente como a cópia e a exportação o produzem.
* Selecionar apenas este item — marca apenas este nó e desmarca os restantes; só aparece enquanto outro item também estiver marcado.
* Expandir ramo / Recolher ramo — para pastas.

Se o caminho já não existir no disco, abrir o item no gestor de ficheiros ou copiar o seu conteúdo mostra uma mensagem de erro; copiar o caminho continua a funcionar.

## 3) Ficheiro
* Abrir pasta… — abre a pasta raiz ({mod}O)
* Nova janela — abre uma nova instância independente do DevProjex
* Recente — lista de pastas locais abertas recentemente
* Atualizar — volta a analisar uma pasta local e reconstrói a árvore (F5)
* Exportar para ficheiro:
  * Exportar árvore
  * Exportar conteúdo
  * Exportar árvore e conteúdo
* Exportar projeto:
  * Para uma pasta…
  * Para um arquivo ZIP…

«Exportar projeto» cria uma pasta ou um arquivo ZIP separado a partir da árvore atual, preservando a estrutura de diretórios.

Os tipos de ficheiro selecionados, as regras de exclusão e os itens marcados são respeitados. Se nada estiver marcado, é exportada toda a árvore atual.

Os ficheiros de texto e binários são copiados, e as pastas vazias incluídas são preservadas. Os ficheiros de origem não são modificados. O resultado não pode ser guardado dentro do projeto de origem.

Durante a exportação, não é possível alterar a árvore ou as definições, usar o filtro, mudar o formato ou o modo de pré-visualização, executar comandos Git, atualizar nem abrir outro projeto.

Regras de formato:
* Exportar árvore:
  * ASCII -> apenas `.txt`.
  * JSON -> `.json` por predefinição; `.json` e `.txt` estão disponíveis na caixa de diálogo Guardar.
  * XML -> `.xml` por predefinição; `.xml` e `.txt` estão disponíveis na caixa de diálogo Guardar.
  * MD -> `.md` por predefinição; `.md` e `.txt` estão disponíveis na caixa de diálogo Guardar.
* Exportar conteúdo — sempre no formato de conteúdo de texto, ficheiro `.txt` (o seletor de formato da árvore não se aplica).
* Exportar árvore e conteúdo — sempre um ficheiro `.txt`; o formato de árvore selecionado afeta apenas o bloco da árvore dentro do resultado.

Os ficheiros exportados são escritos em UTF-8 sem BOM.

### Arrastar e largar
Arrastar e largar funciona na área inicial (zona de largar) quando não há nenhum projeto carregado.

Regras:
* pode largar uma pasta;
* pode largar um ficheiro — nesse caso, é aberta a pasta que o contém;
* se largar vários itens, é usado o primeiro caminho local adequado;
* se um caminho não estiver disponível ou não existir, são aplicadas as mesmas verificações de acesso de «Abrir pasta…»;
* os itens não suportados ou não locais são ignorados.

### Recente
O item «Ficheiro → Recente» mostra o histórico de pastas locais abertas recentemente.

Regras:
* só são adicionadas à lista pastas locais;
* os repositórios Git clonados com o DevProjex não são adicionados a esta lista;
* não são criados duplicados — voltar a abrir a mesma pasta move-a para o topo;
* são guardadas até 32 pastas recentes;
* o histórico é preservado entre execuções da aplicação.

Cada item mostra a pasta principal e o nome do projeto, por exemplo `Projects / App`.

## 4) Iniciar a partir do terminal
O DevProjex oferece um espaço de trabalho interativo no terminal (Terminal Workspace) e comandos diretos para scripts e CI.

Se o comando já estiver configurado, abra um terminal e execute:
`devprojex --help`

Isto lista os comandos e as opções de nível superior. Execute `devprojex help <command>` para ver as opções e os exemplos de um comando específico.

Exemplos:
* `devprojex` — abre o espaço de trabalho interativo do terminal. Dentro dele, as ações são executadas através da linha de comandos `:` (por exemplo, `:copy`, `:analyze`, `:branch`, `:language`); a lista completa de comandos está na ajuda integrada do espaço de trabalho e na documentação do projeto.
* `devprojex tui .` — abre a pasta indicada diretamente no espaço de trabalho do terminal.
* `devprojex open . --preview` — abre a pasta atual na pré-visualização do Desktop.
* `devprojex analyze . --format json` — analisa o projeto atual e devolve JSON.
* `devprojex tree .` — imprime a árvore do projeto no terminal.
* `devprojex export context . --format markdown -o ../devprojex-context.md` — guarda um contexto pronto para IA fora do projeto de origem.
* `devprojex export project . --as folder -o ../devprojex-submission` — exporta a árvore efetiva do projeto para uma pasta exata.
* `devprojex export project . --as zip -o ../devprojex-submission.zip` — exporta a árvore efetiva do projeto para um arquivo ZIP.
* `devprojex export context https://github.com/owner/repo -o -` — empacota um repositório remoto sem que tenha de o clonar.
* `devprojex analyze . --git-mode tracked --exclude smart-ignore` — analisa os ficheiros controlados pelo Git com o Smart Ignore.
* `devprojex search Configure . --symbols` — encontra onde uma declaração é definida; `--symbols` aceita nomes de declarações e recusa a sintaxe de expressões regulares, enquanto `--regex` pesquisa texto com uma expressão regular.
* `devprojex related src/App.cs` — lista os ficheiros que um ficheiro utiliza e os ficheiros que o utilizam.
* `devprojex mcp --root .` — inicia o servidor MCP local só de leitura para que os agentes de IA leiam o projeto em segurança.
* `devprojex mcp connect . --client claude-code` — liga um cliente de IA ao projeto (secção 19).
* `devprojex mcp log . --last` — mostra a sessão mais recente do diário do agente.

Notas:
* `.` significa a pasta atual do terminal;
* os caminhos com espaços devem ficar entre aspas;
* `--git-mode` seleciona `none`, `gitignore`, `tracked`, `staged`, `changes` ou `diff:<ref>..<ref>`;
* `--exclude` controla as exclusões comuns separadamente da filtragem Git;
* os comandos de análise e exportação são determinísticos e não abrem a interface gráfica;
* `tui`, `open`, `analyze`, `search`, `tree` e os dois comandos `export` também aceitam o URL de um repositório Git, e `related` aceita-o através de `--project`; o clone vai para uma cache gerida (`devprojex cache`);
* os comandos têm aliases e opções curtas documentados, por exemplo `export ctx`, `-f`, `-n`; `devprojex help` mostra-os;
* `analyze --findings` lista as deteções de ocultação sem os valores, e `--fail-on-findings` devolve um código de saída diferente de zero para CI;
* `export context --max-tokens N` mantém o contexto dentro de um orçamento de tokens, e a opção experimental `--rank importance` admite primeiro os ficheiros mais importantes;
* os comandos de análise, pesquisa e exportação não modificam os ficheiros do projeto — o DevProjex funciona em modo só de leitura.

Se o comando `devprojex` não funcionar, abra no DevProjex:
«Ajuda → Iniciar a partir do terminal».

## 5) Git
«Git → Clonar repositório…» clona um repositório para a cache do DevProjex e abre-o. «Ramo» e «Obter atualizações» só estão disponíveis para projetos clonados desta forma. A aplicação não mexe nos seus ficheiros — trabalha apenas com a cache.

A cache é guardada no diretório de cache do sistema do utilizador. Execute `devprojex doctor` para ver o caminho efetivo.

* Ramo — mostra a lista de ramos disponíveis com o ativo assinalado; ao mudar, a árvore é atualizada para o ramo selecionado. Se o ramo já existir localmente, a mudança é feita offline (sem atualização). Se não existir localmente, é obtido e criado.
* Obter atualizações — atualiza apenas o ramo atual: fetch e reposição para origin/<branch>. Num projeto clonado com o Git Clone, F5 executa a mesma ação; o comando habitual «Ficheiro → Atualizar» fica desativado.

### Janela de clonagem
Na janela do Git Clone, a lista «Ligações recentes» com os repositórios clonados recentemente pode aparecer por baixo do campo do URL.

Regras:
* a lista só aparece se o histórico já contiver repositórios clonados recentemente;
* só são adicionadas à lista origens de repositório em rede (`https://`, `ssh://` e a sintaxe SCP);
* os caminhos locais e as origens `file://` não são adicionados a esta lista;
* não são criados duplicados — voltar a clonar o mesmo repositório move-o para o topo;
* são guardados até 16 repositórios recentes;
* o histórico é preservado entre execuções da aplicação.

Selecionar um item preenche automaticamente o campo do URL.
Enquanto a clonagem decorre, a lista fica temporariamente oculta.

## 6) Copiar
### Seletor de formato da árvore (ASCII / JSON / XML / MD)
O seletor define o formato de representação da árvore nas operações em que a árvore faz parte do resultado.

* ASCII — árvore de texto com ramos.
* JSON — árvore estruturada em JSON.
* XML — árvore XML compacta para analisadores e ferramentas.
* MD — lista aninhada de Markdown para documentação e prompts de IA.

O seletor afeta:
* Copiar árvore
* Copiar árvore e conteúdo
* Exportar árvore
* Exportar árvore e conteúdo

O seletor não afeta:
* Copiar conteúdo
* Exportar conteúdo

### Copiar árvore
Copia a árvore do projeto.
Se houver nós marcados, a árvore é construída a partir da seleção; se a seleção estiver vazia ou for inválida, é copiada a árvore completa.
O formato do resultado é definido pelo seletor de formato da árvore.
Teclas de atalho: {mod}{shift}C e {mod}{alt}C.

### Copiar conteúdo
Copia o conteúdo dos ficheiros:
* se houver ficheiros marcados, apenas esses; caso contrário, todos os ficheiros do projeto;
* cada ficheiro é precedido por um cabeçalho com o caminho local completo (em projetos do Git Clone, o caminho web do repositório);
* os ficheiros que não são de texto são ignorados (incluindo binários);
* para ficheiros de texto vazios, são gerados o caminho e a linha `[No Content, 0 bytes]`;
* para ficheiros que contêm apenas espaços ou quebras de linha, são gerados o caminho e a linha `[Whitespace, N bytes]`.
Tecla de atalho: {mod}{alt}V.

### Copiar árvore e conteúdo
Combina a árvore e o conteúdo:
* a árvore é construída a partir da seleção; se a seleção estiver vazia ou for inválida, é usada a árvore completa;
* o conteúdo segue as mesmas regras de «Copiar conteúdo»;
* o formato do bloco da árvore é definido pelo seletor de formato da árvore.
Tecla de atalho: {mod}{shift}V.

### Representações da árvore
Os formatos de árvore usam representações diferentes para a mesma árvore de projeto selecionada.

JSON:
* `rootPath` — caminho absoluto da raiz normalizado com `/`.
* `tree` — conteúdo da pasta raiz.
* A exportação JSON usa este formato de árvore: as matrizes contêm ficheiros, os objetos contêm subpastas, `/` contém os ficheiros da pasta atual e `[]` representa uma pasta vazia.

XML:
* o nó raiz é `<t r="...">`;
* as pastas são `<d n="...">`;
* os ficheiros são `<f>File.cs</f>`.

MD:
* começa com `Root: ...`;
* usa uma lista aninhada de Markdown;
* as pastas terminam com `/`.

Árvore + conteúdo:
* o formato de árvore selecionado aplica-se ao bloco da árvore;
* o bloco de conteúdo continua a ser texto;
* os cabeçalhos de ficheiro no bloco de conteúdo usam caminhos relativos com `/`;
* é exportado como `.txt`.

## 7) Modo de pré-visualização
Abre-se com o botão do ícone do olho na barra superior ou com {mod}B.

Os botões laterais do rato seguem a navegação de um browser: Avançar abre o modo de pré-visualização e Voltar fecha-o. Repetir a direção atual não tem efeito.

{mod}{shift}F abre ou fecha a pesquisa no conteúdo dos ficheiros da pré-visualização. Enter ou F3 vai para a correspondência seguinte; {shift}Enter ou {shift}F3, para a anterior.

Mostra o resultado final numa área de trabalho separada, junto à árvore. Este modo não copia para a área de transferência nem exporta para um ficheiro por si só — é um modo de pré-visualização.

Por predefinição, a área de trabalho abre-se assim:
* à esquerda — árvore do projeto;
* ao centro — painel de pré-visualização;
* à direita — painel de definições, se estava aberto.

Modos disponíveis:
* Árvore
* Conteúdo
* Árvore + conteúdo

São aplicadas as mesmas regras da cópia e da exportação:
* os nós marcados são respeitados;
* se a seleção estiver vazia, é usado o conjunto de dados completo;
* são aplicadas as regras de exclusão e as opções de seleção atuais.

Além disso:
* na pré-visualização, os ficheiros são separados por linhas horizontais;
* durante a deslocação, o caminho do ficheiro atual fica fixado no topo; clicar no caminho fixado volta ao início desse ficheiro;
* a barra de deslocação da pré-visualização marca as correspondências da pesquisa e as linhas com valores detetados; clicar numa marca salta para a respetiva linha; um valor mantido sem alterações continua marcado, e os cabeçalhos de caminho mascarados geram uma única marca na primeira linha;
* o zoom da árvore e o da pré-visualização podem ser independentes;
* no modo de pré-visualização, pode copiar o resultado atual completo ou o bloco do ficheiro visível sem abrir o menu Copiar.

Botões:
* botão de copiar no lado esquerdo da ilha superior da pré-visualização — copia o modo de pré-visualização atual:
  * Árvore
  * Conteúdo
  * Árvore + conteúdo
* X no painel da árvore — oculta a árvore e deixa apenas o painel de pré-visualização;
* X no painel superior da pré-visualização — fecha completamente o modo de pré-visualização;
* pequeno botão de copiar no cabeçalho do ficheiro fixado — copia o bloco do ficheiro visível exatamente como é mostrado na pré-visualização;
* premir novamente o ícone do olho ou {mod}B também fecha o modo de pré-visualização.

Pesquisar e Filtrar estão disponíveis enquanto o painel da árvore estiver visível na pré-visualização.
Se a árvore estiver oculta, Pesquisar e Filtrar ficam temporariamente indisponíveis até sair do modo só de pré-visualização.

## 8) Ver
### Zoom
* {mod}+ / {mod}= — ampliar
* {mod}- — diminuir o zoom
* {mod}0 — repor
* {mod}roda do rato — zoom suave no painel sob o cursor

Comportamento:
* no modo normal, a árvore é ampliada;
* na pré-visualização com a árvore visível, Ampliar, Diminuir zoom e Repor zoom no menu aplicam-se à árvore e à pré-visualização;
* com {mod}roda do rato, a árvore e a pré-visualização são ampliadas separadamente, consoante a posição do cursor;
* no modo só de pré-visualização, apenas o painel de pré-visualização é ampliado.

Intervalo: 6–28; o valor ao repor é 15.

### Modo compacto
Torna a interface mais densa: menos espaçamento na árvore e nas definições.
Enquanto a área de trabalho de pré-visualização está ativa, o modo compacto é ativado automaticamente.

### Animações
«Ver → Animações» controla separadamente a expansão da árvore, os contadores de estado e o aparecimento inicial das ferramentas. As três estão ativadas por predefinição; uma animação desativada mostra imediatamente o seu estado final.

### Fonte de árvore
A fonte da árvore é selecionada em «Ver → Fonte de árvore».
«Padrão» repõe a fonte predefinida da árvore.
A fonte selecionada é aplicada depois de clicar em «Aplicar definições» no painel de definições.

### Atividade do agente
Ative «Ver → Atividade do agente» para ver que ficheiros um agente de IA recebeu numa sessão live: ficam marcados com ✦ na árvore (secção 19.4).

## 9) Pesquisa (árvore)
Abre a barra de pesquisa, realça as correspondências e permite navegar entre elas.
* {mod}F — mostrar ou ocultar
* Enter — resultado seguinte
* {shift}Enter — resultado anterior
* Esc — fechar

A pesquisa expande automaticamente apenas os ramos necessários; limpar a consulta recolhe a árvore (exceto a raiz).
As linhas com correspondências também são marcadas na barra de deslocação da árvore; clicar numa marca salta para essa correspondência.
Com conjuntos muito grandes de correspondências, a aplicação pode limitar a expansão automática e o realce global para manter a interface reativa.
Quando a barra de pesquisa é fechada, a consulta é limpa depois de terminar a animação de fecho.

Restrições:
* abrir Pesquisar fecha Filtrar automaticamente;
* Pesquisar está disponível na pré-visualização enquanto o painel da árvore estiver visível;
* se a árvore estiver oculta, Pesquisar fica temporariamente indisponível.

## 10) Filtro (por nome)
Mostra apenas os nós que correspondem ao texto do filtro e os respetivos nós pai. A lista é atualizada com um breve atraso enquanto escreve.
* {mod}{shift}N — mostrar ou ocultar o filtro
* Esc — fechar o filtro

Restrições:
* abrir Filtrar fecha Pesquisar automaticamente;
* Filtrar está disponível na pré-visualização enquanto o painel da árvore estiver visível;
* se a árvore estiver oculta, Filtrar fica temporariamente indisponível.

## 11) Opções (painel de definições)
Disponível à direita:
* Aplicar definições
* Processamento de conteúdo
* Exclusões
* Tipos de ficheiro

As alterações em «Exclusões» e «Tipos de ficheiro» ficam pendentes no painel e são aplicadas depois de clicar em «Aplicar definições».

Depois de alterar uma caixa de seleção, a aplicação pode atualizar em segundo plano as opções disponíveis e as respetivas contagens. A árvore resultante só é reconstruída depois de clicar em «Aplicar definições».

Se uma atualização das opções disponíveis for cancelada com o botão X na barra de estado, as alterações por concluir não são aplicadas e o painel regressa ao último estado concluído.

Cada lista tem uma opção «Todos».

Nota sobre «Tipos de ficheiro»:
* esta lista mostra apenas ficheiros que têm extensão;
* os ficheiros sem extensão não são adicionados a esta lista e são controlados por uma opção separada em «Exclusões».

Processamento de conteúdo:
* transforma o conteúdo dos ficheiros de texto selecionados sem alterar a árvore;
* «Ocultar segredos» e «Ocultar dados privados» substituem os valores detetados (secções 12.3 e 12.4);
* «Comprimir código» mantém as declarações e encurta as implementações com nome em 14 linguagens;
* «Remover comentários» remove os comentários e os comentários de documentação em 20 pacotes de linguagens;
* «Remover linhas em branco» remove as linhas que contêm apenas espaços nos mesmos pacotes, preservando os literais de várias linhas;
* as alterações entram em vigor depois de «Aplicar definições».

{mod}P — mostrar ou ocultar o painel.

### 11.1 Perfis de parâmetros de projetos locais
Para pastas locais, o DevProjex memoriza os últimos parâmetros de projeto aplicados:
* tipos de ficheiro selecionados;
* opções selecionadas na secção «Exclusões».

São guardados quando clica em «Aplicar definições».
Quando a mesma pasta local é aberta novamente, os parâmetros são repostos automaticamente.

Importante:
* os perfis só são guardados para projetos locais;
* para projetos abertos com o Git Clone, os perfis não são guardados;
* se algumas opções guardadas já não estiverem disponíveis no projeto atual, são ignoradas e os restantes parâmetros são aplicados;
* se uma atualização ou uma nova abertura revelar um novo tipo de ficheiro ou uma nova opção em «Exclusões», esta fica ativada por predefinição;
* as opções já vistas mantêm a escolha explícita do utilizador: novos ficheiros de um tipo desativado não voltam a ativar esse tipo.

## 12) Exclusões
A secção «Exclusões» controla que ficheiros e pastas são excluídos da árvore, do conteúdo e dos resultados de cópia e exportação.

Um item só é mostrado quando todas estas condições são cumpridas:
* o seu tipo de ficheiro está selecionado, se o ficheiro tiver um tipo;
* nenhuma regra de exclusão ativada o exclui.

As regras de exclusão são cumulativas. Se pelo menos uma regra ativada ocultar um item, outra regra não o pode tornar visível.

### 12.1 Regras disponíveis
Consoante o conteúdo do projeto, podem ser apresentadas as seguintes opções:

* Smart Ignore
* Pastas vazias
* Ficheiros vazios
* Pastas ocultas
* Ficheiros ocultos
* Pastas ponto
* Ficheiros ponto
* Ficheiros sem extensão

O seletor da GUI e as linhas de opção do eixo Git na TUI ficam totalmente ocultos quando a filtragem Git não é aplicável: não há limite de repositório e o filtro `.gitignore` não pode alterar a árvore atual. Quando o eixo está visível fora de um repositório, a GUI oferece apenas «sem filtragem» e `.gitignore`, enquanto a TUI desativa as linhas que exigem um repositório. Dentro de um repositório Git, os cinco valores habituais são: sem filtragem, `.gitignore`, ficheiros controlados, ficheiros preparados e todas as alterações atuais; na TUI, um âmbito `diff:<ref>..<ref>` ativo aparece como sexta linha. Escolher um valor substitui o modo Git atual sem alterar o Smart Ignore nem as exclusões básicas. As restantes opções aparecem quando as respetivas regras podem alterar a árvore atual, pelo que a lista pode mudar depois de alterar outra regra ou um tipo de ficheiro.

Uma opção nova fica ativada por predefinição quando aparece pela primeira vez. Uma opção conhecida mantém a escolha do utilizador mesmo que desapareça temporariamente da lista.

### 12.2 Smart Ignore
O Smart Ignore oculta dependências, resultados de compilação, caches e outros artefactos de serviço do projeto.

Primeiro, o DevProjex identifica o tipo de projeto a partir da estrutura e dos ficheiros marcadores, por exemplo:

* `.csproj`
* `package.json`
* `pyproject.toml`
* `Cargo.toml`

Em seguida, as regras da stack correspondente são aplicadas dentro do âmbito do projeto detetado. Por exemplo, as regras do .NET não se estendem a um projeto Python ou JavaScript vizinho.

O nome de uma pasta nem sempre é suficiente. Nomes ambíguos como `build`, `vendor`, `packages`, `cache`, `pkg` ou `Library` também são verificados pelo conteúdo. Isto evita que uma pasta normal do utilizador seja ocultada só porque tem um nome semelhante.

Alguns repositórios de dependências e diretórios de serviço podem ser reconhecidos pela sua estrutura interna característica, mesmo fora de um projeto detetado explicitamente.

A deteção de âmbitos de projeto é limitada, para que carregar uma pasta grande do utilizador não se transforme numa análise completa e repetida de cada diretório. As estruturas comuns usam uma deteção superficial, enquanto os monorepos reconhecidos são analisados com mais profundidade. Depois de encontrado um âmbito, o Smart Ignore aplica-se a toda a sua subárvore, sem limite de profundidade.

### 12.3 Ocultar segredos
«Ocultar segredos» está desativado por predefinição. Analisa apenas o conteúdo de texto selecionado e substitui cada valor detetado no próprio local, mantendo o ficheiro e o código à sua volta. Enquanto a opção estiver desativada, não é executada nenhuma análise nem é mostrada nenhuma contagem. Depois de analisada a seleção atual, o rótulo mostra o número de valores detetados; se as decisões de manter deixarem menos valores ocultos, mostra detetados/ocultos, e o indicador ? da linha indica ambas as contagens.

Os excertos ocultados são realçados na pré-visualização. Clique num deles para manter apenas essa ocorrência sem alterações; {alt}↓ / {alt}↑ percorrem as deteções e Enter alterna a ativa. No Terminal Workspace, `[` e `]` percorrem as ocorrências e `Enter` ou `Space` alternam a ativa. A decisão aplica-se durante a sessão atual à pré-visualização, à área de transferência, à exportação de contexto, à cópia em pasta e ao ZIP; não é guardada no perfil do projeto.

O menu de contexto da pré-visualização alarga estas decisões. Clique com o botão direito numa ocorrência detetada para manter — ou voltar a ocultar — numa única ação todas as ocorrências da sua regra ou todas as ocorrências detetadas no mesmo ficheiro. Clique com o botão direito num valor selecionado no conteúdo do ficheiro para o marcar manualmente: «Ocultar … aqui» oculta apenas essa ocorrência durante a sessão, «Ocultar sempre …» cria uma marcação persistente para todas as ocorrências do valor, e «Ocultar … como dado privado» cria uma marcação persistente controlada por «Ocultar dados privados». «Remover marcação» aparece numa marcação manual e elimina-a; um valor que o detetor continua a encontrar permanece oculto. Um valor manual tem de ser uma única linha de 8 a 512 caracteres selecionada no conteúdo do ficheiro. Criar uma marcação ativa automaticamente a opção correspondente. As marcações persistentes guardam apenas uma identidade do valor com chave e a sua classe, nunca o texto original.

Uma cópia em pasta ou ZIP também altera o texto correspondente e pode deixar de compilar ou de ser executada. Os ficheiros binários são copiados sem alterações e não são analisados. Um ficheiro de texto selecionado com mais de 16 MiB é omitido e indicado, enquanto o resto da saída é concluído. Uma falha de deteção interrompe toda a operação.

A contagem indica apenas correspondências com as regras. Zero não significa que o projeto seja seguro. A CLI usa `--hide-secrets`; os detalhes técnicos e os limites estão em `Docs/HideSecrets.md`.

### 12.4 Ocultar dados privados
«Ocultar dados privados» está desativado por predefinição. Deteta endereços de e-mail, endereços IP globais, nomes de utilizador locais em caminhos, endereços MAC e números de telefone internacionais nos ficheiros de texto selecionados. As deteções usam as mesmas decisões da pré-visualização e o mesmo fluxo de saída de «Ocultar segredos»; as marcações manuais criadas com «Ocultar … como dado privado» pertencem a esta classe e seguem esta opção (secção 12.3). Os nomes de utilizador locais nos cabeçalhos de caminho gerados e na raiz da árvore são mascarados como uma única deteção partilhada: a contagem inclui-a como um valor, o indicador ? indica se está oculta ou visível, e um clique alterna todos os caminhos mascarados.

Os intervalos e anfitriões de documentação, os nomes de utilizador comuns de CI, os resolvedores DNS públicos conhecidos e os intervalos de telefones fictícios documentados permanecem visíveis. Zero correspondências não é garantia de privacidade. A CLI usa `--hide-private-data`; as regras completas e os limites da primeira fase estão em `Docs/HidePrivateData.md`.

### 12.5 Usar .gitignore
Quando ativado, o DevProjex segue a vista da árvore de trabalho do `git status`: os ficheiros controlados permanecem visíveis e os não controlados são mostrados, a menos que as regras de exclusão do repositório os excluam. Aplica todos os `.gitignore` acessíveis, e não apenas o ficheiro na raiz da pasta aberta, incluindo os que estão acima dela até à raiz do repositório.

Cada `.gitignore` aplica-se:

* à pasta que o contém;
* a todas as pastas acessíveis abaixo dela;
* apenas dentro desse âmbito.

As regras de um `.gitignore` aninhado não afetam as pastas pai nem as irmãs.

Para um caminho específico, as regras são processadas do `.gitignore` pai em direção aos mais profundos. Dentro de um ficheiro, as regras são processadas de cima para baixo. A última regra correspondente determina o resultado do Git.

Uma regra que começa por `!` cancela uma exclusão anterior do Git apenas dentro do seu âmbito. Não pode repor um ficheiro enquanto a sua pasta pai continuar excluída. Um `.gitignore` dentro de uma pasta totalmente excluída e inacessível não participa na avaliação.

Uma linha mal formada ou não suportada é ignorada de forma independente. As restantes regras válidas desse ficheiro e as regras dos âmbitos vizinhos continuam a funcionar.

O ficheiro local do repositório `.git/info/exclude` também é aplicado, com prioridade inferior à do `.gitignore` da raiz. Uma pasta aninhada com o seu próprio `.git` também segue o `git status`: um repositório incorporado que não esteja declarado em `.gitmodules` é opaco, pelo que os seus ficheiros não são mostrados, enquanto um submódulo declarado aplica o seu próprio `.gitignore` e `info/exclude`. Selecione `none` para ver os ficheiros dos repositórios incorporados. As regras globais de exclusão do Git (`core.excludesFile`) não são aplicadas; as definições efetivas do repositório para comparação de caminhos, como `core.ignoreCase` e, no macOS, `core.precomposeUnicode`, são respeitadas. Uma ligação simbólica com o nome `.gitignore` não é seguida, tal como o Git faz com este ficheiro de controlo. Se um ficheiro `.gitignore` ou `info/exclude` não puder ser lido, o âmbito do respetivo diretório é excluído em segurança e a análise indica um acesso parcial, em vez de incluir silenciosamente ficheiros sem a avaliação completa das regras. Quando existe um índice legível para o âmbito do repositório a que o caminho pertence, os ficheiros controlados permanecem visíveis mesmo que correspondam ao `.gitignore`; sem esse índice ou sem a CLI do Git, esse âmbito regressa em segurança à avaliação apenas por padrões.

O perfil integrado `standard` seleciona `gitignore`, além de `smart-ignore`, `hidden-folders`, `hidden-files`, `dot-folders`, `dot-files`, `empty-folders`, `empty-files` e `extensionless-files`.

### 12.6 Apenas ficheiros controlados
«Apenas ficheiros controlados» constrói a etapa Git da árvore a partir dos ficheiros existentes na árvore de trabalho registados em cada índice Git legível. Os ficheiros controlados modificados e os novos ficheiros preparados continuam incluídos; os ficheiros não controlados são excluídos. Esta é a árvore de trabalho atual, não uma captura histórica do `HEAD` nem de um repositório remoto.

Cada repositório é resolvido de forma independente: os repositórios irmãos dentro da pasta aberta e os submódulos declarados usam cada um o seu próprio índice, e um repositório filho não herda os caminhos controlados do repositório pai nem de um irmão. Um repositório incorporado que não esteja declarado em `.gitmodules` continua opaco, tal como no modo `.gitignore`. Este modo requer a CLI do Git; um índice vazio, mas legível, é válido. Se o Terminal Workspace (TUI) for iniciado neste modo e nenhum índice aplicável puder ser carregado, o espaço de trabalho não é aberto. Se o modo for selecionado interativamente num espaço de trabalho TUI já aberto e nenhum índice aplicável puder ser carregado, a alteração é rejeitada e o último modo Git utilizável permanece ativo. Na mesma situação, os comandos diretos devolvem uma falha de política ou de verificação. O DevProjex nunca passa silenciosamente para `.gitignore`. Se outro índice aplicável puder ser lido, os âmbitos aninhados indisponíveis são excluídos com um aviso.

Num espaço de trabalho do Desktop já aberto, a seleção explícita de ficheiros controlados permanece visível e falha em segurança: a saída e a exportação são bloqueadas quando a prontidão falha, enquanto a prontidão parcial continua com um aviso localizado.

Os modos Git são mutuamente exclusivos; `none` desativa a filtragem Git. Os modos momentâneos `staged`, `changes` e `diff:<ref>..<ref>` não são guardados nos perfis. Enquanto um modo momentâneo está ativo, o perfil local do projeto na GUI mantém o último modo persistente ativado, `gitignore` ou `tracked`. O modo `none` só é guardado quando está ativo no momento da gravação. A TUI e a CLI recusam guardar um perfil portátil enquanto um modo momentâneo está ativo.

### 12.7 Relação entre a filtragem Git e o Smart Ignore
O modo Git selecionado e o Smart Ignore são controlos independentes. O modo Git é aplicado primeiro em cada âmbito Git acessível. Depois, o Smart Ignore processa os itens restantes e, por fim, são aplicadas as regras básicas.

O Smart Ignore pode ficar oculto enquanto o modo Git selecionado já abranger todos os seus candidatos e aparecer depois de o modo Git ser alterado ou desativado. Dentro de um repositório Git, todos os modos Git que dependem do repositório continuam disponíveis.

Uma regra de negação do Git que começa por `!` cancela apenas um resultado do Git. Não desativa o Smart Ignore nem uma regra básica.

### 12.8 Regras básicas
«Pastas ponto» e «Ficheiros ponto» verificam se o nome do item começa por um ponto.

«Pastas ocultas» e «Ficheiros ocultos» verificam o atributo oculto do sistema. Em algumas plataformas, um nome iniciado por ponto e o atributo do sistema podem descrever o mesmo item ou itens diferentes.

«Ficheiros vazios» oculta os ficheiros com tamanho de 0 bytes.

«Ficheiros sem extensão» oculta ficheiros como `Dockerfile`, `Makefile` e `README`.

«Pastas vazias» oculta as pastas logicamente vazias. Uma pasta está logicamente vazia quando não resta nenhum ficheiro ou subpasta visível depois de aplicados os tipos de ficheiro selecionados e todas as outras regras.

Por isso, a contagem de pastas vazias pode mudar depois de alternar outra regra: ocultar ficheiros pode deixar logicamente vazias as pastas que os contêm.

### 12.9 Contadores
A contagem junto a uma regra mostra a sua contribuição direta com as definições atuais, e não o número físico de itens semelhantes no disco.

Um item não é atribuído ao mesmo tempo a vários contadores sobrepostos. Por exemplo, a pasta `.git` pode ter simultaneamente um nome iniciado por ponto e o atributo Oculto do sistema, mas a sua exclusão é atribuída a uma única regra.

É usada uma ordem estável para escolher a regra à qual uma exclusão é atribuída:

* pastas: `.gitignore`, Smart Ignore, nome com ponto inicial, atributo Oculto do sistema;
* ficheiros: `.gitignore`, Smart Ignore, nome com ponto inicial, sem extensão, ficheiro vazio, atributo Oculto do sistema.

Esta ordem afeta apenas os contadores. A visibilidade final segue uma regra mais simples: um item fica oculto se qualquer mecanismo ativado o excluir.

### 12.10 Aplicar alterações
Alternar as caixas de seleção atualiza primeiro as definições disponíveis e os contadores do painel. A árvore final é reconstruída depois de selecionar «Aplicar definições».

Se a preparação das definições for cancelada, o DevProjex devolve o painel ao último estado totalmente concluído. As regras calculadas parcialmente não são aplicadas.

## 13) Como a árvore e as métricas são calculadas
O resultado depende de:
* tipos de ficheiro selecionados
* regras de exclusão
* filtro ativo
* nós marcados na árvore (para operações baseadas na seleção)

Se o acesso for negado, o nó mantém o nome e o ícone habituais e recebe o sufixo «[acesso negado]».

### 13.1 O que mostram os contadores da barra de estado
A barra de estado tem dois blocos:
* Árvore — métricas da saída de texto da árvore;
* Conteúdo — métricas da saída do conteúdo dos ficheiros exportados.

Formato:
* Linhas
* Caracteres
* ≈Tokens (aproximado)

Os valores grandes são mostrados com sufixos compactos (K/M).

Importante:
* «Linhas» no bloco «Árvore» é o número de linhas da representação final da árvore, e não o número de ficheiros no disco;
* este valor inclui pastas, ficheiros e elementos de serviço da árvore (por exemplo, nós com acesso negado).

### 13.2 Como as métricas são calculadas
Métricas da árvore:
* são calculadas a partir da saída real da árvore gerada pelo mesmo pipeline de exportação;
* respeitam o formato de árvore atual.

Métricas do conteúdo:
* seguem as mesmas regras da cópia e da exportação de conteúdo;
* os ficheiros binários são excluídos;
* os ficheiros vazios e os que contêm apenas espaços são contados através de marcadores de serviço (`[No Content, 0 bytes]`, `[Whitespace, N bytes]`).

### 13.3 Quando os contadores são atualizados
O recálculo é executado:
* depois de abrir ou atualizar um projeto;
* depois de aplicar as definições (exclusões e tipos de ficheiro);
* quando as caixas de seleção da árvore mudam (com um breve atraso);
* ao mudar o formato da árvore (para operações em que é usada a saída da árvore);
* quando o cálculo em segundo plano é cancelado, os contadores ficam a 0 até ao próximo recálculo concluído.

## 14) Ícones
Ordem de seleção dos ícones:
1) tipo de nó (pasta ou ficheiro)
2) nome exato (se existir uma regra)
3) extensão
4) caso contrário — desconhecido

## 15) Tema e efeitos
A secção Tema permite escolher Sistema, Claro ou Escuro e um efeito de fundo:
* Transparência
* Desfoque
* Mica

Sistema está selecionado por predefinição e acompanha as alterações de tema do sistema operativo. Após o primeiro arranque ou uma reposição das definições, um tema claro do sistema começa com um fundo opaco normal, enquanto um tema escuro do sistema começa com Desfoque. Se não for possível determinar a preferência do sistema, o DevProjex usa Escuro com Desfoque. Claro e Escuro memorizam os seus efeitos separadamente. Uma seleção explícita de Claro ou Escuro ignora as alterações do sistema até que Sistema seja novamente selecionado.

Os efeitos são mutuamente exclusivos. Clicar novamente no efeito selecionado desativa-o e repõe um fundo opaco normal.

Definições disponíveis:
* Transparência de fundo — disponível para Transparência e Desfoque.
* Contraste da barra superior — ajusta o painel principal que contém os comandos de pré-visualização, pesquisa, filtro e formato da árvore.
* Transparência do menu — aplica-se igualmente ao menu principal e aos seus submenus.
* Visibilidade do contorno — ajusta a intensidade com que os contornos da interface são mostrados.

O Mica usa o material do sistema da plataforma e não tem uma definição própria de transparência de fundo. Se o efeito Desfoque ou Mica selecionado não estiver disponível, a aplicação tenta primeiro o outro efeito nativo. Só é usado um fundo opaco normal quando nem o Desfoque nem o Mica estão disponíveis.

No modo Transparência, o fundo da janela principal permanece transparente. Os menus, submenus e outras superfícies pop-up usam Desfoque quando é suportado, para que os elementos da árvore e do conteúdo por trás deles não prejudiquem a leitura.

## 16) Ajuda

### 16.1 Atualizações
«Ajuda → Atualizações» compara a versão atual com a versão estável mais recente publicada no GitHub. As verificações automáticas estão desativadas por predefinição; quando ativadas, o DevProjex verifica no arranque depois de passarem pelo menos sete dias desde a última verificação bem-sucedida. A caixa de seleção tem efeito imediato. O último resultado bem-sucedido é mantido entre execuções da aplicação e não é apagado por uma falha de rede posterior. A instalação continua a ser uma ação do utilizador.

### 16.2 Repor definições
Repor definições («Ajuda → Repor definições») repõe os valores predefinidos do tema, dos efeitos, do modo compacto, das animações e do idioma da interface. Os perfis de projeto, o histórico e os ficheiros no disco não são alterados.

### 16.3 Repor dados
Repor dados («Ajuda → Repor dados») remove os perfis de parâmetros guardados dos projetos locais:
* tipos de ficheiro selecionados;
* opções selecionadas na secção «Exclusões»;
* definições selecionadas de processamento de conteúdo;
* marcações manuais de segredos.

Também limpa as sessões concluídas do diário do agente (secção 19.3); as sessões ativas são mantidas.

Importante:
* o histórico de pastas locais recentes não é apagado;
* o histórico de repositórios recentes na janela do Git Clone não é apagado;
* os ficheiros e as pastas no disco não são modificados nem eliminados.

## 17) Idiomas
O idioma é selecionado no menu Idioma.
O idioma selecionado é mantido entre execuções. «Ajuda → Repor definições» limpa o idioma guardado e devolve a interface ao idioma predefinido.

## 18) Barra de progresso e cancelamento
O centro da barra de estado mostra a operação ativa e o seu progresso.

Modos de progresso:
* Indeterminado — sem percentagem (a duração da operação é desconhecida).
* Determinado — com percentagem (0–100).

Comportamento:
* durante o cálculo de dados em segundo plano, o progresso é mostrado em percentagem;
* em algumas operações do Git, a percentagem é mostrada quando a fonte de progresso a fornece;
* a atualização das opções disponíveis e a aplicação das definições são mostradas quando a operação demora um tempo percetível;
* as operações rápidas terminam sem mostrar progresso.

Botão X (cancelar) na barra de estado:
* tenta cancelar, na medida do possível, as operações que suportam cancelamento;
* interrompe o cálculo de dados em segundo plano;
* quando uma atualização das opções disponíveis é cancelada, devolve o painel ao último estado concluído;
* nas operações que não suportam cancelamento, interrompe a indicação na barra de estado, embora a própria operação possa ainda terminar em segundo plano.

## 19) MCP e agentes de IA
O DevProjex inclui um servidor MCP local só de leitura. Os agentes de IA, como o Claude Code, o Codex, o Cursor e o VS Code, leem o projeto através dele: a ocultação de segredos está sempre ativa e o agente não pode alterar os ficheiros do projeto. O servidor disponibiliza oito ferramentas: `list_projects`, `get_tree`, `analyze`, `search_project`, `related_files`, `get_file`, `pack_context` e `read_pack`.

### 19.1 Ligar um cliente
O menu MCP contém:
* Live context — o servidor segue os itens marcados nesta janela (secção 19.2);
* Padrão — o servidor não depende da seleção da janela;
* Diário… — o que os agentes pediram e receberam (secção 19.3);
* Documentação — abre a documentação do servidor MCP.

Live context e Padrão contêm as mesmas ações — Abrir no Claude Code, Abrir no Codex, Abrir no Cursor, Abrir no VS Code e Outros clientes… —, disponíveis enquanto houver um projeto aberto.

O Claude Code e o Codex são registados através do respetivo comando instalado e, em seguida, o cliente abre-se num novo terminal na pasta do projeto. O Cursor e o VS Code recebem um `.cursor/mcp.json` ou `.vscode/mcp.json` local do projeto; os outros servidores desse ficheiro são mantidos. «Outros clientes…» mostra uma configuração pronta para o Claude Desktop e outros clientes. Se o comando de um cliente não existir ou a ligação falhar, o DevProjex mostra a configuração manual. Depois de uma ligação bem-sucedida, o DevProjex pode propor adicionar o comando `devprojex` ao PATH.

O Codex mantém uma única ligação partilhada ao DevProjex, pelo que ligar outro projeto pede confirmação antes de a substituir. Uma sessão de cliente que já esteja em execução tem de ser reiniciada para carregar o servidor. Num terminal, `devprojex mcp connect` regista o modo Padrão, a menos que adicione `--mode live` para o Live context; `--print` apenas imprime a configuração.

### 19.2 Live context
No Live context, os itens marcados na árvore definem o foco do agente: os pedidos de árvore, pesquisa, análise, ficheiros relacionados e empacotamento ficam dentro deles. Os filtros da janela — tipos de ficheiro, exclusões e o modo Git — são o limite de acesso: o agente pode ainda abrir outros ficheiros pelo nome, mas apenas os que esses filtros permitem.

A janela não precisa de ficar aberta. O servidor lê a última seleção guardada do projeto em cada pedido, pelo que as novas marcações e as definições aplicadas chegam ao agente no pedido seguinte, sem o reiniciar.

Enquanto uma sessão live está ativa, o título da janela termina com `· Live context (<client>)`, ou com o número de sessões quando estão várias ativas.

### 19.3 Diário
«MCP → Diário…» mostra o que os agentes pediram e receberam através do DevProjex: as sessões com cliente, modo, chamadas, caracteres, tokens estimados, ficheiros entregues e valores mascarados, e as chamadas da sessão selecionada. Está disponível sem um projeto aberto; com um projeto aberto, «Apenas o projeto atual» está selecionado por predefinição.

O diário é guardado apenas neste computador, na pasta de estado do DevProjex, e mantém no máximo 200 sessões durante 30 dias. Não guarda o conteúdo dos ficheiros, os valores secretos detetados nem o texto das consultas de pesquisa. «Exportar…» guarda uma sessão como recibo em Markdown ou JSON. «Limpar» elimina as sessões concluídas após confirmação; as sessões ativas e as partilhadas com outros projetos são mantidas.

### 19.4 Atividade do agente
«Ver → Atividade do agente» está desativado por predefinição: selecione-o para mostrar as marcas e selecione-o novamente para as ocultar. Enquanto estiver ativado e houver uma sessão live ativa, cada ficheiro cujo conteúdo o agente recebeu nessa sessão — o ficheiro inteiro, um intervalo de linhas, resultados de pesquisa ou uma declaração — é marcado com ✦ na árvore. Um ficheiro que o agente apenas viu numa listagem da árvore ou numa estimativa de tamanho não é marcado. Passe o ponteiro sobre ✦ para ver quantas vezes o agente recebeu o ficheiro, por exemplo «O agente recebeu o ficheiro 3 vezes».

As marcas mostram apenas o que foi entregue: nunca alteram caixas de seleção, filtros nem o que o agente pode ler. São limpas quando começa uma sessão live mais recente, quando a sessão live termina, quando «Atividade do agente» é desativado e quando o projeto é reaberto; os ficheiros que o agente receber depois disso voltam a ser marcados. As sessões no modo Padrão aparecem no diário, mas não adicionam marcas.

No Terminal Workspace, `:set activity on` marca os mesmos ficheiros com A na árvore e, quando um desses ficheiros está em foco, a linha de estado mostra quantas vezes o agente o recebeu; `:set activity off` remove as marcas.

* Se as permissões forem insuficientes, a aplicação pode sugerir reiniciar com privilégios elevados; se recusar, é mostrada uma notificação.
