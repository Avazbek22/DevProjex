## 1) Qu’est‑ce que c’est et pourquoi
DevProjex prépare rapidement le contexte d’un projet : affiche la structure dossiers/fichiers, permet de sélectionner des éléments et de copier l’arborescence et/ou le contenu des fichiers dans le presse‑papiers. Utile pour code review, support, formation et partage de structure avec un assistant IA.

Important : DevProjex ne modifie pas les fichiers du projet ouvert.

## 2) Arborescence du projet
* Icônes de type fichier/dossier.
* Cases à cocher sur les nœuds.
* Déplier/replier.

Cases à cocher : cocher un nœud s’applique aux enfants ; l’état des parents se recalculent automatiquement.

Raccourcis :
* {mod}E — tout déplier
* {collapseAll} — tout replier (la racine reste ouverte)

### Menu contextuel
Clic droit sur un nœud — ou {shift}F10 / touche Menu sur le nœud sélectionné :
* Afficher dans l’Explorateur de fichiers / Afficher dans le Finder / Ouvrir dans le gestionnaire de fichiers — révèle l’élément dans le gestionnaire de fichiers du système ; le libellé dépend de la plateforme.
* Copier le chemin complet — le chemin absolu de l’élément.
* Copier le chemin relatif — le chemin depuis la racine du projet, commençant par le nom du dossier racine, par exemple `project/src/File.cs`.
* Copier le contenu — pour les fichiers : copie le contenu avec les transformations appliquées, exactement comme la copie et l’export.
* Sélectionner uniquement cet élément — coche uniquement ce nœud et efface le reste de la sélection ; n’apparaît que tant qu’un autre élément est aussi coché.
* Développer la branche / Réduire la branche — pour les dossiers.

Si le chemin n’existe plus sur le disque, l’ouverture dans le gestionnaire de fichiers et la copie du contenu affichent un message d’erreur ; la copie des chemins continue de fonctionner.

## 3) Fichier
* Ouvrir le dossier… — ouvrir le dossier racine ({mod}O)
* Nouvelle fenêtre — ouvrir une nouvelle instance indépendante de DevProjex
* Récents — liste des dossiers locaux ouverts récemment
* Actualiser — relire un dossier local et reconstruire l’arborescence (F5)
* Exporter vers un fichier :
  * Exporter l’arborescence
  * Exporter le contenu
  * Exporter arborescence et contenu
* Exporter le projet :
  * Vers un dossier…
  * Vers une archive ZIP…

L’export du projet crée un dossier distinct ou une archive ZIP à partir de l’arborescence actuelle, tout en conservant la structure des répertoires.

Les types de fichiers, règles d’exclusion et éléments cochés sont pris en compte. Si rien n’est coché, toute l’arborescence actuelle est exportée.

Les fichiers texte et binaires sont copiés, et les dossiers vides inclus sont conservés. Les fichiers sources ne sont pas modifiés. Le résultat ne peut pas être enregistré dans le projet source.

Pendant l’export, vous ne pouvez pas modifier l’arborescence ou les paramètres, utiliser le filtre, changer le format ou le mode d’aperçu, lancer des commandes Git, actualiser ou ouvrir un autre projet.

Règles de format :
* Exporter l’arborescence :
  * ASCII -> uniquement `.txt`.
  * JSON -> `.json` par défaut, avec `.json` et `.txt` disponibles dans la boîte de sauvegarde.
  * XML -> `.xml` par défaut, avec `.xml` et `.txt` disponibles dans la boîte de sauvegarde.
  * MD -> `.md` par défaut, avec `.md` et `.txt` disponibles dans la boîte de sauvegarde.
* Exporter le contenu — toujours au format texte du contenu, fichier `.txt` (le sélecteur de format d’arborescence n’influence pas).
* Exporter arborescence et contenu — toujours fichier `.txt` ; le format d’arborescence choisi n’influence que le format du bloc arborescence dans le résultat.

Les fichiers exportés sont écrits en UTF-8 sans BOM.

### Drag & Drop
Le glisser-déposer fonctionne dans la zone de démarrage (Drop Zone) quand aucun projet n’est chargé.

Règles :
* vous pouvez déposer un dossier ;
* vous pouvez déposer un fichier — dans ce cas, le dossier contenant ce fichier est ouvert ;
* si plusieurs éléments sont déposés, le premier chemin local valide est utilisé ;
* si un chemin est indisponible ou inexistant, les mêmes vérifications d’accès que pour « Ouvrir le dossier… » sont appliquées ;
* les éléments non pris en charge ou non locaux sont ignorés.

### Récents
L’élément « Fichier → Récents » affiche l’historique des dossiers locaux ouverts récemment.

Règles :
* seuls les dossiers locaux sont ajoutés à la liste ;
* les dépôts Git clonés via DevProjex ne sont pas ajoutés à cette liste ;
* aucun doublon n’est créé — rouvrir le même dossier le remonte en haut de la liste ;
* jusqu’à 32 derniers dossiers sont conservés ;
* l’historique est conservé entre les démarrages de l’application.

Pour chaque élément, le dossier parent et le nom du projet sont affichés, par exemple `Projects / App`.

## 4) Lancement depuis le terminal
DevProjex fournit un espace de travail interactif dans le terminal et des commandes directes pour les scripts et la CI.

Si la commande est déjà configurée, ouvrez un terminal et exécutez :
`devprojex --help`

Vous verrez ainsi toutes les commandes, options et exemples disponibles.

Exemples :
* `devprojex` — ouvrir l’espace de travail interactif du terminal.
* `devprojex open . --preview` — ouvrir le dossier courant dans l’aperçu Desktop.
* `devprojex analyze . --format json` — analyser le projet courant au format JSON.
* `devprojex export context . --format markdown -o ../devprojex-context.md` — enregistrer un contexte prêt pour l’IA hors du projet source.
* `devprojex export project . --as folder -o ../devprojex-submission` — exporter l’arborescence effective vers un dossier exact.
* `devprojex export project . --as zip -o ../devprojex-submission.zip` — exporter l’arborescence effective vers une archive ZIP.
* `devprojex analyze . --git-mode tracked --exclude smart-ignore` — analyser les fichiers suivis par Git avec Smart Ignore.

Particularités :
* `.` désigne le dossier courant du terminal ;
* les chemins contenant des espaces doivent être placés entre guillemets ;
* `--git-mode` choisit aucune filtration Git, `.gitignore` ou uniquement les fichiers suivis par Git ;
* `--exclude` gère les exclusions ordinaires séparément de la filtration Git ;
* les commandes d’analyse et d’exportation sont déterministes et n’ouvrent pas l’interface graphique ;
* la commande ne modifie pas les fichiers du projet — DevProjex fonctionne en lecture seule.

Si la commande `devprojex` ne fonctionne pas, ouvrez dans DevProjex :
« Aide → Lancement depuis le terminal ».

## 5) Git
Le menu Git n’est disponible que pour les projets clonés via DevProjex (Git Clone). L’application ne touche pas à vos fichiers — elle travaille uniquement avec le cache.

Le cache est stocké dans le répertoire de cache de l’utilisateur. `devprojex doctor` affiche le chemin effectivement utilisé.

* Branche — affiche la liste des branches disponibles avec indication de la branche active ; le changement met à jour l’arborescence sur la branche choisie. Si la branche existe déjà en local, le changement se fait hors ligne (sans mise à jour). Si elle n’existe pas localement, elle est récupérée (fetch) et créée localement.
* Obtenir les mises à jour — met à jour uniquement la branche courante : fetch et reset vers origin/<branche>. Pour un projet Git Clone, F5 effectue la même action ; la commande normale « Fichier → Actualiser » est désactivée.

### Fenêtre de clonage
Dans la fenêtre Git Clone, une liste « Dépôts récents » peut apparaître sous le champ URL.

Règles :
* la liste apparaît seulement si l’historique contient déjà des dépôts clonés récemment ;
* seules les URL des dépôts sont ajoutées à la liste ;
* les dossiers locaux ne sont pas ajoutés à cette liste ;
* aucun doublon n’est créé — re-cloner le même dépôt le remonte en haut de la liste ;
* jusqu’à 16 derniers dépôts sont conservés ;
* l’historique est conservé entre les démarrages de l’application.

Si vous choisissez un élément dans la liste, l’URL est automatiquement insérée dans le champ de saisie.
Pendant un clonage actif, la liste est temporairement masquée.

## 6) Copier
### Sélecteur de format de l’arborescence (ASCII / JSON / XML / MD)
Le sélecteur définit le format de représentation de l’arborescence pour les opérations où l’arbre participe au résultat.

* ASCII — arborescence textuelle avec branches.
* JSON — arborescence structurée en JSON.
* XML — arborescence XML compacte pour les parseurs et outils.
* MD — liste Markdown imbriquée pour la documentation et les prompts IA.

Le sélecteur influence :
* Copier l’arborescence
* Copier l’arborescence + le contenu
* Exporter l’arborescence
* Exporter arborescence et contenu

Le sélecteur n’influence pas :
* Copier le contenu
* Exporter le contenu

### Copier l’arborescence
Copie l’arborescence du projet.
S’il y a des nœuds cochés, l’arborescence est construite à partir de la sélection ; si la sélection est vide ou invalide, l’arborescence complète est copiée.
Le format du résultat est défini par le sélecteur de format d’arborescence.
Raccourcis : {mod}{shift}C et {mod}{alt}C.

### Copier le contenu
Copie le contenu des fichiers :
* si des fichiers sont cochés — seuls ceux-ci ; sinon — tous les fichiers du projet ;
* les fichiers non textuels sont ignorés (y compris les binaires) ;
* pour les fichiers texte vides, le chemin et la ligne `[No Content, 0 bytes]` sont ajoutés ;
* pour les fichiers ne contenant que des espaces/retours à la ligne, le chemin et la ligne `[Whitespace, N bytes]` sont ajoutés ;
* chaque fichier est précédé d’un en-tête avec son chemin local complet (pour les projets Git Clone — le chemin web du dépôt).
Raccourci : {mod}{alt}V.

### Copier l’arborescence + le contenu
Combine arborescence et contenu :
* arborescence depuis la sélection ; si la sélection est vide ou invalide, l’arborescence complète est utilisée ;
* contenu selon les mêmes règles que « Copier le contenu » ;
* le format du bloc arborescence est défini par le sélecteur de format d’arborescence.
Raccourci : {mod}{shift}V.

### Représentations de l’arborescence
Les formats représentent différemment la même arborescence de projet sélectionnée.

JSON :
* `rootPath` — chemin racine absolu normalisé avec `/`.
* `tree` — contenu du dossier racine.
* L’export JSON utilise ce format d’arborescence : les tableaux contiennent les fichiers, les objets contiennent les sous-dossiers, `/` contient les fichiers du dossier courant, et `[]` représente un dossier vide.

XML :
* le nœud racine est `<t r="...">` ;
* les dossiers sont `<d n="...">` ;
* les fichiers sont `<f>File.cs</f>`.

MD :
* commence par `Root: ...` ;
* utilise une liste Markdown imbriquée ;
* les dossiers se terminent par `/`.

Arborescence + contenu :
* le format d’arborescence choisi s’applique au bloc arborescence ;
* le bloc contenu reste textuel ;
* les en-têtes de fichiers du bloc contenu utilisent des chemins relatifs avec `/` ;
* export en `.txt`.

## 7) Mode aperçu
S’ouvre avec le bouton icône œil dans la barre supérieure ou avec {mod}B.

Les boutons latéraux de la souris suivent la navigation du navigateur : Suivant ouvre le mode aperçu et Précédent le ferme. Répéter la direction déjà active n’a aucun effet.

{mod}{shift}F ouvre ou ferme la recherche dans le contenu des fichiers de l’aperçu. Enter ou F3 passe au résultat suivant ; {shift}Enter ou {shift}F3 au précédent.

Affiche le résultat final dans un espace de travail séparé, à côté de l’arborescence. Ce mode ne copie rien dans le presse-papiers et n’exporte rien vers un fichier par lui-même : il sert uniquement à la consultation.

Par défaut, l’espace de travail s’ouvre ainsi :
* à gauche — l’arborescence du projet ;
* au centre — le panneau d’aperçu ;
* à droite — le panneau des paramètres, s’il était ouvert.

Modes disponibles :
* Arborescence
* Contenu
* Arborescence et contenu

Les mêmes règles que pour la copie et l’export sont appliquées :
* les nœuds cochés sont pris en compte ;
* si la sélection est vide, l’ensemble complet des données est utilisé ;
* les règles d’ignorance et les paramètres de sélection actuels sont appliqués.

En plus :
* les fichiers de l’aperçu sont séparés par des lignes horizontales ;
* pendant le défilement, le chemin du fichier courant reste épinglé en haut ; un clic sur le chemin épinglé fait défiler jusqu’au début de ce fichier ;
* la barre de défilement de l’aperçu marque les correspondances de recherche et les lignes avec des valeurs détectées ; un clic sur une marque saute à sa ligne ; une valeur conservée reste marquée, et les chemins masqués des en-têtes donnent une seule marque à leur première ligne ;
* le zoom de l’arborescence et celui de l’aperçu peuvent vivre séparément.
* en mode aperçu, vous pouvez copier soit le résultat complet actuel, soit le bloc du fichier actuellement visible sans passer par le menu « Copier ».

Boutons :
* bouton de copie à gauche dans le panneau supérieur d’aperçu — copie le mode d’aperçu actuel :
  * Arborescence
  * Contenu
  * Arborescence et contenu
* X dans le panneau de l’arborescence — masque l’arborescence et laisse uniquement le panneau d’aperçu ;
* X dans la barre supérieure de l’aperçu — ferme complètement le mode aperçu ;
* petit bouton de copie dans l’en-tête épinglé du fichier — copie le bloc du fichier actuellement visible tel qu’il est affiché dans l’aperçu ;
* un nouveau clic sur l’icône œil ou {mod}B ferme aussi le mode aperçu.

La recherche et le filtre restent disponibles tant que le panneau de l’arborescence est visible dans l’aperçu.
Si l’arborescence est masquée, la recherche et le filtre deviennent temporairement indisponibles jusqu’à la sortie du mode aperçu seul.

## 8) Affichage
### Zoom
* {mod}+ / {mod}= — agrandir
* {mod}- — réduire
* {mod}0 — réinitialiser
* {mod}molette — zoom fluide dans le panneau sous le curseur

Comportement :
* en mode normal, c’est l’arborescence qui est zoomée ;
* en aperçu avec l’arborescence visible, Agrandir, Réduire et Réinitialiser du menu s’appliquent à la fois à l’arborescence et à l’aperçu ;
* avec {mod}molette, l’arborescence et l’aperçu zooment indépendamment selon la position du curseur ;
* en mode aperçu seul, seul le panneau d’aperçu est zoomé.

Plage : 6–28, reset : 15.

### Mode compact
Rend l’interface plus dense : moins d’espaces dans l’arbre et les paramètres.
Quand l’espace de travail d’aperçu est actif, le mode compact est activé automatiquement.

### Animation de déploiement de l’arborescence
Fait pivoter la flèche et déploie ou replie une branche en déplaçant les lignes voisines. Activée par défaut ; lorsqu’elle est désactivée, le déploiement est immédiat.

### Police de l’arborescence
La police de l’arborescence se choisit via « Affichage → Police de l’arborescence ».
« Par défaut » rétablit la police standard de l’arborescence.
La police choisie est appliquée après clic sur « Appliquer » dans le panneau des paramètres.

## 9) Recherche dans l'arbre
Ouvre la recherche, met en évidence les correspondances et permet la navigation.
* {mod}F — afficher/masquer
* Enter — résultat suivant
* {shift}Enter — précédent
* Esc — fermer

La recherche n’ouvre que les branches nécessaires ; en effaçant la requête, l’arbre se replie (sauf la racine).
Les lignes des correspondances sont aussi marquées sur la barre de défilement de l’arbre ; un clic sur une marque saute à cette correspondance.
Pour un très grand nombre de correspondances, l’application peut limiter l’ouverture automatique et la mise en évidence globale afin de garder l’interface réactive.
À la fermeture de la recherche, la requête est effacée après la fin de l’animation de fermeture.

Limitations :
* à l’ouverture de la recherche, le filtre se ferme automatiquement ;
* la recherche reste disponible dans l’aperçu tant que le panneau de l’arborescence est visible ;
* si l’arborescence est masquée, la recherche devient temporairement indisponible.

## 10) Filtrer par nom
Affiche uniquement les nœuds correspondant au filtre et leurs parents. Mise à jour avec délai (debounce).
* {mod}{shift}N — afficher/masquer le filtre
* Esc — fermer le filtre

Limitations :
* à l’ouverture du filtre, la recherche se ferme automatiquement ;
* le filtre reste disponible dans l’aperçu tant que le panneau de l’arborescence est visible ;
* si l’arborescence est masquée, le filtre devient temporairement indisponible.

## 11) Options
À droite sont disponibles :
* Appliquer
* Traitement du contenu
* Exclusions
* Types de fichiers

Les changements dans « Exclusions » et « Types de fichiers » sont préparés dans le panneau et appliqués après clic sur « Appliquer ».

Après la modification d’une case, l’application peut actualiser en arrière-plan les options disponibles et leurs compteurs. L’arborescence résultante n’est reconstruite qu’après un clic sur « Appliquer ».

Si l’actualisation des options disponibles est annulée avec le bouton X de la barre d’état, les changements inachevés ne sont pas appliqués et le panneau revient à son dernier état terminé.

Chaque liste a un bouton Tous.

Remarque sur « Types de fichiers » :
* cette liste affiche uniquement les fichiers avec extension ;
* les fichiers sans extension ne sont pas ajoutés à cette liste et sont gérés par une option séparée dans « Exclusions ».

Traitement du contenu :
* cette section transforme le contenu des fichiers texte sélectionnés sans modifier l’arborescence ;
* « Masquer les secrets » et « Masquer les données privées » remplacent les valeurs détectées (sections 12.3 et 12.4) ;
* « Compresser le code » conserve les déclarations et raccourcit les implémentations nommées dans 14 langages ;
* « Supprimer les commentaires » retire les commentaires et les commentaires de documentation dans 20 packs de langages ;
* « Supprimer les lignes vides » retire les lignes d’espaces dans les mêmes packs en préservant les littéraux multilignes ;
* les changements prennent effet après « Appliquer ».

{mod}P — afficher/masquer le panneau.

### 11.1 Profils de paramètres des projets locaux
Pour les dossiers locaux, DevProjex mémorise les derniers paramètres de projet appliqués :
* types de fichiers sélectionnés ;
* options sélectionnées dans la section « Exclusions ».

L’enregistrement est effectué après clic sur « Appliquer ».
Lors de la réouverture du même dossier local, les paramètres sont restaurés automatiquement.

Important :
* les profils sont enregistrés uniquement pour les projets locaux ;
* pour les projets ouverts via Git Clone, les profils ne sont pas enregistrés ;
* si certaines options enregistrées ne sont plus disponibles dans le projet actuel, elles sont ignorées, les autres paramètres sont appliqués.
* si l’actualisation ou la réouverture fait apparaître un nouveau type de fichiers ou une nouvelle option dans « Exclusions », cet élément est activé par défaut ;
* les éléments déjà connus conservent le choix explicite de l’utilisateur : de nouveaux fichiers d’un type désactivé ne réactivent pas ce type.

## 12) Exclusions
La section « Exclusions » détermine les fichiers et dossiers exclus de l’arbre, du contenu, de la copie et de l’export.

Un élément n’est affiché que si son type de fichier est sélectionné et si aucune règle active ne l’exclut. Les règles se cumulent : si l’une d’elles masque un élément, une autre ne peut pas le rendre visible.

### 12.1 Règles disponibles
Selon le contenu du projet, Smart Ignore, « Utiliser .gitignore », « Uniquement les fichiers suivis par Git », les dossiers et fichiers vides, cachés ou commençant par un point, ainsi que les fichiers sans extension peuvent être proposés.

Dans un dépôt Git, « Utiliser .gitignore » et « Uniquement les fichiers suivis par Git » restent visibles sous la forme de deux cases. Activer l’une désactive l’autre ; cliquer de nouveau sur la case active désactive entièrement le filtrage Git sans modifier Smart Ignore ni les règles de base. Les autres options apparaissent lorsqu’elles peuvent modifier l’arbre actuel. La liste peut donc changer après la modification d’une autre règle ou d’un type de fichier. Une nouvelle option est activée par défaut lors de sa première apparition ; une option connue conserve le choix de l’utilisateur même si elle disparaît temporairement.

### 12.2 Smart Ignore
Smart Ignore masque les dépendances, résultats de build, caches et autres artefacts de service. DevProjex identifie le type du projet à partir de sa structure et de fichiers marqueurs comme `.csproj`, `package.json`, `pyproject.toml` ou `Cargo.toml`. Les règles de la technologie reconnue restent dans la zone du projet et ne s’étendent pas aux projets voisins d’une autre technologie.

Pour les noms ambigus comme `build`, `vendor`, `packages`, `cache`, `pkg` ou `Library`, le contenu est également vérifié. Un dossier utilisateur ordinaire n’est donc pas masqué uniquement à cause de son nom. Certains magasins de dépendances et dossiers de service peuvent aussi être reconnus hors d’un projet explicite grâce à leur structure caractéristique.

La détection de nouvelles zones de projet est limitée afin d’éviter une analyse répétée de chaque dossier dans un grand répertoire utilisateur. La recherche reste peu profonde dans une structure normale et va plus loin dans un monorepo reconnu. Une fois la zone détectée, Smart Ignore s’applique à tout son sous-arbre sans limite de profondeur.

### 12.3 Masquer les secrets
« Masquer les secrets » est désactivé par défaut. L’option analyse uniquement le texte sélectionné et remplace chaque valeur détectée sur place, sans retirer le fichier ni son contexte. Lorsqu’elle est désactivée, aucune analyse n’est lancée et aucun compteur n’apparaît. Après l’analyse de la sélection, le libellé indique le nombre de valeurs détectées ; si des décisions « conserver » laissent moins de valeurs masquées, il affiche les deux nombres — détectées/masquées — et l’indicateur ? de la ligne les précise en texte.

Les correspondances sont mises en évidence dans l’aperçu. Cliquez sur l’une d’elles pour conserver uniquement cette occurrence ; {alt}↓ / {alt}↑ parcourent les valeurs détectées et Enter bascule la valeur active. Dans Terminal Workspace, `[` et `]` parcourent les occurrences, et `Enter` ou `Space` basculent l’occurrence active. La décision s’applique pendant la session à l’aperçu, au presse-papiers, aux exports de contexte, au dossier et au ZIP ; elle n’est pas enregistrée dans le profil du projet.

Le menu contextuel de l’aperçu étend ces décisions. Un clic droit sur une occurrence détectée permet de conserver — ou de masquer à nouveau — en une seule action toutes les occurrences de sa règle ou toutes les occurrences détectées dans le même fichier. Un clic droit sur une valeur sélectionnée dans le contenu d’un fichier ajoute un marquage manuel : « Masquer … ici » masque uniquement cette occurrence pour la session, « Toujours masquer … » crée un marquage persistant pour toutes les occurrences de la valeur, et « Masquer … comme donnée privée » crée un marquage persistant contrôlé par « Masquer les données privées ». « Supprimer le marquage » apparaît sur un marquage manuel et le supprime ; une valeur toujours reconnue par le détecteur reste masquée. La valeur manuelle est une seule ligne de 8 à 512 caractères sélectionnée dans le contenu du fichier. La création d’un marquage active automatiquement l’option correspondante. Les marquages persistants ne conservent qu’une identité de valeur à clé et sa classe, jamais le texte d’origine.

Une copie en dossier ou ZIP modifie également le texte correspondant et peut ne plus se compiler ou s’exécuter. Les fichiers binaires ne sont pas analysés et restent inchangés. Un fichier texte sélectionné de plus de 16 Mio ou une erreur de détection arrête l’opération au lieu d’exporter du texte non vérifié.

Le compteur indique seulement les correspondances aux règles. Zéro ne signifie pas que le projet est sûr. La CLI utilise `--hide-secrets` ; les détails figurent dans `Docs/HideSecrets.md`.

### 12.4 Masquer les données privées
« Masquer les données privées » est désactivé par défaut. Cette option détecte les adresses e-mail, les adresses IP globales, les noms d’utilisateur locaux dans les chemins, les adresses MAC et les numéros de téléphone internationaux dans les fichiers texte sélectionnés. Les résultats utilisent les mêmes décisions d’aperçu et le même pipeline de sortie que Masquer les secrets ; les marquages manuels créés avec « Masquer … comme donnée privée » appartiennent à cette classe et suivent cette option (section 12.3). Les noms d’utilisateur locaux dans les en-têtes de chemins générés et dans la racine de l’arbre sont masqués comme une seule découverte partagée : le compteur la compte comme une valeur, l’indicateur ? précise si elle est masquée ou affichée, et un clic bascule tous les chemins masqués à la fois.

Les plages et hôtes de documentation, les noms d’utilisateur CI courants, les résolveurs DNS publics connus et les numéros fictifs documentés restent visibles. Zéro correspondance ne garantit pas la confidentialité. La CLI utilise `--hide-private-data` ; les règles complètes et les limites de la première phase figurent dans `Docs/HidePrivateData.md`.

### 12.5 Utiliser .gitignore
Lorsqu’elle est activée, l’option applique chaque `.gitignore` accessible, et pas seulement celui de la racine. Chaque fichier s’applique à son propre dossier et à tous ses sous-dossiers accessibles, jamais aux dossiers parents ou voisins.

Pour un chemin donné, les règles sont évaluées du `.gitignore` parent vers les fichiers plus profonds ; dans un même fichier, de haut en bas. La dernière règle correspondante détermine le résultat Git.

Une règle commençant par `!` annule uniquement une exclusion Git antérieure dans sa zone. Elle ne peut pas restaurer un fichier tant que son dossier parent reste exclu. Un `.gitignore` situé dans un dossier entièrement exclu et inaccessible n’est pas évalué.

Une ligne incorrecte ou non prise en charge est ignorée séparément ; les autres règles valides continuent de fonctionner. L’option couvre uniquement les fichiers `.gitignore` de l’arbre de travail. `.git/info/exclude` et les règles d’exclusion Git globales ne sont pas appliqués ; les paramètres effectifs du dépôt pour la comparaison des chemins, tels que `core.ignoreCase` et, sous macOS, `core.precomposeUnicode`, sont respectés. Lorsqu’un index Git lisible existe pour la zone du dépôt propriétaire du chemin, les fichiers suivis restent visibles même s’ils correspondent à `.gitignore` ; sans cet index ou Git CLI, cette zone revient en toute sécurité à l’évaluation des motifs seuls.

Un lien symbolique nommé `.gitignore` n’est pas suivi, conformément au comportement de Git pour ce fichier de contrôle. Si un fichier `.gitignore` ordinaire ne peut pas être lu, la zone de son répertoire est entièrement exclue de manière sûre et l’analyse signale un accès partiel au lieu d’inclure des fichiers sans évaluer toutes les règles.

Le profil intégré `standard` sélectionne `gitignore` et les huit groupes d’exclusion : `smart-ignore`, `hidden-folders`, `hidden-files`, `dot-folders`, `dot-files`, `empty-folders`, `empty-files` et `extensionless-files`.

### 12.6 Uniquement les fichiers suivis par Git
« Uniquement les fichiers suivis par Git » construit l’étape Git de l’arbre à partir des fichiers existants de l’arbre de travail enregistrés dans chaque index Git lisible. Les fichiers suivis modifiés et les nouveaux fichiers ajoutés à l’index restent inclus ; les fichiers non suivis sont exclus. Il s’agit de l’arbre de travail actuel, et non d’un instantané historique de `HEAD` ou d’un dépôt distant.

Chaque dépôt imbriqué et chaque worktree accessible sont traités indépendamment à chaque niveau d’imbrication accessible. Un dépôt enfant n’hérite pas des chemins suivis de son parent ni d’un dépôt voisin. Ce mode nécessite la CLI Git ; un index vide mais lisible est valide. Si l’espace de travail interactif du terminal (TUI) démarre dans ce mode et qu’aucun index applicable ne peut être chargé, l’espace de travail ne s’ouvre pas. Si ce mode est sélectionné de manière interactive dans un espace de travail TUI déjà ouvert et qu’aucun index applicable ne peut être chargé, la modification est refusée et le dernier mode Git utilisable reste actif. Dans la même situation, les commandes directes renvoient une erreur de stratégie ou de vérification. DevProjex ne bascule jamais silencieusement vers `.gitignore`. Lorsqu’un autre index applicable est lisible, les zones imbriquées indisponibles sont exclues avec un avertissement.

Dans un espace de travail Desktop déjà ouvert, la sélection explicite reste visible et échoue de façon sûre : la sortie et l’exportation sont bloquées si la disponibilité échoue, tandis qu’une disponibilité partielle permet de continuer avec un avertissement localisé.

« Utiliser .gitignore » et « Uniquement les fichiers suivis par Git » s’excluent lors de l’activation. La case active peut aussi être décochée pour désactiver le filtrage Git. Pour les projets locaux prenant en charge les profils, cet état est enregistré avec les types de fichiers et les autres règles d’exclusion.

### 12.7 Relation entre le filtrage Git et Smart Ignore
Le mode Git sélectionné et Smart Ignore sont contrôlés indépendamment. Le mode Git est appliqué en premier dans chaque zone Git accessible, puis Smart Ignore traite les éléments restants et les règles de base s’appliquent en dernier.

Smart Ignore peut rester masqué tant que le mode Git sélectionné couvre déjà tous ses candidats, puis apparaître après un changement ou une désactivation du mode. Les deux cases Git restent disponibles dans le dépôt.

Une négation Git avec `!` annule uniquement le résultat Git. Elle ne désactive ni Smart Ignore ni une règle de base.

### 12.8 Règles de base
Les règles « commençant par un point » vérifient le nom ; les règles « caché » vérifient l’attribut système Hidden. Selon la plateforme, elles peuvent viser le même élément ou des éléments différents.

« Fichiers vides » masque les fichiers de 0 octet. « Fichiers sans extension » masque par exemple `Dockerfile`, `Makefile` et `README`.

« Dossiers vides » masque les dossiers logiquement vides. Un dossier est logiquement vide lorsqu’aucun fichier ou sous-dossier visible ne reste après l’application des types sélectionnés et de toutes les autres règles. Son compteur peut donc changer lorsqu’une autre règle est modifiée.

### 12.9 Compteurs
Un compteur indique la contribution directe d’une règle avec les paramètres actuels, et non le nombre physique d’éléments similaires sur le disque. Un élément n’est pas attribué simultanément à plusieurs compteurs qui se recouvrent.

L’ordre stable d’attribution est : pour les dossiers, `.gitignore`, Smart Ignore, nom commençant par un point, attribut Hidden ; pour les fichiers, `.gitignore`, Smart Ignore, nom commençant par un point, absence d’extension, fichier vide, attribut Hidden. Cet ordre ne concerne que les compteurs. Pour la visibilité, tout mécanisme actif peut exclure l’élément.

### 12.10 Application des modifications
Les cases à cocher mettent d’abord à jour les options disponibles et leurs compteurs. L’arbre final est reconstruit après « Appliquer les paramètres ». Si la préparation est annulée, DevProjex revient au dernier état entièrement terminé ; aucune règle partiellement calculée n’est appliquée.

## 13) Comment l'arbre et les métriques sont calculés
Le résultat dépend de :
* types de fichiers sélectionnés
* règles d’exclusion
* filtre actif
* nœuds cochés dans l’arbre (pour les opérations basées sur la sélection)

Si l’accès est refusé, le nœud garde son nom et son icône habituels et reçoit le suffixe « [accès refusé] ».

### 13.1 Ce que montrent les compteurs de la barre d’état
La barre d’état contient deux blocs :
* Arbre — métriques de la sortie texte de l’arborescence ;
* Contenu — métriques de la sortie de contenu des fichiers.

Format :
* Lignes
* Caractères
* ~Tokens (approximation)

Les grandes valeurs sont affichées en format compact (K/M).

Important :
* « Lignes » dans le bloc « Arbre » correspond au nombre de lignes de la représentation finale de l’arborescence, et non au nombre de fichiers sur le disque ;
* cette valeur inclut les dossiers, les fichiers et les éléments techniques de l’arbre (par exemple, les nœuds avec accès refusé).

### 13.2 Comment les métriques sont calculées
Métriques de l’arbre :
* sont calculées à partir de la sortie réelle de l’arbre générée par le même pipeline d’export ;
* respectent le format d’arborescence courant.

Métriques du contenu :
* suivent les mêmes règles que la copie/export du contenu ;
* les fichiers binaires sont exclus ;
* les fichiers vides et uniquement blancs sont comptés via des marqueurs de service (`[No Content, 0 bytes]`, `[Whitespace, N bytes]`).

### 13.3 Quand les compteurs sont mis à jour
Le recalcul est effectué :
* après ouverture/actualisation d’un projet ;
* après application des paramètres (exclusions, types de fichiers, dossiers racine) ;
* lors des changements de cases à cocher dans l’arbre (avec debounce) ;
* lors du basculement du format d’arborescence (pour les opérations utilisant l’arbre).
* si le calcul en arrière-plan est annulé, les compteurs sont remis à 0 jusqu’au prochain recalcul terminé.

## 14) Icônes
Ordre de sélection :
1) type de nœud (dossier/fichier)
2) nom exact (s’il existe une règle)
3) extension
4) sinon — inconnu

## 15) Thème et effets
La section « Thème » permet de choisir Système, Clair ou Sombre et un effet d’arrière-plan :
* Transparence
* Flou
* Mica

Système est sélectionné par défaut et suit les changements de thème du système d’exploitation. Après le premier démarrage ou une réinitialisation des paramètres, un thème système clair utilise un arrière-plan opaque normal, tandis qu’un thème système sombre utilise le Flou. Si la préférence système ne peut pas être déterminée, DevProjex utilise Sombre avec le Flou. Les thèmes Clair et Sombre mémorisent leurs effets séparément. Un choix explicite de Clair ou Sombre ignore les changements du système jusqu’à ce que Système soit de nouveau sélectionné.

Les effets sont mutuellement exclusifs. Un nouveau clic sur l’effet sélectionné le désactive et rétablit un arrière-plan opaque normal.

Paramètres disponibles :
* Transparence de l’arrière-plan — disponible pour Transparence et Flou.
* Contraste de la barre supérieure — règle la barre principale contenant les commandes d’aperçu, de recherche, de filtre et de format d’arborescence.
* Transparence des menus — s’applique de la même manière au menu principal et à ses sous-menus.
* Visibilité des bordures — règle l’intensité des bordures de l’interface.

Mica utilise le matériau système de la plateforme et ne possède pas de réglage séparé pour la transparence de l’arrière-plan. Si l’effet sélectionné, Flou ou Mica, n’est pas disponible, l’application essaie d’abord l’autre effet natif. Un arrière-plan opaque normal n’est utilisé que si aucun des deux effets n’est disponible.

En mode Transparence, l’arrière-plan de la fenêtre principale reste transparent. Les menus, sous-menus et autres surfaces contextuelles utilisent le Flou lorsqu’il est pris en charge, afin que l’arborescence et le contenu situés derrière ne gênent pas la lecture.

## 16) Aide

### 16.1 Mises à jour
« Aide → Mises à jour » compare la version actuelle à la dernière version stable publiée sur GitHub. La vérification automatique est désactivée par défaut ; lorsqu’elle est activée, DevProjex effectue la vérification au démarrage si au moins sept jours se sont écoulés depuis la dernière vérification réussie. La case à cocher est appliquée immédiatement. Le dernier résultat réussi est conservé entre les exécutions de l’application et n’est pas effacé par une erreur réseau ultérieure. L’installation reste une action de l’utilisateur.

### 16.2 Réinitialiser les paramètres
Réinitialiser les paramètres (Aide → Réinitialiser les paramètres) rétablit les valeurs par défaut du thème, des effets, du mode compact, de l’animation de déploiement de l’arborescence et de la langue de l’interface. Les profils de projet, l’historique et les fichiers sur le disque ne sont pas modifiés.

### 16.3 Réinitialiser les données
Réinitialiser les données (Aide → Réinitialiser les données) supprime les profils enregistrés de paramètres des projets locaux :
* types de fichiers sélectionnés ;
* options sélectionnées dans la section « Exclusions ».

Important :
* l’historique « Récents » des dossiers locaux n’est pas effacé ;
* l’historique des « Dépôts récents » dans la fenêtre Git Clone n’est pas effacé ;
* les fichiers et dossiers des projets sur le disque ne sont ni modifiés ni supprimés.

## 17) Langues
La langue se choisit via le menu Langue.
La langue choisie est conservée entre les lancements. « Aide → Réinitialiser les paramètres » efface ce choix enregistré et revient à la langue par défaut.

## 18) Barre de progression et annulation
La partie centrale de la barre d’état affiche l’opération active et sa progression.

Modes de progression :
* Indeterminate — sans pourcentage (durée inconnue).
* Determinate — avec pourcentage (0–100).

Comportement :
* pendant le calcul de données en arrière-plan, une progression en pourcentage est affichée ;
* pour certaines opérations Git, le pourcentage est affiché si la source de progression le fournit ;
* la mise à jour des options disponibles et l’application des paramètres sont affichées si l’opération prend un temps perceptible ;
* les opérations rapides se terminent sans afficher de progression.

Bouton X (annuler) dans la barre d’état :
* exécute une annulation best-effort pour les opérations qui prennent en charge l’annulation ;
* arrête le calcul de données en arrière-plan ;
* lors de l’annulation d’une actualisation des options disponibles, rétablit le dernier état terminé du panneau ;
* pour les opérations sans prise en charge de l’annulation, arrête l’indication dans la barre d’état, tandis que l’opération peut se terminer en arrière-plan.

## 19) Notes
* Si les permissions sont insuffisantes, l’app peut proposer un redémarrage avec élévation ; sinon un avertissement s’affiche.
