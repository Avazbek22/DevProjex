## 1) Qu’est‑ce que c’est et pourquoi
DevProjex prépare rapidement le contexte d’un projet : affiche la structure dossiers/fichiers, permet de sélectionner des éléments et de copier l’arborescence et/ou le contenu des fichiers dans le presse‑papiers. Utile pour code review, support, formation et partage de structure avec un assistant IA.

Important : l’application est en lecture seule et ne modifie jamais les fichiers.

## 2) Arborescence du projet
* Icônes de type fichier/dossier.
* Cases à cocher sur les nœuds.
* Déplier/replier.

Cases à cocher : cocher un nœud s’applique aux enfants ; l’état des parents se recalculent automatiquement.

Raccourcis :
* Ctrl+E — tout déplier
* Ctrl+W — tout replier (la racine reste ouverte)

## 3) Fichier
* Ouvrir le dossier… — ouvrir le dossier racine (Ctrl+O)
* Nouvelle fenêtre — ouvrir une nouvelle instance indépendante de DevProjex
* Récents — liste des dossiers locaux ouverts récemment
* Actualiser — relire un dossier local et reconstruire l’arborescence (F5)
* Exporter vers un fichier :
  * Exporter l’arborescence
  * Exporter le contenu
  * Exporter arborescence et contenu

Règles de format :
* Exporter l’arborescence :
  * ASCII -> uniquement `.txt`.
  * JSON -> `.json` par défaut, avec `.json` et `.txt` disponibles dans la boîte de sauvegarde.
  * XML -> `.xml` par défaut, avec `.xml` et `.txt` disponibles dans la boîte de sauvegarde.
  * MD -> `.md` par défaut, avec `.md` et `.txt` disponibles dans la boîte de sauvegarde.
* Exporter le contenu — toujours au format texte du contenu, fichier `.txt` (le sélecteur de format d’arborescence n’influence pas).
* Exporter arborescence et contenu — toujours fichier `.txt` ; le format d’arborescence choisi n’influence que le format du bloc arborescence dans le résultat.

Les fichiers exportés sont écrits en UTF-8 sans BOM.

### Drag & Drop
Le glisser-déposer fonctionne dans la zone de démarrage (Drop Zone) quand aucun projet n’est chargé.

Règles :
* vous pouvez déposer un dossier ;
* vous pouvez déposer un fichier — dans ce cas, le dossier contenant ce fichier est ouvert ;
* si plusieurs éléments sont déposés, le premier chemin local valide est utilisé ;
* si un chemin est indisponible ou inexistant, les mêmes vérifications d’accès que pour « Ouvrir le dossier… » sont appliquées ;
* les éléments non pris en charge ou non locaux sont ignorés.

### Récents
L’élément « Fichier → Récents » affiche l’historique des dossiers locaux ouverts récemment.

Règles :
* seuls les dossiers locaux sont ajoutés à la liste ;
* les dépôts Git clonés via DevProjex ne sont pas ajoutés à cette liste ;
* aucun doublon n’est créé — rouvrir le même dossier le remonte en haut de la liste ;
* jusqu’à 15 derniers dossiers sont conservés ;
* l’historique est conservé entre les démarrages de l’application.

Pour chaque élément, le dossier parent et le nom du projet sont affichés, par exemple `Projects / App`.

## 4) Lancement depuis le terminal
DevProjex peut être lancé depuis le terminal.

Si la commande est déjà configurée, ouvrez un terminal et exécutez :
`devprojex --help`

Vous verrez ainsi toutes les commandes, options et exemples disponibles.

Exemples :
* `devprojex .` — ouvrir le dossier courant.
* `devprojex "C:\Projects\App"` — ouvrir le dossier indiqué.
* `devprojex . --export tree` — afficher l’arborescence du projet dans le terminal.
* `devprojex . --export content` — afficher le contenu des fichiers dans le terminal.
* `devprojex . --export tree-content` — afficher l’arborescence et le contenu dans le terminal.
* `devprojex . --export tree-content -o context.txt` — enregistrer le résultat dans un fichier.
* `devprojex --benchmark "C:\Projects\App"` — mesurer le workflow standard de rapport de projet.
* `devprojex --last --preview` — ouvrir le dernier projet directement en mode aperçu.
* `devprojex --benchmark-ui "C:\Projects\App"` — mesurer le scénario UI standard.
* `devprojex --session-metrics "C:\Projects\App"` — enregistrer les métriques de la session UI jusqu’à la fermeture de la fenêtre.

Particularités :
* `.` désigne le dossier courant du terminal ;
* les chemins contenant des espaces doivent être placés entre guillemets ;
* si aucun fichier de sortie n’est indiqué, le résultat est affiché directement dans le terminal ;
* la commande ne modifie pas les fichiers du projet — DevProjex fonctionne en lecture seule.

Si la commande `devprojex` ne fonctionne pas, ouvrez dans DevProjex :
« Aide → Lancement depuis le terminal ».

## 5) Git
Le menu Git n’est disponible que pour les projets clonés via DevProjex (Git Clone). L’application ne touche pas à vos fichiers — elle travaille uniquement avec le cache.

Le cache est stocké dans le dossier temporaire du système. Sous Windows, c’est généralement :
`%TEMP%\DevProjex\RepoCache`

* Branche — affiche la liste des branches disponibles avec indication de la branche active ; le changement met à jour l’arborescence sur la branche choisie. Si la branche existe déjà en local, le changement se fait hors ligne (sans mise à jour). Si elle n’existe pas localement, elle est récupérée (fetch) et créée localement.
* Obtenir les mises à jour — met à jour uniquement la branche courante : fetch et reset vers origin/<branche>. Pour un projet Git Clone, F5 effectue la même action ; la commande normale « Fichier → Actualiser » est désactivée.

### Fenêtre de clonage
Dans la fenêtre Git Clone, une liste « Dépôts récents » peut apparaître sous le champ URL.

Règles :
* la liste apparaît seulement si l’historique contient déjà des dépôts clonés récemment ;
* seules les URL des dépôts sont ajoutées à la liste ;
* les dossiers locaux ne sont pas ajoutés à cette liste ;
* aucun doublon n’est créé — re-cloner le même dépôt le remonte en haut de la liste ;
* jusqu’à 7 derniers dépôts sont conservés ;
* l’historique est conservé entre les démarrages de l’application.

Si vous choisissez un élément dans la liste, l’URL est automatiquement insérée dans le champ de saisie.
Pendant un clonage actif, la liste est temporairement masquée.

## 6) Copier
### Sélecteur de format de l’arborescence (ASCII / JSON / XML / MD)
Le sélecteur définit le format de représentation de l’arborescence pour les opérations où l’arbre participe au résultat.

* ASCII — arborescence textuelle avec branches.
* JSON — arborescence structurée en JSON.
* XML — arborescence XML compacte pour les parseurs et outils.
* MD — liste Markdown imbriquée pour la documentation et les prompts IA.

Le sélecteur influence :
* Copier l’arborescence
* Copier l’arborescence + le contenu
* Exporter l’arborescence
* Exporter arborescence et contenu

Le sélecteur n’influence pas :
* Copier le contenu
* Exporter le contenu

### Copier l’arborescence
Copie l’arborescence du projet.
S’il y a des nœuds cochés, l’arborescence est construite à partir de la sélection ; si la sélection est vide ou invalide, l’arborescence complète est copiée.
Le format du résultat est défini par le sélecteur de format d’arborescence.
Raccourcis : Ctrl+Shift+C et Ctrl+Alt+C.

### Copier le contenu
Copie le contenu des fichiers :
* si des fichiers sont cochés — seuls ceux-ci ; sinon — tous les fichiers du projet ;
* les fichiers non textuels sont ignorés (y compris les binaires) ;
* pour les fichiers texte vides, le chemin et la ligne `[No Content, 0 bytes]` sont ajoutés ;
* pour les fichiers ne contenant que des espaces/retours à la ligne, le chemin et la ligne `[Whitespace, N bytes]` sont ajoutés.
Raccourci : Ctrl+Alt+V.

### Copier l’arborescence + le contenu
Combine arborescence et contenu :
* arborescence depuis la sélection ; si la sélection est vide ou invalide, l’arborescence complète est utilisée ;
* contenu selon les mêmes règles que « Copier le contenu » ;
* le format du bloc arborescence est défini par le sélecteur de format d’arborescence.
Raccourci : Ctrl+Shift+V.

### Représentations de l’arborescence
Les formats représentent différemment la même arborescence de projet sélectionnée.

JSON :
* `rootPath` — chemin racine absolu normalisé avec `/`.
* `tree` — contenu du dossier racine.
* L’export JSON utilise ce format d’arborescence : les tableaux contiennent les fichiers, les objets contiennent les sous-dossiers, `/` contient les fichiers du dossier courant, et `[]` représente un dossier vide.

XML :
* le nœud racine est `<t r="...">` ;
* les dossiers sont `<d n="...">` ;
* les fichiers sont `<f>File.cs</f>`.

MD :
* commence par `Root: ...` ;
* utilise une liste Markdown imbriquée ;
* les dossiers se terminent par `/`.

Arborescence + contenu :
* le format d’arborescence choisi s’applique au bloc arborescence ;
* le bloc contenu reste textuel ;
* les en-têtes de fichiers du bloc contenu utilisent des chemins relatifs avec `/` ;
* export en `.txt`.

## 7) Mode aperçu
S’ouvre avec le bouton icône œil dans la barre supérieure ou avec Ctrl+B.

Affiche le résultat final dans un espace de travail séparé, à côté de l’arborescence. Ce mode ne copie rien dans le presse-papiers et n’exporte rien vers un fichier par lui-même : il sert uniquement à la consultation.

Par défaut, l’espace de travail s’ouvre ainsi :
* à gauche — l’arborescence du projet ;
* au centre — le panneau d’aperçu ;
* à droite — le panneau des paramètres, s’il était ouvert.

Modes disponibles :
* Arborescence
* Contenu
* Arborescence et contenu

Les mêmes règles que pour la copie et l’export sont appliquées :
* les nœuds cochés sont pris en compte ;
* si la sélection est vide, l’ensemble complet des données est utilisé ;
* les règles d’ignorance et les paramètres de sélection actuels sont appliqués.

En plus :
* les fichiers de l’aperçu sont séparés par des lignes horizontales ;
* pendant le défilement, le chemin du fichier courant reste épinglé en haut ;
* le zoom de l’arborescence et celui de l’aperçu peuvent vivre séparément.
* en mode aperçu, vous pouvez copier soit le résultat complet actuel, soit le bloc du fichier actuellement visible sans passer par le menu « Copier ».

Boutons :
* bouton de copie à gauche dans le panneau supérieur d’aperçu — copie le mode d’aperçu actuel :
  * Arborescence
  * Contenu
  * Arborescence et contenu
* X dans le panneau de l’arborescence — masque l’arborescence et laisse uniquement le panneau d’aperçu ;
* X dans la barre supérieure de l’aperçu — ferme complètement le mode aperçu ;
* petit bouton de copie dans l’en-tête épinglé du fichier — copie le bloc du fichier actuellement visible tel qu’il est affiché dans l’aperçu ;
* un nouveau clic sur l’icône œil ou Ctrl+B ferme aussi le mode aperçu.

La recherche et le filtre restent disponibles tant que le panneau de l’arborescence est visible dans l’aperçu.
Si l’arborescence est masquée, la recherche et le filtre deviennent temporairement indisponibles jusqu’à la sortie du mode aperçu seul.

## 8) Affichage
### Zoom
* Ctrl++ / Ctrl+= — agrandir
* Ctrl+- — réduire
* Ctrl+0 — réinitialiser
* Ctrl + molette — zoom fluide dans le panneau sous le curseur

Comportement :
* en mode normal, c’est l’arborescence qui est zoomée ;
* en aperçu avec l’arborescence visible, Agrandir, Réduire et Réinitialiser du menu s’appliquent à la fois à l’arborescence et à l’aperçu ;
* avec Ctrl + molette, l’arborescence et l’aperçu zooment indépendamment selon la position du curseur ;
* en mode aperçu seul, seul le panneau d’aperçu est zoomé.

Plage : 6–28, reset : 15.

### Mode compact
Rend l’interface plus dense : moins d’espaces dans l’arbre et les paramètres.
Quand l’espace de travail d’aperçu est actif, le mode compact est activé automatiquement.

### Animation de l'arborescence
Active une animation de glissement fluide au survol des lignes de l'arborescence.

### Police de l’arborescence
La police de l’arborescence se choisit via « Affichage → Police de l’arborescence ».
« Par défaut » rétablit la police standard de l’arborescence.
La police choisie est appliquée après clic sur « Appliquer » dans le panneau des paramètres.

## 9) Recherche dans l'arbre
Ouvre la recherche, met en évidence les correspondances et permet la navigation.
* Ctrl+F — afficher/masquer
* Enter — résultat suivant
* Shift+Enter — précédent
* Esc — fermer

La recherche n’ouvre que les branches nécessaires ; en effaçant la requête, l’arbre se replie (sauf la racine).
Pour un très grand nombre de correspondances, l’application peut limiter l’ouverture automatique et la mise en évidence globale afin de garder l’interface réactive.
À la fermeture de la recherche, la requête est effacée après la fin de l’animation de fermeture.

Limitations :
* à l’ouverture de la recherche, le filtre se ferme automatiquement ;
* la recherche reste disponible dans l’aperçu tant que le panneau de l’arborescence est visible ;
* si l’arborescence est masquée, la recherche devient temporairement indisponible.

## 10) Filtrer par nom
Affiche uniquement les nœuds correspondant au filtre et leurs parents. Mise à jour avec délai (debounce).
* Ctrl+Shift+N — afficher/masquer le filtre
* Esc — fermer le filtre

Limitations :
* à l’ouverture du filtre, la recherche se ferme automatiquement ;
* le filtre reste disponible dans l’aperçu tant que le panneau de l’arborescence est visible ;
* si l’arborescence est masquée, le filtre devient temporairement indisponible.

## 11) Options
À droite sont disponibles :
* Appliquer
* Ignorer
* Types de fichiers
* Dossiers de premier niveau

Les changements dans « Ignorer », « Types de fichiers » et « Dossiers de premier niveau » sont préparés dans le panneau et appliqués après clic sur « Appliquer ».

Après la modification d’une case, l’application peut actualiser en arrière-plan les options disponibles et leurs compteurs. L’arborescence résultante n’est reconstruite qu’après un clic sur « Appliquer ».

Si l’actualisation des options disponibles est annulée avec le bouton X de la barre d’état, les changements inachevés ne sont pas appliqués et le panneau revient à son dernier état terminé.

Chaque liste a un bouton Tous.

Remarque sur « Types de fichiers » :
* cette liste affiche uniquement les fichiers avec extension ;
* les fichiers sans extension ne sont pas ajoutés à cette liste et sont gérés par une option séparée dans « Ignorer ».

Ctrl+P — afficher/masquer le panneau.

### 11.1 Profils de paramètres des projets locaux
Pour les dossiers locaux, DevProjex mémorise les derniers paramètres de projet appliqués :
* dossiers de premier niveau sélectionnés ;
* types de fichiers sélectionnés ;
* options sélectionnées dans le bloc « Ignorer ».

L’enregistrement est effectué après clic sur « Appliquer ».
Lors de la réouverture du même dossier local, les paramètres sont restaurés automatiquement.

Important :
* les profils sont enregistrés uniquement pour les projets locaux ;
* pour les projets ouverts via Git Clone, les profils ne sont pas enregistrés ;
* si certaines options enregistrées ne sont plus disponibles dans le projet actuel, elles sont ignorées, les autres paramètres sont appliqués.
* si l’actualisation ou la réouverture fait apparaître un nouveau dossier de premier niveau, un nouveau type de fichiers ou une nouvelle option dans « Ignorer », cet élément est activé par défaut ;
* les éléments déjà connus conservent le choix explicite de l’utilisateur : de nouveaux fichiers d’un type désactivé ne réactivent pas ce type.

## 12) Ignorer
La liste « Ignorer » est générée automatiquement à partir du chemin actuel et des dossiers de premier niveau sélectionnés.

Ordre des options :
* Smart ignore (si applicable)
* Utiliser .gitignore (si applicable)
* Dossiers vides
* Fichiers vides
* Dossiers cachés
* Fichiers cachés
* Dossiers commençant par un point
* Fichiers commençant par un point
* Fichiers sans extension

La liste dépend de l’arborescence actuelle et des règles actives. Une option de base n’est affichée que si elle peut modifier le résultat. Si les éléments correspondants sont déjà masqués par une autre règle, l’option peut disparaître temporairement puis réapparaître après une modification des paramètres.

Les options `.gitignore` et Smart Ignore tiennent également compte de leur effet réel sur l’arborescence. Une option explicitement désactivée peut rester visible afin de pouvoir être réactivée.

Une nouvelle option est activée par défaut lors de sa première apparition. Une option déjà connue conserve le choix explicite de l’utilisateur, même si elle a temporairement disparu de la liste.

La ligne sous « Utiliser .gitignore » sépare les règles Git/Smart des règles de visibilité de base.

### 12.1 Portée des règles
L’application construit des zones de projet (scopes) où les règles d’ignore sont appliquées :
* racine (si la racine contient `.gitignore` ou un marqueur de projet)
* dossiers du premier niveau
* sous-dossiers de projet imbriqués

La recherche des zones de projet imbriquées est limitée et dépend de la structure du dossier.
Une recherche peu profonde est utilisée pour les projets ordinaires. La recherche peut aller plus loin dans les monorepos reconnus.
Les dossiers système, les dépendances et les artefacts de build confirmés sont ignorés pendant la recherche des zones.

Cette limite concerne uniquement la détection des zones imbriquées pour `.gitignore` et Smart Ignore. Une fois la zone trouvée, les règles sont appliquées à son contenu par le parcours normal de l’arbre.

### 12.2 « Utiliser .gitignore »
* Activé : les règles `.gitignore` sont appliquées dans les zones détectées.
* Désactivé : les règles `.gitignore` sont entièrement désactivées.

Dans un dossier multi-projets, le `.gitignore` d’un projet ne s’applique pas aux projets voisins hors de sa zone.

### 12.3 Fonctionnement de Smart Ignore
Smart Ignore masque les artefacts de build courants, les caches d’outils et les magasins de dépendances. Il combine deux approches complémentaires :

1. Règles de projet. Des fichiers marqueurs comme `.csproj`, `package.json`, `pyproject.toml` ou `Cargo.toml` déterminent le type de projet. Les règles de la technologie correspondante sont ensuite appliquées dans sa zone.
2. Vérification des artefacts. Pour des noms ambigus comme `build`, `vendor`, `packages`, `cache`, `pkg` ou `Library`, le nom seul ne suffit pas. Le contenu du dossier doit confirmer qu’il s’agit d’un résultat de build, d’un cache ou d’un magasin de dépendances.

Dans un projet reconnu, un dossier d’artefacts standard est identifié par la combinaison du type de projet et du nom du dossier. Hors de ce contexte, Smart Ignore reste prudent et ne masque pas un dossier ordinaire uniquement parce que son nom est similaire.

Certains artefacts portables confirmés peuvent aussi être masqués hors d’une zone de projet formelle. Cela permet de traiter les espaces de travail mixtes sans étendre les règles d’un projet aux dossiers source voisins.

Désactiver Smart Ignore désactive les deux approches.

### 12.4 Règles de base
Options :
* Dossiers cachés
* Fichiers cachés
* Dossiers commençant par un point
* Fichiers commençant par un point
* Dossiers vides
* Fichiers vides
* Fichiers sans extension

Quand une option est activée, elle masque les éléments correspondants dans l’arbre et dans les résultats de copie/export.
Les règles de base s’activent séparément de `.gitignore` et de Smart Ignore, mais le résultat final est toujours calculé à partir de l’arbre courant après application de tous les filtres actifs.

### 12.5 Interaction entre `.gitignore` et Smart Ignore
1. Un projet avec une seule zone et un `.gitignore`.
En général, seule l’option « Utiliser .gitignore » est affichée. Ce bouton contrôle la politique d’ignore commune du projet : lorsqu’il est activé, `.gitignore` et les règles Smart applicables fonctionnent ensemble ; lorsqu’il est désactivé, les deux mécanismes sont arrêtés.

2. Un projet sans `.gitignore`.
Smart Ignore est affiché s’il peut modifier l’arborescence.

3. Un espace de travail contenant plusieurs projets.
`.gitignore` ne s’applique que dans les zones où il est trouvé. Smart Ignore peut apparaître séparément et compléter les règles dans les autres zones applicables. Dans ce cas, les boutons fonctionnent indépendamment.

4. Un dossier sans règles applicables.
Si `.gitignore` et Smart Ignore ne modifient pas le résultat, ces options sont masquées. Seules les règles de base applicables restent affichées.

### 12.6 Dossiers vides
Masque les dossiers logiquement vides dans l’arbre et dans les résultats de copie/export.
Un dossier logiquement vide est un dossier dans lequel il ne reste plus aucun descendant visible après application des règles de visibilité actuelles, de `.gitignore`, de Smart Ignore et des types de fichiers sélectionnés.
Si le dossier lui-même n’est pas masqué par d’autres règles, sa suppression de l’arbre est contrôlée précisément par cette option.

### 12.7 Fichiers vides
Masque les fichiers vides de taille 0 octet dans l’arbre et dans les résultats de copie/export.

### 12.8 Fichiers sans extension
Masque les fichiers sans extension (par exemple : `Dockerfile`, `Makefile`, `README`) dans l’arbre et dans les résultats de copie/export.

### 12.9 Compteurs dans le bloc « Ignorer »
Le nombre est affiché à côté des règles de base disponibles au format `(N)`.

Un compteur indique la contribution directe de cette règle avec la combinaison actuelle de paramètres, et non le nombre total d’éléments similaires sur le disque. Modifier une option peut donc changer le compteur d’une autre : un élément ne doit pas être compté à la fois comme résultat de plusieurs règles qui se recouvrent.

Par exemple, sous Windows, le dossier `.git` peut à la fois commencer par un point et être caché. Tant que « Dossiers commençant par un point » le masque, il n’est pas compté séparément comme résultat de « Dossiers cachés ».

## 13) Comment l'arbre et les métriques sont calculés
Le résultat dépend de :
* dossiers de premier niveau sélectionnés
* types de fichiers sélectionnés
* règles d’exclusion
* filtre actif
* nœuds cochés dans l’arbre (pour les opérations basées sur la sélection)

Si l’accès est refusé, le nœud est marqué Accès refusé.

### 13.1 Ce que montrent les compteurs de la barre d’état
La barre d’état contient deux blocs :
* Arbre — métriques de la sortie texte de l’arborescence ;
* Contenu — métriques de la sortie de contenu des fichiers.

Format :
* Lignes
* Caractères
* ~Tokens (approximation)

Les grandes valeurs sont affichées en format compact (K/M).

Important :
* « Lignes » dans le bloc « Arbre » correspond au nombre de lignes de la représentation finale de l’arborescence, et non au nombre de fichiers sur le disque ;
* cette valeur inclut les dossiers, les fichiers et les éléments techniques de l’arbre (par exemple, les nœuds avec accès refusé).

### 13.2 Comment les métriques sont calculées
Métriques de l’arbre :
* sont calculées à partir de la sortie réelle de l’arbre générée par le même pipeline d’export ;
* respectent le format d’arborescence courant.

Métriques du contenu :
* suivent les mêmes règles que la copie/export du contenu ;
* les fichiers binaires sont exclus ;
* les fichiers vides et uniquement blancs sont comptés via des marqueurs de service (`[No Content, 0 bytes]`, `[Whitespace, N bytes]`).

### 13.3 Quand les compteurs sont mis à jour
Le recalcul est effectué :
* après ouverture/actualisation d’un projet ;
* après application des paramètres (ignore, types de fichiers, dossiers racine) ;
* lors des changements de cases à cocher dans l’arbre (avec debounce) ;
* lors du basculement du format d’arborescence (pour les opérations utilisant l’arbre).
* si le calcul en arrière-plan est annulé, les compteurs sont remis à 0 jusqu’au prochain recalcul terminé.

## 14) Icônes
Ordre de sélection :
1) type de nœud (dossier/fichier)
2) nom exact (s’il existe une règle)
3) extension
4) sinon — inconnu

## 15) Thème et effets
La section « Thème » permet de choisir un thème clair ou sombre et un effet d’arrière-plan :
* Transparence
* Flou
* Mica

Les effets sont mutuellement exclusifs. Un nouveau clic sur l’effet sélectionné le désactive et rétablit un arrière-plan opaque normal.

Paramètres disponibles :
* Transparence de l’arrière-plan — disponible pour Transparence et Flou.
* Contraste de la barre supérieure — règle la barre principale contenant les commandes d’aperçu, de recherche, de filtre et de format d’arborescence.
* Transparence des menus — s’applique de la même manière au menu principal et à ses sous-menus.
* Visibilité des bordures — règle l’intensité des bordures de l’interface.

Mica utilise le matériau système de la plateforme et ne possède pas de réglage séparé pour la transparence de l’arrière-plan. Si un effet n’est pas pris en charge par le système, l’application utilise un affichage opaque sûr.

## 16) Aide

### 16.1 Réinitialiser les paramètres
Réinitialiser les paramètres (Aide → Réinitialiser les paramètres) rétablit les valeurs par défaut du thème, des effets, du mode compact, de l’animation de l’arborescence et de la langue de l’interface. Les profils de projet, l’historique et les fichiers sur le disque ne sont pas modifiés.

### 16.2 Réinitialiser les données
Réinitialiser les données (Aide → Réinitialiser les données) supprime les profils enregistrés de paramètres des projets locaux :
* dossiers de premier niveau sélectionnés ;
* types de fichiers sélectionnés ;
* options sélectionnées dans le bloc « Ignorer ».

Important :
* l’historique « Récents » des dossiers locaux n’est pas effacé ;
* l’historique des « Dépôts récents » dans la fenêtre Git Clone n’est pas effacé ;
* les fichiers et dossiers des projets sur le disque ne sont ni modifiés ni supprimés.

## 17) Langues
La langue se choisit via le menu Langue.
La langue choisie est conservée entre les lancements. « Aide → Réinitialiser les paramètres » efface ce choix enregistré et revient à la langue par défaut.

## 18) Barre de progression et annulation
La partie centrale de la barre d’état affiche l’opération active et sa progression.

Modes de progression :
* Indeterminate — sans pourcentage (durée inconnue).
* Determinate — avec pourcentage (0–100).

Comportement :
* pendant le calcul de données en arrière-plan, une progression en pourcentage est affichée ;
* pour certaines opérations Git, le pourcentage est affiché si la source de progression le fournit ;
* la mise à jour des options disponibles et l’application des paramètres sont affichées si l’opération prend un temps perceptible ;
* les opérations rapides se terminent sans afficher de progression.

Bouton X (annuler) dans la barre d’état :
* exécute une annulation best-effort pour les opérations qui prennent en charge l’annulation ;
* arrête le calcul de données en arrière-plan ;
* lors de l’annulation d’une actualisation des options disponibles, rétablit le dernier état terminé du panneau ;
* pour les opérations sans prise en charge de l’annulation, arrête l’indication dans la barre d’état, tandis que l’opération peut se terminer en arrière-plan.

## 19) Notes
* Par défaut, le thème sombre avec l’effet Flou est utilisé. Si l’effet n’est pas pris en charge par le système, l’application utilise un affichage opaque sûr.
* Si les permissions sont insuffisantes, l’app peut proposer un redémarrage avec élévation ; sinon un avertissement s’affiche.
