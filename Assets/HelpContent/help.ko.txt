## 1) 개요 및 용도
DevProjex는 프로젝트 컨텍스트를 빠르게 준비합니다. 폴더와 파일 구조를 표시하고, 확인란으로 항목을 선택하고, 트리나 파일 내용을 클립보드에 복사할 수 있습니다. 코드 검토, 지원, 학습, AI 도우미와 프로젝트 구조를 공유할 때 유용합니다.

중요: DevProjex는 사용자가 연 프로젝트의 파일을 수정하지 않습니다. 유일한 예외는 Cursor 또는 VS Code에 대한 명시적인 MCP 연결로, 이 경우 `.cursor/mcp.json` 또는 `.vscode/mcp.json`을 만들거나 업데이트합니다(섹션 19.1).

## 2) 프로젝트 트리
* 파일 및 폴더 유형 아이콘.
* 노드의 확인란.
* 펼치기 및 접기.

확인란: 노드를 선택하면 하위 노드에도 적용되며, 상위 노드의 상태는 자동으로 다시 계산됩니다.

단축키:
* {mod}E — 모두 펼치기
* {collapseAll} — 모두 접기(루트는 펼친 상태로 유지)

### 상황에 맞는 메뉴
노드를 마우스 오른쪽 버튼으로 클릭하거나, 포커스가 있는 노드에서 {shift}F10 또는 메뉴 키를 누르세요.
* 파일 탐색기에 표시 / Finder에서 보기 / 파일 관리자에서 열기 — 시스템 파일 관리자에서 항목을 표시합니다. 이름은 현재 플랫폼에 맞게 표시됩니다.
* 전체 경로 복사 — 항목의 절대 경로를 복사합니다.
* 상대 경로 복사 — 루트 폴더 이름으로 시작하는 프로젝트 루트 기준 경로를 복사합니다(예: `project/src/File.cs`).
* 내용 복사 — 파일의 경우, 복사 및 내보내기와 똑같이 콘텐츠 변환을 적용한 내용을 복사합니다.
* 이 항목만 선택 — 이 노드만 선택하고 나머지는 해제합니다. 다른 항목도 선택되어 있을 때만 표시됩니다.
* 하위 트리 펼치기 / 하위 트리 접기 — 폴더에서 사용할 수 있습니다.

경로가 디스크에 더 이상 없으면 파일 관리자에서 항목을 열거나 내용을 복사할 때 오류 메시지가 표시됩니다. 경로 복사는 계속 작동합니다.

## 3) 파일
* 폴더 열기... — 루트 폴더를 엽니다({mod}O)
* 새 창 — 독립적인 새 DevProjex 인스턴스를 엽니다
* 최근 폴더 — 최근에 연 로컬 폴더 목록
* 새로 고침 — 로컬 폴더를 다시 검색하고 트리를 다시 만듭니다(F5)
* 파일로 내보내기:
  * 트리 내보내기
  * 콘텐츠 내보내기
  * 트리 및 콘텐츠 내보내기
* 프로젝트 내보내기:
  * 폴더로…
  * ZIP 아카이브로…

“프로젝트 내보내기”는 디렉터리 구조를 유지하면서 현재 트리로 별도의 폴더 또는 ZIP 아카이브를 만듭니다.

선택한 파일 형식, 제외 규칙, 선택한 항목이 반영됩니다. 아무것도 선택하지 않으면 현재 트리 전체를 내보냅니다.

텍스트 파일과 바이너리 파일이 복사되고, 포함된 빈 폴더도 유지됩니다. 원본 파일은 수정되지 않습니다. 결과를 원본 프로젝트 안에 저장할 수는 없습니다.

내보내는 동안에는 트리나 설정 변경, 필터 사용, 형식이나 미리보기 모드 변경, Git 명령 실행, 새로 고침, 다른 프로젝트 열기를 할 수 없습니다.

형식 규칙:
* 트리 내보내기:
  * ASCII -> `.txt`만 가능합니다.
  * JSON -> 기본값은 `.json`이며, 저장 대화 상자에서 `.json`과 `.txt`를 선택할 수 있습니다.
  * XML -> 기본값은 `.xml`이며, 저장 대화 상자에서 `.xml`과 `.txt`를 선택할 수 있습니다.
  * MD -> 기본값은 `.md`이며, 저장 대화 상자에서 `.md`와 `.txt`를 선택할 수 있습니다.
* 콘텐츠 내보내기 — 항상 텍스트 콘텐츠 형식의 `.txt` 파일입니다(트리 형식 전환은 적용되지 않음).
* 트리 및 콘텐츠 내보내기 — 항상 `.txt` 파일입니다. 선택한 트리 형식은 결과 안의 트리 블록 형식에만 영향을 줍니다.

내보낸 파일은 BOM 없는 UTF-8로 기록됩니다.

### 드래그 앤 드롭
프로젝트가 로드되지 않았을 때 시작 영역(드롭 영역)에서 드래그 앤 드롭을 사용할 수 있습니다.

규칙:
* 폴더를 놓을 수 있습니다.
* 파일을 놓을 수도 있으며, 이 경우 파일이 들어 있는 폴더가 열립니다.
* 여러 항목을 놓으면 첫 번째로 적합한 로컬 경로가 사용됩니다.
* 경로를 사용할 수 없거나 존재하지 않으면 “폴더 열기...”와 같은 접근 검사가 적용됩니다.
* 지원되지 않거나 로컬이 아닌 항목은 무시됩니다.

### 최근 폴더
“파일 → 최근 폴더” 항목은 최근에 연 로컬 폴더의 기록을 보여 줍니다.

규칙:
* 로컬 폴더만 목록에 추가됩니다.
* DevProjex로 복제한 Git 저장소는 이 목록에 추가되지 않습니다.
* 중복 항목은 만들어지지 않습니다. 같은 폴더를 다시 열면 해당 폴더가 맨 위로 이동합니다.
* 최근 폴더는 최대 32개까지 저장됩니다.
* 기록은 앱을 다시 실행해도 유지됩니다.

각 항목에는 상위 폴더와 프로젝트 이름이 표시됩니다(예: `Projects / App`).

## 4) 터미널에서 실행
DevProjex는 대화형 터미널 작업공간과, 스크립트 및 CI에서 바로 사용할 수 있는 명령을 제공합니다.

명령이 이미 설정되어 있다면 터미널을 열고 다음을 실행하세요.
`devprojex --help`

최상위 명령과 옵션이 나열됩니다. 각 명령의 옵션과 예를 보려면 `devprojex help <command>`를 실행하세요.

예:
* `devprojex` — 대화형 터미널 작업공간을 엽니다. 작업공간에서는 `:` 명령줄(예: `:copy`, `:analyze`, `:branch`, `:language`)로 작업을 실행합니다. 전체 명령 목록은 작업공간의 기본 제공 도움말과 프로젝트 문서를 참조하세요.
* `devprojex tui .` — 지정한 폴더를 터미널 작업공간에서 바로 엽니다.
* `devprojex open . --preview` — 현재 폴더를 데스크톱 미리보기에서 엽니다.
* `devprojex analyze . --format json` — 현재 프로젝트를 분석하여 JSON으로 출력합니다.
* `devprojex tree .` — 프로젝트 트리를 터미널에 출력합니다.
* `devprojex export context . --format markdown -o ../devprojex-context.md` — AI용 컨텍스트를 원본 프로젝트 밖에 저장합니다.
* `devprojex export project . --as folder -o ../devprojex-submission` — 유효한 프로젝트 트리를 지정한 폴더로 내보냅니다.
* `devprojex export project . --as zip -o ../devprojex-submission.zip` — 유효한 프로젝트 트리를 ZIP 아카이브로 내보냅니다.
* `devprojex export context https://github.com/owner/repo -o -` — 직접 복제하지 않고 원격 저장소를 압축합니다.
* `devprojex analyze . --git-mode tracked --exclude smart-ignore` — Git에서 추적하는 파일을 스마트 무시와 함께 분석합니다.
* `devprojex search Configure . --symbols` — 선언이 정의된 위치를 찾습니다. `--symbols`는 선언 이름을 받으며 정규식 구문은 거부합니다. 정규식으로 텍스트를 검색하려면 `--regex`를 사용하세요.
* `devprojex related src/App.cs` — 파일이 사용하는 파일과 그 파일을 사용하는 파일을 나열합니다.
* `devprojex mcp --root .` — AI 에이전트가 프로젝트를 안전하게 읽을 수 있도록 로컬 읽기 전용 MCP 서버를 시작합니다.
* `devprojex mcp connect . --client claude-code` — AI 클라이언트를 프로젝트에 연결합니다(섹션 19).
* `devprojex mcp log . --last` — 에이전트 저널의 최근 세션을 표시합니다.

참고:
* `.`는 현재 터미널 폴더를 의미합니다.
* 공백이 포함된 경로는 따옴표로 묶어야 합니다.
* `--git-mode`에서는 `none`, `gitignore`, `tracked`, `staged`, `changes`, `diff:<ref>..<ref>` 중 하나를 선택합니다.
* `--exclude`는 Git 필터링과 별도로 일반 제외를 제어합니다.
* 분석 및 내보내기 명령은 항상 같은 결과를 내며 데스크톱 인터페이스를 열지 않습니다.
* `tui`, `open`, `analyze`, `search`, `tree` 및 두 `export` 명령은 Git 저장소 URL도 받으며, `related`는 `--project`로 URL을 받습니다. 복제본은 관리되는 캐시(`devprojex cache`)에 저장됩니다.
* 명령에는 `export ctx`, `-f`, `-n` 같은 별칭과 짧은 플래그가 있습니다. `devprojex help`에서 확인할 수 있습니다.
* `analyze --findings`는 값을 노출하지 않고 마스킹 결과를 나열하며, `--fail-on-findings`는 CI용으로 0이 아닌 종료 코드를 반환합니다.
* `export context --max-tokens N`은 컨텍스트를 토큰 예산 안에 맞추고, 실험적인 `--rank importance`는 중요한 파일부터 포함합니다.
* 분석, 검색, 내보내기 명령은 프로젝트 파일을 수정하지 않습니다. DevProjex는 읽기 전용 모드로 작동합니다.

`devprojex` 명령이 작동하지 않으면 DevProjex에서 “도움말 → 터미널에서 실행”을 여세요.

## 5) Git
“Git → 저장소 복제...”는 저장소를 DevProjex 캐시에 복제하고 엽니다. “브랜치”와 “업데이트 받기”는 이렇게 복제한 프로젝트에서만 사용할 수 있습니다. 앱은 원본 파일을 건드리지 않고 캐시만 사용합니다.

캐시는 사용자의 시스템 캐시 디렉터리에 저장됩니다. 실제 경로는 `devprojex doctor`로 확인할 수 있습니다.

* 브랜치 — 사용 가능한 브랜치 목록을 현재 브랜치를 표시하여 보여 줍니다. 전환하면 트리가 선택한 브랜치의 내용으로 업데이트됩니다. 브랜치가 이미 로컬에 있으면 오프라인으로 전환합니다(업데이트하지 않음). 로컬에 없으면 가져온 후 만듭니다.
* 업데이트 받기 — 현재 브랜치만 업데이트합니다. 가져온 후 origin/<branch>로 재설정합니다. Git으로 복제한 프로젝트에서는 F5도 같은 작업을 수행하며, 일반 “파일 → 새로 고침” 명령은 비활성화됩니다.

### 복제 창
Git 복제 창에서는 URL 필드 아래에 “최근 링크” 목록이 나타날 수 있습니다.

규칙:
* 목록은 최근에 복제한 저장소가 기록에 있을 때만 나타납니다.
* 네트워크 저장소 소스(`https://`, `ssh://`, SCP 구문)만 목록에 추가됩니다.
* 로컬 경로와 `file://` 소스는 이 목록에 추가되지 않습니다.
* 중복 항목은 만들어지지 않습니다. 같은 저장소를 다시 복제하면 해당 저장소가 맨 위로 이동합니다.
* 최근 저장소는 최대 16개까지 저장됩니다.
* 기록은 앱을 다시 실행해도 유지됩니다.

항목을 선택하면 URL 필드가 자동으로 채워집니다.
복제가 진행되는 동안에는 목록이 잠시 숨겨집니다.

## 6) 복사
### 트리 형식 전환(ASCII / JSON / XML / MD)
이 전환은 출력에 트리가 포함되는 작업에서 트리 표현 형식을 정합니다.

* ASCII — 가지 선이 있는 텍스트 트리.
* JSON — JSON 구조 트리.
* XML — 파서와 도구를 위한 간결한 XML 트리.
* MD — 문서와 AI 프롬프트를 위한 Markdown 중첩 목록.

전환이 영향을 주는 작업:
* 트리 복사
* 트리 및 콘텐츠 복사
* 트리 내보내기
* 트리 및 콘텐츠 내보내기

전환이 영향을 주지 않는 작업:
* 콘텐츠 복사
* 콘텐츠 내보내기

### 트리 복사
프로젝트 트리를 복사합니다.
선택한 노드가 있으면 선택 항목으로 트리를 만들고, 선택이 비어 있거나 유효하지 않으면 전체 트리를 복사합니다.
결과 형식은 트리 형식 전환으로 정해집니다.
단축키: {mod}{shift}C 및 {mod}{alt}C.

### 콘텐츠 복사
파일 내용을 복사합니다.
* 선택한 파일이 있으면 그 파일만, 없으면 모든 프로젝트 파일이 대상입니다.
* 각 파일 앞에는 전체 로컬 경로(Git으로 복제한 프로젝트는 저장소 웹 경로)가 포함된 머리글이 붙습니다.
* 텍스트가 아닌 파일(바이너리 포함)은 무시됩니다.
* 빈 텍스트 파일은 경로와 `[No Content, 0 bytes]` 줄이 출력됩니다.
* 공백이나 줄 바꿈만 있는 파일은 경로와 `[Whitespace, N bytes]` 줄이 출력됩니다.
단축키: {mod}{alt}V.

### 트리 및 콘텐츠 복사
트리와 콘텐츠를 함께 출력합니다.
* 트리는 선택 항목으로 만들어지며, 선택이 비어 있거나 유효하지 않으면 전체 트리가 사용됩니다.
* 콘텐츠는 “콘텐츠 복사”와 같은 규칙을 따릅니다.
* 트리 블록 형식은 트리 형식 전환으로 정해집니다.
단축키: {mod}{shift}V.

### 트리 표현
트리 형식마다 같은 선택 트리를 다른 방식으로 표현합니다.

JSON:
* `rootPath` — `/`로 정규화된 절대 루트 경로.
* `tree` — 루트 폴더의 내용.
* JSON 내보내기는 이 트리 형식을 사용합니다. 배열은 파일, 객체는 하위 폴더, `/`는 현재 폴더의 파일을 담고, `[]`는 빈 폴더를 나타냅니다.

XML:
* 루트 노드는 `<t r="...">`입니다.
* 폴더는 `<d n="...">`입니다.
* 파일은 `<f>File.cs</f>`입니다.

MD:
* `Root: ...`로 시작합니다.
* Markdown 중첩 목록을 사용합니다.
* 폴더 이름은 `/`로 끝납니다.

트리 + 콘텐츠:
* 선택한 트리 형식이 트리 블록에 적용됩니다.
* 콘텐츠 블록은 텍스트로 유지됩니다.
* 콘텐츠 블록의 파일 머리글은 `/`를 사용하는 상대 경로를 씁니다.
* `.txt`로 내보냅니다.

## 7) 미리보기 모드
상단 표시줄의 눈 아이콘 버튼이나 {mod}B로 엽니다.

마우스 측면 버튼은 브라우저처럼 작동합니다. 앞으로 버튼은 미리보기 모드를 열고, 뒤로 버튼은 닫습니다. 같은 방향을 반복해도 아무 일도 일어나지 않습니다.

{mod}{shift}F는 미리보기에서 파일 내용 검색을 열거나 닫습니다. Enter 또는 F3은 다음 일치 항목으로, {shift}Enter 또는 {shift}F3은 이전 일치 항목으로 이동합니다.

최종 결과를 트리 옆의 별도 작업 영역에 표시합니다. 이 모드는 보기 전용이며, 그 자체로 클립보드에 복사하거나 파일로 내보내지 않습니다.

기본적으로 작업 영역은 다음과 같이 열립니다.
* 왼쪽 — 프로젝트 트리.
* 가운데 — 미리보기 창.
* 오른쪽 — 설정 패널(열려 있던 경우).

사용 가능한 모드:
* 트리
* 콘텐츠
* 트리 + 콘텐츠

복사 및 내보내기와 같은 규칙이 적용됩니다.
* 선택한 노드가 반영됩니다.
* 선택이 비어 있으면 전체 데이터가 사용됩니다.
* 현재 제외 규칙과 선택 옵션이 적용됩니다.

추가로:
* 미리보기의 파일은 가로선으로 구분됩니다.
* 스크롤하는 동안 현재 파일의 경로가 상단에 고정됩니다. 고정된 경로를 클릭하면 해당 파일의 시작 부분으로 돌아갑니다.
* 미리보기 스크롤 막대에는 검색 일치 항목과 마스킹 결과가 있는 줄이 표시됩니다. 표시를 클릭하면 해당 줄로 이동합니다. 원래 값으로 유지한 결과도 계속 표시되며, 마스킹된 경로 머리글은 첫 줄에 표시를 하나 추가합니다.
* 트리와 미리보기의 확대/축소는 따로 설정할 수 있습니다.
* 미리보기 모드에서는 “복사” 메뉴를 열지 않고도 현재 결과 전체나 현재 보이는 파일 블록을 복사할 수 있습니다.

버튼:
* 상단 미리보기 영역 왼쪽의 복사 버튼 — 현재 미리보기 모드의 내용을 복사합니다.
  * 트리
  * 콘텐츠
  * 트리 + 콘텐츠
* 트리 창의 X — 트리를 숨기고 미리보기 창만 남깁니다.
* 상단 미리보기 창의 X — 미리보기 모드를 완전히 닫습니다.
* 고정된 파일 머리글의 작은 복사 버튼 — 현재 보이는 파일 블록을 미리보기에 표시된 그대로 복사합니다.
* 눈 아이콘을 다시 누르거나 {mod}B를 눌러도 미리보기 모드가 닫힙니다.

미리보기에서 트리 창이 보이는 동안에는 검색과 필터를 사용할 수 있습니다.
트리를 숨기면 미리보기 전용 모드를 끝낼 때까지 검색과 필터를 잠시 사용할 수 없습니다.

## 8) 보기
### 확대/축소
* {mod}+ / {mod}= — 확대
* {mod}- — 축소
* {mod}0 — 초기화
* {mod}+마우스 휠 — 커서 아래의 창을 부드럽게 확대/축소

동작:
* 일반 모드에서는 트리가 확대/축소됩니다.
* 트리가 보이는 미리보기에서는 메뉴의 확대, 축소, 확대/축소 초기화이 트리와 미리보기 모두에 적용됩니다.
* {mod}+마우스 휠을 사용하면 커서 위치에 따라 트리와 미리보기가 따로 확대/축소됩니다.
* 미리보기 전용 모드에서는 미리보기 창만 확대/축소됩니다.

범위: 6–28, 초기화 값은 15입니다.

### 컴팩트 모드
UI를 더 촘촘하게 만들어 트리와 설정의 간격을 줄입니다.
미리보기 작업 영역이 활성화된 동안에는 컴팩트 모드가 자동으로 켜집니다.

### 애니메이션

선택한 글꼴은 설정 패널에서 “설정 적용”을 클릭하면 적용됩니다.

### 에이전트 활동

## 9) 검색(트리)
검색 표시줄을 열고, 일치 항목을 강조 표시하며, 일치 항목 사이를 이동할 수 있게 합니다.
* {mod}F — 표시/숨기기
* Enter — 다음 결과
* {shift}Enter — 이전 결과
* Esc — 닫기

검색은 필요한 분기만 자동으로 펼칩니다. 검색어를 지우면 트리가 접힙니다(루트 제외).
일치하는 줄은 트리 스크롤 막대에도 표시됩니다. 표시를 클릭하면 해당 일치 항목으로 이동합니다.
일치 항목이 매우 많으면 UI의 응답성을 유지하기 위해 자동 펼치기와 전체 강조 표시가 제한될 수 있습니다.
검색 표시줄을 닫으면 닫기 애니메이션이 끝난 후 검색어가 지워집니다.

제약:
* 검색을 열면 필터가 자동으로 닫힙니다.
* 미리보기에서도 트리 창이 보이는 동안에는 검색을 사용할 수 있습니다.
* 트리가 숨겨져 있으면 검색을 잠시 사용할 수 없습니다.

## 10) 필터(이름)
필터 문자열과 일치하는 노드와 그 상위 노드만 표시합니다. 업데이트는 입력이 멈춘 후에 적용됩니다(디바운스).
* {mod}{shift}N — 필터 표시/숨기기
* Esc — 필터 닫기

제약:
* 필터를 열면 검색이 자동으로 닫힙니다.
* 미리보기에서도 트리 창이 보이는 동안에는 필터를 사용할 수 있습니다.
* 트리가 숨겨져 있으면 필터를 잠시 사용할 수 없습니다.

## 11) 옵션(설정 패널)
오른쪽에 다음 항목이 있습니다.
* 설정 적용
* 콘텐츠 처리
* 제외 항목
* 파일 형식

“제외 항목”과 “파일 형식”의 변경 내용은 패널에 보류되었다가 “설정 적용”을 클릭하면 적용됩니다.

확인란을 바꾸면 앱이 백그라운드에서 사용 가능한 옵션과 개수를 업데이트할 수 있습니다. 결과 트리는 “설정 적용”을 클릭한 후에만 다시 만들어집니다.

상태 표시줄의 X 버튼으로 사용 가능한 옵션 업데이트를 취소하면, 완료되지 않은 변경 내용은 적용되지 않고 패널은 마지막으로 완료된 상태로 돌아갑니다.

각 목록에는 “모두” 전환이 있습니다.

“파일 형식”에 대한 참고:
* 이 목록에는 확장자가 있는 파일만 표시됩니다.
* 확장자가 없는 파일은 이 목록에 추가되지 않으며 “제외 항목”의 별도 옵션으로 제어됩니다.

콘텐츠 처리:
* 트리를 바꾸지 않고 선택한 텍스트 파일의 내용을 변환합니다.
* “비밀 정보 숨김”과 “개인 데이터 숨김”은 감지된 값을 대체합니다(섹션 12.3 및 12.4).
* “코드 압축”은 14개 언어에서 선언은 유지하고 이름이 있는 구현을 짧게 줄입니다.
* “주석 제거”는 20개 언어 팩에서 주석과 문서 주석을 제거합니다.
* “빈 줄 제거”는 같은 언어 팩에서 여러 줄 리터럴은 유지하고 공백만 있는 줄을 제거합니다.
* 변경 내용은 “설정 적용” 후에 적용됩니다.

{mod}P — 패널 표시/숨기기.

### 11.1 로컬 프로젝트 매개변수 프로필
로컬 폴더의 경우 DevProjex는 마지막으로 적용한 프로젝트 매개변수를 기억합니다.
* 선택한 파일 형식.
* “제외 항목” 섹션에서 선택한 옵션.

저장은 “설정 적용”을 클릭할 때 이루어집니다.
같은 로컬 폴더를 다시 열면 매개변수가 자동으로 복원됩니다.

중요:
* 프로필은 로컬 프로젝트에 대해서만 저장됩니다.
* Git으로 복제하여 연 프로젝트에는 프로필이 저장되지 않습니다.
* 저장된 옵션 중 일부를 현재 프로젝트에서 더 이상 사용할 수 없으면 해당 옵션은 건너뛰고 나머지 매개변수가 적용됩니다.
* 새로 고침하거나 다시 열 때 새 파일 형식이나 “제외 항목” 옵션이 나타나면 기본적으로 켜집니다.
* 이미 나타난 적이 있는 옵션은 사용자가 명시적으로 선택한 상태를 유지합니다. 꺼 둔 형식의 새 파일이 생겨도 그 형식이 다시 켜지지 않습니다.

## 12) 제외 항목
“제외 항목” 섹션은 트리, 콘텐츠, 복사, 내보내기 결과에서 제외할 파일과 폴더를 제어합니다.

항목은 다음 조건을 모두 충족할 때만 표시됩니다.
* 파일에 형식이 있으면 그 파일 형식이 선택되어 있습니다.
* 켜져 있는 제외 규칙 중 어느 것도 항목을 제외하지 않습니다.

제외 규칙은 누적됩니다. 켜져 있는 규칙 중 하나라도 항목을 숨기면 다른 규칙이 그 항목을 다시 표시할 수 없습니다.

### 12.1 사용 가능한 규칙
프로젝트 내용에 따라 다음 옵션이 표시될 수 있습니다.

* 스마트 무시
* 빈 폴더
* 빈 파일
* 숨김 폴더
* 숨김 파일
* 도트 폴더
* 도트 파일
* 확장자 없는 파일

Git 필터링을 적용할 수 없는 경우, 즉 저장소 경계가 없고 `.gitignore` 필터가 현재 트리를 바꿀 수 없는 경우에는 GUI 선택기와 TUI의 Git 축 라디오 항목이 모두 숨겨집니다. 저장소 밖에서 축이 표시되면 GUI에서는 필터링 없음과 `.gitignore`만 선택할 수 있고, TUI에서는 저장소가 필요한 항목이 비활성화됩니다. Git 저장소 안에서는 필터링 없음, `.gitignore`, 추적된 파일, 스테이징된 파일, 현재의 모든 변경 사항이라는 다섯 가지 일반 값을 사용할 수 있습니다. TUI에서는 활성 `diff:<ref>..<ref>` 범위가 여섯 번째 줄로 나타납니다. 값을 선택하면 스마트 무시나 기본 제외는 그대로 두고 현재 Git 모드만 바뀝니다. 다른 옵션은 해당 규칙이 현재 트리를 바꿀 수 있을 때 표시되므로, 다른 규칙이나 파일 형식을 바꾸면 목록이 달라질 수 있습니다.

새 옵션은 처음 나타날 때 기본적으로 켜집니다. 이미 알고 있는 옵션은 목록에서 잠시 사라지더라도 사용자의 선택을 유지합니다.

### 12.2 스마트 무시
스마트 무시는 종속성, 빌드 출력, 캐시 등 프로젝트의 작업용 산출물을 숨깁니다.

DevProjex는 먼저 구조와 마커 파일로 프로젝트 유형을 식별합니다. 예:

* `.csproj`
* `package.json`
* `pyproject.toml`
* `Cargo.toml`

그런 다음 해당 스택의 규칙을 감지된 프로젝트 범위 안에서 적용합니다. 예를 들어 .NET 규칙은 옆에 있는 Python 또는 JavaScript 프로젝트로 확장되지 않습니다.

폴더 이름만으로 항상 충분한 것은 아닙니다. `build`, `vendor`, `packages`, `cache`, `pkg`, `Library`처럼 모호한 이름은 내용까지 확인합니다. 그래서 비슷한 이름이라는 이유만으로 일반 사용자 폴더가 숨겨지지 않습니다.

일부 종속성 저장소와 서비스 디렉터리는 명시적으로 감지된 프로젝트 밖에서도 특징적인 내부 구조로 인식할 수 있습니다.

프로젝트 범위 검색에는 한도가 있어, 큰 사용자 폴더를 로드해도 모든 디렉터리를 반복해서 전부 분석하지 않습니다. 일반 구조는 얕게 검색하고, 인식된 모노레포는 더 깊이 검색합니다. 범위를 찾으면 스마트 무시는 그 하위 트리 전체에 깊이 제한 없이 적용됩니다.

### 12.3 비밀 정보 숨김
“비밀 정보 숨김”은 기본적으로 꺼져 있습니다. 선택한 텍스트 콘텐츠만 검사하고 감지된 각 값을 제자리에서 대체하며, 파일과 주변 코드는 그대로 둡니다. 옵션이 꺼져 있으면 검사가 실행되지 않고 개수도 표시되지 않습니다. 현재 선택을 검사한 후에는 레이블에 감지된 값의 개수가 표시됩니다. 원래 값 유지 결정으로 숨겨진 값이 더 적으면 “감지/숨김”이 표시되고, 해당 행의 ? 표시기가 두 개수를 모두 알려 줍니다.

마스킹된 부분은 미리보기에서 강조 표시됩니다. 클릭하면 그 위치만 원래 값으로 유지할 수 있습니다. {alt}↓ / {alt}↑로 감지 결과 사이를 이동하고 Enter로 현재 결과를 전환합니다. 터미널 작업공간에서는 `[`와 `]`로 위치 사이를 이동하고 `Enter` 또는 `Space`로 현재 위치를 전환합니다. 이 결정은 현재 세션의 미리보기, 클립보드, 컨텍스트 내보내기, 폴더 복사, ZIP에 적용되며 프로젝트 프로필에는 저장되지 않습니다.

미리보기의 상황에 맞는 메뉴로 이 결정을 한 번에 적용할 수 있습니다. 감지된 위치를 마우스 오른쪽 버튼으로 클릭하면 같은 규칙의 모든 위치나 같은 파일에서 감지된 모든 위치를 한 번에 원래 값으로 유지하거나 다시 숨길 수 있습니다. 파일 내용에서 선택한 값을 마우스 오른쪽 버튼으로 클릭하면 직접 표시할 수 있습니다. “여기에서 ‘…’ 숨기기”는 세션 동안 그 위치만 숨기고, “항상 ‘…’ 숨기기”는 그 값의 모든 위치에 대한 영구 표시를 만들며, “‘…’을(를) 개인 데이터로 숨기기”는 “개인 데이터 숨김”으로 제어되는 영구 표시를 만듭니다. 직접 만든 표시에는 “표시 제거”가 나타나며 표시를 삭제합니다. 감지기가 여전히 일치시키는 값은 숨겨진 상태로 유지됩니다. 직접 표시할 값은 파일 내용 안에서 선택한 8~512자의 한 줄이어야 합니다. 표시를 만들면 해당 옵션이 자동으로 켜집니다. 영구 표시에는 키가 적용된 값 식별자와 분류만 저장되며 원본 텍스트는 저장되지 않습니다.

폴더나 ZIP 복사본에서도 일치하는 텍스트가 바뀌므로 빌드하거나 실행하지 못할 수 있습니다. 바이너리 파일은 바뀌지 않고 복사되며 검사되지 않습니다. 16 MiB를 넘는 선택한 텍스트 파일은 생략되고 보고되며, 나머지 출력은 완료됩니다. 감지에 실패하면 전체 작업이 중지됩니다.

개수는 규칙 일치만 나타냅니다. 0이라고 해서 프로젝트가 안전하다는 뜻은 아닙니다. CLI에서는 `--hide-secrets`를 사용합니다. 기술 세부 정보와 제한은 `Docs/HideSecrets.md`에 있습니다.

### 12.4 개인 데이터 숨김
“개인 데이터 숨김”은 기본적으로 꺼져 있습니다. 선택한 텍스트 파일에서 이메일 주소, 글로벌 IP 주소, 경로의 로컬 사용자 이름, MAC 주소, 국제 전화번호를 감지합니다. 감지 결과에는 “비밀 정보 숨김”과 같은 미리보기 결정과 출력 파이프라인이 적용됩니다. “‘…’을(를) 개인 데이터로 숨기기”로 만든 직접 표시도 이 분류에 속하며 이 스위치를 따릅니다(섹션 12.3). 생성된 경로 머리글과 트리 루트의 로컬 사용자 이름은 하나의 공통 결과로 마스킹됩니다. 카운터에는 값 하나로 포함되고, ? 표시기는 숨김 또는 표시 상태를 알려 주며, 한 번 클릭하면 마스킹된 모든 경로가 전환됩니다.

문서용 주소 범위와 호스트, 일반적인 CI 사용자 이름, 잘 알려진 공용 DNS 확인자, 문서용으로 정해진 가상의 전화번호 범위는 계속 표시됩니다. 일치 항목이 0개라고 해서 개인 정보 보호가 보장되는 것은 아닙니다. CLI에서는 `--hide-private-data`를 사용합니다. 전체 규칙과 1단계 제한은 `Docs/HidePrivateData.md`에 있습니다.

### 12.5 .gitignore 사용
이 옵션을 켜면 DevProjex는 `git status`가 보여 주는 작업 트리 상태를 따릅니다. 추적된 파일은 계속 표시되고, 추적되지 않는 파일은 저장소의 제외 규칙이 제외하지 않는 한 표시됩니다. 열린 폴더 루트의 파일뿐 아니라 접근 가능한 모든 `.gitignore`를 적용하며, 열린 폴더 위쪽부터 저장소 루트까지의 파일도 포함합니다.

각 `.gitignore`는 다음 범위에 적용됩니다.

* 그 파일이 들어 있는 폴더.
* 그 아래의 접근 가능한 모든 폴더.
* 해당 범위 안에서만.

중첩된 `.gitignore`의 규칙은 상위 폴더나 형제 폴더에 영향을 주지 않습니다.

특정 경로에 대해 규칙은 상위 `.gitignore`에서 더 깊은 파일 순서로 처리됩니다. 한 파일 안에서는 위에서 아래로 처리됩니다. 마지막으로 일치한 규칙이 Git 결과를 결정합니다.

`!`로 시작하는 규칙은 해당 범위 안에서만 앞선 Git 제외를 취소합니다. 상위 폴더가 제외된 상태에서는 파일을 복원할 수 없습니다. 완전히 제외되어 접근할 수 없는 폴더 안의 `.gitignore`는 평가에 사용되지 않습니다.

형식이 잘못되었거나 지원되지 않는 줄은 개별적으로 건너뜁니다. 같은 파일의 다른 유효한 규칙과 인접 범위의 규칙은 계속 작동합니다.

저장소 로컬 `.git/info/exclude` 파일도 루트 `.gitignore`보다 낮은 우선순위로 적용됩니다. 자체 `.git`이 있는 중첩 폴더도 `git status`와 같은 방식으로 처리됩니다. `.gitmodules`에 선언되지 않은 내장 저장소는 불투명하게 취급되어 그 파일이 표시되지 않고, 선언된 하위 모듈에는 자체 `.gitignore`와 `info/exclude`가 적용됩니다. 내장 저장소의 파일을 보려면 `none`을 선택하세요. 전역 Git 제외 규칙(`core.excludesFile`)은 적용되지 않습니다. `core.ignoreCase`와 macOS의 `core.precomposeUnicode` 같은 저장소의 유효한 경로 비교 설정은 존중됩니다. `.gitignore`라는 이름의 심볼릭 링크는 Git의 제어 파일 동작과 마찬가지로 따라가지 않습니다. `.gitignore` 또는 `info/exclude` 파일을 읽을 수 없으면 해당 디렉터리 범위는 실패 시 차단 방식으로 제외되며, 규칙을 완전히 평가하지 못한 파일을 조용히 포함하는 대신 검사에서 부분 접근을 보고합니다. 경로를 소유한 저장소 범위에 읽을 수 있는 인덱스가 있으면 추적된 파일은 `.gitignore`와 일치해도 계속 표시됩니다. 그 인덱스나 Git CLI가 없으면 해당 범위는 안전하게 패턴만으로 평가합니다.

기본 제공 `standard` 프로필은 `gitignore`와 함께 `smart-ignore`, `hidden-folders`, `hidden-files`, `dot-folders`, `dot-files`, `empty-folders`, `empty-files`, `extensionless-files`를 선택합니다.

### 12.6 추적된 Git 파일만
“추적된 Git 파일만”은 읽을 수 있는 각 Git 인덱스에 기록되어 있고 작업 트리에 존재하는 파일로 트리의 Git 단계를 만듭니다. 수정된 추적 파일과 스테이징된 새 파일은 포함되고, 추적되지 않는 파일은 제외됩니다. 이것은 현재 작업 트리이며 `HEAD`나 원격 저장소의 과거 스냅숏이 아닙니다.

각 저장소는 독립적으로 처리됩니다. 열린 폴더 안의 형제 저장소와 선언된 하위 모듈은 각각 자체 인덱스를 사용하며, 하위 저장소는 상위나 형제 저장소의 추적 경로를 물려받지 않습니다. `.gitmodules`에 선언되지 않은 내장 저장소는 `.gitignore` 모드에서와 마찬가지로 불투명하게 유지됩니다. 이 모드에는 Git CLI가 필요하며, 읽을 수 있는 빈 인덱스도 유효합니다. 터미널 작업공간(TUI)이 이 모드로 시작되었는데 해당 인덱스를 불러올 수 없으면 작업공간이 열리지 않습니다. 열려 있는 TUI 작업공간에서 이 모드를 대화형으로 선택했는데 해당 인덱스를 불러올 수 없으면 변경이 거부되고 마지막으로 사용할 수 있었던 Git 모드가 유지됩니다. 같은 상황에서 직접 명령은 정책 또는 검사 실패를 반환합니다. DevProjex는 절대 조용히 `.gitignore`로 대체하지 않습니다. 다른 해당 인덱스를 읽을 수 있으면 사용할 수 없는 중첩 범위는 경고와 함께 제외됩니다.

이미 열려 있는 데스크톱 작업 영역에서는 명시적으로 선택한 추적 모드가 계속 표시되며 실패 시 차단 방식으로 작동합니다. 준비에 실패하면 출력과 내보내기가 차단되고, 일부만 준비되면 현지화된 경고와 함께 계속됩니다.

Git 모드는 서로 배타적이며 `none`은 Git 필터링을 끕니다. 일시적인 `staged`, `changes`, `diff:<ref>..<ref>` 모드는 프로필에 저장되지 않습니다. 일시적 모드가 켜져 있는 동안 GUI의 로컬 프로젝트 프로필에는 마지막으로 켠 영구 모드인 `gitignore` 또는 `tracked`가 유지됩니다. `none`은 저장 시점에 `none` 자체가 켜져 있을 때만 저장됩니다. TUI와 CLI는 일시적 모드가 켜져 있는 동안 포터블 프로필 저장을 거부합니다.

### 12.7 Git 필터링과 스마트 무시의 관계
선택한 Git 모드와 스마트 무시는 서로 독립된 설정입니다. Git 모드가 접근 가능한 모든 Git 범위에 먼저 적용되고, 그다음 스마트 무시가 남은 항목을 처리하며, 마지막으로 기본 규칙이 적용됩니다.

선택한 Git 모드가 스마트 무시의 후보를 이미 모두 제외하고 있는 동안에는 스마트 무시가 숨겨져 있다가, Git 모드를 바꾸거나 해제하면 나타날 수 있습니다. Git 저장소 안에서는 저장소를 사용하는 모든 Git 모드를 사용할 수 있습니다.

`!`로 시작하는 Git 부정 규칙은 Git 결과만 취소합니다. 스마트 무시나 기본 규칙은 해제되지 않습니다.

### 12.8 기본 규칙
“도트 폴더”와 “도트 파일”은 항목 이름을 검사합니다.

“숨김 폴더”와 “숨김 파일”은 시스템 숨김 속성을 검사합니다. 플랫폼에 따라 점으로 시작하는 이름과 시스템 속성이 같은 항목을 가리킬 수도, 다른 항목을 가리킬 수도 있습니다.

“빈 파일”은 크기가 0바이트인 파일을 숨깁니다.

“확장자 없는 파일”은 `Dockerfile`, `Makefile`, `README` 같은 파일을 숨깁니다.

“빈 폴더”는 논리적으로 비어 있는 폴더를 숨깁니다. 선택한 파일 형식과 다른 모든 규칙을 적용한 후 보이는 파일이나 하위 폴더가 남아 있지 않으면 그 폴더는 논리적으로 비어 있는 것입니다.

따라서 다른 규칙을 바꾸면 빈 폴더 개수가 달라질 수 있습니다. 파일을 숨기면 그 파일이 들어 있던 폴더가 논리적으로 비게 될 수 있기 때문입니다.

### 12.9 카운터
규칙 옆의 개수는 디스크에 있는 비슷한 항목의 실제 개수가 아니라, 현재 설정에서 그 규칙이 직접 제외하는 항목 수를 보여 줍니다.

한 항목이 겹치는 여러 카운터에 동시에 집계되지는 않습니다. 예를 들어 `.git` 폴더는 점으로 시작하는 이름과 시스템 숨김 속성을 모두 가질 수 있지만, 그 제외는 하나의 규칙에만 집계됩니다.

제외를 어느 규칙에 집계할지는 고정된 순서로 정해집니다.

* 폴더: `.gitignore`, 스마트 무시, 점으로 시작하는 이름, 시스템 숨김 속성.
* 파일: `.gitignore`, 스마트 무시, 점으로 시작하는 이름, 확장자 없음, 빈 파일, 시스템 숨김 속성.

이 순서는 카운터에만 영향을 줍니다. 최종 표시 여부는 더 단순한 규칙을 따릅니다. 켜져 있는 메커니즘 중 하나라도 항목을 제외하면 그 항목은 숨겨집니다.

### 12.10 변경 사항 적용
확인란을 바꾸면 먼저 패널의 사용 가능한 설정과 카운터가 업데이트됩니다. 최종 트리는 “설정 적용”을 선택한 후에 다시 만들어집니다.

설정 준비를 취소하면 DevProjex는 패널을 마지막으로 완전히 완료된 상태로 되돌립니다. 일부만 계산된 규칙은 적용되지 않습니다.

## 13) 트리와 지표 계산 방법
결과는 다음에 따라 달라집니다.
* 선택한 파일 형식
* 제외 규칙
* 활성 필터
* 선택한 트리 노드(선택 기반 작업의 경우)

접근이 거부되면 노드는 평소의 이름과 아이콘을 유지하고 “[접근 불가]” 접미사가 붙습니다.

### 13.1 상태 표시줄 카운터의 의미
상태 표시줄에는 두 개의 블록이 있습니다.
* 트리 — 트리 텍스트 출력의 지표.
* 콘텐츠 — 내보낼 파일 콘텐츠 출력의 지표.

형식:
* 줄
* 문자
* ≈토큰(근삿값)

큰 값은 짧은 접미사(K/M)로 표시됩니다.

중요:
* “트리” 블록의 “줄”은 디스크의 파일 수가 아니라 최종 트리 표현의 줄 수입니다.
* 이 값에는 폴더, 파일, 트리 보조 요소(예: 접근이 거부된 노드)가 포함됩니다.

### 13.2 지표 계산 방법
트리 지표:
* 같은 내보내기 파이프라인이 생성한 실제 트리 출력으로 계산됩니다.
* 현재 트리 형식을 반영합니다.

콘텐츠 지표:
* 콘텐츠 복사 및 내보내기와 같은 규칙을 따릅니다.
* 바이너리 파일은 제외됩니다.
* 빈 파일과 공백만 있는 파일은 보조 표시(`[No Content, 0 bytes]`, `[Whitespace, N bytes]`)로 집계됩니다.

### 13.3 카운터 업데이트 시점
다음 시점에 다시 계산합니다.
* 프로젝트를 열거나 새로 고친 후.
* 설정(제외 항목과 파일 형식)을 적용한 후.
* 트리 확인란이 바뀔 때(디바운스 적용).
* 트리 형식을 바꿀 때(트리 출력을 사용하는 작업의 경우).
* 백그라운드 계산이 취소되면 다음 재계산이 완료될 때까지 카운터가 0으로 설정됩니다.

## 14) 아이콘
아이콘 선택 순서:
1) 노드 유형(폴더/파일)
2) 정확한 이름(규칙이 있는 경우)
3) 확장자
4) 그 외 — 알 수 없음

## 15) 테마 및 효과
“테마” 섹션에서 시스템, 밝게, 어둡게 중 하나와 배경 효과 하나를 선택할 수 있습니다.
* 투명도
* 흐림
* Mica

기본적으로 시스템이 선택되어 있으며 운영 체제의 테마 변경을 따릅니다. 처음 실행하거나 설정을 초기화한 후에는 시스템 테마가 밝으면 일반 불투명 배경으로, 어두우면 흐림으로 시작합니다. 시스템 설정을 확인할 수 없으면 DevProjex는 어둡게와 흐림을 사용합니다. 밝게와 어둡게는 각자의 효과를 따로 기억합니다. 밝게 또는 어둡게를 명시적으로 선택하면 다시 시스템을 선택할 때까지 시스템 변경은 무시됩니다.

효과는 서로 배타적입니다. 선택된 효과를 다시 클릭하면 해당 효과가 꺼지고 일반 불투명 배경으로 돌아갑니다.

사용 가능한 설정:
* 배경 투명도 — 투명도와 흐림에서 사용할 수 있습니다.
* 상단바 대비 — 미리보기, 검색, 필터, 트리 형식 명령이 있는 기본 패널을 조정합니다.
* 메뉴 투명도 — 기본 메뉴와 하위 메뉴에 똑같이 적용됩니다.
* 테두리 표시 — 인터페이스 테두리가 얼마나 진하게 보일지 조정합니다.

Mica는 플랫폼의 시스템 재질을 사용하며 별도의 배경 투명도 설정이 없습니다. 선택한 흐림 또는 Mica 효과를 사용할 수 없으면 앱은 먼저 다른 기본 효과를 시도합니다. 흐림과 Mica를 모두 사용할 수 없을 때만 일반 불투명 배경이 사용됩니다.

투명도 모드에서는 기본 창 배경이 투명하게 유지됩니다. 메뉴, 하위 메뉴, 기타 팝업 표면은 지원되는 경우 흐림을 사용하므로 그 뒤에 있는 트리와 콘텐츠 요소가 가독성을 해치지 않습니다.

## 16) 도움말

### 16.1 업데이트
“도움말 → 업데이트”는 현재 버전을 GitHub의 최신 안정 릴리스와 비교합니다. 자동 확인은 기본적으로 꺼져 있습니다. 켜면 이전에 확인에 성공한 후 최소 7일이 지났을 때 시작 시 확인합니다. 확인란은 즉시 적용됩니다. 마지막으로 성공한 결과는 앱을 다시 실행해도 유지되며, 이후 네트워크 오류가 발생해도 지워지지 않습니다. 설치는 사용자가 직접 합니다.

### 16.2 설정 초기화
설정 초기화(도움말 → 설정 초기화)은 테마, 효과, 컴팩트 모드, 애니메이션 설정, 인터페이스 언어를 기본값으로 되돌립니다. 프로젝트 프로필, 기록, 디스크의 파일은 바뀌지 않습니다.

### 16.3 데이터 초기화
데이터 초기화(도움말 → 데이터 초기화)은 저장된 로컬 프로젝트 매개변수 프로필을 삭제합니다.
* 선택한 파일 형식.
* “제외 항목” 섹션에서 선택한 옵션.
* 선택한 콘텐츠 처리 설정.
* 직접 만든 비밀 정보 표시.

완료된 에이전트 저널 세션도 지워집니다(섹션 19.3). 활성 세션은 유지됩니다.

중요:
* 로컬 폴더의 최근 기록은 지워지지 않습니다.
* Git 복제 창의 최근 저장소 기록은 지워지지 않습니다.
* 디스크의 파일과 폴더는 수정되거나 삭제되지 않습니다.

## 17) 언어
언어는 “언어” 메뉴에서 선택합니다.
선택한 언어는 다음에 실행할 때도 유지됩니다. “도움말 → 설정 초기화”을 실행하면 저장된 언어 선택이 지워지고 인터페이스 언어가 기본값으로 돌아갑니다.

## 18) 진행률 표시줄 및 취소
상태 표시줄 가운데에는 진행 중인 작업과 진행률이 표시됩니다.

진행률 모드:
* 불확정 — 백분율 없음(작업 소요 시간을 알 수 없음).
* 확정 — 백분율 표시(0–100).

동작:
* 백그라운드 데이터 계산 중에는 진행률이 백분율로 표시됩니다.
* 일부 Git 작업에서는 진행률 정보가 제공될 때 백분율이 표시됩니다.
* 사용 가능한 옵션 업데이트와 설정 적용은 시간이 걸릴 때 표시됩니다.
* 빨리 끝나는 작업은 진행률을 표시하지 않고 완료됩니다.

상태 표시줄의 X 버튼(취소):
* 취소를 지원하는 작업을 가능한 범위에서 취소합니다.
* 백그라운드 데이터 계산을 중지합니다.
* 사용 가능한 옵션 업데이트를 취소하면 패널을 마지막으로 완료된 상태로 되돌립니다.
* 취소를 지원하지 않는 작업은 상태 표시줄 표시만 멈추고, 작업 자체는 백그라운드에서 끝날 수 있습니다.

## 19) MCP 및 AI 에이전트
DevProjex에는 로컬 읽기 전용 MCP 서버가 포함되어 있습니다. Claude Code, Codex, Cursor, VS Code 같은 AI 에이전트는 이 서버를 통해 프로젝트를 읽습니다. 비밀 정보 마스킹은 항상 켜져 있으며, 에이전트는 프로젝트 파일을 바꿀 수 없습니다. 서버는 8개의 도구를 제공합니다: `list_projects`, `get_tree`, `analyze`, `search_project`, `related_files`, `get_file`, `pack_context`, `read_pack`.

### 19.1 클라이언트 연결
“MCP” 메뉴에는 다음 항목이 있습니다.
* Live context — 서버가 이 창에서 선택한 항목을 따릅니다(섹션 19.2).
* 표준 — 서버가 창의 선택에 의존하지 않습니다.
* 저널… — 에이전트가 요청하고 받은 내용(섹션 19.3).
* 문서 — MCP 서버 문서를 엽니다.

“Live context”와 “표준”에는 같은 작업이 있습니다: “Claude Code에서 열기”, “Codex에서 열기”, “Cursor에서 열기”, “VS Code에서 열기”, “기타 클라이언트…”. 이 작업은 프로젝트가 열려 있는 동안 사용할 수 있습니다.

Claude Code와 Codex는 설치된 명령으로 등록되며, 그다음 프로젝트 폴더에서 새 터미널로 클라이언트가 열립니다. Cursor와 VS Code에는 프로젝트 안의 `.cursor/mcp.json` 또는 `.vscode/mcp.json`이 기록되며, 그 파일의 다른 서버는 유지됩니다. “기타 클라이언트…”는 Claude Desktop 및 기타 클라이언트에서 바로 쓸 수 있는 구성을 보여 줍니다. 클라이언트 명령이 없거나 연결에 실패하면 대신 수동 구성이 표시됩니다. 연결에 성공한 후 DevProjex가 `devprojex` 명령을 PATH에 추가하도록 제안할 수 있습니다.

Codex는 공유 DevProjex 연결을 하나만 유지하므로 다른 프로젝트를 연결할 때는 바꾸기 전에 확인을 요청합니다. 이미 실행 중인 클라이언트 세션은 서버를 불러오려면 다시 시작해야 합니다. 터미널에서 `devprojex mcp connect`는 기본적으로 표준 모드를 등록합니다. Live context를 사용하려면 `--mode live`를, 구성만 출력하려면 `--print`를 추가하세요.

### 19.2 Live context
Live context에서는 트리에서 선택한 항목이 에이전트의 포커스가 됩니다. 트리, 검색, 분석, 관련 파일, 팩 요청은 그 범위 안에서만 처리됩니다. 창의 필터(파일 형식, 제외 항목, Git 모드)는 접근 경계입니다. 에이전트는 이름을 지정해 다른 파일을 열 수도 있지만, 이 필터가 허용하는 파일만 열 수 있습니다.

창을 계속 열어 둘 필요는 없습니다. 서버는 요청할 때마다 해당 프로젝트에 마지막으로 저장된 선택을 읽으므로, 새로 선택한 항목과 적용한 설정은 에이전트를 다시 시작하지 않아도 다음 요청부터 반영됩니다.

라이브 세션이 활성 상태인 동안 창 제목 끝에 `· Live context (<client>)`가 표시되며, 여러 세션이 활성 상태이면 세션 수가 표시됩니다.

### 19.3 저널
“MCP → 저널…”은 에이전트가 DevProjex를 통해 요청하고 받은 내용을 보여 줍니다. 세션별로 클라이언트, 모드, 호출, 문자 수, 예상 토큰 수, 전달된 파일, 마스킹된 값이 표시되고, 선택한 세션의 호출도 볼 수 있습니다. 프로젝트를 열지 않아도 사용할 수 있으며, 프로젝트가 열려 있으면 기본적으로 “현재 프로젝트만”이 선택됩니다.

저널은 이 컴퓨터의 DevProjex 상태 폴더에만 저장되며, 최대 200개 세션을 30일 동안 보관합니다. 파일 내용, 감지된 비밀 정보 값, 검색어 텍스트는 저장하지 않습니다. “내보내기…”는 세션을 Markdown 또는 JSON 영수증으로 저장합니다. “지우기”는 확인 후 완료된 세션을 삭제하며, 활성 세션과 다른 프로젝트와 공유하는 세션은 유지됩니다.

### 19.4 에이전트 활동
“보기 → 에이전트 활동”은 기본적으로 꺼져 있습니다. 켜면 최근 라이브 세션 중에 에이전트가 받은 파일이 트리에 ✦로 표시되고, 표시의 도구 설명에는 에이전트가 그 파일을 받은 횟수가 나타납니다. 이 표시는 필터나 확인란을 바꾸지 않습니다. 새 라이브 세션이 시작되거나, 에이전트 활동을 끄거나, 프로젝트를 다시 열면 표시가 지워집니다. 표준 모드 세션은 저널에 표시되지만 표시를 추가하지 않습니다.

## 20) 참고 사항
* 권한이 부족하면 앱에서 권한 상승으로 다시 시작하도록 제안할 수 있습니다. 거부하면 알림이 표시됩니다.
