## 1) 그것이 무엇이며 왜
DevProjex 프로젝트 컨텍스트를 신속하게 준비합니다. 폴더/파일 구조를 표시하고, 확인란을 사용하여 항목을 선택하고, 트리 및/또는 파일 내용을 클립보드에 복사할 수 있습니다. 코드 검토, 지원, 학습, AI 도우미와의 프로젝트 구조 공유에 유용합니다.

중요: DevProjex 사용자가 연 프로젝트의 파일을 수정하지 않습니다.

## 2) 프로젝트 트리
* 파일/폴더 유형 아이콘.
* 노드의 확인란.
* 확장/축소.

확인란: 노드를 선택하면 해당 하위 노드에 적용됩니다. 상위 상태는 자동으로 다시 계산됩니다.

단축키:
* {mod}E - 모두 확장
* {collapseAll} — 모두 축소(루트는 확장된 상태로 유지됨)

### 상황에 맞는 메뉴
노드를 마우스 오른쪽 버튼으로 클릭하거나 {shift}F10 또는 초점이 맞춰진 노드에서 메뉴 키를 누르세요.
* 파일 탐색기에 표시 / Finder에 표시 / 파일 관리자에서 열기 - 시스템 파일 관리자에 항목을 표시합니다. 레이블은 현재 플랫폼과 일치합니다.
* 전체 경로 복사 - 항목의 절대 경로입니다.
* 상대 경로 복사 — 루트 폴더 이름으로 시작하는 프로젝트 루트의 경로입니다(예: `project/src/File.cs` ).
* 내용 복사 - 파일의 경우: 복사 및 내보내기를 통해 생성되는 것과 똑같은 내용 변환이 적용된 내용을 복사합니다.
* Select only this — 이 노드만 확인하고 나머지는 지웁니다. 다른 항목도 체크되어 있는 동안에만 표시됩니다.
* 분기 확장/분기 축소 — 폴더의 경우.

경로가 디스크에 더 이상 존재하지 않는 경우 파일 관리자에서 항목을 열거나 해당 내용을 복사하면 오류 메시지가 표시됩니다. 경로 복사는 여전히 작동합니다.

## 3) 파일
* 폴더 열기... — 루트 폴더 열기( {mod}O)
* 새 창 — 새로운 독립 DevProjex 인스턴스를 엽니다.
* 최근 — 최근에 열린 로컬 폴더 목록
* 새로 고침 - 로컬 폴더를 다시 검색하고 트리를 다시 작성합니다(F5).
* 파일로 내보내기:
  * 트리 내보내기
  * 콘텐츠 내보내기
  * 트리 및 콘텐츠 내보내기
* 프로젝트 내보내기:
  * 폴더로…
  * ZIP 아카이브로…

프로젝트 내보내기는 디렉토리 구조를 유지하면서 현재 트리에서 별도의 폴더 또는 ZIP 아카이브를 생성합니다.

선택한 파일 형식, 제외 규칙 및 선택한 항목이 존중됩니다. 아무것도 선택하지 않으면 현재 트리 전체를 내보냅니다.

텍스트 및 바이너리 파일이 복사되고 포함된 빈 폴더는 보존됩니다. 소스 파일은 수정되지 않습니다. 결과는 소스 프로젝트 내에 저장할 수 없습니다.

내보내는 동안에는 트리나 설정을 변경하거나, 필터를 사용하거나, 형식 또는 미리 보기 모드를 변경하거나, Git 명령을 실행하거나, 새로 고치거나, 다른 프로젝트를 열 수 없습니다.

형식 규칙:
* 내보내기 트리:
  * ASCII -> `.txt` 만 가능합니다.
  * JSON -> 기본 `.json` , 저장 대화 상자에서 `.json` 및 `.txt` 모두 사용할 수 있습니다.
  * XML -> 기본 `.xml` , 저장 대화 상자에서 `.xml` 및 `.txt` 모두 사용할 수 있습니다.
  * MD -> 기본 `.md` , 저장 대화 상자에서 `.md` 및 `.txt` 모두 사용할 수 있습니다.
* 콘텐츠 내보내기 — 항상 텍스트 콘텐츠 형식, `.txt` 파일(트리 형식 전환이 적용되지 않음)
* 트리 및 콘텐츠 내보내기 — 항상 `.txt` 파일; 선택한 트리 형식은 결과 내부의 트리 블록 형식에만 영향을 미칩니다.

내보내기 파일은 BOM 없이 UTF-8로 작성됩니다.

### 드래그 앤 드롭
드래그 앤 드롭은 프로젝트가 로드되지 않은 경우 시작 영역(드롭 영역)에서 작동합니다.

규칙:
* 폴더를 삭제할 수 있습니다.
* 파일을 삭제할 수 있습니다. 이 경우 포함된 폴더가 열립니다.
* 여러 항목을 삭제한 경우 첫 번째로 적합한 로컬 경로가 사용됩니다.
* 경로를 사용할 수 없거나 존재하지 않는 경우 "폴더 열기..."와 동일한 액세스 확인이 적용됩니다.
* 지원되지 않거나 로컬이 아닌 항목은 무시됩니다.

### 최근의
“파일 → 최근” 항목은 최근에 열어본 로컬 폴더의 기록을 보여줍니다.

규칙:
* 로컬 폴더만 목록에 추가됩니다.
* DevProjex 통해 복제된 Git 저장소는 이 목록에 추가되지 않습니다.
* 중복 항목은 생성되지 않습니다. 동일한 폴더를 다시 열면 해당 폴더가 맨 위로 이동됩니다.
* 최대 32개의 최근 폴더가 저장됩니다.
* 앱 실행 간에 기록이 보존됩니다.

각 항목에는 상위 폴더와 프로젝트 이름이 표시됩니다(예: `Projects / App` .

## 4) 터미널에서 실행
DevProjex 대화형 터미널 작업 공간과 스크립트 및 CI 대한 직접 명령을 제공합니다.

명령이 이미 설정된 경우 터미널을 열고 다음을 실행합니다.
`devprojex --help`

여기에는 최상위 명령과 옵션이 나열됩니다. 해당 명령의 자체 옵션과 예를 보려면 `devprojex help <command>` 를 실행하세요.

예:
* `devprojex` — 대화형 터미널 작업 공간을 엽니다. 작업 공간 내에서 `:` 명령줄(예 `:copy` , `:analyze` , `:branch` )을 통해 작업을 수행합니다. 전체 명령 목록을 보려면 내장된 작업 공간 도움말과 프로젝트 문서를 참조하세요.
* `devprojex tui .` — 터미널 작업 공간에서 직접 지정된 폴더를 엽니다.
* `devprojex open . --preview` — 데스크탑 미리보기에서 현재 폴더를 엽니다.
* `devprojex analyze . --format json` — 현재 프로젝트를 JSON 으로 분석합니다.
* `devprojex tree .` — 프로젝트 트리를 터미널에 인쇄합니다.
* `devprojex export context . --format markdown -o ../devprojex-context.md` — 소스 프로젝트 외부에 AI 지원 컨텍스트를 저장합니다.
* `devprojex export project . --as folder -o ../devprojex-submission` — 효과적인 프로젝트 트리를 정확한 폴더로 내보냅니다.
* `devprojex export project . --as zip -o ../devprojex-submission.zip` — 유효한 프로젝트 트리를 ZIP 아카이브로 내보냅니다.
* `devprojex export context https://github.com/owner/repo -o -` — 직접 복제하지 않고 원격 저장소를 압축합니다.
* `devprojex analyze . --git-mode tracked --exclude smart-ignore` — Smart Ignore 를 사용하여 추적된 Git 파일을 분석합니다.
* `devprojex mcp --root .` — AI 에이전트가 프로젝트를 안전하게 읽을 수 있도록 로컬 읽기 전용 MCP 서버를 시작합니다.

참고:
* `.` 는 현재 터미널 폴더를 의미합니다.
* 공백이 있는 경로는 따옴표로 묶어야 합니다.
* `--git-mode` Git 필터링 없음, `.gitignore` 또는 추적된 Git 파일을 선택합니다.
* `--exclude` Git 필터링과 별도로 일반 제외를 제어합니다.
* 분석 및 내보내기 명령은 결정적이며 데스크탑 인터페이스를 열지 않습니다.
* `tui` , `open` , `analyze` 및 두 `export` 명령 모두 Git 저장소 URL을 허용합니다. 클론은 관리되는 캐시( `devprojex cache` `)로 이동합니다.
* 명령에는 문서화된 별칭과 짧은 플래그가 있습니다(예: `export ctx` , `-f` , `-n` ). `devprojex help` 이를 보여줍니다.
* `analyze --findings` 수정 결과를 값 없이 나열하고 `--fail-on-findings` CI 대해 0이 아닌 종료 코드를 반환합니다.
* 이 명령은 프로젝트 파일을 수정하지 않습니다. DevProjex 읽기 전용 모드에서 작동합니다.

`devprojex` 명령이 작동하지 않으면 DevProjex 에서 엽니다.
“도움말 → 터미널에서 실행”.

## 5) Git
Git 메뉴는 DevProjex ( Git Clone)를 통해 복제된 프로젝트에만 사용할 수 있습니다. 앱은 파일에 영향을 주지 않으며 캐시에서만 작동합니다.

캐시는 사용자의 시스템 캐시 디렉터리에 저장됩니다. 해결된 경로를 보려면 `devprojex doctor` 실행하세요.

* 지점 — 활성 지점이 표시된 사용 가능한 지점 목록을 표시합니다. 전환하면 트리가 선택한 분기로 업데이트됩니다. 분기가 이미 로컬에 존재하는 경우 전환은 오프라인입니다(업데이트 없음). 로컬에 존재하지 않는 경우 가져와서 생성됩니다.
* 업데이트 받기 - 현재 분기만 업데이트합니다. 원본/<branch>를 가져오고 재설정합니다. Git Clone 프로젝트의 경우 F5는 동일한 작업을 수행합니다. 일반적인 "파일 → 새로 고침" 명령은 비활성화됩니다.

### 복제 창
Git Clone 창에서 URL 필드 아래에 "최근 저장소" 목록이 나타날 수 있습니다.

규칙:
* 목록은 기록에 최근에 복제된 저장소가 이미 포함된 경우에만 나타납니다.
* 저장소 URL만 목록에 추가됩니다.
* 로컬 폴더는 이 목록에 추가되지 않습니다.
* 중복 항목은 생성되지 않습니다. 동일한 저장소를 다시 복제하면 해당 저장소가 맨 위로 이동됩니다.
* 최대 16개의 최근 저장소가 저장됩니다.
* 앱 실행 간에 기록이 보존됩니다.

항목을 선택하면 URL 필드가 자동으로 채워집니다.
복제가 진행되는 동안에는 목록이 일시적으로 숨겨집니다.

## 6) 복사
### 트리 형식 토글(ASCII/ JSON / XML /MD)
토글은 트리가 출력의 일부인 작업에 대한 트리 표현 형식을 정의합니다.

* ASCII — 가지가 있는 텍스트 트리.
* JSON — JSON 의 구조화된 트리입니다.
* XML — 파서 및 도구를 위한 컴팩트 XML 트리입니다.
* MD — 문서 및 AI 프롬프트를 위한 마크다운 중첩 목록입니다.

토글은 다음에 영향을 미칩니다.
* 복사 트리
* 트리 + 콘텐츠 복사
* 트리 내보내기
* 트리 및 콘텐츠 내보내기

토글은 다음 항목에 영향을 주지 않습니다.
* 콘텐츠 복사
* 콘텐츠 내보내기

### 복사 트리
프로젝트 트리를 복사합니다.
확인된 노드가 있으면 선택을 통해 트리가 만들어집니다. 선택 항목이 비어 있거나 유효하지 않은 경우 전체 트리가 복사됩니다.
결과 형식은 트리 형식 토글로 정의됩니다.
단축키: {mod}{shift}C 및 {mod}{alt}C.

### 콘텐츠 복사
파일 내용을 복사합니다.
* 파일이 확인된 경우 - 해당 파일만 확인됩니다. 그렇지 않으면 — 모든 프로젝트 파일;
* 각 파일 앞에는 전체 로컬 경로( Git Clone 프로젝트의 경우 저장소 웹 경로)가 포함된 헤더가 있습니다.
* 텍스트가 아닌 파일은 무시됩니다(바이너리 포함).
* 빈 텍스트 파일의 경우 경로와 `[No Content, 0 bytes]` 줄이 출력됩니다.
* 공백/줄 바꿈만 포함하는 파일의 경우 경로와 `[Whitespace, N bytes]` 줄이 출력됩니다.
단축키: {mod}{alt}V.

### 트리 + 콘텐츠 복사
트리와 콘텐츠를 결합합니다.
* 트리는 선택을 통해 만들어집니다. 선택 항목이 비어 있거나 유효하지 않은 경우 전체 트리가 사용됩니다.
* 콘텐츠는 "콘텐츠 복사"와 동일한 규칙을 따릅니다.
* 트리 블록 형식은 트리 형식 토글로 정의됩니다.
단축키: {mod}{shift}V.

### 트리 표현
트리 형식은 선택한 동일한 프로젝트 트리에 대해 서로 다른 표현을 사용합니다.

JSON :
* `rootPath` — `/` 로 정규화된 절대 루트 경로입니다.
* `tree` — 루트 폴더의 내용.
* JSON 내보내기는 다음 트리 형식을 사용합니다. 배열에는 파일이 포함되고, 객체에는 하위 폴더가 포함되며, `/` 에는 현재 폴더의 파일이 포함되고 `[]` 는 빈 폴더를 나타냅니다.

XML :
* 루트 노드는 `<t r="...">` 입니다.
* 폴더는 `<d n="...">` 입니다.
* 파일은 `<f>File.cs</f>` 입니다.

MD:
* `Root: ...` 로 시작합니다.
* Markdown 중첩 목록을 사용합니다.
* 폴더는 `/` 로 끝납니다.

트리 + 콘텐츠:
* 선택한 트리 형식이 트리 블록에 적용됩니다.
* 콘텐츠 블록은 텍스트로 유지됩니다.
* 콘텐츠 블록의 파일 헤더는 `/` 와 함께 상대 경로를 사용합니다.
* `.txt` 로 내보냅니다.

## 7) 미리보기 모드
상단 표시줄의 눈 아이콘 버튼이나 {mod}B를 사용하여 열 수 있습니다.

마우스 측면 버튼은 브라우저 스타일 탐색을 따릅니다. 앞으로는 미리보기 모드를 열고 뒤로는 미리보기 모드를 닫습니다. 현재 방향을 반복해도 효과가 없습니다.

{mod}{shift}F는 미리보기에서 파일 콘텐츠 검색을 열거나 닫습니다. Enter 또는 F3을 누르면 다음 일치 항목으로 이동합니다. {shift}Enter 또는 {shift}F3는 이전 일치 항목으로 이동합니다.

트리 옆에 있는 별도의 작업 공간에 최종 결과를 표시합니다. 이 모드는 클립보드에 복사하지 않고 자체적으로 파일로 내보내지 않는 보기 모드입니다.

기본적으로 작업공간은 다음과 같이 열립니다.
* 왼쪽 — 프로젝트 트리;
* 중앙 — 미리보기 창;
* 오른쪽 — 설정 패널(열려 있는 경우)

사용 가능한 모드:
* 나무
* 콘텐츠
* 트리 및 콘텐츠

복사 및 내보내기와 동일한 규칙이 적용됩니다.
* 확인된 노드는 존중됩니다.
* 선택 항목이 비어 있으면 전체 데이터 세트가 사용됩니다.
* 현재 무시 규칙 및 선택 옵션이 적용됩니다.

추가로:
* 미리보기의 파일은 수평선으로 구분됩니다.
* 스크롤하는 동안 현재 파일의 경로가 상단에 고정됩니다. 고정된 경로를 클릭하면 해당 파일의 시작 부분으로 다시 스크롤됩니다.
* 미리보기 스크롤바는 검색 일치 항목과 수정 결과가 있는 행을 표시합니다. 마커를 클릭하면 해당 라인으로 이동합니다. 있는 그대로 유지된 결과는 표시된 상태로 유지되고 마스크된 경로 헤더는 첫 번째 줄에 하나의 마커를 추가합니다.
* 트리 및 미리보기 확대/축소는 독립적으로 실행될 수 있습니다.
* 미리보기 모드에서는 복사 메뉴를 열지 않고도 전체 현재 결과 또는 현재 표시되는 파일 블록을 복사할 수 있습니다.

버튼:
* 상단 미리보기 아일랜드 왼쪽에 있는 복사 버튼 — 현재 미리보기 모드를 복사합니다.
  * 나무
  * 콘텐츠
  * 트리 및 콘텐츠
* 트리 창의 X — 트리를 숨기고 미리보기 창만 남깁니다.
* 상단 미리보기 창의 X - 미리보기 모드를 완전히 닫습니다.
* 고정된 파일 헤더의 작은 복사 버튼 — 현재 표시되는 파일 블록을 미리보기에 표시된 것과 똑같이 복사합니다.
* 눈 아이콘을 다시 누르거나 {mod}B를 누르면 미리보기 모드도 닫힙니다.

미리보기에 트리 창이 표시되는 동안 검색 및 필터를 사용할 수 있습니다.
트리가 숨겨진 경우 미리보기 전용 모드를 종료할 때까지 검색 및 필터를 일시적으로 사용할 수 없습니다.

## 8) 보기
### 줌
* {mod}+ / {mod} = — 확대
* {mod} - — 축소
* {mod}0 - 재설정
* {mod} 마우스 휠 - 커서 아래 창을 부드럽게 확대/축소합니다.

행동:
* 일반 모드에서는 트리가 확대됩니다.
* 나무가 보이는 미리보기에서 메뉴의 확대, 축소 및 재설정은 나무와 미리보기 모두에 적용됩니다.
* {mod} 마우스 휠을 사용하면 커서 위치에 따라 트리 및 미리보기가 독립적으로 확대/축소됩니다.
* 미리보기 전용 모드에서는 미리보기 창만 확대됩니다.

범위: 6~28, 재설정은 15입니다.

### 컴팩트 모드
UI를 더 조밀하게 만듭니다. 트리 및 설정의 간격이 더 작아집니다.
미리보기 작업 영역이 활성화되어 있는 동안 컴팩트 모드가 자동으로 활성화됩니다.

### 나무 확장 애니메이션
갈매기 모양을 부드럽게 회전하고 인접한 행을 이동하면서 나무 가지를 확장하거나 축소합니다. 기본적으로 활성화되어 있습니다. 비활성화되면 확장이 즉시 이루어집니다.

### 트리 글꼴
트리 글꼴은 “보기 → 트리 글꼴”을 통해 선택됩니다.
"기본값"은 표준 트리 글꼴을 복원합니다.
설정 패널에서 '설정 적용'을 클릭하면 선택한 글꼴이 적용됩니다.

## 9) 검색(트리)
검색창을 열고 일치 항목을 강조 표시하며 탐색을 허용합니다.
* {mod}F — 표시/숨기기
* Enter - 다음 결과
* {shift}Enter — 이전
* Esc — 닫기

검색은 필요한 분기만 자동 확장합니다. 쿼리를 지우면 트리가 축소됩니다(루트 제외).
일치 선은 트리 스크롤 막대에도 표시됩니다. 마커를 클릭하면 해당 일치 항목으로 이동합니다.
매우 큰 일치 세트의 경우 앱은 UI 반응성을 유지하기 위해 자동 확장 및 전역 강조 표시를 제한할 수 있습니다.
검색창을 닫으면 닫기 애니메이션이 완료된 후 쿼리가 지워집니다.

제약:
* 검색을 열면 필터가 자동으로 닫힙니다.
* 검색은 트리 창이 표시되는 동안 미리보기에서 사용할 수 있습니다.
* 트리가 숨겨져 있으면 검색을 일시적으로 사용할 수 없습니다.

## 10) 필터(이름별)
필터 문자열과 해당 상위 항목과 일치하는 노드만 표시합니다. 업데이트가 디바운스되었습니다.
* {mod}{shift}N — 필터 표시/숨기기
* Esc — 필터 닫기

제약:
* 필터를 열면 검색이 자동으로 닫힙니다.
* 필터는 트리 창이 표시되는 동안 미리보기에서 사용할 수 있습니다.
* 트리가 숨겨져 있으면 필터를 일시적으로 사용할 수 없습니다.

## 11) 옵션(설정 패널)
오른쪽에서 사용 가능:
* 설정 적용
* 콘텐츠 처리
* 제외
* 확장

"제외" 및 "확장"의 변경 사항은 패널에 단계적으로 적용되며 "설정 적용"을 클릭하면 적용됩니다.

체크박스가 변경된 후 앱은 백그라운드에서 사용 가능한 옵션과 해당 개수를 업데이트할 수 있습니다. 결과 트리는 "설정 적용"을 클릭한 후에만 다시 작성됩니다.

상태 표시줄의 X 버튼을 사용하여 사용 가능한 옵션 업데이트를 취소하면 완료되지 않은 변경 사항이 적용되지 않고 패널이 마지막으로 완료된 상태로 돌아갑니다.

각 목록에는 모두 토글이 있습니다.

"확장"에 대한 참고 사항:
* 이 목록에는 확장자가 있는 파일만 표시됩니다.
* 확장자가 없는 파일은 이 목록에 추가되지 않으며 "제외"의 별도 옵션으로 제어됩니다.

콘텐츠 처리:
* 트리를 변경하지 않고 선택한 텍스트 파일의 내용을 변환합니다.
* 비밀 숨기기 및 개인 데이터 숨기기는 감지된 값을 대체합니다(섹션 12.3 및 12.4).
* 압축 코드는 선언을 유지하면서 14개 언어에 걸쳐 명명된 구현을 단축합니다.
* 스트립 주석은 20개 언어 팩의 주석과 문서 주석을 제거합니다.
* Strip 공백 줄은 여러 줄 리터럴을 유지하면서 동일한 팩에서 공백 전용 줄을 제거합니다.
* 변경 사항은 "설정 적용" 후에 적용됩니다.

{mod}P — 패널을 표시하거나 숨깁니다.

### 11.1 로컬 프로젝트 매개변수 프로필
로컬 폴더의 경우 DevProjex 마지막으로 적용된 프로젝트 매개변수를 기억합니다.
* 선택한 파일 형식;
* "제외" 섹션에서 선택한 옵션.

"설정 적용"을 클릭하면 저장이 수행됩니다.
동일한 로컬 폴더를 다시 열면 매개변수가 자동으로 복원됩니다.

중요한:
* 프로필은 로컬 프로젝트에 대해서만 저장됩니다.
* Git Clone을 통해 열린 프로젝트의 경우 프로필이 저장되지 않습니다.
* 저장된 옵션 중 일부를 현재 프로젝트에서 더 이상 사용할 수 없으면 해당 옵션을 건너뛰고 나머지 매개변수가 적용됩니다.
* 새로 고치거나 다시 열면 "제외"에 새 파일 형식이나 옵션이 표시되는 경우 기본적으로 활성화됩니다.
* 이미 표시된 옵션은 사용자의 명시적인 선택을 유지합니다. 비활성화된 유형의 새 파일은 해당 유형을 다시 활성화하지 않습니다.

## 12) 제외사항
"제외" 섹션에서는 트리, 콘텐츠, 복사 및 내보내기 결과에서 제외되는 파일과 폴더를 제어합니다.

항목은 다음 조건이 모두 충족되는 경우에만 표시됩니다.
* 파일에 유형이 있으면 해당 파일 유형이 선택됩니다.
* 활성화된 무시 규칙이 없으면 이를 제외합니다.

무시 규칙은 누적됩니다. 하나 이상의 활성화된 규칙이 항목을 숨기는 경우 다른 규칙은 해당 항목을 표시할 수 없습니다.

### 12.1 사용 가능한 규칙
프로젝트 내용에 따라 다음과 같은 옵션이 표시될 수 있습니다.

* Smart Ignore
* .gitignore 사용
* 추적된 Git 파일만
* 빈 폴더
* 빈 파일
* 숨겨진 폴더
* 숨겨진 파일
* 점이 붙은 폴더
* 점이 붙은 파일
* 확장자가 없는 파일

Git 저장소 내에서 ".gitignore 사용" 및 "추적된 Git 파일만"은 안정적인 확인란 쌍으로 표시됩니다. 하나를 활성화하면 다른 하나는 지워집니다. 활성 확인란을 다시 클릭하면 해당 확인란이 지워지고 Smart Ignore 또는 기본 제외를 변경하지 않고 두 Git 필터가 모두 꺼진 상태로 유지됩니다. 해당 규칙이 현재 트리를 변경할 수 있는 경우 다른 옵션이 표시됩니다. 따라서 다른 규칙이나 파일 형식을 전환한 후에 목록이 변경될 수 있습니다.

새 옵션이 처음 나타날 때 기본적으로 활성화됩니다. 알려진 옵션은 목록에서 일시적으로 사라지더라도 사용자의 선택을 유지합니다.

### 12.2 Smart Ignore
Smart Ignore 종속성, 빌드 출력, 캐시 및 기타 프로젝트 서비스 아티팩트를 숨깁니다.

DevProjex 먼저 구조와 마커 파일에서 프로젝트 유형을 식별합니다. 예를 들면 다음과 같습니다.

* `.csproj`
* `package.json`
* `pyproject.toml`
* `Cargo.toml`

그런 다음 해당 스택에 대한 규칙이 감지된 프로젝트 범위 내에 적용됩니다. 예를 들어 .NET 규칙은 인접한 Python 또는 JavaScript 프로젝트로 확장되지 않습니다.

폴더 이름만으로는 항상 충분하지 않습니다. `build` , `vendor` , `packages` , `cache` , `pkg` 또는 `Library` 와 같은 모호한 이름도 해당 내용으로 확인됩니다. 이렇게 하면 일반 사용자 폴더가 비슷한 이름을 가지고 있다는 이유만으로 숨겨지는 것을 방지할 수 있습니다.

일부 종속성 저장소와 서비스 디렉터리는 명시적으로 검색된 프로젝트 외부에서도 특징적인 내부 구조로 인식될 수 있습니다.

프로젝트 범위 검색은 제한되어 있으므로 대규모 사용자 폴더를 로드해도 모든 디렉터리에 대한 전체 반복 분석이 되지는 않습니다. 일반 구조는 얕은 검색을 사용하는 반면, 인식된 단일 저장소는 더 깊이 검색됩니다. 범위를 찾은 후 Smart Ignore 깊이 제한 없이 전체 하위 트리에 적용됩니다.

### 12.3 비밀 숨기기
"비밀 숨기기"는 기본적으로 꺼져 있습니다. 선택한 텍스트 콘텐츠만 검사하고 감지된 각 값을 제자리에 대체하여 파일과 주변 코드를 유지합니다. 옵션이 꺼져 있으면 스캔이 실행되지 않으며 카운트도 표시되지 않습니다. 현재 선택 항목을 스캔한 후 레이블에 감지된 값의 수가 표시됩니다. 현재 상태 유지 결정에 따라 숨겨진 값이 더 적어지면 감지/숨김이 표시되고 행의 ? 표시기는 두 가지 개수를 모두 보고합니다.

수정된 범위는 미리보기에서 강조표시됩니다. 해당 항목만 있는 그대로 유지하려면 하나를 클릭합니다. {alt}↓ / {alt}↑ 결과 사이를 이동하고 Enter를 누르면 활성 항목이 전환됩니다. 터미널 작업 공간에서 `[` 및 `]` 사용하여 발생 항목 사이를 이동하고 `Enter` 또는 `Space` 사용하여 활성 항목을 전환합니다. 결정은 현재 세션의 미리보기, 클립보드, 컨텍스트 내보내기, 폴더 복사 및 ZIP 에 적용됩니다. 프로젝트 프로필에는 저장되지 않습니다.

미리보기 상황에 맞는 메뉴는 이러한 결정을 확장합니다. 감지된 항목을 마우스 오른쪽 버튼으로 클릭하면 해당 규칙의 모든 항목 또는 동일한 파일에서 감지된 모든 항목을 한 번의 작업으로 유지하거나 다시 숨길 수 있습니다. 파일 콘텐츠 내에서 선택한 값을 마우스 오른쪽 버튼으로 클릭하여 수동으로 표시합니다. "여기에서 숨기기"는 세션에서 해당 항목만 숨기고, "항상 숨기기..."는 해당 값이 발생할 때마다 영구 표시를 생성하며, "개인 데이터로 숨기기"는 개인 데이터 숨기기로 제어되는 영구 표시를 생성합니다. 수동 표시에 "표시 제거"가 나타나고 삭제됩니다. 감지기와 여전히 일치하는 값은 숨겨진 상태로 유지됩니다. 수동 값은 파일 콘텐츠 내에서 선택된 8~512자의 한 줄이어야 합니다. 마크를 생성하면 해당 옵션이 자동으로 활성화됩니다. 영구 표시는 키 값 ID와 해당 클래스만 저장하며 원본 텍스트는 저장하지 않습니다.

폴더 또는 ZIP 복사본도 일치하는 텍스트를 변경하므로 더 이상 빌드되거나 실행되지 않을 수 있습니다. 바이너리 파일은 변경되지 않고 복사되며 검사되지 않습니다. 16MiB를 초과하는 선택된 텍스트 파일 또는 감지 실패로 인해 검사되지 않은 텍스트를 내보내는 대신 작업이 중지됩니다.

개수 보고 규칙은 일치만 합니다. 0이 프로젝트가 안전하다는 의미는 아닙니다. CLI `--hide-secrets` 사용합니다. 기술적인 세부 사항과 제한 사항은 `Docs/HideSecrets.md` 에 있습니다.

### 12.4 개인 데이터 숨기기
"개인 데이터 숨기기"는 기본적으로 꺼져 있습니다. 선택한 텍스트 파일에서 이메일 주소, 글로벌 IP 주소, 경로의 로컬 사용자 이름, MAC 주소 및 국제 전화번호를 탐지합니다. 결과는 Hide Secrets와 동일한 미리보기 결정 및 동일한 출력 파이프라인을 사용합니다. "비공개 데이터로 숨기기"로 생성된 수동 표시는 이 클래스에 속하며 이 스위치를 따릅니다(섹션 12.3). 생성된 경로 헤더와 트리 루트의 로컬 사용자 이름은 하나의 공유 결과로 마스킹됩니다. 카운터는 이를 하나의 값으로 포함합니다. 표시기는 숨김 또는 표시 여부를 보고하며 한 번의 클릭으로 마스크된 모든 경로를 전환합니다.

문서 범위 및 호스트, 일반적인 CI 사용자 이름, 잘 알려진 공용 DNS 확인자, 문서화된 가상 전화 범위는 계속 표시됩니다. 일치하지 않는 항목은 개인정보 보호를 보장하지 않습니다. CLI `--hide-private-data` 사용합니다. 전체 규칙과 1단계 제한은 `Docs/HidePrivateData.md` 에 있습니다.

### 12.5 .gitignore 사용
활성화되면 DevProjex 열린 폴더의 루트에 있는 파일뿐만 아니라 접근 가능한 모든 `.gitignore` 적용합니다.

각 `.gitignore` 가 적용됩니다.

* 그것을 포함하는 폴더로;
* 그 아래에 있는 액세스 가능한 모든 폴더에
* 해당 범위 내에서만 가능합니다.

중첩된 `.gitignore` 의 규칙은 상위 또는 형제 폴더에 영향을 주지 않습니다.

특정 경로의 경우 규칙은 상위 `.gitignore` 에서 더 깊은 파일로 처리됩니다. 하나의 파일 내에서 규칙은 위에서 아래로 처리됩니다. 마지막 일치 규칙에 따라 Git 결과가 결정됩니다.

`!` 로 시작하는 규칙은 해당 범위 내에서만 이전 Git 제외를 취소합니다. 상위 폴더가 제외된 상태에서는 파일을 복원할 수 없습니다. 완전히 제외되고 접근할 수 없는 폴더 내의 `.gitignore` 는 평가에 참여하지 않습니다.

형식이 잘못되었거나 지원되지 않는 줄은 독립적으로 건너뜁니다. 해당 파일의 다른 유효한 규칙과 인접 범위의 규칙은 계속 작동합니다.

이 옵션은 일반 작업 트리 `.gitignore` 파일에만 적용됩니다. `.git/info/exclude` 의 규칙과 전역 Git 제외 규칙은 적용되지 않습니다. `core.ignoreCase` 및 macOS 에서는 `core.precomposeUnicode` 와 같은 효과적인 저장소 경로 비교 설정이 존중됩니다. Git 의 제어 파일 동작과 일치하여 `.gitignore` 라는 심볼릭 링크를 따르지 않습니다. 일반 `.gitignore` 읽을 수 없는 경우 해당 디렉토리 범위는 페일클로즈로 제외되고 스캔에서는 완전한 규칙 평가 없이 파일을 자동으로 포함하는 대신 부분 액세스를 보고합니다. 경로를 소유한 저장소 범위에 대한 읽기 가능한 인덱스를 사용할 수 있는 경우 추적된 파일은 `.gitignore` 와 일치하더라도 계속 표시됩니다. 해당 인덱스나 Git CLI 없으면 해당 범위는 패턴 전용 평가로 안전하게 대체됩니다.

내장된 `standard` 프로필은 `gitignore` 와 `smart-ignore` , `hidden-folders` , `hidden-files` , `dot-folders` , `dot-files` , `empty-folders` , `empty-files` 및 `extensionless-files` .

### 12.6 추적된 Git 파일만
"추적된 Git 파일만"은 읽을 수 있는 각 Git 인덱스에 기록된 기존 작업 트리 파일에서 트리의 Git 단계를 구축합니다. 수정된 추적 파일과 단계적 추가는 계속 포함됩니다. 추적되지 않은 파일은 제외됩니다. 이것은 `HEAD` 의 기록 스냅샷이나 원격 저장소가 아닌 현재 작업 트리입니다.

도달 가능한 모든 중첩 저장소 및 작업 트리는 도달 가능한 모든 중첩 수준에서 독립적으로 해결됩니다. 하위 저장소는 상위 또는 형제 저장소로부터 추적된 경로를 상속하지 않습니다. 이 모드에는 Git CLI 필요합니다. 읽을 수 있는 빈 인덱스가 유효합니다. TUI (터미널 작업 공간)가 이 모드에서 시작되고 해당 인덱스를 로드할 수 없으면 작업 공간이 열리지 않습니다. 열려 있는 TUI 작업 영역에서 모드를 대화형으로 선택하고 해당 인덱스를 로드할 수 없는 경우 변경 사항이 거부되고 마지막으로 사용 가능한 Git 모드가 활성 상태로 유지됩니다. 동일한 상황에서 직접 명령은 정책 또는 검사 실패를 반환합니다. DevProjex 절대 조용히 `.gitignore` 로 돌아가지 않습니다. 적용 가능한 다른 인덱스를 읽을 수 있는 경우 사용할 수 없는 중첩 범위는 경고와 함께 제외됩니다.

이미 열려 있는 데스크톱 작업 영역에서는 명시적으로 추적된 선택 항목이 계속 표시되고 실패 시 닫힙니다. 준비가 실패하면 출력 및 내보내기가 차단되고 부분 준비는 현지화된 경고와 함께 계속됩니다.

".gitignore 사용"과 "추적된 Git 파일만"은 활성화되면 상호 배타적입니다. 활성 확인란을 선택 취소하여 Git 필터링을 비활성화할 수도 있습니다. 프로필을 지원하는 로컬 프로젝트의 경우 이 상태는 파일 형식 및 기타 제외 설정과 함께 저장됩니다.

### 12.7 Git 필터링과 Smart Ignore 의 관계
Git 확인란과 Smart Ignore 는 독립적인 컨트롤입니다. 선택한 Git 모드는 도달 가능한 모든 Git 범위에 먼저 적용됩니다. 그러면 Smart Ignore 나머지 항목을 처리하고 기본 규칙이 마지막으로 실행됩니다.

선택한 Git 모드가 이미 모든 후보를 포함하는 동안 Smart Ignore 숨겨진 상태로 유지되었다가 Git 모드가 변경되거나 지워진 후에 표시될 수 있습니다. 두 Git 확인란 모두 Git 저장소 내에서 계속 사용할 수 있습니다.

`!` 로 시작하는 Git 부정 규칙은 Git 결과만 취소합니다. Smart Ignore 또는 기본 규칙은 비활성화되지 않습니다.

### 12.8 기본 규칙
"점 접두사가 붙은 폴더" 및 "점 접두사가 붙은 파일"은 항목 이름을 검사합니다.

"숨겨진 폴더" 및 "숨겨진 파일"은 시스템 숨김 속성을 검사합니다. 일부 플랫폼에서는 점으로 시작하는 이름과 시스템 속성이 동일한 항목을 설명할 수도 있고 다른 항목을 설명할 수도 있습니다.

"빈 파일"은 크기가 0바이트인 파일을 숨깁니다.

"확장자가 없는 파일"은 `Dockerfile` , `Makefile` 및 `README` 와 같은 파일을 숨깁니다.

"빈 폴더"는 논리적으로 빈 폴더를 숨깁니다. 선택한 파일 형식과 다른 모든 규칙이 적용된 후에 표시되는 파일이나 하위 폴더가 남아 있지 않으면 폴더는 논리적으로 비어 있습니다.

따라서 빈 폴더 수는 다른 규칙이 전환된 후에 변경될 수 있습니다. 즉, 파일을 숨기면 포함된 폴더가 논리적으로 비어 있게 될 수 있습니다.

### 12.9 카운터
규칙 옆의 개수는 디스크에 있는 유사한 항목의 물리적 개수가 아니라 현재 설정에 따른 직접적인 기여도를 보여줍니다.

하나의 항목이 동시에 여러 개의 중복된 카운터에 귀속되지 않습니다. 예를 들어 `.git` 폴더에는 점으로 시작하는 이름과 시스템 숨김 속성이 모두 있을 수 있지만 해당 제외는 하나의 규칙에만 적용됩니다.

제외 소유자를 선택하려면 안정적인 순서가 사용됩니다.

* 폴더: `.gitignore` , Smart Ignore , 점 접두사가 붙은 이름, 시스템 숨겨진 속성;
* 파일: `.gitignore` , Smart Ignore , 점 앞에 붙은 이름, 확장자 없음, 빈 파일, 시스템 숨김 속성.

이 순서는 카운터에만 영향을 미칩니다. 최종 가시성은 더 간단한 규칙을 따릅니다. 즉, 활성화된 메커니즘에서 항목을 제외하면 항목이 숨겨집니다.

### 12.10 변경사항 적용
확인란을 전환하면 먼저 패널에서 사용 가능한 설정과 카운터가 업데이트됩니다. "설정 적용"을 선택한 후 최종 트리가 다시 작성됩니다.

설정 준비가 취소되면 DevProjex 패널을 마지막으로 완전히 완료된 상태로 되돌립니다. 부분적으로 계산된 규칙은 적용되지 않습니다.

## 13) 트리와 메트릭이 계산되는 방법
결과는 다음에 따라 달라집니다.
* 선택한 확장
* 규칙을 무시하세요
* 활성 필터
* 확인된 트리 노드(선택 기반 작업용)

액세스가 거부되면 노드는 일반적인 이름과 아이콘을 유지하고 "[액세스 거부됨]" 접미사를 얻습니다.

### 13.1 상태 표시줄 카운터에 표시되는 내용
상태 표시줄에는 두 개의 블록이 있습니다.
* 트리 — 트리 텍스트 출력의 측정항목입니다.
* 콘텐츠 — 내보낸 파일 콘텐츠 출력의 측정항목입니다.

체재:
* 윤곽
* 문자
* ~토큰(대략)

큰 값은 간단한 접미사(K/M)로 표시됩니다.

중요한:
* "Tree" 블록의 "라인"은 디스크의 파일 수가 아니라 최종 트리 표현의 라인 수를 의미합니다.
* 이 값에는 폴더, 파일 및 트리 서비스 요소(예: 액세스 거부 노드)가 포함됩니다.

### 13.2 지표 계산 방법
트리 측정항목:
* 동일한 내보내기 파이프라인에서 생성된 실제 트리 출력에서 ​​계산됩니다.
* 현재 트리 형식을 존중합니다.

콘텐츠 지표:
* 콘텐츠 복사/내보내기와 동일한 규칙을 따릅니다.
* 바이너리 파일은 제외됩니다.
* 비어 있고 공백만 있는 파일은 서비스 마커( `[No Content, 0 bytes]` , `[Whitespace, N bytes]` )를 통해 계산됩니다.

### 13.3 카운터가 업데이트되는 경우
재계산 실행:
* 프로젝트를 열거나 새로 고친 후;
* 설정 적용 후(제외 및 확장)
* 트리 체크박스가 변경될 때(디바운스 사용)
* 트리 형식을 전환할 때(트리 출력이 사용되는 작업의 경우)
* 백그라운드 계산이 취소되면 다음 재계산이 완료될 때까지 카운터는 0으로 설정됩니다.

## 14) 아이콘
아이콘 선택 순서:
1) 노드 유형(폴더/파일)
2) 정확한 이름(규칙이 있는 경우)
3) 확대
4) 그렇지 않으면 — 알 수 없음

## 15) 테마 및 효과
테마 섹션에서는 시스템, 밝게 또는 어두움과 하나의 배경 효과를 선택할 수 있습니다.
* 투명도
* 흐림
* 운모

시스템은 기본적으로 선택되며 운영 체제 테마 변경 사항을 따릅니다. 처음 실행하거나 설정을 재설정한 후 밝은 시스템 테마는 일반 불투명 배경으로 시작되고 어두운 시스템 테마는 흐림으로 시작됩니다. 시스템 기본 설정을 결정할 수 없는 경우 DevProjex Dark with Blur를 사용합니다. 빛과 어둠은 그 효과를 독립적으로 기억합니다. 명시적으로 밝게 또는 어둡게 선택하면 시스템을 다시 선택할 때까지 시스템 변경이 무시됩니다.

효과는 상호 배타적입니다. 선택한 효과를 다시 클릭하면 효과가 비활성화되고 일반 불투명 배경이 복원됩니다.

사용 가능한 설정:
* 배경 투명도 - 투명도 및 흐림 효과에 사용할 수 있습니다.
* 상단 패널 대비 — 미리보기, 검색, 필터 및 트리 형식 명령이 포함된 기본 패널을 조정합니다.
* 메뉴 투명도 - 기본 메뉴와 하위 메뉴에 동일하게 적용됩니다.
* 테두리 가시성 — 인터페이스 테두리가 표시되는 정도를 조정합니다.

운모는 플랫폼의 시스템 자료를 사용하며 별도의 배경 투명도 설정이 없습니다. 선택한 흐림 효과 또는 운모 효과를 사용할 수 없는 경우 앱은 먼저 다른 기본 효과를 시도합니다. 일반 불투명 배경은 Blur나 Mica를 모두 사용할 수 없는 경우에만 사용됩니다.

투명 모드에서는 기본 창 배경이 투명하게 유지됩니다. 메뉴, 하위 메뉴 및 기타 팝업 표면은 지원되는 경우 Blur를 사용하므로 그 뒤에 있는 트리 및 콘텐츠 요소가 가독성을 방해하지 않습니다.

## 16) 도움말

### 16.1 업데이트
"도움말 → 업데이트"는 현재 버전을 안정적인 최신 GitHub 릴리스와 비교합니다. 자동 검사는 기본적으로 꺼져 있습니다. 활성화되면 DevProjex 이전 성공적인 확인 이후 최소 7일이 경과한 후 시작 시 확인합니다. 확인란은 즉시 적용됩니다. 최근에 성공한 결과는 애플리케이션 실행 사이에 유지되며 나중에 네트워크 오류가 발생해도 지워지지 않습니다. 설치는 사용자 작업으로 유지됩니다.

### 16.2 재설정 설정
설정 재설정(도움말 → 설정 재설정)은 기본 테마, 효과, 컴팩트 모드, 트리 확장 애니메이션 및 인터페이스 언어를 복원합니다. 디스크의 프로젝트 프로필, 기록 및 파일은 변경되지 않습니다.

### 16.3 데이터 재설정
데이터 재설정(도움말 → 데이터 재설정)은 저장된 로컬 프로젝트 매개변수 프로필을 제거합니다.
* 선택한 파일 형식;
* "제외" 섹션에서 선택한 옵션.

중요한:
* 로컬 폴더의 최근 기록은 지워지지 않습니다.
* Git Clone 창의 최근 리포지토리 기록은 지워지지 않습니다.
* 디스크의 파일과 폴더는 수정되거나 삭제되지 않습니다.

## 17) 언어
언어는 언어 메뉴를 통해 선택됩니다.
선택한 언어는 실행 사이에 저장됩니다. “도움말 → 설정 재설정”은 저장된 언어 선택을 지우고 인터페이스 언어를 기본값으로 되돌립니다.

## 18) 진행률 표시줄 및 취소
상태 표시줄 중앙에는 활성 작업과 진행 상황이 표시됩니다.

진행 모드:
* 불확정 - 백분율 없음(작업 기간을 알 수 없음)
* 확정 - 백분율(0~100)로 결정합니다.

행동:
* 백그라운드 데이터 계산 중에 진행률이 표시됩니다.
* 일부 Git 작업의 경우 진행률 소스가 제공할 때 백분율이 표시됩니다.
* 작업에 상당한 시간이 걸릴 때 사용 가능한 옵션 업데이트 및 설정 응용 프로그램이 표시됩니다.
* 진행 상황을 표시하지 않고 빠른 작업이 완료됩니다.

상태 표시줄의 X 버튼(취소):
* 취소를 지원하는 작업에 대해 최선의 취소를 수행합니다.
* 백그라운드 데이터 계산을 중지합니다.
* 사용 가능한 옵션 업데이트가 취소되면 패널을 마지막 완료된 상태로 되돌립니다.
* 취소 지원이 없는 작업의 경우 상태 표시줄 표시가 중지되지만 작업 자체는 여전히 백그라운드에서 완료될 수 있습니다.
