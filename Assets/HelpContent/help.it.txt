## 1) Cos’è e a cosa serve
DevProjex prepara rapidamente il contesto del progetto: mostra la struttura di cartelle/file, permette di selezionare gli elementi e copiare l’albero e/o il contenuto dei file negli appunti. Utile per code review, supporto, formazione e condivisione della struttura con un assistente AI.

Importante: l’app è solo in lettura e non modifica i file.

## 2) Albero del progetto
* Icone per tipo file/cartella.
* Checkbox sui nodi.
* Espandi/riduci.

Checkbox: la selezione di un nodo si applica ai figli; lo stato dei genitori è ricalcolato automaticamente.

Scorciatoie:
* Ctrl+E — espandi tutto
* Ctrl+W — comprimi tutto (la radice resta aperta)

## 3) File
* Apri cartella… — apri la cartella radice (Ctrl+O)
* Nuova finestra — apri una nuova istanza indipendente di DevProjex
* Recenti — elenco delle cartelle locali aperte di recente
* Aggiorna — rileggi e ricostruisci l’albero (F5)
* Esporta su file:
  * Esporta albero
  * Esporta contenuto
  * Esporta albero e contenuto

Regole di formato:
* Esporta albero:
  * ASCII -> solo `.txt`.
  * JSON -> predefinito `.json`, con `.json` e `.txt` disponibili nella finestra di salvataggio.
  * XML -> predefinito `.xml`, con `.xml` e `.txt` disponibili nella finestra di salvataggio.
  * MD -> predefinito `.md`, con `.md` e `.txt` disponibili nella finestra di salvataggio.
* Esporta contenuto — sempre formato testo del contenuto, file `.txt` (il selettore formato albero non influisce).
* Esporta albero e contenuto — sempre file `.txt`; il formato albero selezionato influisce solo sul formato del blocco albero nel risultato.

I file esportati vengono scritti in UTF-8 senza BOM.

### Drag & Drop
Il drag & drop funziona nell’area iniziale (Drop Zone) quando nessun progetto è caricato.

Regole:
* puoi trascinare una cartella;
* puoi trascinare un file — in questo caso viene aperta la cartella che lo contiene;
* se vengono trascinati più elementi, viene usato il primo percorso locale valido;
* se un percorso non è disponibile o non esiste, vengono applicati gli stessi controlli di accesso di «Apri cartella…»;
* elementi non supportati o non locali vengono ignorati.

### Recenti
La voce «File → Recenti» mostra la cronologia delle cartelle locali aperte di recente.

Regole:
* nell’elenco vengono aggiunte solo cartelle locali;
* i repository Git clonati tramite DevProjex non vengono aggiunti a questo elenco;
* non vengono creati duplicati — riaprire la stessa cartella la sposta in cima;
* vengono conservate fino a 15 cartelle recenti;
* la cronologia viene mantenuta tra gli avvii dell’applicazione.

Per ogni elemento viene mostrato il nome breve della cartella; il percorso completo è disponibile in un tooltip.

## 4) Avvio dal terminale
DevProjex può essere avviato dal terminale.

Se il comando è già configurato, apri un terminale ed esegui:
`devprojex --help`

Così vedrai tutti i comandi, le opzioni e gli esempi disponibili.

Esempi:
* `devprojex .` — aprire la cartella corrente.
* `devprojex "C:\Projects\App"` — aprire la cartella indicata.
* `devprojex . --export tree` — stampare l’albero del progetto nel terminale.
* `devprojex . --export content` — stampare il contenuto dei file nel terminale.
* `devprojex . --export tree-content` — stampare albero e contenuti nel terminale.
* `devprojex . --export tree-content -o context.txt` — salvare il risultato in un file.
* `devprojex --benchmark "C:\Projects\App"` — misurare il workflow standard del report di progetto.
* `devprojex --last --preview` — aprire l’ultimo progetto direttamente in modalità anteprima.
* `devprojex --benchmark-ui "C:\Projects\App"` — misurare lo scenario UI standard.
* `devprojex --session-metrics "C:\Projects\App"` — registrare le metriche della sessione UI fino alla chiusura della finestra.

Note:
* `.` indica la cartella corrente del terminale;
* i percorsi con spazi devono essere racchiusi tra virgolette;
* se non viene indicato un file di output, il risultato viene stampato direttamente nel terminale;
* il comando non modifica i file del progetto — DevProjex lavora in sola lettura.

Se il comando `devprojex` non funziona, apri in DevProjex:
“Aiuto → Avvio dal terminale”.

## 5) Git
Il menu Git è disponibile solo per i progetti clonati tramite DevProjex (Git Clone). L'app non tocca i tuoi file — lavora solo con la cache.

La cache si trova nella cartella temporanea di sistema. Su Windows di solito è:
`%TEMP%\DevProjex\RepoCache`

* Branch — mostra l’elenco dei branch disponibili con indicazione di quello attivo; il cambio aggiorna l’albero al branch scelto. Se il branch esiste già in locale, il cambio è offline (senza aggiornamento). Se non esiste in locale, viene scaricato (fetch) e creato localmente.
* Ottieni aggiornamenti — aggiorna solo il branch corrente: fetch e reset a origin/<branch>.

### Finestra di clonazione
Nella finestra Git Clone può comparire sotto il campo URL un elenco «Repository recenti».

Regole:
* l’elenco appare solo se nella cronologia esistono già repository clonati di recente;
* nell’elenco vengono aggiunti solo gli URL dei repository;
* le cartelle locali non vengono aggiunte a questo elenco;
* non vengono creati duplicati — clonare di nuovo lo stesso repository lo sposta in cima;
* vengono conservati fino a 7 repository recenti;
* la cronologia viene mantenuta tra gli avvii dell’applicazione.

Se selezioni un elemento dall’elenco, l’URL viene inserito automaticamente nel campo di input.
Durante una clonazione attiva l’elenco viene nascosto temporaneamente.

## 6) Copia
### Selettore formato albero (ASCII / JSON / XML / MD)
Il selettore definisce il formato di rappresentazione dell’albero per le operazioni in cui l’albero partecipa al risultato.

* ASCII — albero testuale con rami.
* JSON — albero strutturato in JSON.
* XML — albero XML compatto per parser e strumenti.
* MD — lista Markdown annidata per documentazione e prompt AI.

Il selettore influisce su:
* Copia albero
* Copia albero + contenuto
* Esporta albero
* Esporta albero e contenuto

Il selettore non influisce su:
* Copia contenuto
* Esporta contenuto

### Copia albero
Copia l’albero del progetto.
Se ci sono nodi selezionati, l’albero è costruito dalla selezione; se la selezione è vuota o non valida, viene copiato l’albero completo.
Il formato del risultato è definito dal selettore formato albero.
Scorciatoie: Ctrl+Shift+C e Ctrl+Alt+C.

### Copia contenuto
Copia il contenuto dei file:
* se ci sono file selezionati — solo quelli; altrimenti — tutti i file del progetto;
* i file non testuali vengono ignorati (inclusi i binari);
* per i file di testo vuoti vengono riportati il percorso e la riga `[No Content, 0 bytes]`;
* per i file composti solo da spazi/ritorni a capo vengono riportati il percorso e la riga `[Whitespace, N bytes]`.
Scorciatoia: Ctrl+Alt+V.

### Copia albero + contenuto
Combina albero e contenuto:
* albero dalla selezione; se la selezione è vuota o non valida, viene usato l’albero completo;
* contenuto secondo le stesse regole di «Copia contenuto»;
* il formato del blocco albero è definito dal selettore formato albero.
Scorciatoia: Ctrl+Shift+V.

### Rappresentazioni dell’albero
I formati albero rappresentano in modi diversi lo stesso albero di progetto selezionato.

JSON:
* `rootPath` — percorso radice assoluto normalizzato con `/`.
* `tree` — contenuto della cartella radice.
* L’export JSON usa questo formato albero: gli array contengono i file, gli oggetti contengono le sottocartelle, `/` contiene i file della cartella corrente e `[]` rappresenta una cartella vuota.

XML:
* il nodo radice è `<t r="...">`;
* le cartelle sono `<d n="...">`;
* i file sono `<f>File.cs</f>`.

MD:
* inizia con `Root: ...`;
* usa una lista Markdown annidata;
* le cartelle terminano con `/`.

Albero + contenuto:
* il formato albero selezionato si applica al blocco albero;
* il blocco contenuto resta testuale;
* le intestazioni dei file nel blocco contenuto usano percorsi relativi con `/`;
* esportazione in `.txt`.

## 7) Modalità anteprima
Si apre con il pulsante con icona a forma di occhio nella barra superiore o con Ctrl+B.

Mostra il risultato finale in un’area di lavoro separata accanto all’albero. Questa modalità non copia nulla negli appunti e non esporta nulla su file: serve solo per la visualizzazione.

Per impostazione predefinita l’area di lavoro si apre così:
* a sinistra — albero del progetto;
* al centro — pannello di anteprima;
* a destra — pannello delle impostazioni, se era aperto.

Modalità disponibili:
* Albero
* Contenuto
* Albero e contenuto

Si applicano le stesse regole della copia e dell’esportazione:
* i nodi selezionati vengono considerati;
* se la selezione è vuota, viene usato il set completo dei dati;
* vengono applicate le regole di ignoramento e i parametri di selezione correnti.

Inoltre:
* i file nell’anteprima sono separati da linee orizzontali;
* durante lo scorrimento, il percorso del file corrente resta fissato in alto;
* lo zoom dell’albero e quello dell’anteprima possono vivere separatamente.
* nella modalità anteprima puoi copiare sia il risultato completo corrente sia il blocco del file attualmente visibile senza aprire il menu «Copia».

Pulsanti:
* pulsante di copia a sinistra nel pannello superiore di anteprima — copia la modalità di anteprima corrente:
  * Albero
  * Contenuto
  * Albero e contenuto
* X nel pannello dell’albero — nasconde l’albero e lascia solo il pannello di anteprima;
* X nella barra superiore dell’anteprima — chiude completamente la modalità anteprima;
* piccolo pulsante di copia nell’intestazione fissata del file — copia il blocco del file attualmente visibile esattamente come appare nell’anteprima;
* anche premere di nuovo l’icona occhio o Ctrl+B chiude la modalità anteprima.

Ricerca e filtro restano disponibili finché nell’anteprima è visibile il pannello dell’albero.
Se l’albero è nascosto, ricerca e filtro diventano temporaneamente non disponibili fino all’uscita dalla modalità solo anteprima.

## 8) Visualizza
### Zoom
* Ctrl++ / Ctrl+= — aumenta
* Ctrl+- — riduci
* Ctrl+0 — reset
* Ctrl + rotellina — zoom fluido nel pannello sotto il cursore

Comportamento:
* in modalità normale viene scalato l’albero;
* in anteprima con l’albero visibile, Aumenta, Riduci e Reset dal menu si applicano contemporaneamente all’albero e all’anteprima;
* con Ctrl + rotellina, albero e anteprima scalano in modo indipendente in base alla posizione del cursore;
* in modalità solo anteprima viene scalato solo il pannello di anteprima.

Intervallo: 6–28, reset: 15.

### Modalità compatta
Rende l'interfaccia più densa: spazi più piccoli nell'albero e nelle impostazioni.
Quando l’area di lavoro di anteprima è attiva, la modalità compatta viene abilitata automaticamente.

### Animazione albero
Attiva un'animazione di scorrimento fluido quando si passa il mouse sulle righe dell'albero.

### Font albero
Il font dell’albero si sceglie da « Visualizza → Font albero ».
« Predefinito » ripristina il font standard dell’albero.
Il font scelto viene applicato dopo aver premuto « Applica » nel pannello impostazioni.

## 9) Ricerca nell'albero
Apre la ricerca, evidenzia le corrispondenze e permette la navigazione.
* Ctrl+F — mostra/nascondi
* Enter — risultato successivo
* Shift+Enter — precedente
* Esc — chiudi

La ricerca apre solo i rami necessari; svuotando la query l’albero si richiude (tranne la radice).
Con un numero molto elevato di corrispondenze, l’app può limitare l’espansione automatica e l’evidenziazione globale per mantenere l’interfaccia reattiva.
Alla chiusura della ricerca, la query viene svuotata dopo il completamento dell’animazione di chiusura.

Limitazioni:
* all’apertura della ricerca, il filtro si chiude automaticamente;
* la ricerca è disponibile in anteprima finché il pannello dell’albero è visibile;
* se l’albero è nascosto, la ricerca è temporaneamente non disponibile.

## 10) Filtra per nome
Mostra solo i nodi che corrispondono al filtro e i loro genitori. Aggiornamento con debounce.
* Ctrl+Shift+N — mostra/nascondi filtro
* Esc — chiudi filtro

Limitazioni:
* all’apertura del filtro, la ricerca si chiude automaticamente;
* il filtro è disponibile in anteprima finché il pannello dell’albero è visibile;
* se l’albero è nascosto, il filtro è temporaneamente non disponibile.

## 11) Opzioni
A destra sono disponibili:
* Applica
* Ignora
* Tipi di file
* Cartelle di primo livello

Le modifiche in « Ignora », « Tipi di file » e « Cartelle di primo livello » vengono preparate nel pannello e applicate dopo aver premuto « Applica ».

Ogni lista ha il toggle Tutti.

Nota su « Tipi di file »:
* in questa lista vengono mostrati solo file con estensione;
* i file senza estensione non vengono aggiunti a questa lista e sono gestiti da un’opzione separata in « Ignora ».

Ctrl+P — mostra/nascondi pannello.

### 11.1 Profili dei parametri dei progetti locali
Per le cartelle locali, DevProjex memorizza gli ultimi parametri di progetto applicati:
* cartelle di primo livello selezionate;
* tipi di file selezionati;
* opzioni selezionate nel blocco «Ignora».

Il salvataggio avviene quando fai clic su «Applica».
Quando si riapre la stessa cartella locale, i parametri vengono ripristinati automaticamente.

Importante:
* i profili vengono salvati solo per i progetti locali;
* per i progetti aperti tramite Git Clone, i profili non vengono salvati;
* se alcune opzioni salvate non sono più disponibili nel progetto corrente, vengono ignorate e gli altri parametri vengono applicati.
* se l’aggiornamento o la riapertura mostra una nuova cartella di primo livello, un nuovo tipo di file o una nuova opzione in « Ignora », quel punto viene attivato per impostazione predefinita;
* i punti già noti mantengono la scelta esplicita dell’utente: nuovi file di un tipo disattivato non riattivano quel tipo.

## 12) Ignora
L’elenco « Ignora » viene generato automaticamente in base al percorso corrente e alle cartelle di primo livello selezionate.

Ordine delle opzioni:
* Smart ignore (se disponibile)
* Usa .gitignore (se viene trovato almeno un `.gitignore`)
* Cartelle vuote
* File vuoti
* Cartelle nascoste
* File nascosti
* Cartelle con punto iniziale
* File con punto iniziale
* File senza estensione

Le opzioni delle regole base (nascosti, con punto, vuoti, senza estensione) vengono mostrate solo se esistono elementi corrispondenti.
Quando un’opzione in « Ignora » diventa disponibile per la prima volta, viene attivata per impostazione predefinita. Un’opzione disattivata esplicitamente in precedenza mantiene quello stato quando torna disponibile.

La linea sotto « Usa .gitignore » separa le regole Git/Smart dalle regole base di visibilità.

### 12.1 Ambito delle regole
L’app costruisce ambiti di progetto (scope) in cui applicare le regole di ignore:
* radice (se la radice contiene `.gitignore` o un marker di progetto)
* cartelle di primo livello
* sottocartelle di progetto annidate

La ricerca degli ambiti di progetto annidati è limitata e dipende dalla struttura della cartella.
Per i progetti normali viene usata una ricerca poco profonda. Nei monorepo riconosciuti la ricerca può essere più profonda.
Le cartelle di sistema, le dipendenze e gli artefatti di build confermati vengono ignorati durante la ricerca degli ambiti.

Questo limite riguarda solo la scoperta degli ambiti annidati per `.gitignore` e Smart Ignore. Una volta trovato un ambito, le regole vengono applicate al suo contenuto tramite la normale scansione dell’albero.

### 12.2 « Usa .gitignore »
* Attivo: le regole `.gitignore` sono applicate negli ambiti rilevati.
* Disattivo: le regole `.gitignore` sono completamente disattivate.

Nelle cartelle multi-progetto, il `.gitignore` di un progetto non si applica ai progetti vicini fuori dal suo ambito.

### 12.3 « Smart ignore »
* Viene mostrato solo quando può modificare l’albero risultante.
* Attivo: nasconde anche i tipici artefatti di build, le cache degli strumenti e gli archivi delle dipendenze.
* Disattivo: le regole smart non vengono applicate.

Una cartella non viene ignorata solo per il suo nome.
Per nomi comuni come `build`, `vendor`, `packages`, `cache`, `pkg` o `Library` viene controllato anche il contenuto.
Se la cartella contiene normali file sorgente, rimane visibile.

Smart Ignore considera la struttura di ogni progetto rilevato e opera separatamente nel relativo ambito.

### 12.4 Regole base
Opzioni:
* Cartelle nascoste
* File nascosti
* Cartelle con punto iniziale
* File con punto iniziale
* Cartelle vuote
* File vuoti
* File senza estensione

Quando un’opzione è attiva, nasconde gli elementi corrispondenti nell’albero e nei risultati di copia/esportazione.
Le regole di base vengono attivate separatamente da `.gitignore` e Smart Ignore, ma il risultato finale viene sempre calcolato sull’albero corrente dopo l’applicazione di tutti i filtri attivi.

### 12.5 Comportamento interno: casi tipici
1. Progetto singolo con `.gitignore`.
Di norma viene mostrato solo « Usa .gitignore ».
Quando è attivo, `.gitignore` e Smart Ignore lavorano insieme.
Quando è disattivo, entrambi vengono disattivati.

2. Progetto singolo senza `.gitignore`.
« Usa .gitignore » non viene mostrato.
« Smart ignore » viene mostrato solo se può influire sull’albero corrente.

3. Workspace multi-progetto, alcuni progetti con `.gitignore`, altri senza.
Vengono mostrati « Usa .gitignore » e « Smart ignore ».
`.gitignore` opera nel proprio ambito.
Smart Ignore (se attivo) completa il filtraggio negli ambiti rilevati.

4. Workspace multi-progetto, tutti i progetti hanno `.gitignore`.
Viene mostrato « Usa .gitignore ».
« Smart ignore » non viene mostrato come opzione separata.

5. Cartella senza regole applicabili.
Se non viene trovato `.gitignore` e Smart Ignore non influisce sull’albero, queste opzioni non vengono mostrate.
Restano solo le regole base di visibilità.

### 12.6 Cartelle vuote
Nasconde le cartelle logicamente vuote dall’albero e dai risultati di copia/esportazione.
Una cartella logicamente vuota è una cartella nella quale non restano discendenti visibili dopo l’applicazione delle regole di visibilità correnti, di `.gitignore`, di Smart Ignore e dei tipi di file selezionati.
Se la cartella stessa non è nascosta da altre regole, la sua rimozione dall’albero è controllata proprio da questa opzione.

### 12.7 File vuoti
Nasconde i file vuoti di dimensione 0 byte dall’albero e dai risultati di copia/esportazione.

### 12.8 File senza estensione
Nasconde i file senza estensione (ad esempio: `Dockerfile`, `Makefile`, `README`) dall’albero e dai risultati di copia/esportazione.

### 12.9 Contatori nel blocco « Ignora »
Vicino alle opzioni disponibili viene mostrato il numero nel formato `(N)`.
Per le regole di base, questo numero mostra quanti elementi vengono nascosti proprio da quella regola nella configurazione corrente dell’albero.
## 13) Come vengono calcolati albero e metriche
Il risultato dipende da:
* cartelle di primo livello selezionate
* tipi di file selezionati
* regole di esclusione
* filtro attivo
* nodi selezionati con checkbox nell’albero (per operazioni basate sulla selezione)

Se l’accesso è negato, il nodo è marcato Accesso negato.

### 13.1 Cosa mostrano i contatori nella barra di stato
La barra di stato contiene due blocchi:
* Albero — metriche dell’output testuale dell’albero;
* Contenuto — metriche dell’output contenuti file.

Formato:
* Righe
* Caratteri
* ~Token (stima)

I valori grandi sono mostrati in formato compatto (K/M).

Importante:
* « Righe » nel blocco « Albero » indica il numero di righe della rappresentazione finale dell’albero, non il numero di file su disco;
* in questo valore rientrano cartelle, file ed elementi di servizio dell’albero (ad esempio nodi con accesso negato).

### 13.2 Come vengono calcolate le metriche
Metriche albero:
* sono calcolate dall’output reale dell’albero generato dalla stessa pipeline di export;
* rispettano il formato albero corrente.

Metriche contenuto:
* seguono le stesse regole della copia/export contenuto;
* i file binari sono esclusi;
* file vuoti e solo spazi sono conteggiati tramite marker di servizio (`[No Content, 0 bytes]`, `[Whitespace, N bytes]`).

### 13.3 Quando i contatori vengono aggiornati
Il ricalcolo avviene:
* dopo apertura/aggiornamento progetto;
* dopo applicazione impostazioni (ignore, tipi file, cartelle root);
* quando cambiano le checkbox nell’albero (con debounce);
* quando si cambia formato albero (per operazioni che usano l’albero).
* quando il calcolo in background viene annullato, i contatori vengono impostati a 0 fino al successivo ricalcolo completato.

## 14) Icone
Ordine di scelta:
1) tipo nodo (cartella/file)
2) nome esatto (se esiste una regola)
3) estensione
4) altrimenti — sconosciuto

## 15) Tema ed effetti
Il popover del tema permette di scegliere:
* tema chiaro/scuro
* Trasparente / Mica / Acrylic
* intensità, blur, contrasto, bordi

Gli elementi [Beta] possono cambiare tra versioni.

## 16) Aiuto

### 16.1 Ripristina impostazioni
Ripristina impostazioni (Aiuto → Ripristina impostazioni) reimposta solo i parametri visivi dell’interfaccia (tema, effetti, modalità compatta, animazione albero) e non modifica i dati del progetto.
Questa azione azzera anche la lingua dell’interfaccia salvata.

### 16.2 Ripristina dati
Ripristina dati (Aiuto → Ripristina dati) rimuove i profili salvati dei parametri dei progetti locali:
* cartelle di primo livello selezionate;
* tipi di file selezionati;
* opzioni selezionate nel blocco «Ignora».

Importante:
* la cronologia «Recenti» delle cartelle locali non viene cancellata;
* la cronologia dei «Repository recenti» nella finestra Git Clone non viene cancellata;
* file e cartelle dei progetti sul disco non vengono modificati né eliminati.

## 17) Lingue
La lingua si seleziona dal menu Lingua.
La lingua scelta viene salvata tra gli avvii dell’app. « Aiuto → Ripristina impostazioni » cancella la lingua salvata e riporta l’interfaccia alla lingua predefinita.

## 18) Barra di avanzamento e annullamento
Nella parte centrale della barra di stato vengono mostrati operazione attiva e progresso.

Modalità progresso:
* Indeterminate — senza percentuale (durata sconosciuta).
* Determinate — con percentuale (0–100).

Comportamento:
* durante il calcolo dati in background viene mostrata la percentuale;
* per alcune operazioni Git la percentuale viene mostrata se la sorgente la fornisce;
* l’aggiornamento delle opzioni disponibili e l’applicazione delle impostazioni vengono mostrati se l’operazione richiede un tempo percepibile;
* le operazioni rapide terminano senza mostrare il progresso.

Pulsante X (annulla) nella barra di stato:
* esegue annullamento best-effort per operazioni che supportano l’annullamento;
* interrompe il calcolo dati in background;
* per operazioni senza supporto annullamento, ferma l’indicazione nella barra di stato, mentre l’operazione può comunque terminare in background.

## 19) Note
* Per impostazione predefinita, tema scuro ed effetti di trasparenza sono attivi (se supportati).
* Se i permessi non bastano, l’app può proporre il riavvio con privilegi elevati; in caso di rifiuto viene mostrato un avviso.
