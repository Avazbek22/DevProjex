## 1) Cos’è e a cosa serve
DevProjex prepara rapidamente il contesto del progetto: mostra la struttura di cartelle/file, permette di selezionare gli elementi e copiare l’albero e/o il contenuto dei file negli appunti. Utile per code review, supporto, formazione e condivisione della struttura con un assistente IA.

Importante: DevProjex non modifica i file del progetto aperto. L’unica eccezione è una connessione MCP esplicita per Cursor o VS Code, che crea o aggiorna `.cursor/mcp.json` o `.vscode/mcp.json` (sezione 19.1).

## 2) Albero del progetto
* Icone per tipo file/cartella.
* Checkbox sui nodi.
* Espandi/riduci.

Checkbox: la selezione di un nodo si applica ai figli; lo stato dei genitori è ricalcolato automaticamente.

Scorciatoie:
* {mod}E — espandi tutto
* {collapseAll} — comprimi tutto (la radice resta aperta)

### Menu contestuale
Clic destro su un nodo — oppure {shift}F10 / tasto Menu sul nodo selezionato:
* Mostra in Esplora file / Mostra nel Finder / Apri nel gestore file — mostra l’elemento nel gestore file di sistema; l’etichetta dipende dalla piattaforma.
* Copia percorso completo — il percorso assoluto dell’elemento.
* Copia percorso relativo — il percorso dalla radice del progetto, che inizia con il nome della cartella radice, ad esempio `project/src/File.cs`.
* Copia contenuto — per i file: copia il contenuto con le trasformazioni applicate, esattamente come copia ed esportazione.
* Seleziona solo questo elemento — spunta solo questo nodo e azzera il resto della selezione; appare solo finché è spuntato anche un altro elemento.
* Espandi ramo / Comprimi ramo — per le cartelle.

Se il percorso non esiste più sul disco, l’apertura nel gestore file e la copia del contenuto mostrano un messaggio di errore; la copia dei percorsi continua a funzionare.

## 3) File
* Apri cartella… — apri la cartella radice ({mod}O)
* Nuova finestra — apri una nuova istanza indipendente di DevProjex
* Recenti — elenco delle cartelle locali aperte di recente
* Aggiorna — rileggi una cartella locale e ricostruisci l’albero (F5)
* Esporta in file:
  * Esporta albero
  * Esporta contenuto
  * Esporta albero e contenuto
* Esporta progetto:
  * In una cartella…
  * In un archivio ZIP…

L’esportazione del progetto crea una cartella separata o un archivio ZIP dall’albero corrente, mantenendo la struttura delle directory.

Vengono rispettati i tipi di file, le regole di esclusione e gli elementi selezionati. Se non è selezionato nulla, viene esportato l’intero albero corrente.

Vengono copiati i file di testo e binari e conservate le cartelle vuote incluse. I file di origine non vengono modificati. Il risultato non può essere salvato all’interno del progetto di origine.

Durante l’esportazione non è possibile modificare l’albero o le impostazioni, usare il filtro, cambiare formato o modalità di anteprima, eseguire comandi Git, aggiornare o aprire un altro progetto.

Regole di formato:
* Esporta albero:
  * ASCII -> solo `.txt`.
  * JSON -> predefinito `.json`, con `.json` e `.txt` disponibili nella finestra di salvataggio.
  * XML -> predefinito `.xml`, con `.xml` e `.txt` disponibili nella finestra di salvataggio.
  * MD -> predefinito `.md`, con `.md` e `.txt` disponibili nella finestra di salvataggio.
* Esporta contenuto — sempre formato testo del contenuto, file `.txt` (il selettore formato albero non influisce).
* Esporta albero e contenuto — sempre file `.txt`; il formato albero selezionato influisce solo sul formato del blocco albero nel risultato.

I file esportati vengono scritti in UTF-8 senza BOM.

### Drag & Drop
Il drag & drop funziona nell’area iniziale (Drop Zone) quando nessun progetto è caricato.

Regole:
* puoi trascinare una cartella;
* puoi trascinare un file — in questo caso viene aperta la cartella che lo contiene;
* se vengono trascinati più elementi, viene usato il primo percorso locale valido;
* se un percorso non è disponibile o non esiste, vengono applicati gli stessi controlli di accesso di «Apri cartella…»;
* gli elementi non supportati o non locali vengono ignorati.

### Recenti
La voce «File → Recenti» mostra la cronologia delle cartelle locali aperte di recente.

Regole:
* nell’elenco vengono aggiunte solo cartelle locali;
* i repository Git clonati tramite DevProjex non vengono aggiunti a questo elenco;
* non vengono creati duplicati — riaprire la stessa cartella la sposta in cima;
* vengono conservate fino a 32 cartelle recenti;
* la cronologia viene mantenuta tra gli avvii dell’applicazione.

Per ogni elemento vengono mostrati la cartella padre e il nome del progetto, ad esempio `Projects / App`.

## 4) Avvio dal terminale
DevProjex offre un’area di lavoro interattiva nel terminale e comandi diretti per script e CI.

Se il comando è già configurato, apri un terminale ed esegui:
`devprojex --help`

Così vedrai i comandi e le opzioni di primo livello. Le opzioni e gli esempi di un singolo comando si mostrano con `devprojex help <command>`.

Esempi:
* `devprojex` — aprire l’area di lavoro interattiva del terminale. All’interno dell’area di lavoro, le azioni si eseguono tramite la riga di comando `:` (ad esempio `:copy`, `:analyze`, `:branch`, `:language`); l’elenco completo dei comandi è disponibile nella guida integrata dell’area di lavoro e nella documentazione del progetto.
* `devprojex tui .` — aprire la cartella indicata direttamente nell’area di lavoro del terminale.
* `devprojex open . --preview` — aprire la cartella corrente nell’anteprima Desktop.
* `devprojex analyze . --format json` — analizzare il progetto corrente in formato JSON.
* `devprojex tree .` — stampare l’albero del progetto nel terminale.
* `devprojex export context . --format markdown -o ../devprojex-context.md` — salvare un contesto pronto per l’IA fuori dal progetto sorgente.
* `devprojex export project . --as folder -o ../devprojex-submission` — esportare l’albero effettivo in una cartella esatta.
* `devprojex export project . --as zip -o ../devprojex-submission.zip` — esportare l’albero effettivo in un archivio ZIP.
* `devprojex export context https://github.com/owner/repo -o -` — impacchettare un repository remoto senza clonarlo manualmente.
* `devprojex analyze . --git-mode tracked --exclude smart-ignore` — analizzare i file tracciati da Git con Smart Ignore.
* `devprojex search Configure . --symbols` — trovare dove è definita una dichiarazione; `--symbols` accetta nomi di dichiarazioni e rifiuta la sintassi delle espressioni regolari, mentre `--regex` cerca il testo con un’espressione regolare.
* `devprojex related src/App.cs` — elencare i file usati da un file e i file che lo usano.
* `devprojex mcp --root .` — avviare il server MCP locale in sola lettura perché gli agenti IA leggano il progetto in sicurezza.
* `devprojex mcp connect . --client claude-code` — collegare un client IA al progetto (sezione 19).
* `devprojex mcp log . --last` — mostrare l’ultima sessione del registro dell’agente.

Note:
* `.` indica la cartella corrente del terminale;
* i percorsi con spazi devono essere racchiusi tra virgolette;
* `--git-mode` seleziona `none`, `gitignore`, `tracked`, `staged`, `changes` o `diff:<ref>..<ref>`;
* `--exclude` gestisce le esclusioni ordinarie separatamente dal filtro Git;
* i comandi di analisi ed esportazione sono deterministici e non aprono l’interfaccia grafica;
* `tui`, `open`, `analyze`, `search`, `tree` ed entrambi i comandi `export` accettano anche l’URL di un repository Git, e `related` lo accetta tramite `--project`; il clone finisce in una cache gestita (`devprojex cache`);
* i comandi hanno alias e forme brevi documentati, ad esempio `export ctx`, `-f`, `-n`; `devprojex help` li mostra;
* `analyze --findings` elenca i rilevamenti di mascheramento senza i loro valori, e `--fail-on-findings` restituisce un codice di uscita diverso da zero per la CI;
* `export context --max-tokens N` mantiene il contesto entro un budget di token, e l’opzione sperimentale `--rank importance` ammette per primi i file più importanti;
* i comandi di analisi, ricerca ed esportazione non modificano i file del progetto — DevProjex lavora in sola lettura.

Se il comando `devprojex` non funziona, apri in DevProjex:
«Aiuto → Avvia dal terminale».

## 5) Git
«Git → Clona repository…» clona un repository nella cache di DevProjex e lo apre. «Branch» e «Ottieni aggiornamenti» sono disponibili solo per i progetti clonati in questo modo. L’app non tocca i tuoi file — lavora solo con la cache.

La cache viene archiviata nella directory della cache dell’utente. `devprojex doctor` mostra il percorso effettivamente utilizzato.

* Branch — mostra l’elenco dei branch disponibili con indicazione di quello attivo; il cambio aggiorna l’albero al branch scelto. Se il branch esiste già in locale, il cambio è offline (senza aggiornamento). Se non esiste in locale, viene scaricato (fetch) e creato localmente.
* Ottieni aggiornamenti — aggiorna solo il branch corrente: fetch e reset a origin/<branch>. Per un progetto clonato, F5 esegue la stessa azione; il normale comando «File → Aggiorna» è disattivato.

### Finestra di clonazione
Nella finestra «Clona repository» può comparire sotto il campo URL un elenco «Collegamenti recenti».

Regole:
* l’elenco appare solo se nella cronologia esistono già repository clonati di recente;
* vengono aggiunte all’elenco solo le origini di repository di rete (`https://`, `ssh://` e la sintassi SCP);
* i percorsi locali e le origini `file://` non vengono aggiunti a questo elenco;
* non vengono creati duplicati — clonare di nuovo lo stesso repository lo sposta in cima;
* vengono conservati fino a 16 repository recenti;
* la cronologia viene mantenuta tra gli avvii dell’applicazione.

Se selezioni un elemento dall’elenco, l’URL viene inserito automaticamente nel campo di input.
Durante una clonazione attiva l’elenco viene nascosto temporaneamente.

## 6) Copia
### Selettore formato albero (ASCII / JSON / XML / MD)
Il selettore definisce il formato di rappresentazione dell’albero per le operazioni in cui l’albero fa parte del risultato.

* ASCII — albero testuale con rami.
* JSON — albero strutturato in JSON.
* XML — albero XML compatto per parser e strumenti.
* MD — lista Markdown annidata per documentazione e prompt IA.

Il selettore influisce su:
* Copia albero
* Copia albero + contenuto
* Esporta albero
* Esporta albero e contenuto

Il selettore non influisce su:
* Copia contenuto
* Esporta contenuto

### Copia albero
Copia l’albero del progetto.
Se ci sono nodi selezionati, l’albero è costruito dalla selezione; se la selezione è vuota o non valida, viene copiato l’albero completo.
Il formato del risultato è definito dal selettore formato albero.
Scorciatoie: {mod}{shift}C e {mod}{alt}C.

### Copia contenuto
Copia il contenuto dei file:
* se ci sono file selezionati — solo quelli; altrimenti — tutti i file del progetto;
* ogni file è preceduto da un’intestazione con il suo percorso locale completo (per i progetti clonati — il percorso web del repository);
* i file non testuali vengono ignorati (inclusi i binari);
* per i file di testo vuoti vengono riportati il percorso e la riga `[No Content, 0 bytes]`;
* per i file composti solo da spazi/ritorni a capo vengono riportati il percorso e la riga `[Whitespace, N bytes]`.
Scorciatoia: {mod}{alt}V.

### Copia albero + contenuto
Combina albero e contenuto:
* albero dalla selezione; se la selezione è vuota o non valida, viene usato l’albero completo;
* contenuto secondo le stesse regole di «Copia contenuto»;
* il formato del blocco albero è definito dal selettore formato albero.
Scorciatoia: {mod}{shift}V.

### Rappresentazioni dell’albero
I formati albero rappresentano in modi diversi lo stesso albero di progetto selezionato.

JSON:
* `rootPath` — percorso radice assoluto normalizzato con `/`.
* `tree` — contenuto della cartella radice.
* L’export JSON usa questo formato albero: gli array contengono i file, gli oggetti contengono le sottocartelle, `/` contiene i file della cartella corrente e `[]` rappresenta una cartella vuota.

XML:
* il nodo radice è `<t r="...">`;
* le cartelle sono `<d n="...">`;
* i file sono `<f>File.cs</f>`.

MD:
* inizia con `Root: ...`;
* usa una lista Markdown annidata;
* le cartelle terminano con `/`.

Albero + contenuto:
* il formato albero selezionato si applica al blocco albero;
* il blocco contenuto resta testuale;
* le intestazioni dei file nel blocco contenuto usano percorsi relativi con `/`;
* esportazione in `.txt`.

## 7) Modalità anteprima
Si apre con il pulsante con icona a forma di occhio nella barra superiore o con {mod}B.

I pulsanti laterali del mouse seguono la navigazione del browser: Avanti apre la modalità anteprima, Indietro la chiude. Ripetere la direzione già attiva non produce effetti.

{mod}{shift}F apre o chiude la ricerca nel contenuto dei file dell’anteprima. Enter o F3 passa al risultato successivo; {shift}Enter o {shift}F3 a quello precedente.

Mostra il risultato finale in un’area di lavoro separata accanto all’albero. Questa modalità non copia nulla negli appunti e non esporta nulla su file: serve solo per la visualizzazione.

Per impostazione predefinita l’area di lavoro si apre così:
* a sinistra — albero del progetto;
* al centro — pannello di anteprima;
* a destra — pannello delle impostazioni, se era aperto.

Modalità disponibili:
* Albero
* Contenuto
* Albero e contenuto

Si applicano le stesse regole della copia e dell’esportazione:
* i nodi selezionati vengono considerati;
* se la selezione è vuota, viene usato il set completo dei dati;
* vengono applicate le regole di esclusione e i parametri di selezione correnti.

Inoltre:
* i file nell’anteprima sono separati da linee orizzontali;
* durante lo scorrimento, il percorso del file corrente resta fissato in alto; un clic sul percorso fissato scorre all’inizio di quel file;
* la barra di scorrimento dell’anteprima marca le corrispondenze di ricerca e le righe con valori rilevati; un clic su un segno salta alla sua riga; un valore conservato resta marcato, e i percorsi mascherati nelle intestazioni danno un solo segno alla loro prima riga;
* lo zoom dell’albero e quello dell’anteprima possono essere regolati separatamente;
* nella modalità anteprima puoi copiare sia il risultato completo corrente sia il blocco del file attualmente visibile senza aprire il menu «Copia».

Pulsanti:
* pulsante di copia a sinistra nel pannello superiore di anteprima — copia la modalità di anteprima corrente:
  * Albero
  * Contenuto
  * Albero e contenuto
* X nel pannello dell’albero — nasconde l’albero e lascia solo il pannello di anteprima;
* X nella barra superiore dell’anteprima — chiude completamente la modalità anteprima;
* piccolo pulsante di copia nell’intestazione fissata del file — copia il blocco del file attualmente visibile esattamente come appare nell’anteprima;
* anche premere di nuovo l’icona occhio o {mod}B chiude la modalità anteprima.

Ricerca e filtro restano disponibili finché nell’anteprima è visibile il pannello dell’albero.
Se l’albero è nascosto, ricerca e filtro diventano temporaneamente non disponibili fino all’uscita dalla modalità solo anteprima.

## 8) Visualizza
### Zoom
* {mod}+ / {mod}= — zoom avanti
* {mod}- — zoom indietro
* {mod}0 — reimposta
* {mod}rotellina — zoom fluido nel pannello sotto il cursore

Comportamento:
* in modalità normale viene scalato l’albero;
* in anteprima con l’albero visibile, Zoom avanti, Zoom indietro e Reimposta zoom dal menu si applicano contemporaneamente all’albero e all’anteprima;
* con {mod}rotellina, albero e anteprima scalano in modo indipendente in base alla posizione del cursore;
* in modalità solo anteprima viene scalato solo il pannello di anteprima.

Intervallo: 6–28, ripristino: 15.

### Modalità compatta
Rende l’interfaccia più densa: spazi più piccoli nell’albero e nelle impostazioni.
Quando l’area di lavoro di anteprima è attiva, la modalità compatta viene abilitata automaticamente.

### Animazioni
«Visualizza → Animazioni» consente di controllare separatamente l’espansione dell’albero, i contatori di stato e la comparsa iniziale degli strumenti. Tutte e tre le animazioni sono attive per impostazione predefinita; disattivandone una, viene mostrato subito il suo stato finale.

### Font albero
Il font dell’albero si sceglie da «Visualizza → Font albero».
«Predefinito» ripristina il font standard dell’albero.
Il font scelto viene applicato dopo aver premuto «Applica» nel pannello impostazioni.

### Attività dell’agente
Attiva «Visualizza → Attività dell’agente» per vedere quali file ha ricevuto un agente IA durante una sessione live: nell’albero sono contrassegnati con ✦ (sezione 19.4).

## 9) Ricerca nell’albero
Apre la ricerca, evidenzia le corrispondenze e permette la navigazione.
* {mod}F — mostra/nascondi
* Enter — risultato successivo
* {shift}Enter — precedente
* Esc — chiudi

La ricerca apre solo i rami necessari; svuotando la query l’albero si richiude (tranne la radice).
Le righe delle corrispondenze sono marcate anche sulla barra di scorrimento dell’albero; un clic su un segno salta a quella corrispondenza.
Con un numero molto elevato di corrispondenze, l’app può limitare l’espansione automatica e l’evidenziazione globale per mantenere l’interfaccia reattiva.
Alla chiusura della ricerca, la query viene svuotata dopo il completamento dell’animazione di chiusura.

Limitazioni:
* all’apertura della ricerca, il filtro si chiude automaticamente;
* la ricerca è disponibile in anteprima finché il pannello dell’albero è visibile;
* se l’albero è nascosto, la ricerca è temporaneamente non disponibile.

## 10) Filtra per nome
Mostra solo i nodi che corrispondono al filtro e i loro genitori. Aggiornamento con debounce.
* {mod}{shift}N — mostra/nascondi filtro
* Esc — chiudi filtro

Limitazioni:
* all’apertura del filtro, la ricerca si chiude automaticamente;
* il filtro è disponibile in anteprima finché il pannello dell’albero è visibile;
* se l’albero è nascosto, il filtro è temporaneamente non disponibile.

## 11) Opzioni
A destra sono disponibili:
* Applica
* Elaborazione contenuti
* Esclusioni
* Tipi di file

Le modifiche in «Esclusioni» e «Tipi di file» vengono preparate nel pannello e applicate dopo aver premuto «Applica».

Dopo la modifica di una casella, l’app può aggiornare in background le opzioni disponibili e i relativi contatori. L’albero risultante viene ricostruito solo dopo aver premuto «Applica».

Se l’aggiornamento delle opzioni disponibili viene annullato con il pulsante X nella barra di stato, le modifiche incomplete non vengono applicate e il pannello torna all’ultimo stato completato.

Ogni lista ha il selettore Tutti.

Nota su «Tipi di file»:
* in questa lista vengono mostrati solo file con estensione;
* i file senza estensione non vengono aggiunti a questa lista e sono gestiti da un’opzione separata in «Esclusioni».

Elaborazione contenuti:
* questa sezione trasforma il contenuto dei file di testo selezionati senza modificare l’albero;
* «Nascondi segreti» e «Nascondi dati privati» sostituiscono i valori rilevati (sezioni 12.3 e 12.4);
* «Comprimi il codice» conserva le dichiarazioni e accorcia le implementazioni con nome in 14 linguaggi;
* «Rimuovi commenti» elimina i commenti e i commenti di documentazione in 20 pacchetti di linguaggi;
* «Rimuovi righe vuote» elimina le righe di soli spazi negli stessi pacchetti preservando i letterali multilinea;
* le modifiche hanno effetto dopo «Applica».

{mod}P — mostra/nascondi pannello.

### 11.1 Profili dei parametri dei progetti locali
Per le cartelle locali, DevProjex memorizza gli ultimi parametri di progetto applicati:
* tipi di file selezionati;
* opzioni selezionate nella sezione «Esclusioni».

Il salvataggio avviene quando fai clic su «Applica».
Quando si riapre la stessa cartella locale, i parametri vengono ripristinati automaticamente.

Importante:
* i profili vengono salvati solo per i progetti locali;
* per i progetti aperti tramite «Clona repository», i profili non vengono salvati;
* se alcune opzioni salvate non sono più disponibili nel progetto corrente, vengono ignorate e gli altri parametri vengono applicati;
* se l’aggiornamento o la riapertura mostra un nuovo tipo di file o una nuova opzione in «Esclusioni», quel punto viene attivato per impostazione predefinita;
* i punti già noti mantengono la scelta esplicita dell’utente: nuovi file di un tipo disattivato non riattivano quel tipo.

## 12) Esclusioni
La sezione «Esclusioni» controlla quali file e cartelle vengono esclusi dall’albero, dal contenuto, dalla copia e dall’esportazione.

Un elemento viene mostrato solo quando sono soddisfatte tutte queste condizioni:
* il suo tipo di file è selezionato, se il file ha un tipo;
* nessuna regola di esclusione attiva lo esclude.

Le regole di esclusione si sommano. Se almeno una regola attiva nasconde un elemento, un’altra regola non può renderlo visibile.

### 12.1 Regole disponibili
A seconda del contenuto del progetto possono comparire le seguenti opzioni:

* Smart Ignore
* Cartelle vuote
* File vuoti
* Cartelle nascoste
* File nascosti
* Cartelle con punto iniziale
* File con punto iniziale
* File senza estensione

Il selettore della GUI e le righe radio dell’asse Git nella TUI vengono nascosti completamente quando il filtro Git non è applicabile: non esiste un confine di repository e il filtro `.gitignore` non può modificare l’albero corrente. Quando l’asse è visibile fuori da un repository, la GUI offre solo nessun filtro e `.gitignore`, mentre la TUI disabilita le righe che richiedono un repository. In un repository Git sono disponibili i cinque valori normali: nessun filtro, `.gitignore`, file tracciati, file in staging e tutte le modifiche correnti; nella TUI, un ambito `diff:<ref>..<ref>` attivo compare come sesta riga. La scelta di un valore sostituisce la modalità Git corrente senza modificare Smart Ignore o le esclusioni di base. Le altre opzioni compaiono quando le relative regole possono cambiare l’albero corrente, quindi l’elenco può cambiare dopo aver modificato un’altra regola o un tipo di file.

Una nuova opzione è attiva per impostazione predefinita alla prima comparsa. Un’opzione già nota conserva la scelta dell’utente anche se scompare temporaneamente dall’elenco.

### 12.2 Smart Ignore
Smart Ignore nasconde dipendenze, risultati di build, cache e altri artefatti di servizio del progetto.

DevProjex identifica prima il tipo di progetto dalla sua struttura e dai file marker, ad esempio:

* `.csproj`
* `package.json`
* `pyproject.toml`
* `Cargo.toml`

Le regole dello stack corrispondente vengono quindi applicate all’interno dell’area del progetto rilevato. Ad esempio, le regole .NET non si estendono a un progetto Python o JavaScript vicino.

Il solo nome di una cartella non sempre basta. I nomi ambigui come `build`, `vendor`, `packages`, `cache`, `pkg` o `Library` vengono verificati anche in base al contenuto. In questo modo una normale cartella dell’utente non viene nascosta solo perché ha un nome simile.

Alcuni archivi di dipendenze e directory di servizio possono essere riconosciuti dalla loro struttura interna caratteristica anche fuori da un progetto rilevato esplicitamente.

La ricerca delle aree di progetto è limitata, così che il caricamento di una grande cartella utente non diventi un’analisi completa e ripetuta di ogni directory. Le strutture normali usano una ricerca poco profonda, mentre i monorepo riconosciuti vengono esaminati più in profondità. Dopo aver trovato un’area, Smart Ignore si applica all’intero sottoalbero senza limite di profondità.

### 12.3 Nascondi segreti
«Nascondi segreti» è disattivato per impostazione predefinita. Analizza solo il testo selezionato e sostituisce ogni valore rilevato sul posto, conservando il file e il codice circostante. Quando è disattivato non viene eseguita alcuna scansione e non appare alcun contatore. Dopo la scansione della selezione corrente, l’etichetta mostra il numero di valori rilevati; se le decisioni «conserva» lasciano meno valori nascosti, mostra rilevati/nascosti, e l’indicatore ? della riga riporta entrambi i numeri.

I valori mascherati sono evidenziati nell’anteprima. Fai clic su uno di essi per conservare invariata solo quell’occorrenza; {alt}↓ / {alt}↑ scorrono i valori rilevati e Enter attiva o disattiva quello corrente. Nell’area di lavoro del terminale, `[` e `]` scorrono le occorrenze e `Enter` o `Space` attivano o disattivano quella corrente. La decisione vale per la sessione in anteprima, appunti, esportazione del contesto, copia in cartella e ZIP; non viene salvata nel profilo del progetto.

Il menu contestuale dell’anteprima estende queste decisioni. Un clic destro su un’occorrenza rilevata consente di conservare — o nascondere di nuovo — in un’unica azione tutte le occorrenze della sua regola oppure tutte le occorrenze rilevate nello stesso file. Un clic destro su un valore selezionato nel contenuto di un file aggiunge un contrassegno manuale: «Nascondi … qui» nasconde solo quell’occorrenza per la sessione, «Nascondi sempre …» crea un contrassegno persistente per tutte le occorrenze del valore, e «Nascondi … come dato privato» crea un contrassegno persistente controllato da «Nascondi dati privati». «Rimuovi contrassegno» appare su un contrassegno manuale e lo elimina; un valore ancora riconosciuto dal rilevatore resta nascosto. Il valore manuale deve essere una singola riga da 8 a 512 caratteri selezionata nel contenuto del file. La creazione di un contrassegno attiva automaticamente l’opzione corrispondente. I contrassegni persistenti conservano solo un’identità del valore con chiave e la sua classe, mai il testo originale.

Anche una copia in cartella o ZIP modifica il testo corrispondente e potrebbe non compilarsi o avviarsi. I file binari vengono copiati senza modifiche e non vengono analizzati. Un file di testo selezionato oltre 16 MiB viene omesso e segnalato, mentre il resto dell’output viene completato. Un errore di rilevamento interrompe l’intera operazione.

Il contatore segnala soltanto le corrispondenze con le regole. Zero non significa che il progetto sia sicuro. La CLI usa `--hide-secrets`; i dettagli tecnici e i limiti sono in `Docs/HideSecrets.md`.

### 12.4 Nascondi dati privati
«Nascondi dati privati» è disattivato per impostazione predefinita. Rileva indirizzi e-mail, indirizzi IP globali, nomi utente locali nei percorsi, indirizzi MAC e numeri di telefono internazionali nei file di testo selezionati. I risultati usano le stesse decisioni dell’anteprima e la stessa pipeline di output di «Nascondi segreti»; i contrassegni manuali creati con «Nascondi … come dato privato» appartengono a questa classe e seguono questa opzione (sezione 12.3). I nomi utente locali nelle intestazioni dei percorsi generati e nella radice dell’albero sono mascherati come un’unica rilevazione condivisa: il contatore la conta come un valore, l’indicatore ? riporta se è nascosta o visibile, e un clic commuta tutti i percorsi mascherati insieme.

Gli intervalli e gli host di documentazione, i comuni utenti CI, i resolver DNS pubblici noti e gli intervalli di numeri fittizi documentati rimangono visibili. Zero corrispondenze non garantisce la riservatezza. La CLI usa `--hide-private-data`; le regole complete e i limiti della prima fase sono in `Docs/HidePrivateData.md`.

### 12.5 Usa .gitignore
Quando l’opzione è attiva, DevProjex segue la vista dell’albero di lavoro di `git status`: i file tracciati restano visibili e i file non tracciati vengono mostrati, a meno che le regole di esclusione del repository non li escludano. DevProjex applica ogni `.gitignore` raggiungibile, non solo il file nella radice della cartella aperta, inclusi i file sopra di essa fino alla radice del repository.

Ogni `.gitignore` si applica:

* alla cartella che lo contiene;
* a tutte le cartelle accessibili sottostanti;
* solo all’interno di quell’area.

Le regole di un `.gitignore` annidato non influiscono sulle cartelle superiori o adiacenti.

Per un percorso, le regole vengono elaborate dal `.gitignore` padre verso i file più profondi. All’interno di un file, le regole vengono elaborate dall’alto verso il basso. L’ultima regola corrispondente determina il risultato Git.

Una regola che inizia con `!` annulla una precedente esclusione Git solo nella propria area. Non può ripristinare un file finché la cartella padre rimane esclusa. Un `.gitignore` dentro una cartella completamente esclusa e irraggiungibile non partecipa alla valutazione.

Una riga errata o non supportata viene ignorata singolarmente. Le altre regole valide di quel file e le regole delle aree vicine continuano a funzionare.

Viene applicato anche il file `.git/info/exclude` locale del repository, con priorità inferiore rispetto al `.gitignore` della radice. Anche una cartella annidata con un proprio `.git` segue `git status`: un repository incorporato non dichiarato in `.gitmodules` è opaco, quindi i suoi file non vengono mostrati, mentre un sottomodulo dichiarato applica i propri `.gitignore` e `info/exclude`. Seleziona `none` per vedere i file dei repository incorporati. Le regole di esclusione Git globali (`core.excludesFile`) non vengono applicate; vengono rispettate le impostazioni effettive del repository per il confronto dei percorsi, come `core.ignoreCase` e, su macOS, `core.precomposeUnicode`. Un collegamento simbolico denominato `.gitignore` non viene seguito, in conformità al comportamento di Git per questo file di controllo. Se un file `.gitignore` o `info/exclude` non può essere letto, l’ambito della sua directory viene escluso in modo sicuro e la scansione segnala un accesso parziale invece di includere silenziosamente file senza valutare tutte le regole. Se è disponibile un indice Git leggibile per l’ambito del repository proprietario del percorso, i file tracciati restano visibili anche quando corrispondono a `.gitignore`; senza tale indice o la CLI di Git, quell’ambito torna in modo sicuro alla sola valutazione dei pattern.

Il profilo integrato `standard` seleziona `gitignore` insieme a `smart-ignore`, `hidden-folders`, `hidden-files`, `dot-folders`, `dot-files`, `empty-folders`, `empty-files` e `extensionless-files`.

### 12.6 Solo file tracciati da Git
«Solo file tracciati da Git» costruisce la fase Git dell’albero dai file esistenti nell’albero di lavoro registrati in ogni indice Git leggibile. I file tracciati modificati e i nuovi file aggiunti all’indice restano inclusi; i file non tracciati vengono esclusi. Questo è l’albero di lavoro corrente, non un’istantanea storica di `HEAD` o di un repository remoto.

Ogni repository viene risolto in modo indipendente: i repository adiacenti nella cartella aperta e i sottomoduli dichiarati usano ciascuno il proprio indice, e un repository figlio non eredita i percorsi tracciati dal repository padre o da uno adiacente. Un repository incorporato non dichiarato in `.gitmodules` resta opaco, come nella modalità `.gitignore`. Questa modalità richiede la CLI di Git; un indice vuoto ma leggibile è valido. Se l’area di lavoro del terminale (TUI) viene avviata in questa modalità e non è possibile caricare alcun indice applicabile, l’area di lavoro non viene aperta. Se la modalità viene selezionata interattivamente in un’area di lavoro TUI già aperta e non è possibile caricare alcun indice applicabile, la modifica viene rifiutata e resta attiva l’ultima modalità Git utilizzabile. Nella stessa situazione, i comandi diretti terminano con un errore di criterio o di verifica. DevProjex non passa mai silenziosamente a `.gitignore`. Quando è leggibile un altro indice applicabile, gli ambiti annidati non disponibili vengono esclusi con un avviso.

In un’area di lavoro Desktop già aperta, la selezione esplicita resta visibile e fallisce in modo sicuro: output ed esportazione vengono bloccati se la verifica non riesce, mentre una disponibilità parziale consente di continuare con un avviso localizzato.

Le modalità Git si escludono a vicenda; `none` disattiva il filtro Git. Le modalità temporanee `staged`, `changes` e `diff:<ref>..<ref>` non vengono salvate nei profili. Quando una modalità temporanea è attiva, il profilo locale del progetto della GUI conserva l’ultima modalità persistente abilitata, `gitignore` o `tracked`. `none` viene salvata solo se è attiva al momento del salvataggio. La TUI e la CLI rifiutano di salvare un profilo portabile mentre è attiva una modalità temporanea.

### 12.7 Relazione tra il filtro Git e Smart Ignore
La modalità Git selezionata e Smart Ignore sono controllati in modo indipendente. La modalità Git viene applicata per prima in ogni area Git raggiungibile, poi Smart Ignore elabora gli elementi rimasti e infine agiscono le regole di base.

Smart Ignore può restare nascosto finché la modalità Git selezionata copre già tutti i suoi candidati e comparire dopo un cambio o la disattivazione della modalità. In un repository Git restano disponibili tutte le modalità che dipendono dal repository.

Una negazione Git con `!` annulla solo il risultato Git. Non disattiva Smart Ignore né una regola di base.

### 12.8 Regole di base
«Cartelle con punto iniziale» e «File con punto iniziale» controllano il nome dell’elemento.

«Cartelle nascoste» e «File nascosti» controllano l’attributo di sistema Hidden. Su alcune piattaforme, un nome con punto iniziale e l’attributo di sistema possono descrivere lo stesso elemento oppure elementi diversi.

«File vuoti» nasconde i file con dimensione di 0 byte.

«File senza estensione» nasconde file come `Dockerfile`, `Makefile` e `README`.

«Cartelle vuote» nasconde le cartelle logicamente vuote. Una cartella è logicamente vuota quando, dopo l’applicazione dei tipi di file selezionati e di tutte le altre regole, non rimangono file o sottocartelle visibili.

Il contatore delle cartelle vuote può quindi cambiare quando viene modificata un’altra regola: nascondere dei file può rendere logicamente vuote le cartelle che li contengono.

### 12.9 Contatori
Il contatore accanto a una regola mostra il suo contributo diretto con le impostazioni correnti, non il numero fisico di elementi simili sul disco.

Lo stesso elemento non viene attribuito contemporaneamente a più contatori sovrapposti. Ad esempio, la cartella `.git` può avere sia un nome con punto iniziale sia l’attributo di sistema Hidden, ma la sua esclusione viene attribuita a una sola regola.

Per scegliere a quale regola attribuire un’esclusione si usa un ordine stabile:

* cartelle: `.gitignore`, Smart Ignore, nome con punto iniziale, attributo di sistema Hidden;
* file: `.gitignore`, Smart Ignore, nome con punto iniziale, nessuna estensione, file vuoto, attributo di sistema Hidden.

Questo ordine riguarda solo i contatori. La visibilità finale segue una regola più semplice: un elemento è nascosto se un qualsiasi meccanismo attivo lo esclude.

### 12.10 Applicazione delle modifiche
Le caselle aggiornano prima le opzioni disponibili e i contatori nel pannello. L’albero finale viene ricostruito dopo aver scelto «Applica».

Se la preparazione delle impostazioni viene annullata, DevProjex riporta il pannello all’ultimo stato completato. Le regole calcolate solo in parte non vengono applicate.

## 13) Come vengono calcolati albero e metriche
Il risultato dipende da:
* tipi di file selezionati
* regole di esclusione
* filtro attivo
* nodi selezionati con checkbox nell’albero (per operazioni basate sulla selezione)

Se l’accesso è negato, il nodo mantiene il nome e l’icona abituali e riceve il suffisso «[accesso negato]».

### 13.1 Cosa mostrano i contatori nella barra di stato
La barra di stato contiene due blocchi:
* Albero — metriche dell’output testuale dell’albero;
* Contenuto — metriche dell’output dei contenuti dei file.

Formato:
* Righe
* Caratteri
* ≈Token (stima)

I valori grandi sono mostrati in formato compatto (K/M).

Importante:
* «Righe» nel blocco «Albero» indica il numero di righe della rappresentazione finale dell’albero, non il numero di file su disco;
* in questo valore rientrano cartelle, file ed elementi di servizio dell’albero (ad esempio nodi con accesso negato).

### 13.2 Come vengono calcolate le metriche
Metriche albero:
* sono calcolate dall’output reale dell’albero generato dalla stessa pipeline di export;
* rispettano il formato albero corrente.

Metriche contenuto:
* seguono le stesse regole della copia/export contenuto;
* i file binari sono esclusi;
* file vuoti e solo spazi sono conteggiati tramite marker di servizio (`[No Content, 0 bytes]`, `[Whitespace, N bytes]`).

### 13.3 Quando i contatori vengono aggiornati
Il ricalcolo avviene:
* dopo apertura/aggiornamento progetto;
* dopo l’applicazione delle impostazioni (esclusioni e tipi di file);
* quando cambiano le checkbox nell’albero (con debounce);
* quando si cambia formato albero (per operazioni che usano l’albero);
* quando il calcolo in background viene annullato, i contatori vengono impostati a 0 fino al successivo ricalcolo completato.

1) tipo nodo (cartella/file)
2) nome esatto (se esiste una regola)
3) estensione

## 15) Tema ed effetti
La sezione «Tema» permette di scegliere Sistema, Chiaro o Scuro e un effetto di sfondo:
* Trasparenza
* Sfocatura
* Mica

Sistema è selezionato per impostazione predefinita e segue le modifiche del tema del sistema operativo. Dopo il primo avvio o il ripristino delle impostazioni, un tema di sistema chiaro usa un normale sfondo opaco, mentre un tema di sistema scuro usa Sfocatura. Se la preferenza di sistema non può essere determinata, DevProjex usa Scuro con Sfocatura. I temi Chiaro e Scuro ricordano i propri effetti separatamente. Una scelta esplicita di Chiaro o Scuro ignora le modifiche del sistema finché non viene selezionato nuovamente Sistema.

Gli effetti si escludono a vicenda. Un nuovo clic sull’effetto selezionato lo disattiva e ripristina un normale sfondo opaco.

Impostazioni disponibili:
* Trasparenza dello sfondo — disponibile per Trasparenza e Sfocatura.
* Contrasto barra superiore — regola la barra principale con i comandi di anteprima, ricerca, filtro e formato dell’albero.
* Trasparenza dei menu — si applica allo stesso modo al menu principale e ai relativi sottomenu.
* Visibilità dei bordi — regola quanto sono evidenti i bordi dell’interfaccia.

Mica usa il materiale di sistema della piattaforma e non ha un’impostazione separata per la trasparenza dello sfondo. Se l’effetto selezionato, Sfocatura o Mica, non è disponibile, l’app prova prima l’altro effetto nativo. Un normale sfondo opaco viene usato solo quando nessuno dei due effetti è disponibile.

In modalità Trasparenza, lo sfondo della finestra principale rimane trasparente. Menu, sottomenu e altre superfici popup usano Sfocatura, se supportata, affinché l’albero e il contenuto sottostanti non riducano la leggibilità.

## 16) Aiuto

### 16.1 Aggiornamenti
«Aiuto → Aggiornamenti» confronta la versione corrente con l’ultima versione stabile pubblicata su GitHub. I controlli automatici sono disattivati per impostazione predefinita; se attivati, DevProjex controlla all’avvio quando sono trascorsi almeno sette giorni dall’ultimo controllo riuscito. La casella di controllo viene applicata immediatamente. L’ultimo risultato riuscito viene conservato tra le esecuzioni dell’applicazione e non viene cancellato da un successivo errore di rete. L’installazione resta un’azione dell’utente.

### 16.2 Ripristina impostazioni
Ripristina impostazioni (Aiuto → Ripristina impostazioni) ripristina i valori predefiniti di tema, effetti, modalità compatta, impostazioni delle animazioni e lingua dell’interfaccia. I profili dei progetti, la cronologia e i file sul disco non vengono modificati.

### 16.3 Ripristina dati
Ripristina dati (Aiuto → Ripristina dati) rimuove i profili salvati dei parametri dei progetti locali:
* tipi di file selezionati;
* opzioni selezionate nella sezione «Esclusioni»;
* impostazioni selezionate per l’elaborazione dei contenuti;
* contrassegni manuali dei segreti.

Cancella inoltre le sessioni completate del registro dell’agente (sezione 19.3); le sessioni attive vengono conservate.

Importante:
* la cronologia «Recenti» delle cartelle locali non viene cancellata;
* la cronologia «Collegamenti recenti» nella finestra «Clona repository» non viene cancellata;
* file e cartelle dei progetti sul disco non vengono modificati né eliminati.

## 17) Lingue
La lingua si seleziona dal menu Lingua.
La lingua scelta viene salvata tra gli avvii dell’app. «Aiuto → Ripristina impostazioni» cancella la lingua salvata e riporta l’interfaccia alla lingua predefinita.

## 18) Barra di avanzamento e annullamento
Nella parte centrale della barra di stato vengono mostrati l’operazione attiva e il suo avanzamento.

Modalità di avanzamento:
* Indeterminate — senza percentuale (durata sconosciuta).
* Determinate — con percentuale (0–100).

Comportamento:
* durante il calcolo dei dati in background viene mostrata la percentuale;
* per alcune operazioni Git la percentuale viene mostrata se la sorgente la fornisce;
* l’aggiornamento delle opzioni disponibili e l’applicazione delle impostazioni vengono mostrati se l’operazione richiede un tempo percepibile;
* le operazioni rapide terminano senza mostrare l’avanzamento.

Pulsante X (annulla) nella barra di stato:
* esegue un annullamento best-effort per le operazioni che supportano l’annullamento;
* interrompe il calcolo dei dati in background;
* quando viene annullato un aggiornamento delle opzioni disponibili, riporta il pannello all’ultimo stato completato;
* per le operazioni senza supporto all’annullamento, ferma l’indicazione nella barra di stato, mentre l’operazione può comunque terminare in background.

## 19) MCP e agenti IA
DevProjex include un server MCP locale in sola lettura. Gli agenti IA come Claude Code, Codex, Cursor e VS Code leggono il progetto attraverso di esso: il mascheramento dei segreti è sempre attivo e l’agente non può modificare i file del progetto. Il server offre otto strumenti: `list_projects`, `get_tree`, `analyze`, `search_project`, `related_files`, `get_file`, `pack_context` e `read_pack`.

### 19.1 Collegare un client
Il menu «MCP» contiene:
* Live context — il server segue gli elementi selezionati in questa finestra (sezione 19.2);
* Standard — il server non dipende dalla selezione nella finestra;
* Registro… — ciò che gli agenti hanno richiesto e ricevuto (sezione 19.3);
* Documentazione — apre la documentazione del server MCP.

«Live context» e «Standard» contengono le stesse azioni: «Apri in Claude Code», «Apri in Codex», «Apri in Cursor», «Apri in VS Code» e «Altri client…». Sono disponibili mentre un progetto è aperto.

Claude Code e Codex vengono registrati tramite il loro comando installato, poi il client si apre in un nuovo terminale nella cartella del progetto. Cursor e VS Code ricevono un file `.cursor/mcp.json` o `.vscode/mcp.json` locale al progetto; gli altri server in quel file vengono conservati. «Altri client…» mostra una configurazione pronta all’uso per Claude Desktop e altri client. Se il comando di un client manca o la connessione non riesce, DevProjex mostra invece la configurazione manuale. Dopo una connessione riuscita, DevProjex può proporre di aggiungere il comando `devprojex` al PATH.

Codex mantiene un’unica connessione DevProjex condivisa, quindi il collegamento di un altro progetto chiede conferma prima di sostituirla. Una sessione del client già in esecuzione deve essere riavviata per caricare il server. In un terminale, `devprojex mcp connect` registra la modalità standard per impostazione predefinita; aggiungi `--mode live` per Live context o `--print` per stampare solo la configurazione.

### 19.2 Live context
In Live context, gli elementi selezionati nell’albero definiscono il focus dell’agente: le richieste di albero, ricerca, analisi, file correlati e pacchetti restano al loro interno. I filtri della finestra — tipi di file, esclusioni e modalità Git — costituiscono il limite di accesso: l’agente può comunque aprire altri file per nome, ma solo quelli consentiti da questi filtri.

La finestra non deve restare aperta. A ogni richiesta il server legge l’ultima selezione salvata per il progetto, quindi le nuove spunte e le impostazioni applicate raggiungono l’agente alla richiesta successiva senza riavviarlo.

Mentre una sessione live è attiva, il titolo della finestra termina con `· Live context (<client>)`, oppure con il numero di sessioni quando ne sono attive più di una.

### 19.3 Registro
«MCP → Registro…» mostra ciò che gli agenti hanno richiesto e ricevuto tramite DevProjex: le sessioni con client, modalità, chiamate, caratteri, token stimati, file consegnati e valori mascherati, e le chiamate della sessione selezionata. È disponibile anche senza un progetto aperto; con un progetto aperto, «Solo progetto corrente» è selezionato per impostazione predefinita.

Il registro viene conservato solo su questo computer, nella cartella di stato di DevProjex, e mantiene al massimo 200 sessioni per 30 giorni. Non memorizza il contenuto dei file, i valori segreti rilevati né il testo delle query di ricerca. «Esporta…» salva una sessione come ricevuta in Markdown o JSON. «Cancella» elimina le sessioni completate dopo una conferma; le sessioni attive e quelle condivise con altri progetti vengono conservate.

### 19.4 Attività dell’agente
«Visualizza → Attività dell’agente» è disattivato per impostazione predefinita: selezionalo per mostrare i contrassegni e selezionalo di nuovo per nasconderli. Finché è attivo ed è in corso una sessione live, ogni file di cui l’agente ha ricevuto il contenuto in quella sessione — il file intero, un intervallo di righe, risultati di ricerca o una dichiarazione — è contrassegnato con ✦ nell’albero. Un file che l’agente ha visto solo in un elenco dell’albero o in una stima delle dimensioni non viene contrassegnato. Passa il puntatore su ✦ per vedere quante volte l’agente ha ricevuto il file, ad esempio «L’agente ha ricevuto il file 3 volte».

I contrassegni mostrano solo ciò che è stato consegnato: non modificano mai checkbox, filtri o ciò che l’agente può leggere. Vengono rimossi quando inizia una sessione live più recente, quando la sessione live termina, quando l’attività dell’agente viene disattivata e quando il progetto viene riaperto; i file che l’agente riceve in seguito vengono contrassegnati di nuovo. Le sessioni Standard compaiono nel registro ma non aggiungono contrassegni.

Nell’area di lavoro del terminale, `:set activity on` contrassegna gli stessi file con A nell’albero e, quando uno di questi file ha il focus, la riga di stato mostra quante volte l’agente lo ha ricevuto; `:set activity off` rimuove i contrassegni.

* Se i permessi non bastano, l’app può proporre il riavvio con privilegi elevati; in caso di rifiuto viene mostrato un avviso.
